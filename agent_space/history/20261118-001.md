# 중대한 성능 문제: 기본 편집 조작의 장시간 지연

- 기록일: 2026-11-18
- 분류: 중대한 사용성·성능 문제
- 상태: 사용자 증상 및 비용이 큰 구현 경로 확인, 구간별 실행시간 측정과 수정 대기
- 기준 커밋: `b385fb392443d090e47f39ebf3cff0c0acc2d4d5`
- 조사: [최적화 연구](../research/20261118-001.md)

## 1. 발생과 영향

사용자가 프로젝트 열기, 슬롯·디렉터리·그래프 객체 선택, 그래프 설정 변경에서 심한 지연을 보고했다. 기본 편집 조작의 응답성이 작업을 방해하므로 중대한 문제로 기록한다.

사용자가 제공한 디버그 로그는 13줄이며, 그중 조작별 시각을 아래 표에 옮겼다. 마지막 audit에는 `1.1.43-wip`, Firefox 160, CSV 10개, chart 10개, slot 10개, image 0개, control 320개가 기록되어 있다. audit의 `issues: 0`은 해당 검사 항목의 결과다. 응답시간 검사는 포함되어 있지 않다.

관측 조작 순서는 프로젝트 가져오기 → 슬롯 선택 → 디렉터리 선택 → 그래프 객체 선택 → 그래프 설정 변경이다. 사용한 프로젝트 파일의 크기·CSV 행 수와 각 조작의 입력 시작·화면 표시 완료 시각은 확보하지 못했다.

## 3. 정적 조사에서 확인한 구조

1. **선택 변경이 넓은 UI 구독을 갱신한다.** `sourcecode/frontend/mantine_ui.js:277-293,405-416`의 공통 입력과 여러 컴포넌트가 같은 전체 revision을 구독한다. 숫자 입력의 대상·현재 값 조회도 별도로 수행된다. 실제 마운트된 컴포넌트별 호출 횟수는 아직 측정하지 않았다.
2. **작은 화면 정보 조회에 큰 자산 데이터가 동반된다.** `sourcecode/backend/project_state.js:315-345,418-434,453-468`의 트리·휴지통·삭제 대상·그래프 편집 조회가 CSV 행과 bytes 등을 복사한다. `sourcecode/frontend/mantine_ui.js:872-885,937,989-1041,1636-1638,2031-2033`에는 이름·개수·선택 항목만 필요한 소비자가 있다.
3. **불변 복사의 재귀 방문이 반복된다.** `sourcecode/backend/project_state.js:697-704`는 복사 후 재귀 freeze를 수행한다. 트리의 공유 자식 참조가 여러 경로에서 다시 방문된다. `structuredClone`은 참조 그래프를 보존하므로 이 현상을 조상마다 별도 복사본이 생성되는 것으로 해석하면 안 된다.
4. **작은 그래프 설정 변경도 전체 프로젝트 비용을 지불한다.** `sourcecode/backend/project_efsm.js:639-675`의 후보 복사·검증, `sourcecode/backend/project_state.js:77-83`의 initialize 복사·검증, `sourcecode/backend/project_efsm.js:57-86,124-153`의 실제 결과 비교가 결합된다. 그래프 검증의 열 정의 계산은 CSV 행을 순회한다(`sourcecode/backend/graphs.js:553-603`).

디렉터리·그래프 객체 선택은 Frontend FSM 변경 경로다. 이 조작들의 공통 비용을 조사할 때 UI 구독·조회·복사 경로를 우선 확인해야 한다. 선택된 그래프의 Plotly 실행 비용도 별도 측정 대상으로 남긴다.

## 4. 앞선 변경에서 남긴 검토 공백

Plan042의 공통 입력은 입력 처리 규칙을 통합했지만, 대상·현재 값 조회에 따른 데이터량과 전체 revision 구독 비용을 제한하지 않았다. Plan044는 작업공간의 그래프 갱신 범위를 줄였지만, Sidebar 조회·불변 복사·변경 후보 검증 비용은 남아 있다.

앞선 완료 기록의 문법·번역·정적 검사 결과에 실제 응답시간 근거가 부족했다. 이번 증상은 전체 작업 경로의 성능 검증 필요성을 드러낸다. 각 변경이 지연을 발생시킨 정확한 시점과 시간 비중은 추가 계측으로 확인해야 한다.
