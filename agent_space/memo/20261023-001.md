# 후속 확인 항목

사용자 요청에 따라 일반 코딩 원칙의 전체 준수 확인은 후속 체크리스트로 기록하고, 확정된 명세의 구현을 계속한다. 메모는 새로운 설계·정책 원천이 아니다.

- [ ] 개발 정책 §2: 계산/상태 변경 분리, current-authority 조건 검증 및 단일 mutation 경로.
- [ ] Single Source of Truth: export snapshot/view/DOM 측정값은 한 작업의 읽기 전용 입력으로만 소비하고 다른 작업 또는 mutation 입력에 재유입하지 않는지 확인.
- [ ] 참조 무결성: visible slot ID, ordered label ID, figure/image projection의 대응과 누락 처리를 확인.
- [ ] 최소 복잡도: createTargetExportView 등의 작업 로컬 adapter가 필요한 표현 변환만 하는지, 중복 상태·책임·불필요한 추상화를 추가하지 않는지 확인.
- [ ] 자원 정리 검증: r117에서 exportChartImage의 렌더링 실패와 purge 실패가 동시에 발생해도 원래 실패를 보존하고 host 제거는 계속 시도하도록 구현했다. downloadExportPayload도 handoff/revoke 동시 실패에 같은 규칙을 적용했다. pseudocode/frontend/renderer.pcal의 PropagateOriginalFailure 대응이며 148/150에 보강했으나 실행 검증은 대기 중이다.
- [ ] 정리만 실패한 경우 결과 의미를 Source Script/PlusCal의 전체 관련 계약에서 확인한다. 미확정이면 하위 구현에서 임의로 오류 무시/성공/실패 규칙을 결정하지 않는다.
- [ ] r118은 Source renderer의 statusSink 비권위 계약과 current의 동일 completion 규칙을 적용했다. current/target에서 동기 progress callback이 던져도 작업을 취소하지 않고, 거부 사유와 완료된 handoff의 saved 결과를 보존한다. 성공 telemetry의 throw도 결과를 바꾸지 않는다.147/149에 시작/완료/거부 status와 debug 실패 검사를 보강했으나 실행 대기다. 비동기 callback 프로토콜을 새로 정의하지 않았고 cleanup-only 의미 결정과는 별개다.
- [ ] current capture: DOM Plotly handle의 비동기 수명, 화면 변경 중 일관성, image clipping 및 caption paragraph 표현을 관련 명세와 대조.
- [ ] 회귀 148의 렌더링·정리 동시 실패와 150의 handoff·revoke 동시 실패 검사를 r117에 추가했다. 실제 실행, 149의 현재 viewport 외 실제 plot/image/label 경로 검증은 남아 있다.
- [ ] 최신 변경을 실제 허가된 Actions에서 검증하고, 실행 기준 commit/run ID/로그를 기록한다. 과거 d7aa9e2의 성공을 현재 작업 검증으로 사용하지 않는다.

정책 §7.2에 따라 구현 후 전체 역검증을 새로운 공통 필수 gate로 만들지 않는다. 위 항목은 현재 작업에서 발견한 구체적인 확인 사항이다. 정책은 수정하지 않는다.
