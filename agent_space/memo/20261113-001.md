# 상위 구현 결정이 필요한 항목

## 1. canonical VFS tree와 별도 slot/chart 표시의 공급 경계

`pseudocode/backend/project_state.pcal`의 `BuildVfsRead`는 directories/assets의 canonical tree를 반환한다. 현재 UI의 별도 slot 목록은 visible slot의 contentType/chart/imageId와, 연결된 chart의 editability를 사용한다. 참조가 없는 chart도 이 목록에 나타날 수 있다. 이 facts를 어느 공식 read로 제공할지 Source에서 정하고 PlusCal에 반영해야 canonical tree의 공개 반환과 해당 UI 소비를 함께 전환할 수 있다. canonical tree에 slot/chart를 임의로 섞거나 Frontend가 Backend 내부를 읽는 방식으로 정하지 않는다.

명시 경로 자산 조회·삭제 대상·참조 수·휴지통 하위 트리 계산은 이 결정의 대상이 아니다.

## 2. grid 단일 차원 편집의 입력 조합

`setGrid(rows, cols)`의 명시 입력 계약은 정해져 있다. UI가 한 dimension만 편집할 때 나머지 값을 render 때 표시된 값으로 보낼지, 이벤트 시점의 공식 read 값으로 보낼지와 invalid-input fallback 조합을 결정해야 한다. 예를 들어 화면 2×2 뒤 현재가 2×3으로 바뀌었다면 row=3 편집을 3×2와 3×3 중 어느 입력으로 해석할지다. 이 결정 전에는 새 companion 병합 규칙을 추가하지 않는다.

## 3. debug toggle의 명시 입력

`setDebugEnabled(value)`에 어떤 반전 값을 보낼지 정해야 한다. render 때 표시한 telemetry 값의 반전인지, 클릭 시점 runtime 값의 반전인지가 현재 상세 Source에 없다. 중간에 값이 바뀌는 경우의 의미를 정한 뒤 호출 입력을 번역한다.
