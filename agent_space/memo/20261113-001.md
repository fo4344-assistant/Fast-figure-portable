# 상위 알고리즘 보완 및 번역 정합성 확인 기록

2026-11-14 Plan027에서 아래 세 항목을 Source Script → pseudocode → source code 순서로 반영하고 실제 소비자를 정적으로 대조했다(r157, `patches/20261114-014.patch` 및 동명 설명). 아래 본문은 반영 전 지적·보완 근거의 이력이며 사용자 선호 결정이나 미반영 작업 목록이 아니다. 실행 확인은 하지 않았고 새 계층 상태는 stale이다.

세부 알고리즘이나 구현 절차가 부족하면 반드시 기존 SSoT와 책임 경계를 지켜 보완한다. 변경하지 않는 값·변경 전제조건은 해당 owner의 현재 authoritative state와 공식 조회 경로를 기준으로 해결하며, UI 표시값·과거 projection·별도 mirror를 권위 원천으로 삼지 않는다. 이미 정책과 Source Script로 정해지는 내용을 새 사용자 선호 결정으로 취급하지 않는다. 보완이 필요한 상위 의미는 Source Script → pseudocode → 실제 코드/소비자 순서로 대응한다.

## 1. 슬롯별 사용 에셋 표시의 상위 알고리즘 보완과 번역 불일치 수정

새 API 방식이나 사용자 선호를 결정할 항목이 아니라, 기존 표시 기능의 상위 알고리즘을 보완하고 번역 대응을 수정할 작업이다. 현재 UI는 에셋 목록과 `/slots` 아래 슬롯별 사용 에셋 항목을 표시한다. 독립적인 chart 관리 목록을 추가하는 작업이 아니다.

Source Script에는 슬롯·chart·에셋 연결 관계가 있으나, 슬롯별 사용 에셋을 조회·종합해 표시하는 절차가 명시적으로 연결돼 있지 않다. 레이아웃이 정한 표시 슬롯을 순회하고 각 슬롯 오브젝트의 imageId 또는 chart→graph objects→csvId 관계를 공식 조회 경로에서 해결해 표시 결과를 만드는 상위 알고리즘을 보완한다. 빈 슬롯·외부 에셋 참조가 없는 chart의 기존 표시도 보존한다. 기존 객체와 조회 책임을 재사용하며 전용 신규 API를 필수 조건으로 삼거나 Frontend가 Backend 내부를 직접 읽게 하지 않는다.

별도로 Source Script/pseudocode의 `assets.readTree`는 directories/assets의 canonical VFS tree를 반환하지만, 현재 구현은 `{ directories, data, images, charts, slots }` 평면 묶음을 반환하고 UI가 이를 소비한다. 상위 알고리즘 보완 후 Source Script → pseudocode → Backend read/public API/실제 UI 소비자 순서로 대응을 맞춰 이 번역 불일치를 수정한다. canonical 자산 트리와 슬롯별 연결 표시를 구분하고 두 기존 기능을 유지한다.

명시 경로 자산 조회·삭제 대상·참조 수·휴지통 하위 트리 계산은 이 작업으로 다시 열지 않는다.

## 2. grid 단일 차원 편집의 SSoT 준수와 세부 절차 보완

`setGrid(rows, cols)`는 변경 후 전체 행·열 수를 받아 현재 프로젝트에서 안전한 슬롯 유지·추가·삭제를 계산하는 기존 계약이다. 슬롯 resize 알고리즘이나 사용자 선호를 새로 결정할 문제가 아니다. SSoT는 Backend `activeProject.layout.gridRows/gridCols`이며 UI 입력란의 값은 공식 `layout.readState`에서 받은 표시용 projection이다.

행만 편집하면 새 행 값과 현재 authoritative 열 값을, 열만 편집하면 현재 authoritative 행 값과 새 열 값을 조합한다. 공식 조회·명령 경계를 지키고 Frontend가 Backend 내부를 직접 읽지 않는다. 이전 render의 값을 별도 원천으로 사용해 변경하지 않은 차원을 덮어쓰거나 grid mirror를 추가하지 않는다. invalid 입력에서 기존 값을 유지할 필요가 있을 때도 현재 SSoT를 기준으로 하며 UI 복사본을 fallback authority로 쓰지 않는다. 이 입력 구성·조회·검증의 세부 알고리즘이 부족하면 SSoT 원칙에 맞게 Source Script에서 보완하고 pseudocode와 실제 소비자까지 대응한다. 현재 상태 재검증과 한 번의 candidate commit이라는 기존 Backend 규칙은 유지한다.

## 3. debug toggle의 Source Script 처리 절차 보완과 번역 대응

`sourcescript/system.py`는 `debugEnabled`를 session runtime authority로, `uiTelemetryState.debugEnabled`를 단방향 표시용 projection으로 정의하고 projection에서 authority로 되돌아가는 mutation 경로를 금지한다. 반전 기준을 사용자 선호나 미결정 UX 정책으로 다시 선택할 항목이 아니다.

Source Script에 클릭 처리 → runtime owner의 현재 `debugEnabled` 읽기 → 반전 값 계산 → 공식 변경 경로 적용 → 표시 projection 갱신의 세부 절차를 명시적으로 연결하도록 보완한다. 읽기와 변경의 책임을 같은 runtime owner에 두고 UI가 과거 telemetry 값을 반전해 권위 상태에 되쓰거나 별도 debug mirror를 만들지 않도록 한다. 기존 `setDebugEnabled(value)`의 명시 bool 설정 계약과 runtime/project 책임 구분을 유지하며 새 toggle API나 새 상태 저장소를 필수 해법으로 도입하지 않는다. 보완한 Source Script를 pseudocode와 실제 UI/공식 setter/runtime owner의 소비 경로까지 순서대로 대응한다. 실제 구현 수정은 별도 반영 지시에 따른다.
