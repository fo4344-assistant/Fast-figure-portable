# 20261002-006 — inline + split ZIP distribution build

## 목적과 변경 내용

Fast Figure를 EXE 없이 배포할 때 두 가지 오프라인 배포 형태를 같은 원본에서 자동 생성하도록
기존 `scripts/build-portable.py`를 확장한다.

기본 실행:

```bash
python scripts/build-portable.py
```

생성 경로:

```text
dist/
├─ inline/
│  └─ Fast-figure.html
└─ split/
   └─ Fast-figure.zip
```

`dist/`는 생성 산출물이므로 `.gitignore`에서 제외한다.

### inline 배포

`dist/inline/Fast-figure.html`은 다음 런타임 의존성을 모두 HTML 안에 인라인한다.

- Plotly.js
- React/Mantine runtime bundle
- `fast-figure.js`
- `fast-figure-ui.js`

기존 single-file portable 방식의 의미를 유지한다.

### split ZIP 배포

`dist/split/Fast-figure.zip`은 압축 해제 후 다음 구조를 갖는다.

```text
Fast-figure/
├─ Fast-figure.html
├─ fast-figure.js
├─ fast-figure-ui.js
├─ vendor/
│  ├─ plotly.min.js
│  └─ fast-figure-ui-runtime.js
├─ README.md
└─ LICENSE
```

HTML의 기존 상대 script 경로를 바꾸지 않으므로 압축 해제 후
`Fast-figure/Fast-figure.html`을 `file://`로 직접 열 수 있다.

ZIP은 고정 timestamp와 정해진 member 순서를 사용해 checkout 시각에 따라 아카이브 내용이
달라지는 것을 피한다.

## 자동 생성 스크립트 변경

`scripts/build-portable.py`는 단일 HTML만 만드는 함수에서 다음 책임으로 확장했다.

- `build_inline()`: 외부 script tag를 실제 JS bytes로 치환해 single HTML 생성
- `build_split_zip()`: split runtime/source/document/license를 ZIP으로 패키징
- `build_distribution()`: 두 산출물을 한 번에 생성

CLI:

- `--dist-dir`: 배포 루트 변경
- `--inline-output`: inline HTML 출력 경로 변경
- `--output`: 기존 호출 호환성을 위해 `--inline-output` alias로 유지
- `--zip-output`: split ZIP 출력 경로 변경

따라서 기본 build 명령 하나로 두 배포본이 함께 만들어진다.

## 회귀 테스트 변경

이전 browser regression runner는 split 파일들을 테스트용 임시 폴더에 직접 복사하고
portable HTML만 실제 builder로 만들었다.

이제 회귀는 실제 배포 builder 자체를 실행한다.

1. 임시 `dist/`에 두 산출물 생성
2. inline HTML 존재 확인
3. split ZIP 존재 확인
4. ZIP member set이 예상 구조와 정확히 일치하는지 확인
5. ZIP 해제
6. inline HTML에 대해 file:// 13개 회귀
7. split ZIP 해제본에 대해 같은 file:// 13개 회귀

따라서 ZIP 구성 누락이나 잘못된 상대경로도 회귀에서 직접 검출된다.

`agent_space/tests/browser-regression.js`의 target source-code는 r2로 갱신했다.

## 선택 이유

두 배포 방식 모두 동일한 split source에서 매번 생성하게 하면 배포본이 별도의 권위 원천이 되지 않는다.

`dist/inline`과 `dist/split`을 분리하면 single HTML과 split ZIP을 명확히 구분하면서도
하나의 build script와 하나의 source tree를 유지할 수 있다.

ZIP 안에 README와 LICENSE도 같이 넣어 독립 배포 패키지로 사용 가능하게 했다.

## 고려했지만 선택하지 않은 방향

### 생성된 dist 파일을 저장소에 commit

선택하지 않았다.

생성된 HTML/ZIP을 source와 함께 commit하면 같은 내용을 두 위치에서 관리해야 하고
source-of-truth가 중복된다. `dist/`는 항상 재생성 가능한 derived artifact로 유지한다.

### inline HTML만 유지

선택하지 않았다.

사용자가 의존성을 분리한 ZIP 배포도 요구했고, Plotly 같은 큰 vendor 파일을 분리하면
파일별 교체·검사·압축 배포가 가능하다.

### split ZIP 안에도 inline HTML을 넣기

선택하지 않았다.

그 경우 ZIP이 split 배포라는 목적을 잃고 큰 vendor/source bytes가 HTML과 별도 파일에 중복된다.

### 별도 새 packaging script 추가

선택하지 않았다.

기존 `build-portable.py`가 이미 distribution 생성 책임을 갖고 있어 같은 입력을 읽는 두 번째
builder를 만들면 패키징 규칙이 중복된다.

### EXE/앱 런타임 패키징

선택하지 않았다.

이번 요구는 브라우저에서 직접 실행 가능한 HTML 기반 배포 두 종류이며, 별도 native runtime은 필요하지 않다.

## rollback

이 패치를 되돌릴 때:

1. `scripts/build-portable.py`를 r1 상태로 되돌린다.
2. browser regression runner를 수동 split-copy + single portable 검사 방식으로 되돌린다.
3. regression target을 r1로 되돌린다.
4. README와 workflow trigger 변경을 되돌린다.
5. `.gitignore`의 `/dist/` 항목을 제거한다.
6. source-code metadata를 r1 fingerprint/review로 되돌린다.

Source Script와 verification-model에는 rollback할 변경이 없다.
