# 20260901-010 — Mantine Label staging 계약 연결

## 목적

`plan-003.md` Commit B의 Label staging 단계입니다. `20260901-008`과 `20260901-009`에서 분리한 DOM-free mutation 계약을 비활성 Mantine Label Modal에 연결합니다. 현재 legacy UI는 계속 유일한 활성 UI이며 shell cutover는 수행하지 않습니다.

## 변경 내용

- 애플리케이션 버전을 `1.1.40-alpha`로 갱신합니다.
- `FastFigureLabelModalStaging({ opened })`을 추가합니다.
- Modal이 열릴 때 `fastFigureUiBridge.read().labels`에서 임시 draft를 구성합니다.
- Mantine `Switch`로 label 표시와 괄호 사용을 편집합니다.
- Mantine `Select`로 기존 소스에 정의된 label format, order, font family 선택지를 그대로 제공합니다.
- Mantine `NumberInput`으로 font size, X/Y 위치를 편집합니다.
- 적용 시 다음 DOM-free bridge만 호출합니다.
  - `setAnnotationEnabled("label", enabled)`
  - `applyLabelSettings(values)`
  - `applyLabelPosition({x, y})`
- 위치 초기화는 `resetLabelPosition()`을 호출하고 반환된 project 값을 local draft에 반영합니다.
- 기존 `FastFigureOverlayHostStaging`의 Label summary를 `FastFigureLabelModalStaging`으로 교체합니다.
- `window.FastFigureReactShell` export에 새 staging component를 추가합니다.

## 선택지의 근거

이번 staging의 enum 값은 현재 Fast Figure native control에 실제 정의된 값을 그대로 사용합니다.

- format: `lower-alpha`, `upper-alpha`, `decimal`, `lower-roman`, `upper-roman`
- order: `row-major`, `column-major`
- font family: `system-ui, sans-serif`, `Arial, sans-serif`, `Times New Roman, serif`, `Georgia, serif`, `Courier New, monospace`

새 식별자나 선택지는 만들지 않습니다.

## 상태 소유권

project/domain 상태의 권위는 `annotations.labels`입니다. React local state는 Modal에서 아직 적용하지 않은 입력값만 보유합니다. overlay open/close는 기존 EFSM이 계속 소유합니다.

## Preview/drag 경계

기존 `labelPreview`, preview slot geometry, pointer drag는 Fast Figure 고유 좌표계를 사용하는 domain renderer입니다. Mantine 일반 form primitive로 재작성하지 않습니다. 이번 커밋은 해당 renderer를 legacy DOM event로 우회 호출하지 않으며, cutover 전에 React shell 내부 host와 기존 renderer를 연결하는 별도 단계에서 처리합니다.

## 검증 기준

- patch target은 `Fast-figure.html` 하나뿐이어야 합니다.
- `git apply --check`, `git diff --check`, main inline JavaScript `node --check`를 통과해야 합니다.
- staging component에서 native Label control ID를 읽거나 `.click()`으로 legacy handler를 호출하지 않아야 합니다.
- enum 값은 현재 source의 native select 값과 일치해야 합니다.
- staging shell은 아직 mount되지 않아 현재 사용자 UI 동작이 변하지 않아야 합니다.

## 후속 작업

다음 단계는 Caption의 values/payload 계약 분리입니다. Caption 일반 form을 DOM-free mutation 경계로 옮긴 뒤 Mantine Caption staging을 구성합니다.
