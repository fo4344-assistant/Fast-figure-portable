# 20260916-031 — legacy file-name DOM projection removal retry

## 목적과 변경 내용

`20260916-030`의 의도를 current source의 정확한 line/context 기준으로 다시 작성하여 native `#fileName` JavaScript projection을 제거한다.

변경 내용:
- `setFileName()` 제거
- project render, CSV/image selection, image insertion/import, data import, Plotly editable conversion의 `setFileName(...)` 호출 제거

## 선택 이유

`030`은 source 적용 전에 `git apply --check`에서 실패했으므로 application source를 변경하지 않았다. 설계 판단은 그대로 유효하지만 multi-hunk context를 재사용하지 않고 current `main`에서 각 위치를 다시 확인해 최소 context hunk로 작성한다.

`setFileName()`은 `#fileName.textContent`만 변경하며 권위 상태나 renderer 결과를 변경하지 않는다. asset identity의 SoT는 project model과 `appFSM.state.assetPath/assetSelection`이다.

## 선택하지 않은 방향

- 실패한 `030.patch`를 수정하거나 덮어쓰지 않는다. 실패 기록은 audit history로 보존한다.
- native DOM을 다시 생성하거나 optional compatibility path를 만들지 않는다.
- asset-selection event/API, project VFS, domain model은 변경하지 않는다.

## 전제 / 후속 작업 / 누락

- 각 `setFileName` 정의/호출 위치를 `20260916-029` 적용 후 current source에서 재확인했다.
- native `fileName/status` markup과 관련 CSS, `status()`의 DOM projection은 다음 patch에서 함께 정리한다.
- rollback은 이 patch를 되돌리면 JavaScript file-name projection만 복구된다.
