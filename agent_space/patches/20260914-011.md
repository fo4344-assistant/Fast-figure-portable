# 20260914-011 — layout style and debug DOM cutover

## 목적
legacy HTML 제거 전에 startup에서 계속 호출되는 `applySlotStyle()`와 old debug button handlers의 DOM 의존을 제거한다.

## 변경
- `slotStyleFromControls()` 제거.
- `applySlotStyle()`는 `activeProject.layout.slotStyle`만 source로 사용한다.
- old layout input 값 역동기화와 `showSlotBorders` button sync 제거.
- renderer roots(`dashboard`, optional `layoutMap`, `dashboardCaption`)의 style 적용은 유지.
- old `saveDebug`, `clearDebug`, `toggleDebug` handler 제거.
- Mantine `FastFigureStatusDebug`가 이미 `setDebugEnabled`, `saveDebugOutput`, `clearDebugOutput`과 telemetry를 직접 사용하므로 debug 기능은 유지된다.

## 이유
`applySlotStyle()`는 startup과 Mantine layout 양쪽에서 호출되는 active command이므로 hidden legacy inputs를 읽으면 markup 삭제가 불가능하다. debug도 Mantine ownership이 이미 완성되어 old button handlers는 중복 owner다.

## Source of truth
layout style은 `activeProject.layout.slotStyle`, debug state/log는 UI telemetry state다.

## EFSM/core 영향
FFPX/FFSX/Plotly, project schema, layout 계산 및 debug event payload 형식은 변경하지 않는다.

## 검증
workflow 전체 검증을 통과해야 한다.

## 롤백
patch revert로 old layout/debug DOM bridge를 복원할 수 있다. persistent migration은 없다.
