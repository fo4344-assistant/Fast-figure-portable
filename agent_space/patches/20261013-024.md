# 20261013-024 — Add direct UI ownership regressions for Source Code r13

## 목적

Source Code r13의 plan-009 UI 항목 중 기존 regression이 간접적으로만 다루던 세 항목을 browser regression에서 직접 검증한다.

## 추가 검증

1. Layout preview
   - preview grid와 resize handle이 같은 rendered width를 사용한다.
   - preview가 Modal content에서 수평 가운데 정렬된다.
   - 실제 rendered width를 `layout.readState(width)`에 넣었을 때 계산되는 geometry height와 DOM height가 일치한다.

2. 설정 Modal 공통 폭
   - Label / Caption / Print / Layout 네 overlay가 같은 실제 Modal width를 사용한다.
   - 목적이 다른 README Modal은 이 테스트 대상에 포함하지 않는다.

3. trash asset action Menu
   - 일반 CSV를 trash로 이동한다.
   - trash directory를 펼친 뒤 해당 asset의 row action target이 존재하고 disabled가 아닌지 확인한다.
   - target click으로 Mantine Menu dropdown이 실제 열린다는 것을 확인한다.

## 계층 영향

application Source Code 파일은 변경하지 않는다. source-code r13 revision/fingerprint/lineage는 유지한다.

## 선택 이유

정적 코드 대조만으로도 ownership은 확인할 수 있지만, plan-009가 사용자 관찰 가능한 UI 동작을 포함하므로 file:// browser regression에서 실제 DOM 결과까지 확인한다.

## 기각한 방향

- Mantine 내부 CSS 변수 이름을 검사하는 방식: 라이브러리 내부 구현 식별자에 불필요하게 결합되므로 사용하지 않는다.
- trash selection을 활성화해서 menu 접근을 우회 검증하는 방식: Source Script 의미와 다르므로 사용하지 않는다.
- preview requested width를 직접 내부 state로 주입하는 테스트: renderer 구현 세부에 과도하게 결합되므로 사용하지 않는다.

## 후속

GitHub-hosted Fast Figure regression에서 inline 및 split ZIP 모두 통과하는지 확인한다.
