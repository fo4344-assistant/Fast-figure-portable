# 20260910-010 — Print target export value entry 정상 hunk 적용

## 목적
20260910-009의 한 줄 patch는 context 0 unified diff였고 workflow의 `git apply`가 `--unidiff-zero`를 사용하지 않으므로 적용되지 않았다. 실제 source line과 앞뒤 context를 포함한 정상 hunk로 `exportDashboardTarget`의 Mantine용 값 기반 호출 경계를 구현한다.

## 변경
- `exportDashboardTarget(options = null)`로 확장한다.
- `{ width, height, dpi, format, onStatus }`를 직접 받을 수 있게 한다.
- options가 있으면 legacy `#printWidth/#printHeight/#printDpi/#printFormat/#printStatus`를 Mantine 경로의 source/projection으로 사용하지 않는다.
- options가 없으면 기존 legacy print 경로를 그대로 유지한다.

## 선택 이유
출력 알고리즘을 복제하지 않고 동일 renderer에 독립적인 값 입력 경계를 제공하는 것이 최종 Mantine 구조와 가장 일관된다. 실패 원인은 architecture가 아니라 patch 형식이었으므로 설계는 유지한다.

## 기각안
- legacy input `.value` bridge: 독립성이 깨지므로 기각.
- React export 알고리즘 복제: source of truth가 분리되므로 기각.
- context 0 patch를 workflow 변경으로 허용: application 변경을 위해 workflow 규칙을 완화할 필요가 없어 기각.

## Source of truth / EFSM 영향
project model과 기존 export renderer가 source of truth다. print options는 일회성 호출 값이다. FFPX schema와 EFSM 의미는 변경하지 않는다.

## WIP

## 검증
workflow의 git apply, JS syntax, portable build, split/portable smoke를 모두 통과해야 한다.

## Rollback
