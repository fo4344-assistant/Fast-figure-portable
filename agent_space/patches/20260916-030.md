# 20260916-030 — legacy file-name DOM projection removal

## 목적과 변경 내용

Mantine 전환 후에도 남아 있던 native `#fileName` 표시용 JavaScript projection을 제거한다.

변경 내용:
- `setFileName()` 제거
- project render, CSV/image selection, image insertion/import, data import, Plotly editable conversion에서 `setFileName(...)` 호출 제거

## 선택 이유

`setFileName()`은 `#fileName`의 `textContent`만 갱신하며 domain state, logic EFSM, API/router, renderer 또는 반환값에 영향을 주지 않는다. 선택된 asset의 권위 상태는 이미 `appFSM.state.assetPath/assetSelection`과 project model에 있으며 Mantine은 해당 경로를 읽는다.

따라서 이 함수는 동일 사실을 native DOM에 다시 투영하던 legacy frontend output일 뿐이다. SoT를 변경하지 않고 projection을 제거하는 것이 구조적으로 가장 단순하다.

## 선택하지 않은 방향

- `#fileName` DOM을 계속 유지하면서 SoT와 동기화하지 않는다.
- 별도 file-name cache/read model을 만들지 않는다.
- asset selection event, project VFS, CSV/image model은 변경하지 않는다.

## 전제 / 후속 작업 / 누락

- current `setFileName()`의 유일한 동작이 native DOM text 갱신임을 확인했다.
- paired markup/CSS와 native status DOM projection은 다음 패치에서 제거한다.
- rollback은 이 패치를 되돌리면 native file-name projection 함수와 호출만 복구된다.
