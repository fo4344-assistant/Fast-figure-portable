# 20261017-005 — Plan022 import/FFSX 번역 진행 기록

## 목적·이유

계속 작업 요청에 따라 Source r37의 import constructor와 FFSX CSV mapping/target chart ownership 계산을 임시 PlusCal 작업본으로 더 구체화했다. 해당 작업의 실제 범위와 미완료 범위를 plan-022 §12에 남긴다. 기존 Source의 설정/instance 데이터 구분, shared representation validator, 단일 candidate/commit과 같은-read source 경계를 보존하기 위한 작업이다.

## 실제 포함 범위

- 기준 HEAD: `4d427acfc79ea1a22e3ebb1497bffed283679598`.
- semantic endpoint: `a8ffa67e99541710f2289f3e101a6511edc262cb`.
- `.patch`는 위 두 실제 commit의 `git diff --binary`이며 plan-022.md 1파일, 15줄 추가다.
- patch/.md 쌍 자체는 endpoint 이후 순차 게시되므로 자기 참조 diff에 넣지 않는다. 여러 Contents API commit을 단일 atomic commit으로 표현하지 않는다. 각 write 직전 expected HEAD/current blob, 신규 경로 404와 현재 tree의 번호를 확인한다.

## 선택·거절한 대안

- Source entry/signature를 유지한 채 private read/attempt 인자로 동일 source를 전달했다. 새 authority/context registry나 공개 입력을 추가하는 대안은 거절했다.
- conversion view와 실제 project CSV의 수집/remap은 같은 representation 판정을 사용한다. 모든 imported object를 project CSV로 취급하거나 빈 chart에 fake CSV/object를 만드는 대안은 거절했다.
- 실제 metadata/owner/byte loop를 전개하고 미완료 package assembly는 남은 것으로 기록한다. helper 이름이나 entry 개수가 있다는 이유로 전체 번역을 current로 표시하는 대안은 거절했다.

## 미포함·한계

작업 경로 안 `.work/plan022/pseudocode/` 및 연결 메모는 transient 번역 작업물이다. 저장소 patch/remote/rollback에 포함되지 않는다. 이번 patch를 적용하면 진행 기록만 복원되며 해당 작업본까지 복원된다고 주장하지 않는다. 전체 충실도 확인 후에만 활성 hierarchy로 교체한다.

Source 의미 파일/metadata/활성 pseudocode/하위 구현/정책은 변경하지 않았다. Source37 closed, 활성 pseudocode11 stale 및 하위 stale와 fingerprint를 유지했다. FFPX document writer/reader 조립·일부 normalization과 전체 producer/consumer/retry/throw/resource 대조가 남아 있다.

## 확인

실제 semantic endpoint diff의 whitespace 확인과 해당 endpoint를 넣은 격리 index에서 patch reverse cached apply check가 통과했다. 임시 index는 삭제했다. 이는 파일 diff/복원 범위 확인이지 Source/PlusCal parser·동작·충실도 증명이 아니다.

로컬 Source/application/PlusCal/parser/checker/test/build/TLC 실행·delegation은 없으며, branch 변경이 진행 기록뿐이므로 새 Actions dispatch도 하지 않았다. 모든 transport/helper/temp는 현재 작업 경로 안에 두었다.
