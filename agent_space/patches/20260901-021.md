# 20260901-021

## 목적

`20260901-020`에서 준비한 project-name mutation/invalidation 계약을 비활성 Mantine staging sidebar에 연결한다. 기존 읽기 전용 프로젝트 이름 표시를 실제 Mantine `TextInput`으로 교체해 sidebar 일반 form 전환을 시작한다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.51-alpha`로 올린다.
- `FastFigureSidebarStaging()`의 Mantine import에 `TextInput`을 추가한다.
- 기존 프로젝트 이름 `Text` 표시를 `TextInput`으로 교체한다.
- 값의 source of truth는 `snapshot.projectName`으로 유지한다.
- 입력 중에는 `fastFigureUiBridge.setProjectName(value)`를 호출해 기존 native `input` 의미와 동일하게 즉시 project state를 갱신한다.
- focus가 빠질 때 `setProjectName(value, true)`를 호출해 기존 native `change` 단계의 trim 및 debug log 의미를 유지한다.
- 최대 입력 길이는 기존 domain 규칙과 동일하게 120자로 제한한다.

## 이 방향을 선택한 이유

`020`이 domain-only mutation 뒤 external-store invalidation을 제공하므로 controlled Mantine `TextInput`을 사용해도 React local state를 영속 source로 둘 필요가 없다. 입력값은 기존 project object가 계속 소유하고 React는 snapshot을 다시 읽어 표시한다.

이 방식은 sidebar form을 Mantine으로 옮기면서도 별도 form store나 상태 복제를 도입하지 않는다. 또한 native handler와 staging handler가 같은 mutation 계약을 사용하므로 cutover 전후 project-name 의미가 달라지지 않는다.

## 선택하지 않은 방향

- 프로젝트 이름을 React local state에 복제하지 않는다.
- uncontrolled `defaultValue`를 사용하지 않는다. project load/외부 domain 변경을 다시 반영하기 어렵기 때문이다.
- staging sidebar의 다른 control을 같은 패치에서 함께 옮기지 않는다. 첫 실제 sidebar input의 binding 계약을 독립적으로 검증한다.
- 활성 legacy `projectName` input은 아직 제거하지 않는다. staging shell은 mount되지 않으므로 동시 활성 UI는 발생하지 않는다.
- FFPX 형식이나 project naming 규칙은 변경하지 않는다.

## 검증 항목

- `git apply --check`
- `git diff --check`
- 메인 JavaScript `node --check`
- APP_BUILD와 built-in README 버전 일치
- staging project-name input에서 legacy DOM ID 미사용
- project name 최대 120자 유지
- 입력 중 즉시 project state 반영
- blur commit에서 trim 및 debug log 유지
- React local state에 project name 복제 없음
- staging shell은 비활성 상태 유지

## 후속 작업

다음 sidebar 공통 control은 slot content type이다. 기존 `setSlotContentType()`은 이미 EFSM `SLOT_TYPE_CHANGED`를 사용하므로 DOM-free event 경계가 있는지 확인하고, UI sync와 file-picker/panel renderer side effect를 분리한 뒤 Mantine segmented/toggle control에 연결한다.

## 패치에 포함되지 않은 변경사항

이 `.patch`와 설명 `.md` 자체는 재귀적인 diff에 포함하지 않는다. 실제 HTML 수정은 제한된 patch workflow가 검증 후 적용한다.
