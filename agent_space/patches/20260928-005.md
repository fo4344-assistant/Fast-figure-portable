# 20260928-005

## 목적과 변경 내용

Mantine가 이미 소유하고 있는 generic GUI 위에 남아 있던 legacy custom CSS를 제거한다.

현재 HTML body에는 native `button`, `input`, `select`, `textarea`, `dialog` markup이 0개이며 활성 generic UI는 React + Mantine shell이 소유한다. 그러나 Fast Figure custom stylesheet에는 old toolbar/sidebar/popup/form 규칙이 남아 있었고 특히 다음 전역 selector가 Mantine이 실제로 렌더링하는 태그까지 덮고 있었다.

- `header`
- `label`
- `input, select, button`
- `button`
- `button.light`

이 patch는 다음 범주의 legacy generic UI CSS를 제거한다.

- old header/toolbar
- old aside/sidebar resize/collapse controls
- native fieldset/details/palette form layout
- native input/select/button/label geometry
- old row/button layout helpers
- old setting toggle/hint
- old README wrapper button sizing
- old layout popup/popup heading/layout controls
- old ratio controls
- old dashboard zoom controls
- old layout resize handle
- old layout map/slot UI
- old icon-only action sizing
- old generic disabled/light-button palette overrides
- 위 규칙에서만 사용되던 toolbar/popup/icon numeric CSS variables

## Mantine 도입 목적과의 관계

이번 제거가 핵심이다. Mantine Button/Input/Modal을 사용하더라도 뒤쪽에 global `button`/ `input` CSS가 남아 있으면 실제 크기·margin·padding·border는 다시 custom CSS가 결정한다.

`20260928-004`에서 공통 control geometry와 Modal lifecycle을 Mantine theme/default props에 올렸으므로, 이제 해당 legacy 규칙을 제거해 Mantine이 실제 단일 GUI 규칙 소유자가 되도록 한다.

## 유지하는 CSS

다음은 generic UI가 아니라 기능 renderer 또는 shell-renderer 연결이므로 유지한다.

- `.app`, `.app > main`, `--sidebar-width`
- dashboard/slot/Plotly renderer
- image surface
- caption renderer
- slot label
- slot drag/select surface
- graph area
- `#ff-react-bootstrap-root`

Mantine Header가 global body typography의 영향을 받지 않게 기존 `body`의 14px font override는 제거한다. 기존 dashboard renderer의 글자 크기를 보존하기 위해 같은 font 규칙은 `.app > main`으로 범위를 좁혀 이동한다.

## 선택하지 않은 방향

### legacy CSS를 이름만 바꿔 유지

Mantine과 같은 책임을 이중 소유하므로 선택하지 않는다.

### `!important`로 Mantine CSS가 이기게 만들기

중복 규칙 자체를 남기므로 선택하지 않는다.

### renderer CSS까지 Mantine style prop으로 이동

Plotly/dashboard/slot/caption surface는 generic GUI가 아니라 기능 renderer다. 이번 목적과 무관한 renderer 재작성은 하지 않는다.

### shell layout 연결 제거

Mantine Navbar와 sibling dashboard renderer 사이의 폭 전달은 현재 기능 배치에 필요하므로 별도 설계 없이 제거하지 않는다.

## 검증

- 현재 body native generic control markup이 0개인지 확인
- 제거 selector가 활성 React/renderer class/id에서 사용되지 않는지 확인
- GitHub Actions `git apply --check`
- `git diff --check`
- JS syntax
- portable build
- split/portable `file://` smoke
- 적용 후 custom stylesheet에서 global `button`, `input/select/button`, `label`, old toolbar/sidebar/layout-panel selector가 사라졌는지 재검사

## 후속 작업

다음 GUI 단계에서는 Mantine shell 내부에 남은 직접 style 기반 일반 UI 요소를 감사한다. 특히 sidebar resize handle, raw table, file input trigger 같은 부분에서 Mantine primitive/component를 사용할 수 있는 곳을 우선 교체한다.
