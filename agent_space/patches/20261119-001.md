# 계층 지문 계산 기준 통일

- 검사기는 현재 작업 파일마다 `git hash-object`를 호출한다. Git이 해당 경로를 추가할 때 적용하는 줄바꿈 정규화와 필터를 거친 내용을 해시한다. 경로별 해시를 정렬해 계층 지문을 만드는 방식은 유지한다.
- 작업 파일의 원시 바이트를 사용하면 LF와 CRLF 체크아웃에서 결과가 달라진다. HEAD나 인덱스의 blob만 사용하면 아직 스테이징하지 않은 수정을 읽지 못한다. 현재 작업 파일에 Git의 경로별 변환을 적용하면 두 문제를 함께 해결할 수 있다.
- 새 기준에 따라 현재 Source Script 및 source code 지문만 갱신했다. Source Script의 열린 상태, 기존 파생 관계와 두 계층의 버전 번호는 유지했다. pseudocode와 verification-model 지문은 새 기준에서도 같았다.
- 기준: `99fb9cdf554c06bcbd494827731cddce7fff94f1` (`20261118-010.patch`까지 반영한 상태). 이번 실제 Git diff는 검사기와 메타데이터만 담는다.
- Windows 작업 폴더와 LF 체크아웃에서 기존 계층 검사기가 같은 지문으로 통과했다. 별도 체크아웃에서 스테이징하지 않은 source code 내용 변경은 지문 오류로 검출됐다. 이 변경은 Source Script 닫힘 판정이나 하위 계층 번역을 수행하지 않는다.
