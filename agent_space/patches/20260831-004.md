# 20260831-004

## 목적

`agent_space/plans`에 실제 적용 전 작업 계획 문서를 추가하고, 계획 문서의 파일 이름이 날짜나 작업 내용이 아니라 전체 계획 순번을 기준으로 정해지도록 규칙을 명확히 한다.

## 변경 내용

- `agent_space/plans/plan-001.md`를 추가했다.
- `plan-001.md`에는 현재 `swapSlotContents()`의 콘텐츠 누락 문제와 `slot.content` 구조, EFSM 경로, FFPX v3 호환성, grid rebuild, 테스트 및 회귀 검증 계획을 기록했다.
- `agent_space/plans/plans.md`에 계획 문서 이름 규칙을 추가했다.
- 계획 문서는 `plan-NNN.md` 형식을 사용하고 `NNN`은 전체 계획의 3자리 순번으로 증가시킨다.
- 계획 파일 이름에는 날짜와 계획 내용을 넣지 않는다.

## 이 방향을 선택한 이유

계획 문서는 패치보다 수명이 길고 하나의 계획이 여러 날짜에 걸쳐 수정·검토될 수 있으므로 날짜를 파일의 주 식별자로 사용하는 것이 적절하지 않다. 또한 계획의 내용이 검토 과정에서 확장되거나 수정될 수 있으므로 파일 이름에 내용을 넣으면 실제 범위와 이름이 어긋날 수 있다.

`plan-NNN.md` 형식은 계획 간 선후 관계를 안정적으로 표현하면서 내용과 시간 정보는 문서 본문과 Git 이력에서 관리하도록 책임을 분리한다.

## 선택하지 않은 방향

- 날짜 기반 이름은 선택하지 않았다. 하나의 계획이 여러 날짜에 걸쳐 유지될 수 있고 계획의 순서를 이름만으로 바로 파악하기 어렵기 때문이다.
- 기능명이나 문제명을 파일 이름에 넣지 않았다. 계획 범위가 변경될 때 이름이 실제 내용과 어긋날 수 있기 때문이다.
- 패치와 동일한 `YYYYMMDD-NNN` 규칙을 사용하지 않았다. 패치는 변경 기록이고 계획은 실행 전 작업 단위이므로 식별 목적이 다르다.
- 전체 계획 문서를 `plans.md` 하나에 누적하지 않았다. 계획별 독립적인 검토·수정·참조와 이력 추적이 어려워지기 때문이다.

## 패치에 포함되지 않은 변경사항

`20260831-004.patch`와 이 설명 파일 자체의 생성은 자기 자신을 재귀적으로 포함할 수 없으므로 패치 본문에 포함하지 않았다.

`20260831-004.patch`의 `plan-001.md` 부분은 새 계획 문서가 추가되었다는 구조와 범위를 기록하기 위해 요약된 diff를 사용한다. 실제 `plan-001.md`에는 앞서 검토한 전체 문제 분석, 적용 단계, 대안 검토와 테스트 계획이 상세하게 기록되어 있다.
