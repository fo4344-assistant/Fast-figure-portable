# 20260901-026 — Mantine CSV 헤더 설정 staging 경계

## 목적과 변경 내용

`plan-003.md`의 Commit B를 이어서 inactive `FastFigureSidebarStaging`에 선택 CSV의 헤더 줄 수 control을 준비한다.

- 현재 선택된 CSV와 표시 조건을 DOM 없이 계산하는 `selectedCsvHeaderModel()`을 추가한다.
- 기존 `headerLines` DOM change handler의 실제 쓰기·파생 갱신을 `applyCsvHeaderLinesFromValue(value, csvId)`로 추출한다.
- Mantine `NumberInput`과 legacy number input이 같은 값 기반 명령을 호출한다.
- 선택 CSV가 콜백 생성 뒤 바뀌었으면 이전 `csvId`의 쓰기를 거부한다.
- 헤더 변경 뒤 기존 열 control 갱신, 해당 CSV를 참조하는 편집 가능 그래프 재구축, dashboard render와 debug log를 유지한다.
- 앱 버전을 `1.1.55-alpha`로 올린다.

## source of truth 검토

새로운 영속 상태나 React local state를 추가하지 않는다.

- CSV 헤더 줄 수의 source of truth는 기존 project CSV model의 `csv.headerLines`다.
- 현재 CSV 식별자는 기존 `activeCsvId`를 사용한다.
- `selectedCsvHeaderModel()`이 반환하는 고정 객체는 현재 CSV model에서 즉시 계산한 renderer용 일회성 snapshot이다.
- Mantine `NumberInput`은 snapshot 값을 표시하지만 자체 복사본을 저장하지 않는다.
- `applyCsvHeaderLinesFromValue()`은 전달된 `csvId`가 현재 `activeCsvId`와 다르면 쓰지 않아 오래된 snapshot이 다른 CSV를 변경하지 못하게 한다.
- 변경 뒤 `publishFastFigureUiStore()`는 상태를 복제하지 않고 renderer가 source of truth를 다시 읽도록 invalidation만 발행한다.

## 이 방향을 선택한 이유

기존 handler는 헤더 줄 수 보정, CSV model 변경, 열 선택 갱신, 참조 그래프 재구축, dashboard render를 한 DOM event 안에서 수행했다. 이 동작 순서는 이미 기능 의미를 완성하고 있으므로 Mantine용 로직을 다시 만들지 않고 DOM 값 읽기만 legacy adapter에 남겼다.

헤더 상한은 기존 전역 `rows` 대신 권위 대상인 `csv.rows`에서 계산한다. 현재 CSV가 바뀐 뒤 늦게 도착한 UI callback이 다른 대상을 수정하는 것도 `csvId` guard로 차단한다.

## 고려했지만 선택하지 않은 방향

### React local state에 헤더 줄 수 draft 저장

선택하지 않았다. 기존 동작은 change 시 즉시 CSV와 그래프에 반영되며 별도의 적용/취소 의미가 없다. draft를 추가하면 같은 헤더 값의 두 번째 상태와 동기화가 필요하다.

### Mantine callback에서 `csv.headerLines` 직접 변경

선택하지 않았다. legacy handler와 열/그래프 갱신 순서가 갈라지고 React bridge가 project 내부 구조를 직접 알아야 한다.

### 헤더 변경을 새 EFSM event로 재설계

선택하지 않았다. 이번 단계는 UI ownership 전환 준비이며 기존 domain 동작의 의미를 확대하는 단계가 아니다. renderer 재읽기에는 상태 없는 invalidation이면 충분하다.

### 그래프 설정 전체를 같은 패치에서 전환

선택하지 않았다. 축, 범례, 제목, 오브젝트 control은 더 큰 form 계약과 선택 상태를 포함한다. CSV 헤더 경계를 먼저 독립적으로 검증한다.

## 호환성과 동작 보존

- 헤더 줄 수는 기존과 동일하게 0 이상의 정수로 자르고 CSV 행 수를 상한으로 사용한다.
- 선택 CSV의 `headerLines`만 변경한다.
- 해당 CSV를 참조하며 편집 가능한 그래프만 기존 `rebuildEditableGraph()`로 재구축한다.
- 열 control, dashboard, debug log 갱신을 유지한다.
- staging shell은 계속 비활성 상태다.

## 후속 작업 / 범위 밖

- CSV preview table 자체는 기존 domain renderer로 유지한다.
- 그래프 생성/축/범례/오브젝트 설정과 프로젝트 import/export control은 후속 Commit B 패치에서 다룬다.
- legacy `csvSelectionPanel`, `headerLines` markup과 handler 제거는 Commit C/D까지 보류한다.
- asset tree 본체의 Mantine row/action 전환은 아직 남아 있다.
