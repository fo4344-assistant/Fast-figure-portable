# 20260906-008 — lifecycle / overlay 정책 helper active 경로 연결

## 목적

`20260903-009`와 `20260903-011`에서 Mantine shell cutover용으로 준비한 DOM-free workspace/lifecycle/overlay 경계 중 lifecycle/overlay 정책 helper를 현재 active legacy presentation 경로에서도 실제로 재사용한다.

JS source split 이후 `fast-figure.js`의 현재 코드를 직접 확인한 결과, `applyLifecycleDomainState()`와 `applyOverlayOpenPolicy()`는 정의되어 있지만 기존 `enterLifecycleState()`와 `setOverlayDomState()`가 같은 정책을 각각 별도로 구현하고 있다. cutover 직전까지 이 중복을 유지하면 legacy active 경로와 Mantine cutover 경로가 서로 다른 정책 구현을 갖게 된다.

## 변경 내용

- 앱 버전 `1.1.111-alpha` → `1.1.112-alpha`
- `setOverlayDomState(name)`의 popup-open 시 slot selection clear를 `applyOverlayOpenPolicy(name)` 호출로 통합
- `enterLifecycleState({ state, payload })`의 lifecycle error logging을 `applyLifecycleDomainState({ state, payload })` 호출로 통합

## 동작 보존

### overlay

현재 legacy `setOverlayDomState()`에서 `popup`은 `layout`, `label`, `caption`, `print`일 때만 true다. `applyOverlayOpenPolicy()`도 `none`과 `readme`를 제외한 overlay에서만 `clearAllSlotSelections()`를 호출하므로 현재 허용 overlay 집합에서는 동일한 정책이다.

DOM 표시, panel/toggle class, `aria-expanded`, README dialog, layout popup class는 그대로 legacy adapter가 담당한다.

### lifecycle

현재 legacy `enterLifecycleState()`는 error 상태에서 `payload.error`를 debug log에 기록한다. `applyLifecycleDomainState()`가 동일 로그를 담당하며 optional payload guard가 있어 기존 의미를 줄이지 않는다.

`app-busy`, `aria-busy`, legacy control disabled 상태 관리는 아직 presentation adapter에 남긴다.

## Mantine 전환과의 관계

이 변경은 cutover 자체가 아니다. 일반 UI의 active ownership은 아직 legacy에 둔다.

목적은 cutover 전에 다음 두 정책을 단일 경로로 만드는 것이다.

- overlay open 시 domain selection 정리
- lifecycle error domain logging

따라서 실제 cutover에서 EFSM callback을 DOM-free 경계로 바꿀 때 active legacy 경로와 별도의 의미를 새로 만들 필요가 없다.

## source of truth / EFSM / core

- EFSM state 정의와 transition target은 변경하지 않는다.
- project/domain data 의미를 변경하지 않는다.
- FFPX/FFSX/Plotly 파일 의미를 변경하지 않는다.
- Plotly/image/layout renderer를 변경하지 않는다.
- 새 state/cache를 추가하지 않는다.

## 선택하지 않은 방향

### 지금 바로 APP_STATE_DEFINITIONS를 DOM-free helper로 교체

현재 `FastFigureShellStaging`은 아직 active mount되지 않았고 legacy UI가 active owner다. workspace/lifecycle/overlay presentation callback을 먼저 제거하면 legacy 화면 동기화가 끊어진다. `plan-004/005`의 단일 ownership cutover 원칙에 맞지 않아 이번 patch에서는 하지 않는다.

### helper를 다시 legacy 함수 안으로 inline

cutover용 DOM-free 경계를 없애므로 선택하지 않는다.

## 회귀 위험

낮음.

동일 정책의 호출 위치만 공통 helper로 합치며, active DOM presentation 코드는 유지한다.
