# 20260831-005

## 목적

GitHub 커넥터가 약 5 MB 크기의 `Fast-figure.html` 전체 본문을 직접 갱신하기 어려운 상황에서, 저장소에 기록된 diff 패치를 GitHub Actions가 한 번만 검증·적용할 수 있는 제한된 적용 경로를 추가한다.

## 변경 내용

- `.github/workflows/apply-fast-figure-patch.yml`을 추가한다.
- `main` 브랜치에 `agent_space/patches/*.patch`가 추가되는 push에서만 실행한다.
- 한 push에서 변경된 패치 파일이 정확히 하나일 때만 진행한다.
- 패치와 같은 기본 이름의 `.md` 설명 파일이 이미 존재해야 한다.
- 패치가 수정할 수 있는 대상은 `Fast-figure.html` 하나로 제한한다.
- 적용 전에 `git apply --check`를 수행한다.
- 적용 후 `git diff --check`와 HTML의 메인 JavaScript에 대한 `node --check`를 수행한다.
- 실제 변경이 없으면 커밋하지 않는다.
- 변경이 있으면 Actions 전용 작성자로 한 번 커밋하고 `main`에 push한다.
- concurrency group을 하나로 고정해 동시에 여러 패치가 같은 HTML을 수정하지 못하게 한다.

## 이 방향을 선택한 이유

현재 GitHub Contents API 경로는 작은 텍스트 파일 수정에는 적합하지만 `Fast-figure.html` 전체를 매번 5 MB 문자열로 전달하는 것은 비효율적이다. 반면 실제 수정은 이미 diff 패치로 기록해야 하므로, 저장소 자체에서 그 패치를 검증 후 적용하는 경로는 기존 작업 규칙과 일치한다.

트리거를 패치 파일 경로로만 제한했기 때문에 Actions가 생성하는 `Fast-figure.html` 커밋은 워크플로를 다시 실행하지 않는다. 또한 한 번에 한 패치, 한 대상 파일만 허용해 반복 적용이나 의도치 않은 저장소 전체 수정 가능성을 줄인다.

## 선택하지 않은 방향

- 모든 push에서 실행하는 워크플로는 선택하지 않았다. HTML 적용 커밋이 다시 워크플로를 호출해 반복 실행 위험을 만들 수 있다.
- 저장소의 최신 패치를 자동 탐색해 계속 적용하는 방식은 선택하지 않았다. 실행 시점에 어떤 패치를 적용할지 불명확해지고 이미 적용한 패치를 다시 집을 수 있다.
- 여러 패치를 한 실행에서 순차 적용하는 방식은 선택하지 않았다. 실패 지점과 변경 책임이 섞이고 부분 적용 위험이 커진다.
- 임의 파일을 수정할 수 있는 범용 패치 적용기는 선택하지 않았다. 이 워크플로가 필요한 직접적인 이유는 대용량 `Fast-figure.html` 갱신이므로 대상도 해당 파일로 제한한다.
- Actions 내부에서 파일 내용을 생성하거나 변환하는 방식은 선택하지 않았다. 수정 내용의 단일 기준은 `agent_space/patches`의 diff 패치로 유지한다.

## 패치에 포함되지 않은 변경사항

`20260831-005.patch`와 이 설명 파일 자체는 자기 자신을 재귀적으로 포함할 수 없으므로 패치 본문에는 포함하지 않는다.
