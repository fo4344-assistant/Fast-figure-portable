# 20261013-028 — Restore pseudocode as the complete translation layer

## 목적

상위 정책 `agent_space/policies/source-script-policy.md` v0.2.6과 불일치하던 pseudocode 계층 분류와 lineage 검사를 수정한다.

기존 `development-versions.json`과 checker는 `pseudocode/`를 archived/non-authoritative artifact로 취급하고 `Source Script → verification-model → Source Code`를 직접 권위 순서로 사용했다. 이는 PlusCal pseudocode를 Source Script 전체의 언어중립 실행 절차 번역 계층으로 정의하고 verification model을 그 pseudocode의 선택적 파생 검증 표현으로 정의한 상위 정책과 충돌한다.

## 변경 내용

- `agent_space/AGENT.md`: 기본 의미 계층을 Source Script → PlusCal pseudocode → Source Code로 정렬하고, verification-model/TLC를 선택적 중간 검증 단계로 분리한다.
- `development-versions.json`: pseudocode를 정식 `layers.pseudocode`로 복구하고 verification/source-code lineage에 pseudocode fingerprint를 추가한다.
- `scripts/check-development-layer-versions.py`: current pseudocode가 current/closed Source Script에서 파생되었는지, verification-model이 current pseudocode에서 파생되었는지, Source Code가 세 lineage를 모두 만족하는지 검사한다.
- `pseudocode/README.md`: r17 현재 상태와 Source Script 전체 번역 계층이라는 역할을 기록한다.
- `verification/README.md`: verification을 pseudocode의 선택적 bounded 검증 표현으로 설명하고 r11 current/TLC-passed 상태로 갱신한다.
- `agent_space/reviews/review-20261013-010-pseudocode-lineage-policy-alignment.md`: 현재 lineage 정렬 판정을 기록한다.

## fingerprint 범위

pseudocode 의미 fingerprint는 활성 `pseudocode/**/*.pcal`만 대상으로 한다.

```text
sha256:459b4ea5f5eefe9cda1e27b9241e4deb379df5c5ec9e2e82b0649751b8caf898
```

verification 의미 fingerprint는 `verification/**/*.tla`와 `verification/**/*.cfg`만 대상으로 한다.

```text
sha256:b4156896514d84f2b38b2d9346aaf93111249e927297ff3173485c702bd70a2b
```

README 같은 상태 문서 변경이 의미 revision/fingerprint를 바꾸지 않도록 분리한다.

## 변경하지 않은 의미 파일

다음 파일은 수정하지 않는다.

- `sourcescript/**/*.py`
- `pseudocode/**/*.pcal`
- `verification/**/*.tla`
- `verification/**/*.cfg`
- `Fast-figure.html`
- `fast-figure.js`
- `fast-figure-ui.js`
- `scripts/build-portable.py`

따라서 Source Script r17, pseudocode r3의 실제 번역, verification-model r11의 TLC 대상 의미, Source Code r13 application 동작은 변하지 않는다.

## 선택 이유

상위 정책을 현재 잘못된 메타데이터에 맞춰 수정하지 않고, 하위 계층 정의를 정책에 맞춘다. pseudocode 전체 번역과 verification coverage를 분리하면 두 책임을 혼동하지 않으면서 Source Code까지 직접 추적할 수 있다.

## 기각한 방향

- pseudocode를 archived/non-authoritative로 유지: 상위 정책과 충돌하므로 기각한다.
- verification-model을 전체 pseudocode 대체물로 사용: verification은 선택적 bounded 검증 표현이므로 기각한다.
- README를 의미 fingerprint에 포함: 상태 문서 수정만으로 의미 revision이 변하므로 기각한다.
- r17에서 의미가 변하지 않은 `.pcal` 주석까지 일괄 갱신: 불필요한 의미 파일 변경이므로 하지 않는다.

## 회귀 위험

checker의 lineage 조건이 강화된다. 앞으로 Source Script 변경 후 pseudocode를 갱신하지 않은 채 verification 또는 Source Code를 current로 표시하면 CI가 실패한다. 이는 의도한 정책 enforcement다.

## 검증과 후속

GitHub-hosted `Development layer versions` workflow를 통과한 뒤 GitHub-hosted `Build distribution`을 실행한다. self-hosted runner는 사용하지 않는다.

## rollback

이 패치의 계층 정의를 단독으로 이전 archived/non-authoritative 상태로 되돌리면 상위 정책과 다시 충돌한다. rollback이 필요하면 정책 정렬 전체를 함께 재검토해야 한다.
