# 20260908-002 — Correct image editor patch formatting

## 목적

`20260908-001`의 Mantine image editor 변경 의도를 그대로 적용하되, 잘못 작성된 unified diff hunk line count 때문에 `git apply --check`가 패치를 읽지 못한 문제를 교정한다.

`20260908-001` GitHub Actions run `34208092657`은 `Check and apply patch` 단계에서 다음 오류로 중단되었다.

```text
error: corrupt patch at agent_space/patches/20260908-001.patch:57
```

따라서 `001`의 application source 변경은 전혀 적용되지 않았고 JavaScript syntax/build/smoke 단계에도 도달하지 않았다.

## 원인

`001.patch`의 실제 hunk 내용과 header의 old/new line count가 일치하지 않았다.

- `fast-figure.js` 첫 hunk 실제 count: `33 -> 45`
- `001` header: `20 -> 33`
- `fast-figure-ui.js` import hunk 실제 count: `7 -> 19`
- `001` header: `7 -> 17`
- image editor 삽입 hunk 실제 count: `6 -> 84`
- `001` header: `6 -> 86`

첫 UI hunk의 순증가도 +10이 아니라 +12이므로 다음 hunk의 new-side 시작 위치 역시 함께 교정한다.

## 변경 내용

application 변경 의도와 코드 내용은 `20260908-001.md`와 동일하다.

- `fast-figure.js`: legacy DOM과 독립적인 `applyImageSettingsFromValues(values)` 최소 command 추출
- 기존 `applyImageSettings()`는 legacy form adapter로 유지
- `fast-figure-ui.js`: Mantine `Image`, `Select`, `NumberInput`을 사용하는 `FastFigureImageEditor` 추가
- image settings source of truth는 기존 `activeProject.images[*].settings`
- 기존 `syncSlotImageElement()`와 `IMAGE_SETTINGS_CHANGED` notification 유지
- 별도 React persistent state, bridge, EFSM, project schema 추가 없음

`002.patch`에서는 unified diff header를 실제 hunk 내용에 맞춰 다시 작성한다.

## 선택 이유

실패한 `001` 파일을 수정해 이력을 덮지 않는다. `AGENT.md`의 시간순 패치 기록 원칙에 따라 실패 원인과 교정을 별도의 패치 쌍으로 남긴다.

## 기각한 대안

### `20260908-001.patch` 직접 수정 후 다시 실행

기각. 이미 실패한 큐 커밋과 Actions 결과가 존재하므로 기록과 실제 실행 결과가 불일치하게 된다.

### application source를 직접 수정

기각. 모든 변경을 diff 패치로 기록한다는 저장소 규칙을 위반한다.

### image editor 구현을 다시 설계

기각. 이번 실패는 코드 설계나 기능 검증 결과가 아니라 patch parser 단계의 형식 오류다. `001`의 설계 판단은 아직 반증되지 않았다.

## Source of truth / EFSM 영향

`20260908-001.md`와 동일하며 추가 영향 없음.

## 검증

workflow 전체를 다시 통과해야 한다.

1. `git apply --check`
2. `git diff --check`
3. `node --check fast-figure.js`
4. `node --check fast-figure-ui.js`
5. portable build
6. split `file://` smoke
7. portable `file://` smoke

그 뒤 `001.md`에 기록한 image editor 수동 parity 항목을 기준으로 후속 검토한다.

## 롤백

`20260908-002.patch`를 역적용한다. `001`은 source에 적용되지 않았으므로 별도 application rollback 대상이 아니다.
