# 20260902-049 — React shell domain-renderer workspace host staging

## 목적

`plan-004`와 `plan-005`에 따라 Mantine shell cutover의 실제 blocker인 main workspace host를 준비한다. 구버전 UI 배치를 복제하는 것이 아니라, 기존 Plotly/slot/image/caption surface renderer가 계속 사용할 수 있는 DOM host contract만 React shell 안에 둔다.

## 변경 내용

- 앱 버전을 `1.1.89-alpha`로 올린다.
- `FastFigureWorkspaceStaging()`을 추가한다.
- workspace component는 기존 domain renderer가 사용하는 host ID/class를 유지한다.
  - `graphArea`
  - `dashboard`
  - `dashboardCaption`
  - `captionPrefix`
  - `captionText`
- `dashboard`의 기존 초기 grid CSS custom property를 유지한다.
- `captionText`의 contenteditable/role/placeholder contract를 유지한다.
- `FastFigureShellStaging()`의 placeholder main text를 `FastFigureWorkspaceStaging`으로 교체한다.
- component를 `window.FastFigureReactShell` export에 추가한다.

## 변경하지 않는 영역

- Plotly 코드와 bundled Plotly library를 읽거나 수정하지 않는다.
- `makeSlots`, graph/image renderer, dashboard geometry/export 계산을 수정하지 않는다.
- caption domain/EFSM 의미를 수정하지 않는다.
- legacy shell을 아직 숨기거나 제거하지 않는다.
- React shell을 아직 mount하지 않는다.

## 이유

초기 staging shell의 `<main>`은 `UI staging` 텍스트만 렌더했다. 이 상태에서 shell ownership을 전환하면 기존 domain renderer가 요구하는 `#dashboard` 등의 target이 사라진다.

`plan-005`에 따라 구버전 일반 UI 구조 자체를 보존할 필요는 없지만, Plotly/slot/image surface는 Mantine로 교체할 일반 UI가 아니라 유지해야 할 domain renderer다. 따라서 cutover 전에 renderer target만 React shell 내부에 명시적으로 준비한다.

## 고려했지만 선택하지 않은 방향

- **기존 `#graphArea` DOM을 React Portal로 재사용:** legacy/React ownership이 섞이므로 사용하지 않는다.
- **Plotly/slot surface를 React component로 재작성:** Mantine 전환 범위를 벗어나고 domain renderer를 불필요하게 변경하므로 사용하지 않는다.
- **legacy main을 그대로 유지한 채 toolbar/sidebar만 cutover:** 일반 UI shell ownership이 분리되므로 단일 shell 계획에 맞지 않는다.

## 회귀 위험

현재 shell은 비활성 staging이므로 사용자-visible 동작 변화는 없어야 한다. 실제 cutover에서는 script 초기화 시점에 legacy host ID를 참조하는 handler가 있으므로, legacy markup 제거 전에 React root mount 순서와 DOM-binding 초기화를 별도로 검토해야 한다.

## rollback

이 patch만 되돌리면 staging shell main이 이전 placeholder로 돌아간다. domain/file state에는 영향이 없다.
