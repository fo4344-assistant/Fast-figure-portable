# 20260911-009 — Complete remaining Mantine interaction surfaces

## Purpose

Finish the remaining Mantine-side interaction surfaces before further legacy UI removal. This patch implements Mantine-owned status/debug presentation, label preview dragging with geometry clamp, and layout preview geometry/resizing parity.

## Exact changes

### `fast-figure.js`
- Add a UI-independent telemetry snapshot/subscription channel for status text and debug output.
- Route the existing `status()` command through that telemetry channel while retaining its current DOM projection during WIP coexistence.
- Publish debug lines through the same channel.
- Add UI-independent `setDebugEnabled()`, `clearDebugOutput()`, and `saveDebugOutput()` commands for Mantine.
- Preserve existing debug logging semantics and maximum retained log length.

### `fast-figure-ui.js`
- Add `useUiTelemetry()` and a Mantine `FastFigureStatusDebug` surface.
- Show current status with `aria-live` semantics.
- Add Mantine controls for debug enable/disable, log save, clear, and visible log output.
- Add pointer drag support to the Mantine label preview.
- Convert pointer coordinates to the actual selected-slot reference geometry and clamp the label inside the available slot area.
- Commit drag completion through the existing labels notification path.
- Render the Mantine layout preview using `dashboardGeometry()` values for aspect, gap, outer margin, and radius instead of an arbitrary equal-size preview grid.
- Add a pointer resize handle for the layout preview; resizing only changes preview scale and does not alter project layout state.
- Mount/export the new status/debug component in the Mantine shell.

## Rationale

The remaining work should complete Mantine functionality before deleting legacy markup. Status/debug previously existed only as legacy DOM controls, while label and layout previews were present in Mantine but lacked important interaction/geometry parity. Implementing these directly against existing commands and geometry avoids preserving old UI as an API.

## Source of truth

- Status/debug presentation snapshot: UI telemetry channel in `fast-figure.js`.
- Debug behavior: existing `debugEnabled`, `debugSequence`, `debugLog`, and `auditApp` semantics.
- Label position: `activeProject.labelSettings`.
- Layout geometry: existing project layout model plus `dashboardGeometry()` / `gridSlotGeometry()`.
- UI state: `appFSM` plus transient React drag/preview state only.

## EFSM / core impact

No project-model or EFSM transition semantics change. The telemetry channel exposes transient UI information only and is not persisted. Label drag still modifies the existing label settings and emits the existing label notification. Layout preview resizing does not modify project data.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, CSV, image, parser, serializer, manifest, or package-version behavior changes.

## Rejected alternatives

- Read legacy `#status` / `#debugLog` DOM from React: rejected because it would keep legacy UI as a compatibility API.
- Add a separate React-owned persistent debug store: rejected because debug/status are transient presentation data and should have one runtime channel.
- Keep the simplified fixed Mantine layout grid: rejected because it did not preserve actual gap/margin/aspect geometry.
- Implement label dragging through the old preview DOM: rejected because Mantine must own the interaction directly.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert this patch's application commit. No stored project data or file format migration is involved.
