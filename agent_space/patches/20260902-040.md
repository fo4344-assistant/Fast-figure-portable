# 20260902-040 — legacy graph palette command 재사용

## 배경

`20260902-039`에서 graph object 전체에 색상 배열을 순환 적용하는 `setGraphObjectColorsFromPalette()` DOM-free command를 추가했다.

기존 reset/load handler는 동일한 `objects.map(... color: palette[index % length])` 계산을 각각 보유하고 있다.

## 목적

- legacy reset/load와 향후 Mantine palette UI가 동일 palette mutation command를 사용하도록 한다.
- legacy handler에는 파일 입력/상태 메시지/목록 렌더 책임만 남긴다.

## 변경 내용

- 앱 버전 `1.1.81-alpha` → `1.1.82-alpha`
- `resetGraphPalette` handler가 `setGraphObjectColorsFromPalette(DEFAULT_COLORS, chart.id)` 호출
- `loadGraphPaletteFile` handler가 기존 HEX 검증 후 `setGraphObjectColorsFromPalette(valid, chart.id)` 호출
- command 성공 후 `renderGraphObjects(ensureGraphObjects(editing))`으로 legacy 목록 갱신

## source of truth

색상 변경은 `039` command → `replaceGraphObjects()` → 기존 EFSM/action 경로에서만 수행된다. legacy handler는 object 배열을 직접 재작성하지 않는다.

## 유지하는 기존 동작

- reset은 `DEFAULT_COLORS`를 object 순서에 순환 적용
- load는 JSON array 또는 `{ colors: [...] }` 허용
- `#RRGGBB` 형식만 유효 색상으로 인정
- 파일 입력 초기화
- status/debug log
- legacy 목록 즉시 갱신

## 변경하지 않음

- `saveGraphPalette` 파일 저장
- palette 파일 포맷
- single-object color UI
- EFSM event/action
- Plotly trace/layout
- import/export

## 기각한 대안

### legacy map 로직을 유지

기각. 같은 palette 적용 의미가 command와 handler에 이중 구현된다.

### 파일 파싱까지 command로 이동

기각. 파일 I/O와 JSON 검증은 UI/import adapter 책임이고 graph domain mutation과 분리하는 편이 단순하다.

## 검증

- patch apply/check
- JavaScript syntax
- reset/load handler에서 object color map 직접 구현 제거
- command 성공 뒤 legacy renderer 호출
- Plotly bundle 미접촉

## rollback

- reset/load의 기존 `saveGraphObjects(...map...)` 코드 복원
- 앱 버전 `1.1.81-alpha` 복원

`039` command는 독립적으로 남길 수 있다.

## 후속

Mantine graph-object 영역에서 palette reset/load/save UI를 어느 수준까지 옮길지 현재 sidebar 구조와 공통 파일 picker 정책을 기준으로 검토한다.
