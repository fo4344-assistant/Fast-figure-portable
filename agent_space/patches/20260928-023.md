# 20260928-023

## 목적과 변경 내용

활성 Mantine 프로젝트 자산 트리와 데이터 가져오기를 하나의 ownership 단위로 정리한다. 트리 읽기, 이동 가능 여부, 휴지통의 내용과 참조 수, 이동 대상과 충돌 계획, 폴더 생성, 휴지통 비우기, 자산 선택·다운로드·슬롯 연결·드롭 가져오기, 데이터 패널 다중 가져오기가 프로젝트/EFSM core의 `FastFigureApi.assets`를 거친다. 파일 이름 충돌의 replace/rename 선택 Modal은 Mantine에 남고, 충돌 모델과 최종 경로 결정은 기존 core 함수에서 읽는다.

프로젝트 자산 트리 UI에는 펼침/접힘, 드래그 중인 경로, 이동·충돌 확인창, 입력 중인 새 폴더 이름 같은 컴포넌트 범위의 임시 상태만 남긴다. `PROJECT_DIRECTORY_CREATED`, `PROJECT_NODE_MOVED`, `PROJECT_TRASH_EMPTIED`, `SELECT_ASSET`, 슬롯 연결 이벤트와 기존 파일 가져오기 명령의 의미를 유지한다. 프로젝트 자산 모델이나 파일 schema는 변경하지 않는다.

## 선택 이유

이전 UI는 `projectVfs`와 `activeProject`를 직접 읽고 이동/삭제 정책 및 참조 관계를 계산했다. 해당 결정은 프로젝트 모델의 현재 상태에 따라야 하므로 core가 매 요청에서 SoT를 읽고, UI는 사용자 선택과 확인만 전달하도록 했다. 기존 command와 이벤트를 그대로 재사용하고 별도 공유 트리 저장소나 동기화 계층은 만들지 않는다.

## 고려했지만 선택하지 않은 방향

- **트리 전체를 React state에 복제하고 이동 시 갱신:** 파일 경로·참조 관계의 두 번째 SoT가 생기고 EFSM 변경과 동기화가 필요하다.
- **이동 충돌·휴지통 참조 계산만 UI에 유지:** 삭제 명령을 core로 옮긴 뒤에도 같은 자산 관계 정책을 UI가 소유하게 되어 경계가 일관되지 않다.
- **파일 가져오기만 얇은 Mantine adapter로 감싸고 기존 UI 분기를 유지:** 슬롯 유형, 충돌 계획, 자산 교체 결정이 UI에 남아 기능 command 추출을 미루게 된다.

## 범위와 후속 작업

트리의 확장 상태·Modal 선택·드래그 상태는 UI 범위에 남는다. 프로젝트 이름/FFPX, 이미지 편집, 슬롯 초기화 등 다른 UI 직접 접근과 전체 17항목 상호작용 회귀는 별도로 남는다. 그래프 native 입력 폼은 현재 HTML에 존재하지 않으므로 이 패치에서 삭제할 대상이 없다. 역적용하면 트리 이동·충돌·휴지통 정책과 가져오기 분기가 UI 파일로 돌아간다.
