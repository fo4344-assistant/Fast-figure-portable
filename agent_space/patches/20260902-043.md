# 20260902-043 — graph palette file boundary cleanup

## 목적

그래프 palette 파일 load/save에서 UI handler 내부에 중복된 파싱·다운로드 구현을 제거하고, Mantine 파일 UI가 재사용할 수 있는 최소 공통 경계를 만든다.

## 변경 범위

1. `parseGraphPaletteText(text)` 추가
   - JSON 문자열 파싱
   - 기존 지원 형식 유지: 최상위 배열 또는 `{ colors: [...] }`
   - 기존 HEX 검증 유지: `#RRGGBB`
   - 기존 오류 문구 유지
   - 유효 색상 배열만 반환
2. legacy `saveGraphPalette` handler의 직접 `Blob/<a>/URL.revokeObjectURL` 구현을 제거하고 이미 존재하는 `downloadJsonFile()`을 재사용
3. legacy `loadGraphPaletteFile` handler가 동일한 inline JSON/HEX 검증 대신 `parseGraphPaletteText()`를 사용
4. 버전 `1.1.83-alpha` → `1.1.84-alpha`

## 이유

`saveGraphPalette` 바로 뒤에 이미 일반 JSON 다운로드 helper인 `downloadJsonFile(payload, name)`이 존재하지만 palette save만 같은 기능을 별도로 구현하고 있었다. 같은 자유도와 출력 형식을 유지하면서 중복 코드를 줄일 수 있으므로 최소복잡도 원칙에 따라 공용 helper를 사용한다.

palette load의 지원 JSON 형식과 HEX 필터도 DOM/file-input handler 내부에 묶여 있어 Mantine `FileButton`에서 재사용하려면 동일 검증을 복제해야 한다. 파일 읽기 자체와 palette mutation은 UI/I/O 책임으로 남기고, 텍스트 → 색상 배열 변환만 순수 helper로 분리한다.

## source of truth

- palette 파일 형식: `parseGraphPaletteText()` 한 곳
- palette mutation: 기존 `setGraphObjectColorsFromPalette()`
- JSON 파일 다운로드: 기존 `downloadJsonFile()`
- canonical graph colors: `chart.editor.objects`

새 persistent state는 없다.

## EFSM / core 영향

없음. graph object mutation event나 chart schema를 변경하지 않는다. `parseGraphPaletteText()`는 순수 데이터 변환 helper다. Plotly renderer 및 trace 코드는 수정하지 않는다.

## 호환성

기존 동작을 그대로 유지한다.

- 저장 파일 구조: `{ "colors": [...] }`
- 파일명: `chart-palette-<ISO timestamp>.json`
- 불러오기: 배열 또는 `{ colors: [...] }`
- 유효 색상: 6자리 HEX 문자열만 적용
- 일부 잘못된 색상이 섞인 경우 기존처럼 유효 항목만 사용
- 유효 색상이 하나도 없으면 기존 오류 문구 유지

## 기각안

### load/save 전체를 바로 Mantine component 안으로 이동

기각. 파싱 규칙과 다운로드 방식이 먼저 공용 경계로 정리되지 않으면 legacy와 Mantine에 파일 규칙이 중복된다.

### 새로운 다운로드 helper 추가

기각. 기존 `downloadJsonFile()`이 동일 책임을 이미 수행한다.

### palette parser가 mutation까지 수행

기각. 파일 형식 검증과 graph-object mutation은 별도 책임이다.

## rollback

- `parseGraphPaletteText()` 제거
- legacy load handler의 기존 inline parser 복원
- save handler의 기존 Blob/download block 복원
- 버전 문자열 두 곳 복원

`039/040/042`에는 영향이 없다.
