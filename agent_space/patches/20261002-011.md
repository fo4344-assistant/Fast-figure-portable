# 20261002-011 — startup dashboard projection

## 목적과 변경 내용

`review-022-mantine-ui-regression-qa.md`의 2번 문제인
“HTML 최초 로드 시 오른쪽 작업 뷰어의 슬롯이 보이지 않음”을 수정한다.

변경:

- `fast-figure.js`
  - startup에서 `applySlotStyle()` 다음, `appFSM.ready()` 전에 `renderDashboard()` 호출
- `agent_space/tests/browser-regression.js`
  - regression target을 source code r5로 갱신
  - 사용자 상호작용 전 default 2×2 slot 4개가 DOM에 렌더되었는지 검사
- `development-versions.json`
  - source-code r4 → r5
  - fingerprint 갱신
  - validation review를 review-023으로 연결
- `agent_space/reviews/review-023-source-code-r5-startup-render.md`
  - r5의 Source Script 적합성과 회귀 범위를 기록

## 이 방향을 선택한 이유

초기 project는 이미 2×2 empty slot 4개를 생성한다. 문제는 모델 생성이 아니라
startup renderer projection 한 단계가 빠진 것이다.

`applyUiPalette()`가 `renderDashboard()`를 호출하기 때문에 palette 적용을 눌렀을 때
우연히 slot이 나타났지만, appearance 변경이 초기 renderer 생성의 전제 조건이 되어서는 안 된다.

따라서 새 상태나 별도 초기화 flag를 만들지 않고 기존 `renderDashboard()`를 startup에서
한 번 호출하는 것이 최소 복잡도이며 Source Script r12와 일치한다.

## 고려했지만 선택하지 않은 다른 방향

### `applyUiPalette()`를 startup에서 호출

appearance projection과 dashboard initialization을 다시 결합한다.
palette 적용이 renderer 생성의 숨은 side effect가 되는 현재 문제를 유지하므로 선택하지 않았다.

### `createProjectState()`에서 DOM을 생성

project model 생성 함수가 renderer side effect를 소유하게 되어 model/renderer 경계가 깨진다.

### `appFSM.ready()` 이후 비동기 render 예약

ready가 “초기 projection 완료”보다 먼저 관찰될 수 있다. Source Script의 initialize 순서와
회귀 검사 목적에 맞지 않아 선택하지 않았다.

## Source Script / verification 판정

- Source Script r12 변경 없음

- TLC 상태 변경 없음

2. 사용자 command 실행 전에 project slot count가 4다.
3. 같은 시점에 visible dashboard slot DOM count가 4다.

CI의 development-layer version 검사와 browser regression을 통과해야 완료로 본다.
