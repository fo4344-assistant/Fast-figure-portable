# 20260906-032

## 목적

파일 가져오기 시 동일 경로 충돌을 처리하는 replace/rename 선택 의미를 보존하면서, 현재 `planProjectAssetImport()` 안에 직접 섞여 있는 `window.confirm`/`window.alert`를 Mantine choice dialog가 재사용할 수 있는 read model과 resolver 경계로 분리합니다.

이번 패치는 UI를 제거하지 않습니다. 기존 legacy 경로는 동일한 browser dialog를 adapter로 계속 사용하며, 다음 패치에서 Mantine 경로가 같은 descriptor를 사용하도록 준비합니다.

## 변경 내용

- 파일 충돌을 분석하는 `projectAssetImportCollisionModel()`을 추가합니다.
  - 충돌 없음
  - 같은 종류의 교체 가능한 자산 충돌: `replace-or-rename`
  - 기본 빈 CSV 또는 다른 종류 자산 충돌: `rename-only`
  - 같은 batch에서 예약된 경로 충돌: 자동 unique rename
  을 구분합니다.
- 충돌 model과 사용자 선택을 실제 `{ path, replaceId }`로 바꾸는 `resolveProjectAssetImportPlan()`을 추가합니다.
- 기존 `planProjectAssetImport()`은 legacy UI adapter가 됩니다.
  - `replace-or-rename`: 기존 confirm 문구와 확인/취소 의미 유지
  - `rename-only`: 기존 alert 문구 유지
  - 이후 공통 resolver를 호출
- 앱 빌드를 `1.1.136-alpha`로 올립니다.

## 기능 보존

- 같은 종류의 기존 CSV/이미지와 충돌할 때:
  - 확인 = 기존 파일 교체 + 기존 참조 유지
  - 취소 = unique 이름으로 새 파일 추가
  를 그대로 유지합니다.
- 기본 빈 CSV는 교체할 수 없고 unique 이름으로 추가합니다.
- 다른 종류 자산과 같은 경로가 충돌하면 교체하지 않고 unique 이름으로 추가합니다.
- 한 번의 다중 import 안에서 이미 예약된 경로와 충돌하면 기존과 같이 unique 이름을 발급합니다.
- `projectVfs.uniquePath()`를 계속 단일 이름 충돌 해결 규칙으로 사용합니다.
- CSV/image loader, slot 연결, 참조 유지, FFPX/FFSX semantics는 변경하지 않습니다.

## 선택 이유

Mantine choice dialog는 `window.confirm`의 boolean 결과보다 풍부한 UI를 사용할 수 있지만, replace/rename 결정 자체는 UI 구현과 분리되어야 합니다. 충돌 상황을 descriptor로 읽고 선택을 resolver에 전달하면 legacy dialog와 Mantine dialog가 같은 domain 판단을 공유할 수 있습니다.

또한 다중 file import와 drag/drop은 비동기 입력 수명을 포함하므로, collision 분석과 실제 Modal orchestration을 한 패치에 섞지 않고 먼저 안정적인 command/read-model 경계를 만드는 편이 rollback과 회귀 검증에 유리합니다.

## 고려했지만 선택하지 않은 방향

### 충돌 시 항상 rename

기존의 참조 유지 교체 기능을 삭제하므로 기각했습니다.

### 충돌 시 항상 replace

기존의 새 파일로 추가하는 선택 자유도를 삭제하므로 기각했습니다.

### 기본 CSV나 다른 종류 충돌에서 import 자체를 실패시킴

현재 unique 이름으로 정상 import하는 기능을 축소하므로 기각했습니다.

### 즉시 `planProjectAssetImport()`를 async Modal 함수로 변경

두 loader와 다중 drag import를 동시에 async orchestration으로 바꾸게 되어 변경 범위가 불필요하게 커집니다. 먼저 descriptor/resolver를 분리하고 다음 패치에서 Mantine UI를 연결합니다.

## 위험 요소

- `reservedPaths`는 실제 VFS 충돌과 달리 batch 내부 예약이므로 replace 대상으로 취급하면 안 됩니다. 기존처럼 unique rename만 허용합니다.
- replace choice는 현재 VFS에서 같은 종류이고 기본 빈 CSV가 아닌 collision에만 유효합니다.
- resolver는 기존 `projectVfs.uniquePath()`를 사용하여 이름 발급 규칙을 중복 구현하지 않습니다.

## 후속 작업

Mantine 파일 선택 및 asset-tree 외부 파일 drop 경로에서 이 collision model을 읽어 공통 choice/notice Modal로 연결합니다. 다중 파일 import에서는 각 충돌 결정을 순차 처리하되 File 객체 자체를 장기 UI source of truth로 만들지 않는 구조를 사용합니다.
