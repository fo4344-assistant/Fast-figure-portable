# 20260907-049 — Mantine project trash confirmation

## Purpose

Replace the PROJECT DATA trash-emptying confirmation path with Mantine UI while preserving the existing project VFS, project model, and functional EFSM event.

The Mantine path must not call the legacy `emptyProjectTrash()` handler because that handler owns a native `window.confirm()` presentation. Instead, Mantine presents the confirmation and dispatches the already-existing `PROJECT_TRASH_EMPTIED` event directly.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- `emptyProjectTrash()`
- `ApplicationStateMachine`
- `APP_STATE_DEFINITIONS`
- project classes/models
- VFS mutation rules
- FFPX/FFSX data formats

## Existing functional path reused

The existing event remains the sole mutation path:

- `PROJECT_TRASH_EMPTIED`

The event payload is the same UI-to-FSM direction used by the legacy handler. The existing event continues to determine removed directory/CSV/image counts and remove affected references.

## Exact changes

1. Adds presentation-local state for a Mantine trash confirmation dialog inside `FastFigureProjectDataTree`.
2. Detects whether `/assets/trash` is the currently selected directory.
3. Detects whether the trash contains any nested directory, CSV, or image.
4. Adds a `휴지통 비우기` Mantine button only while `/assets/trash` is selected.
5. The button is disabled while lifecycle state is busy or the trash is empty.
6. Before opening the dialog, the UI computes the number of remaining references to trashed CSV/image assets using the existing `projectAssetReferenceCount()` helper.
7. The Mantine dialog warns when references will also be removed.
8. Confirming sends `PROJECT_TRASH_EMPTIED` with `direction: "ui-to-fsm"`, updates legacy availability projection for parity, and reports the counts returned through the existing event payload.
9. Cancel/close performs no model mutation.
10. No legacy button click and no native `window.confirm()` are used by the Mantine path.

## State ownership

The dialog stores only temporary presentation data (`opened` and reference count). Persistent directory, CSV, image, slot, and chart state remains owned by the existing project model and functional EFSM.

## Why this direction

The project trash mutation is already represented by an EFSM event. Reusing the old handler would preserve a native browser confirmation and make legacy UI presentation part of the Mantine implementation. Reimplementing deletion logic in React would duplicate the functional path. A Mantine confirmation that dispatches the existing event is the narrowest implementation consistent with the target architecture.

## Rejected alternatives

### Calling `emptyProjectTrash()` from Mantine

Rejected because it invokes native `window.confirm()`.

### Adding a new Mantine-specific trash event

Rejected because `PROJECT_TRASH_EMPTIED` already represents the required mutation.

### Duplicating VFS deletion/reference cleanup in React

Rejected because those responsibilities already belong to the model/EFSM.

### Modifying the legacy handler in this patch

Rejected because this migration step only replaces presentation and should not alter the working legacy path before cutover.

## Rollback

Revert `20260907-049.patch`. No project data migration or EFSM rollback is required.
