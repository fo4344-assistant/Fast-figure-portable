# 20261013-034 — Verification model r12 for interaction repairs

## 목적과 변경 내용

PlusCal pseudocode r4에서 상태 기반 검증이 필요한 의미만 verification model에 반영한다.

- `FastFigureInteractionCore`
  - trash membership과 tree recovery move 허용을 분리.
  - entering-trash reference detach.
  - leaving-trash가 detached reference를 자동 복원하지 않음.
  - trash asset의 direct slot connection 거부.
  - fixed trash root move 거부.
- `FastFigureSlotCore`
  - selectedSlotId를 검증 상태에 포함.
  - successful slot swap에서 selected payload identity가 source/target을 따라 이동.
- cfg에 새 invariant를 연결.
- verification-model revision을 r12/current로 올리고 TLC 상태는 `pending`으로 둔다.

## 선택 이유

실제 shared/authoritative state와 reference 관계를 바꾸는 의미만 TLC 대상에 포함했다. settings overlay height와 Layout preview geometry는 project state를 변경하지 않는 UI-local projection이므로 verification state에서 제외하고 browser regression에서 검증한다.

## 고려했지만 선택하지 않은 방향

- Mantine Tree DOM/drag event를 TLC 모델에 포함: browser implementation detail이며 상태 invariant와 직접 관계가 없어 기각.
- overlay height/pointer capture를 shared state로 모델링: component-local interaction을 불필요하게 authority처럼 만들므로 기각.
- preview pixel geometry를 TLC에서 탐색: 순수 projection이며 browser regression이 더 직접적인 검증이므로 기각.
- slot swap 검증을 InteractionCore에 중복 구현: SlotCore가 이미 slot-local payload mutation을 소유하므로 selectedSlotId만 그 모델에 추가했다.

## 추상화와 한계

InteractionCore의 asset은 하나의 대표 CSV/image-like resource로 축약한다. 이 모델은 asset byte/type 세부나 directory descendant 전체를 검증하지 않고, 이번 변경에서 중요한 location/reference/connection precondition만 검사한다.

SlotCore는 기존 bounded grid/slot set을 유지한다. TLC 결과는 이 유한 범위에서 invariant 반례를 찾는 검증이며 무한 상태공간의 일반 증명이 아니다.

## 후속

push 후 GitHub-hosted `TLA Slot Core` workflow를 실행해 translation/parse/TLC 결과를 확인한다. 성공하기 전까지 `tlc`는 pending이고 source-code는 stale 상태를 유지한다.
