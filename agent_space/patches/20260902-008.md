# 20260902-008 — Mantine graph 축 상세 staging

## 목적

`20260902-005`와 `20260902-007`에서 마련한 graph layout read/write 경계를 사용해 네 축의 상세 설정 UI를 inactive Mantine sidebar에 추가한다.

축마다 동일한 JSX와 callback을 네 벌 만들지 않고 `FastFigureGraphAxisStaging({ chartLayout, axisKey, label })` 하나가 다음 축을 공통 처리한다.

- `xBottom` — 아래 X축
- `xTop` — 위 X축
- `yLeft` — 왼쪽 Y축
- `yRight` — 오른쪽 Y축

## 변경 내용

앱 버전은 `1.1.58-alpha`에서 `1.1.59-alpha`로 올린다.

각 축에서 Mantine으로 옮기는 기존 기능:

- 축 이름
- 최소/최대
- tick mode / tick 간격
- 로그축 minor tick
- 숫자 표기 방식
- 축 유형
- 값 나누기
- 축 이름 크기
- 숫자 크기
- 축선 굵기
- 격자 표시
- 축 표시
- 값 표시

네 축은 Mantine `Accordion`으로 묶는다. `Accordion`은 표시/접기 lifecycle만 담당하며 축 상태를 소유하지 않는다.

## 기존 축 규칙 보존

### tick mode

legacy `syncAxisTickModeControl()`의 의미를 그대로 유지한다.

비로그축:

- `plotly` ↔ `increment` 토글
- tick 입력 표시
- 버튼 표시는 현재 mode에 따라 `tick 간격` 또는 `increment`

로그축:

- `tickMode`는 `plotly`로 강제
- tick 입력은 표시하지 않음
- 같은 버튼은 `minorTicks`를 토글
- 버튼 표시는 `minor tick 표시` / `minor tick 해제`

### scale type

기존 선택지와 값을 그대로 사용한다.

- `linear` — 선형
- `log` — 로그
- `reciprocal` — 역수

`log`로 전환할 때만 기존 DOM sync와 동일하게 `tickMode: "plotly"`를 함께 commit한다. `minorTicks` 값 자체는 보존한다.

### notation

기존 선택지를 그대로 사용한다.

- `none` — 숫자
- `power` — 지수
- `e` — 과학 표기

## commit timing

legacy axis input/select는 native `change`에서 적용되고, 숫자/텍스트 input은 Enter 시 blur되어 한 번 적용된다. toggle/tick-mode 버튼은 클릭 즉시 적용된다.

Mantine staging도 같은 의미를 유지한다.

- `TextInput`, `NumberInput`: `defaultValue`를 사용하고 blur에서 commit
- Enter: preventDefault 후 blur하여 동일 commit 경로 사용
- `Select`, `Switch`, tick-mode `Button`: 변경 즉시 commit

React `useState`에 axis settings를 복제하지 않는다. focus 중 입력값만 component 내부 draft다.

## source of truth

축 설정의 유일한 persisted source는 selected chart의 `editor.globalSettings.axes`다.

`FastFigureGraphAxisStaging`은 `readChartLayout()` snapshot의 해당 `axisKey`를 읽을 뿐이다. 모든 쓰기는 다음 하나의 경로로 보낸다.

```text
FastFigureGraphAxisStaging
→ fastFigureUiBridge.applyChartLayout({ axes: { [axisKey]: changes } }, chartId)
→ applyGraphLayoutSettings(...)
→ CHART_LAYOUT_CHANGED
→ 기존 Plotly render 경로
```

snapshot, Accordion open state, input draft는 source of truth가 아니다.

## stale callback

`20260902-007`에서 추가한 `chartId` guard를 그대로 사용한다.

focus 중 selected chart가 바뀐 뒤 이전 input의 blur가 늦게 발생해도 이전 snapshot의 `chartId`와 현재 chart가 다르면 쓰기를 거부한다.

## Mantine/Core 분류

이 패치는 UI staging만 추가한다.

변경하지 않는다.

- graph/domain 데이터 구조
- `CHART_LAYOUT_CHANGED` event/action/guard
- `readGlobalSettings()` / global settings normalization 의미
- Plotly renderer
- 축 계산 및 표시 알고리즘
- graph object EFSM
- import/export
- 현재 활성 legacy UI

로그축의 tick-mode 규칙도 새 규칙이 아니라 기존 DOM UI가 갖고 있던 동작을 Mantine presentation에 동일하게 매핑한 것이다.

## 최소복잡도

축 네 개에 독립 component를 만들거나 callback을 복사하지 않는다.

공통 요소:

- `commit(changes)`
- blur commit
- Enter → blur
- NumberInput 생성
- notation/scale 선택
- tick mode 처리
- visibility switches

를 하나의 함수가 `axisKey`에 따라 처리한다.

이 wrapper는 Mantine 위에 새 UI framework를 만드는 wrapper가 아니다. Fast Figure 고유의 반복되는 **axis domain 의미와 event mapping**을 한 번만 정의하는 component이므로 `plan-004`의 허용 범위에 해당한다.

## 선택하지 않은 방향

### 축마다 JSX 네 벌 작성

같은 규칙과 callback이 네 군데 생기므로 선택하지 않는다.

### axis settings 전체를 React state에 복제

project/domain settings와 React가 같은 지속 의미를 동시에 소유하게 되므로 선택하지 않는다.

### 로그축에서도 tick 값을 편집 가능하게 유지

기존 UI가 log scale에서 tick input을 hidden/disabled하므로 동작 변경이 된다. 선택하지 않는다.

### Mantine 전환과 함께 축 계산 규칙 정리

Plotly/domain 계산은 이번 UI 전환의 변경 사유가 아니다. 별도 결함이 확인되지 않았으므로 건드리지 않는다.

## 회귀 위험

낮음~중간. staging은 inactive이지만 기존 축 UI의 세부 상호작용을 모두 표현한다.

확인 항목:

- 네 axis key가 기존과 정확히 일치
- notation/scale option 값 일치
- log 전환 시 `tickMode=plotly`
- log 상태에서는 tick NumberInput 미표시
- log tick button은 `minorTicks`만 토글
- non-log tick button은 `plotly/increment` 토글
- `showGrid`, `visible`, `showValues` boolean 보존
- `lineWidth` 최소값 0 유지
- min/max/divide/titleSize/fontSize 값에 새 제약을 추가하지 않음
- selected chart 변경 뒤 stale blur 차단
- 기존 legacy axis event binding과 Plotly 경로에 변경 없음

## rollback

1. `FastFigureGraphAxisStaging` 제거
2. sidebar의 `Accordion` destructuring 제거
3. `그래프 축 설정` Accordion block 제거
4. 앱 버전 복원

`20260902-005`와 `007`의 graph layout bridge/global staging은 독립적으로 유지할 수 있다.

## 후속

축 staging까지 성공하면 아직 남은 graph trace/object form의 `configFromForm()` 결합을 조사한다. 이 영역은 graph object 생성/편집과 EFSM에 직접 닿으므로, 기존 command/action을 확인한 뒤 values boundary와 UI staging을 별도 단계로 진행한다.
