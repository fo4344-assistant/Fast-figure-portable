# 20260902-019 — graph object 목록 순수 read model

## 목적

Mantine graph object 목록을 이관하기 전에 현재 chart의 object 목록을 legacy `#graphObjects` DOM이나 `renderGraphObjects()` 결과가 아니라 canonical chart model에서 직접 읽는 순수 read 경계를 추가한다.

이번 패치는 목록 action(selection/reorder/color/delete/add)을 변경하지 않는다. 먼저 목록 표시용 snapshot만 분리한다.

## 변경 내용

- 앱 버전 `1.1.66-alpha` → `1.1.67-alpha`
- `selectedGraphObjectsModel(slot = getSelectedSlot())` 추가
- `fastFigureUiBridge.readGraphObjects()` 추가
- 반환 snapshot:
  - `slotId`
  - `chartId`
  - `editable`
  - `selectedObjectIndex`
  - `objects[]`
- 각 object 항목에는 presentation에 필요한 파생값만 포함
  - `index`
  - `selected`
  - `csvId`
  - `csvName`
  - `x`, `y`
  - `xAxisSide`, `yAxisSide`
  - `legendName`
  - `type`
  - `color`
  - `label`

## read 순수성

`ensureGraphObjects()`를 호출하지 않는다.

구형 기준본의 `ensureGraphObjects()`는:

- `chart.editor` 생성
- `chart.editor.objects` 배열 생성
- 각 object를 base/default와 병합
- csvId/x/y 보정
- 결과를 다시 `chart.editor.objects`에 대입

하는 mutation 함수다.

따라서 목록 selector에서는:

```text
Array.isArray(chart.editor.objects)
→ 현재 배열을 직접 읽음
→ 각 object에서 display snapshot 계산
```

만 수행한다.

## label 파생 규칙

기존 `renderGraphObjects()`의 표시 의미를 보존한다.

```text
{순번}. {legendName 또는 "x · y"} · {CSV 이름 또는 "CSV 없음"} · {아래/위} X / {왼쪽/오른쪽} Y
```

label은 persisted state가 아니라 presentation 파생값이다.

## color 파생 규칙

기존 renderer와 같이 object.color가 문자열이면 사용하고, 아니면 `DEFAULT_COLORS[index % DEFAULT_COLORS.length]`를 fallback으로 사용한다.

이번 selector는 color를 object에 대입하지 않는다.

## selected index

`selectedObjectIndex`는 기존 graphObject selection state를 반영하기 위한 snapshot 값이다.

selector가 index를 보정하거나 `SELECT_GRAPH_OBJECT`/`CLEAR_GRAPH_OBJECT`를 보내지 않는다.

## source of truth

- object 목록: `chart.editor.objects`
- 선택: 기존 graphObject EFSM / `selectedObjectIndex`
- CSV 이름: `object.csvId`로 조회한 project CSV
- label/color: 위 canonical 값에서 계산한 read-only presentation 값

React 또는 bridge에 별도 목록 상태를 저장하지 않는다.

## Mantine/Core 분류

DOM-free presentation selector 추가다.

변경하지 않는다.

- `selectGraphObject()`
- `saveGraphObjects()`
- `renderGraphObjects()`
- `GRAPH_OBJECTS_REPLACED`
- `SELECT_GRAPH_OBJECT` / `CLEAR_GRAPH_OBJECT`
- drag reorder
- color/delete/add handler
- activeCsvId / activeDataName
- trace/Plotly renderer

## 선택하지 않은 방향

### `ensureGraphObjects(editing)`을 읽기 전에 호출

선택하지 않았다. selector 호출만으로 domain state를 보정하는 read-side mutation이 생긴다.

### legacy `.graph-object` DOM을 clone/parse

선택하지 않았다. Mantine 목록이 legacy renderer에 종속된다.

### 목록 action까지 이번 patch에서 같이 분리

선택하지 않았다. 특히 selection은 구형 기준에서 EFSM 선택 외에 active CSV와 legacy form 갱신까지 결합되어 있으므로 의미를 먼저 분리해 확인해야 한다.

### fallback color를 object에 저장

선택하지 않았다. display fallback만 계산한다.

## 회귀 위험

낮음. 새 selector와 bridge read method만 추가하며 기존 호출자는 변경하지 않는다.

검증 항목:

- graph slot에서 object 목록 snapshot 반환
- image/빈 slot에서는 null
- object 없는 chart에서는 빈 frozen array 반환
- selected flag가 `selectedObjectIndex`와 일치
- CSV 이름이 object.csvId 기준
- selector 호출 전후 chart.editor.objects 불변
- snapshot 수정이 원본 object에 영향 없음
- 기존 selection/save/render 함수 diff 없음

## rollback

1. `readGraphObjects()` bridge method 제거
2. `selectedGraphObjectsModel()` 제거
3. 앱 버전 `1.1.66-alpha` 복원

`012`~`018` graph object form staging은 독립 유지 가능하다.

## 후속 작업

다음에는 목록 action을 기능별로 분리해 현재 main의 의미를 확인한다.

1. selection toggle
2. color update
3. delete
4. reorder
5. add

selection은 `selectGraphObject()`가 active CSV/legacy form까지 갱신하는 결합을 갖고 있으므로, 단순히 React에서 `appFSM.send("SELECT_GRAPH_OBJECT")`를 직접 호출하지 않고 기존 기능 의미 중 domain과 legacy renderer 책임을 분리한 뒤 공통 command를 만든다.
