# 20260901-005 — Mantine shell sidebar/overlay staging

## 목적

`plan-003.md` Commit B를 이어서 수행해, 아직 활성화하지 않은 React/Mantine shell 안에 Sidebar와 OverlayHost 구조를 준비합니다. `20260901-004`에서 준비한 Toolbar/Shell staging을 확장하되 사용자에게 보이는 legacy UI ownership은 유지합니다.

## 변경 내용

- 애플리케이션 버전을 `1.1.35-alpha`로 갱신합니다.
- `FastFigureSidebarStaging`을 추가합니다.
  - `fastFigureUiBridge` snapshot에서 project/workspace/selected slot/asset selection을 읽습니다.
  - 별도 React domain state를 만들지 않습니다.
  - 아직 실제 form control을 복제하거나 legacy sidebar와 연결하지 않습니다.
- `FastFigureOverlayModalStaging`을 추가합니다.
  - Mantine `Modal`을 사용합니다.
  - `opened`는 호출자가 EFSM overlay snapshot에서 계산합니다.
  - `onClose`는 기존 `CLOSE_OVERLAY` event를 보냅니다.
  - popup 위치, Escape, outside-click lifecycle을 별도로 구현하지 않습니다.
- `FastFigureOverlayHostStaging`을 추가합니다.
  - Layout / Label / Caption / Print / README overlay를 controlled Modal 구조로 준비합니다.
  - 현재 domain snapshot은 staging 검증을 위해 읽기 전용으로 표시합니다.
- `FastFigureShellStaging`에 sidebar/main/overlay host의 최상위 배치를 추가합니다.
- `window.FastFigureReactShell` export에 새 staging component를 추가합니다.

## 이 방향을 선택한 이유

`plan-003`은 cutover 전에 하나의 React root가 소유할 shell 전체를 비활성 상태로 준비하고, toolbar/sidebar/modal을 부분적으로 활성화하지 않도록 정합니다. `20260901-004`에서 toolbar만 staging된 상태이므로 다음 단계는 shell 활성화가 아니라 sidebar와 overlay host의 component 경계를 먼저 완성하는 것입니다.

Modal open state를 React local state로 복제하지 않고 기존 overlay region을 그대로 사용합니다. 이 구조는 cutover 시 기존 `setOverlayDomState()`와 popup lifecycle을 제거할 수 있게 하면서 EFSM event/action 의미는 유지합니다.

## 고려했지만 선택하지 않은 방향

- **Toolbar만 즉시 mount:** legacy sidebar/overlay와 동시에 두 UI 체계가 interactive해져 `plan-003`의 단일 ownership 원칙을 위반하므로 선택하지 않습니다.
- **Sidebar form을 이번 패치에서 전부 구현:** 현재 bridge snapshot에는 graph/image/form의 모든 편집 payload 계약이 아직 준비되지 않았습니다. DOM `.value`를 다시 읽는 임시 adapter를 만들면 Mantine 전환 목적과 충돌하므로 component boundary를 먼저 준비합니다.
- **각 Modal이 개별 `useSyncExternalStore` 구독:** 하나의 OverlayHost 구독으로 충분하므로 중복 listener를 만들지 않습니다.
- **별도 popup wrapper/lifecycle:** Mantine `Modal`이 제공하는 동작을 다시 구현하지 않습니다.
- **React Portal로 legacy panel 위치에 삽입:** migration 중 UI ownership을 혼합하므로 사용하지 않습니다.

## 검증 및 회귀 위험

- 이 staging tree는 현재 React root에 mount하지 않으므로 사용자 UI 동작은 바뀌지 않아야 합니다.
- Toolbar/Sidebar/OverlayHost는 모두 기존 `fastFigureUiBridge`를 사용하고 새 global state owner를 추가하지 않습니다.
- Modal close는 `CLOSE_OVERLAY`, toolbar open/toggle은 기존 `TOGGLE_OVERLAY` 경로를 유지합니다.
- domain renderer, Plotly/dashboard, layout map, label preview는 변경하지 않습니다.
- patch 적용 후 GitHub Actions의 `git apply --check`, `git diff --check`, main JavaScript `node --check` 결과를 확인합니다.

## 후속 작업

Commit B에서 아직 남은 핵심은 실제 sidebar form/asset menu와 각 overlay form의 DOM-free values/payload 계약입니다. 이 계약을 staging component에 연결한 뒤에만 Commit C 단일 cutover를 수행합니다.

## 패치에 포함되지 않은 변경사항

`20260901-005.patch`와 이 설명 파일 자체는 patch 본문에 포함하지 않습니다. 실제 `Fast-figure.html` 적용은 기존 `.github/workflows/apply-fast-figure-patch.yml`의 단발성 patch 적용 경로를 사용합니다.
