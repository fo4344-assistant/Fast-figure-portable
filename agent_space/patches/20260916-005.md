# 20260916-005 — Remove dead native graph editor projection

## Purpose
Begin the graph compatibility DOM cutover after annotation and print/export cleanup by removing the obsolete `editChart` function, which only projects chart/project state into the deleted/native graph editor controls and has no remaining caller.

## Exact changes
Remove `editChart(id)` from `fast-figure.js`.

The removed function previously:
- selected the chart CSV and copied runtime selection values;
- wrote CSV/header state into native controls;
- projected graph-object fields into native `xCol`, `yCol`, axis-side, chart-type, legend, line, marker, and bar controls;
- projected global legend/title/zero-line, graph font, title/legend font size, and per-axis values into native controls;
- rendered the legacy native graph-object list;
- synchronized native type-specific visibility and editable-state controls.

Preserve `activateChartModel(id)`, which is the live workspace/model activation path and updates runtime/model-facing selection state without projecting the graph editor into native DOM.

Also preserve all `graphEditor*` command functions used by the active Mantine editor, Plotly/dashboard rendering, graph model validation, import/export, FFSX/FFPX behavior, axis state, and palette behavior.

## Why this direction
A full-source reference check found `editChart` only at its definition/debug strings; there is no executable caller. The active Mantine graph editor reads project/chart state directly and uses `graphEditorSelectCsv`, `graphEditorObjectValues`, `graphEditorAdd`, `graphEditorMove`, `graphEditorDelete`, `graphEditorHeaderLines`, `graphEditorSetEditable`, and direct `CHART_LAYOUT_CHANGED` events. Workspace entry uses `activateChartModel`.

`editChart` therefore represents a dead state-to-native-DOM projection path. Removing this single function first is a low-risk ownership cutover step and avoids prematurely deleting legacy helper functions that still have internal callers elsewhere.

## Rejected alternatives
- Remove all legacy graph form/render helpers in the same patch: rejected because functions such as `renderGraphObjects`, `applyGraphSettings`, and `applyGraphLayoutSettings` still have call chains that must be audited separately before deletion.
- Merge `editChart` into `activateChartModel`: rejected because the native DOM projection is precisely the obsolete behavior being removed; `activateChartModel` already has the correct narrower responsibility.
- Redirect Mantine through `editChart`: rejected because that would recreate a legacy DOM bridge and violate the direct command/model ownership policy.
- Modify graph model/Plotly behavior while deleting the projection: rejected as unrelated and higher risk.

## Source of truth
No source-of-truth change. Existing chart/project objects and appFSM remain authoritative. Mantine reads and changes graph editor state through the direct graph command/event paths. `activateChartModel` remains the runtime activation command.

## EFSM/core impact
None intended. No UI-FSM/EFSM event, chart state transition, graph-object semantics, Plotly layout/traces, project schema, persistence, FFSX/FFPX, Plotly JSON import/export, or renderer behavior is changed.
