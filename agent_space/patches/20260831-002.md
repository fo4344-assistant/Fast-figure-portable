# 20260831-002

## 목적

패치 기록 파일 이름에서 변경 내용 자체를 제거하고, 시간적 식별에 필요한 메타정보만 사용하도록 명명 규칙을 수정한다.

## 변경 내용

- 기존 `agent-space-layout.patch` / `agent-space-layout.md`를 `20260831-001.patch` / `20260831-001.md`로 변경했다.
- `AGENT.md`에 `YYYYMMDD-NNN` 형식의 패치 이름 규칙을 추가했다.
- `patches.md`에도 같은 규칙과 예시를 기록했다.
- 파일 이름에는 변경 내용, 기능명, 모듈명, 구현 방식 같은 의미 정보를 넣지 않도록 명시했다.
- 실제 패치의 내용은 동명 `.md` 파일에서 확인하도록 역할을 분리했다.

## 이 방향을 선택한 이유

패치 파일 이름은 정렬과 식별을 위한 안정적인 메타정보만 담당하고, 변경 의미는 설명 문서가 담당하도록 책임을 분리하기 위해서다.

`YYYYMMDD-NNN` 형식은 다음 정보를 이름만으로 확인할 수 있다.

- 언제 기록된 패치인지
- 같은 날짜의 몇 번째 패치인지
- 시간순 정렬 순서

반면 변경 내용은 이후 수정이나 범위 확장에 따라 이름과 실제 내용이 어긋날 수 있으므로 파일 이름에 넣지 않는다.

## 선택하지 않은 방향

- 기능명이나 변경 요약을 파일 이름에 넣는 방식은 선택하지 않았다. 이름만으로 내용을 추측하게 만들고, 실제 변경 범위가 달라질 때 이름이 부정확해질 수 있기 때문이다.
- 앱 버전만으로 패치를 구분하는 방식은 선택하지 않았다. 애플리케이션 버전과 무관한 문서·에이전트 작업도 존재하고, 같은 버전에서 여러 패치가 발생할 수 있기 때문이다.
- Git commit SHA를 파일 이름에 사용하는 방식은 선택하지 않았다. 패치 문서가 commit보다 먼저 만들어질 수 있고 사람이 시간순으로 읽거나 생성하기에도 불편하다.
- 전체 저장소에서 하나의 누적 숫자만 사용하는 방식은 선택하지 않았다. 날짜 정보가 없어 기록 시점을 이름만으로 확인할 수 없기 때문이다.

## 패치에 포함되지 않은 변경사항

`20260831-002.patch`와 이 설명 파일 자체의 생성은 자기 자신을 재귀적으로 포함할 수 없으므로 패치 본문에 포함하지 않았다.

GitHub Contents API는 파일 rename을 단일 조작으로 제공하지 않아 실제 저장소에서는 새 이름의 파일 생성 후 기존 파일 삭제로 수행되었다. `20260831-002.patch`에서는 이 논리적 변경을 Git rename diff 형태로 기록했다.
