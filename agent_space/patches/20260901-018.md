# 20260901-018

## 목적

`plan-003.md` Commit B의 asset tree / action menu 준비 단계다. 현재 asset action은 action availability 판정, selected asset context 계산, handler 실행과 legacy DOM menu 렌더링이 서로 결합되어 있다. Mantine `Menu`가 같은 domain action을 재사용할 수 있도록 DOM-free action model과 실행 경계를 먼저 분리한다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.48-alpha`로 올린다.
- `assetTreeActionItems(nodeType, context)`를 추가한다.
  - 기존 `ASSET_TREE_ACTION_SCHEMA`의 `when`/`disabled` 규칙을 그대로 사용한다.
  - React/Mantine가 읽을 수 있는 `key`, `label`, `disabled`, `disabledTitle` 데이터만 반환한다.
- `selectedAssetTreeActionModel()`을 추가한다.
  - 권위 상태는 기존 `appFSM.state.assetSelection`과 `assetPath`를 그대로 사용한다.
  - 기존 `projectVfs`를 통해 선택 경로, 휴지통 여부, 휴지통 내용 존재 여부를 계산한다.
  - 선택이 유효하지 않으면 빈 action model을 반환한다.
- `runAssetTreeAction(key, context)`를 추가해 기존 `ASSET_TREE_ACTION_HANDLERS`를 단일 실행 경계로 만든다.
- legacy `renderAssetTreeActionMenu()`도 새 action item helper를 사용하도록 바꿔 staging과 legacy가 availability 규칙을 중복 구현하지 않게 한다.
- legacy `syncAssetTreeActionMenu()`도 `selectedAssetTreeActionModel()`을 사용한다.
- `fastFigureUiBridge.readAssetActions()`와 `runAssetAction()`을 추가한다.

## 이 방향을 선택한 이유

Mantine 전환의 목적은 메뉴 외형만 교체하는 것이 아니라 custom menu lifecycle과 domain action 판정을 분리하는 것이다. action schema와 handler는 이미 기능 의미가 잘 분리되어 있으므로 새 action 체계를 만들 필요가 없다. 기존 schema/handler를 유지하면서 DOM-free projection과 실행 adapter만 추가하는 것이 같은 기능 자유도를 가장 작은 추가 복잡도로 제공한다.

또한 legacy renderer까지 같은 helper를 사용하게 해야 cutover 전후 action availability가 달라지는 이중 구현을 피할 수 있다.

## 선택하지 않은 방향

- 이번 패치에서 Mantine `Menu` 자체를 staging sidebar에 연결하지 않는다. action 계약과 UI wiring을 분리해 회귀 원인을 좁힌다.
- asset hierarchy, drag/drop, move/delete/import semantics는 변경하지 않는다.
- `assetSelection`/`assetPath`를 React local state로 복제하지 않는다.
- legacy menu의 outside-click/Escape/focus lifecycle은 아직 제거하지 않는다. 이는 shell cutover 또는 cleanup 단계에서 제거한다.
- 새 action registry를 만들지 않고 기존 `ASSET_TREE_ACTION_SCHEMA`와 `ASSET_TREE_ACTION_HANDLERS`를 재사용한다.

## 후속 작업

다음 패치에서는 `readAssetActions()`와 `runAssetAction()`을 사용해 `FastFigureSidebarStaging`에 Mantine `Menu`를 연결한다. 그 패치에서도 legacy menu는 활성 UI이므로 제거하지 않으며, Commit C cutover 전까지 두 renderer가 동시에 interactive하게 활성화되지 않도록 staging shell은 계속 비활성 상태로 유지한다.
