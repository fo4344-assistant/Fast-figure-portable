## Reasons and rejected alternatives

- Chose official queries because current source membership, fixed roots, canonical identities and destination rules belong to Backend. Reusing existing pure planProjectNodeMove with explicit current source avoids duplicating the move algorithm.
- Rejected keeping Application destination filters: they allowed missing/fixed inputs and silently removed trash destinations contrary to the declared procedure.
- Rejected preliminary CLEAR_GRAPH_OBJECT or a separate availability publication: SELECT_ASSET already owns accepted selection and graph-index clearing; wrong-kind references must not produce intermediate changes.
- Rejected introducing a generic query facade, a cached asset-tree model or a compatibility return-shape bridge: direct routes suffice and temporary reads must not become authority.
- Did not expand a test suite. Only existing112 was extended for the changed ownership paths. Execution remains pending, so assertions are not claimed to pass.
