# 20261001-028 — formal verification 계층 version gate 마이그레이션

## 목적

정책 v0.2.0의 개발 순서:

```text
Source Script
→ PlusCal/TLA+ verification model
→ TLC model checking
→ source code
```

를 실제 저장소의 lineage metadata와 CI gate가 강제하도록 변경한다.

이번 패치는 검증 모델 자체를 작성하지 않는다.
중간 계층의 정의와 gate만 바꾸는 것이 목표다.

## 변경 내용

### development-versions.json

schema를 1에서 2로 올린다.

authority precedence:

```text
source-script
> verification-model
> source-code
```

새 verification-model 초기 상태:

```text
revision = 0
status = missing
fingerprint = null
derived_from.source-script = null
tlc = pending
validation_review = null
```

source code의 upstream lineage는:

```text
source-script
verification-model
```

로 변경한다.

기존 pseudocode r2는 삭제하지 않고 `legacy_artifacts.pseudocode`로 이동한다.

- status = archived
- 기존 fingerprint 유지
- 기존 Source Script r12 derivation 유지
- 기존 validation=passed 기록 유지
- 정책 v0.1.1에서 생성된 비권위 참고 산출물임을 명시

### version checker

`scripts/check-development-layer-versions.py`를 schema 2에 맞춘다.

검사:

- Source Script는 항상 current
- Source Script closed에는 closure review 필요
- verification-model:
  - missing / stale / current
  - TLC pending / passed
  - current이면 closed Source Script의 정확한 fingerprint에서 파생
  - passed이면 current여야 하고 validation review가 존재
- source code:
  - current가 되려면 verification-model current
  - TLC passed
  - Source Script/verification-model fingerprint lineage 일치
- 기존 pseudocode:
  - archived artifact fingerprint가 임의 변경되지 않았는지 확인

revision progression:

- verification/ 변경 시 verification-model revision 증가
- verification/ 변경 결과는 current여야 함
- TLC pending→passed 전환에는 새 validation review 필요
- source code 변경은 verification-model current + TLC passed 이후에만 허용

schema 1에서 schema 2로 넘어가는 이번 migration commit도 base manifest를 읽어 처리할 수 있게 한다.

### CI workflow

version-chain workflow trigger에 다음을 반영한다.

- `verification/**`
- archived `pseudocode/**`
- policy source
- validation/closure reviews

### AGENT.md

운영 지침의 precedence와 source-code gate를 새 정책에 맞춘다.

### plan-008

이미 완료된 Source Script 정규화 의미는 유지한다.

lineage/Phase 7만 새 정책에 맞춰:

```text
Source Script
→ verification model
→ TLC
→ source code
```

로 갱신한다.

## 선택 이유

정책 문서만 PlusCal/TLA+ + TLC로 바꾸고
manifest/checker가 계속 pseudocode를 요구하면 실제 작업 순서가 두 개 존재하게 된다.

따라서 source-code 구현 전에 version gate 자체를 먼저 옮겨
새 정책을 우회해서 application source를 수정할 수 없도록 한다.

## 고려했지만 선택하지 않은 방향

### pseudocode layer 이름만 verification-model로 변경

선택하지 않았다.

현재 pseudocode r2는 자연어 Markdown이며 TLC가 실행할 수 있는 formal model이 아니다.
이름만 바꾸면 검증되지 않은 산출물을 TLC-passed 계층처럼 오인할 수 있다.

### 기존 pseudocode 삭제

선택하지 않았다.

Source Script r12를 언어 중립 절차로 정리한 기존 작업은
새 TLA+ 모델을 작성할 때 참고자료로 가치가 있다.
다만 권위 계층에서는 제외한다.

### verification-model을 즉시 current/passed로 표시

선택하지 않았다.

아직 `verification/` 모델 파일과 TLC 실행 결과가 없으므로 허위 lineage가 된다.

### 이번 패치에서 TLA+ 모델까지 작성

선택하지 않았다.

사용자가 한 번에 너무 많은 작업을 진행하지 않도록 요청했다.
이번 목표는 gate 마이그레이션 하나로 제한한다.

## 현재 완료 후 상태

```text
Source Script r12: current / closed
verification-model r0: missing / TLC pending
source code r0: stale
legacy pseudocode r2: archived reference
```

다음 작업은 Source Script r12에서 첫 PlusCal/TLA+ verification-model revision을 작성하는 것이다.
