# 20260910-026 — Remove obsolete asset DOM dependencies

## Purpose

Supersede failed patches `20260910-024` and `20260910-025` by removing the obsolete legacy asset import/tree DOM together with every boot-time dependency on the deleted `#filePick` and `#file` controls.

The compatibility boundary is unchanged: FFPX/FFSX and other persisted/interchange formats remain supported; legacy UI structure is not a compatibility target.

## Failure analysis

`20260910-024` failed because `REQUIRED_CONTROL_IDS` still required deleted legacy controls.

`20260910-025` removed those audit requirements but still failed the browser smoke test. The remaining direct dependency was `syncSlotContentTypeUi()`, which runs through `renderDashboard() -> updateFileAvailability()` during startup and still mutated `#filePick` label attributes and `#file.accept`. Removing those controls therefore caused a null dereference before `appFSM.ready()`.

Those mutations only configured the old browser UI. `FastFigureDataActions` now owns its React file input and determines import behavior directly from the selected slot/model, so they have no functional role in the Mantine path.

## Exact changes

### `Fast-figure.html`

- Remove legacy `#file` input.
- Remove the complete legacy `.asset-tree-shell` and its toolbar/tree controls.
- Keep `#fileName` temporarily because remaining non-tree runtime helpers still write to it. This is not a compatibility promise; it will be removed with the next model/value cleanup.

### `fast-figure.js`

- Remove `assetActions`, `assetActionMenu`, `assetDownload`, `assetTree`, `file`, and `filePick` from `REQUIRED_CONTROL_IDS`.
- Remove `#filePick -> #file.click()`.
- Remove legacy `#file.onchange` asset import.
- Remove `#file` from `connectLifecycleTasksToFSM()`.
- Remove `syncSlotContentTypeUi()` writes to `#filePick` and `#file`.
- Keep the rest of `syncSlotContentTypeUi()` temporarily because it still updates other legacy-dependent workspace controls that are being removed incrementally.

## Source of truth

Ordinary asset import is owned by `FastFigureDataActions`, including its React-owned file input and lifecycle call. Project tree behavior is owned by `FastFigureProjectDataTree` from project snapshot/model and `appFSM` state.

The selected slot type is already available from the project/slot model. No compatibility DOM is required to communicate that state.

## File-format compatibility

No FFPX/FFSX implementation is modified. ZIP/XML readers and writers, package versioning, project validation, original asset byte packaging, slot/project serialization, and import semantics are untouched.

## EFSM / core impact

None. No FSM transition/action, project VFS operation, asset loader, chart/slot model mutation, or file-format implementation changes.

## Rationale

A legacy UI element must not remain solely because old synchronization code expects it. Once Mantine owns the interaction, the correct simplification is to remove the obsolete synchronization dependency as well as the DOM.

## Rejected alternatives

- Add hidden replacement elements for `file`/`filePick`: rejected because it preserves legacy UI compatibility by stealth.
- Null-check the removed controls while keeping old synchronization code: rejected because the synchronization itself has no Mantine function.
- Change FFPX/FFSX logic: rejected as unrelated.

## Validation

Patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests must all pass before application.

## Rollback

Revert the application commit for `20260910-026` to restore the old asset import/tree DOM and legacy synchronization. FFPX/FFSX compatibility is unaffected by either state.
