## 재검토 결론

plan-007의 큰 단계 구조는 유지할 가치가 있지만 일부 구체 해결안은 더 나은 대안이 확인되었다.

비채택:

- grid shrink 시 row-major 자동 packing
- shared chart를 clone하여 exclusive topology로 보정
- 현재 persisted slot-caption placeholder를 atomic content occupancy로 취급
- label drag에 UI-local draft 추가
- export settings를 비영속 operation input으로 재정의
- protected default CSV를 graph invariant로 유지
- mutate 후 rollback을 일반 mutation pattern으로 고정

## 선택한 개선 방향

- grid shrink는 implicit reflow 없이 안전한 경우만 허용
- chart는 현재 FFPX 의미에 맞춰 slot과 1:1 ownership, malformed shared/orphan topology는 거부
- caption placeholder를 authoritative state에서 분리하고 caption 이동 semantics는 별도 matrix로 결정
- label position은 single SoT continuous edit
- README 계약대로 export settings를 persistent project state에 복원
- zero-object editable chart를 허용해 protected default CSV 제거
- mutation은 candidate-first validate-and-commit을 기본으로 사용
- version metadata에 Source Script closure와 pseudocode validation gate를 추가할 계획

## 이전 계획을 그대로 채택하지 않은 이유

plan-007은 몇 군데에서 current implementation의 특수 구조를 요구사항으로 승격하거나, 데이터 보존을 위해 필요한 것보다 더 많은 자동 변환/draft/rollback 구조를 추가했다.

Source Script 정책은 목적에 없는 규칙을 추가하지 않고, 같은 자유도를 더 낮은 복잡도로 얻을 수 있으면 기존 특수 구조를 통합·제거하도록 요구한다. 따라서 더 단순하고 명시적이며 file roundtrip과 README 계약에 일치하는 plan-008로 대체한다.

## 고려했지만 선택하지 않은 다른 방향

### plan-007 본문을 직접 전면 수정

선택하지 않았다. 기존 계획이 어떤 해결안을 제시했고 왜 폐기되었는지 추적하기 어렵게 된다. 기존 본문을 보존하고 상단에 대체 상태만 추가했다.

### 문제별로 plan-009, plan-010 등 여러 계획으로 분리

선택하지 않았다. grid/chart/caption/default-CSV/export-state는 project invariant와 file roundtrip에서 서로 영향을 주므로 Source Script closure라는 하나의 coherent 계획 안에서 순서를 관리하는 편이 낫다.

### shared chart 기능을 유지하기 위해 FFPX를 즉시 확장

선택하지 않았다. 현재 UI 요구가 없고 current FFPX writer/reader가 shared identity를 roundtrip하지 못한다. 기능 자유도 증가가 실제 요구로 확인되지 않은 상태에서 format 구조를 확장하는 것은 과도하다.

### caption 이동 semantics를 이번 review에서 바로 하나로 확정

선택하지 않았다. FFSX, swap, slot-caption mode가 서로 다른 방향의 근거를 주며 현재 사용자 명시 요구로 하나가 정해지지 않는다. placeholder state를 먼저 정리한 뒤 미확정 설계 항목으로 유지한다.

### Source Script를 이번 patch에서 바로 수정

선택하지 않았다. 이번 변경은 실행 계획 재기준화다. 실제 Source Script 수정은 plan-008의 Phase 0/1부터 새 revision과 별도 patch pair로 수행한다.

## 버전 영향

`sourcescript/` 내용은 변경하지 않았으므로 Source Script revision/fingerprint는 그대로다.

현재:

- Source Script r1: current, closure는 논리적으로 open
- pseudocode r0: missing
- source code r0: stale / pre-version-chain

closure metadata 자체는 plan-008 Phase 0에서 별도 patch로 도입한다.
