# 20260902-007 — Mantine graph 전역 layout staging 재생성

## 상태

`20260902-006.patch`는 `git apply --check`의 patch parse 단계에서 거부되어 `Fast-figure.html`에는 적용되지 않았다.

오류:

```text
error: patch fragment without header at agent_space/patches/20260902-006.patch:32
```

원인은 `applyChartLayout` hunk가 실제 기존/신규 각 7줄인데 header에 6줄로 기록된 unified diff 형식 오류다. JavaScript 검사와 실제 commit에는 도달하지 않았다.

`007`은 `006`과 같은 구현을 유지하고 모든 hunk의 기존/신규 줄 수를 다시 계산해 정상 diff로 재생성한다.

## 목적

`20260902-005`에서 만든 DOM-free graph layout bridge를 inactive Mantine sidebar staging에서 사용한다.

이번 범위:

- 그래프 제목
- 범례 표시
- 타이틀 표시
- 0선 표시
- 그래프 폰트
- 타이틀 글자 크기
- 범례 글자 크기

축 상세 설정은 다음 패치로 분리한다.

## 변경 내용

- 앱 버전 `1.1.57-alpha` → `1.1.58-alpha`
- sidebar에서 `readChartLayout()` snapshot 사용
- Mantine `TextInput`, `Switch`, `Select`, `NumberInput`, `SimpleGrid`, `Stack`으로 graph 전역 설정 staging 추가
- 기존 `GRAPH_FONT_OPTIONS` 재사용
- commit은 `fastFigureUiBridge.applyChartLayout(values, chartId)` 하나로 통일
- 제목/숫자는 uncontrolled input의 blur/Enter에서 commit
- toggle/font Select는 즉시 commit
- 오래된 blur callback이 새 selected chart를 덮어쓰지 못하도록 `chartId` stale guard 추가

## stale callback guard

`selectedChartLayoutModel()`이 반환하는 `chartId`를 callback과 함께 전달한다.

`applyGraphLayoutSettings(values, expectedChartId)`는 현재 selected chart ID와 다르면 mutation과 Plotly render를 수행하지 않고 `false`를 반환한다.

legacy 호출은 인자를 주지 않으므로 기존 동작을 유지한다.

이 ID는 source of truth가 아니라 stale snapshot을 거부하기 위한 식별자다.

## commit timing

legacy와 동일한 의미를 유지한다.

- 제목: change/Enter-blur에 해당하는 blur commit
- title/legend font size: blur/Enter commit
- graph font: 선택 즉시 commit
- legend/title/zero-line toggle: 즉시 commit

TextInput/NumberInput에 별도 React `useState`를 두지 않고 `defaultValue`를 사용한다. focus 동안의 입력값만 component 내부 draft다.

## source of truth

유일한 persisted source는 selected chart editor/global settings다.

- `readChartLayout()`은 snapshot
- input draft는 focus 동안만 존재
- `GRAPH_FONT_OPTIONS`는 기존 선택지 정의 재사용
- `chartId`는 stale guard용

React staging 값은 다른 기능의 권위 입력으로 재사용하지 않는다.

## Mantine/Core 분류

주 변경은 UI staging이다. stale guard는 UI adapter 경계의 안전장치이며 graph/domain semantics를 바꾸지 않는다.

변경하지 않는 항목:

- `CHART_LAYOUT_CHANGED`
- graph/domain model
- Plotly renderer와 stale-render 검사
- graph object EFSM
- 축 계산 규칙
- import/export
- 현재 활성 legacy UI

## 선택하지 않은 방향

- graph settings 전체를 React `useState`에 복제
- 제목/숫자를 매 keystroke마다 적용
- stale callback을 현재 선택된 다른 chart에 적용
- 축 상세 UI까지 같은 patch에 포함
- Plotly React 재작성

## 회귀 위험

낮음. staging은 아직 비활성이며 기존 graph event/renderer를 재사용한다.

검사:

- graph slot에서만 전역 설정 표시
- image/빈 slot에서는 미표시
- font options 동일
- boolean false 보존
- 빈 font-size의 자동값 의미 유지
- Enter → blur → 단일 commit
- chart 변경 후 이전 draft의 늦은 callback 거부
- legacy 무인자 `applyGraphLayoutSettings()` 유지

## rollback

1. sidebar graph 전역 staging block 제거
2. `Switch` destructuring과 `chartLayout` snapshot 변수 제거
3. bridge의 `chartId` 전달 제거
4. `applyGraphLayoutSettings()`의 `expectedChartId` guard 제거
5. 버전 복원

`20260902-005`의 DOM-free graph layout 경계는 독립 유지 가능하다.

## 후속

적용 후 실제 diff를 검증하고, 다음 패치에서 네 축의 상세 설정을 같은 bridge에 추가한다. tick-mode/log-scale/minor-ticks 규칙은 기존 동작을 그대로 보존한다.
