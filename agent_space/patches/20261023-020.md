# 20261023-020 — 중요 작업 자료 보존과 Plan 016 diff 출처 확인

## 목적과 변경

사용자의 중요 데이터 이동/Plan 016 diff 조사 요청에 따라 저장소 상위 `.work`의 과거 원시 로그 33개, static trace 1개, diff 4개를 `agent_space/logs/20261023-work-archive/`로 옮긴다. 이동 전후 SHA-256과 byte 수를 `inventory.json`으로 남기며, trace의 byte-identical 중복 1개만 이동 완료/hash 재확인 뒤 제거했다. 조사 근거는 `agent_space/reviews/review-20261023-017-work-archive.md`에 기록한다.

## 선택 이유와 기각한 대안

- `logs/logs.md`가 정한 원시 실행·오류 기록 보존 경로를 사용한다. 실행 로그와 해석/review를 분리한다. 임시 작업 폴더를 정식 보관 원천으로 남기지 않는다.
- 코드/Source/PlusCal 비교 diff 세 개는 서로 다른 실제 Git baseline/endpoint의 결과와 전체 bytes가 일치했다. 파일명이 다르다고 정식 patch에 덮어씌우거나 새 기능으로 적용하는 대안은 잘못된 이력·중복 구현을 만들므로 기각한다.
- `plan016-local.diff`는 사용자 지시로 폐기됐다고 기존 기록에 명시된 palette 미커밋 초안이다. 메모리 재구성으로 blob header를 확인했지만 구현에는 복원하지 않는다. 기록 유실을 막기 위해 원시 자료로만 보존한다.
- `.work`의 모든 파일을 무조건 보관하거나 삭제하지 않는다. 일회성 helper/index/context와 Git에 이미 있는 hierarchy 원본은 이동 대상에서 제외한다. 실제 데이터가 다른 실패/보정 로그는 이름이 비슷해도 중복으로 제거하지 않는다.

## patch 범위와 외부 이동 기록

기준 HEAD는 `444f7b726fee2c5cb038281f5fa1057114d3b978`이다. 동명 patch는 이 기준 대비 archive/inventory와 review의 실제 신규 diff이며, 자기참조를 피하기 위해 020 patch/설명 쌍 자체는 포함하지 않는다. 저장소 밖 `.work`는 Git 관리 대상이 아니므로 원본 삭제는 저장소 diff에 나타나지 않는다. `inventory.json`의 source/destination/hash와 deduplicated 항목이 외부 이동 및 중복 제거 내역이다. 보존 파일 원문의 줄바꿈/whitespace는 변경하지 않았다.

사용자 지시에 따라 패치 파일 생성에는 Node를 사용하지 않는다. 이 patch는 Git 자체의 `git diff --cached --binary --no-ext-diff --no-textconv --output=agent_space/patches/20261023-020.patch 444f7b726fee2c5cb038281f5fa1057114d3b978 -- agent_space/logs/20261023-work-archive agent_space/reviews/review-20261023-017-work-archive.md`로 재생성했다(저장소 루트 기준).

## 검증 및 미포함

38개 이동 파일 총 755203 bytes의 SHA-256 일치, 원본 경로 부재, trace 중복 동일성 및 세 historical diff의 정확한 commit 재현을 확인했다. local palette 초안의 두 new blob은 reachable Git 이력에 없고 기존 폐기 문서와 일치한다. 파일/Git 정적 확인만 수행했으며 application/test/build/checker/Actions/TLC는 실행하지 않았다. 원시 로그/과거 diff의 기존 whitespace는 보존하며 새 inventory/review/설명 문서의 whitespace 검사와 구분한다.

application source, Source Script, PlusCal, 정책, development-versions.json, distribution, 기존 patch는 수정하지 않았다. 새 실행 성공/current/번역 완료를 주장하지 않는다. 원격 publication이나 push는 수행하지 않는다.
