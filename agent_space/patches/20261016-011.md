# 20261016-011 — Source Script r28 import·의미 계층 파일 배치

## 목적 / 이유

사용자 지시대로 서술형 Source Script 참조 목록을 import 표기로 바꾸고, 평면 파일을 기존 의미 계층에 맞게 배치한다. 정책 §3.2.1–3.2.3 / §4.3.2를 확인했으며 정책 자체는 변경하지 않는다. 호출 관계를 부모–자식 관계로 바꾸지 않고 기존 Backend / Application boundary / Frontend / Portable build 소유권을 유지한다.

## 실제 누적 변경

- 기준: `b3cd9648ff6705f07510c8b3c4947d4276ffdb61`.
- 의미 변경 endpoint: `1cbc78c50f498e93a9f10233f809bace3a456c37`.
- `.patch`는 위 두 실제 Git commit 사이의 `git diff --no-renames --binary` 전체 결과다. checker가 각 변경 source 경로를 대조할 수 있도록 rename 탐지 대신 실제 추가/삭제 diff를 기록한다. patch 자체와 이 설명은 자기참조를 피하기 위해 endpoint 뒤에 게시한다.
- `sourcescript/backend/`: state/query/EFSM/domain/candidate/serialization.
- `sourcescript/application/`: adapter와 `public_api/` wrapper. 후자의 네 파일은 기존 public-api 논리 모듈의 물리 파일이다.
- `sourcescript/frontend/`: interface FSM / Mantine-local interaction / supplied-input renderer.
- `sourcescript/portable_build/`: 기존 packaging 책임.
- `sourcescript/system.py`: 실제 module import와 기존 hierarchy owner의 새 경로 연결. 기존 평면 파일과 중복 파일 목록을 제거한다.
- 혼합 파일의 Backend 계산 / Application wrapper / Frontend UI·renderer를 각각 옮겼다. export snapshot을 Application에서 query한 뒤 renderer 입력으로 전달해 renderer의 Backend 직접 참조를 없앴다. graph object edit 계산은 기존 Backend helper의 책임으로 정리한다.
- source revision r28 / fingerprint `sha256:dbf4e7a295261f492b1b4742222742c1171403cba868169b43149a31d8105ad6`, closure open / closure_review null. 하위 PlusCal/model/code는 stale 그대로다.
- Plan 017 진행 기록과 `agent_space/reviews/review-20261016-006-sourcescript-r28-hierarchy-open.md`를 포함한다.

## 검토한 대안과 배제 이유

- 단순 폴더 이동만 하고 혼합 책임 유지: Application wrapper/UI가 Backend 소유처럼 보이므로 배제.
- 호출자가 쓰는 domain을 호출자 아래로 재부모화: 의미 포함관계가 아니므로 배제.
- domain별 물리 파일을 새 논리 계층으로 자동 승격: 사용자가 요청한 파일 정리를 이유로 새 의미 decomposition을 만들지 않기 위해 배제.
- 기존 평면 호환 파일 유지: 중복 entry/dependency authority가 생기므로 배제.
- 구조 변경과 동시에 JS/PlusCal 반영 또는 closed 선언: 상위 미정 의미와 전체 trace가 남아 있으므로 배제.

## 포함하지 않은 작업 / 한계

정책, PlusCal/model, application JS/UI, regression tests, build workflow와 distribution은 수정하지 않았다. Plan 017 D/E의 concrete palette/default 원천, numeric/axis/Plotly field별 계산, 전체 공개 API trace는 남아 있다. 이번 변경은 전체 Source Script semantic closure 또는 실행 등가성의 증명이 아니다.

GitHub Contents API로 파일마다 예상 branch HEAD와 현재 blob SHA를 확인하고 순차 PUT/DELETE했다. 새 파일은 404를 확인하고, 삭제는 기존 blob 일치와 로컬 경로 제거를 확인했다. 다중 파일 원자 commit이 아니므로 전송 도중에는 새/기존 경로 중복이나 metadata fingerprint 불일치가 있다. 중간 push Actions의 실패를 최종 누적 검사와 혼동하지 않는다. 최종 endpoint에서는 평면 bridge를 남기지 않는다.

## 검증

- 로컬: 파일 읽기/편집, Git diff/hash/전송만 수행했다. 누적 `git diff --check` 통과. Source Script import/application/test/version checker/build/TLC를 실행하지 않았다.
- patch의 endpoint tree에 대해 임시 index로 `git apply --cached --reverse --check`를 수행해 적용 가능성을 확인했다. 임시 index는 작업 디렉터리 `.work/`에 두고 제거했다. application 또는 Source Script 실행이 아니다.
- GitHub Actions 누적 검사: [38853792910](https://github.com/fo4344-assistant/Fast-figure-portable/actions/runs/38853792910), 실제 HEAD `1e6f9252dd2ce2858abb8b8a8d3a2f89a95716bd`, `base_sha=b3cd9648ff6705f07510c8b3c4947d4276ffdb61`, **PASS**. patch 쌍을 포함한 전체 누적 revision/fingerprint/patch-marker 검사이며 로그에 `source-script: r28 current/open`과 위 fingerprint가 확인된다. semantic closure 검사는 아니다.
- endpoint push 검사 38853733202는 `development-layer-version: FAIL: source-script changed without increasing its revision (28 -> 28)`로 실패했다. 이 push는 마지막 단일 파일 삭제를 기준으로 검사하므로 누적 revision/새 patch 쌍을 아직 포함하지 않는 전송 중간 검사다. 이후 patch 쌍이 존재하는 실제 HEAD에서 명시적 baseline 누적 검사가 통과했다. 중간 실패를 삭제하거나 성공으로 표현하지 않는다.
