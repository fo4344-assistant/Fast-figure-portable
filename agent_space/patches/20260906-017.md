# 20260906-017 — audit owner boundary

## 목적

React/Mantine shell owner cutover 이후에도 `auditApp()`이 core/EFSM 검증을 계속 수행하면서, 제거된 legacy native control ID 때문에 무조건 실패하지 않도록 presentation-owner 경계를 추가한다.

현재 `auditApp()`은 `REQUIRED_CONTROL_IDS` 전체가 DOM에 존재하는지 항상 검사한다. 이는 현재 legacy owner에서는 유효하지만 Mantine shell이 owner가 된 뒤에는 제거 대상 native controls를 존재해야 하는 것으로 잘못 간주한다.

## 변경 내용

- 앱 버전 `1.1.120-alpha` → `1.1.121-alpha`
- `auditApp(context, { requireLegacyControls = true } = {})` 옵션 추가
- 기본값은 `true`로 유지하여 현재 legacy owner의 동작과 검증 강도를 그대로 보존
- `requireLegacyControls === false`일 때만 `REQUIRED_CONTROL_IDS` missing-control 검사를 생략
- duplicate ID, required function, EFSM lifecycle/workspace/overlay/direction, write lock, workspace/model 일치, project object 검증 등 나머지 audit는 그대로 유지

## Mantine 전환과의 관계

후속 owner cutover patch는 React shell이 실제 owner가 된 뒤 `auditApp(..., { requireLegacyControls: false })`를 사용할 수 있다. 이 옵션은 legacy DOM 제거를 정당화하는 전역 bypass가 아니라, presentation owner가 더 이상 legacy controls가 아님을 명시하는 경계다.

React shell 자체의 필수 host와 기능 누락은 별도 cutover 검증에서 확인한다.

## source of truth / EFSM / core

- project/domain source of truth 변경 없음
- EFSM state/transition/event 변경 없음
- FFPX/FFSX schema 변경 없음
- React state 추가 없음
- 현재 실행 경로에서는 기본값 `true`라 observable behavior 변경 없음

## 선택하지 않은 방향

### `REQUIRED_CONTROL_IDS`를 즉시 삭제

현재 owner가 아직 legacy UI이므로 현재 회귀 검증 능력을 잃는다.

### 누락된 모든 DOM을 optional chaining으로 변경

owner 경계가 불명확해지고 실제 필수 renderer host 누락까지 조용히 숨길 수 있으므로 선택하지 않는다.

## 회귀 위험

낮음.

기존 호출은 두 번째 인자를 전달하지 않으므로 기존 audit 결과와 동일하다.

## 검증

1. `git apply --check`
2. `git diff --check`
3. `node --check fast-figure.js`
4. portable build
5. split/portable `file://` smoke test
6. 기존 `auditApp("app:init")`가 legacy control 검사를 계속 수행하는지 정적 확인
7. `auditApp("mantine-cutover", { requireLegacyControls: false })`가 legacy control 누락만 생략하고 EFSM/core 검사를 유지하는지 정적 확인

## rollback

`auditApp()` 두 번째 인자와 조건부 `missingControls` 계산을 제거하고 앱 버전을 `1.1.120-alpha`로 복원한다.
