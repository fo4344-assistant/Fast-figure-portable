# 20260901-002

## 목적

`plan-003.md` Commit B의 첫 준비 단계로 React/Mantine shell이 기존 EFSM을 상태 원본으로 사용할 수 있는 external-store bridge를 추가한다. 활성 UI는 변경하지 않는다.

## 변경 내용

- 애플리케이션 버전을 `1.1.32-alpha`로 올린다.
- `buildFastFigureUiSnapshot()`을 추가한다.
  - FSM snapshot과 project/domain object에서 UI가 읽을 값을 만든다.
  - 일반 UI DOM ID, `.value`, `.classList`, dataset을 읽지 않는다.
- `fastFigureUiBridge`를 추가한다.
  - `subscribe`: 기존 `appFSM.subscribe()` 재사용
  - `getSnapshot`/`getServerSnapshot`: 기존 `appFSM.state`를 그대로 external-store snapshot으로 사용
  - `read`: UI용 읽기 snapshot 제공
  - `send`/`notify`/`run`: 기존 EFSM 진입점 재사용
- `useFastFigureFsmSnapshot()`을 추가해 React `useSyncExternalStore`와 bridge를 연결한다.
- bridge를 `window.FastFigureUiBridge`에 노출해 이미 vendoring된 UI runtime과 이후 비활성 shell component가 같은 경계를 사용할 수 있게 한다.
- Mantine shell은 아직 렌더하지 않는다. legacy UI가 계속 유일한 활성 renderer다.

## 이 방향을 선택한 이유

React가 `overlay`, `workspace`, selection 또는 project object를 별도 state로 복제하면 기존 EFSM과 새로운 UI state가 동시에 권위자가 된다. 반대로 DOM dataset이나 native input을 React가 읽게 만들면 legacy renderer 결합을 그대로 유지하게 된다.

따라서 기존 `ApplicationStateMachine`의 `subscribe()`와 immutable `state` object를 `useSyncExternalStore` 계약에 직접 연결한다. Project/domain 값은 필요할 때 registry에서 읽고, mutation은 기존 `send`/`notify`/`run` 경로를 그대로 사용한다.

이 구조는 새로운 상태 관리 계층을 추가하지 않으면서 React renderer를 EFSM의 관찰자로 만든다.

## 고려했지만 선택하지 않은 방향

### React Context/useState에 FSM state 복제

선택하지 않았다. 두 source of truth가 생긴다.

### `document.body.dataset`을 React store로 사용

선택하지 않았다. `publish()`의 legacy renderer side effect를 새로운 UI 계약으로 고착시킨다.

### toolbar/sidebar component를 이 패치에서 활성화

선택하지 않았다. `plan-003`의 단일 shell cutover 원칙에 따라 full shell 준비가 끝날 때까지 legacy UI만 활성 상태를 유지한다.

### 모든 domain object를 한 snapshot에 깊게 복제

선택하지 않았다. UI가 실제로 필요로 하는 layout/labels/captions/appearance와 selection metadata만 읽는다. 이후 component별 selector를 추가해 범위를 더 좁힐 수 있다.

## 검증

로컬 context-equivalent baseline에서 다음을 확인했다.

- `git apply --check` 통과
- `git diff --check` 통과
- 마지막 application script `node --check` 통과
- patch는 current main과 동일한 `1.1.31-alpha` version context와 `const appFSM = new ApplicationStateMachine(...)` anchor를 사용한다.
- 신규 selector/bridge에는 일반 UI DOM read/write가 없다.

GitHub 적용 시 기존 patch workflow에서 현재 main에 대해 다시 `git apply --check`, `git diff --check`, JavaScript syntax 검사를 수행해야 한다.
