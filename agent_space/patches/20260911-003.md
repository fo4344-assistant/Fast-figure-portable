# 20260911-003 — Disconnect legacy graph UI execution paths

## Purpose

Remove all active event wiring and startup installation for the obsolete sidebar graph editor now that Mantine owns graph editing and file actions. This makes the remaining legacy graph functions/markup dead code that can be deleted without preserving fallback behavior.

## Exact changes

### `fast-figure.js`
- Remove legacy graph-object outside-click handling and the `#addGraphObject` DOM action path.
- Remove legacy graph type/line/marker/bar/text/number input bindings.
- Remove legacy graph palette reset/save/load button and file-input handlers.
- Remove legacy FFSX/Plotly export/import button/input bindings while retaining `downloadSlotFfsx()`, `downloadPlotlyJson()`, `importSlotFile()`, FFSX parsers/builders, and Plotly conversion functions for Mantine.
- Remove legacy `#headerLines` onchange wiring.
- Remove legacy legend/title/zero-line and axis-field event wiring.
- Remove graph-only entries from `connectLifecycleTasksToFSM()` because Mantine wraps those operations directly.
- Stop startup initialization of legacy graph font select, axis fields, graph palette DOM, graph-object renderer, editable-state DOM, and legacy graph toggles.

## Rationale

Keeping event listeners attached to hidden or obsolete controls is still legacy UI compatibility. The user explicitly does not require that compatibility. Mantine already calls the same UI-independent commands and file-format functions directly, so the old execution paths should cease to exist before the DOM facade is removed.

## Source of truth

- Graph model and object selection: project chart model / `appFSM`.
- Graph UI: Mantine graph editor/layout/palette/file components.
- FFSX/Plotly compatibility: existing parser/serializer/import/export functions, unchanged.

## EFSM / core impact

No graph event semantics, chart schema, renderer, parser, serializer, or project state rules are changed. Only obsolete DOM event entrypoints and startup installers are removed.

## File-format compatibility

FFPX, FFSX, Plotly JSON and image/data file formats are unchanged. FFSX/Plotly functional commands remain callable by Mantine.

## Rejected alternatives

- Leave old handlers attached to hidden controls: rejected because legacy UI compatibility is not required.
- Make Mantine invoke those handlers: rejected because it would recreate a DOM bridge.
- Move FFSX/Plotly parsing into React: rejected because file compatibility belongs outside generic UI.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert the application commit to restore legacy graph UI execution wiring. No stored data migration is involved.

## Follow-up

Delete the now-dead legacy graph form readers/renderers/helpers and then remove `#buildBox`, its required IDs, and graph-only CSS. Preserve the independent FFSX/Plotly format layer.
