# 20260831-017

## 목적

`20260831-016`의 theme 구현 의도는 유지하되, 잘못 작성된 unified diff hunk count 때문에 `git apply`가 실패한 transport 오류를 수정해 Mantine 공통 control theme를 실제 HTML에 적용한다.

## 변경 내용

- `fastFigureTheme`를 `createTheme()`로 정의한다.
- 기존 Fast Figure UI geometry를 migration baseline으로 사용한다.
  - font: `system-ui, "Segoe UI", sans-serif`
  - 공통 control 높이: 38px
  - 기본 font size: 14px
  - 기본 radius: 6px
- `Button` 기본 size `ff`에서 `--button-height`, `--button-padding-x`, `--button-fz`를 중앙 정의한다.
- `ActionIcon` 기본 size `ff`에서 `--ai-size: 38px`를 사용한다.
- 공통 `Input` 기본 size `ff`에서 `--input-height`, `--input-fz`, `--input-radius`를 정의한다.
- `Input` default props를 통해 TextInput/NumberInput/Select 등 Input 기반 컴포넌트가 같은 size 규칙을 상속하도록 한다.
- `MantineProvider`에 `theme: fastFigureTheme`를 연결한다.
- 애플리케이션 및 built-in README 버전을 `1.1.31-alpha`로 맞춘다.
- toolbar/sidebar/modal DOM은 이 커밋에서 교체하지 않는다.

## 20260831-016과의 관계

`20260831-016`은 HTML에 적용되기 전에 `corrupt patch`로 거부되었다. 따라서 애플리케이션 상태는 변경되지 않았다. 이번 patch는 같은 구현을 실제 HTML 순서에 맞춰 다시 생성했으며, 로컬 mock repository에서 `git apply --check`를 통과하도록 hunk count와 순서를 검증했다.

## 이 방향을 선택한 이유

이번 단계의 책임은 실제 control migration 전에 공통 규칙의 단일 소유점을 만드는 것이다. Mantine의 component `defaultProps`와 `vars`를 사용하면 이후 각 버튼/입력에서 높이와 padding을 다시 쓰지 않아도 된다.

38px, 14px, 6px는 기존 Fast Figure의 geometry를 유지하기 위한 초기 기준이며, 전체 시각 디자인 변경과 분리한다.

## 공식 API 확인

- Mantine `theme.components`의 `extend({ defaultProps, vars })` 사용 가능
- Button: `--button-height`, `--button-padding-x`, `--button-fz`
- ActionIcon: `--ai-size`
- Input: `--input-height`, `--input-fz`, `--input-radius`
- `Input` default props는 Input 기반 컴포넌트에 공통 상속

## 고려했지만 선택하지 않은 방향

- 아직 사용 중인 legacy `.toolbar button` 등의 CSS를 이번 단계에서 제거하지 않는다.
- 각 컴포넌트마다 `size="ff"`를 반복하지 않는다.
- `AppButton`, `AppInput` 같은 단순 style wrapper를 만들지 않는다.
- palette나 primary color를 이 단계에서 재설계하지 않는다.

## 검증 항목

- patch 형식 mock `git apply --check` 통과
- 실제 repository `git apply --check`
- 적용 후 엄격한 `git diff --check`
- main JavaScript `node --check`
- `APP_BUILD`와 built-in README 버전 일치
- 기존 toolbar/sidebar/overlay markup 비변경

## 패치에 포함되지 않은 변경사항

이 설명 파일과 patch 기록 파일 자체는 재귀적으로 diff에 포함하지 않는다. 실제 HTML 적용은 명시적 HTML patch workflow가 검증 후 수행한다.
