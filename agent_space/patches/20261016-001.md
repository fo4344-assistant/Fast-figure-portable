# 20261016-001 — Plan 016 selection/reconciliation ownership (WIP)

## 목적과 변경

Frontend selection/reconciliation에서 Backend state를 직접 읽거나 정규화하던 경로를 Backend query provider → Application adapter → validated Frontend input으로 옮긴다. Frontend FSM에 live ProjectObject context를 전달하지 않고 persistent command action 연결을 제거한다. invalid reference는 reject/no-change로, explicit null은 deselection으로 처리한다. graph selection이 graph index와 CSV path를 함께 선택하고 live chart/editor/object 배열은 변경하지 않는다. commit 성공 이후에만 Backend-resolved reconciliation input을 적용한다. 회귀 항목 37/38, lineage r32와 진행/검토 기록을 포함한다.

## 선택한 이유와 기각한 대안

- Source Script r25 / PlusCal r11에 이미 확정된 Backend query, Frontend validated input, Application ordering 책임을 그대로 사용한다.
- Frontend가 Backend helper를 다시 호출하는 wrapper만 추가하는 대안은 직접 dependency를 숨길 뿐이므로 선택하지 않았다.
- Frontend ProjectObject mirror/cache, 새 command bus 또는 두 번째 authority는 추가하지 않는다.
- 전체 renderer/API를 중간 bridge로 감싸는 대안은 선택하지 않았다. 해당 ownership cutover는 후속 작업으로 남긴다.
