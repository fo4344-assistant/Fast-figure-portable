# 20261001-010 — 개발 단계 closure/validation gate 추가

## 목적과 변경 내용

plan-008 Phase 0에 따라 version metadata가 단순 freshness뿐 아니라 단계 완료 조건도 강제하도록 보완한다.

변경:

- `development-versions.json`
  - Source Script에 `closure: open|closed`
  - Source Script에 `closure_review`
  - pseudocode에 `validation: pending|passed`
- `scripts/check-development-layer-versions.py`
  - Source Script closure 상태 검증
  - closed 전환 시 새 closure review 요구
  - Source Script가 closed가 아니면 pseudocode current 금지
  - pseudocode validation이 passed가 아니면 source code current 금지

현재 Source Script 내용은 바꾸지 않으므로 source-script revision/fingerprint는 그대로 유지한다.

## 선택 이유

기존 metadata의 `current`는 실제 파일 내용이 최신 상위 revision에서 파생되었는지만 나타냈다.
하지만 개발 정책의 “앞 단계가 구조적으로 닫힌 뒤 다음 단계로 이동”은 freshness와 별개의 조건이다.

따라서:

- freshness: `status`
- Source Script 논리적 닫힘: `closure`
- pseudocode 검증 완료: `validation`

을 분리한다.

## 고려했지만 선택하지 않은 방향

### current 값을 closed 의미까지 포함하도록 재정의

선택하지 않았다. 최신이지만 아직 구조적으로 열린 Source Script가 현재처럼 존재할 수 있으므로 두 의미를 하나의 flag에 합치면 상태를 정확히 표현할 수 없다.

### closure review 존재를 문서 규칙으로만 요구

선택하지 않았다. 다음 단계 gate를 자동화하려는 목적에 맞지 않는다. closed 전환 시 새 review 파일이 실제 commit에 포함되어야 한다.

### Source Script revision 증가

선택하지 않았다. 이번 변경은 개발 lineage metadata와 checker만 수정하며 `sourcescript/` 의미 파일은 바꾸지 않는다.

## 버전 상태

- Source Script r1: current / open
- pseudocode r0: missing / pending
- source code r0: stale / pre-version-chain
