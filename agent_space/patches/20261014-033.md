# 20261014-033 — Make raw-file-to-slot import atomic in Source Code r28

## 변경

- directory batch import와 slot import가 동일한 `stageProjectAssetImport` candidate staging helper를 사용한다.
- helper는 raw CSV/image parse, id allocation, replace/new 분기, path assignment만 수행하며 authoritative state를 변경하지 않는다.
- `importProjectFileToSlot`은 asset candidate를 만든 뒤 target slot/chart/image 변경까지 같은 project candidate에 반영한다.
- CSV import:
  - image slot이면 image reference를 제거하고 graph slot으로 전환한다.
  - existing editable chart면 새 graph object를 candidate에 추가한다.
  - chart가 없으면 candidate 내부에서 새 chart id를 할당한다.
- image import:
  - target slot의 owned chart를 candidate에서 제거하고 image reference/contentType/imageSettings를 한 번에 설정한다.
- 전체 candidate validation 뒤 `ASSETS_IMPORTED` 한 projectEFSM command로 commit한다.
- chart Plotly projection은 commit 후 authoritative chart를 다시 읽어 rebuild한다.

## 일반 코딩 원칙

raw file parsing과 candidate 계산을 authoritative mutation과 분리했다.
directory/slot import가 같은 parse/id/path 로직을 공유해 중복 구현을 만들지 않는다.
asset 생성과 slot 연결을 별도 commit으로 쪼개지 않아 실패 시 부분 project mutation이 남지 않는다.

## 남은 범위

projectEFSM 내부의 일부 legacy action이 아직 mutate/rollback 방식을 사용한다.
이들은 권위 우회는 아니지만 candidate-first 원칙에 맞춰 후속 revision에서 정리한다.
