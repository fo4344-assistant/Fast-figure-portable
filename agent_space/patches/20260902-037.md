# 20260902-037 — legacy graph object add handler command 재사용

## 배경

`20260902-035`에서 graph object 추가 기능을 DOM-free command로 분리했고, `20260902-036`에서 Mantine sidebar가 해당 command를 사용하도록 연결했다.

기존 `#addGraphObject` handler에는 같은 기능 의미가 여전히 별도로 구현되어 있다. 특히 다음 로직이 command와 중복된다.

- 빈 슬롯에서 `SLOT_DATA_CONNECTED`
- 기존 chart에서 object 생성/append
- 빈 axis title 보충
- `CHART_MODEL_REPLACED`
- 새 object 선택
- graph view 갱신

반면 legacy DOM의 선택 object form과 목록을 다시 그리는 일은 renderer 책임이므로 command에 넣지 않는다.

## 목적

- graph object 추가의 기능 구현을 `035` command 하나로 통일한다.
- legacy handler에는 legacy DOM renderer 책임만 남긴다.
- `selectGraphObject()`와 add handler가 동일한 선택 object DOM 동기화 코드를 재사용하도록 한다.

## 변경 내용

- 앱 버전 `1.1.79-alpha` → `1.1.80-alpha`
- `renderSelectedGraphObjectLegacy(objects)` helper 추출
- `selectGraphObject()`가 helper를 사용하도록 변경
- legacy `#addGraphObject` handler에서 직접 chart/object/EFSM 조작 제거
- handler가 `selectedGraphObjectAddModel()` → `fastFigureUiBridge.addGraphObject()` → legacy renderer helper 순서만 수행

## 책임 경계

```text
기능 상태 변경
selectedGraphObjectAddModel()
→ fastFigureUiBridge.addGraphObject()
→ 035 command
→ EFSM/domain

legacy UI 동기화
renderSelectedGraphObjectLegacy()
→ headerLines/loadData
→ populateObjectForm
→ renderGraphObjects
```

## source of truth

legacy handler는 더 이상 `configFromForm()`의 DOM 값을 graph object 추가의 권위 있는 상태로 사용하지 않는다. 추가 대상은 `035` command가 canonical chart/selected object + active CSV에서 계산한다.

legacy DOM은 command 완료 후 canonical object를 읽어 표시만 갱신한다.

## 기존 동작 보존

- 데이터/슬롯이 준비되지 않은 경우 기존 안내 문구 유지
- 추가 성공 후 새 object가 선택된 상태 유지
- 선택 object의 CSV/header/form/list를 legacy UI에 표시
- graph view 갱신은 `035` command가 담당
- 기존 EFSM event/action 경로 유지

## 의도적인 변경

기존 handler는 `configFromForm()`의 아직 canonical model에 반영되지 않은 legacy DOM 값을 새 object 생성에 사용할 수 있었다. Mantine 전환 후에는 선택 object form 변경이 즉시 canonical chart에 반영되므로 이 DOM draft를 별도 authority로 유지하지 않는다.

따라서 legacy add 버튼도 Mantine과 동일한 canonical command 의미를 사용한다. 이는 기능 축소가 아니라 source-of-truth 통일이다.

## 변경하지 않음

- `035` command
- Mantine add button
- EFSM event/action 정의
- chart/model schema
- Plotly trace/layout 구현
- import/export

## 기각한 대안

### legacy handler에 기존 구현을 계속 유지

기각. 동일한 add 의미가 두 구현으로 갈라져 이후 버그 수정과 rollback 판단이 어려워진다.

### DOM renderer 동기화를 `035` command에 넣기

기각. Mantine command가 제거 예정인 legacy DOM에 다시 의존하게 된다.

### `editChart()` 호출로 legacy UI 전체 재초기화

기각. `editChart()`는 `selectedObjectIndex = null`로 초기화하므로 add command가 만든 선택 상태를 불필요하게 흔든다.

## 검증

- patch apply/check
- JavaScript syntax
- `#addGraphObject` handler에서 직접 `SLOT_DATA_CONNECTED`/`CHART_MODEL_REPLACED` 호출이 제거됨
- helper는 DOM renderer만 수행
- `selectGraphObject()`의 기존 DOM 표시 의미 유지
- Plotly bundle 미접촉

## rollback

- 기존 `selectGraphObject()` 내부 renderer 코드를 복원
- 기존 `#addGraphObject` handler의 직접 구현 복원
- `renderSelectedGraphObjectLegacy()` 제거
- 앱 버전 `1.1.79-alpha` 복원

`035`/`036`은 독립적으로 남기거나 별도 rollback할 수 있다.

## 후속

성공 후 graph-object legacy/Mantine 경계에서 남은 직접 DOM/domain 혼합 호출을 점검하고, 목록/추가 기능이 모두 공통 command를 사용하는지 횡단 검토한다.
