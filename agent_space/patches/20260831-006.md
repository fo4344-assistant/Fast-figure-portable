# 20260831-006

## 목적

`swapSlotContents()`가 `chart`, `imageId`, `contentType`만 개별 교환해 `caption`이 원래 물리 슬롯에 남는 문제를 해결하고, 이후 슬롯 콘텐츠 속성이 추가되어도 swap과 grid rebuild에서 필드 누락이 반복되지 않도록 런타임 슬롯 구조를 개선한다.

이 패치는 `agent_space/plans/plan-001.md`의 적용 계획 1~6단계를 한 번에 적용한다. 중간 단계만 적용하면 runtime 구조와 기존 flat 처리 경로가 혼재하므로 하나의 일관된 변경으로 묶는다.

## 변경 내용

- 애플리케이션 버전을 `1.1.29-alpha`로 올리고 인라인 README 버전도 동일하게 맞춘다.
- `slot.content`를 런타임에서 이동 가능한 슬롯 콘텐츠의 단일 원본으로 도입한다.
- `normalizeSlotContent(slot)`와 `normalizeSlotContents(slots)`를 추가한다.
- 기존 flat slot의 `chart`, `imageId`, `contentType`, `caption`을 `slot.content`로 옮기되 이미 존재하는 `content` 객체의 추가 필드는 보존한다.
- 기존 코드 호환을 위해 `slot.chart`, `slot.imageId`, `slot.contentType`, `slot.caption`을 non-enumerable accessor로 유지한다.
- `toJSON()`을 통해 `projectClone()`과 FFPX v3 직렬화에서는 기존 flat slot representation을 유지한다.
- `ProjectObject` constructor, `initialize()`, `slots` setter를 slot normalization 경계로 사용한다.
- `newGridSlot()`이 처음부터 nested `content` 구조의 slot을 생성한다.
- `rebuildGridSlots()`가 `content` 객체 전체를 복제한 뒤 현재 유효한 chart/image 참조만 보정하도록 바꾼다. 미래 content 필드는 보존된다.
- `SLOTS_SWAPPED`를 실제 workspace EFSM event로 등록하고 `applySlotsSwappedAction()`에서 mutation을 수행한다.
- swap action은 writable guard, source/target 검증, content 전체 교환, 선택 슬롯 이동, editor/asset transient state 초기화, project validation, 실패 시 rollback을 수행한다.
- overlay에서는 현재 상태를 유지하면서 update를 허용하고, graph object와 asset selection은 `SLOTS_SWAPPED`에서 `none`으로 정리한다.
- 기존 `swapSlotContents()`는 직접 slot mutation을 하지 않고 `appFSM.send("SLOTS_SWAPPED", ...)`만 호출하는 dispatcher로 축소한다.
- FFPX `PACKAGE_FORMAT_VERSION`은 3으로 유지한다.

## 이 방향을 선택한 이유

현재 문제만 보면 `caption`을 기존 key 배열에 추가할 수 있지만, 그 방식은 movable state의 목록을 호출자가 계속 알아야 한다. 새로운 image/graph 전용 속성이 추가될 때마다 같은 누락 문제가 반복된다.

`slot.content`를 하나의 단위로 만들면 swap은 객체 참조 교환 하나로 정의되고 grid rebuild도 동일한 단위를 보존할 수 있다. 추가된 구조 복잡도는 compatibility accessor와 normalization boundary에 집중되고, 대신 이후 콘텐츠 확장에서 swap/rebuild 코드를 수정할 필요가 줄어들기 때문에 기능·구현·확장 자유도 대비 더 적절하다.

FFPX v3를 동시에 변경하지 않은 이유는 이번 문제의 원인이 런타임 구조에 있고 외부 파일 형식 변경이 필요하지 않기 때문이다. non-enumerable accessor와 `toJSON()`을 통해 기존 flat representation을 유지하면 불필요한 포맷 버전 증가를 피할 수 있다.

## 선택하지 않은 방향

- `caption`만 기존 swap key 배열에 추가하는 방법은 선택하지 않았다. 현재 증상만 고치고 구조적 누락 위험을 남긴다.
- `SLOT_CONTENT_FIELDS` 같은 공통 배열로 movable field를 모으는 방법은 선택하지 않았다. hardcoded enumeration 위치만 옮길 뿐 새 필드 추가 시 수정 의무가 남는다.
- slot 객체 전체를 swap하는 방법은 선택하지 않았다. `id`, 좌표, span, hidden 같은 물리 슬롯 identity까지 이동해 요구 동작과 달라진다.
- 모든 기존 접근을 즉시 `slot.content.*`로 바꾸는 방법은 선택하지 않았다. 변경 범위와 회귀 위험이 지나치게 커지므로 compatibility accessor를 사용한다.
- FFPX v4로 즉시 변경하는 방법은 선택하지 않았다. 현재 필요한 동작은 v3 flat serialization을 유지하면서 구현할 수 있다.
- `swapSlotContents()` 내부에서 직접 mutation 후 `notify()`만 보내는 기존 패턴은 유지하지 않았다. slot domain mutation을 EFSM action으로 이동해 다른 상태 변경 경로와 일치시킨다.

## 적용 전 검증

로컬의 저장소 업로드본과 동일한 `Fast-figure.html`을 기준으로 다음 검사를 완료했다.

- 메인 inline JavaScript를 추출해 `node --check` 통과.
- legacy flat slot을 `slot.content`로 normalize하는 합성 테스트 통과.
- 두 slot의 `content` 객체 전체 교환 시 `caption`과 임의의 미래 필드가 함께 이동하는 테스트 통과.
- `projectClone()` 호출 시 `content`가 외부 representation에 노출되지 않고 기존 `chart`, `imageId`, `contentType`, `caption` flat 필드가 생성되는 FFPX v3 호환 테스트 통과.
- 생성한 patch를 원본 파일에 `git apply --check` 후 적용했을 때 후보 파일과 byte-for-byte 일치함을 확인.
- 적용 결과에 대해 `git diff --check` 통과.
- 기존 `let keys = ["chart", "imageId", "contentType"]` swap 목록이 제거되는 것을 확인.
- `PACKAGE_FORMAT_VERSION = 3` 유지 확인.

## 적용 후 확인할 항목

GitHub Actions는 패치 적용 전에 다시 `git apply --check`, 적용 후 `git diff --check`, 메인 JavaScript `node --check`를 실행한다.

실제 브라우저 회귀 테스트에서는 다음을 추가 확인해야 한다.

- graph + caption ↔ 빈 슬롯
- graph + caption ↔ graph + caption
- image + caption ↔ graph + caption
- 선택 슬롯이 콘텐츠와 함께 상대 슬롯으로 이동하는지
- graph object selection과 asset selection이 swap 후 해제되는지
- layout/caption overlay가 열린 상태에서 상태 불일치가 없는지
- grid resize/rebuild 후 swapped content와 caption이 유지되는지
- FFPX v3 export/import roundtrip
- FFSX import/export
- merge/split, label, caption editor 회귀

## 패치에 포함되지 않은 변경사항

`20260831-006.patch`와 이 설명 파일 자체는 패치 본문에 포함하지 않는다.

실제 `Fast-figure.html` 적용은 `.github/workflows/apply-fast-figure-patch.yml`이 이 패치 파일의 push를 한 번 감지해 수행한다. 워크플로는 `Fast-figure.html`만 수정하며, Actions가 만든 커밋은 `agent_space/patches/*.patch`를 변경하지 않으므로 재실행되지 않는다.
