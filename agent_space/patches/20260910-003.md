# 20260910-003 — Mantine print/export ownership

## 목적
WIP Mantine 포팅에서 print/export UI를 legacy form control에 의존하지 않는 독립적인 Mantine ownership으로 옮긴다. 출력 렌더링 알고리즘은 기존 구현을 그대로 재사용하고 UI 입력/상태 전달만 값 기반 경계로 정리한다.

## 변경
- `exportDashboard(capture, options)`가 선택적으로 `{ dpi, format, onStatus }`를 받도록 확장한다.
- `exportDashboardTarget(options)`가 선택적으로 `{ width, height, dpi, format, onStatus }`를 받도록 확장한다.
- options가 없을 때는 기존 legacy print controls를 그대로 읽고 쓰므로 기존 UI 경로도 WIP 동안 유지된다.
- options가 있을 때는 legacy `#printWidth/#printHeight/#printDpi/#printFormat`을 source로 사용하지 않으며 legacy print control에 값을 되쓰지 않는다.
- `FastFigurePrintOverlay` Mantine Modal을 추가한다.
- PNG/JPEG, DPI 36–1200, 폭 100–20000, 높이 100–20000 또는 빈 값 자동 높이를 제공한다.
- 설정 크기 저장은 기존 `PRINT_EXPORT` lifecycle + `exportDashboardTarget(options)`에 연결한다.
- 현재 화면 캡처는 기존 `CAPTURE_EXPORT` lifecycle + `exportDashboard(true, options)`에 연결한다.
- 출력 진행/오류 문구는 React local status에 전달하며 영속 상태로 저장하지 않는다.

## 선택 이유
print/export의 실제 기능은 이미 `exportDashboard`와 `exportDashboardTarget`에 구현되어 있다. Mantine용 별도 export 알고리즘을 복제하면 출력 규칙이 두 source of truth로 갈라진다. 반대로 legacy input을 Mantine에서 `.value`로 쓰고 기존 버튼을 호출하면 금지된 bridge가 된다. 따라서 기존 core가 값 객체를 직접 받도록 확장하는 것이 가장 독립적이고 일관된 경계다.

## 기각안
- Mantine에서 legacy print input의 `.value`를 채우고 `#savePrint/#capturePrint.click()` 호출: legacy DOM bridge이므로 기각.
- React에서 export 알고리즘 전체 복제: 기능 규칙 중복과 장기 divergence 때문에 기각.
- print renderer를 새로 작성: 현재 포팅 목적에 불필요하며 기존 renderer를 보존한다.

## Source of truth / EFSM 영향
프로젝트/레이아웃/캡션/레이블/차트/이미지는 기존 project model이 계속 유일한 source of truth다. print width/height/DPI/format은 export 호출 시점의 일회성 UI 값이며 영속 project 상태가 아니다. 기존 `PRINT_EXPORT`/`CAPTURE_EXPORT` lifecycle과 export renderer를 그대로 사용한다. FFPX schema와 functional EFSM은 변경하지 않는다.

## WIP 제한
legacy print panel과 handler는 아직 제거하지 않는다. Mantine Modal과 legacy overlay DOM이 공존할 수 있으며 최종 cutover에서 legacy popup lifecycle, focus/outside-click, 중복 markup을 정리한다. 현재 단계에서는 독립적인 Mantine 기능 경로를 먼저 완성한다.

## 검증
workflow의 `git apply --check`, JavaScript syntax, portable build, split/portable `file://` smoke를 통과해야 한다. 최종 pixel/parity 검증은 WIP 통합 단계에서 수행한다.

## Rollback
이 패치를 역적용하면 value-based export options와 Mantine Print Modal이 제거되고 기존 legacy print/export 경로만 남는다. project data/schema migration은 필요하지 않다.
