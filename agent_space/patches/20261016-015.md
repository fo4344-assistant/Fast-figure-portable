## 의미·책임·참조

- Application public wrapper가 command tuple의 committed를 검사한 뒤 captions.readGlobal/readSlot, public labels.readState, appearance.readPalette를 반환한다. command 13개는 미commit/명시적 취소 False, throw/rejection 전파다. command 성공 뒤 query/render/notification failure는 숨은 rollback/과거 성공 값으로 위장하지 않는다.
- caption global/explicit slot owner를 보존한다. 공개 label read는 현재 Frontend slot identity만 Backend에 전달하고 current layout에서 reference geometry를 계산한다. none/missing 선택은 1x1 표시 reference이며 slot 생성이나 선택 변경이 아니다.
- label reset은 기존 setPosition(0, 0) command를 재사용한다. finish는 완료 알림과 현재 read 반환이며 position의 두 번째 commit이 없다.
- appearance reset은 Backend DEFAULT_UI_PALETTE를 import한 copy를 같은 setPalette 경로에 전달한다. r30 전체 palette 의미를 partial merge로 바꾸지 않는다.
- hierarchy/authority와 기존 87개 public inventory는 유지한다. 새 API/envelope/persistent mirror를 만들지 않는다.

## 선택 이유·기각 대안

- 성공은 bool보다 owner의 detached read: 기존 annotation read와 UI palette reset draft 소비를 보존한다. 내부 orchestration tuple 공개는 public 반환과 renderer/result 내부 경계를 섞으므로 제외한다.
- 미commit False는 이미 선언된 image/print 설정의 성공 read/거부 규칙과 일관되게 이 설정군에만 적용한다. 모든 graph/asset/lifecycle failure를 False로 바꾸는 방식은 기존 결과 의미를 훼손하므로 제외한다.
- mutation projection을 반환/다음 candidate로 보관하는 방식 제외: success read는 commit 후 current authority에서 다시 계산한다. source of truth를 공유 snapshot으로 대체하지 않는다.
- reset/finish 전용 command·preview authority·generic result registry/framework 추가 제외: 기존 position/palette command와 공식 read만으로 충분하다.
- JS부터 수정하거나 하위 동작을 상위 권위로 자동 채택하는 방향 제외: Source-first를 유지한다. JS wrapper/UI는 호환성 자료로만 읽었다.
