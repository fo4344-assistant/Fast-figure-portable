# 20261001-014 — Source Script r5 slot-local ownership과 caption semantics 확정

## 변경 원인

사용자가 slot object가 GUI layout의 특정 slot 위치에 연결되는 단위이며,
각 slot에만 적용되는 하위 내용은 slot object의 하위 속성을 기본값으로 해야 한다고 명시했다.

또한:

- slot별 caption은 해당 slot object의 속성
- slot caption 추가/편집은 이 속성을 UI에 노출하거나 text로 사용할 수 있게 하는 기능
- global caption은 project-level property
- slot object가 layout에서 이동하면 그 하위 속성도 함께 이동

이라는 의미가 명시되었다.

이 명시 요구로 r4의 마지막 의미적 closure blocker였던 caption operation semantics를 확정한다.

## 의미 변경

### ownership

- 특정 slot에만 적용되는 persistent 값은 slot object 아래에 둔다.
- chart/image/contentType과 slot.caption은 같은 slot object에 귀속된 local state다.
- global caption만 project annotations.captions 아래의 project property다.
- persistent project `slotMode`는 Source Script에서 제거한다.
- global/selected-slot 중 무엇을 UI가 편집하는지는 UI/runtime editor target이다.

### slot caption UI

- slot caption 편집은 selected slot의 `slot.caption`을 직접 노출하고 수정한다.
- placeholder는 UI projection이며 slot.caption에 자동 저장하지 않는다.
- “slot captions 추가”는 slot.caption들을 text로 계산해 global caption text에 명시적으로 삽입하는 command다.
- 삽입 작업은 source slot.caption을 변경하지 않는다.

### layout operations

- swap: slot-local properties 전체가 함께 상대 GUI 위치로 이동
- merge:
  - non-default slot-local state를 가진 source slot은 최대 하나
  - 하나이면 contentType/chart/image/caption을 함께 anchor로 이동
  - 둘 이상이면 암묵적 합성/문자열 결합 없이 merge 거부
- split:
  - anchor slot object의 local properties는 anchor에 유지
  - 복원되는 slot들은 local defaults로 시작
- reset:
  - slot-local properties 전체를 defaults로 되돌림
  - explicit slot caption도 함께 제거
- FFSX:
  - chart와 slot-local caption을 같은 slot package 의미로 target slot에 적용

## 선택 이유

slot object가 GUI 위치에 연결되는 이동 단위라면 그 하위 속성 중 caption만 좌표 위치에 고정하는 것은 ownership 규칙을 깨뜨린다.
반대로 global caption은 특정 slot의 하위 정보가 아니므로 project-level property가 자연스럽다.

이 구분을 사용하면 별도 persistent slot-caption mode, caption 이동 예외, merge 후 caption 특수 처리가 필요하지 않다.

## 기존 안을 채택하지 않은 기록

r4까지 사용한 다음 안은 더 이상 채택하지 않는다.

- slot caption을 slot-local state로 저장하면서도 swap/merge/split/reset 이동 의미는 별도 미확정 annotation rule로 두는 안

비채택 이유:

사용자 명시 요구에 따라 slot caption의 authoritative owner가 slot object로 확정되었다.
owner object가 이동하는데 child property만 원래 GUI 위치에 남기는 것은 같은 slot object의 상태를 분리하므로 일관되지 않다.

또한 persistent `slotMode`를 project property로 두는 안도 채택하지 않는다.
이는 figure state가 아니라 어떤 caption target을 현재 UI에서 편집 중인지 나타내는 interaction state이기 때문이다.

## 닫힘 판정 영향

caption ownership과 swap/merge/split/reset/FFSX semantics는 닫혔다.

남은 Source Script closure 작업은 의미 결정이 아니라:

- application_fsm.py의 candidate-first mutation/event contract 정규화
- api_ui.py의 method-level public API contract 완결
- 전체 Source Script closure review

이다.

따라서 r5는 current/open으로 유지한다.

## 하위 단계 전파 범위

향후 pseudocode/source code에서:

- persistent slotCaptionsEnabled/slotMode 제거 또는 UI runtime state로 이동
- slot caption placeholder 자동 저장 제거
- swap 시 caption 함께 이동
- merge 시 non-default slot-local payload를 원자적으로 이동
- reset 시 slot caption 포함 local state reset
- slot caption 편집 API와 global caption API 분리
- slot captions → global caption text insertion을 명시적 command로 유지

해야 한다.
