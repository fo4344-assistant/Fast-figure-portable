# 20260902-021 — graph object 목록 selector hunk count 교정

## 배경

`20260902-019`와 `020`은 모두 `git apply --check`에서 실패했고 HTML에는 적용되지 않았다.

`020`을 다시 계산한 결과 selector insertion은 실제로 35줄인데 unified diff hunk header가 기존 5줄 + 추가 32줄인 것처럼 `+37`로 기록되어 있었다.

정확한 hunk count는:

```text
old: 5 lines
added: 35 lines
new: 40 lines
```

이다.

따라서 실패 원인은 selector 코드나 현재 source context가 아니라 patch metadata의 line-count 오류다.

## 목적

`020`과 동일한 `selectedGraphObjectsModel()`을 정확한 unified diff hunk count로 적용한다.

## 변경 내용

- 앱 버전 `1.1.66-alpha` → `1.1.67-alpha`
- `selectedGraphObjectsModel(slot = getSelectedSlot())` 추가
- bridge는 아직 추가하지 않음

selector 의미는 `019/020` 설명과 동일하다.

- canonical `chart.editor.objects` 직접 read
- `ensureGraphObjects()` 호출 없음
- selected index snapshot
- object CSV 이름 파생
- 기존 graph object list label 의미 보존
- object color fallback은 display에서만 계산
- 모든 반환 item/array/container freeze

## source of truth

- 목록: `chart.editor.objects`
- 선택: `selectedObjectIndex` / 기존 graphObject EFSM
- CSV: object.csvId가 가리키는 project CSV
- label/color fallback: presentation 파생값

새 persisted 상태를 만들지 않는다.

## 변경하지 않음

- bridge
- 목록 action
- `selectGraphObject()`
- `saveGraphObjects()`
- `renderGraphObjects()`
- EFSM events/actions
- renderer/import/export

## 실패 기록 처리

`019`와 `020`은 overwrite하지 않고 실패 기록으로 유지한다. 이 문서는 실패 원인과 정확한 재생성 근거를 남긴다.

## 검증

- `git apply --check`
- 실제 apply
- `git diff --check`
- inline JavaScript `node --check`
- 적용 commit diff에서 selector 외 기능 변경이 없는지 확인

## rollback

- selector 제거
- 앱 버전 `1.1.66-alpha` 복원

## 후속

성공 후 `022`에서 `fastFigureUiBridge.readGraphObjects()` 메서드 하나만 별도 추가한다.
