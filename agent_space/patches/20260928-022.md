# 20260928-022

## 목적과 변경 내용

활성 Mantine 그래프 파일 입출력과 프로젝트 자산 삭제의 SoT/API 경계를 정리한다. FFSX/Plotly JSON export는 기존 core 명령을 `FastFigureApi.graphs`에서 제공하고, import는 선택 슬롯을 core에서 읽어 기존 `importSlotFile`에 전달한다. import 오류 경로의 legacy CSV DOM control 갱신 호출을 제거한다.

프로젝트 CSV/이미지 삭제 확인창은 선택 자산과 참조 수를 `FastFigureApi.assets.readDeletionTarget()`에서 읽는다. 실제 삭제·참조 그래프 오브젝트 제거·이미지 슬롯 초기화·선택 해제·renderer 갱신은 `assets.delete()`의 core 명령에 모은다. 기존 EFSM 이벤트, 보호된 기본 CSV 제한, 확인창과 결과 메시지의 의미를 유지한다.

## 선택 이유

삭제 확인 UI는 표시와 승인 입력만 담당하고, 참조 관계와 연쇄 변경은 프로젝트/EFSM이 소유해야 한다. 그래프 파일 UI도 선택 슬롯 객체와 legacy control을 직접 다루지 않으면서 기존 기능 명령을 호출해야 한다. 새 저장소나 화면 공유 상태 없이 매 요청 때 현재 선택 및 프로젝트에서 값을 읽는다.

## 고려했지만 선택하지 않은 방향

- **자산 참조 목록을 React state에 저장해 삭제 시 사용:** 확인창이 열린 동안 프로젝트가 바뀌면 참조 목록이 낡고, 프로젝트 관계의 중복 SoT가 된다.
- **CSV/이미지 삭제를 서로 다른 Mantine 이벤트 핸들러에 유지:** 같은 삭제 확인 흐름에서 연쇄 EFSM 변경과 renderer 호출이 계속 UI에 남는다.
- **그래프 파일 import 실패 시 legacy CSV control을 계속 갱신:** 제거 대상 native UI의 DOM을 Mantine 오류 처리에 의존시키며, 프로젝트 상태를 갱신하는 명령이 아니다.

## 범위와 후속 작업

이 패치는 그래프 파일 입출력과 자산 삭제 ownership을 다룬다. 프로젝트 트리의 이동·휴지통·충돌 처리 및 기타 직접 접근, legacy native graph UI 제거, annotation/image/layout/print-export SoT 감사와 전체 상호작용 회귀는 포함하지 않는다. 프로젝트 파일 schema는 변경하지 않는다. 역적용하면 UI의 직접 삭제 로직과 import 오류의 legacy control 갱신으로 돌아간다.
