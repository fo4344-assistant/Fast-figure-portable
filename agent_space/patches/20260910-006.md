# 20260910-006 — Print export value entry 적용

## 목적
003~005의 unified diff 표현 문제를 반복하지 않고 현재 source의 실제 작은 context 단위로 print/export core를 값 기반 entry로 전환한다. 이는 별도 선행 설계가 아니라 Mantine print ownership 구현 자체의 core 부분이다.

## 변경
- `exportDashboard(capture, options)`가 `dpi`, `format`, `onStatus`를 직접 받는다.
- `exportDashboardTarget(options)`가 `width`, `height`, `dpi`, `format`, `onStatus`를 직접 받는다.
- options가 있는 경우 legacy print controls를 입력 source나 출력 projection으로 사용하지 않는다.
- options가 없는 기존 legacy 호출은 기존 동작을 유지한다.

## 이전 실패와의 관계
003~005는 application source에 적용되지 않았다. 006은 동일 구현을 작은 exact-context hunk로 표현하여 patch 적용 안정성을 높인다. 성공 즉시 후속 patch에서 같은 ownership의 Mantine Modal을 연결한다.

## Source of truth / EFSM 영향
출력 알고리즘과 project model은 기존 구현을 유지한다. options는 일회성 호출 값이며 영속 상태가 아니다. FFPX schema와 EFSM 의미는 변경하지 않는다.

## WIP
현재 빌드는 WIP이며 core entry가 먼저 적용된 직후 Mantine print UI를 직접 연결한다. 이를 별도 장기 abstraction으로 취급하지 않는다.

## 검증
workflow의 git apply, JS syntax, portable build, split/portable smoke를 통과해야 한다.

## Rollback
역적용 시 기존 DOM 기반 export entry로 돌아간다.
