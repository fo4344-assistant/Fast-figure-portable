# 20260906-027

## 목적

Mantine UI cutover에서 기존 확인 절차를 제거하지 않고, generic confirmation을 Mantine `Modal`로 통합할 수 있는 공통 경계를 추가합니다.

이번 패치는 첫 적용 대상으로 휴지통 비우기를 선택합니다. 기존 기능인 참조 개수 경고, 취소 가능성, 영구 삭제 확인, FSM 전이, 상태 메시지는 그대로 유지합니다.

## 변경 내용

- 공통 `FastFigureConfirmationStaging`을 추가합니다.
  - Mantine `Modal`, `Button`, `Group`, `Stack`, `Text`를 사용합니다.
  - 닫기/Escape/backdrop/focus/z-index 같은 generic dialog lifecycle은 Mantine에 맡깁니다.
- asset action 실행 전에 confirmation descriptor를 조회할 수 있는 bridge 경계를 추가합니다.
- `emptyProjectTrash()`를 다음 세 책임으로 분리합니다.
  - confirmation 내용 계산
  - 실제 휴지통 비우기 command
  - 현재 legacy UI용 `window.confirm` adapter
- Mantine asset action menu에서는 휴지통 비우기를 `window.confirm`으로 보내지 않고 Mantine confirmation modal을 거쳐 동일 command를 실행합니다.
- 앱 빌드를 `1.1.131-alpha`로 올립니다.

## 선택 이유

Mantine 전환의 목표는 기능 축소가 아니라 일반 UI 규칙의 통합입니다. 기존 확인 절차를 없애는 대신, 여러 파괴적 작업에서 재사용할 수 있는 상위 confirmation UI로 승격하면 다음 항목들도 같은 구조에 통합할 수 있습니다.

- 슬롯 초기화
- CSV/이미지 삭제
- 휴지통 이동 시 참조 제거 경고
- 휴지통 영구 비우기
- 필요한 경우 파일 교체 확인

이렇게 하면 각각의 `window.confirm`과 bespoke popup 규칙을 개별 유지하지 않고 Mantine의 modal lifecycle을 공통으로 사용할 수 있습니다.

## 기능 보존

이번 패치는 휴지통 비우기의 다음 의미를 유지합니다.

- 휴지통 자산 참조가 남아 있으면 참조 개수를 경고합니다.
- 사용자는 취소할 수 있습니다.
- 확인 후 기존 `PROJECT_TRASH_EMPTIED` FSM event를 그대로 사용합니다.
- 성공 후 기존 directory/CSV/image 삭제 수를 상태 메시지로 표시합니다.
- 실패 시 기존 오류 상태 메시지를 유지합니다.

FFPX/FFSX 파일 의미나 schema, graph/image/layout domain renderer, EFSM transition 정의는 변경하지 않습니다.

## 고려했지만 선택하지 않은 방향

### 기존 `window.confirm` 유지

Mantine 단일 UI owner 목표와 맞지 않습니다. 브라우저 기본 dialog는 크기, focus, close lifecycle, 시각 규칙을 Mantine과 통합할 수 없습니다.

### 확인 절차 제거

기능 축소이므로 선택하지 않았습니다. 파괴적 동작의 사용자 확인은 실제 기능입니다.

### 모든 `window.confirm`/`prompt`를 한 패치에서 제거

파일 충돌, drag/drop, 자산 삭제, 슬롯 초기화는 각각 참조 정리와 rollback 의미가 달라 회귀 위험이 큽니다. 공통 confirmation UI를 먼저 만들고 기능별 command 경계를 순차적으로 연결하는 편이 rollback과 검증에 유리합니다.

### legacy dialog DOM을 Mantine 안으로 이동

legacy UI를 보존하는 우회가 되어 최종 구조와 맞지 않으므로 선택하지 않았습니다.

## 위험 요소

- Mantine asset action menu에서 confirmation context가 오래된 selection을 가리키지 않아야 합니다. 이번 구현은 dialog를 열 때 frozen action context를 함께 저장하고, 확인 시 그 context와 action key를 그대로 사용합니다.
- legacy UI가 아직 active인 동안 기존 `emptyProjectTrash()`는 `window.confirm` adapter를 계속 사용합니다. 이는 임시 cutover 경계이며 최종 legacy UI 제거 시 함께 삭제 대상입니다.

## 후속 작업

같은 confirmation 구조에 슬롯 초기화와 자산 삭제를 연결하고, 폴더 생성은 Mantine text-input modal로 분리합니다. 기능이 Mantine에 동등하게 이관된 순서대로 대응 legacy `window.confirm`/`window.prompt` 및 legacy UI handler를 제거합니다.
