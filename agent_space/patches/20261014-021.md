# 20261014-021 — Audit FFPX EFSM and interface FSM responsibilities

## 목적

plan-015 F 단계로 현재 Source Script와 application runtime의 state/mutation/read/renderer 책임을 실제 의미 기준으로 분류한다.

## 핵심 확인

- activeProject는 이미 단일 FFPX ProjectObject authority다.
- 현재 appFSM state vector는 lifecycle/workspace/overlay/selection 등 interface/runtime state다.
- 문제는 FFPX persistent mutation action이 workspace region event에 결합되어 있다는 점이다.
- plan-014의 send-completion renderer boundary는 두 FSM 분리의 orchestration 기반으로 재사용할 수 있다.

## 선택 이유

class 이름을 먼저 나누거나 모든 UI-local state를 새 FSM에 넣는 방식이 아니라, authority와 transition 의미를 기준으로 분리 범위를 먼저 닫아야 Source Script → PlusCal → Source Code 구조가 일관된다.

## 기각한 방향

- 현재 appFSM 전체를 FFPX EFSM으로 간주.
- activeProject와 별도 project-state copy를 EFSM 내부에 추가.
- 모든 React local state를 interface FSM으로 승격.
- serialization 자체를 EFSM으로 간주.
- legacy appFSM과 새 두 FSM을 장기간 병행하는 bridge.

## 후속

다음 plan-015 G 단계에서 project_efsm / interface_fsm / application orchestration의 Source Script 책임과 명령 순서를 정의한다. 이 감사 patch는 application 의미 파일을 변경하지 않으므로 development revision을 올리지 않는다.
