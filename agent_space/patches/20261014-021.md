# 20261014-021 — Derive verification r20 from pseudocode r8

## 목적

Source Script r22 / pseudocode r8의 explicit project command ownership을 verification model에 반영한다.

## 변경

- Slot Core:
  - reset/swap/grid/merge/split commit result를 대응 projectEFSM command에 매핑한다.
  - 모든 modeled persistent commit이 declared project command에 귀속되는 ownership invariant를 추가한다.
- Interaction Core:
  - CSV 생성, graph-object 변경, project node move, slot data connection commit result를 대응 project command에 매핑한다.
  - 해당 slice의 project command ownership invariant를 추가한다.
- 두 cfg에 새 ownership invariant를 등록한다.
- verification r20 lineage를 Source Script r22 / pseudocode r8로 갱신하고 TLC는 pending으로 둔다.

## 추상화와 생략

image settings, caption settings, label settings, layout style, export settings는 이 두 verification slice가 검사하는 slot/reference/selection/tree invariant를 변경하지 않는다. 별도 authoritative/shared state도 만들지 않으므로 독립 verification state로 복제하지 않는다.

이 생략은 해당 설정 값 자체의 범위 validation을 TLC로 증명한다는 뜻이 아니다. 이후 그 설정이 reference, selection, lifecycle 또는 다른 modeled invariant에 영향을 주게 되면 verification model에 다시 포함해야 한다.

## 선택 이유

새 command 이름만 확인하기 위해 동일 project settings 전체를 verification state에 복제하면 상태공간과 중복 authority 표현만 늘어난다. 기존 commit result에서 command ownership을 파생 invariant로 검사하는 방식이 r22의 책임 경계를 보존하면서 최소 복잡도 원칙에 맞는다.

## 기각

- 모든 r22 command payload를 상태 변수로 추가: 현재 property와 독립적인 상태를 중복 모델링한다.
- 기존 r19 TLC 결과 재사용: r20은 새 r22/r8 lineage이므로 허용하지 않는다.
- Source Code 진행: TLC gate 통과 전에는 금지한다.
