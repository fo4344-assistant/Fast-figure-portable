# 20260910-024 — Remove legacy asset import/tree DOM

## Purpose

Remove legacy DOM that no longer owns any active UI behavior after the Mantine project-data tree and Mantine data actions became the active UI path.

This change follows the clarified compatibility boundary: persisted/interchange file compatibility such as FFPX/FFSX remains in scope, but compatibility with the former custom/legacy UI does not.

## Exact changes

### `Fast-figure.html`

- Remove the legacy hidden `#file` input from the old data fieldset.
- Remove the entire legacy `.asset-tree-shell`, including:
  - `#filePick`
  - `#assetDownload`
  - `#newAssetFolder`
  - `#assetActions`
  - `#assetActionMenu`
  - `#assetTree`
- Keep `#fileName` temporarily because existing non-tree runtime helpers still write status-like selected-file text to it. Its removal belongs to the subsequent legacy-form dependency cleanup rather than being replaced with another compatibility shim.

### `fast-figure.js`

- Remove the legacy `#filePick -> #file.click()` bridge.
- Remove the legacy `#file.onchange` import path.
- Remove `#file` from `connectLifecycleTasksToFSM()` because Mantine data actions run `ASSET_IMPORT` through `runLifecycleTask()` directly.

## Source of truth

The active asset import UI is `FastFigureDataActions`, which owns its own React file input and calls the existing UI-independent import/load functions. The active project tree is `FastFigureProjectDataTree`, derived from `projectDataTreeSnapshot(projectDataTreeObjects())` and app FSM state.

No replacement DOM bridge is introduced.

## FFPX / FFSX compatibility

No file-format code is changed. In particular this patch does not modify:

- FFPX ZIP/XML read/write
- FFSX ZIP/XML read/write
- project/package format versioning
- CSV/image original-byte packaging
- project object validation or import conversion logic

The deleted `#file` input is only the former browser UI entrypoint for ordinary asset import and is unrelated to FFPX/FFSX persistence semantics.

## EFSM / core impact

None. Existing asset import commands, project VFS behavior, data/image model mutations, slot linking, and lifecycle events remain unchanged. Mantine continues to call the same functional loaders and FSM events.

## Rationale

Keeping these controls as hidden fallback UI would preserve a second UI implementation with no current owner. That adds maintenance cost and encourages future code to bridge back to `.click()`/DOM values. Since legacy UI compatibility is not a requirement, removing the obsolete entrypoint is simpler and makes ownership explicit.

## Rejected alternatives

- **Keep the legacy tree hidden as fallback:** rejected; legacy UI compatibility is explicitly not required.
- **Have Mantine trigger `#file.click()`:** rejected; this recreates the forbidden `Mantine -> legacy DOM` bridge.
- **Remove all old data/graph form DOM in the same patch:** rejected only for change isolation. Several remaining runtime helpers still read legacy form values; those dependencies should be removed directly in follow-up patches before deleting their elements.

## Validation

Before queueing, the unified patch was checked with `git apply --check` against synthetic files containing the exact target contexts. Repository CI must additionally pass:

- patch validation/application
- JavaScript syntax check
- portable HTML build
- split/portable Chromium `file://` smoke tests

## Rollback

Revert the application commit for `20260910-024` to restore the former legacy browser file input/tree markup and its ordinary asset-import handler. FFPX/FFSX compatibility is unaffected in either direction.
