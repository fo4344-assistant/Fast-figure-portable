# 20260907-047 — Mantine selected-slot reset confirmation

## Purpose

Replace the selected-slot reset button's legacy `window.confirm()` UI with a Mantine confirmation modal while preserving the existing functional EFSM events and reset behavior.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- `SLOTS_RESET` EFSM definition/action
- `CLEAR_ASSET_SELECTION` EFSM definition/action
- project slots/charts/images model code
- renderer implementation
- legacy reset handler

## Existing behavior preserved

The current legacy reset handler:

1. requires a selected slot,
2. asks for destructive confirmation,
3. sends `SLOTS_RESET` for that slot ID,
4. sends `CLEAR_ASSET_SELECTION`,
5. rerenders the dashboard,
6. reports completion and removed chart IDs to status/debug output.

The Mantine implementation follows the same functional sequence after its own modal confirmation.

## Exact changes

1. Adds presentation-local `resetSlotId` state to `FastFigureDataActions`.
2. Adds a `선택 슬롯 초기화` Mantine button when a slot is selected.
3. Clicking it stores the selected slot ID and opens a Mantine `Modal`.
4. Cancel/close only clears the local modal state.
5. Confirm sends the existing EFSM events directly:
   - `SLOTS_RESET` with the stored slot ID
   - `CLEAR_ASSET_SELECTION`
6. The existing `renderDashboard()`, `status()`, and `debugLog()` side effects are preserved after the EFSM operation.
7. No legacy button `.click()` or `window.confirm()` path is used by the Mantine implementation.
8. The selected slot ID is captured when the dialog opens, so a later selection change cannot silently redirect the destructive action to another slot.

## State ownership

`resetSlotId` is temporary confirmation-dialog state only. Slot contents and selection remain owned by the existing project model and FSM.

## Why this direction

The reset's functional mutation is already expressed through existing EFSM events. The only generic UI primitive that needs replacement is confirmation. Mantine can own that confirmation lifecycle without introducing a bridge or changing EFSM behavior.

## Rejected alternatives

### Calling the legacy `#resetSelectedSlot` button

Rejected because it would make legacy DOM an internal API and still invoke `window.confirm()`.

### Modifying `SLOTS_RESET` for Mantine

Rejected because the current event already performs the required functional reset.

### Moving reset mutation into React state

Rejected because project state must remain under the existing model/EFSM.

## Rollback

Revert the `20260907-047.patch` changes in `fast-figure-ui.js`. No model or EFSM rollback is required.
