# 20260928-012

## 목적과 변경 내용

shell 공통 geometry 수치를 CSS와 React에 따로 하드코딩하던 중복을 Mantine theme의 `other.shell` 한 곳으로 통합한다.

공통 값:

- header height: 57
- initial navbar width: 370
- navbar min width: 360
- navbar max width: 620
- resize handle width: 8

`MantineProvider.cssVariablesResolver`가 같은 theme 값에서 renderer sibling용 CSS 변수를 생성한다.

- `--ff-header-height`
- `--ff-navbar-width`

동적으로 resize/collapse된 실제 renderer offset은 기존처럼 component state에서 `--ff-renderer-navbar-width`로 투영한다.

## 선택 이유

기존에는 같은 header/sidebar geometry가 다음 위치에서 중복 정의되었다.

- custom CSS `--header-height: 57px`
- custom CSS `--sidebar-width: 370px`
- AppShell `header.height: 57`
- React `useState(370)`
- clamp `360/620`
- resize handle `8/-4`

이는 Mantine 도입 목적과 반대되는 구조다. 공통 수치는 Mantine theme 한 곳에 두고 AppShell과 renderer bridge가 같은 값을 읽게 한다.

## Mantine API 확인

현재 vendored runtime에서 `MantineProvider`가 `cssVariablesResolver`를 받고 resolver의 `variables/light/dark` 결과를 지정 selector(기본 `:root`)에 CSS 변수로 생성하는 구현을 확인했다.

## 선택하지 않은 방향

- CSS variable을 다시 source of truth로 두고 React가 `getComputedStyle`로 읽지 않는다.
- shell geometry를 여러 component에 literal로 반복하지 않는다.
- renderer를 AppShell 내부 React DOM으로 재작성하지 않는다.
- 별도 layout config store를 만들지 않는다.
