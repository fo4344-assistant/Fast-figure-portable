# 20261014-030 — Start Source Code EFSM/interface cutover r25 and remove mandatory TLC gate

## 정책 정정

`source-script-policy.md`는 PlusCal/TLA+/TLC 검증이 Source Code 구현의 필수 단계가 아니라고 명시한다.
기존 `check-development-layer-versions.py`는 verification-model이 current/passed가 아니면 Source Code 변경과 current 상태를 금지해 이 정책과 충돌했다.

검사기는 이제:
- Source Code 구현의 필수 상위 단계로 current pseudocode만 요구한다.
- verification fingerprint가 Source Code lineage에 기록된 경우에는 일치 여부만 확인한다.
- TLC pending 자체를 Source Code 변경 금지 사유로 사용하지 않는다.
- 구현 중인 Source Code revision이 `stale`로 남는 것을 허용한다.

## Source Code r25 변경

- 기존 `ApplicationStateMachine`을 UI/runtime 책임의 `InterfaceStateMachine`으로 분리한다.
- persistent ProjectObject command를 소유하는 별도 `ProjectStateMachine/projectEFSM`을 둔다.
- `appFSM`은 기존 호출부 호환을 위한 orchestration facade이며 persistent command는 projectEFSM으로 route한다.
- project commit 뒤 interfaceFSM이 ProjectMutationResult/selectionHints를 받아 selection을 reconcile한다.
- project action이 selectedSlotId/interface state를 직접 바꾸던 주요 경로를 result hint로 전환한다.
- project name, label, appearance, export settings와 더불어 image settings, caption settings, layout style, merge/split을 projectEFSM command로 수렴시킨다.
- directory raw-file batch import를 candidate-first로 계산하고 `ASSETS_IMPORTED` 한 command로 원자적으로 commit한다.
- image model builder는 candidate state를 받아 경로 충돌을 현재 candidate 기준으로 계산할 수 있게 한다.

## 일반 코딩 원칙

- 계산과 mutation을 분리한다: batch parse/candidate 작성 후 한 번 commit한다.
- single source of truth를 유지한다: activeProject만 persistent authority이며 interfaceFSM은 selection/runtime state만 소유한다.
- 기존 application dispatch 경계를 재사용하고 별도 mutation bus를 만들지 않는다.
- merge/split의 domain 계산은 project command action 안에 두고 renderer는 commit 뒤에만 호출한다.
- 기존 UI API 호환을 위해 facade를 두되 별도 authoritative state를 만들지 않는다.

## 아직 남은 범위

r25는 WIP이므로 source-code status를 `stale`로 유지한다.
다음 단계에서 asset delete/reference detach, raw-file-to-slot atomic import, graph editable conversion 등
r23 coverage matrix의 남은 persistent route를 같은 projectEFSM 경계로 수렴시킨 뒤 current로 닫는다.

TLC 결과는 이 구현 진행의 gate로 사용하지 않는다.
