# 20261015-009 — Boundary Core GitHub Actions 검증 경로 보완

## 목적과 변경 내용

plan-016 verification r25의 세 canonical model을 실제 GitHub Actions에서 검증할 수 있도록 기존 `.github/workflows/tla-slot-core.yml`에 누락된 Boundary Core 경로를 추가했다.

- `push.paths`에 `verification/FastFigureBoundaryCore.tla`와 `verification/FastFigureBoundaryCore.cfg`를 추가했다.
- 기존 Slot Core / Interaction Core job은 변경하지 않았다.
- 새 `verify-boundary-core` job에서 기존과 동일한 TLA+ tools v1.7.4 및 SHA-1 pin을 사용한다.
- Boundary Core는 PlusCal algorithm 블록이 없는 직접 TLA+ model이므로 SANY parse 후 TLC를 실행한다.
- workflow 파일 자체의 기존 push path로 인해 의미 변경 커밋이 Actions run을 자동 시작했다.

## 이 방향을 선택한 이유

verification r25 원본 기록은 Slot Core, Interaction Core, Boundary Core 세 모델 모두의 실제 TLC 재검증을 요구한다. 기존 workflow는 앞의 두 모델만 실행하므로 현재 검증 범위를 완전하게 실행할 수 없었다.

새 별도 workflow를 만들거나 TLA+ 도구 체계를 중복하지 않고 기존 canonical verification workflow를 최소 확장했다.

## 고려했으나 선택하지 않은 방향

- **Boundary Core만 로컬에서 별도 실행:** 현재 환경의 외부 다운로드 제약을 이유로 Actions를 사용하지 않는 방향이며 사용자 지시와 AGENT.md 실행 절차에 맞지 않아 기각했다.
- **새 workflow 파일 추가:** 동일 TLA+ 버전과 검증 목적을 중복 관리하므로 기각했다.
- **기존 두 job을 matrix 구조로 전면 재작성:** 현재 필요한 범위보다 큰 구조 변경이므로 기각했다.
- **Boundary Core에 불필요한 PlusCal translation 추가:** 해당 파일은 직접 TLA+ model이므로 의미 없는 단계가 되어 기각했다.

## 확인된 Boundary Core 실패

TLC 로그에서 다음 두 증거를 확인했다.

- `phase`가 변경되면서 동시에 `UNCHANGED`로 지정되었다는 경고
- `read-ready` 상태에서 deadlock

원인은 `ConsumeReadProjection`이 `phase' = "read-consumed"`를 지정한 뒤 `UNCHANGED vars`로 `phase`까지 고정한 verification model 내부 모순이다.

따라서 이 실패는 현재 단계에서 Source Script 또는 PlusCal 반례로 분류하지 않고 verification derivation 오류로 처리한다. 후속 패치에서 model을 수정하고 TLC를 다시 실행해야 한다.

## 기록 범위

같은 basename의 `.patch`는 workflow 의미 변경 커밋의 실제 diff를 기록한다. Contents API에 따라 workflow, patch, 설명 파일이 순차 commit되었으므로 하나의 원자적 commit으로 표현하지 않는다.

Source Script, PlusCal pseudocode, application source와 `development-versions.json`은 이 패치에서 변경하지 않았다.
