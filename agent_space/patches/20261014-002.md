- 기존 재귀 `Stack/Group/Button` tree renderer와 별도 expanded Set을 제거.

## 일반 코딩 정책 적용

- VFS/project state를 Tree local data와 양방향 동기화하지 않는다.
- Tree는 read projection과 interaction intent만 제공하고 mutation은 기존 public command에 수렴한다.
- tree move eligibility와 slot connection eligibility를 하나의 `draggable` 상태로 합치지 않는다.
- 네 overlay가 resize algorithm을 각자 복제하지 않고 공통 component로 통합한다.
- preview width/height를 별도 persistent state로 만들지 않는다.
- swap 후 별도 DOM 임시 patch 대신 기존 renderer entry point를 재사용한다.

## 선택 이유

Mantine 9.5.2 자체 Tree가 hierarchy/keyboard/DnD semantics를 제공하므로 동일 기능을 수동 재귀 UI로 중복 유지할 이유가 없다. resource row 자체가 Tree drag element가 되어 Button-child 때문에 drag 시작이 막혔던 Mantine 포팅 회귀도 제거된다.

## 고려했지만 선택하지 않은 방향

- 기존 Group에 draggable만 다시 붙이기: custom tree hierarchy/DnD 구현을 계속 유지해야 하므로 기각.
- `withDragHandle` 사용: 사용자가 파일 row 자체를 잡아 오른쪽 slot으로 끌던 기존 UX와 맞지 않아 기각.
- Mantine `moveTreeNode` 결과를 project state로 사용: VFS와 별도 authority가 되므로 기각.
- trash asset direct slot link 허용: trash의 reference-detach 의미와 충돌하므로 기각.
- Modal resize 값을 project/FFPX에 저장: UI-local state를 persistent authority로 만드는 것이므로 기각.
- Layout preview 아래 handle을 width resize로 유지: 이번 회귀의 직접 원인이므로 제거.
