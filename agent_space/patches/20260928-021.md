# 20260928-021

## 목적과 변경 내용

`review-011-sot-api-boundary.md`의 그래프 변경/읽기 경계에 따라 활성 Mantine 그래프 데이터·오브젝트, 축·전역 설정, 색상 구성 편집을 core의 `FastFigureApi.graphs`로 연결한다. 기존 `graphEditor*` 명령과 `CHART_LAYOUT_CHANGED`/`GRAPH_OBJECTS_REPLACED` EFSM 이벤트의 의미는 유지한다. 헤더 행 수, 편집 모드, 오브젝트 추가·변경·선택·이동·삭제, 축·전역 설정, 팔레트 적용은 core 명령을 통해 처리한다.

각 영역의 읽기는 프로젝트/선택 SoT에서 해당 작업에 필요한 값을 그때 도출하는 `readData`, `readLayout`, `readPalette`로 좁힌다. 그래프 객체 정규화 계산을 순수 함수로 분리해 화면 읽기가 `chart.editor.objects`를 다시 쓰지 않도록 한다. UI가 받는 객체, 미리보기 행, 설정, 색상은 호출 범위의 사본이며 새로운 공유 상태나 별도 저장소가 아니다. Mantine 색상 미리보기·저장과 기본색 버튼의 기존 동작 의미는 유지한다.

## 선택 이유

기존 활성 UI는 `activeProject`, chart, logic EFSM과 `graphEditor*`를 직접 참조했다. 같은 사용자 기능을 기존 SoT/명령 경계에서 읽고 적용하면 UI가 프로젝트 모델을 소유하지 않으며, renderer와 EFSM은 기존 책임을 유지한다. 읽기 영역을 세 개의 필요한 값으로 한정해 하나의 공용 화면 스냅샷이 다른 기능의 근거가 되는 구조도 피한다.

## 고려했지만 선택하지 않은 방향

- **Mantine 쪽에 그래프 상태 캐시와 동기화 로직을 추가:** 선택 CSV·오브젝트·축 설정의 두 번째 SoT가 되고 EFSM과 어느 값이 최신인지 판정해야 한다.
- **기존 그래프 명령을 UI 파일로 이동:** 프로젝트 변경과 renderer 호출을 프런트엔드가 소유하게 되어 문서의 core 경계를 어긴다.
- **그래프 편집 전체를 한 개의 공용 read model로 제공:** 데이터 미리보기, 축 설정, 팔레트가 필요하지 않은 값까지 함께 읽고 공유 표현에 의존한다.

## 범위와 후속 작업

이번 변경은 활성 Mantine 그래프 데이터·오브젝트, 전역/축 설정, 색상 구성 편집의 SoT 경계다. 프로젝트 이름/자산 트리, 그래프 파일 입출력 등 다른 UI의 직접 접근, legacy native graph UI 제거, annotation/image/layout/print-export 영역의 남은 SoT 감사 및 전체 상호작용 회귀는 이 패치에 포함하지 않는다. 원복 시 해당 세 편집 영역의 직접 접근으로 돌아가며 프로젝트 파일 schema는 바뀌지 않는다.
