# 20260916-015

## 목적과 변경 내용

Mantine graph layout editor가 이미 logic EFSM의 `CHART_LAYOUT_CHANGED`를 직접 사용하고 있는 상태에서, 더 이상 호출되지 않는 legacy native graph layout form 경로를 제거한다.

이번 패치는 다음 두 함수만 제거한다.

- `chartLayoutSettingsFromForm(chart)`
  - native DOM의 title/global/axis input 값을 읽어 chart layout payload를 만들던 legacy form reader
- `applyGraphLayoutSettings()`
  - 위 form reader의 결과를 `CHART_LAYOUT_CHANGED`에 전달하고 선택 plot을 즉시 다시 그리던 legacy native apply handler

Mantine `FastFigureGraphLayoutEditor`는 현재 다음 설정을 `readGlobalSettings(chart)`에서 읽고 `CHART_LAYOUT_CHANGED`로 직접 변경한다.

- graph title
- legend/title/zero-line visibility
- graph font family
- title/legend font size
- 4개 축의 title/range/tick mode/minor ticks/notation/scale/divide/font size/line width/grid/visibility/value visibility

따라서 제거되는 두 함수는 기능 command나 renderer가 아니라 교체 완료된 native UI form ownership이다.

## 선택 이유

`20260916-014`에서 native axis DOM 생성기와 tick-mode installer를 제거한 뒤 current source의 호출 관계를 다시 확인했다.

- `chartLayoutSettingsFromForm()`의 유일한 호출자는 `applyGraphLayoutSettings()`다.
- `applyGraphLayoutSettings()`는 더 이상 다른 source에서 호출되지 않는다.
- active Mantine graph layout editor는 동일한 domain mutation을 `CHART_LAYOUT_CHANGED`를 통해 직접 수행한다.

따라서 두 함수를 한 ownership 단위로 함께 제거하면 native DOM form bridge만 사라지고 logic EFSM과 project/domain state는 변경되지 않는다.

## 보존하는 경계

이번 패치는 다음을 수정하거나 제거하지 않는다.

- `CHART_LAYOUT_CHANGED` event와 `applyChartLayoutChangedAction`
- application logic EFSM / `ApplicationStateMachine`
- `activeProject`, chart model, project schema
- `currentAxes()` / `readGlobalSettings()` / `normalizeGlobalSettings()`
- `axisKey()` 및 Plotly axis semantics
- `chartFigure()`, `layout()`, `traces()`, `renderDashboard()` 등 functional renderer
- Plotly relayout/range synchronization infrastructure
- Mantine `FastFigureGraphLayoutEditor`

즉 UI component/UI form 경로 제거와 logic EFSM 변경을 섞지 않는다.

## 고려했지만 선택하지 않은 방향

### `CHART_LAYOUT_CHANGED`까지 제거

선택하지 않았다. 이 event는 Mantine graph layout editor가 현재 사용하는 logic/domain mutation boundary이므로 legacy UI와 별개다.

### `readAxis()`도 같은 패치에서 제거

선택하지 않았다. `readAxis()`는 아직 `configFromForm()`이 사용하는 native graph object/apply 체인에 포함되어 있다. 그 체인은 다음 ownership 패치에서 `configFromForm()` / `applyGraphSettings()`와 함께 닫힘을 확인한 뒤 제거한다.

### `applyGraphLayoutSettings()`의 Plotly redraw 부분을 별도 command로 추출

선택하지 않았다. active Mantine path는 mutation 후 `renderDashboard()`를 사용하고 있으며, legacy handler의 선택 plot 직접 redraw를 재사용하기 위한 새 bridge를 만드는 것은 WIP 포팅 정책과 맞지 않는다.

### native graph form 전체를 한 번에 제거

선택하지 않았다. object/data form에는 `rows`, `columns`, `configFromForm()`, `applyGraphSettings()` 등 별도 ownership이 남아 있어 layout form과 분리해 검증하는 편이 rollback과 책임 경계가 명확하다.
