# 20261016-024 — Source r37 논리 구조 검토 기록

## 목적·내용

사용자 요청에 따라 현재 Source의 논리 구조를 검토하고 `agent_space/reviews/review-20261016-019-source-r37-logical-structure.md`에 결과를 남겼다. 현재 규칙의 입력→출력 연결, 목적 부합, 실제 중복 후보의 분리/통합 이유를 기록했다. 검토 범위에서 구조적 완결성을 깨는 차단 문제를 발견하지 못했다.

Source를 실행 Python으로 오인하거나 하위 구현에서 정할 세부를 새로운 결함으로 만들지 않았다. 과거 open 기록만으로 같은 문제를 반복하지 않고 현재 annotation/config/export 및 command/reconciliation/package 경로를 확인했다.

## 선택 이유·기각 대안

- 선택: 현재 명세에 대한 정적 경로 추적과 구체적인 분리 이유를 하나의 review에 기록한다. 문제를 발견하지 못한 사실도 그대로 남긴다.
- 기각: 검토를 위해 Source를 재설계하거나 추가 설정/validator/framework를 도입하기. 이번 검토에서 그런 변경이 필요하다는 근거를 발견하지 못했다.
- 기각: runtime/시각 검증을 했다고 표현하거나 하위 stale 상태를 Source의 논리적 결함으로 간주하기. 검토 계층과 실제 수행 범위가 다르다.
- 기각: 검토 문서만으로 metadata를 조용히 closed/current로 바꾸기. 이번 단위는 요청한 논리 검토의 기록이며 Source·하위 lineage 변경을 포함하지 않는다.

## 실제 누적 diff·검사

- baseline: `30af22573c0180d0a76ec596ac73e5c9bebee3c8`.
- 의미 변경 종료: `20c948554a056e9da0acf6c3d9cb01a07d40b5bf`.
- `.patch`는 위 두 실제 commit의 `git diff --binary`다. 새 review 한 파일, 69줄 추가이며 이 patch/설명 쌍은 자기 참조를 피하려고 제외했다.
- endpoint diff의 `git diff --check` 성공. endpoint tree를 격리한 임시 index에서 `git apply --cached --reverse --check` 성공 후 임시 index를 제거했다. 이는 문서 patch의 정적 적용 검사이며 application test가 아니다.
- Contents API로 쓰기 직전 branch HEAD/current blob 또는 new-path 404를 확인하고 순차 기록한다. review 의미 commit 뒤 patch와 설명을 별도 파일 commit으로 추가하므로 원자적 multi-file/same-commit 기록이라고 주장하지 않는다. 새 review/patch 순번도 현재 tree에서 확인했다.

## 제외·상태
