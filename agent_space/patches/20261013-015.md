# 20261013-015 — Run r17 interaction verification on push

## 목적

GitHub Actions의 기존 TLA 검증 workflow를 사용해 canonical r17 interaction verification module을 공식 TLA+ tools 1.7.4로 번역, SANY parse, TLC model check한다.

## 확인한 기존 실행 방식

기존 `TLA Slot Core` workflow는 `workflow_dispatch`와 `push.paths`를 모두 지원하지만, r6의 성공 validation review에는 실제 tested commit과 Actions run id가 기록되어 있고 검증 파일/실행 wrapper를 push하여 실행한 방식이 사용되었다.

현재 r17에서 새로 추가한 `verification/FastFigureInteractionCore.tla/.cfg`는 기존 `push.paths`에 없었기 때문에 해당 파일 변경만으로는 workflow가 시작되지 않는다.

## 변경

- `verification/FastFigureInteractionCore.tla`
- `verification/FastFigureInteractionCore.cfg`

를 `push.paths`에 추가한다.

기존 slot-core job은 의미와 명령을 보존하고 이름만 `verify-slot-core`로 명확히 한다.

별도 `verify-interaction-core` job을 추가하여:

1. TLA+ tools v1.7.4 다운로드
2. 기존 고정 SHA-1 검증
3. `pcal.trans FastFigureInteractionCore.tla`
4. `tla2sany.SANY FastFigureInteractionCore.tla`
5. `tlc2.TLC -config FastFigureInteractionCore.cfg FastFigureInteractionCore.tla`

순서로 실행한다.

## 선택 이유

workflow_dispatch를 별도로 호출하는 대신 workflow 파일 자체를 main에 push하면 기존 push trigger 규칙으로 즉시 실행되고, tested commit이 repository history와 직접 연결된다. 이는 이전 r6 검증 기록 방식과 동일한 형태의 증거를 남긴다.

## 기각한 방향

- interaction module을 기존 2x2 slot wrapper에 억지로 포함하지 않는다.
- 기존 slot-core 검증을 제거하지 않는다.
- TLC를 실행하지 않고 metadata만 passed로 바꾸지 않는다.
- GitHub Actions 외부의 미확인 TLA+ binary를 사용하지 않는다.

## 후속

이 push가 만든 workflow run의 두 job 결과와 로그를 확인한다. interaction model에서 translator/parser/model-check 오류가 나오면 오류를 verification 계층에서 수정하고 다시 push한다. 모두 통과한 뒤에만 validation review 및 verification-model current/passed 전환을 수행한다.
