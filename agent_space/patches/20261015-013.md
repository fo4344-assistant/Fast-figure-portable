## 선택한 방향과 이유

`normalizeSlotContent`는 slot.content 교체 및 비열거형 속성 설치 등 명시적인 write operation이다. 이를 read/renderer API에서 사용하는 것은 ProjectObject authority를 우회 수정한다.

따라서 별도 project store나 state cache를 만들지 않고 기존 `readImageSettings` 계산만 수행하여 원본 참조를 보존한다. 작은 단위의 freeze snapshot은 Frontend에 authoritative object를 노출하지 않도록 한다.

## 검토했으나 선택하지 않은 다른 방향

- `normalizeSlotContent`를 renderer/read 경로에 그대로 두기: 읽기 부작용을 유지하므로 기각.
- live slot에 `JSON.stringify`를 호출해 복제: slot custom `toJSON`과 `slotLegacyState`의 정규화 호출을 유발하므로 기각.
- 별도 project mirror나 장기 image settings store 도입: 중복 source of truth가 되므로 기각.
- Plan 016 전체가 current인 것처럼 Source Code r30을 닫기: Interface FSM와 renderer의 직접 Backend 조회가 남아 있으므로 기각.
