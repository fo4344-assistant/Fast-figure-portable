# 20260916-002 — Remove native print/export control fallbacks

## Purpose
Continue the post-Mantine cleanup after annotation ownership completion by removing the remaining native print/export control DOM fallbacks from the two export entry points while preserving the export algorithms and active Mantine print overlay behavior.

## Exact changes
- In `exportDashboard(capture = false, options = null)`:
  - replace fallback writes to deleted `printStatus` DOM with an optional `options.onStatus` sink;
  - replace deleted `printWidth` / `printHeight` reads with explicit option values, falling back to current rendered dashboard geometry;
  - replace deleted `printDpi` / `printFormat` reads with option/default values;
  - remove native control writeback after value normalization.
- In `exportDashboardTarget(options = null)`:
  - replace deleted `printStatus` fallback with an optional `options.onStatus` sink;
  - replace deleted width/height/DPI/format control reads with option/default values;
  - remove native width/DPI/height writeback.

The active `FastFigurePrintOverlay` already passes explicit options for target export and explicit DPI/format/status options for screen capture, so its behavior is preserved.

## Why this direction
The native print markup is absent from `Fast-figure.html`, and the Mantine print overlay owns all current print/export inputs. Keeping fallback references to `printStatus`, `printWidth`, `printHeight`, `printDpi`, and `printFormat` leaves dead DOM ownership inside otherwise reusable export functions and can produce null-control failures if those fallback branches are reached.

The export functions should consume values, project state, renderer geometry, and an optional status callback; they should not depend on removed editor controls. This matches `plan-006`'s direct command/renderer boundary and single-owner policy without changing the export implementation itself.

## Rejected alternatives
- Remove or rewrite `exportDashboard` / `exportDashboardTarget`: rejected because their canvas, Plotly, image, caption, label, DPI, and geometry logic remains live and belongs to the functional renderer/export layer.
- Move export algorithms into React: rejected because export rendering is UI-independent functionality and should remain outside Mantine components.
- Recreate hidden native print controls for compatibility: rejected because hidden bridge DOM violates the current ownership policy.
- Require a non-null options object and throw otherwise: rejected because the functions can remain robust and UI-independent with sensible defaults without adding complexity.
- Change raster limits, DPI range, image quality, filename format, or caption/label geometry: rejected as unrelated behavior changes.

## Source of truth
Project/layout/annotation/chart/image state remains authoritative in the existing project model and snapshots. `FastFigurePrintOverlay` owns print input drafts. Export functions consume passed values and current renderer/project geometry but do not own UI state.

## EFSM/core impact
No intended state-transition or persistence change. `PRINT_EXPORT` and `CAPTURE_EXPORT` lifecycle events remain unchanged. FFPX/FFSX meaning, project schema, export geometry, DPI metadata, raster validation, actual dashboard/caption/label rendering, and file naming remain unchanged.
