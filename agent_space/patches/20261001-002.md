# 20261001-002 — 회귀 테스트 슬롯 선택 helper 수정

## 목적과 변경 내용

`browser-regression.js`의 `select(slot)` helper를 슬롯 선택 토글 호출에서 선택 상태 보장 동작으로 바꾼다.

기존 helper는 항상 `api.slots.select(slot.id)`를 호출했다. Fast Figure의 슬롯 선택 command는 이미 선택된 슬롯에 같은 ID를 다시 전달하면 선택을 해제한다. 따라서 연속된 회귀 항목이 같은 슬롯을 사용할 경우 테스트 준비 단계가 슬롯을 선택하는 대신 선택을 해제할 수 있었다.

수정 후 helper는 `api.slots.readSelected()`로 현재 선택을 확인하고, 대상 슬롯이 아직 선택되지 않은 경우에만 `api.slots.select(slot.id)`를 호출한다.

## 선택 이유

회귀 테스트의 `select(slot)`는 호출 이름과 모든 사용 위치에서 “이 슬롯을 선택 상태로 만든다”는 준비 동작으로 사용된다. 애플리케이션의 실제 슬롯 선택 토글 semantics를 변경할 이유가 없으며, 테스트 helper가 그 semantics를 정확히 감싸는 것이 최소 변경이다.

20261001-001 이후 실행에서 10번 asset delete cascade가 slot 5를 선택한 채 끝난 뒤 11번 move-to-trash cascade가 같은 slot 5에 `select(slot)`를 다시 호출했다. 이 호출이 선택을 해제하여 `api.graphs.addObject()`가 그래프 슬롯 없이 종료했고, 새로 추가한 CSV 참조가 존재하지 않았다.

## 고려했지만 선택하지 않은 방향

### 각 테스트 시작 시 강제로 선택 해제 후 다시 선택

불필요한 상태 전이를 추가하므로 선택하지 않았다. 현재 선택이 이미 대상이면 그대로 사용하는 편이 단순하다.

### 테스트 11에서만 select 호출 제거

테스트 순서에 의존하게 되므로 선택하지 않았다. 개별 테스트가 의도한 준비 상태를 helper 수준에서 보장하는 편이 안정적이다.

### 애플리케이션의 `api.slots.select()`를 idempotent하게 변경

선택하지 않았다. 같은 슬롯을 다시 선택할 때 선택 해제하는 동작은 기존 UI 의미이며, 이번 실패는 애플리케이션 기능이 아니라 테스트 helper의 잘못된 사용이다.

## 검증과 후속 작업

- JavaScript 구문 검사
- split/portable browser regression 재실행
- 11번 move-to-trash cascade가 실제 `planMove()` 및 참조 제거 단계까지 진행하는지 확인

애플리케이션 소스, UI FSM/EFSM, 프로젝트 모델, 파일 의미는 변경하지 않는다.
