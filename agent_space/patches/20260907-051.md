# 20260907-051 — React-owned FFSX / Plotly import input

## Purpose

Remove the Mantine graph-file import button's dependency on the legacy `#importSlotJsonFile` DOM input. The Mantine graph-file section should own its own invisible browser file input and call the existing `importSlotFile(file, slot)` functional boundary directly.

This patch changes presentation ownership only. FFSX/Plotly parsing and slot/project mutations remain in the existing implementation.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- `importSlotFile()`
- FFSX parsing/writing
- Plotly JSON interpretation
- project classes/models
- UI FSM or functional EFSM definitions
- the still-working legacy `#importSlotJsonFile` input before cutover

## Existing functional path reused

The Mantine path reuses:

- `getSelectedSlot()`
- `importSlotFile(file, slot)`
- lifecycle state `importing`
- lifecycle event `SLOT_IMPORT`
- `refreshCsvControls()` on import failure
- existing `status()` and `debugLog()` error reporting

No new slot-import action or parser is introduced.

## Exact changes

1. Removes the global `openSlotImportPicker()` helper that clicked `document.getElementById("importSlotJsonFile")`.
2. `FastFigureGraphFileActions` owns a component-local hidden `<input type="file">` via `useRef`.
3. The visible `FFSX/Plotly JSON 불러오기` Mantine button opens only this React-owned input.
4. The existing selected-slot guard is retained with the same status message.
5. The local input `onChange` captures the selected slot and invokes `importSlotFile(file, slot)` inside the existing `appFSM.run` lifecycle through `runLifecycleTask("importing", "SLOT_IMPORT", ...)`.
6. Import failures preserve the legacy handler behavior exactly:
   - `refreshCsvControls()`
   - `status("슬롯 불러오기 오류: " + error.message)`
   - `debugLog("slot:import-error", { message: error.message })`
7. The input value is always cleared in `finally`, preserving same-file re-selection after success or failure.
8. No legacy DOM ID is read or clicked by the Mantine slot-import path.

## UI and state ownership

The hidden browser file input is local presentation state owned by `FastFigureGraphFileActions`. Persistent slot/chart/project state remains owned by the existing functional code and project model. Lifecycle ownership remains with the existing UI FSM.

## Why this direction

`importSlotFile()` is already the appropriate functional boundary. Calling the legacy file input would keep the legacy DOM as an internal API, while duplicating FFSX/Plotly parsing in React would violate the existing separation. Owning only the file picker and delegating to `importSlotFile()` is the narrowest direct Mantine implementation.

## Rejected alternatives

### Clicking `#importSlotJsonFile`

Rejected because it preserves a legacy DOM bridge.

### Reimplementing FFSX/Plotly parsing in `fast-figure-ui.js`

Rejected because `importSlotFile()` already owns that functionality.

### Adding a new Mantine-specific import event

Rejected because `SLOT_IMPORT` already represents the lifecycle operation and the functional import path already exists.

### Removing the legacy input now

Rejected because legacy UI remains available as a parity reference until cutover.

## Rollback

Revert `20260907-051.patch`. The Mantine button will return to the legacy file-input bridge without any data-format or model rollback.
