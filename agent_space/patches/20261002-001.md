# 20261002-001 — TLA Slot Core 2x2 execution profile and validation

## 검사 결과

직전 3x3 `TLA Slot Core` 실행은 PlusCal translation과 SANY parsing을 통과했지만
45분 TLC model check 제한에 도달해 취소되었다.

종료 직전 TLC 진행 상태:

- generated states: 25,812,902
- distinct states: 20,812,969
- states left on queue: 12,680,664
- search depth: 17
- invariant violation / semantic error / OOM: 확인되지 않음

사용자가 3x3 검증은 필요하지 않다고 명시했으므로,
canonical verification code는 유지하고 실행 bound만 2x2로 줄여 다시 검사했다.

## 변경 내용

### canonical verification code 유지

다음 파일은 수정하지 않는다.

- `verification/FastFigureSlotCore.tla`
- `verification/FastFigureSlotCore.cfg`

따라서 `verification/**/*` fingerprint와 verification-model r6의 의미 번역은 변경하지 않는다.

### 2x2 TLC execution profile 추가

CI 실행 전용 경로에 다음 두 파일을 추가한다.

- `.github/tlc/FastFigureSlotCore2x2.tla`
- `.github/tlc/FastFigureSlotCore2x2.cfg`

execution module은 `FastFigureSlotCore`를 `EXTENDS`하고 실행용 replacement operator만 정의한다.

```tla
VerificationMaxRows == 2
VerificationMaxCols == 2
```

cfg에서 TLC operator override를 사용해:

```text
MaxRows <- VerificationMaxRows
MaxCols <- VerificationMaxCols
```

로 치환한다.

PlusCal translation이 생성하는 procedure-local 초기화용 `defaultInitValue`는
execution wrapper가 translated module을 `EXTENDS`할 때 root model의 constant parameter가 되므로,
동일 cfg에서 `defaultInitValue = defaultInitValue`를 model value로 지정한다.

`InitialRows == 2`, `InitialCols == 2`, chart ids 2개, image ids 1개,
검사 invariant 목록은 canonical model과 동일하게 유지한다.

### workflow 전환

`.github/workflows/tla-slot-core.yml`은 canonical PlusCal translation과 SANY parse를 유지하고,
2x2 execution wrapper도 SANY parse한 뒤 TLC만 `FastFigureSlotCore2x2.tla/.cfg`로 실행한다.

execution profile 파일 변경도 workflow trigger에 포함한다.

### validation 기록

성공 실행 결과를
`agent_space/reviews/review-017-tlc-slot-core-r6-2x2.md`에 기록한다.

`development-versions.json`은 verification-model r6 fingerprint/revision을 바꾸지 않고:

```text
tlc: pending -> passed
validation_review: null -> review-017
```

만 갱신한다.

## 사전 실행 실패

첫 임시 실행 `36895617878`은 wrapper와 SANY parse까지 통과한 뒤
TLC model initialization 전에 `defaultInitValue` 미지정으로 종료되었다.

이는 verification-model counterexample이 아니라 execution cfg 누락으로 판정했고,
최종 cfg에 model value assignment를 추가한 뒤 동일 2x2 bound가 정상 완주했다.

## 선택 이유

이번 문제는 verification algorithm의 의미 오류가 아니라 3x3 bound에서 발생한 상태공간 폭발이었다.
3x3이 요구되지 않으므로 verification code를 변경하는 대신 TLC 실행 경계만 줄이는 것이
의미 계층을 보존하면서 가장 작은 수정이다.

TLC 자체 테스트에서도 config의 `<-` operator override로 기존 또는 확장된 operator를
실행 모델용 replacement operator로 치환하는 방식을 사용한다.

CI execution profile을 `verification/` 밖에 두어 실행 bound 변경을
Source Script -> verification-model 의미 변경과 분리한다.

## 고려했지만 선택하지 않은 방향

### `verification/FastFigureSlotCore.tla`의 MaxRows/MaxCols를 2로 수정

선택하지 않았다. canonical verification code를 그대로 두는 조건과 충돌하고
verification fingerprint/revision까지 변경해야 한다.

### workflow에서 `sed`로 temporary TLA 파일 수정

선택하지 않았다. 실행 시점 텍스트 변환이 실제 검증 입력을 숨기므로
명시적인 execution module/config보다 추적성과 재현성이 낮다.

### chart/image representative cardinality 추가 축소

선택하지 않았다. 2x2에서도 chart ids 2개와 image id 1개를 그대로 둔 상태로
exhaustive run이 완주했으므로 추가 축소가 필요하지 않다.

### operation별 scenario 분할

선택하지 않았다. 2x2 단일 exhaustive model이 완주했으므로 검증 시나리오를 더 쪼갤 필요가 없다.

### timeout 추가 연장

선택하지 않았다. 3x3 실행 종료 시점에도 BFS queue가 증가하고 있었고,
2x2는 기존 45분 제한 안에서 8분 30초에 완주했다.

## rollback

이 변경을 되돌릴 때는:

1. `.github/tlc/FastFigureSlotCore2x2.tla/.cfg`를 제거한다.
2. workflow의 model-check target을 `FastFigureSlotCore.tla/.cfg`로 되돌린다.
3. execution profile용 push path와 parse step을 제거한다.
4. `development-versions.json`의 TLC 상태를 `pending`으로 되돌리고 validation review 참조를 제거한다.
5. `review-017`을 validation evidence에서 제외한다.

canonical verification code와 Source Script에는 rollback 대상 변경이 없다.
