# 20260906-019 — Mantine preview target isolation

## 목적

Mantine visible shell owner 전환 전에 React layout/label preview가 legacy compatibility DOM과 같은 `layoutMap`, `labelPreview`, `labelPreviewLabel` ID를 만들지 않도록 renderer target을 명시적으로 분리한다.

owner cutover 동안 legacy controls는 Plotly relayout 등 아직 남아 있는 compatibility 경로를 위해 DOM에 유지할 예정이다. 따라서 React modal이 같은 ID를 사용하면 `getElementById`의 대상이 모호해지고 audit의 duplicate-control 검사에도 걸린다.

## 변경 내용

- 앱 버전 `1.1.122-alpha` → `1.1.123-alpha`
- `renderLayout(map)`이 선택적 target element를 받도록 확장
  - 인자를 생략하면 기존 `#layoutMap`을 사용하므로 legacy 경로 보존
  - layout slot click 후에도 같은 target에 다시 렌더링
- `fastFigureUiBridge.renderLayoutPreview(target)`가 target을 전달
- Mantine layout modal은 React ref를 사용하고 React preview의 `id="layoutMap"` 제거
- label preview geometry/render/pointer 함수가 선택적 preview/label element를 받도록 확장
  - 인자를 생략하면 기존 `#labelPreview`, `#labelPreviewLabel`을 사용
- Mantine label preview는 React refs를 bridge에 전달하고 React preview의 legacy IDs 제거

## 의미 보존

- `layoutSelected`, layout merge/split 동작 변경 없음
- 레이블 좌표 단위, 제한 영역, 글꼴 크기 계산 변경 없음
- legacy panel renderer는 기존 ID fallback을 계속 사용
- React draft/state 구조 변경 없음
- 프로젝트 모델/FFPX schema 변경 없음

## EFSM / core 경계

EFSM state, transition, event, write lock을 변경하지 않는다. 변경점은 동일 renderer를 어느 preview DOM element에 적용할지를 UI adapter가 명시하게 하는 것뿐이다.

## 선택하지 않은 방향

### legacy preview DOM 즉시 삭제

Plotly/editor 및 project-load compatibility 경로 정리가 아직 끝나지 않았으므로 owner cutover와 동시에 삭제하지 않는다.

### React용 layout/label renderer 재구현

동일 geometry/selection 규칙을 두 번 구현하게 되므로 선택하지 않는다. 기존 renderer를 target-aware하게 재사용한다.

### querySelector로 owner별 ID 우선순위 지정

duplicate ID 자체를 남기고 조회 순서에 의존하므로 선택하지 않는다.

## 회귀 위험

낮음~중간. 기본 인자 경로가 기존 legacy 동작을 그대로 유지하며, React 경로만 명시적 element reference를 사용한다.

## 검증

1. `git apply --check`
2. `git diff --check`
3. `node --check fast-figure.js`
4. portable build
5. split/portable `file://` smoke test
6. React layout preview가 `id="layoutMap"`을 생성하지 않는지 정적 확인
7. React label preview가 legacy label preview IDs를 생성하지 않는지 정적 확인
8. legacy no-argument renderer 호출이 기존 fallback ID를 유지하는지 확인

## rollback

target/ref 인자를 제거하고 React preview의 기존 IDs를 복원한 뒤 앱 버전을 `1.1.122-alpha`로 되돌린다.
