# 20261015-008 — GitHub Actions 실행 절차 보충

## 목적과 변경 내용

`agent_space/AGENT.md`의 기존 Actions 명시적 허용 원칙을 보존하면서, 허용된 실행을 실제로 시도하기 위한 조사와 실행 경로를 추가한다.

- 실제 `.github/workflows/` 정의에서 `workflow_dispatch`, `push.paths`, branch 및 입력 조건 확인
- 수동 실행 수단이 연결 도구에 없을 때 GitHub 웹 UI, `gh`, REST API 등 실제 사용 가능한 경로 검토
- 의미 없는 커밋 없이 정상 변경에 부수되는 push 트리거만 활용
- 과거 run의 재실행과 최신 HEAD 검증을 구분
- 검증 범위가 빠진 workflow는 정규 패치 절차로 보완
- 실행 ID, 기준 commit, 대상 job, 결과 로그를 확인하고 미실행 검증은 통과로 기록하지 않음

## 이 방향을 선택한 이유

기존 `.github/workflows/tla-slot-core.yml`에서 `workflow_dispatch`와 검증 파일에 대한 push 트리거, Java 및 TLA+ 도구 다운로드와 TLC 실행이 확인되었다. 단일 연결 도구의 신규 workflow 실행 기능 부재나 로컬 네트워크 제한만으로 저장소 전체의 실행 가능성을 부정할 수 없다.

이번 변경은 실행 절차를 명시하는 문서 보충이며 실제 workflow 실행이나 검증 결과 갱신은 아니다.

## 고려했으나 선택하지 않은 방향

- **사용자에게 수동 실행을 요구:** 허용된 대체 실행 경로를 확인하지 않고 책임을 이전하게 되어 기각.
- **GitHub Actions 상시 허용:** 기존 사용자별 명시적 허가 조건을 약화하므로 기각.
- **push 이벤트를 위한 무관한 파일 변경:** 불필요한 기록과 중복 실행을 만들므로 기각.
- **프로젝트 전용 workflow 이름이나 API 입력값을 AGENT.md에 고정:** 실제 파일·도구와 달라질 수 있어 현재 저장소에서 조회하도록 규정.
