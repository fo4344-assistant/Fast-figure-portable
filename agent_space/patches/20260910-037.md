# 20260910-037 — Remove legacy image settings form

## Purpose

Complete the image-editor cutover by removing the remaining legacy `#imageBox` form and its DOM synchronization/form-reader path. Mantine `FastFigureImageEditor` already owns these controls and calls `applyImageSettingsFromValues()` directly. Legacy UI compatibility is not retained; file-format compatibility remains unchanged.

This patch supersedes failed patches `20260910-035` and `20260910-036`. Neither changed application source because both failed at `git apply --check`. Patch 036 corrected hunk ordering but still split two adjacent edits across overlapping hunks around `syncImageSettingsUi()` / `syncSlotContentTypeUi()`. Patch 037 merges those edits into one non-overlapping hunk against the current post-034 source.

## Exact changes

### `Fast-figure.html`

- Remove the entire `#imageBox` fieldset.
- Remove legacy fit-mode, manual scale/X/Y controls, and the legacy image preview element.

### `fast-figure.js`

- Remove `imageBox`, `imageFitMode`, `imageManualFields`, `imagePositionX`, `imagePositionY`, `imagePreview`, and `imageScale` from `REQUIRED_CONTROL_IDS`.
- Remove `syncImageSettingsUi()`.
- Remove `imageBox`/`imagePreview` writes from workspace synchronization and project runtime reset paths.
- Remove `exitImageWorkspaceState()` and the image-workspace exit hook because they only hide the deleted form.
- Remove the legacy `applyImageSettings()` form reader and its DOM input handlers.
- Change the capability audit to require `applyImageSettingsFromValues()`.
- Retain `normalizeImageSettings()`, `syncSlotImageElement()`, and `applyImageSettingsFromValues()` unchanged.

## Source of truth

- Persistent image settings: project image object settings.
- Image-setting mutation: `applyImageSettingsFromValues()`.
- Slot image rendering: `syncSlotImageElement()` and the existing dashboard renderer.
- Generic image editor UI: Mantine only.

## EFSM / core impact

No project transition semantics, image data model, renderer geometry, or image-setting normalization changes. The image workspace retains its existing entry/update behavior; only the obsolete legacy form exit-side DOM hide action is removed.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, image byte/base64 representation, package layout, parser, serializer, import/export routine, or package version is modified.

## Rationale

The removed form is a duplicate UI authority. Mantine already reads image state from the project model and sends values through the UI-independent command. Hidden legacy controls would preserve unnecessary compatibility state and invite future DOM bridges.

## Rejected alternatives

- Keep `#imageBox` hidden: rejected because legacy UI compatibility is explicitly not required.
- Synchronize Mantine values into the old form: rejected because it recreates a bidirectional DOM bridge.
- Move image-setting mutation into React-local state: rejected because the project model and existing command are already authoritative.
- Reuse patch 036 unchanged: rejected because adjacent hunks overlapped on `function syncSlotContentTypeUi()` and failed `git apply`.

## Validation

The regenerated patch is syntax-parseable by `git apply --numstat`, and the overlapping image-sync edits are represented as one hunk.

Repository CI must pass:

Manual regression focus: Mantine contain/cover/manual controls, scale/X/Y changes, blank image insertion, image import, image slot rendering, and FFPX/FFSX project/slot interoperability.

## Rollback

Revert the application commit for `20260910-037` to restore the old image form and DOM synchronization path. No persisted data migration is involved.

## Follow-up

Remove image-form-only CSS that becomes dead after this patch, then continue removing legacy CSV/graph UI facades where Mantine ownership is complete. Keep file-format compatibility code independent from UI cleanup.
