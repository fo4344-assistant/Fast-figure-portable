# 20261002-007 — README build source separation

## 목적과 변경 내용

저장소 루트 `README.md`와 `Fast-figure.html` 내부 README가 독립적으로 관리되던 중복을 제거한다.

- `README.md`를 README 내용의 유일한 작성 원천으로 사용한다.
- `Fast-figure.html`에는 `<!-- FAST_FIGURE_README -->` 빌드 표식만 남긴다.
- `scripts/build-portable.py`가 빌드 시 README Markdown을 HTML로 변환해 inline HTML과 split ZIP 내부 HTML 양쪽에 주입한다.
- split ZIP에는 원본 `README.md`도 기존대로 포함한다.
- regression runner가 ZIP의 README byte 동일성, 빌드 표식 제거, 생성 HTML의 README 주입을 검사한다.
- README 변경만으로도 회귀 빌드가 실행되도록 workflow path trigger에 `README.md`를 추가한다.

## 선택 이유

README 내용을 두 위치에서 독립적으로 유지하면 문서가 쉽게 분기된다. 빌드 시 주입하면 저장소 문서와 앱 내 README가 같은 원천을 사용하면서도 inline 단일 파일과 split `file://` 오프라인 실행을 모두 유지할 수 있다.

Markdown 변환은 Python 표준 라이브러리만 사용하며 현재 README에서 실제 사용하는 제목, 문단, fenced code, 순서/비순서 목록, inline code, 굵은 글씨, 링크를 처리한다. 원문은 HTML escape한다.

## 고려했지만 선택하지 않은 방향

### 런타임 README.md fetch

inline 배포에는 별도 README 파일이 없고 split 배포도 `file://` fetch 동작에 의존하게 되므로 선택하지 않았다.

### HTML 내부 README 사본 유지

이번 변경의 목적과 반대로 두 source of truth를 계속 유지하므로 선택하지 않았다.

### 외부 Markdown 패키지 추가

현재 문서 구문을 처리하는 데 새 Python/npm 의존성이 필요하지 않고 독립 빌드 성질을 약화시키므로 선택하지 않았다.

### Markdown 원문을 그대로 preformatted text로 표시

중복 제거는 가능하지만 기존 README overlay의 제목·목록·코드·링크 표시를 퇴행시키므로 선택하지 않았다.
