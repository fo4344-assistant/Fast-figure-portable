# 20260911-005 — Remove legacy graph-object UI entrypoints

## Purpose

Remove the active legacy graph-object editor execution path after `003`/`004` failed during patch application. Mantine already owns object selection, add/reorder/delete, object values, and color changes through `graphEditor*` commands.

## Exact changes

### `fast-figure.js`
- Remove the legacy document pointer handler that cleared/re-rendered `#graphObjects`.
- Remove the legacy `#addGraphObject` click handler and its form-driven chart/object mutation path.
- Remove legacy object form input bindings for X/Y, axis sides, type, line/marker/bar values, legend/title, and graph font controls.
- Stop startup rendering of the legacy `#graphObjects` list.
- Keep the functional `graphEditor*` command family and dashboard renderer unchanged.

## Rationale

The old graph-object form is no longer a compatibility target. Leaving its handlers active would keep a second graph UI authority even if the markup is hidden. Removing entrypoints first makes the remaining old renderer/form helpers dead and safe to delete in the following cleanup.

## Source of truth

Graph objects and selection remain in the chart model/appFSM. Mantine is the sole generic object editor.

## EFSM / core impact

None. No graph model schema or event semantics change.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, CSV, or image file-format code changes.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert this patch's application commit. `003` and `004` changed no application source.

## Follow-up

Remove legacy palette/file/axis UI entrypoints, then delete dead graph form readers/renderers and the `#buildBox` markup/CSS.
