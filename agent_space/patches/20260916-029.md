# 20260916-029 — stale native reset DOM access removal

## 목적과 변경 내용

이미 제거된 native file input과 graph editor box를 `resetProjectRuntimeState()`가 계속 직접 접근하던 잔여 코드를 제거한다.

변경 내용:
- `$("file").value = ""` 제거
- `$("buildBox").classList.add("hidden")` 제거

## 선택 이유

current HTML에는 `#file`과 `#buildBox`가 더 이상 존재하지 않는다. 그런데 project/runtime reset은 두 DOM을 무조건 역참조하고 있어 reset/import/rollback 계열에서 null DOM 접근이 발생할 수 있다.

이 두 줄은 domain state나 UI FSM 상태를 초기화하는 기능이 아니라 제거된 legacy frontend control을 동기화하던 projection이다. 따라서 대체 state나 compatibility DOM을 만들지 않고 제거하는 것이 현재 Mantine ownership과 SoT 원칙에 맞다.

## 선택하지 않은 방향

- 숨은 `#file`/`#buildBox`를 다시 만들지 않는다. 제거된 legacy UI를 compatibility layer로 되살리기 때문이다.
- optional chaining으로 DOM 접근만 무해화하지 않는다. 더 이상 필요한 기능 의미가 없는 projection을 남길 이유가 없다.
- `editing`, `selectedSlotId`, `selectedObjectIndex`, `layoutSelected`의 runtime reset 의미는 변경하지 않는다.

## 전제 / 후속 작업 / 누락

- `#file`과 `#buildBox`가 current HTML에 존재하지 않음을 확인했다.
- 다음 ownership 단위에서 `fileName`과 `status` legacy DOM projection을 각각 제거한다.
- rollback은 이 패치를 되돌리면 두 legacy DOM reset 접근만 복구된다.
