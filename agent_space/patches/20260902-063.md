# 20260902-063 — Dashboard zoom/lock/reset 기능과 legacy UI 동기화 분리

## 목적

`review-006.md`에서 확인한 Layout staging의 남은 기능 누락인 dashboard zoom, 현재 폭 고정, 100% 복귀를 Mantine로 이식하기 전에 기능 command와 legacy native-control 동기화를 분리한다.

현재 `setDashboardZoomLocked()`는 한 함수에서 다음을 함께 수행한다.

- `dashboardZoomLocked` / `dashboardZoomLockedWidth` 기능 상태 변경
- dashboard width 적용
- Plotly resize / dashboard scale commit
- legacy slider disabled
- legacy button aria/title

Mantine callback이 이 함수를 그대로 호출하면 native slider/button DOM이 새로운 UI 기능 계약에 남는다.

## 변경 내용

- `applyDashboardZoom(resize, requestedValue, syncControls = true)`로 확장
  - 기존 zoom/geometry/resize 계산은 그대로 유지
  - `syncDashboardZoomDisplay()`는 `syncControls=true`일 때만 호출
  - legacy 호출의 default 동작은 유지
- `readDashboardZoomModel()` 추가
  - zoom percent
  - locked 여부
  - locked width
  - 현재 dashboard width
  - read-only snapshot 반환
- `setDashboardZoomFromValue(value, commit = false)` 추가
  - lock 상태면 변경하지 않음
  - DOM control sync 없이 기존 zoom 계산 재사용
  - 필요 시 기존 `commitDashboardScale()` 호출
- `setDashboardZoomLockedFromValue(locked)` 추가
  - 기능 상태/locked width 변경
  - 기존 apply/resize/commit/debug 의미 유지
  - legacy native slider/button을 직접 만지지 않음
- `resetDashboardZoomFromValue()` 추가
  - lock 상태에서는 unlock semantics 재사용
  - 아니면 100%로 복귀 후 기존 commit
- 기존 `setDashboardZoomLocked()`는 새 common command를 호출한 뒤 legacy slider/button 표시만 동기화하는 wrapper로 축소

## source of truth

새 persisted state를 만들지 않는다.

- zoom transient state: 기존 `dashboardZoomIntent`
- lock state: 기존 `dashboardZoomLocked`, `dashboardZoomLockedWidth`
- actual renderer width: `#dashboard` geometry
- Mantine staging은 후속 patch에서 `readDashboardZoomModel()` snapshot을 읽고 common command를 호출한다.

## domain / 파일 영향

Dashboard zoom은 presentation/runtime geometry이며 FFPX/FFSX persisted schema를 변경하지 않는다.

`commitDashboardScale()`의 기존 render/debug/notify 경로는 그대로 재사용한다.

## 기각한 대안

### Mantine Slider가 legacy `#dashboardZoom` input 값을 변경

기각한다. legacy DOM이 source of truth가 된다.

### zoom 상태를 React state로 별도 유지

기각한다. 기존 runtime zoom state와 두 source가 된다.

### dashboard width 계산을 React에서 재구현

기각한다. 기존 `dashboardReferenceWidth()` / `applyReferenceGeometry()` 경로를 재사용한다.

## 회귀 확인

- `git apply --check`
- `git diff --check`
- JavaScript `node --check`
- legacy handler의 기본 zoom/lock/reset 동작 유지
- 파일 schema 변경 없음

## rollback

이 patch만 되돌리면 zoom command 분리가 제거되고 legacy 단일 함수 구조로 돌아간다. persisted data에는 영향이 없다.
