# 20260902-032 — Mantine graph object 목록 staging component

## 목적

`20260902-021/022`의 read model과 `024/030`의 DOM-free list command를 이용해 inactive Mantine shell용 graph-object 목록 component를 준비한다.

이번 패치에서는 component 정의만 추가하고 sidebar에는 아직 연결하지 않는다.

## 변경 내용

- 앱 버전 `1.1.74-alpha` → `1.1.75-alpha`
- `FastFigureGraphObjectListStaging({ graphObjects })` 추가
- Mantine `Paper`, `Group`, `Text`, `ColorInput`, `ActionIcon`, `Stack`, `Title` 사용
- row click/keyboard → 기존 bridge `selectGraphObject`
- color input → `setGraphObjectColor`
- delete → `removeGraphObject`
- HTML5 drag/drop → `moveGraphObject`

## UI state

React local object list state를 만들지 않는다.

- 표시 순서: `graphObjects.objects`
- 선택 표시: 각 snapshot item의 `selected`
- 색상: item `color`
- editable: snapshot `editable`
- mutation 이후 external-store invalidation에 따라 canonical model을 다시 읽음

따라서 drag 결과나 color 값을 React 배열에 먼저 반영하고 domain과 동기화하는 구조가 없다.

## drag/drop

새 drag library를 추가하지 않는다.

기존 legacy 목록도 HTML5 drag/drop을 사용하므로 같은 브라우저 primitive를 유지한다.

- drag payload에는 object index 하나만 저장
- drop target index와 함께 `moveGraphObject(from, to, chartId)` 호출
- row 내부 color input / delete button에서 drag 시작하지 않도록 방지
- 별도 dragging React state 없음

## Mantine 공통 규칙

일반 목록 surface와 control은 Mantine primitive를 사용한다.

- row surface: `Paper`의 border/radius/padding
- 색상 입력: `ColorInput`
- 삭제 버튼: `ActionIcon`
- 배치: `Group` / `Stack`

별도 graph-object용 button/input CSS를 추가하지 않는다.

## 선택 표현

selected row는 snapshot의 `selected`만 읽으며 별도 UI state를 만들지 않는다. 텍스트 weight와 `Paper` shadow만 presentation에 사용한다.

## 접근성

- row에 keyboard Enter/Space selection 지원
- `aria-pressed`로 selection 표시
- color/delete에 aria-label 유지

## source of truth

변경 없음.

- objects: selected chart `editor.objects`
- selection: graphObject EFSM
- React component: render snapshot만 소비
- drag index: 단일 drag interaction 동안만 사용하는 transient payload

## 변경하지 않는 영역

- active legacy `renderGraphObjects()`
- add object
- palette UI
- `GRAPH_OBJECTS_REPLACED` / selection EFSM
- graph renderer / trace 생성
- Plotly renderer
- 인라인 Plotly library
- import/export

## 선택하지 않은 방향

### React `useState`로 정렬 배열 관리

선택하지 않는다. domain object 배열과 이중 source가 된다.

### 별도 DnD dependency 추가

선택하지 않는다. 기존 자유도에는 HTML5 drag/drop으로 충분하다.

### legacy CSS class 재사용

선택하지 않는다. Mantine migration의 목적과 반대이며 최종 cleanup을 방해한다.

### component 정의와 sidebar wiring 동시 적용

선택하지 않는다. 이전 대형 patch apply 실패 경험에 따라 component 정의와 wiring을 분리한다.

## 회귀 위험

낮음. component는 아직 sidebar에서 호출하지 않아 사용자 UI 동작은 변하지 않는다.

검사:

- JavaScript syntax
- Mantine runtime 식별자 존재
- React local persistent list state 없음
- bridge command만 호출
- legacy DOM id/class 참조 없음
- Plotly/trace diff 없음

## rollback

- `FastFigureGraphObjectListStaging` 제거
- 앱 버전을 `1.1.74-alpha`로 복원

기존 read/command 경계는 독립 유지 가능하다.

## 후속

`033`에서 sidebar가 `readGraphObjects()`를 읽고 component를 렌더하도록 최소 wiring만 추가한다.

## Plotly 범위

인라인 Plotly library 본문은 읽거나 수정하지 않는다.
