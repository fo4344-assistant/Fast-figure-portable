# 20260902-062 — Mantine Print Capture 버튼 이식

## 목적

`review-006.md`에서 확인한 Print staging의 기능 누락인 `캡처`를 `20260902-060`에서 분리한 capture command에 연결한다.

`20260902-061`은 bridge 객체의 current context 불일치로 apply-check 단계에서 실패했고 HTML에는 반영되지 않았다. 별도 bridge method가 기능적으로 필수는 아니므로, Mantine component가 기존 module-level command를 직접 호출한다.

## 변경 내용

- `FastFigurePrintCaptureStaging({ draft, setStatus })` 추가
  - Mantine `Button` 사용
  - 클릭 시 status adapter를 만들고 `captureDashboardTargetFromValues(draft, statusTarget)` 호출
  - 오류는 기존 export command가 status에 기록하므로 callback에서는 reject를 삼켜 UI event loop로 전파하지 않는다.
- `FastFigurePrintModalStaging`의 하단 action group에 `캡처` 버튼을 `저장` 버튼과 함께 배치한다.
- 기존 저장 버튼/target exporter는 유지한다.

## 설계 판단

Mantine callback이 module-level DOM-free command를 직접 호출하는 것은 `plan-004/005`의 write 경계에 부합한다. 중요한 것은 legacy `#capturePrint` button click이나 native print inputs를 source로 사용하지 않는 것이다.

별도 bridge method를 억지로 추가하기 위해 current bridge 객체 context를 계속 추정하는 것보다 구현 복잡도가 낮다.

## 기능 의미

- `저장`: 사용자가 입력한 width/height를 target export에 사용
- `캡처`: 현재 dashboard host 폭을 기준으로 width를 잡고 height를 layout/caption geometry에서 자동 계산
- DPI/format/status는 동일 UI draft/renderer를 공유

## 파일/EFSM 영향

프로젝트 파일 schema, EFSM, chart/image/layout domain model에는 영향이 없다.
