# 20260902-035 — graph object DOM-free add command

## 배경

`20260902-034`에서 active CSV와 현재 chart/선택 graph object로부터 새 graph object 기본값을 계산하는 `selectedGraphObjectAddModel()`을 추가했다. 이 selector는 별도 draft 상태를 저장하지 않고 기존 `baseGraphObject()`와 `graphDataSelection()`을 재사용한다.

기존 `#addGraphObject` legacy handler는 두 경로를 가진다.

1. chart가 없는 슬롯: `SLOT_DATA_CONNECTED`
2. 기존 chart: 현재 chart 모델에 object를 append하고 `CHART_MODEL_REPLACED`

기존 handler는 두 번째 경로에서 `configFromForm()`을 사용하므로 Mantine UI가 legacy form DOM을 읽지 않고 동일 기능을 호출할 command 경계가 필요하다.

## 목적

- graph object 추가의 기능 의미를 legacy DOM form에서 분리한다.
- 기존 EFSM event/action을 그대로 재사용한다.
- 새 React/Mantine persistent draft state를 만들지 않는다.
- 빈 축 제목 자동 채움과 추가 직후 새 object 선택 규칙을 보존한다.

## 변경 내용

- 앱 버전 `1.1.77-alpha` → `1.1.78-alpha`
- `fastFigureUiBridge.addGraphObject(slotId, chartId)` 추가
- `addGraphObjectFromModel(expectedSlotId, expectedChartId)` 추가

### chart가 없는 경우

```text
selectedGraphObjectAddModel()
→ SLOT_DATA_CONNECTED
→ selectGraphObjectFromIndex(0, newChartId)
→ updateGraphView()
```

### 기존 chart가 있는 경우

```text
canonical chart
→ projectClone(chart)
→ selectedGraphObjectAddModel().object append
→ 비어 있는 해당 X/Y axis title 보충
→ CHART_MODEL_REPLACED
→ 새 마지막 object 선택
→ updateGraphView()
```

## source of truth

추가 command는 selector 결과를 저장하지 않는다. 실행 시 선택 슬롯, chart, active CSV를 다시 읽고 `selectedGraphObjectAddModel()`을 호출한다.

기존 chart를 직접 수정하지 않고 clone을 만든 뒤 기존 `CHART_MODEL_REPLACED` action에 전달한다. 최종 canonical chart는 기존 EFSM/action이 관리한다.

## stale callback guard

Mantine callback이 오래된 snapshot에서 실행되는 경우를 막기 위해 `expectedSlotId`와 `expectedChartId`를 현재 선택 슬롯/chart와 비교한다. chart가 없는 상태는 `null`로 비교한다.

## 기존 legacy handler와의 의미 차이

기존 handler는 `configFromForm()`에서 legacy DOM의 현재 form 값을 읽어 새 object를 만든다. 새 command는 legacy DOM을 읽지 않고 canonical 선택 object/chart 스타일과 active CSV에서 `034` selector가 계산한 값을 사용한다.

이 차이는 Mantine migration에서 의도적이다. Mantine 상세 form은 선택 object 변경을 이미 canonical chart에 즉시 반영하므로, 추가 시점에 별도의 legacy form draft를 권위 있는 상태로 사용할 이유가 없다. 이 구조는 두 번째 source of truth를 만들지 않는다.

## 유지하는 기존 동작

- `SLOT_DATA_CONNECTED` / `CHART_MODEL_REPLACED` event 경로
- chart editable guard
- active CSV 기반 object 생성
- object palette 순번 색상 (`034` selector)
- 빈 X/Y axis title 자동 보충
- 새 object 자동 선택
- graph view 갱신

## 변경하지 않음

- 기존 `#addGraphObject` handler
- active legacy sidebar
- Plotly trace/layout 구현
- import/export
- EFSM event/action 정의
- chart/model schema

## 기각한 대안

### `configFromForm()`을 Mantine에서도 호출

기각. legacy DOM form이 계속 기능 source of truth로 남아 Mantine renderer 제거를 방해한다.

### React `useState`로 새 object draft 보관

기각. 같은 기능 의미를 가진 두 번째 상태를 만들며 현재 단계에서는 추가 자유도를 제공하지 않는다.

### `GRAPH_OBJECTS_REPLACED`만으로 append

기각. 기존 add 동작의 빈 axis title 보충까지 보존하려면 chart global settings도 함께 변경해야 한다. 현재 기존 `CHART_MODEL_REPLACED` 경로가 그 의미를 가장 직접적으로 유지한다.

## 검증

- patch apply/check
- JavaScript syntax
- bridge method 중복 없음
- stale slot/chart guard
- 기존 EFSM event 이름 재사용
- legacy add handler 미변경
- Plotly bundle 미접촉

## rollback

- `fastFigureUiBridge.addGraphObject()` 제거
- `addGraphObjectFromModel()` 제거
- 앱 버전 `1.1.77-alpha` 복원

이 패치는 legacy add handler를 수정하지 않으므로 rollback 시 기존 UI 동작은 그대로 남는다.

## 후속

성공 적용 후 Mantine graph-object list에 추가 버튼을 연결하고, 그 다음 legacy `#addGraphObject` handler도 동일 command를 재사용할 수 있는지 별도 패치로 검토한다.
