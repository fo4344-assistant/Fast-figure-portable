# 20260903-003 — workspace availability / image selection domain 경계 분리

## 목적

Mantine shell cutover 전 workspace 초기화 감사를 계속한다.

현재 `updateFileAvailability()`와 `refreshImageControls()`는 각각 domain/FSM 의미와 legacy DOM 표시를 한 함수에 섞고 있다.

- `updateFileAvailability()`는 버튼 visibility/disabled 외에 슬롯 선택 시 README overlay를 닫는 실제 FSM 정책을 수행한다.
- `refreshImageControls()`는 `activeImageId` 정규화와 native `insertEmptyImage` 버튼 disabled 처리를 동시에 수행한다.

이번 패치는 이 두 domain 의미를 DOM-free helper로 분리한다.

## 변경 내용

- 앱 버전 `1.1.105-alpha` → `1.1.106-alpha`
- `workspaceAvailabilityModel()` 추가
  - selected slot 유무
  - 현재 asset selection 해석
  - download/delete 가능 여부 계산
  - DOM을 읽거나 수정하지 않음
- `applyWorkspaceAvailabilityPolicy(model)` 추가
  - slot이 선택됐고 README overlay가 열려 있으면 기존과 동일하게 `CLOSE_OVERLAY` 전송
  - 계산된 model 반환
- `updateFileAvailability()`는 위 두 helper 결과를 받아 legacy 버튼/menu/slot-type 표시만 갱신
- `setActiveImageFromId(selected)` 추가
  - project image 존재 여부에 따라 기존 `activeImageId` 정규화
  - DOM 접근 없음
- `refreshImageControls()`는 `setActiveImageFromId()` 호출 후 legacy 버튼 disabled만 갱신

## 이유

workspace EFSM entry가 Mantine cutover 후에도 README-close policy와 active image selection 의미를 유지해야 한다. 이 의미를 legacy DOM 함수와 함께 삭제하면 UI migration이 domain behavior를 바꾸게 된다.

반대로 legacy presentation을 그대로 EFSM callback에 남기면 React shell mount 후 제거된 native controls를 계속 찾게 된다.

따라서 계산/정책과 native 표시 adapter를 분리한다.

## 고려했지만 선택하지 않은 방향

### README 자동 닫기 자체를 제거

기각. 슬롯 선택 시 README가 닫히는 것은 현재 overlay/workspace interaction semantics다. UI 구조 변경만으로 삭제하지 않는다.

### Mantine component에서 `updateFileAvailability()` 호출

기각. native button/menu synchronization을 Mantine가 다시 의존하게 된다.

### `activeImageId`를 React local state로 이동

기각. 기존 project/image selection state와 중복 authority가 생긴다.

## source of truth / EFSM

- selected slot / overlay: 기존 `appFSM.state`
- asset selection/path: 기존 `appFSM.state`
- image object: project image model
- active image transient: 기존 `activeImageId`
- 새 model/helper는 영속 상태를 소유하지 않음

## 회귀 위험

낮음.

기존 public wrapper인 `updateFileAvailability()`와 `refreshImageControls()`의 observable legacy 동작은 유지된다.

## 검증

- `git apply --check`
- `git diff --check`
- application JavaScript `node --check`
- slot 선택 + README overlay 시 기존 CLOSE_OVERLAY 유지
- asset download/delete availability 계산 동일
- valid/invalid image ID에서 `activeImageId` 의미 동일
- legacy 버튼/menu 표시 동일

## rollback

두 helper를 제거하고 기존 inline 계산/mutation을 각 wrapper에 복원한 뒤 버전을 `1.1.105-alpha`로 되돌리면 된다.
