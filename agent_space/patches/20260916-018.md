# 20260916-018

## 목적과 변경 내용

Mantine `FastFigureGraphDataEditor`가 graph object 선택·편집·색상·순서·삭제를 직접 담당하고 있는 상태에서, 더 이상 외부 호출자가 없는 legacy native graph object-list DOM renderer/handler 폐쇄군을 제거한다.

이번 패치는 다음 함수만 제거한다.

- `populateObjectForm(object)`
  - native graph form input에 선택 object 값을 투영
- `selectGraphObject(index)`
  - native object-list click 선택 및 native form/data preview 동기화
- `saveGraphObjects(objects)`
  - native object-list drag/color/delete 결과를 logic event에 전달하던 legacy UI handler
- `renderGraphObjects(objects)`
  - `#graphObjects` 아래 native draggable/color/delete DOM을 생성하고 event handler를 부착
- `updateTypeSpecificOptions()`
  - native `chartType`에 따라 line/marker/bar option 영역을 표시/숨김

이 다섯 함수는 current source에서 서로의 내부 호출 외에는 참조되지 않으며, active Mantine graph editor는 별도의 `graphEditor*` functional command 경로를 사용한다.

## 선택 이유

현재 Mantine graph editor에는 다음 기능이 이미 존재한다.

- object 선택: `graphEditorSelectObject()`
- object 값 변경: `graphEditorObjectValues()`
- object 추가: `graphEditorAdd()`
- 순서 이동: `graphEditorMove()`
- 삭제: `graphEditorDelete()`
- 색상 변경: `graphEditorObjectValues()` 또는 palette command

이 command들은 backend/core에서 logic EFSM event와 project/chart SoT를 사용한다. 반면 제거 대상은 native DOM list/form을 위한 별도 UI projection과 event binding이다.

따라서 native object-list renderer를 유지하는 것은 Mantine과 같은 graph object interaction을 이중으로 표현하는 legacy ownership만 남긴다.

`selectGraphObject()`와 `saveGraphObjects()` 내부에 logic EFSM event 호출이 있었지만, 그것은 legacy UI caller가 event를 호출하던 bridge였다. 이번 패치는 그 UI bridge만 제거하며 event/action 자체는 유지한다.

## CSV preview와의 관계

`selectGraphObject()`는 legacy object 선택 시 `loadData(csv.rows, csv.name)`를 호출해 native CSV preview/form을 채웠다. current source에서 `loadData()`의 다른 호출자는 없었다.

따라서 이 패치 적용 후에는 `loadData()`와 global `rows`/`columns`, `clearPreview()`/`preview()`가 완전히 legacy-only dead path가 되는지 다시 확인할 수 있다. 해당 제거는 다음 패치로 분리한다.

## 고려했지만 선택하지 않은 방향

### logic EFSM selection/object events까지 제거

선택하지 않았다. active Mantine command가 같은 logic EFSM event를 사용한다. native caller 제거와 logic event 제거는 별개다.

### `selectedGraphObjectGuard()`까지 함께 제거

선택하지 않았다. 이번 패치 후 이 helper가 무호출이 되더라도 application/logic EFSM state consistency helper에 해당한다. UI cleanup과 섞지 않고 별도 logic-level dead-code audit에서 판단한다.

### `loadData()` / `rows` / `columns` / preview를 같은 패치에서 제거

선택하지 않았다. object-list 제거 결과로 이 path가 정말 무호출이 되었는지 적용 후 current source에서 다시 검증한 뒤 별도 ownership 패치로 제거한다.

### native graph markup/CSS까지 동시 제거

선택하지 않았다. JS ownership을 먼저 제거하고 smoke 검증한 후 markup/CSS를 별도로 정리하면 rollback 경계가 명확하다.
