# 20260906-035

## 목적

Mantine README가 legacy `#readmeDialog .readme-content` DOM에 의존하는 현재 구조를 제거한다. README 본문은 하나의 독립 `<template>`를 source of truth로 두고, Mantine과 legacy dialog가 모두 그 template을 소비하도록 한다.

## 변경 내용

- `Fast-figure.html`의 기존 README 본문 wrapper를 `<template id="readmeContentTemplate">`로 변경한다.
- 기존 README 본문 텍스트·링크·라이선스 내용은 그대로 유지한다.
- legacy dialog 안에는 렌더링 대상 `.readme-content`를 빈 컨테이너로 두고, 닫기 버튼은 dialog presentation으로 분리한다.
- `fastFigureUiBridge.readReadmeHtml()`은 legacy dialog가 아니라 `#readmeContentTemplate`의 HTML을 읽는다.
- `syncLegacyReadmeContent()`을 추가하여 legacy dialog가 열리기 전에 template content를 clone한다.
- 기존 native README dialog의 열기/닫기/Escape/backdrop FSM wiring은 이번 패치에서 유지한다.
- 앱 빌드를 `1.1.139-alpha`로 올린다.

## 기능 보존

- README 본문의 실제 내용과 순서는 변경하지 않는다.
- Mantine README에 표시되는 HTML은 기존 본문과 동일하다.
- legacy README dialog도 동일 본문을 계속 표시한다.
- legacy `Close` 버튼과 overlay FSM 전이는 유지한다.
- README의 외부 링크 속성과 라이선스 텍스트를 변경하지 않는다.
- portable build에서도 template과 동일 content가 포함된다.

## 선택 이유

현재 bridge가 legacy dialog의 렌더링 결과를 다시 clone하면 legacy dialog가 사실상 콘텐츠 authority가 된다. single-shell cutover에서 그 dialog markup을 제거할 수 없게 된다.

독립 `<template>`는 렌더링되지 않는 콘텐츠 source이므로 generic UI presentation과 분리할 수 있다. Mantine은 template HTML을 직접 읽고, legacy dialog는 호환 adapter로 같은 template을 clone한다. 콘텐츠를 JS 문자열과 HTML에 이중으로 복제하지 않으므로 source of truth도 하나로 유지된다.

## 고려했지만 선택하지 않은 방향

### README 본문 전체를 JavaScript 문자열로 이동

긴 HTML/라이선스 텍스트를 escape된 문자열로 관리해야 하며 가독성과 유지보수가 나빠지므로 기각했다.

### legacy dialog 내용을 계속 source로 사용

single-shell cutover blocker가 그대로 남으므로 기각했다.

### README 본문을 두 벌 유지

내용 drift 위험과 source-of-truth 위반 때문에 기각했다.

### 이번 패치에서 native dialog 자체까지 제거

active legacy shell이 아직 존재하므로 cutover 전에 기능을 제거하게 된다. 이번 단계에서는 콘텐츠 authority만 분리한다.

## 위험 요소

- `<template>.content` clone 결과와 `template.innerHTML`이 동일 본문을 나타내야 한다.
- `Close` 버튼은 README 콘텐츠가 아니라 legacy presentation에 속하도록 template 밖에 있어야 한다.
- legacy dialog content clone은 event handler 설치 전에 한 번 수행되어야 한다.
- template 자체는 사용자 화면에 렌더링되지 않아야 한다.
