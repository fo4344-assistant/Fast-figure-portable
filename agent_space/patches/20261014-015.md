# 20261014-015 — Define plan-014 Source Script projection semantics

## 목적과 변경

- `sourcescript/api_ui.py`: Layout Modal selection/background deselection 경계 추가.
- `sourcescript/application_fsm.py`: logical-event completion과 mutation-result 계약 보강.
- `sourcescript/assets_files.py`: trash move/empty에서 실제 제거된 reference 결과를 mutation owner가 산출하도록 명세.
- `sourcescript/renderer_runtime.py`: FULL_DASHBOARD / TARGETED_PROJECTION / NONE invalidation과 send 반환 뒤 orchestration 규칙 추가.
- Source Script r20 fingerprint와 closure review를 등록하고 하위 계층을 stale로 표시.

## 선택 이유

region별 publish는 한 logical event 안에서 여러 번 발생할 수 있으므로 renderer invalidation 경계로 부적합하다. 동기 `send()` 반환 뒤의 final state/result를 사용하면 selection reconciliation까지 끝난 current authority를 한 번만 projection할 수 있다.

conditional invalidation은 renderer가 VFS/DOM을 추측하는 대신 mutation owner가 실제 제거한 reference 결과를 제공하도록 했다.

## 기각한 방향

- appFSM 내부 completion-listener registry 추가: 현재 동기 send contract로 충분하다.
- 모든 publish마다 full render: 중복 render와 중간 state projection을 만든다.
- 모든 mutation을 full render로 통일: targeted renderer의 책임을 불필요하게 넓힌다.
- Layout selection을 project state에 저장: UI-local lifetime을 persistent authority로 잘못 승격한다.
