# 20260902-006 — Mantine graph 전역 layout staging

## 목적

`20260902-005`에서 만든 DOM-free graph layout bridge를 실제 inactive Mantine sidebar staging에서 사용한다.

이번 범위는 graph layout 전체 중 다음 전역 설정으로 제한한다.

- 그래프 제목
- 범례 표시
- 타이틀 표시
- 0선 표시
- 그래프 폰트
- 타이틀 글자 크기
- 범례 글자 크기

네 축의 상세 설정은 tick-mode/log-scale 상호작용까지 포함하므로 다음 패치로 분리한다.

## 변경 내용

- 앱 버전 `1.1.57-alpha` → `1.1.58-alpha`
- `FastFigureSidebarStaging()`에서 `readChartLayout()` snapshot을 읽음
- graph chart가 선택된 경우 Mantine `Stack`, `TextInput`, `Switch`, `Select`, `NumberInput`, `SimpleGrid`로 전역 graph layout UI를 렌더
- `GRAPH_FONT_OPTIONS`를 그대로 Mantine Select data로 재사용
- 모든 commit은 `fastFigureUiBridge.applyChartLayout(values)`를 통과
- 제목/숫자 입력은 uncontrolled draft + blur/Enter commit
- toggle/font Select는 기존 legacy semantics와 같이 즉시 commit

## commit timing 보존

기존 legacy UI:

- 제목: native `change`, Enter 시 blur
- graph font: `change`
- title/legend font size: native `change`, Enter 시 blur
- showLegend/showTitle/showZeroLine: 클릭 즉시 적용

Mantine staging도 같은 의미를 유지한다.

TextInput/NumberInput은 `defaultValue`를 사용하므로 사용자가 focus 중 편집하는 값은 component 내부 입력 draft일 뿐 domain state를 복제한 React persistent state가 아니다.

- blur 시 commit
- Enter 시 blur하여 commit
- 외부 domain 값이 바뀌면 `key`가 바뀌어 새 canonical 값으로 input을 재생성

Switch와 Select는 변경 즉시 기존 bridge로 commit한다.

## source of truth

유일한 persisted source는 selected chart editor/global settings다.

- `readChartLayout()` 반환값은 render snapshot
- uncontrolled input 내부값은 commit 전 draft
- `GRAPH_FONT_OPTIONS`는 기존 graph font 선택지 정의를 그대로 재사용
- Mantine component state를 다른 기능에서 참조하지 않음

## Mantine/Core 분류

순수 UI staging이다.

변경하지 않는다.

- graph/domain model
- `CHART_LAYOUT_CHANGED`
- Plotly renderer
- graph object EFSM
- axis 계산
- import/export
- 기존 legacy UI 활성 상태

staging shell은 기존 계획대로 cutover 전까지 비활성 상태다.

## 기존 구조 재사용

- `fastFigureUiBridge.readChartLayout()`
- `fastFigureUiBridge.applyChartLayout(values)`
- `GRAPH_FONT_OPTIONS`
- Mantine theme의 공통 control 규격

별도 graph settings state나 별도 renderer를 만들지 않는다.

## 선택하지 않은 방향

### React `useState`에 graph global settings 전체 복사

같은 chart 설정을 domain과 React가 동시에 장기간 보유하게 되므로 사용하지 않는다.

### `onChange`마다 제목/숫자 commit

native `change`보다 commit 빈도가 커져 Plotly rerender 횟수와 사용자 동작 의미가 달라지므로 사용하지 않는다.

### 축 UI까지 한 패치에서 추가

축에는 `tickMode`, `minorTicks`, log scale 조건, notation/scale type 등 별도 의미가 있으므로 회귀 범위를 줄이기 위해 분리한다.

## 회귀 위험

낮음. inactive staging UI만 추가하며 기존 legacy handler와 domain/renderer를 바꾸지 않는다.

확인 항목:

- graph slot에서만 전역 graph layout controls 표시
- image/빈 slot에서는 표시하지 않음
- Select option이 기존 `GRAPH_FONT_OPTIONS`와 동일
- `false` toggle이 올바르게 전달됨
- 빈 font-size가 자동값 의미를 유지
- Enter가 blur를 발생시켜 한 번 commit
- selected chart 변경 시 이전 draft가 새 chart로 넘어가지 않음

## rollback

Sidebar staging의 graph-layout render block과 `Switch` import, `chartLayout` snapshot 변수만 제거하고 앱 버전을 복원하면 된다.

`20260902-005`의 DOM-free bridge는 독립적으로 유지할 수 있다.

## 후속

다음 패치에서 xBottom/xTop/yLeft/yRight 축 상세 UI를 동일 bridge에 추가하되 기존 `tickMode`/`minorTicks`와 log-scale 규칙을 그대로 보존한다.
