# 20260916-016

## 목적과 변경 내용

Mantine graph data/object editor가 이미 backend/core `graphEditor*` functional command를 사용하는 상태에서, 더 이상 호출되지 않는 legacy native graph object form read/apply 체인을 제거한다.

이번 패치는 다음 legacy UI 함수와 obsolete audit 항목을 제거한다.

- `readAxis(key)`
  - native axis DOM control 값을 읽던 form reader
- `graphPalette()`
  - `configFromForm()`을 위해 legacy editor object 색상 배열을 읽던 helper
- `configFromForm()`
  - native graph/object/global form control을 chart model copy로 조립하던 legacy form projection
- `applyGraphSettings()`
  - 위 form projection을 `CHART_MODEL_REPLACED`에 전달하던 legacy native apply handler
- `REQUIRED_APP_FUNCTIONS`의 `configFromForm` / `applyGraphSettings` 항목

`applyGraphSettings()` 안에 `20260916-012` 이후 단독으로 남아 있던 제거된 `activeDataReady` debug 참조도 함수 전체와 함께 제거된다. 이를 새 변수나 compatibility bridge로 대체하지 않는다.

## ownership 확인

current source에서 호출 관계를 다시 확인했다.

- `readAxis()`는 `configFromForm()`에서만 호출된다.
- `graphPalette()`는 `configFromForm()`에서만 호출된다.
- `configFromForm()`은 `applyGraphSettings()`에서만 호출된다.
- `applyGraphSettings()`는 정의 외 호출이 없다.

따라서 네 함수는 active Mantine/core 경로와 분리된 하나의 legacy native form ownership 단위다.

## active graph mutation boundary 확인

`review-011-sot-api-boundary.md`의 순서를 다시 확인한 뒤 active Mantine graph mutation 경로도 함께 감사했다.

Mantine frontend는 graph/domain object를 직접 변경하지 않고 다음 backend/core command 또는 logic EFSM event를 사용한다.

- object replacement/update: `graphEditorCommit()` → `GRAPH_OBJECTS_REPLACED`
- object selection: `SELECT_GRAPH_OBJECT` / `CLEAR_GRAPH_OBJECT`
- CSV asset selection: `graphEditorSelectCsv()` → `SELECT_ASSET`
- empty graph creation: `graphEditorAdd()` → `SLOT_DATA_CONNECTED` + `graphEditorCommit()`
- graph layout mutation: `CHART_LAYOUT_CHANGED`

`graphEditorHeaderLines()`와 `graphEditorSetEditable()`는 `fast-figure.js` 안의 functional command 경계 자체이며 Mantine component 내부의 direct project mutation이 아니다. 이 둘을 UI projection으로 오인해 제거하거나 별도 EFSM event를 추가하지 않는다.

## 선택 이유

legacy native form은 현재 사용자 입력 경로가 아니며, 유지할 경우 다음 문제가 남는다.

- native DOM control을 project/chart state의 또 다른 입력 source처럼 보이게 한다.
- 이미 제거된 native axis/layout installer와 결합된 dead path를 계속 유지한다.
- `rows` / `columns` 같은 legacy UI buffer가 backend 기능 상태처럼 보이는 원인이 된다.
- `REQUIRED_APP_FUNCTIONS`가 실제 application/core invariant가 아니라 dead native UI 함수까지 필수 기능처럼 검사한다.

호출이 닫힌 전체 체인을 함께 제거하는 것이 부분 helper 삭제보다 ownership과 rollback 경계가 명확하다.

## 보존하는 경계

이번 패치는 다음을 변경하지 않는다.

- `ApplicationStateMachine`과 logic EFSM definitions/actions
- `GRAPH_OBJECTS_REPLACED`, `CHART_MODEL_REPLACED`, `CHART_LAYOUT_CHANGED`, `SLOT_DATA_CONNECTED`, `SELECT_ASSET` event semantics
- `activeProject`, `ProjectObject`, chart/csv persistence schema
- `graphEditorChart`, `graphEditorCommit`, `graphEditorSelectCsv`, `graphEditorSelectObject`, `graphEditorObjectValues`, `graphEditorAdd`, `graphEditorMove`, `graphEditorDelete`, `graphEditorHeaderLines`, `graphEditorSetEditable`
- `currentAxes`, `readGlobalSettings`, `normalizeGlobalSettings`, `axisKey`
- `traces`, `layout`, `chartFigure`, `renderDashboard`, Plotly renderer/range sync
- Mantine `FastFigureGraphDataEditor`, `FastFigureGraphLayoutEditor`, palette/file actions

즉 native UI component/form code 제거와 logic EFSM/core command 변경을 섞지 않는다.

## 고려했지만 선택하지 않은 방향

### `graphEditorHeaderLines()`를 새 EFSM event로 교체

선택하지 않았다. frontend는 해당 command를 호출할 뿐 `csv.headerLines`를 직접 쓰지 않는다. 이 함수는 header-line 변경과 dependent editable graph rebuild를 묶은 backend functional command다. 새 event를 추가하면 현재 필요한 경계보다 복잡도가 늘어난다.

### `graphEditorSetEditable()`를 여러 EFSM event로 분해

선택하지 않았다. Plotly JSON → editable CSV 전환, object CSV 연결, editable mode 변경은 하나의 functional command ownership으로 동작한다. Mantine component는 내부 project mutation을 수행하지 않는다.

### `CHART_MODEL_REPLACED` event 제거

선택하지 않았다. 이번 패치에서 legacy caller 하나가 사라지더라도 event 자체의 logic/domain 의미를 UI cleanup과 함께 제거해서는 안 된다. 별도 logic-level dead-code audit 없이는 유지한다.

### `loadData()` / `refreshColumnControls()` / `preview()` / `rows` / `columns`까지 같이 제거

선택하지 않았다. 이들은 legacy CSV preview/data buffer ownership으로 별도 호출자와 markup이 남아 있다. 다음 패치에서 native data-preview/object-list 경로와 함께 감사한다.
