# 20260910-017 — Legacy asset explorer interaction cutover

## 목적
013/014/016으로 Mantine PROJECT DATA가 project-node action menu, move/trash, internal drag/drop, project-asset → slot link, external OS file → folder/slot drop, collision Modal을 소유하게 되었으므로 legacy `#assetTree`의 활성 generic UI interaction 경로를 끊는다. 두 UI가 동시에 같은 EFSM/project VFS를 조작하는 이중 ownership과 legacy document-level click handler가 Mantine selection을 지울 수 있는 간섭을 제거한다.

## 변경 내용
- `fast-figure.js`: legacy `#assetDownload` onclick 연결을 제거한다. `downloadProjectAsset()` command는 Mantine에서 사용하므로 유지한다.
- legacy `#assetActions` action-menu onclick 연결을 제거한다.
- legacy `#deleteSelectedAsset` onclick 연결을 제거한다. 삭제 command/helper는 후속 dead-code 정리 전까지 유지한다.
- legacy `#newAssetFolder` onclick 연결을 제거한다.
- legacy `#assetTree` click selection handler를 제거한다.
- legacy document-level asset-selection clear click handler를 제거한다. 이 handler는 Mantine DOM을 legacy tree/control 목록으로 인식하지 못해 Mantine interaction 뒤 selection을 지울 수 있었다.
- 초기화 시 `installAssetTreeInteractions()`를 호출하지 않아 legacy tree keyboard/DnD/action-menu listener가 설치되지 않게 한다.
- legacy renderer/snapshot/helper와 EFSM/project VFS는 이번 패치에서 삭제하지 않는다.

## 설계 및 Source of truth
Persistent authority는 기존 `activeProject`, `projectVfs`, `appFSM` 그대로다. Mantine PROJECT DATA는 013/014/016에서 이 authority에 직접 command/event를 보내는 feature-equivalent path를 확보했다. 이번 패치는 새로운 state나 bridge를 추가하지 않고 legacy DOM event ownership만 끊는다.

`renderProjectDataTree()`, `projectDataTreeSnapshot()`, selection/download/import commands 등은 아직 다른 legacy sync path나 Mantine 코드가 참조할 수 있으므로 기능 단위 의존성 확인 없이 함께 삭제하지 않는다. 이것은 장기 공존을 위한 것이 아니라 cutover와 dead-code deletion을 분리해 롤백 경계를 명확히 하기 위한 것이다.

## EFSM/core 영향
없음. 새로운 event/action/state를 추가하지 않으며 기존 project move/import/delete/link semantics를 수정하지 않는다. `PROJECT_NODE_MOVED`, DATA/IMAGE/SLOT events와 project VFS validation/rollback은 그대로 유지된다.

## 기각안
- Mantine interaction 뒤 legacy DOM `.click()`을 호출하는 bridge: 장기 결합이므로 기각.
- legacy와 Mantine explorer를 모두 활성 상태로 유지: 동일 authority에 두 generic UI owner가 생기고 document click 간섭이 남으므로 기각.
- 이번 패치에서 legacy renderer/helper 전체 삭제: 아직 호출 관계가 남아 있을 가능성이 있으므로 rollback 범위가 과도하게 커져 기각.
- legacy document click handler에 Mantine selector 예외만 추가: 이중 ownership 자체를 남기므로 기각.

## 검증
Workflow의 `git apply --check`, `git diff --check`, JavaScript syntax, portable build, split/portable Chromium `file://` smoke를 통과해야 한다. 수동 확인 항목은 Mantine tree selection 유지, item menu download/move/trash, folder create/empty trash, internal move/link DnD, external folder/slot drop, collision Modal이며 legacy tree 조작이 더 이상 project state를 변경하지 않는지도 확인한다.

## 롤백
이 패치 하나를 revert하면 013/014/016의 Mantine 구현은 남은 채 legacy explorer event wiring만 다시 활성화된다. 따라서 cutover 문제와 Mantine 기능 문제를 별도로 진단할 수 있다.

## 후속
성공 후 `ASSET_TREE_ACTION_SCHEMA`, `renderAssetTreeActionMenu`, `syncAssetTreeActionMenu`, `emptyProjectTrash`, `installAssetTreeInteractions`, legacy delete/create wrappers 등 실제 참조가 사라진 dead helper를 검색해 제거한다. HTML의 legacy explorer controls와 REQUIRED_CONTROL_IDS 제거는 그 다음 ownership cleanup 단위에서 함께 처리한다.
