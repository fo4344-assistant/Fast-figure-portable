# 20261016-007

## 목적과 변경 이유

Plan 016의 나머지 API 경계 작업 중 print/export settings ownership을 전환한다. public API가 authoritative export settings를 직접 읽고 candidate를 만드는 대신 Backend read provider와 Project EFSM command가 해당 책임을 소유하도록 한다. 사용자가 먼저 확인하라고 한 정책 원칙을 기억하고 있는지 확인하고 `development-policy.md`의 관련 원문을 대조한 후 진행했다.

## 실제 누적 diff와 publication

- 시작 HEAD: `b47aaf3e6063f1a425c34e354ed9ef7a68d74fb1`.
- 의미 변경 및 관련 문서 종료 HEAD: `10393943f7b2c40c54e0da9721251bc63d2028fb`.
- 생성 명령: `git diff --find-renames --binary b47aaf3e6063f1a425c34e354ed9ef7a68d74fb1 10393943f7b2c40c54e0da9721251bc63d2028fb`.
- source/test/r36 metadata, Plan 016 진행, review와 Actions bot distribution을 포함한 실제 remote commit 간 누적 diff이다. ZIP은 Git binary patch로 포함했다. 이 patch/설명 쌍은 self-reference를 피하기 위해 종료 HEAD 이후 별도 commit으로 기록한다.
- Contents API의 순차적인 파일별 write 직전마다 최신 HEAD, 대상 blob SHA 또는 새 경로 부재를 확인했다. 원자적인 multi-file source/doc commit은 아니며, 중간 source-before-metadata commit의 실패를 최종 성공으로 은폐하지 않는다. 임시 payload와 helper는 현재 작업경로 아래만 사용했다.

## 구현과 선택한 대안

- `readPrintApiSettings`는 Application을 통해 frozen Backend projection을 받는다. setter는 새 edit patch만 dispatch하고 성공 후 fresh projection을 반환한다.
- Backend `applyExportSettingsChangedAction`은 current export settings에서 candidate를 만들고 기존 숫자 범위·enum fallback·auto/explicit height 규칙을 적용한 뒤 validate/commit한다. public API에 있던 계산을 이전했으며 새로운 기능 의미는 추가하지 않았다.
- API candidate calculation을 유지하는 대안은 ownership cutover를 미완성으로 남기므로 배제했다. read snapshot 전체를 setter input으로 재사용하는 대안은 stale projection을 authority로 되돌리므로 배제했다.
- React print editor는 이미 새 patch만 보내므로 불필요하게 수정하지 않았다. 전체 export renderer를 이번 설정 단위와 동시에 재작성하는 대안은 다른 domain/renderer ownership까지 범위를 넓히므로 배제했다.
