# 20260928-024

## 목적과 변경 내용

활성 Mantine 프로젝트·슬롯·이미지 편집의 남은 직접 SoT 접근을 core API로 이동한다. 프로젝트 이름 읽기/입력/blur 확정과 FFPX 가져오기·내보내기를 `FastFigureApi.project`에서 수행한다. 선택 슬롯의 표시값·선택·유형 변경·초기화는 `slots`에서 읽고 실행한다. 이미지 이름·표시 URL·맞춤 설정은 `images.readEditor()`로 읽고, 설정 변경 및 빈 이미지 삽입은 기존 core 명령으로 실행한다.

이미지 설정의 기본값/범위 계산을 읽기 함수로 분리하여 Mantine 화면을 그리는 과정에서 프로젝트 이미지 객체의 `settings`를 변경하지 않는다. 기존 기능 renderer가 정규화된 설정을 저장하는 경로는 유지한다. UI에는 텍스트 입력과 확인창의 컴포넌트 범위 상태만 남긴다. FFPX와 이미지 schema는 변경하지 않는다.

## 선택 이유

프로젝트 이름과 이미지 설정은 `activeProject`가 소유하고, 선택 슬롯과 유형 변경은 core/EFSM이 소유한다. 기존 UI는 이름을 직접 기록하고 이미지를 읽으면서 정규화 함수로 프로젝트 객체를 변경했다. core의 최소 읽기·명령 경계를 통해 동일한 기능을 제공하면 UI가 프로젝트 참조를 보관하지 않고, renderer와 EFSM의 기존 책임도 유지된다.

## 고려했지만 선택하지 않은 방향

- **프로젝트 이름과 이미지 설정을 React state에 복제한 뒤 변경마다 동기화:** 입력 초안과 영속 상태 사이의 최신성 판정이 생기고, 다른 파일 가져오기나 슬롯 변경에 취약하다.
- **이미지 설정 정규화를 UI에서 계속 호출:** 읽기 렌더만으로 영속 이미지 모델이 바뀌고 프런트엔드가 그 변경을 간접 소유한다.
- **FFPX 파서와 슬롯 초기화 이벤트를 UI에 유지:** 파일 의미와 연쇄 EFSM 명령이 UI에 남아 다른 Mantine 기능과 같은 경계를 갖지 못한다.

## 범위와 후속 작업

프로젝트 이름의 입력 시 120자 제한과 blur trim, 기존 FFPX 및 이미지 설정 명령의 의미를 유지한다. 그래프 native 입력 폼은 현재 HTML에 존재하지 않는다. 남은 작업은 no-op legacy control 정리 여부의 실제 참조 확인과 `plan-006.md`의 17항목 기능 회귀 검사다. Actions 초기화 smoke만으로 파일 왕복, 충돌·드래그·설정 상호작용은 검증되지 않는다. 역적용하면 프로젝트·슬롯·이미지의 UI 직접 접근으로 돌아간다.
