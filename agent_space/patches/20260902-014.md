# 20260902-014 — graph object CSV column read model

## 목적

Mantine graph object form의 X/Y `Select`가 legacy 전역 `columns` 또는 native `#xCol/#yCol` option을 읽지 않도록, 현재 선택 graph object가 참조하는 CSV에서 column option을 직접 파생한다.

`20260902-012`의 `selectedGraphObjectModel()`을 확장하되 persisted state나 write 경로는 변경하지 않는다.

## 변경 내용

- 앱 버전 `1.1.62-alpha` → `1.1.63-alpha`
- selected object의 `csvId`로 `getProjectCsv(object.csvId)`를 조회
- CSV가 있으면 `columnDefinitions(csv.rows, csv.headerLines ?? 1)`로 열 정의 계산
- snapshot에 다음을 추가
  - `csvId`
  - `csvName`
  - `columns: [{ id, label }, ...]`
- 반환 column object와 array는 read snapshot임을 명확히 하기 위해 freeze

## DOM fallback 차단

기존 `columnDefinitions(table, headerLines)`는 두 번째 인자를 생략하거나 `undefined`로 전달하면 legacy `#headerLines` DOM 값을 기본값으로 읽을 수 있다.

따라서 selector에서는 반드시:

```text
columnDefinitions(csv.rows, csv.headerLines ?? 1)
```

처럼 명시적인 header line 값을 전달한다.

이렇게 하면 React read model이 legacy DOM 존재 여부나 현재 활성 CSV form 값에 의존하지 않는다.

## source of truth

- graph object CSV 참조: `object.csvId`
- CSV 데이터/header 설정: project CSV model의 `rows`, `headerLines`
- column list: 위 두 persisted 값에서 계산한 파생 snapshot

전역 `rows`, `columns`, native select option은 source of truth로 사용하지 않는다.

## read 순수성

호출하는 함수:

- `getProjectCsv(id)` — collection lookup
- `columnDefinitions(rows, explicitHeaderLines)` — 전달된 table/header로 열 정의 계산
- `projectClone(object)` — object snapshot 분리

selector는 CSV/chart/object에 대입하지 않으며 normalization/mutation helper를 호출하지 않는다.

## Mantine/Core 분류

UI selector 확장만 수행한다.

변경하지 않는다.

- graph object schema
- CSV header 저장 의미
- `GRAPH_OBJECTS_REPLACED`
- graphObject EFSM
- trace/Plotly renderer
- import/export
- 활성 legacy form

## 선택하지 않은 방향

### 전역 `columns` 재사용

선택하지 않았다. 전역 `columns`는 현재 활성 CSV/editor 흐름의 transient 값이며 selected object가 실제로 참조하는 CSV와 항상 같다는 보장이 없다.

### native `#xCol/#yCol` option clone

선택하지 않았다. Mantine read model이 legacy DOM renderer에 종속된다.

### `columnDefinitions(csv.rows)`만 호출

선택하지 않았다. `csv.headerLines`가 undefined인 경우 DOM default parameter가 실행될 수 있으므로 explicit fallback `?? 1`을 전달한다.

### column definitions를 persisted object에 저장

선택하지 않았다. CSV rows/headerLines에서 계산 가능한 파생값을 별도 persisted state로 만들 필요가 없다.

## 회귀 위험

낮다. 기존 selector의 반환값에 파생 정보만 추가하며 기존 write/renderer 호출자는 변경하지 않는다.

검사 항목:

- object.csvId가 유효하면 해당 CSV 기준 columns 반환
- 다른 active CSV가 선택되어 있어도 object CSV 기준 결과 유지
- CSV가 없으면 `csvId=null`, 빈 columns
- `headerLines=0` 보존 (`?? 1`이 0을 덮어쓰지 않음)
- selector 호출 전후 CSV/chart/object 불변
- legacy DOM read가 selector 경로에 없음

## rollback

1. `selectedGraphObjectModel()`의 csv/column 계산 제거
2. snapshot의 `csvId`, `csvName`, `columns` 제거
3. 앱 버전 `1.1.62-alpha` 복원

`012`/`013` read/write boundary는 독립 유지 가능하다.

## 후속 작업

적용 성공 후 inactive Mantine sidebar에 selected graph object form을 연결한다. X/Y Select data는 이 `columns` snapshot만 사용하며 모든 write는 `applyGraphObject(values, chartId, objectIndex)` 경계로 보낸다.
