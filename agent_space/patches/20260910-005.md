# 20260910-005 — Mantine print/export ownership 최종 교정

## 목적
`20260910-004`는 현재 source context는 정확했지만 동일 파일의 연속 hunk에서 앞선 추가 행 수를 후속 hunk의 `new_start`에 누적하지 않아 `git apply --check`가 실패했다. 구현 내용은 변경하지 않고 unified diff 좌표만 교정해 print/export Mantine ownership을 적용한다.

## 변경
- `exportDashboard(capture, options)`에 `{ dpi, format, onStatus }` 값 기반 호출 경계를 추가한다.
- `exportDashboardTarget(options)`에 `{ width, height, dpi, format, onStatus }` 값 기반 호출 경계를 추가한다.
- Mantine `FastFigurePrintOverlay`를 추가해 PNG/JPEG, DPI, 폭/높이 및 자동 높이, 설정 크기 저장과 현재 화면 캡처를 직접 제공한다.
- Mantine 경로는 legacy print input의 `.value`나 legacy button `.click()`을 사용하지 않는다.
- 기존 `PRINT_EXPORT`/`CAPTURE_EXPORT` lifecycle과 export renderer는 그대로 재사용한다.

## 003/004 실패와의 관계
- `003`: source 실제 위치와 맞지 않는 hunk 좌표로 적용 전 실패.
- `004`: old-side context와 line 위치는 맞았으나 동일 파일 앞 hunk의 추가 행 수를 후속 `new_start`에 반영하지 않은 unified diff 좌표 오류로 적용 전 실패.
- 두 실패 모두 application source를 변경하지 않았다.
- `005`는 004와 동일한 코드 변경에 누적된 new-side line offset만 올바르게 반영한 대체 패치다.

## 선택 이유
기능을 다시 분해하거나 재설계할 이유가 없는 패치 형식 문제다. WIP 구현 우선 원칙에 따라 동일 ownership 단위를 그대로 유지하면서 patch 좌표만 교정한다.

## Source of truth / EFSM 영향
project model과 기존 export renderer가 계속 기능 source of truth다. 출력 입력값은 일회성 React local state다. FFPX schema와 functional EFSM은 변경하지 않는다.

## WIP 제한
legacy print UI는 아직 공존한다. 최종 cutover에서 제거한다.

## 검증
workflow의 git apply, JS syntax, portable build, split/portable file smoke를 모두 통과해야 한다.

## Rollback
역적용 시 Mantine print/export UI와 options 기반 export entry만 제거된다. 데이터 migration은 없다.
