# 20260903-002 — legacy graph editor presentation adapter 추출

## 목적

`20260903-001`에서 graph/CSV selection을 `selectChartForEditing()`으로 분리했다. 이번 패치는 `editChart()`에 남은 native graph form synchronization을 `syncLegacyGraphEditorSelection(selection)` presentation adapter로 명시적으로 분리한다.

이 작업은 workspace EFSM entry에서 domain selection과 legacy UI 표시를 독립적으로 호출할 수 있게 하기 위한 준비 단계다.

## 변경 내용

- 앱 버전 `1.1.104-alpha` → `1.1.105-alpha`
- 기존 `editChart()`의 native form synchronization body를 `syncLegacyGraphEditorSelection(selection)`으로 이동
- `editChart(id)`는 다음 두 단계만 수행하는 wrapper로 축소
  1. `selectChartForEditing(id)`
  2. `syncLegacyGraphEditorSelection(selection)`
- form synchronization 순서와 호출 함수는 변경하지 않음

presentation adapter가 계속 담당하는 항목:

- file name
- header line input
- `loadData()` 기반 legacy X/Y option / preview
- graph object native controls
- global/axis native controls
- legacy graph-object list
- editable UI 표시
- 기존 status message

## 이유

active legacy UI를 유지한 채 cutover boundary를 준비하려면 domain helper와 legacy presentation adapter가 둘 다 필요하다. UI를 조건 분기로 숨기는 대신 책임 자체를 함수 경계로 분리하면, 이후 EFSM workspace entry에서 presentation adapter를 제거할 때 domain selection을 그대로 유지할 수 있다.

## 고려했지만 선택하지 않은 방향

### 현재 단계에서 presentation body 삭제

기각. 아직 legacy sidebar가 active owner이므로 사용자 기능이 즉시 사라진다.

### Mantine component에서 `editChart()` 호출

기각. Mantine가 native form synchronization까지 호출하게 되어 cutover 후 legacy DOM 의존성이 남는다.

### graph form state를 React state로 복제

기각. chart/editor model과 중복 authority가 생긴다.

## 의미 보존

`editChart(id)`를 외부에서 호출했을 때의 현재 동작은 동일하다. 단지 내부적으로 domain selection과 presentation synchronization이 명시적 두 단계가 된다.

FFPX/FFSX/Plotly schema, renderer, EFSM event는 변경하지 않는다.

## 검증

- `git apply --check`
- `git diff --check`
- application JavaScript `node --check`
- `editChart(id)` 호출 시 기존 native controls 동기화 유지
- `selectChartForEditing(id)` 단독 호출 시 native form 접근 없음

## rollback

`syncLegacyGraphEditorSelection()` body를 다시 `editChart()`에 합치고 버전을 `1.1.104-alpha`로 되돌리면 된다.

## 후속

workspace sync 함수들을 domain callback + legacy adapter로 분리한다.
