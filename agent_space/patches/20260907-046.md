# 20260907-046 — Mantine new-folder modal

## Purpose

Replace the PROJECT DATA tree's legacy `window.prompt()` folder-name input with a Mantine `Modal` + `TextInput`, while continuing to use the existing functional EFSM events for directory creation and asset selection.

This is a presentation-layer implementation only. The project VFS, directory validation, project model mutation, and EFSM definitions remain unchanged.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- `createAssetDirectory()` or the legacy prompt path
- `projectVfs`
- `PROJECT_DIRECTORY_CREATED` transition/action
- `SELECT_ASSET` transition/action
- project/model classes
- delete/trash behavior
- asset drag/drop behavior

## Exact changes

1. Adds Mantine `Modal` and `TextInput` to the existing UI-runtime component imports.
2. Extends `FastFigureProjectDataTree` with presentation-local state for:
   - the last directory selected in the Mantine tree,
   - whether the new-folder modal is open,
   - the modal's parent directory,
   - the folder-name text value.
3. Selecting a directory in the Mantine tree records that directory as the next folder-creation parent while still calling the existing `selectDirectoryFromTree(path)` function.
4. Adds a Mantine `새 폴더` button to the PROJECT DATA section.
5. Opening the modal uses the last selected non-trash `/assets` directory as the parent, otherwise `/assets`.
6. Confirming folder creation sends the already-existing EFSM events directly:
   - `PROJECT_DIRECTORY_CREATED` with `{ parent, name, direction: "ui-to-fsm" }`
   - `SELECT_ASSET` for the returned `payload.path`
7. On successful creation, the new path becomes the Mantine tree's remembered parent and the modal closes.
8. Existing EFSM validation errors are surfaced through the existing `status()` path and the modal remains open so the user can correct the name.
9. Escape/outside-click/focus trapping are left to Mantine `Modal` defaults rather than adding new custom popup lifecycle code.

## State ownership

The new React state is exclusively presentation state:

- modal open/closed
- current text input value
- remembered tree directory for the next UI action

Persistent directory state and validation continue to belong to the existing project model/EFSM. No React copy of the VFS is created.

## Why this direction

The legacy `createAssetDirectory()` function combines a browser prompt with already-separated EFSM events. Calling that function from Mantine would preserve `window.prompt()` and defeat the UI replacement. Reimplementing directory creation itself would duplicate project/VFS logic.

The correct replacement point is therefore the prompt and button only: Mantine collects the input, then sends the same existing EFSM events.

## Rejected alternatives

### Calling `createAssetDirectory()` from Mantine

Rejected because it would still invoke `window.prompt()` and leave a legacy generic UI primitive in the Mantine path.

### Calling the legacy `#newAssetFolder` button

Rejected because legacy DOM must not become an internal API.

### Moving directory validation into React

Rejected because `PROJECT_DIRECTORY_CREATED` and the project VFS already own validation and mutation.

### Changing EFSM to support Mantine-specific events

Rejected because the existing events already express exactly the required functional operation.

## Rollback

Revert the `20260907-046.patch` changes in `fast-figure-ui.js`. No project data or EFSM rollback is necessary.
