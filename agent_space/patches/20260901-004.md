# 20260901-004 — React/Mantine shell staging

## 목적

계획 003의 shell cutover 원칙을 유지하면서 React/Mantine application shell 코드를 비활성 staging 상태로 준비합니다.

## 변경 범위

- 애플리케이션 버전을 `1.1.34-alpha`로 갱신합니다.
- 기존 `fastFigureUiBridge`와 `useFastFigureFsmSnapshot()`을 재사용합니다.
- `FastFigureToolbarStaging`을 추가합니다.
  - overlay 활성 상태는 EFSM snapshot에서 읽습니다.
  - Layout/Label/Caption/Print 동작은 기존 `TOGGLE_OVERLAY` 이벤트를 그대로 사용합니다.
  - 별도 React 상태로 overlay 의미를 복제하지 않습니다.
- `FastFigureShellStaging`을 추가합니다.
  - Mantine `Stack`, `Box`, `Title`, `Text`를 사용해 향후 shell의 최상위 구조를 준비합니다.
- staging component는 `window.FastFigureReactShell`에 노출하지만 현재 root에는 렌더링하지 않습니다.

## 의도적으로 하지 않는 변경

- 기존 toolbar/sidebar/main DOM을 숨기거나 교체하지 않습니다.
- React Portal을 legacy UI 위치에 삽입하지 않습니다.
- Plotly/dashboard/layout-map/label-preview 같은 domain renderer를 변경하지 않습니다.
- EFSM event 이름, transition, guard, domain mutation을 변경하지 않습니다.
- legacy DOM sync를 아직 제거하지 않습니다. 실제 shell cutover 시점에 한 번에 제거합니다.

## 회귀 위험과 확인 항목

1. staging component가 mount되지 않으므로 현재 사용자 UI와 동작은 기존과 동일해야 합니다.
2. `useSyncExternalStore`는 003에서 추가한 versioned snapshot을 사용해야 합니다.
3. toolbar callback은 DOM을 직접 조작하지 않고 `fastFigureUiBridge.send()`만 호출해야 합니다.
4. patch 적용 후 JavaScript syntax 검사를 통과해야 합니다.
5. 이후 sidebar와 modal staging이 준비되기 전에는 React shell을 활성화하지 않습니다.
