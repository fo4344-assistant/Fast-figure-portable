# 20260910-020 — Legacy asset DnD policy dead-code removal

## 목적
017에서 legacy asset-tree interaction 설치를 중단한 뒤 더 이상 실행되지 않는 legacy DnD policy/visual-state helper를 제거한다. Mantine tree는 자체 drag gesture state와 기존 project VFS/FSM command를 직접 사용하므로 이 정책 블록과 공유하지 않는다.

## 변경 내용
- `ASSET_TREE_DRAG_TYPE`, `ASSET_TREE_LOCKED_TYPE` 제거.
- `assetTreeDropTarget()` 제거.
- `assetTreeDropPolicy()` 제거.
- `clearAssetTreeDropState()` 제거.
- Mantine이 사용하는 `connectProjectAssetToSlot()`은 유지한다.
- 아직 dead 상태로 남아 있는 `executeAssetTreeDrop()`/`installAssetTreeInteractions()`는 다음 패치에서 제거한다. 이 함수들은 017 이후 호출되지 않으므로 이번 삭제로 runtime behavior는 변하지 않는다.

## Source of truth 및 EFSM 영향
없음. project asset 이동/연결/import authority는 `appFSM`, `projectVfs`, `PROJECT_NODE_MOVED`, SLOT/DATA/IMAGE events 그대로다. Mantine DnD는 013/014/016에서 이 authority에 직접 연결되어 있다.

## 기각안
- legacy policy를 Mantine에서 재사용: legacy DOM dataset과 DataTransfer custom MIME contract를 UI-independent 정책처럼 유지하게 되므로 기각.
- `connectProjectAssetToSlot()`까지 함께 제거: Mantine `/slots` drop이 직접 사용하므로 기각.
- 대규모 DnD 블록을 한 hunk로 삭제: 과거 malformed hunk 실패를 고려해 독립적으로 dead인 policy 블록과 listener/executor 블록의 rollback 경계를 나눈다.

## 검증
Workflow의 patch check, diff check, JavaScript syntax, portable build, split/portable `file://` smoke를 통과해야 한다. Mantine internal move, project asset → slot link, external file → folder/slot drop이 그대로 동작해야 한다.

## 롤백
이 패치만 revert하면 legacy DnD policy/helper 정의만 복원된다. 017 때문에 legacy listener는 여전히 설치되지 않는다.

## 후속
`executeAssetTreeDrop()`, `closeAssetTreeActionMenus()`, `installAssetTreeInteractions()`를 제거하고 legacy explorer renderer/markup 정리로 이동한다.
