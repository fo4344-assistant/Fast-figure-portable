# 20260916-009 — Remove CSV selection cache from logic-EFSM mutation paths

## Purpose
Continue the SoT repair established in `review-011-sot-api-boundary.md` and `20260916-008` by removing the shared `activeCsvId` projection from logic-EFSM/domain mutation and rollback paths.

`20260916-008` made the active Mantine CSV-selection/read path use the authoritative `SELECT_ASSET` / `appFSM.state.assetPath` state. This patch prevents core state transitions from continuing to maintain a second CSV-selection representation as a side effect.

## Ownership decision

- Asset selection is owned by the application logic EFSM (`assetSelection`, `assetPath`).
- Project CSV identity/content is owned by project/domain state.
- `activeCsvId` is not an independent SoT and must not be maintained by unrelated workspace, slot, delete, move, or rollback transitions.
- A legacy native graph editor may still temporarily use historical graph-data UI buffers until that UI ownership unit is removed; that does not authorize the logic EFSM to maintain those buffers.

## Exact changes
Remove `activeCsvId` reads/writes from logic-EFSM/domain mutation paths:

- `applySlotSelectionAction`;
- `applySlotTypeAction`;
- `applyDataObjectDeletedAction`;
- `applySlotsResetAction`;
- `applySlotsSwappedAction` rollback snapshot/reset/restore;
- `applySlotDataConnectedAction` rollback snapshot/restore;
- `applyProjectNodeMovedAction` trash handling;
- `applyAssetSelectionAction`.

`applyAssetSelectionAction` continues to own the authoritative `assetPath` transition. This patch does not alter its transition target or `SELECT_ASSET` event semantics.

The existing image projection (`activeImageId`) and `activeAssetKind` are not removed in this patch. They are a related SoT debt but are kept separate from the CSV/graph-data ownership unit to avoid mixing image-editor cleanup into the current graph-data repair.

## Why this direction
A cache/projection is not allowed to become a second state interface merely because it is in memory. Core transitions were clearing, restoring, or updating `activeCsvId` even though the selected project asset is already represented by the logic EFSM.

Those writes create synchronization obligations between two representations and make rollback code treat a cache as authoritative runtime state. Removing them from logic-EFSM mutation paths restores the direction:

```text
frontend/UI
  -> selection API/router/event
  -> logic EFSM assetPath/assetSelection SoT
```

instead of:

```text
logic EFSM transition
  -> authoritative selection state
  +-> shared activeCsvId mirror
```

## Rejected alternatives

- Replace `activeCsvId` with another shared cache name: rejected; that preserves the duplicate state contract.
- Add synchronization between `activeCsvId` and `assetPath`: rejected; bidirectional or coordinated cache synchronization is explicitly against project SoT policy.
- Remove all graph-data buffers in the same patch: rejected because `rows`, `columns`, `activeDataName`, `activeDataReady`, loader code, workspace activation, and native graph preview/form code form a separate ownership unit that needs a coherent cut rather than blind deletion.
- Remove `activeImageId`/`activeAssetKind` at the same time: rejected for this patch because image selection/editor ownership must be audited independently.

## SoT status after this patch
After this patch, the logic EFSM and the listed project/domain mutation paths no longer treat `activeCsvId` as state that must be updated or rolled back.

`activeCsvId` may still exist temporarily in legacy graph-data UI/runtime code. The next patch must remove its remaining non-UI consumers and either eliminate it completely or confine any genuinely necessary native-UI input buffer so no other subsystem references it.

## EFSM/core impact
No transition/event contract is changed.

Preserved:

- `SELECT_ASSET` and asset selection state;
- slot/workspace transitions;
- data deletion semantics;
- slot swap/reset/connect rollback semantics;
- project move/trash behavior;
- project/chart persistence and renderers.

Only redundant cache maintenance is removed.

## Rollback
Revert `Apply agent patch 20260916-009`.

No schema/data migration is involved.

## Follow-up priority
1. Remove remaining `activeCsvId` use from loader/workspace/legacy graph-data helpers.
2. Remove backend/core dependence on `activeDataReady`, `activeDataName`, `rows`, and `columns`; leave any surviving native-UI draft/buffer strictly inside that UI ownership unit.
3. Audit image-side selection mirrors (`activeImageId`, `activeAssetKind`) under the same rule.
4. Only then continue graph read/write API boundary cleanup and legacy graph UI deletion.
