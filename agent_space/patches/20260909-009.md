# 20260909-009 — Mantine graph palette ownership

## 목적

`review-010-mantine-ui-inventory.md`의 graph palette reset/save/load 기능을 legacy 버튼 및 hidden file input에서 Mantine 소유 UI로 이전한다. graph object 색상 자체는 계속 `chart.editor.objects[*].color`가 source of truth이며 별도 palette 상태를 만들지 않는다.

## 변경 내용

- `fast-figure-ui.js`에 `FastFigureGraphPaletteActions`를 추가한다.
- 현재 graph object 색상 배열을 그대로 JSON `{ colors: [...] }` 형식으로 저장한다.
- reset은 `DEFAULT_COLORS`를 object 순서에 반복 적용한다.
- load는 기존과 동일하게 JSON 배열 또는 `{ colors }`를 허용하고 유효한 `#RRGGBB` 값만 사용한다.
- 실제 object 변경은 `graphEditorCommit()`을 사용한다.
- palette load는 기존 lifecycle 의미를 보존해 `runLifecycleTask("importing", "PALETTE_IMPORT", ...)`에서 실행한다.
- React hidden file input을 component가 직접 소유하며 같은 파일을 다시 선택할 수 있도록 처리 후 값을 비운다.
- imported Plotly original mode(`editor.editable === false`)에서는 reset/load를 비활성화한다. 저장은 현재 색상 구성을 읽기만 하므로 허용한다.
- `FastFigureShell` graph workspace와 `window.FastFigureMantineUi` export에 component를 추가한다.

## 선택 이유

`20260909-007`에서 graph object 변경 경계가 `graphEditorCommit()`으로 정리되어 있다. graph palette는 별도 도메인 객체가 아니라 object color 배열의 일괄 편집/직렬화 기능이므로 이 기존 command를 재사용하는 것이 가장 단순하다.

## 기각한 대안

1. **legacy `#loadGraphPaletteFile`을 Mantine에서 click하는 방식**
   - 장기 legacy DOM bridge가 되므로 기각했다.

2. **graph palette를 별도 React state 또는 project palette object로 저장하는 방식**
   - 현재 영속 의미는 각 graph object의 `color`이며 별도 상태는 두 번째 authority가 된다.

3. **legacy `saveGraphObjects()`를 그대로 호출하는 방식**
   - legacy selection guard/UI projection과 결합되어 있다. 이미 value-based 경계인 `graphEditorCommit()`이 있으므로 이를 사용한다.

## 상태 권한과 경계

- persistent authority: `chart.editor.objects[*].color`
- mutation boundary: `graphEditorCommit()` → `GRAPH_OBJECTS_REPLACED`
- import lifecycle: `PALETTE_IMPORT`
- React local state: file input ref만 사용하며 persistent palette snapshot은 저장하지 않음

## 선행 조건

- `20260909-007`의 `graphEditorCommit()`이 적용되어 있어야 한다.
- `20260909-008` 적용 뒤 graph workspace에 Mantine graph layout editor가 존재하는 상태를 기준으로 한다.

## 검증

workflow:
- `git apply --check`
- `git diff --check`
- JS syntax check
- portable build
- split/portable `file://` smoke

수동 확인:
- default palette가 object 순서대로 반복 적용된다.
- 저장 JSON이 현재 object 색상 순서를 보존한다.
- JSON 배열과 `{ colors }` 모두 불러와진다.
- 유효한 HEX가 하나도 없으면 오류가 표시된다.
- 같은 palette 파일을 연속 두 번 선택할 수 있다.
- imported Plotly original mode에서는 reset/load가 disabled다.
- Mantine 경로에서 legacy palette button/input `.click()`을 사용하지 않는다.

## 후속 작업

- graph editor의 큰 ownership 단위는 data/object, global/axis, palette, file import/export까지 Mantine에 존재한다.
- 다음 단계에서는 `review-010`의 남은 layout/label/caption/print 및 asset generic UI ownership을 현재 source 기준으로 계속 이전한다.
- feature-equivalence 완료 전 legacy graph controls 제거는 하지 않는다.

## 롤백

`FastFigureGraphPaletteActions` 정의와 shell/export의 두 연결 행을 제거하면 된다. core, EFSM, project model, file format 변경은 없으므로 `007`과 `008`은 독립적으로 유지할 수 있다.
