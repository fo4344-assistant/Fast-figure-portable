# 20260928-001

## 목적과 변경 내용

Mantine caption overlay가 caption/domain source of truth와 core renderer 함수를 직접 참조하던 경로를 `FastFigureApi.captions` 경계로 이동한다.

추가 API:

- `readState()`: caption 표시 여부, slot caption mode, 현재 대상 slot의 최소 식별 정보, 현재 편집 text/name/nameBold/settings의 immutable snapshot
- `setEnabled(enabled)`
- `setSlotMode(enabled)`
- `insertSlotCaptions()`
- `setText(text)`
- `setName(name)`
- `setNameBold(bold)`
- `setSettings(patch)`

Mantine `FastFigureCaptionOverlay`는 위 API만 사용해 caption 값을 읽고 변경한다. overlay close는 기존 UI FSM event인 `CLOSE_OVERLAY`를 그대로 사용한다.

기존 기능 의미는 유지한다.

- slot mode 변경: `SLOT_CAPTION_MODE_CHANGED`
- caption text 변경: `CAPTION_TEXT_INPUT`
- slot caption 삽입: `SLOT_CAPTIONS_INSERTED`
- name 변경: 기존 `CAPTION_NAME_CHANGED` notify
- name bold 변경: 기존 `CAPTION_NAME_WEIGHT_CHANGED` notify
- font/settings 변경: 기존 `applyCaptionSettings()`와 `CAPTION_SETTINGS_CHANGED`
- 표시 여부 변경: 기존 `setAnnotationEnabled("caption", ...)`

## 선택 이유

caption 값은 `activeProject` / `ProjectObject` annotations 영역이 소유하는 domain SoT이고, slot-caption mode와 text 변경 의미는 이미 application EFSM event로 구현되어 있다.

따라서 frontend가 `activeProject.caption*`, `getSelectedSlot()`, `initializeSlotCaption()`, `syncDashboardCaption()`, `applyCaptionSettings()`, `setAnnotationEnabled()`를 직접 조합하지 않고, SoT 구현체가 제공하는 작은 read/mutation API를 호출하는 편이 현재 `review-011-sot-api-boundary.md`의 책임 경계와 일치한다.

새 store, presentation model, mirror state는 만들지 않았다. React local state도 caption 값을 복제하지 않는다. `readState()`는 primitive와 frozen shallow snapshot만 반환하며 mutable project object나 slot object를 frontend에 노출하지 않는다.

## 선택하지 않은 방향

### Mantine component에 `activeProject` 접근을 유지

동작 자체는 가능하지만 frontend가 backend/domain SoT를 직접 읽고 쓰는 현재 결합이 그대로 남는다. 이후 legacy 제거와 ownership 정리가 어려워지므로 선택하지 않았다.

### caption state를 React local state로 복제

caption 값은 즉시 project/domain에 반영되는 SoT다. 별도 React mirror를 두면 동기화 및 최신값 판정이 필요해지므로 만들지 않았다.

### 기존 EFSM event를 우회하는 새 caption state machine 추가

slot mode/text/insert 동작에는 이미 대응 application event가 있다. 같은 기능 의미를 다른 상태 머신에 중복 구현하지 않았다.

### renderer 호출을 frontend callback에 남김

`syncDashboardCaption`, `applyCaptionSettings`, annotation renderer 호출은 core/domain operation의 후속 효과이므로 API 내부에 남겼다. Mantine은 renderer 함수를 직접 호출하지 않는다.

## 검증

커밋 전 다음을 확인했다.

- 현재 `main` HEAD와 `20260922-010` 적용 상태를 재확인함.
- current source의 caption overlay와 caption/domain helper를 직접 대조함.
- patch는 exact current snippets에서 자동 unified diff로 생성함.
- 임시 Git 저장소에서 `git apply --check` 통과.
- 실제 apply 후 `git diff --check` 통과.
- 변경된 Mantine caption function에서 `activeProject.caption*`, `activeProject.captions*`, `activeProject.slotCaptions*`, `initializeSlotCaption`, `syncDashboardCaption`, `applyCaptionSettings`, `setAnnotationEnabled("caption", ...)` 직접 참조가 남지 않음을 확인함.

GitHub Actions 적용 단계에서 전체 `fast-figure.js` / `fast-figure-ui.js` syntax check, portable build, split/portable `file://` smoke test를 다시 수행한다.

## 전제와 후속 작업

- project schema, FFPX/FFSX 형식, caption 저장 형식은 변경하지 않는다.
- dashboard caption renderer 자체는 이번 패치의 제거 대상이 아니다.
- caption contenteditable dashboard editor와 export geometry는 core renderer 책임으로 그대로 둔다.
- overlay close/Escape/outside-click의 공통 UI-FSM lifecycle 정리는 별도 ownership 단계에서 수행한다.
- 다음 ownership 단위는 현재 Mantine print/export 또는 남아 있는 annotation/UI 직접 core 접근을 다시 감사한 뒤 선택한다. 순서만을 이유로 선행 삭제하지 않는다.

## 롤백

역적용하면 Mantine caption overlay가 다시 `activeProject` caption 값과 core helper/renderer를 직접 참조한다. domain schema나 저장 데이터 migration은 없으므로 패치 역적용만으로 원상복구된다.
