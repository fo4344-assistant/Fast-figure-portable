# 20260910-012 — README content authority와 Mantine cutover

## 목적
README를 legacy native dialog의 UI 상태와 분리하고 Mantine Modal이 직접 소유하도록 전환한다. README 본문을 복제하지 않고 하나의 정적 template을 canonical content source로 사용한다.

## 변경
- `Fast-figure.html`의 기존 README 본문을 `<template id="readmeContent">` 안으로 옮긴다.
- application version 문자열은 README에 별도로 하드코딩하지 않고 `{{APP_BUILD}}` placeholder를 사용한다.
- `readmeContentHtml()`이 template 본문을 읽고 `APP_BUILD`를 주입한다.
- legacy `readmeDialog.showModal()` 경로를 제거한다. `readme` overlay가 선택되어도 native dialog는 열지 않는다.
- audit은 native README dialog가 열려 있으면 legacy UI 누수로 기록한다.
- `FastFigureReadmeOverlay` Mantine Modal을 추가하고 canonical template content를 렌더링한다.
- 기존 legacy sidebar README 버튼과 Mantine utility button은 모두 동일한 `TOGGLE_OVERLAY` FSM 이벤트를 계속 사용한다.

## 선택 이유
README 본문을 React 상수와 legacy HTML에 각각 복제하면 콘텐츠 authority가 둘로 갈라진다. 반대로 legacy dialog의 렌더링된 innerHTML을 Mantine이 읽으면 legacy UI가 source가 된다. 비렌더링 `<template>`을 하나의 정적 content source로 두면 UI와 콘텐츠를 분리하면서 portable 단일 HTML 특성도 유지할 수 있다.

## 기각안
- legacy dialog `innerHTML`을 그대로 Mantine에 복사: legacy UI 의존이므로 기각.
- README 문자열을 `fast-figure-ui.js`에 다시 작성: HTML과 중복되므로 기각.
- native dialog와 Mantine Modal을 동시에 표시: ownership이 중복되고 top-layer 충돌이 발생하므로 기각.
- README source 정리와 Modal 구현을 별도 패치로 분리: WIP 구현 우선 정책에 따라 같은 ownership 변경에서 처리한다.

## Source of truth / EFSM 영향
README 본문 source of truth는 `#readmeContent` template 하나다. 앱 버전 source of truth는 계속 `APP_BUILD`다. overlay 상태 authority는 계속 `appFSM.state.overlay`다. project data, FFPX schema, functional EFSM은 변경하지 않는다.

## WIP 제한
legacy `readmeDialog`와 `closeReadme` 요소는 required-control 호환을 위해 아직 stub으로 남는다. native dialog는 더 이상 정상 UI 경로에서 열리지 않는다. 최종 legacy markup 제거 시 required-control/audit 목록과 함께 정리한다.

## 검증
workflow의 git apply, JavaScript syntax, portable build, split/portable file smoke를 모두 통과해야 한다. README 링크와 긴 license scroll 동작은 후속 WIP 통합 검증 대상이다.

## Rollback
역적용하면 README 본문이 다시 native dialog 내부의 직접 렌더링 콘텐츠로 돌아가고 Mantine README Modal이 제거된다. project data migration은 없다.
