# 20261001-018 — Source Script r9 image display state를 slot-local로 이동

## 변경 원인

Source Script closure review에서 사용자 명시 원칙:

- 각 slot별로 적용되는 하위 내용은 slot object의 하위 속성을 기본값으로 한다.
- slot object가 GUI layout 위치 사이에서 이동하면 그 하위 속성도 함께 이동한다.

를 caption 외의 slot-specific state에 다시 적용했다.

그 결과 fit/scale/x/y image display settings가 image asset 아래에 남아 있는 것이 발견되었다.
같은 image asset은 여러 slot이 참조할 수 있으므로 이 구조는 slot별 표시 상태를 독립적으로 표현하지 못한다.

## 의미 변경

- image asset은 id/name/directory/MIME/copied bytes만 소유
- fit/scale/x/y는 slot.content.imageSettings의 authoritative slot-local state
- 새 empty slot은 default imageSettings를 가진다.
- 같은 image asset을 여러 slot이 참조해도 imageSettings는 각 slot에 독립
- image editor는 referenced asset + selected slot.imageSettings를 함께 읽음
- image settings mutation은 selected slot object만 변경
- swap/merge/reset에서 imageSettings도 다른 slot-local properties와 함께 이동/초기화
- FFPX slot document가 slot-local imageSettings를 보존
- image asset replacement는 slot display settings를 변경하지 않음

## 선택 이유

image bytes는 여러 slot이 공유할 수 있는 asset이지만 fit/scale/x/y는 특정 GUI slot 안에서 이미지를 어떻게 보여주는지에 대한 값이다.
따라서 asset ownership보다 slot ownership이 실제 의미에 맞는다.

이 구조를 사용하면 동일 image를 여러 panel에 배치하면서 각 panel의 crop/scale/position을 독립적으로 유지할 수 있다.

## 기존 안을 채택하지 않은 기록

### imageAsset.settings 유지

채택하지 않는다.

같은 imageId를 여러 slot이 참조할 경우 하나의 settings 값이 모든 slot에 공유되어
사용자가 확정한 slot-local ownership 원칙에 위배된다.

### image asset을 slot마다 복제해서 settings 독립성 확보

채택하지 않는다.

동일 bytes를 여러 asset object로 복제하면 asset identity와 storage가 중복된다.
공유 가능한 bytes asset과 slot-local display state를 분리하는 편이 더 단순하다.

## 닫힘 판정 영향

slot-local ownership 규칙이 caption뿐 아니라 image display state에도 일관되게 적용되었다.

r9는 다시 closure review를 수행하기 전까지 current/open이다.

## 하위 단계 전파 범위

pseudocode/source code에서:

- imageAsset.settings 제거
- slot.content.imageSettings 추가 및 default/validation 구현
- image editor read/write를 selected slot-local settings로 변경
- image asset replacement와 slot display settings 분리
- FFPX slot image settings read/write 이동
- swap/merge/reset에서 imageSettings 포함

이 필요하다.
