## 선택 이유와 기각 대안

PlusCal의 `completion.threw`와 `PropagateOriginalFailure(completion.failure)`를 JS의 catch/finally와 boolean으로 직접 표현했다. 오류 값을 truthy 검사하면 `throw null`/`throw undefined`를 놓치므로 사용하지 않는다. 모든 cleanup 오류를 무조건 무시하면 기존 cleanup-only 동작까지 임의로 바꾸므로 제외했다. AggregateError나 새 오류 객체는 원래 실패 identity를 바꾸므로 사용하지 않았다. 새로운 공용 cleanup manager/서비스/상태 객체는 이 작업에서 필요하지 않아 추가하지 않았다.

작업 자체가 이미 실패한 때만 status/debug의 secondary exception을 억제한다. status를 새 성공/실패 authority로 만들거나 완료된 다운로드를 retry/rollback하지 않는다. 상위 명세에서 추가 결정이 필요한 progress-only/post-handoff status 및 cleanup-only 전체 의미는 후속 범위로 남긴다.
