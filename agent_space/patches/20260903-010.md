# 20260903-010 — lifecycle / overlay DOM-free 정책 helper 준비

## 목적

Mantine shell ownership cutover 전에 lifecycle/overlay EFSM entry에 섞인 실제 기능 의미와 legacy DOM renderer를 분리할 수 있는 DOM-free 정책 helper를 준비한다.

현재 legacy entry에는 다음이 혼재한다.

### lifecycle
- importing/exporting 상태에 따른 body busy class / aria-busy
- native import/export/save/capture controls disabled
- error lifecycle의 debug 기록

### overlay
- legacy panel hidden/toggle active/ARIA/main class
- native README dialog showModal/close/focus
- 일반 popup 진입 시 `clearAllSlotSelections()`
- layout/label/caption/print의 legacy form/preview synchronization

이 중 Mantine 전환 후에도 UI 구현과 독립적으로 유지해야 할 의미는 error diagnostic과 일반 popup 진입 시 slot selection 해제 정책이다.

## 변경 내용

- 앱 버전 `1.1.108-alpha` → `1.1.109-alpha`
- `applyLifecycleDomainState({ state, payload } = {})` 추가
  - state가 `error`이고 payload.error가 있으면 기존 `fsm:lifecycle-error` debug 기록
  - DOM 접근 없음
- `applyOverlayOpenPolicy(state)` 추가
  - `none`, `readme`가 아닌 일반 overlay가 열릴 때 기존과 동일하게 `clearAllSlotSelections()` 수행
  - DOM 접근 없음
  - state 반환

이번 patch는 함수 정의만 추가하고 기존 `enterLifecycleState`, `setOverlayDomState`, `enterOverlayState`, `exitOverlayState` 호출 구조는 변경하지 않는다.

## 이 방향을 선택한 이유

현재 active UI는 legacy이고 current 대형 HTML의 legacy entry 문맥을 connector로 안정적으로 읽기 어렵다. 먼저 cutover 때 반드시 보존할 의미를 독립 helper로 확보하면, ownership 전환 patch에서 native DOM renderer를 제거하면서 정책까지 실수로 삭제하는 위험을 줄일 수 있다.

또 lifecycle busy 여부 자체는 `appFSM.state.lifecycle`이라는 canonical state에서 Mantine가 직접 표현할 수 있으므로 별도 domain state/helper에 복제하지 않는다.

## 고려했지만 선택하지 않은 방향

### busy 상태를 새 boolean state로 저장

기각. `lifecycle === importing/exporting`에서 직접 파생 가능한 사실을 중복 저장하게 된다.

### README overlay에서도 slot selection 해제

기각. 기존 의미는 일반 popup에만 적용되고 README는 제외된다.

### layout preview render를 이 helper에 포함

기각. `layoutMap` host는 Mantine Modal이 렌더된 뒤 존재하므로 React component/effect가 domain renderer를 호출해야 한다. EFSM entry에서 DOM host lifecycle을 다시 소유하게 만들지 않는다.

### 기존 entry 함수를 이번 patch에서 바로 수정

기각. active legacy UI 회귀 범위를 불필요하게 넓힌다.

## source of truth / EFSM

- lifecycle/overlay source: `appFSM.state`
- busy 여부는 lifecycle에서 파생
- slot selection은 기존 slot selection state/EFSM 의미 유지
- helper는 별도 persistent state를 만들지 않음

## 회귀 위험

매우 낮음. 함수 정의만 추가되고 현재 call graph는 변경되지 않는다.

## 검증

- `git apply --check`
- `git diff --check`
- application JavaScript `node --check`
- 두 helper 내부 `$()`/`document` 접근 없음
- EFSM definitions/file schema/renderer 변경 없음

## rollback

두 helper와 버전 문자열만 제거한다.

## 후속

- Mantine lifecycle busy 표현 경계를 확인/보완
- Overlay Modal에서 layout renderer host가 mount된 뒤 `renderLayout()`을 실행하도록 effect 경계 확인
- active shell cutover patch에서 EFSM callbacks을 DOM-free policy/helper로 전환하고 legacy popup renderer를 비활성화한다.
