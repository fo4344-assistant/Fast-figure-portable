# 20260908-001 — Mantine image editor direct port

## 목적

`review-010-mantine-ui-inventory.md`의 Image editor 항목을 실제 Mantine shell에 직접 포팅한다.

현재 이미지 설정 기능은 `applyImageSettings()`가 `#imageFitMode`, `#imageScale`, `#imagePositionX`, `#imagePositionY` 값을 직접 읽도록 구현되어 있다. 이 함수 자체는 이미지 model과 dashboard renderer를 갱신하는 실제 기능도 함께 수행하므로, Mantine image editor가 legacy form DOM을 내부 API처럼 사용하지 않으려면 값 기반 기능 command를 최소한으로 분리해야 한다.

이번 패치는 과거 staging/bridge 구조를 복원하지 않는다. 현재 source에서 실제 Mantine consumer가 필요해진 시점에만 renderer-neutral command를 추출하고, Mantine component가 그 command를 직접 호출한다.

## 변경 분류

- Mantine UI 직접 포팅
- legacy form DOM 결합에서 실제 image-settings command 최소 추출
- 기존 image model / renderer 재사용
- UI FSM / 기능 EFSM / project schema 변경 없음

## 정확한 변경

### `fast-figure.js`

1. 기존 `applyImageSettings()`의 model/renderer 변경 부분을 `applyImageSettingsFromValues(values)`로 분리한다.
2. 새 command는 기존과 동일하게:
   - 현재 선택 슬롯과 연결 이미지를 사용한다.
   - `normalizeImageSettings()`를 사용한다.
   - fit은 `contain`, `cover`, `manual`만 허용한다.
   - manual scale은 1–1000%로 clamp한다.
   - X/Y는 -100–200%로 clamp한다.
   - 기존 `syncSlotImageElement()` renderer 갱신을 수행한다.
   - 기존 `slot:image-settings` debug log를 남긴다.
   - 기존 `appFSM.notify("images", "IMAGE_SETTINGS_CHANGED")`를 유지한다.
3. 새 command는 legacy image form을 읽거나 쓰지 않는다.
4. 기존 `applyImageSettings()`는 legacy adapter로 남아 기존 form 값을 새 command에 전달하고, 성공 후에만 `syncImageSettingsUi()`를 호출한다.
5. 기존 legacy event binding은 그대로 유지한다.

### `fast-figure-ui.js`

1. Mantine core에서 `Image`, `NumberInput`, `Select`를 사용한다.
2. `FastFigureImageEditor()`를 추가한다.
3. 이 component는 `appFSM.state.workspace === "slot.image"`일 때만 표시한다.
4. 현재 선택 slot/image와 `normalizeImageSettings(image)`를 직접 읽는다.
5. persistent React mirror state를 만들지 않는다.
6. fit/scale/X/Y 변경은 `applyImageSettingsFromValues()`를 직접 호출한다.
7. manual fit일 때만 scale/X/Y `NumberInput`을 표시한다.
8. 현재 선택 이미지를 Mantine `Image` preview로 표시한다.
9. lifecycle이 `ready`가 아니면 설정 control을 비활성화한다.
10. `FastFigureShell` navbar와 `FastFigureMantineUi` export에 image editor를 연결한다.

## Source of truth

변경 없음.

- 이미지 설정의 persistent authority: `activeProject.images[*].settings`
- 선택 슬롯/워크스페이스 authority: 기존 `appFSM` + project slot state
- dashboard image 표시: 기존 slot/image renderer
- React local state: 추가하지 않음

Mantine `Select`/`NumberInput`은 매 render에서 authoritative image settings를 읽고, 변경 시 같은 model에 직접 반영한다. 별도 React settings copy나 양방향 synchronization을 만들지 않는다.

## UI FSM / EFSM / core 영향

- workspace state 정의 변경 없음
- image 관련 EFSM event/transition 추가 없음
- `IMAGE_SETTINGS_CHANGED` notification 의미 유지
- `ProjectObject` / project class 변경 없음
- FFPX/FFSX schema 및 image serialization 변경 없음
- image fit/scale/x/y 범위 변경 없음
- `syncSlotImageElement()` renderer 의미 변경 없음

이번 변경은 기존 `applyImageSettings()` 안에서 이미 수행되던 model mutation과 renderer 갱신을 값 기반 함수로 옮기는 것뿐이다.

## 재사용한 기존 함수

- `getSelectedSlot()`
- `slotImage()`
- `normalizeImageSettings()`
- `syncSlotImageElement()`
- `projectImageDisplayUrl()`
- `debugLog()`
- `appFSM.notify()`

## 선택한 방향

`review-009`는 과거 `20260906-011`을 즉시 replay하지 않고, 실제 Mantine image form 구현 시 기존 command가 DOM에 묶여 있으면 그때 최소 command 추출 여부를 판단하도록 보류했다.

현재 실제 Mantine image editor를 추가하면서 그 조건이 충족되었다. 따라서 과거 migration bridge 전체가 아니라, 현재 source에서 필요한 값 기반 command 경계만 다시 구현한다.

## 기각한 대안

### Mantine control에서 legacy `#imageFitMode` 등의 값을 쓰고 `applyImageSettings()` 호출

기각. Mantine이 제거 대상 legacy DOM을 내부 API로 사용하게 된다.

### Mantine component에서 `image.settings`를 직접 변경하고 renderer 코드도 복제

기각. clamp, debug, renderer update, FSM notification 의미가 두 군데로 중복된다.

### image settings를 React `useState`로 별도 보관

기각. persistent project image settings와 React state 사이의 두 source of truth 및 synchronization이 생긴다.

### 새 image-settings EFSM/state machine 추가

기각. 현재 구조는 image settings를 project image model이 소유하고 기존 notification/renderer 경계가 이미 동작한다. 이번 UI 포팅에 새 기능 상태 계층이 필요하지 않다.

### 과거 `20260906-011` 및 bridge patch 재적용

기각. 당시 patch는 migration bridge consumer를 전제로 작성되었다. 현재는 실제 Mantine component를 직접 구현하므로 필요한 최소 command와 consumer를 하나의 현재 patch로 작성한다.

## 위험 및 확인 사항

- Mantine `NumberInput`은 입력 중에도 값을 전달하므로 legacy change/blur보다 model 반영 시점이 빠를 수 있다. 이는 `review-010`의 "값 변경 즉시 project image settings와 slot image renderer에 반영" 요구와 일치한다.
- 빈 image slot에서는 설정 command를 실행하지 않고 안내만 표시해야 한다.
- `appFSM.notify("images", "IMAGE_SETTINGS_CHANGED")` 후 React snapshot revision이 갱신되어 control 값이 authoritative model에서 다시 읽혀야 한다.
- manual 이외 fit으로 전환해도 기존 scale/x/y 값은 지우지 않는다. 기존 동작과 동일하다.
