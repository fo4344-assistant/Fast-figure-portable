# 20260915-007 — Record ChatGPT session interruption and verified resume point

## Purpose
Record the current ChatGPT web-session reliability problem and the verified GitHub repository resume point so a later session does not repeat already completed work or mistake invisible server-side progress for failure.

## Exact changes
- Add `agent_space/logs/20260915-session-interruption.md`.
- Record the repeated ChatGPT session disconnect behavior observed during long GitHub/tool sequences.
- Record that GitHub work can continue after the ChatGPT connection is lost and therefore repository/workflow state must be re-read after reconnect.
- Record the actual outcomes of `20260915-001` through `20260915-006`, including the pre-application failure of `005` and successful application of `006`.
- Record `20260915-006` / commit `5e0760a6adad3ec8f054adf78219c610495bf545` as the current resume baseline and the next intended annotation cleanup sequence.

## Rationale
The ChatGPT session became unreliable while repository-side work continued. Without an explicit handoff log, a later session could restart from an obsolete visible point, requeue an already applied patch, or misclassify a completed GitHub Action as interrupted work.

## Rejected alternatives
- Put this in `history`: rejected because this is primarily an execution/session incident and recovery record, while `history` is for ordinary chronological project change history.
- Put this in `memo`: rejected because the verified GitHub state and resume procedure are not merely an unconfirmed idea or hypothesis.
- Modify `logs.md` directly: rejected because a dedicated dated incident record is easier to preserve and reference without mixing it with the directory description.
- Queue this patch through the Fast Figure source workflow: rejected because `.github/workflows/apply-fast-figure-patch.yml` only accepts a fixed set of source targets and does not allow `agent_space/logs/*`. The log file is therefore added directly while this diff/description pair records that modification per `AGENT.md`.

## Source of truth
GitHub `main`, patch documents, applied-patch commits, and GitHub Actions results are authoritative for repository progress. The ChatGPT UI's last visible tool step is not authoritative after a disconnect.
