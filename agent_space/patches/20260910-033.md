# 20260910-033 — Remove legacy image-selection action panel

## Purpose

Remove the legacy sidebar image-selection panel and its blank-image button. Mantine `FastFigureImageEditor` already owns the blank-image action and calls the existing UI-independent command directly. Legacy UI compatibility is not retained; file-format compatibility is untouched.

## Exact changes

### `Fast-figure.html`
- Remove `#imageSelectionPanel` and its `#insertEmptyImage` button.

### `fast-figure.js`
- Remove `imageSelectionPanel` and `insertEmptyImage` from `REQUIRED_CONTROL_IDS`.
- Stop toggling the legacy image-selection panel in `syncSlotContentTypeUi()`.
- Remove the legacy disabled-state write from `refreshImageControls()`.
- Remove the legacy `#insertEmptyImage.onclick` binding.
- Keep `insertEmptyImageIntoSelectedSlot()` unchanged because Mantine calls it directly.

## Rationale

The blank-image operation is functional behavior, while the removed button/panel is only one obsolete presentation path. Mantine already owns that presentation and invokes the same command without a DOM bridge. Keeping a hidden duplicate button would add no model or file compatibility.

## Source of truth

- Selected slot and content type: `appFSM` / project model.
- Blank-image mutation: `insertEmptyImageIntoSelectedSlot()` and existing image/project FSM operations.
- Generic blank-image UI: Mantine only.

## EFSM / core impact

None. No project state transition, image model semantics, renderer algorithm, or command behavior is modified.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, image bytes, serializer, parser, version, or import/export code is changed.

## Rejected alternatives

- Keep the legacy button hidden: rejected because old UI compatibility is not required.
- Make Mantine click the legacy button: rejected because it would recreate the forbidden DOM bridge.
- Move blank-image creation into React-local code: rejected because the existing command is already the correct shared functional boundary.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert the application commit for this patch to restore the old panel/button and binding. No data migration is involved.

## Follow-up

Remove the remaining legacy `imageBox` editor form and its form synchronization/handlers while retaining `applyImageSettingsFromValues()` and image model normalization for Mantine and rendering.
