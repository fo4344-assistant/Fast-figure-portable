# 20260902-071 — Mantine graph file actions sidebar wiring

## 목적

`070`의 `FastFigureGraphFileActionsStaging`을 inactive Mantine sidebar에 연결한다.

## 변경 내용

- 앱 버전 `1.1.102-alpha` → `1.1.103-alpha`
- `FastFigureSidebarStaging()`에서 `fastFigureUiBridge.readGraphFileActions()` 호출
- graph 전역 설정보다 앞에 graph file actions component를 렌더
- read model이 `null`이면 component를 렌더하지 않음

## 위치 이유

legacy graph sidebar에서도 FFSX/Plotly import/export와 editable 전환은 object/global 상세 설정보다 상위 수준 기능이다.

따라서 Mantine에서도 순서를 다음처럼 둔다.

1. graph slot 파일/편집 모드
2. graph global layout
3. 4-axis settings
4. graph object/palette/detail

픽셀 배치를 복제하는 것이 아니라 기능 계층을 보존한다.

## source of truth

sidebar는 `graphFileActions` snapshot을 presentation 입력으로만 사용한다. action 실행 시 `070` component가 current read model을 다시 검증하므로 snapshot이 권위 상태가 되지 않는다.

## EFSM / 파일 영향

없음. UI wiring만 추가한다.

- FFSX schema 변경 없음
- Plotly JSON 생성/파싱 변경 없음
- imported Plotly conversion 변경 없음
- graph/editor EFSM 변경 없음

## 회귀 위험

낮음. inactive staging sidebar wiring이며 active legacy UI는 유지된다.

## 검증

- `git apply --check`
- `git diff --check`
- application JavaScript `node --check`
- sidebar에서 read가 한 번만 수행되는지
- chart/global/object UI보다 상위에 file actions가 배치되는지

## rollback

sidebar의 `graphFileActions` read 한 줄과 component render block, 버전 문자열 두 곳만 제거한다. `067/069/070`은 독립 유지 가능하다.
