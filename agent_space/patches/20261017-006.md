## 이유·진행 내용

임시 작업본의 FFPX 문서별 writer/reader, FFSX typed XML producer/consumer, slot-local 정규화와 root file-path 거부 조건을 Source r37에 맞춰 전개했다. FFPX의 slot-local imageSettings는 image asset 부재와 별개의 값이므로 null imageRef로도 보존한다. FFSX의 Project identity 부재와 Project chart 등록 검증을 구별하고 가짜 id로 validator를 통과시키지 않는다. 상세 생성/소비자와 대조 이유는 계획 §13에 있다.

텍스트 목록 점검에서 15 작업본 6,164행, 242 procedure 선언의 explicit call에 미대응 이름/동명 중복은 없었다. 이는 문자열 대조이며 parser/TLC/runtime·전체 충실도 증거가 아니다. 대규모 본문을 tool cache에 보관하려던 시도는 cache 제한으로 실패했다. 파일은 변경/손실되지 않았으며 실행 검증과 무관하다.

## 대안과 제외

- 부분 번역을 활성 pseudocode에 섞고 current로 선언하는 대안은 거부했다. 전체 번역/충실도/lineage가 아직 닫히지 않았다.
- package 조립 전체를 이름만 있는 primitive로 남기는 대안 대신 실제 metadata/bytes/typed 문서/slot reference와 원래 Source owner 경로를 전개했다. XML tree/byte encoding 등 platform primitive와 미완료 domain 계산은 구별한다.
- Source/PlusCal 계층의 의미를 고치거나 새 schema/공개 API/runtime state/authority를 만드는 대안은 채택하지 않았다. 하위 코드는 Source가 유지하도록 명시한 기존 version wire 표기의 확인 자료일 뿐 상위 의미 원천이 아니다.

`.work/plan022/pseudocode/` 및 연결 메모는 현재 작업 경로 안의 임시 작업본이다. 저장소 밖에 있으며 이 patch/remote/rollback에 **포함되지 않는다**. 별도 영구 명세나 구현 입력 authority로 승격하지 않는다. 이번 pair로 해당 임시 파일을 복원할 수 있다고 주장하지 않는다.

Source r37 closed/current, 활성 pseudocode r11 stale와 하위 stale 및 fingerprint는 모두 유지한다. 남은 domain/primitive 경계와 전체 인자·반환·실패·retry/resource 대조, 활성 hierarchy cutover/과거 파일·임시본 정리 및 lineage·Actions 검증은 후속 작업이다. 전체 번역 완료가 아니다.

## 기록·검증 한계

매 쓰기 전 remote HEAD와 기존 blob SHA(새 path는 404)를 재확인하는 순차 Contents API를 사용한다. 원자적 multi-file commit이나 같은 commit 안에 완성된 patch pair가 있다고 주장하지 않는다.

실제 endpoint diff whitespace 확인과 endpoint tree를 사용한 별도 임시 Git index에서 patch reverse cached apply 확인이 통과했다. 이는 파일 기록 점검이며 Source/PlusCal 실행이 아니다. 임시 index는 삭제했다. Source/application/PlusCal/parser/checker/test/build/TLC의 로컬 실행, delegation, 새 Actions dispatch는 하지 않았다.
