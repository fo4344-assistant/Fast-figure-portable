# 20261014-034 — Normalize projectEFSM actions to candidate-first commits r29

## 목적

projectEFSM으로 ownership을 옮긴 뒤에도 일부 legacy action은 live ProjectObject를 먼저 변경하고 실패 시 rollback하거나,
검증 없이 collection/property를 직접 바꾸고 있었다. 같은 command semantics를 유지하면서 mutation pattern을 candidate-first로 통일한다.

## 변경

- caption text와 slot-caption insertion을 candidate에서 계산하고 validate 후 commit한다.
- CSV/image create를 candidate에 stage한 뒤 next-id와 VFS invariant까지 검증하고 commit한다.
- CSV/image replacement에서 live collection 교체/rollback을 제거하고 candidate replacement를 사용한다.
- candidate가 없는 CSV/image delete fallback도 reference detach + asset removal candidate를 만든 뒤 commit한다.
- SLOT_DATA_CONNECTED에서 chart/image slot 전환과 graph-object 추가를 candidate에서 수행한다.
- CHART_LAYOUT_CHANGED를 candidate chart settings commit으로 바꾼다.
- CHART_MODEL_REPLACED의 단일 chart fallback도 candidate replacement를 사용한다.
- PROJECT_DIRECTORY_CREATED를 candidate VFS mutation으로 바꾼다.
- PROJECT_TRASH_EMPTIED를 candidate reference detach + asset/directory removal 후 한 번 commit하도록 바꾼다.
- candidate에서 reference를 제거할 때 Plotly projection을 live project data로 재계산하지 않게 한다.
- 더 이상 호출되지 않는 live-mutating `detachSlotChart` helper를 제거한다.

## 일반 코딩 원칙

모든 변경은 가능한 범위에서 계산/candidate 작성과 authoritative mutation을 분리한다.
실패 가능한 validation 이전에 live ProjectObject를 변경하지 않는다.
rollback용 임시 상태를 유지하지 않고 validated candidate 하나를 commit한다.
새 mutation layer나 generic patch command는 추가하지 않는다.

## 상태

Source Code는 아직 `stale`로 유지한다.
회귀와 전체 public mutation route 대조 후 current/closure 여부를 별도 review에서 결정한다.
