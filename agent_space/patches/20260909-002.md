# Mantine-owned UI palette editor

## 목적

`review-010-mantine-ui-inventory.md`에 기록된 10개 UI palette 값을 Mantine generic UI에서 직접 편집할 수 있게 한다. 영속 source of truth는 기존 `activeProject.appearance.uiPalette` 하나만 유지하고, CSS/theme projection과 dashboard rerender는 기존 `applyUiPalette(false)` 경로를 그대로 재사용한다.

## 변경 내용

### `fast-figure.js`

- `applyUiPaletteValues(values, notify = true)`를 추가한다.
- 전달받은 값 객체를 `DEFAULT_UI_PALETTE`의 key 집합 기준으로 정규화한다.
- 각 색은 기존 `projectColor()` 검증을 통과시킨다.
- 정규화 결과를 `activeProject.appearance.uiPalette`에 한 번 기록한 뒤 기존 `applyUiPalette(false, notify)`를 호출한다.
- 기존 legacy `applyUiPalette()`와 reset handler는 그대로 남긴다.

### `fast-figure-ui.js`

- Mantine `ColorInput`을 사용한다.
- `FastFigurePaletteActions`를 추가한다.
- sidebar에는 `UI 색상` 버튼만 두고, 10개 입력은 표준 Mantine `Modal`에서 편집한다.
- 편집 중 값은 React local `draft`에만 존재한다.
- `적용`은 `applyUiPaletteValues(draft)`를 호출한다.
- `기본값`은 `DEFAULT_UI_PALETTE`를 즉시 적용하고 draft도 같은 값으로 맞춘다. 기존 reset이 즉시 palette를 적용하던 의미를 보존한다.
- `취소`/Modal close는 적용하지 않은 draft를 버린다.

편집 대상 10개 값:

- `uiColor`
- `uiBackgroundColor`
- `uiSurfaceColor`
- `uiMutedColor`
- `uiSubtleColor`
- `uiDisabledBgColor`
- `uiDisabledTextColor`
- `uiShadowColor`
- `paperColor`
- `fontColor`

## source of truth / 상태 경계

영속 authority는 계속 `activeProject.appearance.uiPalette`다.

React local `draft`는 Modal이 열려 있는 동안의 미적용 입력값일 뿐이며 다른 기능은 이를 참조하지 않는다. 적용 후에는 project palette만 남는다.

`applyUiPalette(false)`가 legacy color controls에도 값을 projection하지만 이는 영속 authority가 아니다. Mantine callback은 legacy input의 `.value`를 읽거나 `.click()`을 호출하지 않고, 값 기반 command `applyUiPaletteValues()`만 호출한다.

## 선택 이유

현재 palette 적용 로직은 이미 다음 책임으로 분리돼 있다.

1. project palette 값
2. CSS variable projection
3. dashboard rerender
4. `appFSM.notify("ui", "UI_PALETTE_CHANGED")`

따라서 UI-independent 값 command 하나를 추가하면 Mantine에서 별도 store나 migration bridge 없이 기존 기능을 그대로 재사용할 수 있다.

10개 `ColorInput`을 sidebar에 항상 노출하면 현재 navbar가 지나치게 길어지므로, generic color editing 자체는 Mantine Modal에 두고 sidebar는 한 개의 진입 버튼만 둔다. popup 크기/close/Escape/outside-click/focus 처리도 Mantine 기본 lifecycle에 통합된다.

## 고려했지만 선택하지 않은 방향

### 1. Mantine에서 legacy color input 값을 설정한 뒤 `#applyUiPalette.click()` 호출

기각했다. Mantine → legacy DOM bridge가 생기고 source ownership이 불명확해진다.

### 2. palette 값을 React state에 영속적으로 복제

기각했다. project palette와 React store 중 어느 쪽이 최신인지 동기화해야 하는 이중 source가 생긴다.

### 3. CSS variable projection을 React/Mantine 쪽에 다시 구현

기각했다. 기존 `applyUiPalette(false)`가 이미 dashboard와 legacy renderer 모두에 필요한 projection을 담당한다. 같은 projection을 두 군데 구현할 이유가 없다.

### 4. reset을 draft만 기본값으로 바꾸고 별도 적용을 요구

기각했다. 기존 reset은 기본값을 즉시 적용한다. 사용자 기능 의미를 유지하기 위해 Mantine `기본값`도 즉시 project palette에 적용한다.

## EFSM / domain 영향

- `APP_STATE_DEFINITIONS`: 변경 없음.
- project schema: 변경 없음.
- FFPX/FFSX/Plotly: 변경 없음.
- slot/chart/image/layout/label/caption/export 알고리즘: 변경 없음.
- `UI_PALETTE_CHANGED` notify 의미 유지.

## 재사용한 기존 기능

- `DEFAULT_UI_PALETTE`
- `projectColor()`
- `applyUiPalette(false, notify)`
- `renderDashboard()`
- `appFSM.notify("ui", "UI_PALETTE_CHANGED")`

## 검증

자동 workflow:

1. `git apply --check`
2. `git diff --check`
3. `node --check fast-figure.js`
4. `node --check fast-figure-ui.js`
5. portable HTML build
6. split/portable `file://` smoke

수동 회귀 확인:

1. `UI 색상` 버튼이 standard Mantine Modal을 여는지.
2. 10개 색상이 현재 project palette 값으로 시작하는지.
3. 입력 변경 후 `취소` 시 project palette가 바뀌지 않는지.
4. `적용` 시 project palette, CSS, dashboard가 함께 갱신되는지.
5. `기본값`이 즉시 `DEFAULT_UI_PALETTE`를 적용하는지.
6. 적용 뒤 FFPX export/import에서 palette가 보존되는지.
7. Modal Escape/outside-click/close가 다른 custom popup 규칙 없이 Mantine lifecycle로 동작하는지.

## 위험과 후속 작업

- legacy palette controls는 전체 cutover 전이므로 아직 source에 남는다. 최종 기능-equivalence 확인 뒤 legacy markup/handlers를 제거한다.
- `applyUiPalette(false)`의 legacy control value projection도 최종 cutover 때 제거 대상으로 다시 검토한다. 현재는 retained legacy UI와 CSS projection을 한 함수가 함께 담당하므로 이번 패치에서 섣불리 분리하지 않는다.
- README는 현재 내용 source가 legacy `<dialog>` 내부 HTML이므로, 단순 Modal clone은 하지 않았다. README content source를 한 곳으로 승격하는 별도 작업과 함께 포팅해야 한다.
- CSV header line 수 역시 legacy graph/data preview renderer와 함께 처리하는 것이 맞아 이번 패치 범위에서 제외했다.
