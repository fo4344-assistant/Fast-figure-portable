# 20260910-015 — Mantine external file drop ownership

## 목적
외부 OS 파일을 Mantine PROJECT DATA 트리의 프로젝트 폴더와 `/slots`에 직접 drag/drop할 수 있게 하고, 파일 이름 충돌 선택을 기존 DataActions와 tree가 같은 Mantine controller/Modal로 공유하도록 한다. 다중 파일 폴더 import는 기존 legacy drop과 동일하게 실패 시 전체 추가/교체를 롤백한다.

## 변경 위치
- `fast-figure.js`
  - `importProjectFilesToDirectory(files, directory, planImport)` UI-independent command를 추가한다.
  - CSV/TSV/JSON 및 image만 폴더 import 대상으로 허용한다.
  - 모든 import 계획을 먼저 확정하고 reserved path를 공유해 같은 batch 내부 이름 충돌도 방지한다.
  - 기존 CSV/image ID와 교체 전 모델을 snapshot한 뒤 import 중 실패하면 새 자산 삭제 및 교체 자산 복원으로 batch를 롤백한다.
- `fast-figure-ui.js`
  - `useProjectAssetImportCollision()`을 추가하여 replace/rename 선택과 Mantine Modal을 하나의 공용 UI controller로 만든다.
  - `FastFigureDataActions`의 기존 로컬 collision state/Modal을 이 controller로 교체한다.
  - `FastFigureProjectDataTree`도 같은 controller를 사용한다.
  - 외부 files drag를 내부 project-node drag와 구분한다.
  - 폴더 drop: 여러 CSV/TSV/JSON/image를 대상 폴더로 import하며 FFSX는 거부한다.
  - slot drop: 파일 하나만 허용하고 FFSX는 `importSlotFile`, image/data는 기존 `loadImageFile`/`loadDataFile`에 collision plan을 전달한다.
  - 내부 project asset -> folder/slot drag/drop의 기존 의미는 유지한다.
  - nested directory drop의 bubbling을 차단해 부모 폴더까지 중복 처리되지 않게 한다.

## 설계 이유
외부 폴더 drop의 중요한 기능은 단순 반복 import가 아니라 batch 충돌 계획과 실패 롤백이다. 이를 React component에 복제하면 project mutation 알고리즘이 UI 안에 생기므로 core command로 추출한다. 충돌 여부와 replace/rename 결정만 Mantine UI가 담당하며 실제 asset 생성/교체는 기존 load 함수와 FSM event가 담당한다.

## 기각안
- legacy `#assetTree`에 synthetic drop event 전달: legacy DOM bridge이므로 기각.
- 파일별 즉시 import 후 실패한 지점까지만 남기는 방식: 기존 batch rollback 의미를 잃으므로 기각.
- DataActions와 tree에 별도 collision Modal 복제: generic UI ownership이 중복되므로 기각.
- React가 직접 CSV/image collection을 수정: project model/EFSM 경계를 우회하므로 기각.

## Source of truth / EFSM 영향
- persistent asset/path authority는 기존 `activeProject`, `projectVfs`, DATA/IMAGE FSM events 그대로다.
- collision controller state는 pending user choice만 담는 임시 React state다.
- `importProjectFilesToDirectory`는 새 persistent model을 만들지 않고 기존 load/FSM 경로를 조합한다.

## 검증 항목
- `git apply --check`, `git diff --check`.
- JavaScript syntax 검사.
- portable build.
- split/portable Chromium `file://` smoke.
- 수동 확인 권장:
  1. 외부 CSV/image 여러 개를 임의 사용자 폴더에 drop.
  2. 같은 이름 파일에서 replace / rename 각각 확인.
  3. 같은 batch 내 동일 이름이 unique path로 분리되는지 확인.
  4. 중간 파일 실패 시 앞서 추가/교체한 asset이 원상 복구되는지 확인.
  5. 외부 FFSX를 폴더에 놓으면 거부되고 slot에 놓으면 import되는지 확인.
  6. 외부 data/image를 graph/image slot에 놓을 때 기존 slot-content 전환 규칙과 collision 처리가 유지되는지 확인.
  7. 내부 node drag/drop이 여전히 move/link로 동작하는지 확인.

## 롤백
이 패치를 revert하면 외부 OS 파일 drop은 legacy asset tree 경로로만 돌아가며 DataActions collision UI도 기존 로컬 구현으로 복귀한다. 013/014의 내부 Mantine move/link 기능은 유지된다.

## 후속
외부 drop parity가 검증되면 legacy asset-tree action menu, internal/external drag/drop interaction, `window.prompt`/`window.confirm` 기반 tree UI를 제거하고 필요한 renderer/snapshot helpers만 남긴다.
