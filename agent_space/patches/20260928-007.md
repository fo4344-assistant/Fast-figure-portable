# 20260928-007

## 목적과 변경 내용

React shell 안에 남아 있던 native file input과 직접 작성한 CSV preview table을 Mantine component로 교체한다.

변경 내용:

- 데이터 추가 hidden `<input type="file">` → Mantine `FileButton`
- FFPX import hidden file input → Mantine `FileButton`
- graph palette import hidden file input → Mantine `FileButton`
- FFSX/Plotly import hidden file input → Mantine `FileButton`
- CSV preview의 raw scroll `div` + `table/thead/tbody/tr/th/td` → Mantine `ScrollArea` + `Table*`

파일 input의 기존 같은-file 재선택 동작은 Mantine `FileButton.resetRef`로 유지한다.

## 선택 이유

Mantine 도입 목적은 일반 UI element의 geometry와 interaction을 직접 HTML/CSS로 반복 구현하지 않는 것이다. hidden native input + 수동 ref click 패턴은 파일 선택 UI lifecycle을 각 기능마다 반복 구현한 상태였다.

Mantine `FileButton`이 실제 runtime에서 다음을 이미 제공한다.

- hidden native input ownership
- click delegation
- single/multiple file 전달
- accept 전달
- resetRef를 통한 input value reset

따라서 Fast Figure 쪽은 파일을 처리하는 기능 callback만 소유하면 된다.

CSV preview 또한 scroll container/table/padding/font size를 직접 inline style로 조합하지 않고 Mantine `ScrollArea`와 `Table` primitive가 표면/spacing을 소유하게 한다.

## 기능 보존

- 데이터 multi-file import
- 기존 CSV/TSV/JSON accept
- project import
- palette JSON import
- FFSX/Plotly import
- import lifecycle
- 오류 status/debug
- 실패 후 같은 파일 다시 선택
- CSV preview 최대 30행
- header row bold 표시
- header line count 의미

## 선택하지 않은 방향

### hidden native input을 계속 두고 Button만 Mantine 사용

file picker lifecycle이 여전히 custom implementation으로 남기 때문에 사용하지 않는다.

### 파일을 React state에 저장

File object는 작업 callback 범위에서 바로 기존 import command로 전달한다. 별도 state/store에 복제하지 않는다.

### custom FileButton wrapper

Mantine이 필요한 기능을 이미 제공하므로 추가 wrapper를 만들지 않는다.

### raw table에 Mantine class만 적용

표 구조/scroll/spacing 책임을 여전히 직접 소유하게 되므로 `Table`과 `ScrollArea`를 직접 사용한다.
