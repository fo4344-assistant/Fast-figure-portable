# 20260928-025

## 목적과 변경 내용

대시보드 슬롯으로 파일을 놓는 작업의 가져오기 충돌 확인을 Mantine으로 통합한다. React/Mantine의 `FastFigureDashboardFileDrop`이 대시보드 파일 drop 이벤트와 파일 선택 흐름을 소유한다. 기존 `useProjectAssetImportCollision()` Modal을 사용해 같은 이름 자산의 교체/새 이름 선택, 기본 CSV 보호, 다른 종류 자산의 rename-only 안내를 처리한다. 선택한 계획은 `FastFigureApi.assets.importToSlot`을 통해 기존 core 파일 로더와 EFSM에 전달한다.

대시보드 renderer의 슬롯 간 이동 드래그는 기존 경로에 남는다. 파일 drop 전후의 슬롯 선택·드래그 상태 정리는 `FastFigureApi.slots`의 기능 명령으로 실행한다. 데이터는 파싱하고 이미지 바이트는 읽은 뒤 충돌 계획을 요청하도록 loader의 순서를 유지한다. 파일 로더는 경로 또는 계획 callback을 명시적으로 요구하며 브라우저 기본 `confirm/alert` fallback을 제거한다.

기존 native UI의 읽기만 수행하고 반환값을 사용하지 않던 `refreshCsvControls`/`refreshImageControls`, 이미지 workspace의 no-op UI FSM hook, write-only `selectedExplorerDirectory`, 미사용 `syncSettingToggle`과 해당 호출을 제거한다. 그래프·이미지 기능 renderer, 선택 EFSM 및 프로젝트 모델은 유지한다.

## 선택 이유

충돌 선택은 화면 입력이므로 Mantine 컴포넌트가 소유하고, 경로 계산 및 교체 의미는 프로젝트 SoT가 소유한다. 기존 대시보드 event handler가 core에서 브라우저 기본 확인창을 열던 경로만 UI로 옮기면 별도 공유 선택 상태나 legacy DOM bridge 없이 동일한 기능 명령을 사용할 수 있다. 파일 로더에 명시적인 계획을 요구하면 이후 다른 호출자가 native 확인창에 우회 의존하지 않는다.

## 고려했지만 선택하지 않은 방향

- **core에서 React Modal callback을 전역 변수로 등록해 호출:** core가 임시 UI resolver의 수명과 mount 상태에 의존하는 역방향 bridge가 된다.
- **대시보드 파일 drop은 기존 `window.confirm`을 유지:** 이름 충돌·rename-only 안내가 Mantine의 다른 가져오기 흐름과 분리되어 일반 팝업 통합 목표를 충족하지 않는다.
- **슬롯 이동 드래그까지 React로 다시 구현:** 파일 선택과 무관한 기능 renderer의 슬롯 이동 규칙을 재작성해 이번 변경의 회귀 범위를 불필요하게 넓힌다.

## 범위와 후속 작업

대시보드 파일 drop의 충돌 Modal은 기존 DataActions/자산 트리의 Modal과 같은 UI 구현을 재사용한다. 명시 계획 없는 core 로더 호출은 이제 오류이며 현행 활성 호출 경로는 모두 계획을 전달한다. 파일 drop의 실제 브라우저 상호작용, 교체/rename, 슬롯 이동 및 `plan-006.md`의 17항목 기능 회귀는 초기화 smoke로 검증할 수 없어 후속 검사 대상이다. 역적용하면 core의 브라우저 기본 confirm/alert 경로와 no-op legacy 함수가 복원된다.
