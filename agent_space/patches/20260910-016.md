# 20260910-016 — Mantine external file drop ownership (corrected)

## 목적
`20260910-015`와 동일한 외부 OS 파일 → Mantine PROJECT DATA 폴더/slot drop ownership을 적용한다. 015는 source 적용 전에 context 없는 hunk 때문에 `git apply --check`에서 실패했으므로 기능 변경은 없었다. 이 교정본은 동일 구현에 정상 unified-diff context를 사용한다.

## 변경 내용
- `fast-figure.js`: 다중 파일 폴더 import를 위한 `importProjectFilesToDirectory(files, directory, planImport)` command를 추가한다. batch 내 reserved path를 공유하고, 실패 시 새 asset 삭제 및 교체 전 asset 복원으로 전체 batch를 롤백한다.
- `fast-figure-ui.js`: 파일 충돌 replace/rename 선택을 공용 `useProjectAssetImportCollision()` Mantine controller/Modal로 통합한다.
- 기존 `FastFigureDataActions`도 공용 collision controller를 사용한다.
- `FastFigureProjectDataTree`에서 외부 CSV/TSV/JSON/image를 폴더에 drop할 수 있고, 외부 파일 하나를 `/slots` 항목에 drop할 수 있다. FFSX는 slot에서만 허용한다.
- 내부 project-node move 및 project-asset → slot link drag/drop은 기존 동작을 유지한다.
- nested folder drop은 propagation을 차단한다.

## 설계 및 Source of truth
Persistent asset/path/slot authority는 기존 `activeProject`, `projectVfs`, DATA/IMAGE/SLOT FSM events 그대로다. React state는 충돌에 대한 pending 선택과 drag gesture만 보관한다. 실제 import와 rollback은 UI-independent command 및 기존 load/FSM 경계가 담당한다.

## 기각안
- legacy `#assetTree`에 synthetic event 전달: DOM bridge가 되므로 기각.
- React 안에서 project collections 직접 수정: EFSM 우회이므로 기각.
- 파일별 partial import 허용: 기존 batch rollback 의미를 손상하므로 기각.
- DataActions와 tree에 별도 collision UI 복제: generic UI ownership 중복이므로 기각.

## 검증
`git apply --check`, `git diff --check`, JavaScript syntax, portable build, split/portable Chromium `file://` smoke를 통과해야 한다. 수동으로 폴더 다중 drop, replace/rename, batch rollback, FFSX slot drop, data/image slot drop, 기존 내부 move/link를 확인한다.

## 롤백
이 패치 하나를 revert하면 013/014의 내부 Mantine move/link는 유지하면서 외부 OS file drop과 공용 collision controller만 이전 상태로 돌아간다.
