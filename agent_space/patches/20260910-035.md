# 20260910-035 — Remove legacy image settings form

## Purpose

Remove the remaining legacy image editor fieldset and its DOM synchronization/form-reader path. Mantine `FastFigureImageEditor` already owns image settings and calls `applyImageSettingsFromValues()` directly. Legacy UI compatibility is not retained. File-format compatibility is outside this cleanup and remains unchanged.

## Exact changes

### `Fast-figure.html`
- Remove the entire `#imageBox` fieldset, including fit, manual scale/position controls, and legacy preview image.

### `fast-figure.js`
- Remove image form IDs from `REQUIRED_CONTROL_IDS`.
- Remove `syncImageSettingsUi()`.
- Remove imageBox/imagePreview writes from workspace synchronization and reset paths.
- Remove the image-workspace exit hook that only hid the legacy image form.
- Remove the legacy `applyImageSettings()` form reader and DOM event handlers.
- Update the internal capability audit to require `applyImageSettingsFromValues()` rather than the deleted form reader.
- Retain `normalizeImageSettings()`, `syncSlotImageElement()`, and `applyImageSettingsFromValues()` because they are functional/model-rendering boundaries used by Mantine and the dashboard renderer.

## Rationale

The legacy image form is now a duplicate UI authority. Mantine already reads image settings from the project model, exposes the controls, and sends value objects through `applyImageSettingsFromValues()`. Keeping DOM controls or a form reader solely for fallback compatibility would violate the clarified compatibility boundary and preserve unnecessary two-way UI synchronization.

## Source of truth

- Image settings: project image object settings.
- Image mutation: `applyImageSettingsFromValues()`.
- Slot image rendering: `syncSlotImageElement()` / dashboard renderer.
- Generic image editor UI: Mantine only.

## EFSM / core impact

No project transition semantics, image data model, renderer geometry, or image-setting normalization changes. The image workspace still enters/updates through existing FSM callbacks; only the obsolete exit-side DOM hide action is removed.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, image bytes/base64, package layout, parser, serializer, import/export, or versioning code is modified.

## Rejected alternatives

- Keep `#imageBox` hidden as fallback: rejected because legacy UI compatibility is not required.
- Make Mantine synchronize values into the hidden form: rejected because that would recreate a bidirectional migration store/DOM bridge.
- Remove `applyImageSettingsFromValues()` together with the form: rejected because it is the current UI-independent functional command used by Mantine.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

Manual regression focus: Mantine fit/scale/X/Y controls still update the selected slot image; contain/cover/manual rendering remains correct; project/image import/export behavior is unchanged.

## Rollback

Revert the application commit for this patch to restore the old image form/synchronization. No stored project migration is involved.

## Follow-up

Remove dead image-form CSS, then continue with the legacy CSV/graph editor facade. Keep FFPX/FFSX/Plotly file read/write functions independent from those UI removals.
