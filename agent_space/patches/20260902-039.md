# 20260902-039 — graph object palette DOM-free command

## 배경

현재 graph palette reset/load는 모두 `saveGraphObjects()`를 통해 공통 `replaceGraphObjects()` mutation 경계를 사용한다. 따라서 EFSM/domain 우회는 없다.

하지만 색상 배열을 graph object 순서에 순환 적용하는 계산은 reset handler와 load handler에 각각 중복되어 있으며, Mantine UI에서 같은 기능을 사용하려면 legacy DOM handler와 무관한 command 경계가 필요하다.

## 목적

- graph object 전체 색상 배열 적용 의미를 하나의 DOM-free command로 통합한다.
- 기존 `replaceGraphObjects()`와 `selectedGraphObjectListTarget()`을 재사용한다.
- React/local persistent state를 추가하지 않는다.

## 변경 내용

- 앱 버전 `1.1.80-alpha` → `1.1.81-alpha`
- `setGraphObjectColorsFromPalette(colors, expectedChartId)` 추가
- `fastFigureUiBridge.setGraphObjectColors(colors, chartId)` 추가

## 동작

```text
current selected chart
→ expectedChartId stale guard
→ non-empty string palette 정규화
→ canonical editor.objects를 순서대로 map
→ palette[index % palette.length]
→ replaceGraphObjects()
```

## source of truth

command는 object 배열이나 palette를 저장하지 않는다. 호출 시 현재 canonical chart의 `editor.objects`를 다시 읽고 새 배열을 만들어 기존 `replaceGraphObjects()`에 전달한다.

## 변경하지 않음

- legacy reset/load handler
- palette file format
- single-object color command
- EFSM event/action
- Plotly trace/layout
- import/export

## 기각한 대안

### reset/load handler 안의 map을 유지

기각. 동일한 전체 palette 적용 의미가 UI별로 중복된다.

### palette를 React state에 저장

기각. 파일 입력 또는 기본 palette는 command 입력값이면 충분하며 별도 authority가 필요하지 않다.

## 검증

- patch apply/check
- JavaScript syntax
- stale chart guard는 기존 `selectedGraphObjectListTarget()` 재사용
- 빈/비문자열 palette 거부
- mutation은 `replaceGraphObjects()`만 사용
- Plotly bundle 미접촉

## rollback

- bridge `setGraphObjectColors()` 제거
- `setGraphObjectColorsFromPalette()` 제거
- 앱 버전 `1.1.80-alpha` 복원

## 후속

성공 후 legacy reset/load handler의 중복 map을 이 command 호출로 교체한다.
