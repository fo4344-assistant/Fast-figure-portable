# 20260906-038

## 목적

pre-Mantine source를 복구하고 `20260906-036`에서 JavaScript/Plotly split을 다시 검증한 현재 main에 React/ReactDOM 19.2.8과 Mantine 9.5.2의 **최초 dependency/bootstrap baseline만** 다시 도입한다.

이번 patch의 기준은 과거 최초 runtime 도입 commit:

```text
32292f024920533f49cd265a623c5ed6d3b8decf
```

이다.

이 commit 이후의 Mantine staging, bridge, owner-boundary, compatibility helper는 가져오지 않는다.

## 변경 내용

- React/ReactDOM 19.2.8 + Mantine 9.5.2 vendored production runtime을 `vendor/fast-figure-ui-runtime.js`로 추가
- 개발 HTML에서 해당 runtime을 외부 script로 로드
- 최초 baseline과 동일한 Mantine core CSS 추가
- hidden `ff-react-bootstrap-root`와 빈 `MantineProvider` bootstrap 추가
- `fastFigureTheme`의 최초 baseline 값 복구
- application build `1.1.29-alpha` → `1.1.30-alpha`
- built-in README에 React/Mantine license notice 추가
- top-level `LICENSE`에 동일 license notice 추가
- `scripts/build-portable.py`가 UI runtime도 다시 inline하도록 확장

## 명시적으로 포함하지 않는 것

- visible React/Mantine shell
- toolbar/sidebar/Modal staging
- `FastFigureReactShell`
- external store / UI snapshot
- legacy UI와 Mantine 사이 bridge
- legacy button `.click()` 호출
- legacy input `.value` adapter
- legacy dialog clone
- UI FSM/기능 EFSM/project model 변경
- 기존 UI 제거 또는 ownership cutover

현재 active UI는 이 patch 전후 모두 기존 legacy UI 한 벌이다.

## 구현 방법

GitHub Actions runner가 historical commit `32292f...`의 `Fast-figure.html`과 `LICENSE`를 직접 읽는다.

historical HTML에서 다음을 정확히 추출한다.

- `ff-mantine-runtime` inline script body
- `ff-mantine-core-styles` style block
- hidden React bootstrap root + `ff-mantine-bootstrap`
- built-in README의 React/Mantine notice

현재 split source에는 runtime body를 `vendor/fast-figure-ui-runtime.js`로 외부화해 넣고 나머지 bootstrap/CSS는 historical baseline 그대로 배치한다.

## 정확성 검증

현재 split source를 `scripts/build-portable.py`로 다시 단일 HTML로 합친 결과가 historical 최초 Mantine commit `32292f...`의 `Fast-figure.html`과 **byte-for-byte 동일해야 한다.**

`cmp`가 한 byte라도 다르다고 판단하면 workflow는 source commit을 만들지 않는다.

추가 검증:

- `node --check fast-figure.js`
- `node --check vendor/fast-figure-ui-runtime.js`
- `git diff --check`
- split `file://` smoke
- portable `file://` smoke
- Plotly 존재
- `FastFigureUiRuntime` 존재
- hidden Mantine root 생성 성공 (`window.fastFigureUiRoot`)
- `appFSM` 존재
- lifecycle `ready`

## 이 방향을 선택한 이유

이번 재포팅에서 dependency/runtime 도입과 실제 UI 구현을 분리해야 한다.

과거 최초 runtime commit은 기존 UI를 건드리지 않은 채 React/Mantine dependency와 theme/bootstrap만 추가한 검증 가능한 기준점이다. 이를 정확히 재현하면 이후 Mantine UI를 직접 구현할 때 runtime 문제와 UI 포팅 문제를 분리할 수 있다.

또한 과거 후대 source에서 runtime 파일만 임의로 복사하는 것보다 최초 baseline 전체와 portable bytes를 비교하는 편이 누락된 CSS/bootstrap/license 변화를 확실히 검출할 수 있다.

## 고려했지만 선택하지 않은 방향

### backup branch의 최신 `vendor/fast-figure-ui-runtime.js`와 HTML을 그대로 가져오기

최신 HTML에는 staging shell/bridge와 후대 migration 변경이 섞여 있으므로 선택하지 않는다.

### runtime과 동시에 toolbar/sidebar를 Mantine으로 구현

runtime 자체의 회귀와 UI 포팅 회귀를 분리할 수 없으므로 선택하지 않는다.

### CDN React/Mantine 사용

Fast Figure의 offline/portable 요구와 충돌한다.

### `@mantine/modals` 추가

기존 UI FSM이 overlay state를 소유하며 현재 계획에는 필요하지 않다. controlled `@mantine/core` primitive를 사용한다.

## source of truth / EFSM / project 영향

없음.

- 기존 UI FSM 의미 유지
- 기능 EFSM state/transition 유지
- project class/model 유지
- FFPX/FFSX schema 및 file semantics 유지
- Plotly/slot/image/layout/label renderer 유지
- 새로운 persistent state 없음

hidden React root는 빈 `MantineProvider`의 dependency/bootstrap 검증용이며 기능 상태를 소유하지 않는다.

## 회귀 위험

주요 위험은 historical runtime/CSS/bootstrap을 split source로 옮기면서 byte 위치나 portable embedding이 달라지는 것이다.

이를 historical 최초 Mantine HTML과의 byte-identical portable 비교로 차단한다.

## rollback

이 patch를 reverse apply하면:

- `vendor/fast-figure-ui-runtime.js` 제거
- Mantine CSS/bootstrap 제거
- React/Mantine license notice 제거
- portable builder에서 runtime embedding 제거
- `APP_BUILD` 및 built-in version이 `1.1.29-alpha`로 복원

되어 `20260906-036` 직후의 split pre-Mantine source로 돌아간다.

## 후속 작업

이 patch가 통과한 뒤:

1. 일반 split-source patch workflow가 `vendor/fast-figure-ui-runtime.js`를 검증하도록 최소 갱신한다.
2. legacy UI의 기능 inventory를 현재 pre-Mantine source에서 작성한다.
3. inventory를 기준으로 Mantine component를 기존 UI FSM/기능 command에 직접 연결해 구현한다.
