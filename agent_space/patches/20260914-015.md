# 20260914-015 — Remove legacy layout panel markup

## Purpose
Remove the native legacy layout panel markup now that Mantine owns layout controls and the legacy event ownership has already been disconnected.

## Exact changes
- Delete `section#layoutPanel` and all child controls from `Fast-figure.html`.
- Preserve `main`, `graphArea`, `dashboard`, and `dashboardCaption`.
- Do not change project layout state, EFSM events, dashboard rendering, export geometry, or Mantine components.

## Rationale
The legacy panel no longer owns interaction. Core rendering tolerates the absent `layoutMap`: `renderLayout()` returns when it is missing, and `applySlotStyle()` guards optional layout-map access. Keeping the panel would leave a second obsolete UI implementation in the portable source.

## Rejected alternatives
- Keep the hidden panel indefinitely: rejected because it preserves duplicate UI ownership and dead controls.
- Remove layout-domain helpers together with the markup: rejected for this step because helpers still participate in dashboard geometry/rendering or are safer to classify after markup removal.

## Source of truth
Layout values remain in `activeProject.layout`, updated through the existing EFSM/Mantine path. No second state source is introduced.

## EFSM/core impact
None intended. This is markup deletion only; layout model, events, renderer, slot geometry, and export behavior remain unchanged.
