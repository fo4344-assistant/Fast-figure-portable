# 20260902-016 — graph object type visibility 공통 helper 분할 재시도

## 목적

`20260902-015`의 대형 graph object form staging patch가 `git apply --check` 단계에서 실패했으므로, 기능 단위를 분할해 먼저 legacy/Mantine가 공유할 graph type visibility 규칙만 독립 적용한다.

`015`는 HTML에 적용되지 않았으며 실패 기록으로 보존한다.

## `015` 실패 판정

- patch 파일 자체는 unified diff parser에서 정상이다.
- GitHub Actions 실패 단계는 `Check and apply patch`다.
- JavaScript syntax check와 commit 단계는 실행되지 않았다.
- 따라서 malformed diff가 아니라 현재 main과 하나 이상의 hunk context가 맞지 않은 것으로 판정한다.
- 어떤 hunk가 실패했는지 확정할 수 없는 상태에서 같은 대형 patch를 재생성하지 않는다.

## 변경 내용

- 앱 버전 `1.1.63-alpha` → `1.1.64-alpha`
- `graphObjectTypeVisibility(type)` 순수 helper 추가
- 기존 `updateTypeSpecificOptions()`의 inline 조건을 helper 호출로 교체

공통 규칙:

```text
line: scatter / lines+markers / hidden
marker: markers / lines+markers
bar: bar
```

## 이 방향을 선택한 이유

Mantine graph object form을 연결하기 전에 type별 control 표시 규칙을 하나로 만들어 두면 legacy와 Mantine가 같은 조건을 공유할 수 있다.

분할 적용은 실패 지점을 좁히고 rollback 단위를 작게 만든다.

## 기능 의미 보존

기존 `updateTypeSpecificOptions()`의 결과는 동일하다.

- 기존 세 boolean 계산을 순수 helper로 옮길 뿐이다.
- trace 생성, chart type validation, EFSM, object schema는 변경하지 않는다.
- helper는 presentation visibility만 계산한다.

## 선택하지 않은 방향

### `015` 전체 patch를 context만 넓혀 재시도

선택하지 않았다. 어느 hunk가 실패했는지 불명확한 상태에서 대형 patch를 다시 시도하면 실패 원인 추적성이 낮다.

### Mantine component 내부에 조건 복사

선택하지 않았다. legacy와 Mantine에 같은 규칙을 두 벌 유지하게 된다.

## 검증

- `git apply --check`
- `git diff --check`
- inline JavaScript `node --check`
- 적용 diff에서 `updateTypeSpecificOptions()`의 조건 결과가 기존과 동일한지 확인

## rollback

- `graphObjectTypeVisibility()` 제거
- `updateTypeSpecificOptions()`에 기존 inline 세 조건 복원
- 앱 버전 `1.1.63-alpha` 복원

## 후속 작업

`016` 성공 후 `017`에서 Mantine graph object component/sidebar wiring만 별도 patch로 적용한다. 해당 patch는 이미 준비된 `012`~`014` read/write/column 경계와 `016` visibility helper만 사용한다.
