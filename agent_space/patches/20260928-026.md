# 20260928-026 — 브라우저 회귀 검사

## 목적과 변경

`plan-006.md` 12절의 파일 왕복, 자산 참조, UI 구조를 실제 브라우저의 split 및 portable `file://` 빌드에서 반복 검사한다. `agent_space/tests/browser-regression.js`는 애플리케이션을 실행한 뒤 FFPX/FFSX/Plotly 저장과 재불러오기, CSV와 이미지, 병합, 라벨·캡션·팔레트, 충돌 처리, 삭제·휴지통 참조, ID와 기본 배치 수치를 검사한다. `run-browser-regression.py`는 Chrome의 실행 결과를 수집하고 실패 항목에서 종료 코드 1을 반환한다. 별도 Actions workflow가 두 빌드를 검사한다.

애플리케이션의 영속 source of truth는 기존 project object와 FSM이다. 검사 코드는 배포 빌드에 포함되지 않는다. 테스트가 호출하는 기능 API는 런타임의 실제 command이며 별도 호환 계층을 추가하지 않는다.

## 선택한 이유

기존 Actions smoke는 초기화 여부만 검사한다. 현재 로컬에는 Chrome 실행 파일이 없어 동일한 `file://` 브라우저에서 실행할 수 있는 저장소 내 검사와 Actions 실행 경로가 필요하다. 이 검사는 두 배포 형식을 같은 시나리오로 확인하고 각 항목의 실제 실패를 기록한다.

## 고려했으나 선택하지 않은 방향

- 함수 호출만 grep하거나 Node의 모의 DOM에서 패키지 함수를 호출하는 방법: 실제 React/Plotly 및 브라우저 파일 API 결합을 검증하지 못한다.
- 기존 `apply-fast-figure-patch.yml`에 검사를 넣는 방법: 패치 적용 자체의 게이트에 긴 상호작용 검사를 결합하고 현재 patch target 제한을 우회해야 하므로 독립 회귀 workflow가 더 적합하다.
- 다운로드된 외부 Playwright 브라우저를 로컬에서 설치하는 방법: 현재 실행 환경에서 배포 CDN 접근이 차단되어 재현할 수 없다.

## 실제 포함 범위와 남은 검증

이 diff는 테스트 스크립트 2개와 workflow 1개만 추가한다. 정상 소스 파일은 수정하지 않는다. pre-Mantine FFPX 실물 fixture가 없어 1번은 `blocked`로 표시한다. 10번은 같은 File 객체의 import command 재시도만 확인하며 파일 입력 DOM의 동일 파일 재선택은 아직 확인하지 않는다. 13번은 drag UI가 호출하는 이동 계획/command의 참조 cascade를 확인하며 pointer drag 이벤트 자체는 확인하지 않는다. 15–17번은 구조와 수치에 대한 기본 검사이며, 세밀한 화면 비교 및 generic UI 전체 소유권 감사는 별도 확인이 필요하다. Actions 결과에서 실패가 나오면 실제 원인을 고치고 재실행한다.

일반 패치 적용 workflow는 이 경로들을 허용하지 않는다. 이 패치 쌍은 변경 기록으로 먼저 저장하고, 같은 diff의 세 파일을 GitHub contents API로 직접 생성한다. `Queue Fast Figure` 접두사를 사용하지 않아 허용 경로 밖의 patch가 자동 적용되지 않는다.
