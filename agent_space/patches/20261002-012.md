## 이 방향을 선택한 이유

layout preview slot은 클릭 가능하지만 본질적으로 command button이 아니라
dashboard grid geometry를 축소해서 보여주는 renderer surface다.

generic Button을 유지한 채 height override를 반복하면 전역 Button theme와
preview 전용 geometry가 같은 component 안에서 충돌한다.

Mantine `UnstyledButton`을 사용하면:

- button semantics와 disabled/click interaction은 유지되고
- generic Button의 38px height/padding은 제거되며
- cell 크기는 CSS grid가 결정하고
- Mantine component 체계 안에 남을 수 있다.

따라서 별도 custom button component나 중복 state 없이 문제 원인을 제거한다.

## 고려했지만 선택하지 않은 다른 방향

### Mantine Button에 height: 100%만 추가

Button 내부의 size variable, padding, typography와 component styling이 계속 preview geometry에
결합된다. 이후 theme 변경 때 같은 회귀가 재발할 수 있어 선택하지 않았다.

### native button을 직접 사용

geometry는 해결되지만 UI component 통합 목적과 어긋난다.
동일한 interaction semantics를 Mantine UnstyledButton으로 얻을 수 있으므로 사용하지 않았다.

### preview cell을 비상호작용 div로 변경

slot merge/split 대상 선택 interaction을 잃거나 별도 keyboard semantics를 다시 구현해야 한다.
기능 자유도를 줄이므로 선택하지 않았다.

### layout alignment까지 같은 패치에서 모두 수정

이번 단계는 문제군별 첫 수정 1건을 적용하는 현재 작업 순서를 따른다.
form alignment는 UI specification에 기준만 기록하고 실제 source 수정은 후속 layout/design 단계로 남긴다.

## 디자인 specification 분리

사용자 지시에 따라 디자인 규칙을 Source Script 의미로 승격하지 않았다.

새 문서 `agent_space/docs/ui-design-specification.md`는 특정 소스 함수에 종속되지 않고
다음을 정의한다.

- generic UI control과 renderer surface의 구분
- modal/action hierarchy
- form alignment
- layout preview geometry와 selection
- label preview typography parity
- font selector
- numeric draft/commit
- caption editor alignment
- preview와 실제 renderer의 대응 원칙

domain/persistent/file-format 의미는 해당 문서의 범위에서 제외한다.

## Source Script / verification 판정

- Source Script r12 변경 없음
- verification-model r6 변경 없음
- TLC 상태 변경 없음

layout logical geometry와 selection command는 이미 상위 계층에 존재한다.
이번 수정은 source-code renderer composition만 바로잡는다.

## 검증

추가 browser regression:

1. startup default project의 layout overlay를 연다.
2. preview grid와 direct slot cell이 존재한다.
3. slot cell이 `.mantine-Button-root`가 아니다.
4. CSS grid의 padding/gap/row count로 계산한 한 row 높이와 실제 첫 cell height가 1.5px 이내로 일치한다.
5. 검사 후 overlay를 닫고 기존 regression을 계속 수행한다.

development-layer version 검사, distribution build, browser regression을 모두 통과해야 완료로 본다.

## rollback

이 패치만 되돌릴 경우:

- layout preview cell을 기존 Mantine Button으로 복원
- regression target/test를 r5 상태로 복원

- UI specification과 review-024 제거

persistent project data 변경이나 migration은 없으므로 data rollback은 필요하지 않다.
