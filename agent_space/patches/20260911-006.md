# 20260911-006 — Remove remaining legacy graph UI wiring

## Purpose

Remove the remaining active DOM wiring for the obsolete sidebar graph UI after `20260911-005` disconnected the graph-object editor. Mantine already owns graph palette, FFSX/Plotly actions, header-line editing, global graph settings, and all axis controls. Legacy UI compatibility is not retained.

## Exact changes

### `fast-figure.js`
- Remove legacy graph palette reset/save/load button and hidden file-input handlers.
- Remove legacy FFSX/Plotly export/import button/input handlers and editable-toggle binding.
- Remove legacy `#headerLines` change handler.
- Remove legacy showLegend/showTitle/showZeroLine bindings.
- Remove legacy axis-field change/Enter/toggle event listeners.
- Remove graph-only entries from `connectLifecycleTasksToFSM()`; Mantine wraps those actions directly.
- Stop startup initialization of graph axis fields, graph palette DOM, editable-state DOM, and graph-only setting toggles.
- Remove startup `fillGraphFontSelect("graphFontFamily")`.
- Keep `downloadSlotFfsx()`, `downloadPlotlyJson()`, `importSlotFile()`, FFSX build/read functions, Plotly conversion, chart rendering, and all `graphEditor*` commands.

## Rationale

The old controls are no longer a supported UI surface. Leaving their event handlers or startup initialization active would preserve hidden compatibility state and a second presentation authority. File-format functionality is independent and remains available to Mantine through direct function calls.

## Source of truth

- Persistent graph state: project chart model / `appFSM`.
- Generic graph controls: Mantine.
- FFSX and Plotly compatibility: existing UI-independent parser/serializer/import/export functions.

## EFSM / core impact

None. No event semantics, chart schema, renderer logic, or project mutation rules change.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, CSV, image, parser, serializer, manifest, or package-version behavior changes.

## Rejected alternatives

- Keep hidden legacy controls wired: rejected because legacy UI compatibility is not required.
- Route Mantine through legacy button handlers: rejected because it recreates a DOM bridge.
- Move format code into React: rejected because file compatibility should remain UI-independent.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert this patch's application commit. No stored data migration is involved.

## Follow-up

Remove dead legacy graph form readers/renderers/helpers, decouple `selectCsvFromTree()` and data-table defaults from graph DOM, then delete the complete `#buildBox` markup, required IDs, and graph-only CSS.
