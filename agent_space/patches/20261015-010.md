# 20261015-010 — Boundary Core verification r26 보정

## 목적과 변경 내용

plan-016 verification r25의 실제 TLC 실행에서 발견된 verification model 표현 오류를 수정하고 r26/pending lineage로 갱신한다.

- `FastFigureBoundaryCore.tla`의 `ConsumeReadProjection`에서 `phase` 변경과 `UNCHANGED vars`가 동시에 요구되던 모순을 제거했다.
- `phase: read-ready -> read-consumed`만 변경하고 project authority, reference/result/reconciliation/renderer/projection state는 그대로 유지한다.
- verification fingerprint를 새 TLA blob에 맞춰 갱신하고 revision을 r26으로 증가시켰다.
- `review-20261015-024-verification-r26-correction.md`에 최초 TLC 실패, counterexample 해석, Source Script/PlusCal 대조와 보정 근거를 기록했다.
- `verification/README.md`를 r26 및 재검증 진행 상태로 갱신했다.

## 오류 판정

GitHub Actions run `38703339145`의 Boundary Core job에서 SANY parse는 성공했고 TLC가 다음 증거와 함께 실패했다.

- `phase`가 변경되면서 `UNCHANGED`로도 지정되었다는 경고
- invalid/stale mutation rejection 뒤 read projection에 진입한 후 `read-ready`에서 deadlock

`vars`에 `phase`가 포함되어 있어 `ConsumeReadProjection` action 자체가 만족 불가능했다.

Source Script r25와 pseudocode r11은 read projection 소비가 Backend authority를 변경하지 않는다고 정의하지만 `read-ready`에서 정지하라는 의미는 없다. 따라서 정책에 따라 이 반례를 verification derivation 오류로 분류했으며 상위 Source Script/PlusCal은 변경하지 않았다.

## 선택한 방향과 이유

`ConsumeReadProjection`의 목적은 read projection을 소비한 뒤 안정 상태 `read-consumed`로 전이하는 것이다. 따라서 `phase`만 next-state로 변경하고 나머지 state를 명시적으로 `UNCHANGED`로 유지하는 최소 수정이 상위 명세의 의미를 그대로 보존한다.

## 고려했으나 선택하지 않은 방향

- **deadlock 검사를 끄기:** 모델 오류를 숨기므로 기각했다.
- **`read-ready`를 terminal state로 재정의:** Source Script/PlusCal에 없는 의미를 추가하므로 기각했다.
- **Source Script 또는 PlusCal 수정:** counterexample이 verification 표현의 자기모순으로 설명되므로 기각했다.
- **`UNCHANGED`를 전부 제거:** 관계없는 state가 비결정적으로 바뀔 여지를 만들므로 기각했다.
