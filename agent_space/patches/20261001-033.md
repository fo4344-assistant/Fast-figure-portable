# 20261001-033 — FastFigureSlotCore PlusCal/TLC 검사 workflow

## 목적

verification code r2를 실제 PlusCal translator와 TLC로 검사할 수 있는
재현 가능한 CI 실행 경로를 추가한다.

이번 patch는 verification code 자체의 의미를 변경하지 않는다.

## 검사 순서

1. Ubuntu runner에서 Java 21 설정
2. 공식 TLA+ v1.7.4 `tla2tools.jar` 다운로드
3. 공식 release checksum과 SHA-1 대조
4. verification 파일을 temporary directory로 복사
5. `pcal.trans`로 PlusCal -> TLA+ 번역
6. SANY parser로 생성 TLA+ parsing/semantic analysis
7. TLC로 `FastFigureSlotCore.cfg` model checking

translator가 `.tla` 파일에 생성 translation block을 쓰므로
repository checkout 원본 대신 `/tmp/fast-figure-tla` 복사본에서 실행한다.

## 도구 버전

TLA+ tools: v1.7.4

release checksum:

```text
bee4a54f3ee3d4afc347c3240ec2d9e93b075104  tla2tools.jar
```

공식 TLA+ release에 게시된 checksum을 사용한다.

## 선택 이유

현재 작업 환경에서는 private repository 파일과 외부 TLA+ binary를
동일 local execution environment로 직접 결합하기 어렵다.

GitHub Actions에서는 repository checkout과 공식 TLA+ CLI를 같은 runner에서 사용하므로
실제 repository content를 그대로 검사할 수 있고 이후 verification code 변경에도 재사용할 수 있다.

## 고려했지만 선택하지 않은 방향

### translator가 생성한 TLA+ block을 repository에 미리 commit

선택하지 않았다.

PlusCal이 원천 verification code이고 generated translation은 도구 출력이므로
검사 때마다 재생성하는 편이 원천/생성물 혼동을 줄인다.

### TLC만 실행

선택하지 않았다.

PlusCal 문법 오류와 TLA+ semantic 오류를 구분하기 위해
translator -> SANY -> TLC를 단계별로 실행한다.

### 최신 pre-release/nightly 사용

선택하지 않았다.

첫 검사는 재현 가능한 tagged release v1.7.4와 공개 checksum을 고정한다.
새 버전 기능이 필요할 때 별도 patch로 변경한다.

## version layer 영향

없음.

verification code 파일과 fingerprint는 변경하지 않는다.
`verification-model r2 current / TLC pending` 상태를 유지한다.
