# 20260910-013 — Mantine asset move/menu ownership

## 목적
Mantine `PROJECT DATA` 트리가 파일/폴더 이동, drag/drop, 휴지통 이동, 이름 충돌 확인을 직접 소유하도록 한다. 기존 project VFS 및 `PROJECT_NODE_MOVED` EFSM 명령을 재사용하며 legacy DOM click/value 경유를 추가하지 않는다.

## 변경 위치
- `fast-figure.js`
  - `applyProjectNodeMovedAction()`에 선택적 `payload.name`을 추가한다.
  - 이동 대상 이름은 기존 `projectCsvName()` 규칙으로 검증한다.
  - 파일 이동에서 새 이름을 선택한 경우 `asset.name`과 `asset.directory`를 같은 EFSM action 안에서 갱신한다.
  - 디렉터리 이동의 기존 descendant path rewrite, 휴지통 진입 시 참조 제거, 선택 상태 보정은 그대로 유지한다.
- `fast-figure-ui.js`
  - Mantine `Menu`를 사용해 CSV/image 및 이동 가능한 폴더에 `···` 작업 메뉴를 추가한다.
  - CSV/image 메뉴: 다운로드, 이동, 휴지통으로 이동.
  - 사용자 폴더 메뉴: 이동, 휴지통으로 이동.
  - CSV/image와 사용자 폴더를 HTML5 drag source로 만들고 모든 프로젝트 폴더를 drop target으로 사용한다.
  - 메뉴 이동과 drag/drop은 동일한 `requestProjectNodeMove()` -> `PROJECT_NODE_MOVED` 경로를 사용한다.
  - 이동 대상 선택은 Mantine Modal + searchable Select가 소유한다.
  - 동일 이름 충돌 시 `projectVfs.uniquePath()`로 제안 이름을 계산하고 Mantine 확인 Modal에서 `새 이름으로 이동`을 선택할 수 있다.
  - 휴지통 진입으로 그래프/슬롯 참조가 제거될 경우 기존 `projectAssetReferenceCount()`를 사용해 확인 Modal을 표시한다.
  - 디렉터리 이동 후 Mantine tree의 임시 expanded/last-directory UI state만 새 경로로 재작성한다.

## 설계 이유
`PROJECT_NODE_MOVED`는 이미 프로젝트 경로, 하위 asset path, graph/image reference cascade, selected asset path를 일관되게 갱신하는 유일한 기능 경계다. Mantine에서 별도 이동 알고리즘을 만들면 project VFS의 source of truth가 둘로 나뉜다. 따라서 UI는 이동 계획과 확인만 담당하고 실제 변경은 기존 EFSM action 하나가 담당한다.

충돌 자동 rename을 지원하려면 기존 action이 목적 폴더만 받아 원래 basename을 강제하던 제한을 풀어야 한다. 선택적 `name`은 기존 호출의 의미를 보존하면서 Mantine 충돌 UI가 같은 action을 사용할 수 있게 하는 최소 API 확장이다.

## 기각안
- legacy `assetTree`의 drag/drop handler를 Mantine에서 `.dispatchEvent()` 또는 `.click()`으로 호출: UI bridge가 장기화되므로 기각.
- Mantine component에서 `asset.directory/name`을 직접 수정: EFSM 및 validation 경계를 우회하므로 기각.
- 충돌 시 단순 error/status 출력: 사용자가 drag/drop과 menu 이동을 실제로 완료할 수 없으므로 기각.
- 별도 React file-tree store 도입: persistent project path와 중복 authority가 생기므로 기각.

## Source of truth / EFSM 영향
- persistent project path authority는 계속 `activeProject.fileSystem` + asset `directory/name` + `projectVfs`다.
- 이동 mutation authority는 계속 `PROJECT_NODE_MOVED`다.
- React state는 move picker/confirm/drag source/expanded 같은 일시 UI state뿐이다.
- `payload.name`은 optional이며 기존 모든 호출은 이전과 동일한 basename 이동을 수행한다.

## 롤백
이 패치 하나를 revert하면 Mantine move/menu/drag-drop UI와 `PROJECT_NODE_MOVED.payload.name` 확장이 함께 제거된다. 기존 legacy 이동 동작과 원래 basename-only EFSM semantics로 돌아간다.

## 후속
이 패치가 안정화되면 legacy `assetTree` 자체의 action menu/drag-drop listener와 관련 native confirm 경로를 제거해 중복 generic UI ownership을 정리할 수 있다.
