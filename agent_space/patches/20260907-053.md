# 20260907-053 — Restore PROJECT_IMPORT lifecycle on Mantine import

## Purpose

Restore the UI FSM lifecycle wrapper that the legacy project-file input had around FFPX/JSON project import and that was unintentionally omitted when `20260907-050` moved the file input into React.

This is a parity correction to the direct Mantine implementation, not a new bridge or abstraction.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- FFPX/JSON parsing
- `importProject()`
- project models/classes
- UI FSM definitions
- lifecycle event definitions
- the legacy project input

## Existing lifecycle reused

The legacy lifecycle connector wraps project-file input changes with:

- lifecycle state: `importing`
- event: `PROJECT_IMPORT`

The Mantine path now uses the already-existing `runLifecycleTask("importing", "PROJECT_IMPORT", ...)` helper to preserve that behavior.

## Exact changes

1. Wraps the existing Mantine project import parsing/import body in `runLifecycleTask("importing", "PROJECT_IMPORT", async () => ...)`.
2. Keeps the existing inner project-import error handling unchanged:
   - project import error status
   - `project:import-error` debug log
3. Keeps input reset in an outer `finally`, so same-file reselection remains available regardless of lifecycle or import outcome.
4. Adds no new event, state, handler bridge, or model mutation path.

## Why this direction

`20260907-050` correctly removed the legacy DOM input bridge, but direct ownership also requires preserving the UI FSM lifecycle that used to be attached to that input. Omitting it allows project import to run while `state.lifecycle` remains `ready`, which is behaviorally different from the existing UI contract. The correct fix is to reuse the existing lifecycle, not to restore the legacy input.

## Rejected alternatives

### Reconnect the legacy `#importProjectFile` input

Rejected because that would undo the direct Mantine ownership achieved by `050`.

### Add a new Mantine-specific lifecycle state/event

Rejected because `importing` / `PROJECT_IMPORT` already exist and are the authoritative lifecycle contract.

### Move lifecycle handling into `ffpxReadProject()` or `importProject()`

Rejected because lifecycle is UI FSM responsibility, not project parsing/model responsibility.

## Rollback

Revert `20260907-053.patch`. This only removes the lifecycle wrapper; no project data or format rollback is required.
