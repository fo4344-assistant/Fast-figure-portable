# 20260903-001 — graph editor selection / legacy form sync 경계 분리

## 목적

React/Mantine shell cutover 전 초기화 순서 감사에서 확인된 workspace entry의 legacy DOM 결합을 줄이기 위한 첫 단계다.

현재 `syncGraphWorkspaceState()`는 선택된 chart가 바뀌면 `editChart(id)`를 호출한다. 그런데 `editChart()`는 다음 두 책임을 한 함수에 섞고 있다.

1. canonical 편집 대상 chart/CSV를 선택하고 transient editor selection state를 갱신하는 작업
2. `fileName`, `headerLines`, X/Y column, axis form, toggle, graph-object list 등 legacy native form을 채우는 presentation 작업

Mantine shell cutover 후 workspace EFSM entry에서 2번을 호출하면 제거된 legacy DOM ID에 의존하게 된다. 이번 패치는 1번만 DOM-free helper로 추출한다.

## 변경 내용

- 앱 버전 `1.1.103-alpha` → `1.1.104-alpha`
- `selectChartForEditing(id)` 추가
  - chart 조회 / missing debug
  - chart가 참조하는 CSV 조회
  - read-only imported chart의 기존 default CSV fallback 유지
  - `editing`, `activeDataName`, `activeCsvId`, `selectedObjectIndex` 갱신
  - 기존 `refreshCsvControls(csv.id)` 재사용
  - `{ chart, csv }` 반환
- 기존 `editChart(id)`는 `selectChartForEditing(id)`을 호출한 뒤 기존 legacy UI synchronization을 그대로 수행한다.
- `loadData()`와 `activeDataReady = true`의 순서는 기존과 동일하게 유지한다. 따라서 legacy 데이터 preview 초기화 실패 시 transient ready 상태가 먼저 true가 되는 의미 변경을 만들지 않는다.

## 이 방향을 선택한 이유

현재 active UI는 아직 legacy이므로 `editChart()`에서 native form synchronization을 즉시 제거하면 회귀 위험이 크다. 반대로 Mantine용 chart selection 로직을 새로 구현하면 `editing`/`activeCsvId` 의미가 두 군데로 갈라진다.

따라서 기존 함수의 domain selection 부분만 하나의 helper로 추출하고 legacy wrapper가 동일 helper를 사용하도록 한다. 이후 workspace EFSM entry를 domain-only callback으로 전환할 때 `selectChartForEditing()`을 직접 재사용할 수 있다.

## 고려했지만 선택하지 않은 방향

### `syncGraphWorkspaceState()`에서 Mantine 여부를 검사해 `editChart()` 호출을 조건 분기

기각. UI implementation 여부가 workspace domain transition 로직에 스며든다.

### `editChart()` 전체를 즉시 DOM-free로 변경

기각. 현재 active legacy sidebar의 graph form synchronization이 한 번에 사라져 cutover 전 단계에서 회귀 범위가 너무 커진다.

### React local state로 editing chart/CSV를 별도 보관

기각. 기존 `editing`, project chart, `activeCsvId`와 중복 authority가 생긴다.

## source of truth / EFSM

- chart source: project chart model
- selected editing chart: 기존 `editing`
- active CSV: 기존 `activeCsvId`
- workspace EFSM 의미 변경 없음
- graph object EFSM 변경 없음
- FFPX/FFSX/Plotly schema 변경 없음

## 회귀 위험

낮음~중간.

이번 patch 적용 후 기존 `editChart(id)`의 외부 observable 동작은 동일해야 한다.

확인 항목:

- 존재하지 않는 chart ID의 debug/return 의미 유지
- CSV가 없는 editable chart는 기존과 동일하게 오류
- imported read-only chart의 default CSV fallback 유지
- `setFileName`, `headerLines`, `loadData`, axis/global/object form 동기화 순서 유지
- `activeDataReady` 설정 위치 유지
- JavaScript syntax 정상

## rollback

1. `selectChartForEditing()` 제거
2. `editChart()`의 기존 초기 chart/CSV selection 코드를 inline으로 복원
3. 버전 문자열을 `1.1.103-alpha`로 복원

## 후속

다음 patch에서 `syncProjectWorkspaceState`, `syncGraphWorkspaceState`, `syncImageWorkspaceState`를 domain synchronization과 legacy presentation adapter로 분리한다. 실제 EFSM entry callback 교체는 active Mantine shell mount와 같은 cutover 단계에서 수행한다.
