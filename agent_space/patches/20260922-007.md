# 20260922-007

## 목적과 변경 내용

Mantine UI palette editor가 `activeProject.appearance.uiPalette`, `DEFAULT_UI_PALETTE`, `applyUiPaletteValues()`를 직접 참조하던 경로를 appearance API로 이동한다.

추가 API:

- `FastFigureApi.appearance.readPalette()`
- `FastFigureApi.appearance.setPalette(values)`
- `FastFigureApi.appearance.resetPalette()`

`readPalette()`는 현재 appearance SoT에서 새 frozen snapshot을 반환한다. set/reset command는 기존 `applyUiPaletteValues()`를 backend 내부에서 사용하고 적용 후 snapshot을 반환한다.

Mantine의 `draft`는 modal 입력 중에만 사용하는 component-local UI draft로 유지한다.

## 선택 이유

UI palette는 project appearance의 영속 SoT다. SoT 구현체가 공식 read/write API를 제공하고 frontend는 mutable project object를 직접 보지 않는 구조가 현재 경계 규칙에 맞는다.

반면 color input의 미적용 draft는 명시적인 UI 입력 예외이며 component 밖에서 참조되지 않으므로 local state로 두는 것이 맞다.

## 선택하지 않은 방향

### `activeProject.appearance`를 frontend에 그대로 노출

mutable project object 자체를 전달하면 frontend가 API를 우회해 수정할 수 있으므로 사용하지 않는다.

### `DEFAULT_UI_PALETTE`를 frontend constant로 복제

default 정책이 두 군데 생기므로 사용하지 않는다. reset command가 core default를 적용하고 결과 snapshot을 반환한다.

### draft를 core 상태로 승격

적용 전 입력은 UI-local draft이며 영속 기능 의미가 없다. backend state나 API-visible buffer로 만들지 않는다.

## 전제와 후속 작업

- palette snapshot은 호출 시 생성되고 저장되지 않는다.
- 기존 색상 validation/normalization 및 renderer 적용은 `applyUiPaletteValues()`에 그대로 남는다.
- 다른 Mantine component의 project/model 직접 접근은 기능 ownership별로 후속 API화한다.

## 롤백

역적용하면 palette editor가 다시 `activeProject`와 core palette 함수/constant를 직접 참조한다. project schema와 저장 형식에는 변화가 없다.
