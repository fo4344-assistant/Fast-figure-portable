# Source Script 전체 작성 형식과 정의·처리 분리

## 요청과 범위

Source Script 전체를 저장된 예시 형식으로 고치고, 변수 정의에 처리 과정과 완료 판단을 넣은 문제를 함께 수정하라는 지시를 반영한다. `sourcescript`의 Python 문서 15개, 총 188개 함수·메서드와 그 자료 정의가 대상이다. `settings.json`은 설정 데이터로 유지한다.

## 변경 내용

- 지역변수에는 자료형·원형·값의 의미를 정의하고, 생성·복사·검증·반영은 `처리`에 작성했다. `buildProjectObject`의 candidate는 `ProjectObject` 인스턴스로 정의하고 입력 자료 구성·검증·생성을 순서대로 연결했다.
- 함수마다 `Args`·`Return`·`변경`·`처리`를 배치했다. 인자·반환값의 이름과 실제 속성 접근, 반환 변수, 단계 번호를 맞췄다. 순수 계산과 candidate 변경, 현재 상태·DOM·다운로드 자원 변경을 구분했다.
- Slot 원형과 현재 `activeProject._state` 소유, 저장 슬롯 딕셔너리 변환, graph·CSV·이미지 참조, VFS·패키지, 명령 결과와 실제 경로, 현재 선택 입력과 revision 구독, renderer 자원·caption·raster, 초기화와 배포 작성을 각 담당 절차에 연결했다.
- 분리되어 있던 Python 본문의 조건·호출·반환 의미를 자연어 처리에 포함했다. graph 축·확장 필드 병합, 슬롯 배치, 이미지·caption 수식, 파일 형식과 자원 수명 규칙을 보존했다. 정의되지 않은 일반적인 요청 표현은 명령명·조회명·실제 입력 항목으로 구체화했다.
- chart·layout·논리값·미반영 명령 결과·None의 반환 구분을 보완했다. CSV 선택, 디렉터리 이동·생성, 빈 이미지 생성의 성공 경로와 현재 대상 재검증을 명시했다.
- Source Script revision을 49로 올리고 실제 fingerprint를 기록했다. `stale`·`open`과 하위 계층의 기존 revision·파생 관계는 유지했다. Plan029에 전체 적용 범위와 정적 대조 결과를 기록했다.

## 작성 방식과 확인 범위

기존 모듈·설정·공통 원형을 유지하며 저장된 예시의 형식을 적용했다. 구문을 읽는 작성 보조 도구의 초안을 실제 편집에 반영한 뒤, 절 배치·반환형·명령 인자·사전 필드 표기와 변경 선언을 다시 대조해 수정했다. 전체 구문 파싱, 188개 함수의 절 순서·반환 변수·정의와 처리 분리, 이전 함수·명령 이름 및 주요 수치 보존을 정적으로 확인했다. fingerprint는 기존 도구의 해시 계산 함수만 사용했다.

pseudocode·source code·설정 데이터·배포 파일·정책 본문·AGENT는 이 변경에서 수정하지 않았다. Source Script·앱·테스트·빌드·브라우저·version checker 본체·커밋·푸시를 실행하지 않았다. 전체 계층의 닫힘과 실행 통과를 선언하지 않는다.
