# 20261112-008 — 모듈별 번역 일정 재편

목적: 사용자가 Plan의 기존 작업을 다시 정리해 모듈 단위 일정을 수립하라고 지시했다. 절차별 부분 패치 진척과 모듈 전체 종료가 혼재했던 관리를 바로잡는다.

변경: Plan024 전체를 확인하고 Plan025를 작성했다. 기존 화면/raster 대응 기록은 재사용하고, 남은 15개 논리 모듈의 유지/차수별 범위·실제 caller·종료 산출물·의존 관계를 명시한다. 다음 작업은 backend/graphs 잔여 전체이며 Backend layout/assets/state/EFSM, Frontend FSM/adapter, public API 4개, Mantine, system, portable_build 순으로 마무리하고 허가된 실행 검증은 분리한다. 차수는 순서이지 근거 없는 일수/완료시간 약속이 아니다. 상위 의미 차단을 해당 분기로 격리하고, 차단 모듈을 완료로 세지 않으며 이미 대응된 경로는 재작성하지 않는다. Plan024에는 새 계획 포인터만 추가하고 기존 이력은 보존한다.

이유/기각한 대안: 기존 계획 끝에 또 부분 패치 기록만 쌓는 대신 단일 후속 계획에서 모듈 종료를 관리한다. 전 모듈을 미작성으로 간주한 재개발, 기존 문서/완료 경로 반복 전수 조사, 파일/테스트/패치 수 기반 진척, 새 API·UI 의미 추측, 실행 허가 추정과 날짜 약속은 채택하지 않았다. 모듈별 일정은 논리 책임을 보존하며 필요한 실제 caller 변경을 고립시키지 않는다.

범위/증거: 문서만 변경했다. 정확한 기존 WIP Plan024를 own `.ff-plan025-before`에 보관한 뒤 그 바이트 기준 diff와 새 Plan025를 기록했다(HEAD diff 아님). 2개 파일, 71 additions, 15036 bytes. Patch SHA-256 `825e8ce79aa7cd617a786e81271a690e9af4d8f8f5c1abc5eea5561609f4613d`. 패치/설명 자체는 recursive diff에서 제외한다. 현재 바이트 reverse check, preimage 디렉터리 forward check 및 diff whitespace 점검이 통과했다(기존 repository LF→CRLF 경고만 존재). 점검 후 own snapshot만 제거한다.
