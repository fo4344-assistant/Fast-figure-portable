# 20260902-012 — graph object 순수 read boundary

## 목적

Mantine graph trace/object form 이관 전에 현재 선택된 graph object를 legacy DOM이 아닌 chart/domain model에서 직접 읽는 순수 read 경계를 추가한다.

이번 패치는 write command나 EFSM event를 변경하지 않는다. 먼저 selector/read 계약만 분리하여 이후 Mantine form이 `configFromForm()`이나 native input `.value`를 source로 사용하지 않도록 준비한다.

## 변경 내용

- 앱 버전 `1.1.60-alpha` → `1.1.61-alpha`
- `selectedGraphObjectModel(slot = getSelectedSlot())` 추가
- `fastFigureUiBridge.readGraphObject()` 추가
- selector는 현재 selected slot/chart와 `selectedObjectIndex`를 읽어 선택된 `chart.editor.objects[index]`를 `projectClone()`한 snapshot으로 반환
- snapshot에는 다음 식별/표시 정보만 포함
  - `slotId`
  - `chartId`
  - `objectIndex`
  - `editable`
  - clone된 `object`

## source of truth

선택 graph object의 persisted source of truth는 계속 selected chart의 `editor.objects`다.

`selectedGraphObjectModel()` 반환 객체는 React render 한 번에 사용하는 snapshot일 뿐이며 저장 상태가 아니다.

- `object`는 `projectClone()`으로 분리한다.
- `objectIndex`는 현재 `selectedObjectIndex`를 식별하기 위한 값이다.
- `editable`은 현재 chart editor 상태에서 계산한 표시/guard 정보다.
- bridge는 snapshot을 저장하지 않는다.

React가 이후 이 snapshot을 다른 domain command의 장기 권위 상태로 사용해서는 안 된다. write 시에는 chart/object identity stale guard를 별도로 검토한다.

## read 순수성

selector에서 `ensureGraphObjects()`를 호출하지 않는다.

이 함수는 이름과 기존 사용 위치상 object 구조 보장/mutation 책임을 가질 수 있으므로 read selector에서 안전하다고 확인하지 않은 채 호출하지 않는다.

대신 다음만 수행한다.

```text
chart.editor.objects가 Array인지 검사
→ 현재 selectedObjectIndex가 정수인지 검사
→ 해당 index object 존재 확인
→ projectClone(object)
```

따라서 selector 호출만으로 chart/editor/object 배열을 보정하거나 대입하지 않는다.

## Mantine/Core 분류

Mantine 전환을 위한 DOM-free read adapter다.

변경하지 않는다.

- `configFromForm()`
- `applyGraphSettings()`
- `CHART_MODEL_REPLACED`
- graphObject EFSM region/event/action
- graph object validation/normalization
- trace 생성 알고리즘
- Plotly renderer
- CSV association 의미
- import/export
- 활성 legacy graph form

즉 이번 패치는 graph object 편집 의미를 재설계하지 않고 presentation read 경계만 추가한다.

## 이 방향을 선택한 이유

현재 남은 graph form 이관은 read와 write 모두 domain/EFSM에 가까운 영역이다. 한 패치에서 selector, Mantine form, values normalization, 전체 chart replacement까지 동시에 변경하면 회귀 원인을 분리하기 어렵다.

먼저 순수 read model을 독립 패치로 추가하면 다음 단계에서:

1. canonical object 값을 Mantine form에 표시할 수 있는지 확인
2. 필요한 선택지/CSV column read 모델이 별도로 필요한지 확인
3. write boundary가 `CHART_MODEL_REPLACED`를 그대로 재사용해야 하는지 검토
4. stale chart/object callback 조건을 독립적으로 설계

할 수 있다.

## 고려했지만 선택하지 않은 방향

### `configFromForm()`을 곧바로 values 기반으로 전면 변경

선택하지 않았다. 이 함수는 과거 기준으로 global layout, palette, object fields를 한꺼번에 조립하며 `applyGraphSettings()`의 전체 chart replacement와 연결되어 있다. `20260902-005`에서 layout만 이미 별도 경계로 분리했으므로 현재 object write 의미를 먼저 확인하지 않고 다시 큰 함수 전체를 변경하지 않는다.

### `ensureGraphObjects(chart)` 결과를 selector에서 사용

선택하지 않았다. read-side mutation 가능성을 완전히 배제하기 위해 canonical array를 직접 읽는다.

### React `useState`에 selected object 전체를 복사

선택하지 않았다. domain object와 장기 복제 상태가 생겨 source of truth가 둘로 나뉜다. 실제 input 편집 draft가 필요할 때만 명시적인 수명주기로 제한한다.

### object-level 새 EFSM event 추가

선택하지 않았다. 현재 정식 mutation 경로를 확인하기 전에 Mantine 이관을 이유로 event 의미를 추가하지 않는다.

## 회귀 위험

낮다. 새 read helper와 bridge method만 추가하고 기존 호출자는 변경하지 않는다.

확인 항목:

- graph slot + selected object에서 snapshot 반환
- selected object가 없으면 null
- image/빈 slot에서는 null
- invalid/out-of-range `selectedObjectIndex`에서는 null
- selector 호출 전후 `chart.editor.objects` identity/value 불변
- 반환 `object` 수정이 원본 object에 영향 없음
- 기존 `configFromForm()` / `applyGraphSettings()` / EFSM diff 없음

## rollback

독립적으로 되돌릴 수 있다.

1. `fastFigureUiBridge.readGraphObject()` 제거
2. `selectedGraphObjectModel()` 제거
3. 앱 버전을 `1.1.60-alpha`로 복원

다른 Mantine graph layout/axis staging이나 EFSM 변경을 함께 되돌릴 필요가 없다.

## 검증

GitHub Actions:

- 실제 `git apply`
- `git diff --check`

## 후속 작업

`012`가 적용되면 다음 단계에서 selected object 편집에 필요한 column/options read 경계를 조사한다. 그 뒤 write boundary를 별도 패치로 작성한다.

write boundary는 기존 `CHART_MODEL_REPLACED` 의미를 우선 재사용하고, 기존 command보다 작은 정식 object-level command/action이 실제로 존재하는 경우에만 그 경로를 사용한다.
