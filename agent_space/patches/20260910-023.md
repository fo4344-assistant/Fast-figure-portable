# 20260910-023 — Legacy asset-tree DOM renderer removal

## 목적
022에서 `renderProjectDataTree()`의 모든 실행 호출을 제거한 뒤 정의 1회만 남은 legacy DOM renderer와 그 전용 DOM builder helper를 삭제한다. Mantine PROJECT DATA가 사용하는 `projectDataTreeSnapshot()`/`projectDataTreeObjects()`는 데이터 projection 경계로 유지한다.

## 변경 내용
- legacy tree 전용 `ASSET_TREE_INDENT_PX`, `assetTreeDepth()`, `setAssetTreeRowDepth()` 제거.
- `appendAssetTreeItem()`, `appendAssetTreeButton()`, `createAssetTreeBranch()` 제거.
- 호출이 사라진 `renderProjectDataTree()` 전체 제거.
- `projectDataTreeSnapshot()`와 `projectDataTreeObjects()` 유지.
- Mantine slot link command인 `connectProjectAssetToSlot()` 유지.

## Source of truth 및 EFSM 영향
없음. 삭제 대상은 `#assetTree` DOM을 생성/갱신하던 presentation renderer뿐이다. asset/project 상태는 `projectObjects`, `activeProject`, `appFSM`가 계속 authority이고 Mantine tree는 snapshot projection을 직접 읽는다.

## 기각안
- legacy renderer를 hidden fallback으로 유지: 이미 interaction과 호출이 제거되어 유지 이익이 없고 두 UI 표현 구현의 divergence만 남으므로 기각.
- snapshot 함수까지 삭제하고 React 안에서 데이터 조합을 새로 작성: 동일한 projection 의미를 중복하게 되므로 기각.
- `connectProjectAssetToSlot()`까지 포함한 일괄 삭제: Mantine `/slots` drop의 기능 command이므로 기각.

## 검증
Workflow의 patch/diff check, JavaScript syntax, portable build, split/portable `file://` smoke를 통과해야 한다. Mantine PROJECT DATA가 폴더/CSV/image/slot 정보를 정상 표시하고 selection/move/import/delete/link 후 FSM subscription으로 갱신되는지 확인한다.

## 롤백
이 패치만 revert하면 legacy DOM renderer 정의와 helper만 복원되며 017/022 때문에 실행되지는 않는다. renderer 삭제만 독립적으로 되돌릴 수 있다.

## 후속
`Fast-figure.html`에서 더 이상 필요한 기능이 없는 legacy explorer markup (`assetTree`, asset action controls)을 제거하고 이에 맞춰 `REQUIRED_CONTROL_IDS`와 전용 CSS를 정리한다. 그 후 asset ownership 단위를 종료하고 다음 UI 영역으로 이동한다.
