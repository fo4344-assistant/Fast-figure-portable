# 20260906-024 — Mantine status source-of-truth split

## 목적

일반 사용자 상태 메시지를 legacy `#status` DOM에서 분리해 React/Mantine UI store가 직접 읽을 수 있게 한다.

## 이유

현재 `status(t)`는 `#status.textContent`에만 값을 저장한다. 이 구조에서는 legacy sidebar DOM이 제거되면 상태 메시지 자체가 사라지며, DOM이 사실상 source of truth가 된다.

`plan-004`는 status를 Mantine 전환 대상으로 명시하고 DOM 표시 상태를 source of truth로 사용하지 않도록 요구한다.

## 변경

- runtime UI 상태에 `uiStatusMessage`를 추가한다.
- `status(value)`는 먼저 `uiStatusMessage`를 갱신한다.
- legacy `#status`가 존재하면 동일 값을 표시하되 이는 presentation adapter로만 취급한다.
- UI external store 초기화 이후에는 status 변경만으로도 store version을 갱신한다.
- `buildFastFigureUiSnapshot()`에 `statusMessage`를 포함한다.
- Mantine sidebar에서 현재 status message를 `Text`로 직접 표시한다.
- 앱 빌드 `1.1.127-alpha` → `1.1.128-alpha`.

## 초기화 안전성

`status()`는 앱 bootstrap 초기에 호출될 수 있으므로 `fastFigureUiStoreReady` 플래그가 false인 동안에는 store publish를 수행하지 않는다. external store와 `appFSM`이 모두 초기화된 뒤에만 status-only invalidation을 발행한다.

## 보존

- status 문자열 내용과 호출 지점.
- 현재 active legacy UI의 상태 표시.
- EFSM/domain/file-format 의미.
- FFPX/FFSX schema와 roundtrip.

## 기각안

- React가 `#status.textContent`를 읽는 방식: DOM authority를 유지하므로 기각.
- status를 EFSM region으로 추가하는 방식: 지속 domain state가 아닌 사용자 피드백을 위해 EFSM을 확장할 이유가 없으므로 기각.
- 별도 전역 상태 라이브러리 추가: 기존 external store로 충분하므로 기각.

## 회귀 위험

status-only publish가 기존 FSM publish보다 한 번 더 React render를 유발할 수 있다. 그러나 사용자 피드백 변경 시에만 발생하며 source-of-truth를 분리하는 데 필요한 최소 invalidation이다.
