# 20261002-004 — source-code r1 regression diagnosis

## 목적과 변경 내용

Source Script r12에 맞춰 source-code r1을 구현하는 과정에서 남은 browser
regression 4개 실패를 수정하기 전에 원인 층위를 고정한다.

추가:

- `agent_space/docs/source-sync-regression-diagnosis-r1.md`
- 이 변경 기록 쌍

문서는 각 실패를 Source Script 의미, JavaScript 구현, 테스트 스크립트 문제로
구분하고 이후 수정 순서를 기록한다.

또한 앞으로 개발 계층 구현을 검증하는 테스트 스크립트가 target version을
명시해야 한다는 이번 작업의 적용 규칙을 기록한다.

현재 target:

- source-script r12
- verification-model r6
- source-code target r1
- app build 1.1.32-wip

## 선택 이유

코드 수정 전에 실패 원인을 상위 알고리즘 결함으로 잘못 되돌리지 않기 위해
Source Script와 현재 JS/테스트를 함께 비교했다.

검토 결과 Source Script 의미 변경은 필요하지 않고 다음 두 종류의 하위 문제로
분류됐다.

- FFSX/Plotly import 및 project-node move의 JS 구현 불일치
- candidate commit 뒤 stale object reference를 사용하는 regression assertion

따라서 상위 논리구조를 수정하지 않고 구현/테스트만 수정하는 것이 권위 순서와
최소 변경 원칙에 맞다.

## 고려했지만 선택하지 않은 방향

### Source Script 수정

선택하지 않았다.
현재 Source Script에는 FFSX local-id remap, Plotly conversion state 보존,
zero-object chart, candidate-first trash move가 이미 명시돼 있다.

### 회귀 실패를 모두 구현 문제로 간주

선택하지 않았다.
multi-CSV 및 현재 trash assertion은 authoritative project 교체 후 이전 object
reference를 검사하는 테스트 오류가 직접 원인이다.

### 테스트 오류만 수정

선택하지 않았다.
Plotly import는 FFSX-only remap을 잘못 적용하고 있으며
PROJECT_NODE_MOVED는 authoritative state를 validate 전에 직접 변경하는 실제 구현
불일치도 확인됐다.

## 후속 작업

이 문서 커밋 이후 source-code와 browser regression을 수정한다.
source-code revision/fingerprint는 전수 회귀 통과 전까지 r0/stale로 유지한다.

## rollback

문서와 이 패치 기록 쌍만 제거하면 된다.
Source Script, verification model, application source, version metadata는 이 패치에서
변경하지 않는다.
