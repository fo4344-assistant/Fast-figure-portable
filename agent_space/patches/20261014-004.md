# 20261014-004 — Bind settings resize directly to Mantine Modal.Content

## 목적과 변경 내용

Source Code r15에서 유일하게 실패한 settings Modal height resize를 수정한다.

- 편의 `Modal` component 대신 `Modal.Root / Modal.Overlay / Modal.Content / Modal.Header / Modal.Body`를 직접 구성한다.
- `Modal.Content`에 `contentRef`를 직접 연결한다.
- resize start height는 DOM ancestor 검색이 아니라 `contentRef.current`에서 읽는다.
- height style도 같은 `Modal.Content`에 직접 적용한다.
- header/title/close button과 outside/Escape close semantics는 Mantine Modal primitive를 그대로 사용한다.
- source-code revision r16, app build `1.1.36-wip`.

## 실패 근거

Fast Figure regression run `38503263005`에서 tests 1–28, 30, 31은 inline/split 모두 pass했다.

유일한 실패:

- test 29 `settings overlays share width and resize their own height`
- label modal height가 pointer drag 뒤 변하지 않음.

따라서 Tree, trash, slot drag, bookmark rerender, Layout preview aspect 수정은 유지하고 공통 Modal resize implementation만 좁게 수정한다.

## 선택 이유

resize 대상과 상태가 같은 component에서 직접 연결되므로 DOM selector/ancestor 구조에 의존하지 않는다. 공통 resize algorithm은 그대로 한 곳에 유지한다.

## 고려했지만 선택하지 않은 방향

- regression test만 완화: 실제 height가 변하지 않았으므로 기각.
- CSS `resize: vertical`만 사용: 공통 손잡이 interaction과 높이 clamp/cleanup 의미를 잃으므로 기각.
- 각 overlay마다 별도 Modal resize 구현: 중복 구현이므로 기각.
- arbitrary `.mantine-Modal-content` selector를 query: package 내부 class name 의존이므로 ref보다 열등해 기각.
