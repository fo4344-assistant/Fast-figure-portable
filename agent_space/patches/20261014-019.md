# 20261014-019 — Close Source Script persistent mutation command coverage r22

## 변경 이유

Source Code J1 구현 과정에서 Source Script r21의 projectEFSM 책임 선언과 public persistent mutation surface 사이에 command coverage 누락을 발견했다. 하위 구현에서 command를 임의 생성하지 않고 Source Script로 돌아가 보정한다.

## 변경

- `project_efsm.py`: image settings, caption settings, layout style, merge, split project command와 command coverage rule 추가.
- `layout_annotations_export.py`: 관련 persistent API mutation을 `dispatchProjectCommand` 경계로 명시.
- `api_ui.py`: 관련 public API 설명을 대응 project command와 연결.
- Source Script r22 fingerprint/closure review 갱신.
- pseudocode/verification/source-code는 stale로 전환.

## 선택 이유

명시적 mutation path, single source of truth, 계산과 mutation 분리, 중복 추상화 금지라는 일반 코딩 원칙을 동시에 만족한다. 기존 `dispatchProjectCommand`와 projectEFSM을 자연스럽게 확장하는 것이 별도 mutation layer보다 복잡도 대비 자유도가 높다.

## 기각한 방향

- Source Code에서 누락 command를 먼저 구현: 계층 권위 역전.
- public API가 activeProject를 직접 commit: projectEFSM 우회.
- 하나의 generic patch command: 서로 다른 precondition/reference/selection 의미를 감춘다.
- UI-local state까지 project command로 승격: persistent authority와 runtime state를 혼합한다.

## 이전 닫힘에서 놓친 점

r21 closure는 두 FSM의 owner 분리에 집중했고 `PUBLIC_API_METHODS`와 `PROJECT_COMMANDS`를 coverage matrix로 대조하지 않았다. 그 결과 ownership 원칙은 맞지만 concrete mutation path 일부가 닫히지 않았다.

## 후속

r22를 PlusCal pseudocode로 직접 번역하고 translation review 후 verification model/TLC를 갱신한다. TLC가 passed가 되기 전에는 Source Code를 다시 수정하지 않는다.
