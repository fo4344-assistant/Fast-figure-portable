# 20260906-021 — Mantine native asset tree staging

## 목적

`20260906-020`에서 임시로 추가한 legacy DOM compatibility host를 제거하고, 프로젝트 자산 탐색 UI를 React + Mantine component tree로 직접 렌더링하는 staging 경계로 교체한다.

## 이유

`plan-004`와 `plan-005`는 일반 UI ownership을 Mantine/React로 이동하고 legacy markup/DOM lifecycle 자체는 보존하지 않는다고 명시한다. `020`의 `FastFigureSidebarCompatibilityStaging`은 기존 `#assetTree`, status/table, palette/debug DOM node를 Mantine sidebar 안으로 이동시키는 방식이라 최종 구조와 맞지 않는다.

이번 패치는 그 우회를 더 확장하지 않고 즉시 제거한다.

## 변경

- `FastFigureSidebarCompatibilityStaging` 제거.
- `fastFigureUiBridge.readAssetTree()` 추가.
  - 기존 `projectDataTreeSnapshot(projectDataTreeObjects())` read 경계를 재사용한다.
- `fastFigureUiBridge.selectAssetPath(path)` 추가.
  - 현재 canonical VFS resolve와 기존 directory/CSV/image 선택 command를 재사용한다.
- `FastFigureAssetTreeStaging` 추가.
  - Mantine `NavLink`, `Stack`, `Text`로 `/assets` directory hierarchy, CSV/image asset, `/slots` reference summary를 렌더링한다.
  - React component가 legacy `#assetTree` DOM을 이동하거나 소유하지 않는다.
- sidebar staging에서 compatibility host 대신 Mantine asset tree를 렌더링한다.
- 앱 빌드 `1.1.124-alpha` → `1.1.125-alpha`.

## 유지되는 것

- FFPX/FFSX 파일 의미와 schema.
- project VFS/path 규칙.
- asset selection EFSM 의미.
- 기존 legacy UI는 아직 active owner이므로 현재 사용자 UI 동작은 이 패치만으로 제거하지 않는다.
- Plotly/slot/image/layout-map/label-preview renderer.

## 아직 남은 cutover blocker

Mantine asset tree를 active owner로 전환하기 전에 다음을 별도 패치로 처리한다.

1. CSV/image 선택 command의 legacy form synchronization 분리.
2. asset tree drag/drop을 React/Mantine tree host에 연결하면서 기존 VFS drop policy/execute command 재사용.
3. status/palette/debug 등 남은 일반 UI를 Mantine component로 이식.
4. 그 뒤 legacy sidebar/toolbar/overlay markup/handler/CSS 제거와 단일 owner cutover.

## 기각안

- `020` compatibility host를 유지하며 점진적으로 legacy node를 더 옮기는 안: 최종 제거 대상인 DOM compatibility 계층을 확대하므로 기각.
- asset/VFS 로직 자체를 React state로 복제하는 안: source of truth 이중화가 생기므로 기각.
- 기존 asset tree renderer를 그대로 보이게 두는 안: 일반 UI를 Mantine으로 재구성한다는 계획과 충돌하므로 기각.

## 회귀 위험

현재 React shell은 아직 staging이므로 active legacy UI 동작 위험은 낮다. 다만 staging render에서 잘못된 path/reference 계산이 있으면 향후 cutover 시 자산 표시가 달라질 수 있으므로 split/portable smoke와 후속 drag/drop/selection 검증이 필요하다.

## 롤백

이 patch만 되돌리면 `020`의 compatibility host staging으로 복귀한다. domain/file-format 변경은 없으므로 별도 데이터 migration은 필요 없다.
