# 20260901-006 — Layout values/payload 계약 분리

## 목적

`plan-003.md` Commit B의 다음 단계로, Layout 편집 경로에서 DOM control 값을 직접 읽는 부분과 실제 project/domain mutation을 분리합니다. 현재 legacy UI 동작은 유지하고, 이후 Mantine Layout Modal이 같은 mutation 경로를 사용할 수 있는 명시적 values/payload 계약을 준비합니다.

## 변경 내용

- 애플리케이션 버전을 `1.1.36-alpha`로 갱신합니다.
- `slotStyleFromValues(values)`를 추가해 reference width, gap, outer margin, radius, aspect, border 표시를 DOM과 무관하게 정규화합니다.
- 기존 `slotStyleFromControls()`는 native control 값을 모은 뒤 `slotStyleFromValues()`에 위임하도록 축소합니다.
- `applyLayoutSettingsFromValues(values)`를 추가합니다.
  - rows/columns 1~8 검증을 기존과 동일하게 수행합니다.
  - 전달받은 slot style을 정규화합니다.
  - 기존 `makeSlots()`와 `applySlotStyle(false)`를 재사용합니다.
  - 성공 여부를 boolean으로 반환합니다.
- `fastFigureUiBridge.applyLayoutSettings(values)`를 추가해 staging React/Mantine 코드가 legacy DOM을 읽지 않고 동일한 domain mutation을 호출할 수 있게 합니다.
- 기존 `applyGrid` click handler는 control 값을 payload로 만들고 `applyLayoutSettingsFromValues()`를 호출하도록 변경합니다.

## 이 방향을 선택한 이유

현재 `slotStyleFromControls()`와 `applyGrid` handler는 DOM이 값의 source처럼 보이지만 실제 영속 상태는 `activeProject.layout`입니다. Mantine 전환 중 React 쪽에서 다시 DOM ID를 참조하면 UI framework만 바뀌고 결합 구조는 그대로 남습니다.

따라서 값 정규화와 mutation을 먼저 DOM-free 함수로 분리하고, legacy handler와 미래 Mantine handler가 같은 함수를 호출하도록 합니다. 기존 `makeSlots()`와 `applySlotStyle()`의 domain/render effect는 재작성하지 않습니다.

## 고려했지만 선택하지 않은 방향

- `applySlotStyle()` 전체를 이번 패치에서 React 전용 API로 재작성하지 않습니다. 현재 dashboard/layout-map renderer effect와 native control sync가 함께 있으므로 cutover 전 대규모 변경은 회귀 위험이 큽니다.
- Mantine Layout Modal을 동시에 활성화하지 않습니다. `plan-003`의 단일 cutover 원칙을 유지합니다.
- rows/columns와 style mutation을 React component 내부에서 직접 구현하지 않습니다. mutation 경로 중복을 만들기 때문입니다.
- `slotStyleFromControls()`를 즉시 제거하지 않습니다. legacy UI가 아직 활성 상태이므로 adapter로 유지합니다.

## 검증 및 회귀 위험

- legacy `applyGrid`는 이전과 동일하게 현재 control 값으로 grid를 재구성하고 slot style을 적용해야 합니다.
- 잘못된 rows/columns는 기존과 동일한 상태 메시지를 표시하고 mutation하지 않아야 합니다.
- `applySlotStyle(false)`를 사용해 payload로 설정한 style을 native control 값으로 다시 덮어쓰지 않아야 합니다.
- staging React shell은 여전히 mount되지 않으므로 사용자 UI ownership은 변하지 않습니다.
- GitHub Actions에서 `git apply --check`, `git diff --check`, main JavaScript `node --check`를 통과해야 합니다.

## 후속 작업

다음 패치에서는 이 계약을 비활성 `FastFigureLayoutModalStaging`의 Mantine NumberInput/Switch/Button에 연결하고, 같은 방식으로 Label/Caption/Print의 값/payload 계약을 순차적으로 준비합니다. Commit B 전체 준비가 끝난 뒤에만 Commit C 단일 cutover를 수행합니다.
