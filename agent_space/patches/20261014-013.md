# 20261014-013 — Add plan 014 for selection and renderer invalidation repairs

## 목적과 변경 내용

발견된 Layout selection 및 dashboard stale projection 문제를 수정하기 위한 `agent_space/plans/plan-014.md`를 추가한다.

계획에는 다음을 포함한다.

- Layout preview/background deselection 원인과 수정 범위.
- 선행 outerMargin 기본값 0 변경의 검증 조건.
- trash move / trash empty의 renderer invalidation 누락.
- 개별 command마다 `renderDashboard()`를 추가하는 방식의 재발 위험.
- appFSM region publish가 아니라 logical event completion을 단일 renderer invalidation 경계로 사용하는 우선 설계.
- FULL_DASHBOARD / TARGETED_PROJECTION / NONE 구분.
- Source Script → PlusCal pseudocode → 필요 verification → Source Code 작업 순서와 browser regression 조건.

## 선택 이유

bookmark swap과 trash move에서 같은 state-commit 후 renderer 갱신 누락이 반복되었으므로 개별 버그 패치보다 renderer 책임 경계를 먼저 정리하는 것이 필요하다.

일반 `appFSM.subscribe()`에 full render를 연결하면 한 logical send가 여러 region publish를 만들 수 있어 중복 render가 발생할 수 있으므로 기각하고, logical event completion 1회 경계를 우선안으로 기록했다.

## 고려했지만 선택하지 않은 방향

- 발견된 두 함수에만 `renderDashboard()` 추가: 재발 방지 구조가 없어 계획의 우선 방향으로 선택하지 않음.
- 모든 mutation마다 full render: caption/image/layout style의 좁은 projection 경로를 불필요하게 파괴하므로 기각.
- region publish subscriber에서 render: logical event당 중복 render 가능성 때문에 기각.

## 관련 변경과 전제

선행 `20261014-012`에서 outerMargin 기본값 0 변경은 이미 적용되었다. 이 계획은 해당 변경을 다시 수행하지 않고 regression/lineage 확인 대상으로만 포함한다.

이 패치는 계획 문서만 추가하며 Source Script, pseudocode, verification model, application source는 변경하지 않는다.
