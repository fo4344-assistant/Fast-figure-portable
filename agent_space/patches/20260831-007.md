# 20260831-007

## 목적

`20260831-006.patch`가 GitHub Actions에서 `corrupt patch at line 127`로 거부된 전송 오류를 바로잡고, 동일한 `Fast-figure.html` 변경을 로컬에서 자동 생성·검증한 unified diff로 다시 적용한다.

## 변경 내용

- 기능 변경 내용은 `20260831-006.md`에 기록한 것과 동일하다.
- 새 패치는 현재 저장소의 `Fast-figure.html`과 로컬 후보 파일 사이에서 context 1줄의 unified diff로 다시 생성했다.
- 애플리케이션 버전 `1.1.29-alpha`, `slot.content` runtime source of truth, compatibility accessor, grid rebuild content 보존, `SLOTS_SWAPPED` EFSM action, FFPX v3 flat serialization 유지가 포함된다.

## 이 방향을 선택한 이유

첫 Actions 실행 로그에서 실패 위치가 `Check and apply patch` 단계의 `git apply --check` 이전 parse 단계였고, 메시지가 `corrupt patch at agent_space/patches/20260831-006.patch:127`이었다. JavaScript나 구현 검증 단계에는 도달하지 않았다.

따라서 코드를 다시 설계하거나 실패한 패치를 수정해 이력을 덮어쓰지 않고, 실패 기록은 그대로 남긴 채 자동 생성한 새 patch를 다음 순번으로 추가하는 것이 가장 추적 가능하다.

## 선택하지 않은 방향

- `20260831-006.patch`를 덮어쓰지 않았다. 실제 실패한 입력을 보존해야 Actions 로그와 원인을 재현할 수 있다.
- Actions를 반복 재실행하지 않았다. 같은 손상된 patch를 다시 실행해도 결과가 달라질 근거가 없다.
- 구현 코드를 변경하지 않았다. 실패는 patch 문법/전송 문제였고 로컬 후보 파일과 테스트 결과에는 문제가 확인되지 않았다.

## 검증

- 새 patch를 로컬 원본 `Fast-figure.html`에 `git apply --check`로 검증했다.
- 실제 적용 후 생성 파일이 검토한 `Fast-figure.1.1.29-candidate.html`과 byte-for-byte 일치하는 것을 확인했다.
- 적용 결과 `git diff --check`를 통과했다.
- 후보 HTML의 메인 JavaScript는 `node --check`를 통과했다.
- `slot.content` normalization/swap/FFPX v3 serialization 합성 테스트는 `20260831-006.md`에 기록한 대로 통과한 상태다.

## 패치에 포함되지 않은 변경사항

`20260831-007.patch`와 이 설명 파일 자체는 patch 본문에 포함하지 않는다.

`20260831-006.patch`의 실패 Actions run은 수정하거나 삭제하지 않고 이력으로 유지한다.
