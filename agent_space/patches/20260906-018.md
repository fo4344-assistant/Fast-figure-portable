# 20260906-018 — project I/O owner boundary

## 목적

Mantine shell owner 전환 전에 FFPX 프로젝트 import/export를 legacy `#projectName`, `#importProjectFile`, `#exportProject` DOM에서 분리하고 React/Mantine sidebar에서 동일 기능을 직접 사용할 수 있게 한다.

현재 `downloadProject()`는 `#projectName`을 직접 읽고 쓰며, 프로젝트 import는 native hidden file input의 `onchange` 안에 parsing/lifecycle 처리가 들어 있다. legacy shell을 제거하면 이 경로가 사라진다.

## 변경 내용

- 앱 버전 `1.1.121-alpha` → `1.1.122-alpha`
- `downloadProjectFromValue(projectName)` 추가
  - 프로젝트 이름 commit
  - FFPX build/zip/download
  - status/debug
  - legacy DOM 접근 없음
- 기존 `downloadProject()`는 native `#projectName` 값을 읽어 새 command를 호출하고 control 값만 다시 동기화하는 legacy adapter로 축소
- `loadProjectFile(file)` 추가
  - ZIP/JSON 판별
  - `ffpxReadProject` 또는 JSON parse
  - `importProject()` 호출
  - 오류 status/debug
  - legacy input 접근 없음
- native `#importProjectFile` onchange는 `loadProjectFile(file)` adapter로 축소
- `fastFigureUiBridge.exportProject()` / `importProjectFile(file)` 추가
  - 각각 `appFSM.run("exporting", "PROJECT_EXPORT", ...)`, `appFSM.run("importing", "PROJECT_IMPORT", ...)` 사용
- Mantine sidebar에 `FFPX 내보내기` 버튼과 `FFPX 불러오기` FileButton 추가
- 슬롯 선택 중에는 기존 policy와 동일하게 project import/export를 거부

## 의미 보존

- FFPX schema/build/read logic 변경 없음
- 프로젝트 이름 trim/길이 제한 변경 없음
- native project import/export는 기존 lifecycle wrapper와 동일한 event 이름을 유지
- React 경로도 동일 lifecycle state를 통과함

## source of truth / EFSM / core

- 프로젝트 source of truth는 `activeProject` 그대로 유지
- EFSM state/transition 변경 없음
- `PROJECT_LOADED` event 의미 변경 없음
- FFPX schema 변경 없음
- 새 React/global state 없음

## 선택하지 않은 방향

### Mantine 버튼에서 native hidden input을 click

owner 전환 후 제거될 DOM에 의존하므로 선택하지 않는다.

### FFPX parser/build를 React component로 이동

domain/file-format 책임이 UI component로 새어 나오므로 선택하지 않는다.

### project load rendering까지 동시에 변경

`applyProjectLoadedAction()`의 legacy presentation 분리는 별도 cutover blocker이며, import/export command 분리와 영향 범위가 다르므로 다음 패치에서 처리한다.

## 회귀 위험

낮음~중간.

file format 로직은 그대로 재사용하고 entry point만 분리한다. React import/export가 lifecycle을 직접 통과하므로 native lifecycle wrapper가 없어져도 동일 상태 의미를 유지한다.

Mantine project I/O controls와 bridge methods를 제거하고 `downloadProjectFromValue`/`loadProjectFile` 내용을 기존 native handlers로 되돌린 뒤 앱 버전을 `1.1.121-alpha`로 복원한다.
