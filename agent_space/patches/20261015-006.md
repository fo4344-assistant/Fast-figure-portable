# 20261015-006 — Source Script r25 PlusCal translation

## 목적

plan-016의 다음 미완료 단계인 PlusCal translation patch를 완료한다.

Source Script r25/current/closed의 Backend / Application boundary / Frontend / Portable build hierarchy와
command/query/result/lifecycle ordering을 활성 `pseudocode/**/*.pcal`에 직접 번역하고,
translation review와 development lineage를 함께 갱신한다.

## 변경 내용

- `system.pcal`: renderer에 Backend authority 대신 Application query projection과 final Frontend state를 전달한다.
- `project_state.pcal`: Backend read projection, Frontend intent validation, reconciliation query를 추가한다.
- `project_efsm.pcal`: validation/references 실패를 rejected result로 표현하고 실패 시 authority를 유지한다.
- `interface_fsm.pcal`: Backend 직접 read/resolve 및 lifecycle task callback 실행을 제거한다.
- `application_fsm.pcal`: query, validated interface event, slot-selection optional mutation, commit failure/success, reconciliation, renderer query, lifecycle task ordering을 번역한다.
- `api_ui.pcal`: public project read를 Application query에 수렴시키고 `slots.select`, `slots.swap`을 명시한다.
- `renderer_runtime.pcal`: supplied Backend projection/final Frontend state/public action만 소비하도록 변경한다.
- `graphs.pcal`: explicit slotId/chartId/csvId input과 r25 graph object value edit → existing `GRAPH_OBJECTS_REPLACED` 경로를 번역한다.
- `layout_annotations_export.pcal`: selected target을 explicit slotId로 전달하고 logical owner 경계를 반영한다.
- `assets_files.pcal`: Backend calculation과 co-located Application wrapper의 logical owner를 명시한다.
- `portable_build.pcal`: system-level packaging responsibility를 명시한다.
- translation review `review-20261015-022-pluscal-r25.md`를 추가한다.
- pseudocode를 r11/current로 갱신하고 current Source Script r25 fingerprint를 derived_from에 기록한다.

## 선택한 방향

기존 Source Script r25의 logical hierarchy와 기존 Project EFSM/FastFigureApi/Application adapter를 그대로 번역했다.

특히 Frontend를 위해 별도 ProjectObject mirror, 새 command bus, renderer용 persistent cache를 만들지 않았다.
Backend read는 transient projection이고 Frontend state는 session authority로 유지한다.

Project EFSM 실패를 PlusCal assert로 제거하지 않고 explicit rejected branch로 표현했다.
그래야 Source Script의 "실패 시 기존 authority 유지, success reconciliation 없음" 의미가 verification 단계에 남는다.

## 고려했지만 선택하지 않은 방향

- `20261015-004`처럼 일부 `.pcal`만 변경한 WIP를 남기는 방식: version checker가 modified pseudocode를 current revision으로 끝내도록 요구하고 complete translation 원칙과 맞지 않아 기각했다.
- renderer/Frontend FSM의 read-only Backend direct access 유지: plan-016 경계를 위반하므로 기각했다.
- lifecycle task를 Interface FSM에서 계속 실행: Source Script r25의 Application-owned orchestration과 달라 기각했다.
- file-drop 전용 Backend `prepareFileDrop` route 추가: r25는 기존 public slot selection action을 재사용하므로 기각했다.
- graph object value 전용 새 command 추가: 기존 `GRAPH_OBJECTS_REPLACED`가 동일 owner와 commit contract를 소유하므로 기각했다.

`sorted path + NUL + git-blob-sha1 + LF`에 적용하여 pseudocode fingerprint를 계산했고
manifest 값과 일치함을 확인했다.

정적 boundary 감사에서 다음을 확인했다.

- Interface FSM에 `ReadActiveProject` 및 Backend task 실행 없음.
- renderer에 Backend direct read, direct Project command, direct Interface event dispatch 없음.
- Application boundary에 Backend query/validation/reconciliation query와 commit failure branch 존재.
- public `slots.select` / `SLOTS_SWAPPED` 경로 존재.
- graph object value edit가 explicit chartId를 사용하고 existing commit route로 수렴.

GitHub Actions는 실행하지 않았다.
