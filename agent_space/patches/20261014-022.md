# 20261014-022 — Repair verification r21 TLA membership syntax

## 원인

verification r20의 project-command ownership invariant를 생성할 때 TLA+ membership operator `\in`의 backslash가 문자열 생성 단계에서 빠져 파일에 `in`으로 저장되었다. PlusCal translation은 성공했지만 생성된 TLA+를 SANY가 parse하지 못했다.

## 변경

- Interaction Core ownership invariant의 두 membership 표현을 `\in`으로 복구.
- Slot Core ownership invariant의 두 membership 표현을 `\in`으로 복구.
- verification revision/fingerprint를 r21로 갱신.
- 의미, 상태공간, cfg, lineage는 변경하지 않으며 TLC는 다시 pending으로 둔다.

## 선택 이유

오류가 verification expression의 문법 손실뿐이므로 상태 모델이나 Source Script/pseudocode를 변경할 근거가 없다.

## 기각

- invariant 제거: r22/r8의 command ownership 검증을 잃는다.
- Source Script나 pseudocode 수정: 상위 의미에는 오류가 없다.
- r20 결과를 passed 처리: parse 실패이므로 허용하지 않는다.
