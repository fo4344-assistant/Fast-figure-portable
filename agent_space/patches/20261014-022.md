# 20261014-022 — Split Source Script into project EFSM and interface FSM

## 변경

- `sourcescript/project_efsm.py` 추가.
- `sourcescript/interface_fsm.py` 추가.
- `sourcescript/application_fsm.py`를 혼합 ApplicationStateMachine 명세에서 두 FSM orchestration 명세로 교체.
- `selectedSlotId` ownership을 project_state에서 interface_fsm으로 이동.
- API/assets/graphs/layout/renderer/system의 책임 참조를 갱신.
- renderer invalidation을 projectEFSM commit + interfaceFSM reconciliation 이후 effect로 정의.
- Source Script r21과 fingerprint를 등록하고 하위 계층을 stale로 전환.

## 선택 이유

기존 appFSM state vector는 UI/runtime 상태였지만 persistent mutation까지 workspace region action에 결합되어 있었다. FFPX EFSM의 대상이 ProjectObject임을 기준으로 persistent transition과 interface transition을 서로 다른 state machine으로 분리한다.

activeProject를 그대로 authority로 사용하므로 별도 project-state mirror나 양방향 동기화가 필요 없다.

## 기각한 방향

- 기존 ApplicationStateMachine 이름만 ProjectEFSM으로 변경.
- activeProject 복사본을 새 EFSM state로 추가.
- legacy appFSM과 새 두 FSM을 장기간 병행.
- 모든 React local state를 interfaceFSM으로 승격.
- FFPX serialization을 EFSM state로 취급.

## 후속

H 단계에서 동일 module hierarchy를 PlusCal로 직접 번역하고, 이후 verification/TLC와 Source Code를 순서대로 갱신한다.
