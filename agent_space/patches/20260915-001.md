# 20260915-001 — Apply legacy layout DOM cleanup after failed patch attempts

## Purpose
Complete the native-layout DOM cleanup attempted by 20260914-019 through 20260914-024 without altering layout state, EFSM behavior, geometry algorithms, or export behavior.

## Failed-attempt recovery
- Patches 20260914-019 through 20260914-024 failed in the GitHub Actions `Check and apply patch` step before source modification.
- Their `.patch` and `.md` files are retained as audit history; they are not source-code residue and deleting them would remove the failure trail.
- Current `fast-figure.js` and `fast-figure-ui.js` were re-read directly before preparing this patch and still contain the legacy layout helpers/call sites targeted by those attempts.
- This patch supersedes 019–024. It removes the overlapping adjacent hunk boundary present in 024 by representing the dashboard call deletion and contiguous helper deletion as one non-overlapping hunk.

## Exact changes
- In `fast-figure.js`, stop `applySlotStyle` from projecting slot style/reference geometry to the deleted `layoutMap` DOM while preserving dashboard and dashboard-caption projection.
- Remove the obsolete dashboard `renderLayout()` refresh.
- Delete `syncPopupBounds`, `syncLayoutMapSize`, `installLayoutResizer`, and the legacy DOM `renderLayout` implementation.
- Remove the remaining project-render `renderLayout()` call.
- In `fast-figure-ui.js`, remove calls to the deleted legacy renderer from Mantine slot selection/clear-selection handling.
- Remove Mantine navbar-resize calls to `syncLayoutMapSize`; retain `schedulePlotResize()` for the actual dashboard.

## Rationale
The native layout panel DOM was already removed by earlier successful Mantine cutover patches. These functions only project existing project/layout state into DOM that no longer exists. The Mantine layout overlay reads the authoritative project state directly, while dashboard geometry/rendering remains owned by the existing core renderer.

## Rejected alternatives
- Delete or rewrite the failed 019–024 records: rejected because they are useful audit history and did not modify source.
- Retain the helpers as no-ops: rejected because this preserves a false dependency on removed DOM and keeps duplicate UI projection paths.
- Move dashboard/layout geometry into Mantine during this cleanup: rejected because geometry is shared renderer/core behavior and is outside the legacy-DOM ownership being removed.
- Modify merge/split, zoom, slot layout, EFSM, project schema, or export code in the same patch: rejected because none is required for this ownership cleanup.

## Source of truth
`activeProject.layout`, `activeProject.slots`, `layoutSelected`, and existing EFSM/project commands remain authoritative. No new persistent state or synchronization path is introduced.

## EFSM/core impact
No intended domain or EFSM behavior change. Grid/slot algorithms, `dashboardGeometry`, `gridSlotGeometry`, merge/split commands, zoom state, actual dashboard rendering, project persistence, and export rendering remain unchanged.
