# 20261013-019 — Bound interaction verification graph-object cardinality

## 발견

GitHub Actions run `38356853802`에서 interaction model은 PlusCal translation과 SANY를 통과하고 TLC 상태 탐색에 정상 진입했다.

그러나 verification harness의 `AddGraphObject`가 같은 selected CSV reference를 제한 없이 sequence에 append할 수 있어 상태공간이 유한하지 않았다.

이건 application의 graph-object 개수 제한을 의미하지 않는다. bounded model checking용 representative cardinality가 빠진 것이다.

## 변경

verification harness에:

```text
MaxGraphObjects = 2
```

를 추가한다.

`ValidProject`는 graphObjectCsvRefs 길이가 이 bound 이하인지 검사한다.

`AddGraphObject` harness transition은 현재 길이가 MaxGraphObjects보다 작을 때만 append한다.

CSV reference integrity와 slot selection semantics는 그대로 유지된다.

## bound의 의미

2개는 다음 상태를 모두 검증하기 위한 최소 representative bound다.

- graph object 없음
- 첫 selected CSV reference 추가
- 둘째 graph object 추가
- bound 도달 이후 추가 transition 거부

이는 실제 Fast Figure의 graph-object 최대 개수를 2로 제한하는 명세가 아니다.

## 계층 상태

canonical verification 변경이므로 revision은 r11, fingerprint는 `sha256:66274b5f28db2ce3ba3a509689fa2d827713ece54c71c69bbd2ce898471acf8a`로 갱신한다.

TLC 성공 전까지 stale/pending 상태를 유지한다.

이 push로 다시 GitHub Actions TLC를 실행한다. interaction module이 완주하면 그 run을 r11 validation evidence로 사용한다.
