# 20260902-052 — Mantine 슬롯별 캡션 추가 기능 이식

## 목적

`review-006.md`에서 확인한 Caption staging의 기능 누락을 보완한다.

기존 Caption UI의 `슬롯별 캡션 추가`는 단순 표시 버튼이 아니라 기존 EFSM event `SLOT_CAPTIONS_INSERTED`를 통해 현재 layout의 slot caption marker/text를 global caption에 추가하는 기능이다.

Mantine Caption Modal에도 이 기능을 이식한다.

## 변경 내용

- `insertSlotCaptionsFromCurrentLayout()` DOM-free command를 추가한다.
  - 기존 `clearAllSlotSelections()` 호출을 보존한다.
  - 기존 `SLOT_CAPTIONS_INSERTED` event를 그대로 보낸다.
  - caption text가 실제로 변경됐는지 판정한다.
  - 변경이 없으면 기존과 동일한 사용자 status를 출력한다.
  - 변경된 길이를 기존 debug event `annotation:slot-captions-inserted`에 기록한다.
  - 결과와 최신 `readCaptionEditorState()` snapshot을 반환한다.
- `fastFigureUiBridge.insertSlotCaptions()`를 추가해 Mantine UI가 command를 호출할 수 있게 한다.
- Caption staging draft 변환을 `draftFromEditor(editor)` 하나로 모아 apply/insert 후 동일 mapping을 재사용한다.
- Mantine Caption Modal에 `슬롯별 캡션 추가` Button을 추가한다.
- 버튼 실행 후 command가 반환한 canonical editor snapshot으로 local draft를 갱신한다.

## source of truth

- persisted caption state: 기존 project/domain caption object
- slot caption mode: 기존 EFSM/domain state
- insertion operation: 기존 `SLOT_CAPTIONS_INSERTED`
- React draft: Modal 내부 commit 전 편집값이며 권위 상태가 아니다.

새 persisted state를 만들지 않는다.

## 기존 UI와의 관계

이 패치에서는 legacy handler를 제거하지 않는다. staging은 아직 inactive이므로 active ownership은 여전히 legacy UI다.

후속 cutover cleanup에서 legacy handler는 같은 command를 재사용하도록 바꾸거나 legacy markup과 함께 제거할 수 있다.

## 기각한 대안

### Mantine에서 caption 문자열을 직접 조합

기각한다. 기존 `SLOT_CAPTIONS_INSERTED`의 규칙과 별도 구현이 생긴다.

### legacy `insertSlotCaptions` button click을 programmatically 호출

기각한다. Mantine 기능이 legacy DOM 존재에 의존한다.

## 파일 호환성

Caption persisted 구조나 FFPX/FFSX schema는 변경하지 않는다.

## 회귀 확인

- Actions `git apply --check`
- `git diff --check`
- application JavaScript `node --check`
- insertion 전후 caption editor snapshot이 기존 domain object를 반영하는지 확인
- staging inactive 상태에서 legacy UI 동작이 변하지 않는지 확인

## rollback

동일 번호 patch를 되돌리면 DOM-free insertion command와 Mantine button만 제거된다. 기존 EFSM event/action과 파일 구조는 그대로 남는다.
