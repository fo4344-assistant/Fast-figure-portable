# 20260902-051 — Mantine layout preview와 slot 조작 이식

## 목적

`plan-005.md`의 보존 기준에 따라 기존 Layout UI의 기능성 시각 요소와 조작 기능을 Mantine staging에 이식한다.

기존 Layout UI에서 단순 입력값 외에 다음은 사용자 기능의 일부다.

- 현재 slot 배치와 span/선택 상태를 보여주는 `layoutMap` 미리보기
- 미리보기에서 slot을 선택하는 조작
- 선택 slot 합치기
- 합쳐진 slot 나누기
- 종횡비 기본값 복귀

이들은 legacy DOM/CSS 구현 방식과 달리 제거 대상이 아니다.

## 변경 내용

- `fastFigureUiBridge`에 다음 adapter를 추가한다.
  - `renderLayoutPreview()` → 기존 `renderLayout()` 재사용
  - `mergeSelectedSlots()` → 기존 `mergeSelected()` 재사용
  - `splitSelectedSlots()` → 기존 `splitSelected()` 재사용
- `FastFigureLayoutModalStaging`에 `#layoutMap.layout-map` host를 추가한다.
- Modal이 열린 상태에서 React render 후 기존 `renderLayout()`을 다시 실행해 host에 현재 canonical layout을 그린다.
- 기존 `renderLayout()`이 생성하는 slot click handler와 `layoutSelected`를 그대로 재사용하므로 별도 React selection state를 만들지 않는다.
- 기존 합치기/나누기 기능을 Mantine Button으로 노출한다.
- 종횡비 초기화는 Mantine draft의 `aspect`를 기존 기본값 `1.618`로 되돌린 뒤 사용자가 `레이아웃 적용`으로 commit하도록 한다.
- `layoutMap`의 표시 비율은 draft aspect를 사용해 Modal 안에서 안정적으로 보이게 한다.

## 의도적으로 이식하지 않는 구현 세부

기존 `syncLayoutMapSize()`와 `layoutResize` handle은 `#layoutPanel`의 수동 위치/높이 계산에 결합되어 있다. 이를 Mantine Modal 안으로 그대로 복사하지 않는다.

- popup 위치/폭/스크롤은 Mantine Modal이 소유한다.
- preview의 domain 내용은 기존 `renderLayout()`이 소유한다.
- legacy panel 높이를 드래그해서 바꾸는 구현은 Mantine popup 크기 체계로 대체한다.

이것은 preview 기능을 제거하는 것이 아니라 popup layout lifecycle과 domain preview renderer를 분리하는 것이다.

## EFSM / domain 영향

새 domain 상태나 새 EFSM event를 만들지 않는다.

- layout canonical state: 기존 `activeProject.layout`, `activeProject.slots`
- preview selection: 기존 `layoutSelected`
- merge/split: 기존 `mergeSelected()` / `splitSelected()`
- persisted 파일 의미: 변경 없음

## 기각한 대안

### React로 layout map을 다시 구현

기각한다. 기존 `renderLayout()`이 slot span, content 표시, selection click을 이미 담당하며 재구현하면 두 renderer가 생긴다.

### legacy `syncLayoutMapSize()` / resize handle 전체 복제

기각한다. `#layoutPanel` 위치/높이 계산과 Mantine Modal lifecycle이 중복된다.

### layoutSelected를 React state로 복제

기각한다. selection source of truth가 둘이 된다.

## 회귀 확인

- Actions `git apply --check`
- `git diff --check`
- application JavaScript `node --check`
- Layout staging은 아직 inactive이므로 현재 legacy active UI에는 영향이 없어야 한다.
- FFPX/FFSX와 layout persisted schema는 변경하지 않는다.

## rollback

동일 번호 patch를 되돌리면 Mantine Layout staging의 preview/merge/split adapter만 제거된다. 기존 legacy layout renderer와 domain 함수는 변경하지 않으므로 독립 rollback이 가능하다.
