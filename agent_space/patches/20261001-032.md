# 20261001-032 — verification code r2 직접 pseudocode 번역으로 재작성

## 변경 원인

기존 r1은 Source Script의 일부 의미를 `payload/cover` 중심의 별도 상태 모델로 재구성했다.

사용자 의도는 기존 pseudocode 역할:

> 소스 스크립트를 특정 작성 문법에서 분리하고, 실행 순서와 분기, 값의 생성과 소비, 실패 경로를 검토하기 위한 정식 중간 단계

에 PlusCal/TLA+와 TLC의 실행 가능한 검증을 추가하는 것이다.

따라서 verification code는 별도 설계 모델이 아니라
Source Script의 직접 실행형 pseudocode 번역이어야 한다.

## 변경 내용

`FastFigureSlotCore.tla`를 r2로 다시 작성했다.

### Source Script 구조 보존

기존 r1의:

- `payload`
- `cover`
- 하나의 monolithic operation loop

중심 구조를 제거했다.

대신 Source Script의 slot 구조를 그대로 투영한다.

- id
- row / col
- rowSpan / colSpan
- hidden
- content.chart
- content.imageId
- content.contentType
- content.imageSettings
- caption

### 함수/호출 관계 보존

직접 대응:

- `slotHasNonDefaultLocalState`
- `buildGridResizeCandidate`
- `applySlotsResetAction`
- `applySlotsSwappedAction`
- `setLayoutApiGrid`
- `applyGridLayoutAction`
- `mergeSlots`
- `splitSlots`

grid 경로는 Source Script와 같은 관계를 유지한다.

```text
applyGridLayoutAction
→ setLayoutApiGrid
→ buildGridResizeCandidate
→ validation
→ commit / reject
```

### candidate와 실패 경로

candidate 계산을 authority 변경 전에 수행한다.

- invalid input
- unsafe shrink
- invalid candidate
- invalid merge/split request

는 `activeProject`를 변경하지 않고 rejected result로 끝난다.

r1처럼 invalid request를 단순히 disabled action으로 제거하지 않는다.
Source Script에 존재하는 reject path 자체를 verification code에서 실행 가능하게 남긴다.

### TLC harness 분리

non-default prestate를 만들기 위한 상태 생성기는:

- `VerificationHarnessSeedChart`
- `VerificationHarnessSeedImage`
- `VerificationHarnessSeedCaption`
- `VerificationHarnessSeedImageSettings`

로 별도 명명했다.

이들은 Source Script 번역 대상이 아니며 target source code에 대응하지 않는다.
TLC가 다른 Source Script module이 만들어낼 수 있는 valid prestate에서
현재 slice의 알고리즘을 실행하기 위한 test harness일 뿐이다.

### validation projection

전체 `validateProjectObjectState`를 축소판으로 재정의하지 않는다.

현재 module에서 변경되는 slot/layout/chart/image-reference projection만
`ValidateSlotLayoutProjection`으로 명시적으로 분리했다.

나머지 ProjectObject field는 이 slice에서 변경되지 않고 valid하다는 환경 가정으로 둔다.

## 검증 범위

현재 r2도 project 전체 verification code가 아니다.

이 파일이 직접 번역하는 범위는:

- slot-local ownership
- reset
- swap
- grid resize
- merge
- split
- 해당 범위의 chart/image reference와 chart exact-one-owner invariant

다른 Source Script 고수준 알고리즘은 별도 verification code module에서 직접 번역해야 한다.

## r1 대비 중요한 수정

- state model 재구성 → Source Script slot 구조 직접 사용
- domain `seed-*` action → 명시적 TLC harness로 격리
- disabled invalid action → 실행 가능한 rejected failure path
- merge/split/grid를 monolithic transition으로 합치지 않고 Source Script 함수 경계를 유지
- candidate 생성과 소비 관계를 이름과 순서로 노출
- 정상 grid shrink에서 제거될 default 1x1 slot까지 새 boundary 안에 있어야 한다고 잘못 검사하던 번역 오류 수정
