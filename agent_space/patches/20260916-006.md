# 20260916-006 — Detach active CSV tree selection from legacy graph DOM

## Purpose
Continue the graph compatibility DOM cutover by removing the native graph-editor side effects from the active Mantine asset-tree CSV selection path while preserving CSV/project selection semantics and runtime data state.

## Exact changes
Update `selectCsvFromTree(path)` so it no longer:
- writes the deleted/native `headerLines` input;
- calls `loadData(...)`, which populates native X/Y selects, native table preview, and graph-control visibility;
- calls `renderGraphObjects(...)`, which renders the native graph-object list.

Instead, after the existing `SELECT_ASSET` event, explicitly keep the runtime data state that was functionally relevant:
- `activeDataName = csv.name`;
- `activeDataReady = true`;
- `rows = csv.rows`;
- `columns = columnDefinitions(csv.rows, csv.headerLines)`.

Preserve:
- existing `CLEAR_GRAPH_OBJECT` behavior;
- project asset selection through `SELECT_ASSET`;
- file-name/status behavior;
- no-slot, image-slot, and graph-slot status semantics;
- the rule that selecting a CSV from the project tree does not silently replace an existing graph's data.

## Why this direction
`FastFigureProjectTree` is active Mantine UI and directly calls `selectCsvFromTree`. The old function therefore was not dead; it was an active Mantine-to-native-DOM compatibility bridge. The Mantine graph/data editor already renders its own table, header-line control, column selectors, object list, and graph controls directly from project/chart state. The native `headerLines`, `loadData` form projection, and `renderGraphObjects` output are not required for the active UI.

Keeping `rows` and `columns` updated preserves the pre-existing runtime data context for any remaining non-UI logic while removing only the native presentation side effects.

## Rejected alternatives
- Replace the whole function with `graphEditorSelectCsv`: rejected for this patch because that helper emits an additional `CSV_SELECTION_CHANGED` notification and would slightly change event semantics; this cutover keeps the existing asset-tree event behavior exact.
- Remove `rows`/`columns` updates entirely: rejected until all remaining legacy/core consumers of those runtime values have been audited.
- Remove `updateFileAvailability` now: rejected because it is shared with image/asset/workspace paths and needs a separate ownership audit.
- Remove `loadData`, `renderGraphObjects`, or their helper chains in this patch: rejected because other legacy callers still exist and are being audited independently.
- Change selecting a CSV to reconnect the selected graph automatically: rejected because current behavior explicitly preserves existing graph data.

## Source of truth
Project CSV objects and appFSM asset selection remain authoritative. Mantine graph/data UI reads directly from the selected project CSV/chart state. `rows` and `columns` remain temporary runtime projections, not an independent persistent source of truth.

## EFSM/core impact
No intended transition or persistence change. `CLEAR_GRAPH_OBJECT` and `SELECT_ASSET` events are preserved. CSV/project objects, graph objects, chart model, FFPX/FFSX, Plotly JSON, and renderer behavior are unchanged.
