# 20261016-005

## 목적과 변경 이유

Plan 016의 남은 경계 작업 중 image editor read/settings/targeted renderer를 하나의 ownership 단위로 전환한다. Frontend read snapshot을 persistent mutation source로 재사용하지 않고, Backend current slot-local authority에서 candidate를 만들며 Application 경유 성공 결과 이후에만 fresh renderer projection을 사용한다. 이 변경은 전체 Plan 016 완료나 Source Code `current` 승격이 아니다.

## 실제 누적 patch 범위

- 시작: `7439656689028b2868843e7c6270508d9cb972b2`.
- 종료: `6deca891c7c8a300e3a9db224cc19e7fb7e3d8a1`.
- 생성: `git diff --binary 7439656689028b2868843e7c6270508d9cb972b2 6deca891c7c8a300e3a9db224cc19e7fb7e3d8a1`.
- 실제 remote commit 간 cumulative diff이다. Application source, React edit input, regression case 39, r35 lineage metadata, Plan 016 진행 기록, review, Actions bot이 만든 inline/split distribution을 모두 포함한다. ZIP은 Git binary patch로 포함한다. 역방향 적용 시 해당 범위를 되돌릴 수 있다.
- 이 `.patch`/`.md` 자체는 종료 commit 이후 별도 Contents commits로 추가하므로 self-reference에 포함하지 않는다. Contents API는 파일별 write이며 atomic semantic commit이 아니었다. 매 write 직전 main HEAD와 대상 blob SHA/새 경로 부재를 확인했다.
- 중간 documentation upload의 CRLF 전체-file churn은 마지막 LF 재전송으로 제거했다. patch는 중간 상태의 합이 아니라 최종 remote tree와 시작 tree의 실제 차이다.

## 구현과 대안

- Backend immutable read projection으로 image editor 및 targeted renderer 입력을 제공한다. Application은 Frontend selection ID를 읽고 선언된 command를 dispatch한다. Backend는 현재 slot 설정에 새 patch만 반영해 정규화·검증·commit한다.
- React에서 `{ ...settings, ...patch }`를 유지하는 대안은 stale display snapshot을 mutation authority로 재사용하므로 배제했다.
- renderer에 live slot/image 객체를 넘기는 대안은 query/command와 rendering 경계를 다시 혼합하므로 배제했다.
- 모든 renderer/API를 이번 단위에 함께 재작성하는 대안은 검증 범위가 불필요하게 넓어지므로 배제했다. 단, 이 단위 안에서는 read/command/targeted renderer/React caller를 함께 변경하여 임시 bridge를 남기지 않는다.
