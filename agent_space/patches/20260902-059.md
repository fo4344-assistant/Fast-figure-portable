# 20260902-059 — 현재 dashboard 크기 기반 Capture command 이식

## 목적

`review-006.md`에서 확인한 Print staging의 누락 기능인 `캡처`를 Mantine에서 사용할 수 있도록 DOM-free control 경계를 만든다.

기존 capture는 화면에 표시된 dashboard의 실제 폭/높이를 읽어 저장 크기로 사용했다. 현재 target export engine은 layout/domain snapshot을 출력 크기에 맞춰 다시 렌더링하므로, 별도 capture renderer를 유지할 필요가 없다.

## 변경 내용

- `captureDashboardTargetFromValues(values, statusOut)` 추가
  - 현재 `#dashboard` renderer host의 `getBoundingClientRect().width`를 읽는다.
  - 유효한 dashboard 폭이 없으면 status에 `캡처할 그래프 영역이 없습니다.`를 표시하고 rejected 결과를 반환한다.
  - 현재 화면의 dashboard 폭을 정수 pixel width로 사용한다.
  - height는 자동 계산으로 두어 현재 layout/caption domain 의미에 맞는 전체 Figure 높이를 target exporter가 계산하게 한다.
  - DPI/format은 Mantine Print draft에서 받은 값을 그대로 기존 validation 경계에 전달한다.
  - 실제 이미지 합성/Plotly/image/caption/label export는 기존 `exportDashboardTargetFromValues()`를 그대로 재사용한다.
- `fastFigureUiBridge.captureTarget(values, statusTarget)` 추가.

## 기존 capture와의 관계

legacy capture가 별도 DOM screenshot 합성 engine을 유지하던 것은 과거 UI 구현 방식이다. 새 shell에서는 save와 capture가 같은 domain target renderer를 공유한다.

보존되는 기능 의미:

- 현재 보이는 dashboard의 pixel 폭을 즉시 출력 기준으로 사용
- 현재 layout/slot/image/chart/label/caption 내용을 저장
- Print에서 선택한 DPI/PNG/JPEG 사용
- 상태/오류 메시지 제공

구현 차이:

- height는 오래된 화면 DOM bounding-box 합성이 아니라 현재 domain layout/caption geometry에서 자동 계산한다.
- 이는 새 target export 구조와 일관되며 두 export renderer를 유지하는 복잡도를 제거한다.

## source of truth

- Figure 내용: 기존 project/domain snapshot
- 현재 캡처 폭: renderer host의 순간 geometry
- export 규칙: 기존 `exportDashboardTargetFromValues()`
- React draft: DPI/format input만 전달

## 파일 호환성

FFPX/FFSX 등 프로젝트 파일 schema와 무관한 출력 동작이며 파일 저장 구조를 변경하지 않는다.

## 기각한 대안

### legacy `exportDashboard(true)` 유지/호출

기각한다. legacy print input DOM과 별도 화면 합성 renderer에 다시 의존한다.

### Mantine에서 canvas 합성 재구현

기각한다. save와 capture renderer가 다시 분기된다.
