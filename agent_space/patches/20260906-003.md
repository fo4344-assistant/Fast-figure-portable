# 20260906-003 — split source portable build 경계 재적용

## 목적

실패한 `20260906-002`의 변경을 동일한 설계로 재적용한다.

`002`는 README diff hunk 내부의 빈 context line에 unified-diff prefix 공백이 누락되어 `git apply --check`에서 `corrupt patch`로 중단됐다. 따라서 application/source에는 아무 변경도 반영되지 않았다.

## 변경 내용

`002`와 동일하다.

- 앱 버전 `1.1.110-alpha` → `1.1.111-alpha`
- `scripts/build-portable.py` 추가
- split development source에서 `dist/Fast-figure.html` 단일-file portable build 생성
- top-level README와 built-in README의 source/portable 설명 교정
- application/EFSM/file format 의미는 변경하지 않음

## 형식 교정

이번 patch는 각 hunk의 빈 context line을 명시적인 ` ` context line으로 기록하고, hunk old/new line count를 실제 patch body에서 기계적으로 다시 계산했다.

## 검증

workflow에서 다음을 모두 통과해야 한다.

1. `git apply --check`
2. `git diff --check`
3. application/Plotly/Mantine runtime `node --check`
4. portable build 생성
5. split development source `file://` headless Chrome smoke test
6. generated portable HTML `file://` headless Chrome smoke test
7. 두 실행 모두 Plotly, FastFigureUiRuntime, FastFigureReactShell, appFSM 존재 및 lifecycle `ready`

## rollback

이 patch를 역적용하면 build script와 문서 변경, 버전 변경만 되돌아가며 `20260906-001` source split은 유지된다.
