# 20260910-025 — Supersede failed legacy asset DOM removal

## Purpose

Supersede failed patch `20260910-024` by removing the same obsolete legacy asset import/tree DOM while also removing those deleted controls from the runtime audit list that prevented `appFSM.ready()` from completing.

The compatibility boundary is explicit: FFPX/FFSX and other persisted/interchange formats remain supported; the former custom UI is not a compatibility target.

## Failure analysis of 20260910-024

`20260910-024` passed patch application, JavaScript syntax, and portable build, but the browser smoke test did not reach lifecycle `ready`.

The failure was not caused by FFPX/FFSX code. `REQUIRED_CONTROL_IDS` still required the deleted legacy controls (`assetActions`, `assetActionMenu`, `assetDownload`, `assetTree`, `file`, `filePick`). `auditApp()` therefore treated the intentional UI removal as a missing-control failure during initialization.

## Exact changes

### `Fast-figure.html`

- Remove legacy `#file` input.
- Remove the complete legacy `.asset-tree-shell` and its toolbar/tree controls.
- Keep `#fileName` temporarily because non-tree runtime helpers still write to it; it will be removed when those remaining legacy-form dependencies are converted to model/value paths.

### `fast-figure.js`

- Remove deleted asset-tree/file controls from `REQUIRED_CONTROL_IDS`.
- Remove the legacy `#filePick -> #file.click()` bridge.
- Remove the legacy `#file.onchange` import handler.
- Remove `#file` from `connectLifecycleTasksToFSM()`.

## Source of truth

`FastFigureDataActions` owns ordinary asset import through its React-owned file input and existing functional loaders. `FastFigureProjectDataTree` owns project-tree interaction from `projectDataTreeSnapshot(projectDataTreeObjects())` and `appFSM` state.

No legacy DOM bridge remains for the removed controls.

## File-format compatibility

No FFPX/FFSX implementation is changed. The patch does not alter package layout, XML/ZIP readers or writers, version identifiers, original-byte asset storage, project validation, chart/slot serialization, or import semantics.

## EFSM / core impact

None. The FSM events and project model/VFS commands used by the Mantine UI remain unchanged. The `REQUIRED_CONTROL_IDS` edit changes only the runtime audit's UI-presence expectations so that removed legacy controls are no longer treated as required application structure.

## Rationale

Once Mantine owns the UI path, requiring deleted legacy elements in `REQUIRED_CONTROL_IDS` is itself a compatibility shim. Removing the obsolete audit requirements is preferable to adding hidden placeholder nodes solely to satisfy the old UI contract.

## Rejected alternatives

- Re-add hidden placeholder controls: rejected because legacy UI compatibility is not required and placeholders would preserve a false structural dependency.
- Relax all audit checks at once: rejected; controls still used by active legacy-dependent runtime code remain required until their dependencies are removed.
- Modify FFPX/FFSX paths: rejected as unrelated.

## Validation

The replacement patch was checked locally with `git apply --check` against exact target contexts. Repository CI must pass patch application, JS syntax, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert the application commit for `20260910-025` to restore the old asset import/tree DOM, handlers, and audit requirements. File-format compatibility is unchanged by either state.
