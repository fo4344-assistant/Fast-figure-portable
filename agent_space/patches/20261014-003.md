# 20261014-003 — Stabilize Mantine Tree data identity in Source Code r15

## 목적과 변경 내용

Source Code r14 browser regression이 Chrome timeout으로 종료된 원인을 수정한다.

- `FastFigureProjectDataTree`가 부모 `useTree` controller를 유지하는 동안 매 render마다 새 `TreeNodeData` 배열을 만들던 구조를 수정.
- directory/asset canonical path 목록에서 `assetTreeRevision`을 만들고 `useMemo`로 tree data identity를 안정화.
- VFS 구조가 실제로 바뀔 때만 새 Tree data를 생성.
- `/assets` root, Mantine Tree controller, 기존 expand/selection UX는 유지.
- APP build를 `1.1.35-wip`, source-code revision을 r15로 증가.
- regression target도 r15/1.1.35-wip로 갱신.

## 실패 근거

Fast Figure regression run `38502921787`의 browser job `115653793619`은 syntax check는 통과했지만 Chrome `--dump-dom` 실행이 90초 timeout으로 종료되었다.

Mantine 9.5.2 `Tree`는 `data` identity가 바뀌면 `controller.initialize(data)`를 실행하고, `useTree.initialize`는 expanded/checked/data state를 갱신한다.

r14 구현은 controller를 부모 component가 소유하면서 tree data를 매 render 새 배열로 생성했다. 따라서 controller update가 부모 rerender를 유발하고 새 data identity가 다시 initialize를 유발하는 순환이 가능했다.

## 선택 이유

Tree hierarchy 자체를 제거하거나 `/assets` root를 없애지 않고, 실제 VFS 구조가 바뀔 때만 Tree data identity가 바뀌게 하는 최소 수정이다.

VFS authority, asset selection, drag/drop mutation path에는 변화가 없다.

## 고려했지만 선택하지 않은 방향

- `/assets` root를 Tree 밖으로 제거: 불필요한 기능 손실이므로 기각.
- 외부 `useTree` controller 제거: expansion ownership과 기존 root 초기 expanded 상태를 다시 구성해야 해 변경 범위가 커지므로 기각.
- snapshot 전체 object를 `useMemo` dependency로 사용: `readTree()`가 새 projection object를 만들 수 있어 identity 안정화 목적을 달성하지 못하므로 기각.
- deep equality를 매 render 수행: path 구조만 Tree topology에 필요하므로 과도한 비용이다.

## 후속

push 후 browser regression, development-layer check, distribution build를 다시 실행한다. browser regression이 성공하기 전까지 source-code validation review는 기록하지 않는다.
