# 20260901-014

## 목적

Print/Export 일반 UI를 Mantine으로 옮길 수 있도록 대상 내보내기 함수에서 legacy print form DOM 읽기와 정규화 결과의 form 반영을 분리한다. 실제 canvas/Plotly 렌더링과 저장 로직은 변경하지 않는다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.44-alpha`로 올린다.
- `exportDashboardTarget()`은 legacy print form을 읽고 새 values 기반 export 함수에 전달하는 adapter로 축소한다.
- `exportDashboardTargetFromValues(values, statusOut)`를 추가해 width, height, DPI, format을 전달값에서 읽는다.
- 기존 범위 규칙을 그대로 유지한다: width 100–20000 px, DPI 36–1200.
- 현재 실제 print UI와 renderer가 지원하는 형식인 PNG/JPEG만 허용하고 그 밖의 값은 PNG로 정규화한다.
- legacy form의 정규화된 width/DPI/height 반영은 adapter가 담당한다.
- export 본체는 더 이상 `printWidth`, `printHeight`, `printDpi`, `printFormat` DOM ID를 직접 읽거나 수정하지 않는다.
- 상태 출력은 기존 `textContent` sink 계약을 유지하므로 다음 Mantine staging에서 DOM이 아닌 상태 adapter를 전달할 수 있다.

## 수정된 검증 근거

최초 큐의 patch는 검색 결과에서 얻은 축약된 export 문맥을 현재 원문으로 오인하여 적용되지 않았다. Actions 로그에서 실패 지점이 export hunk 하나임을 확인했고 HTML에는 아무 변경도 적용되지 않았다.

재작성 시 저장소에 제공된 `Fast-figure_v1-1-27-alpha` 원문의 `exportDashboardTarget()`을 직접 확인했다. 현재까지의 후속 Mantine 패치들은 export renderer를 수정하지 않았으므로 해당 본문의 `rasterScale`, `bordersVisible`, `visibleSlots`, 36 DPI 하한, PNG/JPEG 형식 계약을 보존해 diff를 다시 생성했다.

## 이 방향을 선택한 이유

Print 전환에서 필요한 것은 export renderer 재작성이나 EFSM 재설계가 아니라 UI 입력 소유권 분리이다. 래스터 제한, 캡션 높이 검사, Plotly 렌더링, 이미지 인코딩, debug log는 기존 구현을 그대로 재사용한다.

## 선택하지 않은 방향

- export renderer를 React component 내부로 이동하지 않는다.
- 지원하지 않는 WebP/PDF 형식을 이번 migration에서 새로 추가하지 않는다.
- 현재 활성 legacy print modal을 제거하지 않는다.
- 전체 shell cutover를 이 커밋에서 수행하지 않는다.

## 검증 항목

- `git apply --check`
- `git diff --check`
- 메인 JavaScript `node --check`
- APP_BUILD와 built-in README 버전 일치
- legacy export 호출 경로 유지
- values 기반 export 본체에서 print form DOM ID 참조 제거
- PNG/JPEG 및 기존 size/DPI 범위 유지
- PACKAGE_FORMAT_VERSION 3 유지

## 패치에 포함되지 않은 변경사항

이 `.patch`와 설명 `.md` 자체는 재귀적인 diff에 포함하지 않는다. 실제 HTML 수정은 제한된 patch workflow가 검증 후 적용한다.
