# 20260901-014

## 목적

Print/Export 일반 UI를 Mantine으로 옮길 수 있도록 대상 내보내기 함수에서 legacy print form DOM 읽기를 분리한다. 실제 캔버스/Plotly/PDF 렌더링과 파일 저장 로직은 변경하지 않는다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.44-alpha`로 올린다.
- 기존 `exportDashboardTarget()`은 legacy form 값을 읽어 새 values 기반 함수로 전달하는 adapter로 축소한다.
- `exportDashboardTargetFromValues(values, statusOut)`를 추가하고 width, height, DPI, format을 전달값에서 읽도록 한다.
- format은 현재 UI가 지원하는 `png`, `jpeg`, `webp`, `pdf`만 허용하고 나머지는 `png`로 정규화한다.
- 기존 범위 제한을 유지한다: width 100–20000 px, DPI 72–1200.
- 상태 출력은 기존 `textContent` 계약을 유지해 legacy DOM과 Mantine status adapter 모두 같은 export 엔진을 사용할 수 있게 한다.
- `fastFigureUiBridge.exportTarget(values, statusTarget)`를 추가한다.

## 이 방향을 선택한 이유

Print 전환에서 필요한 것은 저장 엔진 재작성이나 EFSM 재설계가 아니라 UI 입력 소유권 분리이다. 기존 렌더링 경로에는 래스터 크기 제한, caption 높이 검사, Plotly 렌더링, PDF/이미지 인코딩 등 이미 검증된 도메인 동작이 있으므로 그대로 재사용한다.

status를 특정 React 상태 API에 결합하지 않고 `textContent` 형태의 작은 sink 계약으로 유지하면 legacy DOM은 그대로 동작하고 Mantine staging에서는 setter adapter만 제공하면 된다.

## 선택하지 않은 방향

- export renderer를 React component 내부로 이동하지 않는다.
- canvas/Plotly/PDF 코드를 다시 작성하지 않는다.
- 현재 활성 legacy print modal을 제거하지 않는다.
- 전체 shell cutover를 이 커밋에서 수행하지 않는다.
