# 20260907-041 — Mantine 데이터 호출 UI 추가

## 목적

`plan-006`의 직접 포팅 순서에 따라 sidebar의 데이터 호출 UI를 Mantine으로 옮긴다. 이번 patch는 데이터 추가 버튼과 선택 슬롯의 그래프/이미지 유형 토글만 구현한다.

## 변경 범위

변경 대상은 `fast-figure-ui.js` 하나뿐이다.

- Mantine `AppShell.Navbar`를 추가한다.
- 선택 슬롯이 있을 때 `그래프` / `이미지` Mantine 버튼을 표시한다.
- 슬롯 유형 버튼은 기존 `setSlotContentType("graph" | "image")`를 직접 호출한다.
- `데이터 추가` 버튼은 기존 native file input `#file`을 연다.
- 기존 FFPX Mantine 버튼은 같은 Navbar 안의 프로젝트 영역에 유지한다.

## 유지되는 기존 경로

`fast-figure.js`는 수정하지 않는다.

- `setSlotContentType()` 내부의 `appFSM.send("SLOT_TYPE_CHANGED", ...)` 경로 유지
- `#file.onchange`와 `connectLifecycleTasksToFSM()`의 `ASSET_IMPORT` lifecycle 경로 유지
- project model, ApplicationStateMachine, APP_STATE_DEFINITIONS, import parser, asset creation 로직 유지

즉 Mantine은 기존 기능 경로의 호출 UI만 추가하며 EFSM 기능 핵심을 변경하지 않는다.

## 하지 않는 변경

- legacy button `.click()` 호출 bridge 추가 안 함
- asset delete/reset 추가 안 함
- confirm/collision UI 변경 안 함
- file import handler 추출 안 함
- UI FSM/EFSM/project model 수정 안 함
- legacy UI cutover 안 함

## 이유

현재 데이터 추가는 hidden native file input이 실제 파일 선택 boundary이고, slot type 변경은 이미 `setSlotContentType()`가 기존 EFSM event를 발행한다. 따라서 새 domain helper나 bridge 없이 Mantine component를 직접 연결할 수 있다.

## 기각한 대안

1. legacy `#filePick` 버튼을 `.click()`하는 방식
   - 제거 대상 UI를 내부 API처럼 사용하므로 기각.
2. 새 asset-import command를 추출하는 방식
   - 현재 단계에서는 필요하지 않으며 EFSM/기능 핵심 변경 범위를 불필요하게 넓히므로 기각.
3. delete/reset까지 한 번에 옮기는 방식
   - 확인창 lifecycle을 Mantine Modal로 함께 이식해야 하므로 별도 patch로 분리.

## rollback

이 patch를 revert하면 `fast-figure-ui.js`의 `FastFigureDataActions`, `openDataPicker`, Navbar 추가만 제거된다. `fast-figure.js`에는 변경이 없으므로 기능 핵심 rollback은 필요 없다.
