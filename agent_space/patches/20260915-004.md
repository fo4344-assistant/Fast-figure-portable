# 20260915-004 — Detach active Mantine annotation paths from removed native DOM

## Purpose
Repair two active annotation paths that still project into native controls removed during the Mantine cutover, before deleting the remaining dead native annotation helpers.

## Exact changes
- In the Mantine label overlay, stop calling the legacy `renderLabelPreview()` DOM projector when label settings change. The React preview already renders directly from `activeProject.labelSettings` and the authoritative slot geometry.
- In `applyCaptionSettings`, perform legacy caption-control writeback only when `fromControls === true`. Mantine calls `applyCaptionSettings(false)`, so its settings path now updates the actual dashboard caption and emits the existing notification without touching removed `captionName`, `captionFontFamily`, `captionFontSize`, or `captionLineHeight` elements.
- Preserve dashboard label rendering, dashboard caption rendering, project state mutation, notification events, and export state.

## Rationale
The native label/caption editor markup has already been removed, while the Mantine overlays own those controls. Leaving active Mantine code dependent on `labelPreview` or native caption inputs can cause null-DOM failures even though syntax/build smoke tests pass. This patch severs only those active dependencies; the dead helper implementations are removed separately so this repair remains small and independently rollbackable.

## Rejected alternatives
- Recreate hidden native label/caption controls: rejected because that would restore duplicate UI ownership and hidden synchronization state.
- Make `$()` return dummy controls: rejected because it would conceal invalid dependencies globally and weaken error detection.
- Fold label/caption rendering into React: rejected here because actual dashboard labels/captions are renderer output shared with export/layout behavior, not editor chrome.
- Delete every annotation helper in the same repair patch: deferred to the next ownership-cleanup patch so the active-path repair can be validated independently.

## Source of truth
`activeProject.labelSettings`, caption project state, slot geometry, and existing EFSM notifications remain authoritative. React owns editor/preview UI; `renderDashboard()` and `syncDashboardCaption()` own actual figure rendering.

## EFSM/core impact
No domain, persistence, schema, label-order, caption-content, or export behavior change is intended. Existing `LABEL_*` and `CAPTION_SETTINGS_CHANGED` notifications are preserved.

## Validation
Run patch check/apply, JavaScript syntax checks, portable build, and split/portable Chromium `file://` smoke tests. After application, Mantine label setting changes must no longer call `renderLabelPreview`, and `applyCaptionSettings(false)` must not dereference removed native caption controls.

## Rollback
Revert `Apply agent patch 20260915-004`. If rolled back after native annotation helper deletion, also roll back the later cleanup patch because this patch establishes the active-path separation required by that deletion.

## Follow-up
Remove the now-dead native label preview/settings functions, native caption settings installer, annotation popup installer, and annotation-control synchronization projections; then verify no removed annotation DOM identifiers remain in executable JavaScript.
