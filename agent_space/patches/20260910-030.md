# 20260910-030 — Remove retired asset-tree MIME handling from dashboard

## Purpose

Remove dashboard drag/drop branches that still depend on the deleted legacy asset-tree transfer format. Legacy UI compatibility is not retained; file-format compatibility such as FFPX/FFSX/Plotly is outside this patch and remains unchanged.

## Exact changes

### `fast-figure.js`

- Remove `ASSET_TREE_DRAG_TYPE` probing from the dashboard `dragover` handler.
- Remove decoding/validation of legacy asset-tree payloads from that handler.
- Remove the corresponding legacy-internal branch from the dashboard `drop` handler.
- Keep external file drop behavior unchanged.
- Keep dashboard slot-to-slot drag/move behavior unchanged.

## Rationale

The legacy explorer producer and `ASSET_TREE_DRAG_TYPE` constant have already been removed. The dashboard still referenced that symbol, so evaluating the affected drag path could raise a `ReferenceError` even though syntax/build checks pass.

The Mantine project-data tree owns current project-node dragging with React-local drag state and its own project-asset-to-slot drop handlers. Reintroducing the retired MIME bridge would preserve obsolete UI compatibility rather than simplify ownership.

## Source of truth

- Project/file state: `appFSM`, project objects, and `projectVfs`.
- Project-data tree interaction: Mantine `FastFigureProjectDataTree`.
- Dashboard interaction: dashboard slot handlers for external-file drops and slot moves.

## EFSM / core impact

None. No project mutation action, transition table, model schema, graph/image algorithm, serializer, parser, or file package code is changed.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, CSV, image serialization, package version, import, or export behavior is modified.

## Rejected alternatives

- Restore `ASSET_TREE_DRAG_TYPE`: rejected because it would recreate a compatibility layer for a deleted UI.
- Emit the retired MIME payload from Mantine: rejected because Mantine should call current project/slot commands directly rather than translate through legacy DOM-era transport.
- Rewrite external-file and slot-swap drag handling in the same patch: rejected because those active dashboard behaviors are independent of the retired tree path.

## Validation

Repository CI must pass patch application, JavaScript syntax checks, portable build, and split/portable Chromium `file://` smoke tests.

Manual regression focus: external files still drop onto dashboard slots; dashboard slot-to-slot movement still works; project assets are moved/linked through the Mantine project-data tree rather than the retired dashboard MIME bridge.

## Rollback

Reverting this patch restores only the old dashboard consumer branch. A functional legacy bridge would additionally require restoring the earlier deleted MIME constant/producer, so rollback should only be used for diagnosis.

## Follow-up

Continue removing legacy data-panel markup, `REQUIRED_CONTROL_IDS`, CSS, and DOM synchronization where Mantine already owns equivalent UI. Do not touch FFPX/FFSX/Plotly file compatibility code as part of that cleanup.
