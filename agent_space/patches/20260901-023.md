# 20260901-023 — Mantine 슬롯 콘텐츠 유형 staging control

## 목적과 변경 내용

`plan-003.md`의 Commit B를 이어서 inactive `FastFigureSidebarStaging`에 슬롯 콘텐츠 유형(`graph` / `image`)을 선택하는 Mantine `SegmentedControl`을 추가한다.

- 선택된 슬롯이 있으면 기존 `selectedSlot.contentType`을 표시한다.
- 선택된 슬롯이 없으면 기존 `pendingSlotContentType`을 표시한다.
- 쓰기는 새 상태를 만들지 않고 기존 `setSlotContentType(type)` 경로를 호출한다.
- 선택된 슬롯이 있는 경우 기존 `SLOT_TYPE_CHANGED` EFSM 전이를 그대로 사용한다.
- 슬롯이 없는 경우 기존 `pendingSlotContentType` 변경 뒤 React external store에 renderer invalidation만 발행한다.
- 앱 버전을 `1.1.52-alpha`로 올린다.

## source of truth 검토

이 패치는 상태의 권위를 추가하지 않는다.

- 선택된 슬롯의 콘텐츠 유형 source of truth: 기존 slot/domain model의 `contentType`.
- 새 슬롯 기본 콘텐츠 유형 source of truth: 기존 `pendingSlotContentType`.
- `buildFastFigureUiSnapshot()`의 값은 렌더 시 읽기 위한 snapshot일 뿐이며 별도 권위 상태로 사용하지 않는다.
- Mantine `SegmentedControl`은 React local state를 만들지 않고 매 렌더마다 현재 snapshot 값을 직접 표시한다.
- bridge가 호출하는 `publishFastFigureUiStore(...)`는 `pendingSlotContentType`을 복제하지 않고 구독자에게 다시 읽으라는 invalidation 신호만 보낸다.

따라서 어느 복사본이 최신인지 판정하거나 두 상태를 동기화하는 경로가 생기지 않는다.

## 이 방향을 선택한 이유

기존 `setSlotContentType(type)`은 이미 필요한 두 의미를 분리하고 있다.

- 슬롯 선택 상태: `appFSM.send("SLOT_TYPE_CHANGED", ...)`를 통한 기존 EFSM 경로.
- 슬롯 미선택 상태: 새 슬롯 생성 전에 사용할 `pendingSlotContentType` 갱신.

Mantine migration 때문에 이 도메인 의미를 다시 설계할 이유가 없다. 필요한 것은 staging renderer가 같은 명령을 호출할 수 있는 얇은 bridge와, EFSM 이벤트가 발생하지 않는 pending 변경 시 React가 새 값을 다시 읽도록 하는 invalidation뿐이다.

## 고려했지만 선택하지 않은 방향

### React local state에 콘텐츠 유형 저장

선택하지 않았다. `slot.contentType` 또는 `pendingSlotContentType`과 같은 의미를 두 번째 상태가 소유하게 되어 source of truth 원칙을 위반하고 동기화가 필요해진다.

### `pendingSlotContentType`을 새 EFSM region/state로 이동

선택하지 않았다. 현재 동작은 새 슬롯 생성 전 기본값이라는 기존 도메인 의미로 이미 안정적으로 사용되고 있으며, Mantine renderer 연결만을 위해 EFSM 의미를 확대하면 migration 범위를 벗어난다.

### `syncSlotContentTypeUi()`의 파일 선택기/패널 표시까지 동시에 React로 이동

선택하지 않았다. 해당 함수는 콘텐츠 유형 표시 외에도 file accept, CSV/image panel, preview 등 legacy renderer 부작용을 함께 가진다. Commit B에서는 새 shell 준비만 하고, 활성 legacy UI와 renderer adapter 제거는 Commit C/D 경계에서 수행한다.

### bridge가 콘텐츠 유형 복사본을 보관

선택하지 않았다. bridge는 읽기/명령 경계일 뿐 상태 저장소가 아니어야 한다.

## 후속 작업 / 범위 밖

- legacy `slotTypeGraph` / `slotTypeImage` 버튼과 `syncSlotContentTypeUi()`는 아직 활성 UI에서 필요하므로 제거하지 않는다.
- staging shell은 계속 비활성 상태다.
- file picker와 CSV/image 설정 panel의 Mantine form migration은 후속 Commit B 작업에서 기존 도메인 계약을 확인한 뒤 진행한다.
- Commit C 이전에는 사용자에게 보이는 UI 소유권을 부분 전환하지 않는다.
