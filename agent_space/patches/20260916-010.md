# 20260916-010 — Eliminate the remaining shared CSV-selection mirror

## Purpose
Continue the SoT/API-boundary repair from `review-011-sot-api-boundary.md`, `20260916-008`, and `20260916-009` by removing the remaining shared `activeCsvId` runtime mirror.

After `009`, logic-EFSM/domain mutation paths no longer maintain `activeCsvId`, but the variable is still written by graph workspace activation, data connection/load paths, runtime rollback snapshots, and the legacy native graph-object selector. That leaves a second representation of "current CSV" beside the authoritative project data and asset-selection state.

This patch removes that shared mirror completely without mixing in the separate cleanup of `activeDataName`, `activeDataReady`, `rows`, or `columns`.

## Ownership decision

- CSV objects and their identity/content are owned by project/domain state (`activeProject.csvFiles`).
- Project asset selection is owned by the application logic EFSM (`assetSelection` / `assetPath`) and is changed through `SELECT_ASSET`.
- A graph object owns its own CSV reference through `object.csvId`.
- `activeCsvId` is neither a project/domain SoT nor a distinct editor SoT; it duplicated information that can be read from those authoritative sources.
- A buffer/cache may not be given independent cross-subsystem meaning merely because it is convenient to keep in memory.

## Exact changes

### `fast-figure.js`

1. Remove the global `activeCsvId` variable.
2. Convert `refreshCsvControls()` from a mirror-maintenance function into a compatibility read-through that resolves the current authoritative selected project CSV and returns the project CSV object without storing any state.
   - This function remains temporarily because several legacy/UI lifecycle callers still invoke it; it no longer owns, mutates, or synchronizes selection state.
3. Remove the `activeCsvId` write from `connectDataToSlotModel()`.
   - The connection already receives an explicit project CSV and graph objects persist their `csvId`; no shared current-CSV mirror is needed.
4. Remove `activeCsvId` assignment and refresh from `activateChartModel()`.
   - The function may still populate the separate legacy native graph UI buffers (`activeDataName`, `activeDataReady`, `rows`, `columns`) until that ownership unit is removed, but it no longer publishes a cross-subsystem CSV-selection mirror.
5. Remove `activeCsvId` from project runtime capture/restore/reset snapshots.
   - Rollback must not treat a cache/projection as authoritative runtime state.
6. Remove `activeCsvId` from `loadDataFile()` rollback bookkeeping and remove the now-unnecessary CSV mirror refresh after import.
7. In the legacy native `selectGraphObject()` path, replace the direct `activeCsvId` write with `graphEditorSelectCsv(csv.id)` so any user-driven CSV selection goes through the existing selection command/router and ultimately `SELECT_ASSET`.

### `fast-figure-ui.js`

When no graph object is explicitly selected, derive the graph editor's displayed CSV from the first graph object's persisted `csvId` before falling back to project asset selection or the first project CSV.

This preserves the previous practical behavior of opening an existing chart around its own data source without reintroducing a shared `activeCsvId` mirror.

## Why this direction

The previous structure could represent the same CSV context in several places:

```text
project CSV objects / graph object csvId
logic-EFSM assetPath
activeCsvId mirror
```

`008` and `009` removed active use of the mirror from the Mantine read path and logic-EFSM mutation path. Leaving the variable alive in workspace/load/rollback code would still create a synchronization obligation and allow later code to accidentally treat it as authoritative again.

The corrected direction is:

```text
project/domain CSV SoT
       ^
       | explicit csvId reference
 graph object

logic-EFSM asset-selection SoT
       ^
       | SELECT_ASSET command/router
 frontend selection intent
```

Derived UI context is read from those sources when needed instead of being stored in a second global variable.

## Rejected alternatives

- Keep `activeCsvId` but synchronize it more carefully with `assetPath`: rejected because this preserves duplicate state and synchronization obligations.
- Promote `activeCsvId` to a new editor SoT: rejected because current behavior does not require an independent persistent editor selection; graph objects already identify their CSV and project asset selection already represents explicit CSV-selection intent.
- Remove `activeDataName`, `activeDataReady`, `rows`, and `columns` in the same patch: rejected because those values still belong to the legacy native graph-data/form ownership unit and must be cut coherently with their remaining consumers.
- Delete `refreshCsvControls()` immediately: deferred because some legacy/UI lifecycle callers still invoke it. In this patch it becomes stateless read-through only, so it no longer violates the cache/SoT rule; deletion can occur with the remaining legacy graph UI cleanup.
- Make `activateChartModel()` write `SELECT_ASSET` automatically: rejected because chart activation and explicit project-asset selection are not necessarily the same user intent. The graph editor can derive its chart CSV from `object.csvId` without mutating the asset-selection SoT.

## SoT status after this patch

After this patch:

- there is no `activeCsvId` global;
- graph CSV references are read from project/chart state;
- explicit project CSV selection continues through `SELECT_ASSET` / `assetPath`;
- runtime rollback no longer saves/restores a CSV-selection cache;
- the active Mantine graph editor derives its default CSV from the chart object before project-selection fallback.

Remaining SoT debt is intentionally separate:

- `activeDataName`;
- `activeDataReady`;
- global `rows` / `columns` native graph-data buffers;
- image-side mirrors `activeImageId` / `activeAssetKind`.

These must be audited next under the same rule: any surviving UI draft/buffer must stay inside its UI ownership scope and must not be consumed by backend/core logic.

## EFSM/core impact

No logic-EFSM event contract, project schema, chart schema, renderer algorithm, or export behavior is changed.

Preserved:

- `SELECT_ASSET`, `assetSelection`, and `assetPath` semantics;
- project CSV persistence;
- graph object `csvId` references;
- slot-data connection semantics;
- project import/load rollback semantics apart from removal of non-authoritative cache state;
- Mantine graph object editing and data-source selection.
