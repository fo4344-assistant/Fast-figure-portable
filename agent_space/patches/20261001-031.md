# 20261001-031 — verification code 직접 번역 원칙 명시

## 변경 요구

사용자가 PlusCal/TLA+ 단계의 역할을 다음처럼 명확히 했다.

```text
Source Script
-> verification code
-> source code
```

verification code는 Source Script를 재구성한 별도 설계 모델이 아니다.
Source Script의 고수준 알고리즘을 직접 실행형 코드로 번역해
일반 컴파일러가 잡기 어려운 전역 상태·순서·불변식 문제를 추가로 검사하는 단계다.

## 변경 내용

정책을 v0.2.2로 갱신했다.

핵심 규칙:

- verification code는 Source Script의 하위 표현이며 독립 설계 권한을 갖지 않는다.
- Source Script의 책임/알고리즘을 검증하기 좋게 다시 분류·재구성하지 않는다.
- TLA+ 문법을 위한 기계적 표현 변환은 허용하지만 원래 state/action/branch/reference/failure 의미를 추적 가능하게 유지한다.
- Source Script와 verification code의 의미가 충돌하면 verification code의 번역 오류로 판정한다.
- Source Script를 verification code에 맞춰 수정하지 않는다.
- TLC 반례가 나오면 먼저 번역·추상화·environment assumption의 충실도를 확인한다.
- 번역이 정확한 상태에서 동일 반례가 Source Script 알고리즘의 직접 결과로 재현되는 경우에만 Source Script 자체의 논리 문제로 별도 처리한다.
- verification code는 compiler가 이미 잘 잡는 항목을 반복하기보다 compiler가 놓치는 상태 조합·순서·invariant 문제를 검사한다.

## 선택 이유

verification 단계에서 Source Script를 재구성하면
두 번째 설계 단계가 생기고, 어느 쪽이 실제 명세인지 다시 판정해야 한다.

직접 번역 관계를 강제하면:

- Source Script가 유일한 고수준 설계 원천으로 남고
- verification code는 그 의미의 실행 가능성만 검사하며
- source code는 검증된 고수준 알고리즘에 target-specific 저수준 구현만 추가하게 된다.

## 고려했지만 선택하지 않은 방향

### verification code를 독립적인 더 좋은 상태 모델로 재설계

선택하지 않았다.

Source Script와 별도 의미 구조가 생겨 상호 drift와 역수정이 발생한다.

### TLC 반례가 나오면 바로 Source Script 수정

선택하지 않았다.

반례가 verification translation이나 abstraction 오류일 수 있으므로
먼저 Source Script와의 충실도를 확인해야 한다.

### Source Script와 verification code 충돌을 양쪽 비교로 해결

선택하지 않았다.

권위는 Source Script에 있으므로 semantic mismatch는 verification code 오류다.

## 현재 프로젝트 영향

정책만 변경한다.

현재 `verification/FastFigureSlotCore.tla` r1은 이전 해석으로 작성되었으므로,
후속 작업에서 Source Script의 직접 번역 규칙을 기준으로 재검토해야 한다.
이번 패치에서는 verification code 자체를 수정하지 않는다.
