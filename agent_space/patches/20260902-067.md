# 20260902-067 — graph editor editable 전환 DOM-free command

## 목적

`review-007`에서 확인한 Mantine graph file/action 누락 중 `원본 JSON` / `편집 가능` 전환을 먼저 공통 command로 분리한다.

현재 legacy `#editorEditable` click handler는 imported Plotly를 editable project CSV-backed graph로 전환하는 domain 작업과 native form 동기화를 한 함수 안에서 수행한다. 이 상태에서는 Mantine control이 기능을 재사용할 수 없다.

## 변경 내용

- 앱 버전 `1.1.99-alpha` → `1.1.100-alpha`
- `setGraphEditorEditableFromValue(editable, expectedChartId)` 추가
- command가 담당하는 기능:
  - stale chart guard
  - editable=true 전환 시 CSV가 없는 imported Plotly의 conversion rows를 project CSV로 생성
  - graph object `csvId` 연결
  - temporary conversion rows 정리
  - `activeCsvId` / `activeDataName` 갱신
  - `chart.editor.editable` 변경
  - editable graph rebuild
  - dashboard render
  - 기존 status/debug 의미 유지
  - `publishFastFigureUiStore(...)`로 React external-store invalidation
- legacy `#editorEditable` handler는 공통 command를 호출하고, command가 새 CSV를 만든 경우에만 기존 native `headerLines`, `loadData`, `setFileName`, `refreshCsvControls` 표시 동기화를 수행한다.
- legacy `syncEditableUi()`는 presentation adapter로 유지한다.

## source of truth

- editable source: `chart.editor.editable`
- generated CSV: project CSV model
- graph object CSV relation: `chart.editor.objects[*].csvId`
- React/local DOM state는 persisted source가 아니다.

## Mantine/Core 판정

기능 의미는 변경하지 않는다. legacy button 안에 섞여 있던 기능 mutation과 DOM synchronization을 분리하는 adapter 정리다.

Plotly conversion 알고리즘, FFSX schema, graph object schema, trace renderer는 변경하지 않는다.

## UI invalidation

이 전환은 기존 EFSM event를 발생시키지 않는 domain-only mutation이므로 `20260901-020`에서 검증된 `publishFastFigureUiStore(state, event)`를 재사용한다. UI 갱신을 위해 새 EFSM event를 만들지 않는다.

## 구버전 UI와의 차이

legacy native form의 `loadData()` 호출은 command 완료 후 wrapper에서 수행된다. persisted graph/CSV 의미는 동일하다. Mantine cutover 후에는 native `xCol/yCol` option 동기화가 필요하지 않으므로 이 표시 adapter는 제거 가능하다.

## 회귀 위험

중간 수준.

확인 항목:

- imported Plotly → editable 전환 시 CSV가 한 번만 생성되는지
- 기존 CSV가 있는 chart는 새 CSV를 만들지 않는지
- object csvId가 생성 CSV를 가리키는지
- editable=false 전환 시 원본 Plotly 표시 의미 유지
- legacy native graph form이 전환 후 계속 동기화되는지
- Mantine external store가 변경을 다시 읽을 수 있는지
- FFSX/Plotly import/export 형식에 diff가 없는지

## 기각한 방향

### Mantine에서 legacy `#editorEditable.click()` 호출

legacy DOM을 기능 API로 유지하므로 기각한다.

### 새 EFSM event 추가

UI migration 때문에 domain EFSM 의미를 확장할 필요가 없어 기각한다.

### Plotly conversion 로직 재작성

기존 검증된 변환을 그대로 재사용한다.

## rollback

1. `setGraphEditorEditableFromValue()` 제거
2. legacy click handler에 기존 inline body 복원
3. 버전 문자열 복원

독립 롤백 가능하다.
