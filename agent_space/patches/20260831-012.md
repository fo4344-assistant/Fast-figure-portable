# 20260831-012

## 목적

Mantine vendoring v3 workflow가 실제 GitHub Actions workflow로 인식되도록 실행 가능한 `.yml` workflow를 추가하고, 일반 문서/리뷰 패치 기록에서 기존 HTML patch 적용 job이 불필요하게 runner를 사용하지 않도록 제한한다.

## 변경 내용

- `.github/workflows/vendor-mantine-runtime-v3.yml`을 추가한다.
- `Apply Fast Figure patch` job에 commit-message guard를 추가한다.
- `Queue Fast Figure HTML patch`로 시작하는 명시적 HTML patch 요청에서만 해당 job을 실행한다.
- v3 builder가 성공하면 실제 React/Mantine runtime 변경을 `20260831-013.patch/.md`와 함께 별도 커밋한다.

## 이 방향을 선택한 이유

GitHub Actions는 `.github/workflows` 아래의 `.yml` 또는 `.yaml` 파일을 workflow로 인식한다. 앞서 만든 `.json` 파일은 실행되지 않았으므로 실제 workflow는 `.yml`로 추가해야 한다.

또한 모든 저장소 변경에 patch pair가 포함되는 현재 규칙에서는 `agent_space/patches/*.patch` 경로만으로 HTML 적용 여부를 구분할 수 없다. job-level guard를 두면 일반 patch 기록에서는 runner job을 실행하지 않고, 실제 HTML diff 적용 시에만 명시적으로 사용할 수 있다.

## 고려했지만 선택하지 않은 방향

- patch 파일명에 기능명을 넣지 않는다. 기존 `YYYYMMDD-NNN` 명명 규칙을 유지한다.
- 모든 patch commit에서 checkout 후 target을 판정하는 방식을 유지하지 않는다. 불필요한 runner 실행이 반복된다.
- 기존 HTML patch workflow 자체는 삭제하지 않는다. 대형 단일 HTML에 diff를 적용할 때 계속 사용할 수 있다.

## 후속 작업

React/Mantine runtime vendoring 성공 후 실패한 일회성 vendor workflow와 실행되지 않는 `.json` 파일을 별도 cleanup 커밋에서 제거한다.

## 패치에 포함되지 않은 변경사항

이 patch와 설명 파일 자체는 재귀적으로 diff에 포함하지 않는다.
