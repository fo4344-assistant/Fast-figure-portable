# 20260902-017 — Mantine graph object component 단독 staging

## 배경

`20260902-015`는 selected graph object Mantine form과 type visibility 공통화를 한 패치에 담았으나 `git apply --check`에서 실패했다. HTML에는 적용되지 않았다.

`20260902-016`에서 type visibility helper와 legacy `updateTypeSpecificOptions()` 통합만 분리해 정상 적용했다.

이번 `017`은 남은 작업 중 **Mantine component 정의만** 추가한다. sidebar read/wiring은 다음 패치로 분리한다.

## 목적

이미 준비된 다음 공통 경계를 사용하는 inactive presentation component를 정의한다.

- `readGraphObject()` / `selectedGraphObjectModel()` — `012`, `014`
- `applyGraphObject(...)` — `013`
- `graphObjectTypeVisibility(type)` — `016`

component 자체는 domain/EFSM state를 소유하거나 변경하지 않는다.

## 변경 내용

- 앱 버전 `1.1.64-alpha` → `1.1.65-alpha`
- `FastFigureGraphObjectStaging({ graphObject })` 추가
- 아직 `FastFigureSidebarStaging()`에서 호출하지 않음

component가 표현하는 기존 object form 기능:

- 참조 CSV 이름
- X/Y column
- X/Y axis side
- graph type
- legend name
- line width / line dash
- marker symbol / marker size
- bar opacity / bar line width

## read 경계

X/Y option은 `graphObject.columns`만 사용한다.

이 값은 `014`에서 selected object의 `csvId`가 가리키는 project CSV로부터 계산되므로 component는 다음을 읽지 않는다.

- 전역 `columns`
- 전역 `rows`
- native `#xCol/#yCol`
- active CSV DOM form

## write 경계

모든 변경은 다음 하나의 함수로 보낸다.

```text
fastFigureUiBridge.applyGraphObject(changes, chartId, objectIndex)
→ applySelectedGraphObjectFromValues(...)
→ saveGraphObjects(...)
→ GRAPH_OBJECTS_REPLACED
```

새 event/action을 만들지 않는다.

## commit timing

기존 legacy input 의미를 보존한다.

- Select: 선택 즉시 commit
- legend name / NumberInput: blur commit
- Enter: blur를 발생시켜 동일 commit 경로 사용

TextInput/NumberInput은 `defaultValue`를 사용한다. focus 중 입력값은 commit 전 UI draft이며 persisted source가 아니다.

`key`에는 chartId/objectIndex/current value를 포함하여 외부 canonical 값이 바뀌면 새 input이 canonical 값으로 재생성된다.

## type별 표시

`016`의 `graphObjectTypeVisibility(object.type)`만 사용한다.

- line controls: scatter / lines+markers / hidden
- marker controls: markers / lines+markers
- bar controls: bar

Mantine component 안에 별도의 type 판정 규칙을 만들지 않는다.

## option value 보존

기존 domain value를 그대로 사용한다.

- graph type: `scatter`, `markers`, `lines+markers`, `bar`, `hidden`
- x side: `bottom`, `top`
- y side: `left`, `right`
- line dash: `solid`, `dot`, `dash`, `dashdot`
- marker symbol: `circle`, `square`, `diamond`, `cross`, `x`, `triangle-up`, `triangle-down`

label은 presentation text이며 기존 legacy 의미와 대응시킨다.

## editable

`graphObject.editable === false`이면 controls를 disabled로 렌더한다.

실제 write command의 editable guard는 그대로 유지되므로 disabled 표시가 권위 검증을 대신하지 않는다.

## source of truth

- selected object: 기존 graphObject selection / `selectedObjectIndex`
- persisted object: `chart.editor.objects[index]`
- column options: object CSV에서 계산한 snapshot
- type visibility: 순수 helper
- component input value: commit 전 draft만 허용

React `useState`에 object clone을 장기간 보관하지 않는다.

## Mantine/Core 분류

순수 inactive UI staging component 추가다.

변경하지 않는다.

- graphObject EFSM
- `GRAPH_OBJECTS_REPLACED`
- `CHART_MODEL_REPLACED`
- object schema
- validation
- trace 생성
- Plotly renderer
- import/export
- 활성 legacy sidebar

## 선택하지 않은 방향

### component와 sidebar wiring을 다시 한 패치에 포함

선택하지 않았다. `015` 실패 위치를 좁히기 위해 component 정의와 wiring을 분리한다.

### component 내부 local object state

선택하지 않았다. domain object와 두 번째 persistent owner가 생긴다.

### `configFromForm()` 호출

선택하지 않았다. legacy DOM form 전체에 다시 결합된다.

## 회귀 위험

낮음. component는 정의만 되고 현재 active/staging tree에서도 아직 호출되지 않는다.

검증:

- patch apply
- JavaScript syntax
- MantineCore에서 사용하는 primitive가 이미 runtime에 존재
- component가 DOM ID를 읽지 않음
- component가 `applyGraphObject` 이외의 graph mutation 함수를 호출하지 않음
- EFSM/renderer diff 없음

## rollback

1. `FastFigureGraphObjectStaging` 함수 제거
2. 앱 버전 `1.1.64-alpha` 복원

`012`~`016`은 독립 유지할 수 있다.

## 후속

`017` 적용 성공 후 `018`에서 sidebar가 `readGraphObject()`를 호출하고 selected object가 있을 때 이 component를 한 번 렌더하도록 연결한다.
