# 20260902-003 — graph layout DOM-free values 경계

## 목적

`plan-004.md` 단계 2에 따라 아직 legacy DOM에 남아 있는 graph layout 일반 UI의 첫 migration 경계를 만든다.

현재 `chartLayoutSettingsFromForm()`과 `applyGraphLayoutSettings()`는 제목, 범례/제목/zero-line 토글, graph font, 축 설정을 native DOM에서 직접 읽는다. 이 상태에서는 Mantine graph form이 같은 기능을 사용하려면 DOM을 흉내 내거나 같은 mutation/Plotly 갱신 로직을 별도로 구현해야 한다.

이번 패치는 graph layout의 **입력 수집**과 **기능 적용**을 분리하되 기존 `CHART_LAYOUT_CHANGED` EFSM event와 Plotly renderer를 그대로 재사용한다.

## 변경 내용

- 앱 버전을 `1.1.57-alpha`로 올린다.
- `chartLayoutControlValues()`를 legacy DOM adapter로 추가한다.
- `chartLayoutSettingsFromValues(chart, values)`를 DOM-free 변환 경계로 추가한다.
- 기존 `chartLayoutSettingsFromForm(chart)`은 legacy DOM 값을 수집해 동일 values helper를 호출하는 얇은 adapter로 축소한다.
- `selectedChartLayoutModel()`을 추가하여 selected graph의 layout 값을 project/domain state에서 순수 snapshot으로 읽는다.
- 기존 `applyGraphLayoutSettings()`의 실제 적용 본문을 `applyGraphLayoutSettingsFromValues(values)`로 이동한다.
- legacy `applyGraphLayoutSettings()`는 `chartLayoutControlValues()`를 전달하는 adapter로 유지한다.
- UI bridge에 `readChartLayout()` / `applyChartLayout(values)`를 추가한다.

## Mantine/Core 분류

이 변경은 graph layout 의미를 바꾸는 코어 변경이 아니다.

Mantine 전환을 위해 필요한 것은 native DOM control을 기능 입력 인터페이스로 사용하지 않도록 만드는 adapter 분리다. 실제 domain mutation은 기존 `CHART_LAYOUT_CHANGED` event를 계속 사용하고, 실제 Plotly 갱신도 기존 코드를 그대로 사용한다.

다음은 변경하지 않는다.

- chart/editor 데이터 의미
- axis/global settings 의미
- `CHART_LAYOUT_CHANGED` event/guard/action
- Plotly figure 계산
- Plotly.react 호출 조건과 stale plot 방어
- graph object selection 의미
- import/export 형식

## source of truth

권위 상태는 계속 selected chart의 editor/global settings다.

- `chartLayoutControlValues()`는 legacy UI에서 순간 입력을 수집하는 adapter일 뿐 권위 상태가 아니다.
- `chartLayoutSettingsFromValues()`는 전달값과 현재 chart state를 합성하는 순수 계산 함수다.
- `selectedChartLayoutModel()`은 React render용 snapshot이며 `projectClone()`으로 설정 객체를 분리한다.
- Mantine에서 이후 사용하는 local input state는 commit 전 draft로만 허용한다.

## read 순수성

`selectedChartLayoutModel()`은:

- selected slot/chart를 읽고
- 기존 순수 `readGlobalSettings(chart)`를 사용하며
- `chartLayoutSettingsFromValues(chart)`로 기본 snapshot을 계산하고
- clone한 결과를 반환한다.

`normalizeGlobalSettings(chart)`처럼 chart에 대입할 수 있는 mutation helper는 read 경로에서 사용하지 않는다.

## 기존 함수 재사용

유지/재사용:

- `readGlobalSettings(chart)`
- `readAxis(key)` — legacy DOM adapter 내부에서만 사용
- `CHART_LAYOUT_CHANGED`
- `chartFigure(chart)`
- `plotlyConfig(...)`
- `Plotly.react(...)`
- 기존 debug/status 경로

새 graph mutation 경로나 renderer를 만들지 않는다.

## 선택하지 않은 방향

### Mantine callback에서 `CHART_LAYOUT_CHANGED` payload와 Plotly 갱신을 재구현

선택하지 않는다. legacy/Mantine 두 구현이 생기고 renderer stale-check도 복제된다.

### React가 native input `.value`를 갱신한 뒤 기존 `applyGraphLayoutSettings()` 호출

선택하지 않는다. legacy DOM을 React 기능 API로 계속 사용하는 구조가 되어 Mantine 전환 목적과 충돌한다.

### `configFromForm()`까지 한 패치에서 전부 변경

선택하지 않는다. `configFromForm()`은 trace/object 데이터 선택과 line/marker/bar 설정까지 포함하여 graph layout보다 범위가 크다. graph object/trace 설정은 다음 경계로 분리해 회귀 범위를 제한한다.

### Plotly renderer를 React component로 재작성

선택하지 않는다. domain renderer이며 Mantine 전환 대상이 아니다.

## 회귀 위험

중간 수준이다. 실제 EFSM/renderer는 유지하지만 layout input normalization 경계가 하나 추가된다.

확인 항목:

- values가 모두 전달될 때 기존 form 결과와 동일한 payload 생성
- 일부 values가 생략되면 현재 chart setting을 유지
- boolean false가 누락값으로 오인되지 않음
- graph font trim 동작 유지
- 각 axis의 기존 저장 필드를 보존하면서 전달 필드만 덮어씀
- selected image/빈 slot에서는 read model이 null
- apply invalid-target debug/status 의미 유지
- legacy Apply 버튼이 기존과 동일하게 작동
- Plotly stale render guard 유지

## rollback

독립 롤백 가능하다.

1. bridge의 `readChartLayout` / `applyChartLayout` 제거
2. `selectedChartLayoutModel`, `chartLayoutSettingsFromValues`, `chartLayoutControlValues` 제거
3. `chartLayoutSettingsFromForm()`에 기존 DOM read/merge 본문 복원
4. `applyGraphLayoutSettingsFromValues()`를 기존 `applyGraphLayoutSettings()` 이름/DOM form 호출로 복원
5. 앱 버전 복원

다른 Mantine staging, EFSM, graph renderer를 되돌릴 필요가 없다.

## 후속

다음 graph staging은 이 bridge를 사용해 layout control을 Mantine로 표현하거나, 더 큰 미이관 영역인 `configFromForm()`의 trace/object 설정을 별도 values boundary로 분리한다. 두 작업을 한 패치에 섞지 않는다.
