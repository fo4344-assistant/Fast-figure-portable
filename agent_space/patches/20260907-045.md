# 20260907-045 — Mantine PROJECT DATA tree presentation

## Purpose

Port the PROJECT DATA tree display and selection surface to the Mantine UI without changing the existing project VFS, project objects, asset-selection UI FSM, asset linking behavior, or legacy functional commands.

This patch is intentionally limited to tree presentation and non-destructive selection. Destructive actions, folder creation, and drag/drop remain separate later steps because they require their own Mantine confirmation/input/drag interaction work.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- `projectVfs`
- `projectDataTreeSnapshot()`
- `projectDataTreeObjects()`
- `selectDirectoryFromTree()`
- `selectCsvFromTree()`
- `selectImageFromTree()`
- asset-selection FSM definitions/events
- project/model mutation code
- asset deletion, trash emptying, folder creation, or drag/drop implementation

## Existing boundaries reused

The current source already exposes renderer-neutral and action boundaries suitable for a direct presentation port:

- `projectDataTreeSnapshot(projectDataTreeObjects())` produces directory, CSV, image, chart-reference, and slot-reference data.
- `selectDirectoryFromTree(path)` performs existing directory-selection behavior and sends the existing `SELECT_ASSET` path.
- `selectCsvFromTree(path)` performs existing CSV selection/link behavior through the existing FSM/project code.
- `selectImageFromTree(path)` performs existing image selection/link behavior through the existing FSM/project code.

The Mantine tree therefore does not need a bridge or duplicate project-data model.

## Exact changes

1. Extends the React import to use `useState` for tree expansion only. Expansion is presentation-local state and is not a project/domain source of truth.
2. Adds `FastFigureProjectDataTree` to `fast-figure-ui.js`.
3. The component reads the current renderer-neutral snapshot from the existing project objects whenever the existing `appFSM` subscription updates React.
4. `/assets` directories are rendered recursively.
5. Directory rows:
   - use Mantine buttons,
   - show expand/collapse state,
   - indicate current `appFSM.state.assetSelection/assetPath`,
   - call `selectDirectoryFromTree(path)` directly.
6. CSV rows:
   - show row count and reference count derived from the existing snapshot,
   - indicate current selection,
   - call `selectCsvFromTree(path)` directly,
   - remain non-selectable when in the existing trash path.
7. Image rows:
   - show slot reference count derived from the existing snapshot,
   - indicate current selection,
   - call `selectImageFromTree(path)` directly,
   - remain non-selectable when in the existing trash path.
8. `/slots` is rendered as a collapsible read-only reference section matching the legacy tree's role: visible slots and their referenced CSV/image/Plotly source are displayed, but no new slot-selection behavior is introduced.
9. `FastFigureProjectDataTree` is inserted into the Mantine navbar and exported through `window.FastFigureMantineUi` for inspection/testing.

## State ownership

The only new local React state is the set of expanded directory/slot branches. This is UI presentation state equivalent to the legacy `<details open>` state.

All meaningful state remains owned by existing structures:

- selected asset/path: `appFSM`
- project files/directories: project model + `projectVfs`
- CSV/image/slot/chart data: existing project objects
- CSV/image linking effects: existing selection functions / EFSM path

## Why this direction

The current source already contains a clean renderer-neutral snapshot and complete selection functions. Reimplementing project VFS traversal or asset-selection transitions in React would duplicate functional logic. Calling the existing legacy DOM tree would create the bridge architecture that this reset specifically avoids.

This patch therefore replaces only the visual tree implementation while calling existing functional boundaries directly.

## Rejected alternatives

### Cloning or hiding the legacy `#assetTree`

Rejected. That would preserve the legacy DOM as an internal API and would not constitute a real Mantine port.

### Reimplementing `projectVfs` traversal in a new React store

Rejected. It would create a second model/source of truth and duplicate path/reference rules already present in the project model.

### Porting delete/trash/new-folder/drag-drop in the same patch

Rejected. Those operations introduce destructive confirmation, text input, and drag/drop lifecycle rules. They will be ported with their corresponding Mantine primitives in separate rollbackable patches.

### Adding new EFSM events for tree rendering

Rejected. The existing asset-selection events and functions already cover the required behavior.

## Rollback

Revert the `20260907-045.patch` changes in `fast-figure-ui.js`. No project data migration or EFSM rollback is required because no functional/model structures are changed.
