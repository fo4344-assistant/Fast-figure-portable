# 20260906-036

## 목적

복구된 pre-Mantine `Fast-figure.html`의 실행 의미를 바꾸지 않고 application JavaScript와 bundled Plotly를 개발용 외부 파일로 분리하고, 동일한 single-file portable HTML을 다시 생성할 수 있는 빌드 경로를 추가한다.

이 패치는 `plan-006`의 첫 source 변경 단계다. React/Mantine runtime이나 UI migration은 포함하지 않는다.

## 변경 범위

예정된 source 변경은 다음으로 제한한다.

- `Fast-figure.html`
  - 기존 inline Plotly script body를 `./vendor/plotly.min.js` 참조로 교체
  - 기존 application inline script body를 `./fast-figure.js` 참조로 교체
- `vendor/plotly.min.js`
  - 기존 HTML에 있던 Plotly script body bytes를 그대로 이동
- `fast-figure.js`
  - 기존 HTML에 있던 Fast Figure application script body bytes를 그대로 이동
- `scripts/build-portable.py`
  - 두 외부 script를 원래 위치에 다시 inline하여 single-file portable HTML 생성

함수 수정, 이름 변경, helper 추출, dead-code cleanup, DOM 구조 변경, CSS 변경, UI FSM/기능 EFSM/project model 변경은 하지 않는다.

## 구현 방법

대용량 단일 HTML을 외부에서 다시 직렬화하지 않고 GitHub Actions runner가 repository의 실제 `Fast-figure.html` bytes를 직접 읽어 분리한다.

분리 스크립트는 다음 조건을 모두 확인한 경우에만 source를 작성한다.

1. `PACKAGE_FORMAT_VERSION`을 포함하는 application inline script가 정확히 하나다.
2. application script가 아닌 1 MB 초과 inline script가 정확히 하나이며 이를 bundled Plotly로 판정할 수 있다.
3. 두 script tag에 별도 attribute가 없다.
4. Plotly script가 application script보다 먼저 위치한다.

script body는 text reformat 없이 bytes 그대로 새 파일에 쓴다.

## portable 동등성 검증

분리 직전 `Fast-figure.html`을 runner의 임시 경로에 보존한다.

새 `scripts/build-portable.py`로 split source를 다시 inline한 뒤 `cmp`로 원본과 **byte-for-byte 동일함**을 검사한다. 한 byte라도 다르면 source commit을 만들지 않는다.

추가 검증:

- `node --check fast-figure.js`
- 외부 Plotly/app script tag가 각각 정확히 존재하는지 확인
- `git diff --check`
- 생성된 diff에 대해 reverse apply check

## 이 방향을 선택한 이유

JS 분리 자체에 로직 수정이 섞이면 이후 Mantine 포팅에서 회귀 원인을 분리하기 어렵다. 따라서 source split은 순수한 물리적 이동으로 한정한다.

또한 pre-Mantine HTML은 매우 크므로, client에서 내용을 받아 재조립하는 대신 repository runner에서 실제 bytes를 직접 이동하면 줄바꿈이나 minified vendor bytes가 변형될 위험을 줄일 수 있다.

## 고려했지만 선택하지 않은 방향

### 기존 `20260906-001` 재적용

해당 패치는 이미 Mantine migration이 진행된 후대 source를 분리한 것이므로 사용하지 않는다. 분리 방식만 참고한다.

### 분리와 동시에 React/Mantine vendor 추가

source split의 동등성을 독립적으로 검증할 수 없게 되므로 하지 않는다.

### application code를 여러 module로 추가 분해

현재 단계의 목적은 patchability 확보이지 application architecture 재설계가 아니다. 실행 scope/order 변경 위험도 있으므로 하지 않는다.

### helper/command 정리 병행

Mantine 포팅 과정에서 실제로 필요해진 경우에만 별도 patch로 판단한다.

## 회귀 위험

주요 위험은 script 경계 또는 byte 이동이 잘못되어 실행 순서나 source bytes가 달라지는 것이다.

이를 막기 위해 portable reconstruction을 원본 HTML과 byte 단위로 비교한다. 이 검사가 통과하면 split 전후 application logic과 Plotly bytes는 동일하다.

## rollback

이 패치의 diff를 reverse apply하면 외부 `fast-figure.js`, `vendor/plotly.min.js`, `scripts/build-portable.py`가 제거되고 두 script body가 원래 `Fast-figure.html` 위치로 돌아간다.

복구 전 전체 Mantine migration 이력은 `backup/mantine-migration-20260906`에도 별도로 보존되어 있다.

## 후속 작업
