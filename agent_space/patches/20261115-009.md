## 범위와 목적

작업 시작 지시에 따라 Source Script에 공통 `Slot` 클래스를 작성하고 생성·복원·조회·소비 경로를 연결했다. 전체 Source Script 재작성은 진행 중이며 닫힘을 선언하지 않는다.

- `sourcescript/backend/layout_annotations.py`: grid 확대의 새 좌표에 `Slot(id, row, col)`을 생성하도록 명시했다. 라벨 조회에서 현재 상태와 슬롯을 찾고 대시보드 치수와 슬롯 치수를 계산하는 호출을 연결했다. `gridSlotGeometry`는 승인된 예시의 변수 선언·입력·반환·자연어 계산 형식을 적용했다.
- `sourcescript/backend/assets_files.py`: 저장 딕셔너리와 Slot 인스턴스 사이의 복원·저장 변환을 명시했다. FFSX 적용은 현재 대상 id를 재조회하고 분리된 candidate의 슬롯에 적용하며 대상의 id·좌표·span을 보존한다.
- graph·Application public API·Frontend·system의 관련 참조와 예시를 Slot 속성 및 실제 `_state` 컬렉션 경로에 맞췄다. 프로젝트 설정의 초기값과 허용 범위 설명도 구분했다.

## 보존한 의미와 선택 근거

공통 원형은 `Slot` 하나로 두고 기존 필드명·저장 문서의 키를 유지했다. 새 클래스에 맞춘 저장 자료 변환을 경계에 배치하여 저장 파일 형식을 바꾸지 않았다. 초기 슬롯은 기존 행 우선 id 계산을 사용하고 grid 확대는 기존 최대 id 다음부터 할당한다. 기존 슬롯의 내용·배치와 chart의 단일 소유 관계를 유지한다.

현재 프로젝트와 명령의 작업 candidate를 구분한다. 복사·정규화·검증은 candidate에서 수행하고 검증 성공 후 소유 상태를 반영한다. 조회 결과는 해당 읽기 작업에 소비하며 별도 프로젝트 읽기 원천이나 선택 상태를 추가하지 않았다. 설정 기본값은 `sourcescript/backend/settings.json`을 사용한다. 이전 전역 `projectState` 원형은 `_state` 구조로 이동하여 같은 상태 구조를 중복 정의하지 않았다.
