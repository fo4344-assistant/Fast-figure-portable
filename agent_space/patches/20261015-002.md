# 20261015-002 — Source Script r25 cross-reference closure correction

## 목적

Source Script r24 closure 뒤 public action 이름과 wrapper 본문을 다시 교차 대조하면서 발견한 두 논리 끊김을 수정한다.

1. renderer의 file-drop 준비 설명이 실제 FastFigureApi에 존재하지 않는 `slots.prepareFileDrop`을 참조했다.
2. `graphEditorObjectValues(chartId, index, values)`가 docstring에서는 `graphEditorCommit`을 통한 persistent mutation을 선언했지만 본문에서는 공식 command로 이어지지 않았다.

r24의 Backend / Application boundary / Frontend hierarchy를 변경하지 않고 두 누락을 이미 존재하는 public API와 Project command에 수렴시킨다.

## 변경 내용

### renderer_runtime.py

`prepareDashboardFileDrop`에서 정의되지 않은 `frontendActions.slots.prepareFileDrop` 호출 의미를 제거했다.

기존 `frontendActions.slots.select(slotId)`를 재사용한다.

```text
file-drop target slotId
→ slots.select(slotId)
→ Application boundary
→ Backend reference validation
→ accepted: Frontend selection/workspace ready
→ rejected/deselected: drop preparation false
```

별도 file-drop target authority, 별도 validation cache, 새 public method는 추가하지 않았다.

### graphs.py

`graphEditorObjectValues(chartId, index, values)`의 본문을 다음 순서로 완결했다.

1. chartId와 object index를 Backend current authority에서 resolve.
2. object.csvId와 column references 검증.
3. enum/numeric value normalize.
4. current object array에서 대상 index만 바꾼 candidateObjects 구성.
5. `graphEditorCommit(chartId, candidateObjects, index)` 호출.
6. 기존 `GRAPH_OBJECTS_REPLACED` Project command로 candidate/validation/commit.

새 graph mutation command는 추가하지 않았다.

## 이전 closure가 놓친 이유

r24 closure는 Module decomposition, Backend direct import 제거, query/mutation ordering, lifecycle, renderer input 경계를 중심으로 검토했다.

그 뒤 patch/lineage 검증 과정에서 renderer가 사용하는 public action 이름을 `PUBLIC_API_METHODS`와 symbol 단위로 대조하고, graph wrapper의 docstring이 실제 함수 본문에서 command까지 이어지는지 다시 확인하면서 두 누락을 발견했다.

따라서 r25 closure review `review-20261015-021-sourcescript-closure-r25.md`에 r24가 놓친 범위와 재검토 근거를 기록했다.

## 선택한 방향

- `prepareFileDrop` 새 API 대신 기존 `slots.select` 사용.
- graph object value 전용 새 command 대신 기존 `graphEditorCommit → GRAPH_OBJECTS_REPLACED` 사용.
- r24 Module hierarchy, ProjectObject schema, Frontend FSM state, renderer projection contract는 유지.

같은 의미를 처리하는 새 abstraction이나 mutation route를 만들지 않는 방향을 선택했다.

## 고려했지만 선택하지 않은 방향

- `slots.prepareFileDrop`를 실제 FastFigureApi에 추가: target validation과 selection을 `slots.select`가 이미 소유하므로 중복 API가 되어 기각.
- renderer가 Backend slot을 직접 조회해 drop validity 판단: plan-016 API/Adapter 경계를 우회하므로 기각.
- `GRAPH_OBJECT_VALUE_CHANGED` 같은 새 Project command 추가: existing `GRAPH_OBJECTS_REPLACED`가 동일 persistent owner와 validation을 이미 제공하므로 기각.
- Frontend-local object copy를 직접 저장: chart SoT의 current objects/reference validation을 우회하므로 기각.
