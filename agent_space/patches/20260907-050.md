# 20260907-050 — React-owned FFPX import input

## Purpose

Remove the Mantine project's dependency on the legacy `#importProjectFile` DOM input. The Mantine project section should own its own invisible browser file input and call the existing project parsing/import functions directly.

This is a presentation ownership correction, not a new import implementation.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- FFPX parsing (`ffpxReadProject`)
- JSON fallback parsing semantics
- `importProject`
- project models/classes
- UI FSM or functional EFSM definitions
- FFPX/FFSX formats
- the still-working legacy `#importProjectFile` path

## Existing functional path reused

The Mantine-owned file input uses exactly the existing functional helpers already used by the legacy handler:

- ZIP signature check on the first four bytes
- `ffpxReadProject(file)` for FFPX ZIP input
- `JSON.parse(await file.text())` for the legacy JSON fallback
- `importProject(payload, file.name)`
- existing `status()` / `debugLog()` reporting

No new project-import model mutation path is introduced.

## Exact changes

1. Adds React `useRef` usage.
2. Removes the global `openProjectImportPicker()` helper that called `document.getElementById("importProjectFile").click()`.
3. `FastFigureProjectActions` owns a hidden `<input type="file">` via a React ref.
4. The visible `FFPX 불러오기` Mantine button opens only that component-local file input.
5. The existing slot-selection guard remains unchanged semantically.
6. The local input's `onChange` performs the same FFPX-vs-JSON detection and calls the same import functions as the legacy handler.
7. The input value is cleared in `finally`, preserving same-file re-selection behavior.
8. No legacy DOM ID is read or clicked by the Mantine project-import path.

## UI ownership

The invisible browser file input is local implementation detail of `FastFigureProjectActions`. The browser's native file chooser remains unavoidable platform UI; all visible Fast Figure controls remain Mantine controls.

Persistent project state remains owned by the existing project model and import functions.

## Why this direction

The previous Mantine button was still a bridge into a legacy DOM control. That contradicts the intended cutover architecture. The project import handler is already thin enough to move to the Mantine presentation layer without changing any parsing or model semantics.

## Rejected alternatives

### Keeping `document.getElementById("importProjectFile").click()`

Rejected because it leaves the legacy DOM as an internal API for Mantine.

### Creating a new import abstraction solely for Mantine

Rejected because `ffpxReadProject()` and `importProject()` already provide the required functional boundaries.

### Removing the legacy input now

Rejected because cutover has not occurred yet; the legacy UI remains a parity reference until the Mantine replacement is complete.

### Adding a guessed file `accept` list

Rejected because this patch should not change existing input acceptance behavior without first verifying the legacy input declaration.

## Rollback

Revert `20260907-050.patch`. The previous Mantine button will again use the legacy project file input bridge.
