# 20260906-015 — overlay entry domain / legacy presentation 분리

## 상태

첫 큐 실행은 `git apply --check`에서 overlay hunk context 적용 실패로 중단되어 실제 `fast-figure.js`에는 적용되지 않았다.

`20260906-014`가 workspace 구간에 줄을 추가한 뒤 overlay 위치가 이동한 상태에서 큰 단일 hunk를 사용한 것이 원인이다. 구현 의미는 변경하지 않고, 동일 변경을 세 개의 작은 context hunk로 분해해 현재 `1.1.118-alpha` source에 다시 적용한다.

## 목적

overlay entry callback에서 overlay-open policy와 native panel/dialog presentation을 분리한다.

현재 `setOverlayDomState()`는 layout/label/caption/print panel/toggle 및 README dialog를 조작한 뒤 `applyOverlayOpenPolicy()`까지 실행하고, `enterOverlayState()`가 이어서 overlay별 legacy 세부 presentation을 수행한다. React/Mantine cutover 시 EFSM entry callback에서 native DOM 조작 없이 동일한 overlay-open policy를 사용할 수 있어야 한다.

## 변경 내용

- 앱 버전 `1.1.118-alpha` → `1.1.119-alpha`
- `setOverlayDomState()`에서 `applyOverlayOpenPolicy()` 제거
- `enterOverlayDomainState({ state })` 추가
  - 기존 `applyOverlayOpenPolicy(state)`만 호출
- 기존 overlay별 layout/label/caption/print 세부 UI 처리를 `syncLegacyOverlayPresentation()`으로 분리
- active `enterOverlayState(context)`는 다음 기존 순서를 그대로 유지
  1. `setOverlayDomState(context.state)`
  2. `enterOverlayDomainState(context)`
  3. `syncLegacyOverlayPresentation(context)`

## 순서 보존 이유

기존 코드는 native panel/toggle/readme 상태를 먼저 반영하고 그 다음 `applyOverlayOpenPolicy()`가 slot selection을 정리한 뒤 overlay별 세부 presentation을 수행한다.

`clearAllSlotSelections()`는 EFSM event를 추가로 발생시킬 수 있으므로 policy를 함수 맨 앞으로 이동하지 않는다. 이번 패치는 domain/presentation을 분리하되 기존 재진입 순서를 보존한다.

## Mantine 전환과의 관계

후속 cutover에서 overlay EFSM entry는 `enterOverlayDomainState`만 직접 사용할 수 있다. Mantine `Modal`의 opened 상태와 close 규칙은 `appFSM.state.overlay` 및 `CLOSE_OVERLAY` event를 통해 관리되므로 native panel/toggle/readme dialog presentation helper는 제거 대상이 된다.

이번 단계에서는 active owner가 아직 legacy UI이므로 wrapper가 세 단계를 모두 실행한다.

## source of truth / EFSM / core

- overlay source of truth는 `appFSM.state.overlay` 그대로 유지
- overlay state 이름/transition/event 변경 없음
- slot selection source of truth 변경 없음
- 새 UI/domain state 추가 없음
- FFPX/FFSX/renderer schema 변경 없음

## 선택하지 않은 방향

### policy를 entry wrapper 맨 앞에서 실행

기존 event 재진입 순서를 바꿀 수 있어 선택하지 않는다.

### `setOverlayDomState()`를 그대로 두고 React 경로에서 policy를 한 번 더 호출

active legacy와 React 경로가 동시에 존재하면 slot-selection policy가 중복 실행될 수 있으므로 선택하지 않는다.

### 즉시 native overlay DOM 제거

React shell이 아직 mount되지 않았으므로 active UI를 깨뜨린다.

## 회귀 위험

낮음~중간.

실행되는 함수의 내용은 동일하지만 `clearAllSlotSelections()`가 EFSM event를 보낼 수 있으므로 기존 호출 순서를 명시적으로 보존한다.
