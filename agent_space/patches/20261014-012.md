# 20261014-012 — Set default layout outer margin to zero

## 목적과 변경 내용

새 project의 layout outer margin 기본값을 0으로 변경하고 import fallback이 같은 default source를 재사용하도록 정리한다.

- Source Script에 `SLOT_STYLE_DEFAULTS`를 명시하고 `outerMargin = 0`을 기본값으로 정의.
- PlusCal pseudocode의 default project creation에 같은 slot style payload를 번역.
- `DEFAULT_SLOT_STYLE.outerMargin`: `120 → 0`.
- project import에서 outerMargin 필드가 없을 때 literal `120` 대신 `DEFAULT_SLOT_STYLE.outerMargin` 사용.
- 기존 project에 명시적으로 저장된 outerMargin은 변경하지 않음.
- browser regression에 새 project outerMargin 기본값 0 검증 추가.
- APP build `1.1.42-wip → 1.1.43-wip`.

## 선택 이유

생성 기본값과 import fallback이 별도 literal을 소유하면 다시 어긋날 수 있다. Source Code에서는 `DEFAULT_SLOT_STYLE`을 기본값 단일 원천으로 재사용한다.

## 고려했지만 선택하지 않은 방향

- 모든 기존 project의 outerMargin을 강제로 0으로 migration: 저장된 사용자 설정을 덮어쓰므로 기각.
- import fallback만 0으로 변경: 새 project 생성 기본값과 다시 분리되므로 기각.
- UI NumberInput의 표시값만 0으로 변경: authoritative project state와 불일치하므로 기각.

## Verification

현재 verification model은 visual slotStyle numeric default를 모델링하지 않는다. trash/reference/slot-swap state transition에는 변화가 없어 model 파일은 유지하고 lineage review만 갱신한다.

## 별도 확인된 문제

이 패치에서는 사용자 요청 중 기본값 변경만 수행한다. 다음 문제는 원인 확인 상태로 남긴다.

- Layout preview local selection은 preview 밖 클릭 해제 handler가 없음.
- project node를 trash로 이동한 뒤 reference detach는 commit되지만 dashboard render가 누락됨.
- trash 비우기에서 legacy/stale reference가 제거되는 경우도 dashboard render 누락 가능.
