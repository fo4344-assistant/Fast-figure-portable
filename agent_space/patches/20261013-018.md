# 20261013-018 — Use homogeneous verification sentinels

## 발견된 오류

GitHub Actions run `38356732343`의 `verify-interaction-core`는 PlusCal translation과 SANY parse를 모두 통과한 뒤 TLC initial-state evaluation에서 다음 오류로 종료했다.

```text
Attempted to check if the value:
"no-slot"
is in the integer interval 1..3
```

이 오류는 invariant counterexample이 아니라 verification harness가 slot/csv id는 정수로, no-selection sentinel은 문자열로 표현한 heterogeneous finite domain 때문에 발생했다.

## 변경

verification harness 내부 sentinel을 다음처럼 바꾼다.

```text
NoSlot = 0
NoCsv  = 0
SlotIds = 1..3
CsvIds  = 1..2
```

0은 실제 application id 의미가 아니라 bounded verification model 내부의 no-reference 값이다.

Source Script의 `none` selection 의미, visible slot 판정, CSV reference 의미는 바뀌지 않는다.

## 계층 상태

canonical verification model이 변경되므로 revision을 r10으로 올리고 fingerprint를 `sha256:886afad260ca3c71a19e056dfe4d7c9ef87ae301cbc24d7d0b7a842ec777c52c`로 갱신한다.

새 TLC run 성공 전까지 stale/pending을 유지한다.

## 후속

이 push로 다시 interaction model을 translate → SANY → TLC 순서로 실행한다. 성공하면 해당 run을 validation evidence로 사용한다.
