# 20260902-025 — `saveGraphObjects()` selection guard 위치 교정

## 목적

`saveGraphObjects(objects)`가 graph-object selection을 공통 저장 선행조건으로 요구해, 선택과 무관하게 동작해야 하는 기존 목록/팔레트 기능까지 차단하는 문제를 교정한다.

이번 변경은 Mantine 전환 자체 때문에 필요한 것이 아니라 기존 활성 UI에서도 존재하는 correctness 문제다.

## 확인된 기존 호출 경로

`saveGraphObjects()` 호출처를 인라인 Plotly 구간을 읽지 않고 함수명 주변의 좁은 application code만 확인했다.

현재/기존 구조에서 다음 기능이 `saveGraphObjects()`를 공유한다.

1. graph object drag reorder
2. row color input 변경
3. row 삭제
4. graph palette reset
5. graph palette load
6. `20260902-013`에서 추가한 selected object form update

이 중 selected object form update만 현재 selection이 기능 대상이다.

나머지는 대상 row index 또는 전체 object 배열이 이미 명시되어 있다.

## 기존 문제

현재 `saveGraphObjects()`에는 다음 guard가 있다.

```js
if (!selectedGraphObjectGuard()) {
  status("변경할 그래프 오브젝트를 먼저 선택하세요.");
  return;
}
```

그러나 이 guard는 저장하려는 object/index와 selected index가 같은지 검사하지 않는다. 단지 **아무 graph object나 하나 선택되어 있는지**만 검사한다.

따라서 동작이 다음처럼 비일관적이다.

- 선택 없음 + row A color 변경 → 저장 거부
- row B 선택 + row A color 변경 → 저장 허용
- 선택 없음 + row A 삭제 → 저장 거부
- row B 선택 + row A 삭제 → 저장 허용
- 선택 없음 + palette reset/load → 저장 거부
- 선택 있음 + palette reset/load → 저장 허용
- 선택 없음 + drag reorder → 저장 거부

즉 이 guard는 대상 보호 규칙으로 기능하지 못하면서 unrelated selection state에 따라 같은 명령의 성공/실패만 바꾼다.

## 변경 내용

- 앱 버전 `1.1.69-alpha` → `1.1.70-alpha`
- `saveGraphObjects()`에서 `selectedGraphObjectGuard()` 선행조건 제거
- chart 존재 검사는 유지
- 실제 mutation은 기존 `GRAPH_OBJECTS_REPLACED` event/action을 그대로 사용
- selected-object 전용 update guard는 `applySelectedGraphObjectFromValues()`에 그대로 유지

## guard 책임의 올바른 위치

선택이 필요한 명령:

```text
selected object form edit
→ applySelectedGraphObjectFromValues()
→ selectedGraphObjectGuard()
→ saveGraphObjects()
```

선택이 필요하지 않은 명령:

```text
row color / row delete / reorder / palette replace
→ target index 또는 object array가 이미 명시됨
→ saveGraphObjects()
→ GRAPH_OBJECTS_REPLACED
```

따라서 공통 배열 저장 helper가 selection policy를 소유하지 않고, selection이 실제 의미인 caller가 guard를 소유하는 구조가 더 일관적이다.

## EFSM 의미

`GRAPH_OBJECTS_REPLACED` event/action 자체는 변경하지 않는다.

`applyGraphObjectsReplacedAction()`은 기존대로:

- chart 존재/editable 검증
- objects 배열 적용
- 빈 배열이면 기본 object recovery
- object normalization
- selected index가 범위를 벗어나면 null 처리
- editable graph rebuild

을 수행한다.

`graphObject` region의 `GRAPH_OBJECTS_REPLACED` transition도 변경하지 않는다.

따라서 mutation authority는 계속 EFSM action에 있다.

## Mantine/Core 분류

이 패치는 **Mantine와 독립적인 correctness + 최소복잡도 개선**으로 분류한다.

Mantine list action을 연결하면서 발견했지만, 활성 legacy UI에서도 이미 같은 selection-dependent failure가 존재한다.

## source of truth

변경 없음.

- objects: chart `editor.objects`
- selection: graphObject EFSM / `selectedObjectIndex`
- selection은 object array 저장 권한의 source가 아니라 별도의 transient selection 의미

두 상태를 불필요하게 결합하던 guard만 제거한다.

## 선택하지 않은 방향

### color/delete/reorder 전에 대상 row를 자동 선택

선택하지 않는다. 기능 수행을 위해 selection state를 인위적으로 변경하며 사용자가 선택한 object 의미까지 바꾼다.

### `saveGraphObjects(objects, requireSelection)` 플래그 추가

선택하지 않는다. selected-object caller가 이미 외부에서 guard를 수행하므로 공통 helper에 policy flag를 추가할 이유가 없다.

### 새 EFSM event를 color/delete/reorder별로 생성

선택하지 않는다. 기존 `GRAPH_OBJECTS_REPLACED`가 전체 object 배열 mutation의 권위 경계로 이미 동작한다.

### editable guard를 새로 추가

이번 패치에서는 하지 않는다. `applyGraphObjectsReplacedAction()`의 기존 editable validation을 변경하지 않는다. selection guard 문제와 별도 사항이다.

## 회귀 위험

중간 이하이다. 공통 저장 helper의 호출 허용 범위가 넓어지므로 호출처를 전부 확인했다.

검증 항목:

- 선택 없음 상태에서 row color 변경 가능
- 선택 없음 상태에서 row delete 가능
- 선택 없음 상태에서 drag reorder 가능
- 선택 없음 상태에서 palette reset/load 가능
- selected object form은 selection guard 계속 요구
- chart 없음 상태는 기존처럼 저장 skip
- `GRAPH_OBJECTS_REPLACED` action/transition 변경 없음
- editable validation 변경 없음
- Plotly/trace code 변경 없음

## rollback

1. `saveGraphObjects()`의 `selectedGraphObjectGuard()` block 복원
2. 앱 버전을 `1.1.69-alpha`로 복원

`024`의 selection command 분리는 독립 유지 가능하다.

## Plotly 범위

이번 검토와 patch는 application helper/caller 주변만 대상으로 했다.

인라인 Plotly library 본문은 읽거나 수정하지 않았다.

## 후속

이 교정 적용 후 color/delete/reorder를 DOM-free command로 묶을 때 selection을 강제로 조작하지 않고 각 action의 명시적 target/index를 사용한다.
