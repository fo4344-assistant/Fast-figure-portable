# 20260902-005 — graph layout DOM-free values 경계 단순 재생성

## 상태

`20260902-003`과 `20260902-004`는 모두 `Fast-figure.html`에 적용되지 않았다.

- `003`: unified diff hunk count 오류로 `git apply --check` 이전 parse 단계에서 거부
- `004`: patch 문법은 정상화됐으나 마지막 함수 말단 context가 현재 main과 일치하지 않아 `git apply --check`에서 거부

두 실행 모두 JavaScript 구문 검사 및 실제 commit 단계에는 도달하지 않았다.

`005`는 같은 graph-layout DOM-free 경계 목표를 유지하되, 별도 `applyGraphLayoutSettingsFromValues()` + legacy wrapper 두 함수를 만들 필요가 없다는 점을 반영해 구현을 더 단순화한다.

## 목적

legacy graph layout form이 native DOM을 직접 기능 API로 사용하는 결합을 제거하고, Mantine이 명시적 values payload를 동일한 기존 graph layout 적용 경로에 전달할 수 있게 한다.

## 변경 내용

- 앱 버전 `1.1.56-alpha` → `1.1.57-alpha`
- `chartLayoutControlValues()` 추가: legacy DOM 값 수집 전용 adapter
- `chartLayoutSettingsFromValues(chart, values)` 추가: DOM-free 순수 계산 경계
- `chartLayoutSettingsFromForm(chart)`은 legacy adapter를 통해 위 순수 helper 재사용
- `selectedChartLayoutModel()` 추가: selected chart의 layout 상태를 순수 snapshot으로 반환
- UI bridge에 `readChartLayout()` / `applyChartLayout(values)` 추가
- 기존 `applyGraphLayoutSettings()` 함수는 이름과 renderer/EFSM 본문을 유지하고, 인자만 `values = chartLayoutControlValues()`로 받아 legacy 호출과 Mantine 호출을 동시에 지원
- 함수 내부에서 `chartLayoutSettingsFromForm(chart)` 대신 `chartLayoutSettingsFromValues(chart, values)` 사용

## 004보다 단순한 이유

`004`는 다음 두 함수를 두려 했다.

```text
applyGraphLayoutSettingsFromValues(values)
applyGraphLayoutSettings() -> legacy adapter
```

하지만 기존 함수 하나를 다음처럼 유지하면 같은 자유도를 더 적은 경계로 제공한다.

```text
applyGraphLayoutSettings(values = chartLayoutControlValues())
```

- legacy button: 인자 없이 호출 → 기존 DOM adapter 사용
- Mantine bridge: values 전달 → DOM을 읽지 않음

따라서 별도 wrapper 함수와 함수 말단 변경이 없어지고, 기존 호출자와 함수 식별자도 그대로 유지된다.

## Mantine/Core 분류

Mantine 전환을 위한 UI adapter 분리다. graph/domain 의미는 변경하지 않는다.

변경하지 않는 항목:

- `CHART_LAYOUT_CHANGED` event/action/guard
- chart/editor 데이터 의미
- axis/global settings 의미
- Plotly figure 생성
- `Plotly.react(...)` 및 stale-render 방어
- graph object selection
- import/export

## source of truth

권위 상태는 계속 selected chart의 editor/global settings다.

- `chartLayoutControlValues()`는 legacy 입력 순간값
- `chartLayoutSettingsFromValues()`는 순수 계산 결과
- `selectedChartLayoutModel()`은 React render snapshot
- UI bridge의 값은 권위 상태가 아님

React가 이후 local state를 쓰더라도 commit 전 draft로만 사용한다.

## read 순수성

`selectedChartLayoutModel()`은 `readGlobalSettings(chart)`를 사용하며, `normalizeGlobalSettings(chart)` 같은 mutation helper를 호출하지 않는다.

`chartLayoutSettingsFromValues()`는 전달값과 기존 chart state를 읽어 새 객체를 반환할 뿐 chart/editor에 대입하지 않는다.

## 기존 함수 재사용

- `readGlobalSettings(chart)` 유지
- `readAxis(key)`는 legacy adapter에서만 재사용
- `applyGraphLayoutSettings()` 식별자와 기존 호출자 유지
- `CHART_LAYOUT_CHANGED` 유지
- 기존 Plotly renderer/debug/status 본문 유지

## 선택하지 않은 방향

### 별도 values apply 함수 + legacy wrapper

기능 자유도가 늘지 않으면서 함수 하나가 더 생기므로 `005`에서는 선택하지 않는다.

### Mantine에서 legacy DOM 값을 먼저 갱신

DOM이 계속 기능 API가 되므로 선택하지 않는다.

### `configFromForm()`까지 동시에 변경

trace/object 생성·편집 범위가 섞이므로 별도 패치로 남긴다.

### Plotly React 재작성

Mantine 전환 대상이 아닌 domain renderer이므로 하지 않는다.

## 회귀 위험

중간 이하.

기존 `applyGraphLayoutSettings()`의 이름과 본문을 유지하고 입력 수집만 분리하므로 이전 003/004보다 변경 표면이 작다.

확인 항목:

- 인자 없이 기존 함수 호출 시 legacy form 결과가 동일한지
- 명시 values 호출 시 native DOM을 읽지 않는지
- `false` boolean 값 보존
- 누락 필드는 현재 chart 설정 유지
- axis 기존 추가 필드 보존
- graph font trim 유지
- image/빈 slot read model은 null
- 기존 invalid-target/debug/status/Plotly stale guard 유지

## rollback

1. bridge의 graph-layout 두 메서드 제거
2. `chartLayoutControlValues`, `chartLayoutSettingsFromValues`, `selectedChartLayoutModel` 제거
3. `chartLayoutSettingsFromForm()` 기존 본문 복원
4. `applyGraphLayoutSettings(values = ...)`를 기존 무인자 함수로 복원하고 form helper 호출 복원
5. 앱 버전 복원

다른 EFSM/renderer/Mantine staging 변경을 되돌릴 필요가 없다.

## 검증

GitHub Actions의 `git apply --check`, 실제 apply, `git diff --check`, 마지막 inline JavaScript `node --check`를 통과해야 한다.

적용 후 실제 commit diff에서 graph layout의 renderer/event 본문에 다른 semantic 변경이 없는지 확인한다.
