# 20260902-024 — graph object 선택 command patch hunk count 교정

## 배경

`20260902-023`은 GitHub Actions의 `git apply --check`에서 다음 오류로 중단되었다.

```text
error: corrupt patch at agent_space/patches/20260902-023.patch:24
```

HTML에는 적용되지 않았고 JavaScript 검사와 commit에도 도달하지 않았다.

원인은 첫 bridge hunk가 실제 기존 6줄 / 신규 9줄인데 header를 `-9,+12`로 기록한 unified diff line-count 오류다.

로컬에서 해당 bridge snippet을 다시 `diff -u`로 계산한 결과 정확한 metadata는 다음과 같다.

```text
@@ -1,6 +1,9 @@
```

selection helper hunk는 기존 19줄 / 신규 36줄로 재확인했다.

## 목적

`023`과 동일한 구현을 유지하고 hunk metadata만 교정해 적용한다.

## 변경 내용

- 앱 버전 `1.1.68-alpha` → `1.1.69-alpha`
- `selectGraphObjectFromIndex(index, expectedChartId)` 추가
- bridge `selectGraphObject(index, chartId)` 추가
- legacy `selectGraphObject(index)`를 공통 selection command + legacy renderer wrapper로 분리

기능 의미, source of truth, 선택하지 않은 방향, rollback 기준은 `20260902-023.md`와 동일하다.

## Plotly 범위

이번 패치는 graph selection 함수와 UI bridge 주변의 좁은 context만 대상으로 한다.

- trace 생성 코드 변경 없음
- Plotly renderer 변경 없음
- 인라인 Plotly library 구간 조회/수정 없음

## 검증

- bridge hunk old/new line count: 6 / 9
- selection hunk old/new line count: 19 / 36
- `git apply --check`
- 실제 apply
- `git diff --check`
- inline application JavaScript `node --check`
- 적용 diff에서 EFSM event/action 및 Plotly/trace 변경이 없는지 확인

## rollback

`023.md`의 rollback 절차와 동일하다.

1. bridge `selectGraphObject` 제거
2. `selectGraphObjectFromIndex()` 제거
3. legacy `selectGraphObject()`의 기존 event/active CSV 코드를 복원
4. 앱 버전을 `1.1.68-alpha`로 복원

## 후속

성공 후 color/delete/reorder command를 선택 상태와 분리할 수 있는지 검토한다. `saveGraphObjects()`의 `selectedGraphObjectGuard()`는 의도를 확인하기 전 제거하지 않는다.
