# 20260902-026 — graph object mutation command / legacy list renderer 분리

## 목적

`saveGraphObjects()`가 현재 두 책임을 함께 수행한다.

1. graph object domain mutation
   - `GRAPH_OBJECTS_REPLACED` 전송
   - `editing` 갱신
   - `updateGraphView()`
   - chart notify
2. legacy graph-object 목록 DOM 갱신
   - `renderGraphObjects(chart.editor.objects)`

Mantine graph object form/list가 이 함수를 그대로 사용하면 inactive staging 단계에서도 legacy `#graphObjects` DOM renderer를 요구하고, 최종 cutover 후에는 제거 예정인 legacy list가 mutation command의 필수 의존성이 된다.

따라서 실제 mutation command와 legacy list renderer wrapper를 분리한다.

## 변경 내용

- 앱 버전 `1.1.70-alpha` → `1.1.71-alpha`
- 기존 domain mutation 본문을 `replaceGraphObjects(objects, expectedChartId = null)`로 이동
- `replaceGraphObjects()`는 성공 시 적용된 chart를 반환하고 실패 시 `null` 반환
- 기존 `saveGraphObjects(objects)`는 legacy wrapper로 유지
  - `replaceGraphObjects(objects)` 호출
  - 성공 시 `renderGraphObjects(chart.editor.objects)` 호출
- `applySelectedGraphObjectFromValues()`는 legacy wrapper가 아니라 `replaceGraphObjects(next, chart.id)`를 사용

## 경계

공통 command:

```text
replaceGraphObjects
→ GRAPH_OBJECTS_REPLACED
→ applyGraphObjectsReplacedAction
→ rebuildEditableGraph
→ updateGraphView
→ notify
```

legacy wrapper:

```text
saveGraphObjects
→ replaceGraphObjects
→ renderGraphObjects
```

따라서 기존 활성 legacy color/delete/reorder/palette caller는 `saveGraphObjects()`를 계속 호출하므로 현재 목록 UI 동작은 유지된다.

Mantine selected-object form은 `replaceGraphObjects()`를 사용해 legacy list DOM에 의존하지 않는다.

## stale chart guard

`replaceGraphObjects(objects, expectedChartId)`는 optional chart identity를 검증한다.

- expected id가 현재 selected chart와 다르면 `null`
- legacy `saveGraphObjects()`는 id를 전달하지 않아 기존 의미 유지
- Mantine selected-object command는 이미 확보한 current chart id를 전달

이 id는 persisted state가 아니라 stale UI write 거부용 식별자다.

## 유지하는 renderer

`updateGraphView()`와 `rebuildEditableGraph()`는 그래프/domain renderer 경로이므로 유지한다.

분리하는 것은 일반 UI인 graph object 목록 DOM renderer `renderGraphObjects()`뿐이다.

## source of truth

변경 없음.

- graph objects: chart `editor.objects`
- mutation authority: 기존 `GRAPH_OBJECTS_REPLACED` action
- selection: graphObject EFSM / selectedObjectIndex
- legacy list DOM: source of truth가 아님

## 최소복잡도

새 mutation 구현을 추가하지 않고 기존 `saveGraphObjects()` 본문을 공통 command로 승격한 뒤 legacy renderer를 얇은 wrapper로 남긴다.

향후 color/delete/reorder Mantine action도 같은 `replaceGraphObjects()`를 재사용할 수 있다.

## 변경하지 않는 영역

- `GRAPH_OBJECTS_REPLACED` event/action/transition
- graph object schema
- selection EFSM
- graph rebuild 알고리즘
- Plotly renderer
- 인라인 Plotly library
- import/export
- palette semantics

## 선택하지 않은 방향

### Mantine에서도 `saveGraphObjects()` 사용

선택하지 않는다. 최종 cutover 이후 legacy `#graphObjects` DOM을 유지해야 하는 구조가 된다.

### `renderGraphObjects()` 자체를 React로 재작성하면서 제거

선택하지 않는다. 아직 shell은 inactive staging이며 active legacy UI를 유지해야 한다. 지금은 mutation 경계만 분리한다.

### `updateGraphView()`까지 legacy wrapper로 이동

선택하지 않는다. 이 함수는 실제 graph surface 갱신 경로이며 일반 목록 UI renderer와 성격이 다르다.

### 새 EFSM event 생성

선택하지 않는다. 기존 `GRAPH_OBJECTS_REPLACED`가 이미 mutation 의미를 담당한다.

## 회귀 위험

낮음~중간이다.

- active legacy callers는 기존 `saveGraphObjects()` 이름을 그대로 사용
- legacy 목록 재렌더 결과 유지
- selected Mantine form update만 불필요한 legacy list render를 생략

검사:

- legacy color/delete/reorder/palette 후 목록 갱신 유지
- selected-object Mantine update 후 graph view/domain state 갱신
- stale chart write 거부
- notify/rebuild/updateGraphView 순서 보존
- Plotly/trace 영역 diff 없음

## rollback

1. `replaceGraphObjects()` 본문을 다시 `saveGraphObjects()`로 합침
2. `renderGraphObjects()` 호출을 원 위치로 복원
3. `applySelectedGraphObjectFromValues()`를 다시 `saveGraphObjects(next)`로 복원
4. 앱 버전을 `1.1.70-alpha`로 복원

## Plotly 조회 범위

이번 작업은 `saveGraphObjects`, `applySelectedGraphObjectFromValues` 주변 application code만 대상으로 한다. 인라인 Plotly 라이브러리 본문은 읽거나 수정하지 않는다.
