# 20261013-017 — Fix generated PlusCal symbol collision and TLC init config

## 발견된 오류

GitHub Actions run `38356583405`에서 interaction verification은 PlusCal translation을 통과했고 SANY parsing도 source text 수준에서는 진행되었으나, generated module semantic processing에서 두 개의 `with slotId`가 같은 generated symbol을 만들면서 충돌했다.

로그:

```text
Multiply-defined symbol 'slotId'
```

또한 과거 r6 TLC 실행에서 확인했던 것처럼 PlusCal procedure local initialization에는 cfg의 `defaultInitValue` model value가 필요하다.

## 변경

- surface-click harness 변수는 `surfaceSlotId`로 변경한다.
- bookmark-click harness 변수는 `bookmarkSlotId`로 변경한다.
- interaction cfg에 다음을 추가한다.

```text
CONSTANTS
    defaultInitValue = defaultInitValue
```

두 변수 이름은 verification harness의 bounded choice 식별자일 뿐 domain 의미를 바꾸지 않는다.

## 계층 상태

canonical verification 파일이 다시 변경되므로 revision을 r9로 증가시키고 fingerprint를 `sha256:796ae3963e238517f42ee8cea24d221a72da913ce70ce705e33290640a17ef5f`로 갱신한다.

아직 새 TLC run이 완료되지 않았으므로 stale/pending 상태를 유지한다.

## version-chain workflow 실패와의 관계

같은 push에서 `Development layer versions`가 실패한 원인은:

```text
modified verification-model must finish as current against the latest Source Script
```

이다.

이는 interaction counterexample이 아니라 checker가 verification 파일 변경 커밋 자체에 current 상태를 요구하기 때문이다. TLC 결과가 없는 상태에서 current/passed를 선기록하지 않고, 먼저 검증 run을 통과시킨 뒤 validation review와 current/passed transition을 별도 커밋으로 기록한다.

## 후속

이 patch push로 새 TLA workflow를 실행한다. SANY/TLC가 통과하면 그 run id, job id, commit SHA, TLC 통계를 validation review에 기록하고 verification-model을 current/passed로 전환한다.
