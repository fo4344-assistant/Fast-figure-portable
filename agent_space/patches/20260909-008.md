# 20260909-008 — Mantine graph global/axis editor

## 목적

`plan-006`과 `review-010-mantine-ui-inventory.md`의 graph editor 항목 중 아직 legacy form에 남아 있던 그래프 전역 설정과 네 축 설정을 Mantine 소유 UI로 옮긴다. 이번 변경은 generic UI ownership만 이전하며 기존 UI FSM, EFSM, project/chart model, Plotly renderer 의미는 변경하지 않는다.

## 변경 내용

- `fast-figure-ui.js`에 `FastFigureGraphLayoutEditor`를 추가한다.
- 선택된 graph slot의 현재 값은 legacy DOM이 아니라 `readGlobalSettings(chart)`와 `chart.editor.title`에서 직접 읽는다.
- 변경은 별도 migration store/bridge 없이 기존 `appFSM.send("CHART_LAYOUT_CHANGED", ...)`로 직접 전달한다.
- 적용 뒤 기존 `renderDashboard()`를 사용해 domain renderer를 갱신한다.
- graph global settings에서 다음 항목을 Mantine으로 제공한다.
  - graph title
  - legend/title/zero-line visibility
  - graph font family
  - title font size / legend font size
- 네 축 `xBottom`, `xTop`, `yLeft`, `yRight`에 동일한 편집 구조를 제공한다.
  - title
  - min / max
  - tick mode (`plotly` / `increment`)
  - log scale의 minor tick toggle
  - tick interval
  - notation (`none`, `power`, `e`)
  - scale type (`linear`, `log`, `reciprocal`)
  - divide
  - axis-title size / value font size
  - axis line width
  - grid / visible / value visibility
- 기존 `chart.editor.editable === false`인 imported Plotly 원본 모드에서는 수정 controls를 비활성화한다.
- `FastFigureShell`의 graph workspace에 data/object editor 다음, graph file actions 이전 순서로 새 editor를 배치한다.
- `window.FastFigureMantineUi` export에도 새 component를 추가한다.

## 선택 이유

현재 graph layout의 기능 경계는 이미 `CHART_LAYOUT_CHANGED`에 존재한다. 따라서 Mantine 전용 command, presentation store, legacy form adapter를 추가하는 것은 같은 상태를 두 번 소유하게 만들 뿐이다. React component가 project/chart model을 읽고 기존 EFSM event를 호출하는 것이 `plan-006`의 목표 경로인

`Mantine UI → existing UI FSM/event or functional command → existing EFSM/project model → existing renderer`

에 가장 직접적이다.

네 축은 현재 source의 `currentAxes()`와 `axisFields()`가 동일 구조를 반복하므로, Mantine에서도 하나의 axis renderer를 네 axis key에 재사용한다. 이 방식은 축마다 별도 state/handler를 만드는 것보다 구조가 작고 기존 데이터 형식과 일치한다.

## 기각한 대안

1. **Mantine control이 legacy `#title`, `#xBottomMin` 등의 DOM 값을 갱신하고 `applyGraphLayoutSettings()`를 호출하는 방식**
   - legacy DOM을 새 UI의 중간 state owner로 유지하므로 장기 bridge가 된다.
   - `plan-006`에서 금지한 Mantine → legacy DOM 경로에 해당하므로 기각했다.

2. **React local state에 graph layout 전체 snapshot을 별도 보관하는 방식**
   - project/chart model과 양방향 동기화가 필요해진다.
   - persistent functional meaning에 두 번째 source of truth를 만들기 때문에 기각했다.

3. **`fast-figure.js`에 Mantine용 graph-layout adapter를 새로 추가하는 방식**
   - 기존 `CHART_LAYOUT_CHANGED`가 이미 필요한 value boundary를 제공한다.
   - UI-specific helper를 core에 추가할 필요가 없어 기각했다.

4. **이번 단계에서 legacy `axisFields()`와 graph layout handlers까지 제거하는 방식**
   - 아직 single-shell cutover가 완료되지 않았고 legacy UI가 fallback으로 존재한다.
   - feature-equivalence 확인 전 broad legacy removal은 `plan-006` 순서와 맞지 않아 보류한다.

## 상태 권한과 경계

- persistent authority: `activeProject.charts[*].editor`, 특히 `chart.editor.globalSettings`와 `chart.editor.title`
- transition boundary: `CHART_LAYOUT_CHANGED`
- renderer: 기존 `layout(chart)`, Plotly/dashboard render 경로
- React local state: 추가하지 않음
- legacy DOM: Mantine graph-layout editor의 read/write 경로에서 사용하지 않음

## 선행 조건

- `20260909-007`이 적용되어 Mantine graph/data editor와 현재 graph workspace 구조가 존재해야 한다.
- 현재 `main` 기준 적용 커밋은 `172e2cd417f67dd2c51792dc08f8fe9e819b8b11`이다.

## 검증

workflow에서 다음을 수행해야 한다.

- `git apply --check`
- `git diff --check`
- `node --check fast-figure.js`
- `node --check fast-figure-ui.js`
- portable HTML build
- split/portable `file://` smoke

수동 확인 항목:

- graph slot에서 global/axis controls가 표시된다.
- imported Plotly 원본 모드에서는 controls가 disabled 상태다.
- editable mode에서 title/legend/zero-line/font settings 변경이 즉시 dashboard에 반영된다.
- 아래/위 X축, 왼쪽/오른쪽 Y축 각각의 title/range/tick/notation/scale/divide/style/visibility가 독립적으로 저장된다.
- log scale에서는 tick-mode button이 minor-tick toggle 의미로 동작하고, linear/reciprocal에서는 `plotly`/`increment`를 전환한다.
- FFPX/FFSX roundtrip 후 `globalSettings.axes` 값이 유지된다.
- Mantine handler가 legacy graph form `.value`, `.click()`, legacy dialog를 호출하지 않는다.

## 후속 작업

- graph palette save/load/reset의 Mantine ownership을 graph editor와 일관되게 정리한다.
- 이후 layout/label/caption/print 등 `review-010`의 남은 ownership 단위를 계속 이전한다.
- 모든 inventory가 Mantine에서 feature-equivalent가 된 뒤 single-shell cutover와 legacy generic UI 제거를 수행한다.

## 롤백

이 패치는 `fast-figure-ui.js`에만 영향을 준다. 롤백 시 `FastFigureGraphLayoutEditor` 정의, `FastFigureShell`의 component mount 한 줄, `window.FastFigureMantineUi` export 한 줄을 제거하면 된다. `fast-figure.js`, EFSM, chart model, file format에는 변경이 없으므로 `20260909-007`을 포함한 이전 graph/data editor는 독립적으로 유지할 수 있다.
