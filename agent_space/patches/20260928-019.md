# 20260928-019

## 목적과 변경 내용

UI 색상 Modal의 `기본값` 버튼이 `적용` 전에 프로젝트 팔레트를 바꾸는 문제를 수정한다. 기존 `resetPalette()` command를 누르던 동작을, API가 제공하는 기본값 사본을 Modal의 `draft`에 넣는 동작으로 바꾼다. `적용`은 계속 `setPalette(draft)`로 커밋하고, `취소`와 Modal 닫기는 프로젝트 상태를 바꾸지 않는다.

기본값의 정의는 기존 `DEFAULT_UI_PALETTE` 한 곳에 남는다. 새 `appearance.readDefaultPalette()`는 그 값을 읽기 전용 사본으로 돌려준다. 즉시 초기화가 필요한 기존 `appearance.resetPalette()` API는 유지된다.

## 선택 이유

현재 Modal은 열 때 팔레트를 draft로 복사하고, 적용할 때만 저장하며, 취소할 수 있는 편집 흐름이다. 기존 `기본값`만 즉시 `activeProject.appearance.uiPalette`를 변경해 취소가 취소로 작동하지 않았다. 초안에 기본값을 채우면 단일 영속 상태와 적용·취소 규칙이 일치한다.

## 고려했지만 선택하지 않은 방향

- **`기본값`을 즉시 초기화한 뒤 Modal을 닫기:** 취소 버튼과의 충돌은 피하지만 같은 편집창에서 기본값을 확인·추가 수정한 뒤 적용하는 흐름을 없앤다.
- **Modal을 열 때 이전 팔레트를 보관하고 취소 시 되돌리기:** 적용 전에도 영속 상태를 바꾸고, 취소·바깥 클릭·Escape마다 역변경을 맞춰야 한다. 팔레트 draft를 이미 사용하는 구조에 불필요한 복구 경로다.
- **기본값 색상 10개를 UI 소스에 복제:** API 추가는 피하지만 domain 기본값과 UI 초안의 정의가 갈라져 후속 변경에서 불일치할 수 있다.

## 롤백과 후속 작업

역적용하면 `기본값`이 다시 즉시 프로젝트 팔레트를 초기화한다. FFPX/FFSX 형식과 domain 팔레트 값은 변경하지 않는다. 전체 UI 상호작용·파일 입출력 회귀 검사는 계속 남아 있다.
