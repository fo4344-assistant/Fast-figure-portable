# 20260916-011 — Confine graph-data runtime buffers to the native UI ownership unit

## Purpose
Continue the SoT/API-boundary repair from `review-011-sot-api-boundary.md` and patches `20260916-008` through `010`.

After `activeCsvId` was removed, four historical graph-data runtime values still crossed ownership boundaries:

- `activeDataName`;
- `activeDataReady`;
- `rows`;
- `columns`.

`rows` and `columns` are native graph-editor preview/form buffers. They are allowed to exist temporarily while that legacy UI remains, but they must not be maintained or consumed by the application logic EFSM, project import/rollback, shared loader, chart activation, or graph renderer. `activeDataName` and `activeDataReady` have no independent authoritative meaning and are removed rather than retained as additional mirrors.

## Ownership decision

- Project CSV rows/header metadata are owned by project/domain state.
- Current project asset selection is owned by the application logic EFSM (`assetPath` / `assetSelection`).
- Graph objects own their explicit `csvId` references.
- Native `rows` / `columns` are frontend UI buffers only. They may be written/read by the still-existing native preview/form functions, but no backend/core or other subsystem may reference them.
- `activeDataName` and `activeDataReady` are redundant projections, not SoTs and not valid shared interfaces.

## Exact changes

1. Remove `activeDataName` and `activeDataReady` globals entirely.
2. Stop slot-selection, slot-type, slot-reset and slot-swap logic-EFSM/domain actions from clearing, snapshotting, or restoring graph-data UI buffers/readiness mirrors.
3. Remove implicit native-buffer/DOM defaults from the shared table helpers:
   - `headerLineCount(value, table = [])`;
   - `columnDefinitions(table = [], headerLines = 1)`;
   - `dataRows(table = [], headerLines = 1)`.
   All domain/backend callers already provide authoritative table/header arguments; native UI callers also pass their buffer explicitly.
4. Remove the backend graph-renderer fallback `c.rows || rows`. `traces()` already supplies each graph object's project CSV rows and header lines from `requireProjectCsv(...)`; `tracesSingle()` therefore falls back only to an empty local value, never to the UI buffer.
5. Make `activateChartModel()` activate only the chart/workspace model. It no longer projects CSV rows/name/readiness into native graph UI memory.
6. Keep the legacy native `applyGraphSettings()` functional without a shared readiness mirror by deriving readiness locally from its own `rows` / `columns` UI buffers.
7. Remove `rows`, `columns`, `activeDataName`, and `activeDataReady` from project-runtime capture/restore/reset. Project load/rollback must not treat frontend buffers as authoritative runtime state.
8. Remove graph-data buffer bookkeeping from the shared file loader. Its completion log reads the created/replaced CSV SoT (`csv.rows.length`) rather than the UI buffer.
9. Remove the dead `activeDataName` projection from the native graph-object selection path. The native UI still explicitly loads the selected CSV into its own `rows` / `columns` buffers through `loadData()`.

## Why this direction
The same JavaScript bundle contains frontend and backend/core code, but that physical packaging does not erase the architecture boundary. A UI cache becomes a second state interface if core code resets it, snapshots it, restores it, or uses it as a renderer fallback.

The intended direction after this patch is:

```text
project/domain CSV SoT + graphObject.csvId
  -> explicit domain/read helpers
  -> renderer / backend logic

native graph UI
  -> loadData(...)
  -> local/shared-within-native-UI rows/columns buffer
  -> native preview/form only
```

The forbidden direction removed here is:

```text
logic EFSM / project loader / renderer
  <-> rows / columns / activeDataReady / activeDataName
```

## Rejected alternatives

- Promote `rows` / `columns` to a shared API/router state: rejected. They are derived UI buffers and must not become another SoT.
- Keep `activeDataReady` synchronized with selected CSV/chart state: rejected. Readiness is derivable and synchronization would preserve duplicate state.
- Make the renderer query the native UI buffer when a graph object has no CSV: rejected. Rendering must follow the graph object's project CSV reference and fail/empty locally rather than borrow frontend state.
- Remove the entire native graph editor in this patch: rejected. That is a later UI ownership/cutover unit; mixing it here would obscure the SoT repair and increase rollback scope.
- Modify image-side mirrors (`activeImageId`, `activeAssetKind`) in the same patch: rejected. They require a separate ownership audit.

## SoT status after this patch

- CSV identity/content remains in project/domain state.
- selected project asset remains in the application logic EFSM.
- graph-to-CSV relation remains `graphObject.csvId`.
- `activeDataName` and `activeDataReady` no longer exist.
- `rows` and `columns` survive only for the legacy native graph UI and are no longer part of logic-EFSM, project rollback, shared loader, chart activation, or renderer state.

No new cache, adapter state, API, router, or synchronization path is introduced.

## Logic EFSM / frontend impact
No logic-EFSM transition/event contract is changed. Slot selection/type/reset/swap still perform their domain/workspace transitions; they simply stop managing frontend graph-data buffers.

No Mantine state contract is changed. The active Mantine graph editor continues to read project CSVs and graph objects from the authoritative paths established by `008`-`010`.

The native graph editor remains WIP compatibility UI and retains its own `rows` / `columns` preview/form buffer until that UI ownership unit is removed.
