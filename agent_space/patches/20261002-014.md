# 20261002-014 — r7 lineage metadata correction

## 목적과 변경 내용

20261002-013의 애플리케이션 source 수정은 정상적으로 r7 fingerprint를 만들었지만,
`development-versions.json` revision field 자동 치환이 잘못된 계층에 적용된 기록 오류를 보정한다.

보정 전 잘못된 상태:

- verification-model revision: 7
- source-code revision: 6
- verification-model 실제 fingerprint/content: r6 그대로
- source-code 실제 fingerprint/content: r7

보정 후:

- verification-model revision: 6
- source-code revision: 7
- verification-model fingerprint/content와 revision 일치
- source-code fingerprint/content와 revision 일치

또한 `20261002-013.patch`를 당시 실제 diff에 맞게 정정하고
`20261002-013.md`에 오류 원인과 014 보정 관계를 기록한다.

## 오류 원인

013 metadata 생성 코드가 계층 경계를 지정하지 않고 첫 번째
`"revision": 6` 문자열을 교체했다.

당시 manifest에서 verification-model과 source-code가 모두 revision 6이었기 때문에
먼저 등장하는 verification-model revision이 7로 바뀌었다.

fingerprint와 validation review는 source-code 고유 문자열을 기준으로 바꿨기 때문에 정상적으로 r7을 가리켰다.

## 선택한 방향

application source와 regression test는 이미 의도한 r7 변경이며
browser inline regression에서도 새 label typography 검사가 통과할 수 있는 상태다.

따라서 source를 되돌렸다 다시 적용하지 않고 lineage metadata만 실제 계층과 맞춘다.

기존 013 patch 기록은 잘못된 metadata diff를 숨기지 않고 당시 실제 diff로 고쳐 보존한다.

## 고려했지만 선택하지 않은 방향

### verification-model을 r7로 유지

verification model 파일은 변경되지 않았고 fingerprint도 r6 그대로다.
revision만 올린 상태는 lineage 의미와 일치하지 않는다.

### source-code를 r6로 유지

source-code fingerprint와 source 파일이 r6와 다르므로 현재 source를 r6로 표시할 수 없다.

### 013 커밋을 강제 rewrite

이미 main과 distribution artifact commit이 뒤따랐으며 history rewrite는 불필요하고 rollback 추적성을 낮춘다.

## Source Script / verification / source code

- Source Script: r12 유지
- verification-model: r6 복원
- source code: r7로 보정
- source-code fingerprint 변경 없음:
  `sha256:afbd3878736c6f01ea0fce5096605f8811861b850953d62b8dd4d7f084ffc3b8`
- validation review: review-025 유지

application source file은 이 패치에서 변경하지 않는다.

## 검증

`scripts/check-development-layer-versions.py`가 current tree에서 다음을 확인해야 한다.

- verification-model r6 fingerprint 일치
- source-code r7 fingerprint 일치
- derived_from 관계 유지
- source-code current / TLC passed

## rollback

이 보정만 되돌리면 잘못된 lineage metadata가 다시 나타나므로
013 application source까지 함께 되돌리는 경우가 아니라면 단독 rollback하지 않는다.
