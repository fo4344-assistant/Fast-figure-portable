# 20260906-013 — legacy UI infrastructure 초기화 경계 도입

## 목적

현재 `fast-figure.js` 끝부분에 직렬로 나열된 초기화 중 legacy/native UI infrastructure 설치 단계를 명시적인 함수 경계로 묶는다.

`FastFigureShellStaging`은 현재 component export만 존재하고 `createRoot`/mount 경로가 없다. React/Mantine shell cutover를 안전하게 하려면 먼저 어떤 초기화가 native UI owner에만 필요한지 코드상으로 분리할 필요가 있다.

이번 단계에서는 domain/project bootstrap과 lifecycle ready 전이를 이동하지 않고, 명백히 legacy DOM control/event infrastructure를 설치하는 연속 구간만 `installLegacyUiInfrastructure()`로 캡슐화한다.

## 변경 내용

- 앱 버전 `1.1.116-alpha` → `1.1.117-alpha`
- 다음 기존 초기화 호출을 `installLegacyUiInfrastructure()` 안으로 이동
  - `syncHeaderHeight()`
  - `syncPopupBounds()`
  - `applyDashboardZoom()`
  - legacy graph/slot toggle 초기값 synchronization
  - `installHelpPopups()`
  - `installSidebarControls()`
  - `installAssetTreeInteractions()`
  - `connectLifecycleTasksToFSM()`
  - `installLayoutResizer()`
  - `axisFields()`
  - `graphColorInputs()`
  - `renderGraphObjects()`
- 기존 위치에서 `installLegacyUiInfrastructure()`를 한 번 호출

## 의도적으로 이동하지 않는 초기화

다음 호출은 이번 패치에서 함수 안으로 넣지 않는다.

- `ensureDefaultCsv()`
- `refreshCsvControls()`
- `installSlotClickController()`
- `makeSlots()`
- `applySlotStyle()`
- project name initial sync
- `syncEditableUi(null)`
- `appFSM.ready()`
- init-complete debug/audit

이 중 일부는 향후 React owner에서도 공통으로 필요하고, 일부는 현재 dashboard renderer/native presentation 양쪽 의미가 섞여 있다. 이번 단계에서 억지로 legacy/domain으로 분류하면 초기화 순서나 source of truth 의미를 바꿀 위험이 있으므로 그대로 둔다.

## 의미 보존

호출 순서는 기존과 동일하다. 새 함수 선언 직후 기존 위치에서 즉시 한 번 호출하므로 이벤트 binding, 초기 control 값, renderer 준비 시점, default CSV 생성, slot 생성 및 `appFSM.ready()` 전이 순서는 변경되지 않는다.

## Mantine 전환과의 관계

이 패치는 React shell을 mount하지 않는다. 목적은 cutover patch에서 native UI installer를 조건부로 제외할 수 있는 명시적 경계를 만드는 것이다.

특히 `connectLifecycleTasksToFSM()`은 native file/button handler를 wrapping하는 adapter이므로 React owner 전환 뒤에는 별도 React command 경로로 대체되어야 한다. 이번 패치에서는 기존 동작을 보존하기 위해 legacy infrastructure에 포함만 시킨다.

## source of truth / EFSM / core

- EFSM definition/transition 변경 없음
- project/domain state 변경 없음
- 초기화 호출 순서 변경 없음
- FFPX/FFSX/Plotly schema 변경 없음
- React state 추가 없음
- DOM ID/handler 의미 변경 없음

## 선택하지 않은 방향

### 전체 초기화를 한 번에 `initializeLegacyApplication()`으로 묶기

`ensureDefaultCsv()`, `makeSlots()`, `appFSM.ready()`까지 legacy owner로 오해하게 만들어 후속 공통 bootstrap 분리가 어려워진다. 따라서 명백한 native infrastructure 구간만 먼저 분리한다.

### 즉시 React `createRoot`를 추가

현재 공통 bootstrap과 native installer가 아직 완전히 분리되지 않았으며 dashboard renderer/event ownership도 남아 있다. 동시에 owner를 두 개 만들면 동일 DOM/FSM에 이중 event binding이 생길 수 있으므로 선택하지 않는다.

### 초기화 호출 순서를 재정렬

이번 목적에 필요하지 않고 회귀 위험만 증가하므로 하지 않는다.

## 회귀 위험

낮음.

새 함수는 기존 연속 호출을 같은 순서로 감싸고 즉시 같은 위치에서 한 번 호출할 뿐이다.
