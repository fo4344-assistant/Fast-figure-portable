# 20260902-038 — legacy graph object add handler command 재사용 재시도

## 배경

`20260902-037`은 legacy add handler 통합과 선택 object renderer helper 추출을 한 패치에 넣었으나, 현재 `selectGraphObject()` 주변 context가 예상과 일치하지 않아 첫 hunk에서 `git apply --check`가 실패했다. 따라서 HTML에는 아무 변경도 적용되지 않았다.

이번 패치는 실패 범위를 줄여 legacy `#addGraphObject` handler 자체만 공통 command로 교체한다.

## 목적

- legacy add handler의 중복 domain/EFSM 구현을 제거한다.
- `035`의 `fastFigureUiBridge.addGraphObject()`를 legacy와 Mantine이 함께 사용하게 한다.
- 현재 확인 가능한 handler 범위 외 코드는 건드리지 않는다.

## 변경 내용

- 앱 버전 `1.1.79-alpha` → `1.1.80-alpha`
- legacy `#addGraphObject` handler의 직접 `SLOT_DATA_CONNECTED` / `CHART_MODEL_REPLACED` 구현 제거
- `selectedGraphObjectAddModel()`로 현재 add target을 읽고 `fastFigureUiBridge.addGraphObject()` 호출
- 성공 후 canonical chart의 현재 선택 object를 legacy header/data/form/list에 표시

## source of truth

기능 상태 변경은 전부 `035` command가 담당한다. legacy handler는 command 완료 후 canonical chart/object를 다시 읽어 DOM을 표시한다.

legacy DOM의 `configFromForm()`은 더 이상 graph object 추가의 authority로 사용하지 않는다.

## `037`과의 차이

`037`에서 시도한 `renderSelectedGraphObjectLegacy()` helper 추출은 이번 패치에 포함하지 않는다. 현재 source context를 정확히 확보하지 못한 위치를 동시에 건드리지 않기 위해서다.

따라서 이번 패치에는 선택 object renderer 코드가 `selectGraphObject()`와 add handler에 소량 중복된다. 이 중복은 기능 source-of-truth 중복이 아니라 legacy renderer 중복이며, 후속 패치에서 정확한 context 확보 후 정리할 수 있다.

## 변경하지 않음

- `selectGraphObject()`
- `035` add command
- `036` Mantine add button
- EFSM event/action 정의
- Plotly trace/layout
- import/export

## 검증

- patch apply/check
- JavaScript syntax
- legacy handler에서 직접 `SLOT_DATA_CONNECTED` / `CHART_MODEL_REPLACED` 호출 제거
- command 후 canonical selected object를 다시 읽음
- Plotly bundle 미접촉

## rollback

- 기존 legacy `#addGraphObject` handler 본문 복원
- 앱 버전 `1.1.79-alpha` 복원

## 후속

성공 후 `selectGraphObject()`와 add handler의 legacy DOM 동기화 부분을 별도 작은 helper로 통합한다. 해당 패치는 현재 source context를 다시 확인할 수 있을 때만 작성한다.
