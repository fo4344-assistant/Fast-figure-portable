# 20260902-029 — graph object 목록 DOM-free mutation command

## 목적

`20260902-021/022`에서 목록 read model을, `024`에서 selection command를, `027/028`에서 graph-object mutation과 legacy list renderer를 분리했다.

이번 패치는 Mantine 목록에서 색상 변경·삭제·순서 이동을 legacy `renderGraphObjects()` handler를 거치지 않고 수행할 수 있도록 명시적 index 기반 command를 추가한다.

## 변경 내용

- 앱 버전 `1.1.72-alpha` → `1.1.73-alpha`
- `selectedGraphObjectListTarget(expectedChartId)` 추가
- `setGraphObjectColorFromIndex(index, color, expectedChartId)` 추가
- `removeGraphObjectFromIndex(index, expectedChartId)` 추가
- `moveGraphObjectFromIndex(from, to, expectedChartId)` 추가
- UI bridge에 세 command를 얇게 노출

## 공통 target 경계

`selectedGraphObjectListTarget()`은 매 호출마다 현재 selected slot/chart를 다시 읽는다.

- image/no-chart/no-editor이면 null
- expected chart id가 현재 chart와 다르면 null
- React snapshot 자체는 source of truth로 사용하지 않음

## 색상 변경

```text
index + color
→ current chart.editor.objects 재조회
→ index 검증
→ 해당 object shallow copy
→ replaceGraphObjects(next, chart.id)
→ GRAPH_OBJECTS_REPLACED
```

selection을 변경하지 않는다. 기존 legacy color input도 대상 row index만으로 동작하므로 의미가 일치한다.

## 삭제

기존 legacy 순서를 보존한다.

```text
대상 index 제거
→ replaceGraphObjects
→ CLEAR_GRAPH_OBJECT
```

기존 delete handler도 저장 후 selection을 무조건 clear한다. 이번 command도 같은 의미를 유지한다.

마지막 object 삭제 시 기본 object recovery는 기존 `applyGraphObjectsReplacedAction()`이 담당한다.

## 순서 이동

기존 drag/drop의 selected index 보정 규칙을 그대로 옮긴다.

- selected == from → selected = to
- from < selected <= to → selected--
- to <= selected < from → selected++
- selection 없음 → null 유지

보정된 index는 기존과 같이 `SELECT_GRAPH_OBJECT` event로 보낸 뒤 object 배열을 `replaceGraphObjects()`로 저장한다.

직접 `selectedObjectIndex`를 새 UI에서 수정하지 않는다.

## source of truth

- object list: chart `editor.objects`
- selection: graphObject EFSM / `selectedObjectIndex`
- React list model: read-only snapshot
- chartId: stale callback guard

새 state owner를 추가하지 않는다.

## 기존 코드 재사용

- mutation: `replaceGraphObjects()`
- EFSM mutation: `GRAPH_OBJECTS_REPLACED`
- selection: `SELECT_GRAPH_OBJECT`, `CLEAR_GRAPH_OBJECT`
- object recovery/normalization/rebuild: 기존 action

## 이번 패치에서 legacy handler를 바꾸지 않는 이유

먼저 command 자체가 정상 적용되고 기존 EFSM과 충돌하지 않는지 검증한다. active legacy color/delete/drag handler는 후속 패치에서 같은 command로 통합한다.

이렇게 하면 command 추가와 활성 UI 행동 변경을 같은 패치에서 섞지 않는다.

## 변경하지 않는 영역

- add graph object
- palette save/load/reset
- graph object schema
- `GRAPH_OBJECTS_REPLACED` action/transition
- Plotly renderer / trace 생성
- 인라인 Plotly library
- import/export

## 선택하지 않은 방향

### 하나의 범용 `mutateGraphObject(action)` 객체 API

선택하지 않는다. 현재 세 동작은 인자와 selection 후처리가 달라 범용 action schema를 추가할 만큼 이득이 없다.

### row action 전에 자동 선택

선택하지 않는다. color/delete/reorder를 위해 사용자의 selection 의미를 인위적으로 바꾸지 않는다.

### React local objects 배열 수정 후 저장

선택하지 않는다. snapshot을 권위 상태로 승격하게 된다. command는 항상 canonical chart에서 다시 읽는다.

### 새 EFSM event 추가

선택하지 않는다. 기존 selection 및 object-replacement event로 충분하다.

## 회귀 위험

중간 이하이다. 이번 패치에서는 active legacy handler를 연결하지 않으므로 사용자 행동은 바뀌지 않는다.

검사:

- stale chart id 거부
- invalid index 거부
- color 변경 시 selection 유지
- delete 후 selection clear
- reorder 후 기존 selected index 보정
- no-selection reorder 시 none 유지
- 마지막 object 삭제 recovery 유지
- editable validation은 기존 `GRAPH_OBJECTS_REPLACED` action에 위임
- Plotly/trace diff 없음

## rollback

- bridge 세 method 제거
- 네 command/helper 제거
- 앱 버전을 `1.1.72-alpha`로 복원

`021/022/024/027/028`은 독립 유지 가능하다.

## 후속

1. active legacy row handlers를 이번 command로 통합해 mutation 규칙 중복 제거
2. 성공 후 Mantine graph object list staging renderer 연결
3. add-object는 별도로 `SLOT_DATA_CONNECTED` / `CHART_MODEL_REPLACED` 의미를 검토

## Plotly 조회 범위

이번 작업은 graph object list application helper만 다룬다. 인라인 Plotly library 본문은 읽거나 수정하지 않는다.
