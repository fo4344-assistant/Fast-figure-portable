# 20260906-012 — layout command / legacy control synchronization 분리

## 목적

Mantine layout modal의 `fastFigureUiBridge.applyLayoutSettings()` 경로가 legacy layout form controls에 직접 의존하지 않도록 분리한다.

현재 `applyLayoutSettingsFromValues()`는 새 grid/slot style을 model에 반영한 뒤 `applySlotStyle(false)`를 호출한다. `applySlotStyle()`는 dashboard/layout renderer 스타일 적용뿐 아니라 `#dashboardReferenceWidth`, `#slotGap`, `#dashboardOuterMargin`, `#slotRadius`, `#dashboardAspect`, `#showSlotBorders`에 값을 쓰는 legacy form synchronization도 함께 수행한다.

React/Mantine shell cutover 후 이 native controls를 제거하면 bridge의 layout command가 renderer 적용 전에 null control 접근으로 실패할 수 있다.

## 변경 내용

- 앱 버전 `1.1.115-alpha` → `1.1.116-alpha`
- legacy slot-style form synchronization을 `syncLegacySlotStyleControls(style)`로 분리
- `applySlotStyle(fromControls, notify, syncControls)`에 세 번째 인자를 추가
  - 기본값은 `true`로 두어 기존 legacy 호출 의미 유지
  - renderer styling, geometry sync, layout notification은 기존 함수에 유지
- `applyLayoutSettingsFromValues()`는 `applySlotStyle(false, true, false)`를 사용해 Mantine/domain command에서 native form synchronization을 건너뜀
- 분리 후 불필요해지는 local `outerMargin` alias 제거

## 의미 보존

### legacy UI

기존 `applySlotStyle()` 호출은 세 번째 인자의 기본값이 `true`이므로 native controls 동기화가 계속 수행된다. `showSlotBorders`, grid controls, project load 등 기존 경로의 observable 동작을 바꾸지 않는다.

### Mantine UI

Mantine layout command는 `values`에서 직접 slot style model을 구성한 뒤 dashboard/layout renderer에 적용한다. native layout input의 존재 여부와 무관하다.

### renderer

다음 동작은 그대로 유지한다.

- dashboard/layoutMap/dashboardCaption border CSS variable 적용
- fixed aspect class 및 aspect ratio 적용
- reference geometry 갱신
- dashboard caption width 동기화
- `LAYOUT_STYLE_CHANGED` notification

## source of truth / EFSM / core

- layout source of truth는 `activeProject.layout.slotStyle` 그대로 유지
- `GRID_LAYOUT_CHANGED` 및 workspace transition 의미 변경 없음
- grid rebuild/slot preserve 로직 변경 없음
- FFPX/FFSX schema 변경 없음
- 새 React/global state 없음

## 선택하지 않은 방향

### `applySlotStyle()` 전체를 React component effect로 이동

현재 dashboard renderer와 export/layout geometry가 동일 함수를 공유하므로 cutover 이전에 renderer ownership까지 동시에 바꾸면 영향 범위가 커진다. 이번 단계에서는 native form synchronization만 분리한다.

### legacy controls를 optional chaining으로만 감싸기

동작은 피할 수 있지만 owner-independent command와 legacy presentation 경계가 계속 섞인다. 명시적인 adapter/helper 분리가 rollback과 cutover 검증에 더 적합하다.

## 회귀 위험

낮음~중간.

`applySlotStyle()` signature가 확장되지만 기존 두 인자 호출은 기본값 때문에 동일하게 동작한다. Mantine command 경로만 legacy form sync를 생략한다.

## rollback

`syncLegacySlotStyleControls()` 내용을 `applySlotStyle()` 내부로 되돌리고 세 번째 인자를 제거한 뒤 `applyLayoutSettingsFromValues()`를 `applySlotStyle(false)`로 복원하고 앱 버전을 `1.1.115-alpha`로 되돌린다.
