# 20261014-010 — Restore common centered settings Modal geometry

## 목적과 변경 내용

직접 `Modal.Root / Content`를 조립하면서 생긴 settings popup geometry 회귀를 수정한다.

- Layout / Label / Caption / Print 공통 wrapper를 다시 Mantine 편의 `Modal`로 되돌린다.
- 공통 `size = min(96vw, 1320px)`와 `centered: true`를 명시한다.
- theme의 Modal lifecycle/portal/overlay/header/content 구성을 다시 그대로 사용한다.
- resize handle은 `Modal` root가 소유한 실제 `[data-modal-content]`를 찾아 높이만 변경한다.
- resize 시작 시 현재 content top을 기록하고 Modal inner를 그 top에 고정한다.
- 이후 drag는 `--modal-content-height`만 바꾸므로 윗변은 고정되고 아랫변만 움직인다.
- 최대 높이는 고정된 top에서 viewport 하단까지의 남은 공간으로 제한한다.
- source-code r22 / APP build `1.1.42-wip`.

## 회귀 원인

직접 compound Modal을 사용한 구현은 `fastFigureTheme.components.Modal.defaultProps`를 사용하는 기존 편의 Modal 경로를 우회했다.

그 결과 popup의 실제 width/centering behavior가 기존 settings popup과 달라졌고, resize 중 content height와 Modal inner 정렬이 함께 다시 계산되어 handle drag가 popup 전체 이동처럼 보였다.

## 일반 코딩 정책 적용

- settings popup의 폭/기본 lifecycle은 하나의 공통 Mantine Modal primitive가 소유한다.
- popup height는 component-local geometry이며 project state에 저장하지 않는다.
- resize는 현재 component가 생성한 DOM content만 조작하며 legacy hidden DOM이나 외부 bridge를 사용하지 않는다.
- 네 overlay가 같은 helper를 공유한다.

## 회귀 테스트

test 29를 다음 의미로 강화했다.

- 네 settings popup 실제 content width가 동일.
- popup 실제 content가 수평 중앙에 위치.
- resize 후 width 불변.
- resize 후 top edge 불변.
- resize 후 height만 변화.
- resize 뒤에도 수평 중앙 유지.

## 고려했지만 선택하지 않은 방향

- compound Modal을 유지하며 Root/Content별 style을 추가 보정: 이미 Mantine 편의 Modal이 제공하는 공통 behavior를 다시 수동 구현하게 되므로 기각.
- centered 상태에서 높이만 변경하고 재중앙 정렬 허용: 사용자가 지적한 popup 전체 이동 현상을 유지하므로 기각.
- popup별 width/position 보정: 분산된 UI geometry를 다시 만드는 것이므로 기각.
