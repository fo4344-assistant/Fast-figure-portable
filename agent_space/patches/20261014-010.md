# 20261014-010 — Drive settings Modal geometry through Mantine content variables

## 목적과 변경 내용

Mantine 9.5.2가 Modal content 높이에 실제로 사용하는 CSS variable을 통해 resize geometry를 제어한다.

- 초기 높이: `--modal-content-height: min(72dvh, 720px)`
- 최대 높이: `--modal-content-max-height: calc(100dvh - 24px)`
- drag 중 계산된 px 높이는 `contentRef.current.style.setProperty("--modal-content-height", ...)`로 적용.
- regression 진단도 일반 `style.height` 대신 Mantine content-height variable의 갱신을 확인.
- source-code revision r21, APP build `1.1.41-wip`.

## 확인된 원인

진단 regression `20261014-009`에서:

1. mousedown handler는 실행됨.
2. mousemove handler도 실행되어 inline geometry 값이 적용됨.
3. 그러나 `getBoundingClientRect().height`는 변하지 않음.

Mantine 9.5.2 `Modal.module.css`를 다시 확인한 결과 content geometry는 다음 package variable로 정의되어 있다.

- `height: var(--modal-content-height, auto)`
- `max-height: var(--modal-content-max-height, ...)`

따라서 일반 height를 병렬로 덮는 대신 package가 제공하는 실제 geometry control point를 사용한다.

## 선택 이유

외부 selector나 Mantine 내부 DOM 추측이 아니라 실제 vendored version의 공식 component CSS contract를 사용한다. settings Modal의 component-local geometry만 바꾸며 project/domain state는 추가하지 않는다.

## 고려했지만 선택하지 않은 방향

- Mantine CSS에 `!important` override 추가: package contract를 우회하므로 기각.
- wrapper div 자체를 resize: Modal content와 scroll/transition geometry가 분리되므로 기각.
- regression 제거: 실제 요구 기능 검증을 잃으므로 기각.
- 별도 popup implementation: Mantine 통합 목적에 반하므로 기각.
