# 20260910-028 — Remove legacy reset/delete asset controls

## Purpose

Remove the legacy sidebar controls for resetting a selected slot and deleting a selected asset now that `FastFigureDataActions` owns both actions with Mantine confirmation UI.

Legacy UI compatibility is not a requirement. FFPX/FFSX compatibility remains untouched.

## Exact changes

### `Fast-figure.html`

- Remove `#resetSelectedSlot`.
- Remove `#deleteSelectedAsset`.

### `fast-figure.js`

- Remove both controls from `REQUIRED_CONTROL_IDS`.
- Remove the `updateFileAvailability()` visibility synchronization for `#resetSelectedSlot`.
- Remove the old `#resetSelectedSlot.onclick` handler, including its native `window.confirm()` path.

There is no remaining legacy delete handler; its command wrapper was already removed in `20260910-019`.

## Source of truth

`FastFigureDataActions` already determines reset/delete availability from `appFSM` state and project VFS/model state. It opens Mantine confirmation modals and sends the existing `SLOTS_RESET`, `DATA_OBJECT_DELETED`, `IMAGE_OBJECT_DELETED`, `GRAPH_OBJECTS_REPLACED`, and selection events as appropriate.

## File-format compatibility

No FFPX/FFSX read/write/package code, versioning, or serialized project state is changed.

## EFSM / core impact

None. Existing FSM actions remain the execution path. This patch only removes a duplicate legacy UI entrypoint and its presence audit.

## Rationale

Retaining a native-confirm fallback would leave two UI ownership paths for the same destructive action. With legacy UI compatibility explicitly excluded, the Mantine path should be the only generic UI owner.

## Rejected alternatives

- Keep hidden buttons as fallback: rejected; legacy UI compatibility is not required.
- Keep the native confirm handler callable without a button: rejected; the Mantine action already expresses the same operation through existing FSM events.
- Move deletion/reset semantics into React-local project mutations: rejected; the existing EFSM/project model remains authoritative.

## Validation

Repository CI must pass patch application, JavaScript syntax checks, portable build, and split/portable Chromium `file://` smoke tests.

## Rollback

Revert the application commit for `20260910-028` to restore the two legacy controls and native reset handler. Project/file-format data is unaffected.
