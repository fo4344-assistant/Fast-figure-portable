# 20261001-021 — Source Script r12 slot-local default 판정 통합

## 변경 원인

r11 closure review에서 사용자 명시 원칙인
“slot별로 적용되는 하위 내용은 slot object 하위 속성이고 slot object와 함께 이동한다”를
grid shrink와 merge의 data-loss guard까지 추적했다.

기존 r11은 chart/image reference와 caption을 주로 비어 있음 판정에 사용했기 때문에,
reference가 없어도 의미가 남는 contentType 또는 non-default imageSettings만 가진 slot을
grid shrink/merge 과정에서 암묵적으로 버릴 가능성이 있었다.

## 의미 변경

- `SLOT_LOCAL_DEFAULTS`를 slot-local empty/default state의 단일 정의로 추가
- `slotHasNonDefaultLocalState(slot)`를 공통 판정으로 추가
- 새 slot 및 restored slot은 `SLOT_LOCAL_DEFAULTS`에서 시작
- grid 확대는 모든 slot-local property를 보존
- grid 축소는 제거 대상 slot이 하나라도 non-default local state이면 거부
- merge는 non-default slot-local payload가 최대 하나일 때만 허용
- merge covered slot은 모든 local property를 defaults로 reset
- split anchor는 imageSettings를 포함한 모든 local property를 유지

## 선택 이유

chart/image/caption 같은 현재 field 목록을 grid와 merge가 각각 따로 나열하면
새 slot-local property가 추가될 때 data-loss guard에서 빠질 수 있다.

default 구조와 하나의 공통 판정을 사용하면
“slot object의 하위 속성은 함께 보존·이동한다”는 규칙을 operation마다 다시 해석하지 않아도 된다.

## 기존 안을 채택하지 않은 기록

### grid/merge에서 필요한 field를 각각 직접 나열

채택하지 않는다.

현재에도 imageSettings와 contentType 누락이 실제로 발생했으며,
향후 slot-local property가 늘어나면 같은 문제가 반복될 수 있다.

### image/reference/caption만 실제 content로 간주

채택하지 않는다.

contentType과 imageSettings도 사용자가 slot object에 설정한 영속 local state이므로
reference가 없다는 이유로 암묵적으로 삭제할 수 없다.

## 닫힘 판정 영향

slot-local state의 default/non-default 판정과 layout data-loss guard가 하나의 규칙으로 통합되었다.
r12는 다시 전체 closure review를 통과하기 전까지 current/open이다.

## 하위 단계 전파 범위

pseudocode/source code에서는:

- 하나의 slot-local default constructor/definition
- 하나의 non-default local-state 판정
- grid shrink/merge에서 그 판정 재사용

을 구현해야 한다.
