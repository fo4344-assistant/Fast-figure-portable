# 20260910-014 — Mantine project asset to slot drop

## 목적
Mantine `PROJECT DATA` 트리의 `/slots` 항목을 실제 drop target으로 만들어, 프로젝트 CSV/image asset을 슬롯에 drag/drop으로 연결하는 기능을 legacy asset-tree DOM에 의존하지 않도록 한다.

## 변경 위치
- `fast-figure-ui.js`
  - `FastFigureProjectDataTree()`에 현재 Mantine drag source의 project path를 해석하는 `draggedProjectAsset()`를 추가한다.
  - 휴지통 항목과 directory는 slot 연결 대상으로 거부한다.
  - `/slots`의 각 표시 슬롯 행을 `Text`에서 Mantine `Button`으로 변경한다.
  - slot 행은 클릭 시 기존 `setSelectedSlot()`을 사용해 선택하고, drag-over/drop 시 기존 `connectProjectAssetToSlot()`을 호출한다.
  - drop effect는 `link`로 표시하여 폴더 이동(`move`)과 의미를 구분한다.

## 설계 이유
프로젝트 asset -> slot 연결은 이미 `connectProjectAssetToSlot()`이 CSV의 `SLOT_DATA_CONNECTED`, image의 `SLOT_IMAGE_IMPORTED`, slot selection 및 dashboard render를 한 경계로 처리한다. Mantine에서 이를 복제하지 않고 그대로 호출하면 slot 연결의 기능 authority를 유지하면서 generic UI만 교체할 수 있다.

## 기각안
- legacy `#assetTree`에 synthetic drag/drop event를 발생시키는 방식: 장기 bridge이므로 기각.
- Mantine component에서 `slot.chart`, `slot.imageId`를 직접 수정: EFSM command 경계를 우회하므로 기각.
- `/slots`를 계속 읽기 전용 표시로 두고 dashboard에서만 drop 처리: 프로젝트 explorer의 기존 기능 parity가 사라지므로 기각.

## Source of truth / EFSM 영향
- persistent slot/asset state에는 새 저장소나 React state를 추가하지 않는다.
- project asset location authority는 project VFS 그대로다.
- 실제 slot 연결 mutation은 기존 `connectProjectAssetToSlot()` 및 그 내부 FSM events가 담당한다.
- `dragNodeRef`는 한 drag gesture 동안만 project path를 보관하는 임시 UI state다.

## 롤백
이 패치 하나를 revert하면 Mantine `/slots` 행은 다시 읽기 전용 텍스트가 되고 project asset -> slot drag/drop은 legacy 경로에만 남는다.

## 후속
외부 OS 파일 -> 폴더/slot drop의 import collision UX까지 Mantine으로 옮긴 뒤 legacy `assetTree` drag/drop listener와 native confirm 경로를 제거한다.
