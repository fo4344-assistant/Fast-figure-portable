# 20261013-030 — Add policy-aligned Mantine Tree and overlay repair plan

## 목적

상위 개발 정책을 다시 확인한 뒤 Mantine Tree 전환, trash/data-tree drag 복구, bookmark slot swap projection 갱신, settings overlay resize 복원, Layout preview 종횡비 수정 작업의 실행 계획을 정책 순서와 책임 경계에 맞게 다시 정의한다.

## 변경

- `agent_space/plans/plan-013.md` 추가.
- `plan-012.md`는 이력으로 유지하고, `plan-013.md`가 후속 실행 계획임을 새 문서에서 명시한다.

application source, Source Script, pseudocode, verification model, version metadata는 이 패치에서 변경하지 않는다.

## 선택 이유

- 정책은 Source Script에서 기능 의미를 먼저 닫고 PlusCal pseudocode로 직접 번역한 뒤 Source Code에서 library/browser 세부를 정하도록 요구한다.
- Mantine `Tree` 사용 여부는 구현 선택이지만 tree move/slot connection/trash/overlay resize의 사용자 관찰 가능 의미는 상위 명세에서 먼저 확정해야 한다.
- VFS, selection, overlay-local sizing, preview projection의 authority를 분리해 Mantine 내부 state나 DOM 측정값이 별도 source of truth가 되지 않도록 해야 한다.
- 현재 프로젝트는 TLC gate를 사용하므로 상태 의미 변경과 UI-only projection 변경을 구분하고 검증 범위를 기록할 필요가 있다.

## 기각한 방향

- 기존 `plan-012.md`를 덮어쓰기: 이미 기록된 계획 이력을 변경하므로 사용하지 않는다.
- Source Code부터 Mantine Tree로 치환: 상위 의미를 구현에서 다시 결정하게 되어 정책 순서를 위반한다.
- Mantine Tree의 local moved data를 project state로 사용: VFS authority와 양방향 동기화가 생긴다.
- trash를 단일 inactive boolean으로 계속 처리: tree move와 slot connection의 서로 다른 precondition을 다시 결합한다.
- preview resize와 Modal resize를 하나의 width state로 처리: 지난 회귀의 직접 원인이다.

## 전제 및 후속

- 현재 source-script r17 / pseudocode r3 / verification-model r11 / source-code r13은 이 계획 작성 시점의 기준 lineage다.
- 다음 실제 작업은 Source Script 수정부터 시작해야 한다.
- 각 단계는 별도 exact diff patch pair와 해당 closure/translation/validation review를 남긴다.
