# 20260906-033

## 목적

`20260906-032`에서 분리한 파일 충돌 descriptor/resolver를 Mantine 파일 선택 경로에 연결하여, 동일 이름 파일의 **기존 파일 교체 + 참조 유지**와 **새 이름으로 추가** 선택을 기능 축소 없이 Mantine choice Modal로 제공한다.

## 변경 내용

- 충돌 descriptor를 generic choice dialog model로 변환하는 경계를 추가한다.
  - `replace-or-rename`: `기존 파일 교체` / `새 이름으로 추가`
  - `rename-only`: 기존 경고를 보여주고 `새 이름으로 추가`
- generic `FastFigureChoiceStaging` Mantine Modal을 추가한다.
  - 임의의 message와 choice button 배열을 표시한다.
  - 닫기/Escape는 dialog의 `closeValue`를 선택한 것으로 처리한다.
- Mantine sidebar의 파일 선택은 collision choice resolver를 `loadProjectFiles()`에 전달한다.
  - 다중 파일은 기존 순서를 유지하며 충돌이 발생한 파일마다 순차적으로 선택한다.
- `loadDataFile()` / `loadImageFile()`은 이미 계산된 `assetPlan`을 선택적으로 받을 수 있게 한다.
- `loadFileIntoSlot()`도 data/image 파일에 선택적 `assetPlan`을 전달한다.
- `loadProjectFiles()`는 선택적 async `resolveImportChoice`를 받아 각 파일의 계획을 준비한 뒤 기존 loader를 호출한다.
- legacy file input과 다른 호출 경로는 resolver를 전달하지 않으므로 기존 browser confirm/alert adapter를 그대로 사용한다.
- 앱 빌드를 `1.1.137-alpha`로 올린다.

## 기능 보존

- 동일 종류 충돌의 두 선택지를 모두 유지한다.
- Modal을 X/Escape로 닫는 것은 기존 `window.confirm`의 취소와 동일하게 `새 이름으로 추가`로 처리한다. 즉 import 자체를 취소하는 새로운 의미를 만들지 않는다.
- 기본 빈 CSV 또는 다른 종류 충돌은 기존 alert와 동일하게 경고 후 unique 이름으로 계속 import한다.
- 충돌이 없으면 Modal 없이 즉시 기존 import를 진행한다.
- 다중 파일 선택 순서와 파일별 import 결과를 유지한다.
- 선택 슬롯이 이미지일 때 한 파일만 사용하는 현재 동작을 유지한다.
- graph slot, project-only import, FFSX slot import 동작을 유지한다.
- 실제 replace/rename 경로와 ID 결정은 `resolveProjectAssetImportPlan()`을 재사용한다.

## 선택 이유

파일 충돌은 확인/취소가 단순 yes/no 취소가 아니라 두 개의 정상적인 작업 선택지를 뜻한다. 따라서 confirmation Modal에 억지로 넣기보다 generic choice Modal로 올리는 편이 기능 의미를 정확히 보존한다.

파일을 읽는 loader 자체가 UI dialog를 소유하면 domain loader와 React가 강하게 결합한다. 대신 loader는 `resolveImportChoice(dialog)` callback만 선택적으로 받아, Mantine UI가 choice를 제공하고 legacy 경로는 기존 adapter를 사용하는 구조로 분리한다.

## 고려했지만 선택하지 않은 방향

### 확인 Modal의 확인/취소 버튼을 그대로 재사용

취소가 import 취소로 오해될 수 있고 실제 의미는 rename이므로 기각했다.

### 충돌 시 import 전체를 중단할 수 있게 변경

기존에는 rename으로 계속 진행하므로 새로운 기능 의미를 추가한다. 이번 migration 범위에서는 하지 않는다.

### File 객체를 Modal state에 저장

파일은 async import stack에서 유지하고 Modal state에는 일반 dialog model과 Promise resolver만 둔다. UI state를 파일/프로젝트 authority로 만들지 않는다.

### 모든 external drag/drop collision까지 한 번에 변경

asset-tree external multi-drop은 별도의 staged/reserved-path 로직이 있어 회귀 범위가 넓다. 이번 패치는 Mantine FileButton 경로를 먼저 이관하고, 다음 패치에서 같은 choice resolver를 external drop에 재사용한다.

## 위험 요소

- Modal이 열려 있는 동안 async `loadProjectFiles()`가 대기하므로 choice를 반드시 resolve해야 한다. X/Escape도 `closeValue`로 resolve한다.
- `rename-only` dialog는 기존 alert처럼 한 가지 진행 경로만 제공해야 한다.
- replace/rename 선택 후 실제 path 계산은 choice 시점의 VFS와 기존 resolver를 사용한다.
- React state의 resolver는 UI 수명 동안만 존재하며 project state에는 저장하지 않는다.
