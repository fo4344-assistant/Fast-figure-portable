# 20261014-023 — Close full persistent mutation routing in Source Script r23

## 목적

r22 이후 추가 횡단 감사에서 assets/graphs의 원자적 mutation 일부가 projectEFSM command에 명시적으로 수렴하지 않는 문제를 발견했다. 정책에 따라 하위 구현을 진행하지 않고 Source Script로 다시 돌아와 전체 persistent mutation route를 닫는다.

## 변경

- `project_efsm.py`
  - atomic mixed raw-file import를 위한 `ASSETS_IMPORTED` 추가.
  - delete, chart editable conversion, slot-chart import의 기존 command 의미를 실제 whole-project atomicity에 맞게 명확화.
  - `PUBLIC_PROJECT_MUTATION_ROUTES` coverage matrix 추가.
- `assets_files.py`
  - pure batch candidate builder와 `ASSETS_IMPORTED` commit 분리.
  - create/delete/move/trash/directory/connect/import/project-load/FFSX apply의 explicit command route 추가.
- `graphs.py`
  - add/commit/editable/header/layout/palette/import persistent operation의 explicit command route 추가.
- `api_ui.py`
  - persistent public API 설명을 coverage matrix와 동일 command 이름으로 명시.
- Source Script r23 fingerprint/closure 갱신, 하위 계층 stale 전환.

## 새 command를 하나만 추가한 이유

mixed CSV/image batch import와 선택적 target slot 연결은 한 candidate로 원자적으로 성공/실패해야 한다. singular create command 반복으로는 같은 의미를 보존할 수 없어 `ASSETS_IMPORTED`가 필요하다.

asset delete와 chart editable conversion은 기존 command의 본래 대상과 동일한 mutation이므로 새 generic command를 만들지 않고 writable scope/candidate 의미만 확장했다.

## 기각

- file별 create command 반복: batch atomicity 손실.
- 범용 `PROJECT_PATCH`: precondition과 ownership 의미를 감추고 분기 복잡도를 증가.
- asset delete용 새 generic command: 기존 kind-specific delete command와 중복.
- Source Code에서 route를 먼저 결정: 상위 권위 계층 역전.

## 이전 닫힘에서 놓친 점

r22는 layout/annotation/export와 새로 드러난 몇 command를 보정했지만, public mutation을 assets/graphs domain 함수까지 역추적하는 전체 coverage matrix가 없었다. r23은 이 matrix를 닫힘 검증 기준으로 추가했다.

## 후속

pseudocode r8을 r23에 맞게 다시 번역하고, verification/TLC를 새 lineage에서 통과한 뒤에만 Source Code를 수정한다.
