## 모델 구조

persistent state를 다음으로 축약했다.

- gridRows / gridCols
- bounded grid cell별 slot-local payload
- merged-cell cover relation
- 존재하는 chart id 집합

slot-local payload는 다음 의미를 하나의 record로 유지한다.

- chart
- image
- contentType
- imageSettings
- caption

따라서 swap/merge/split/reset에서 일부 field만 이동하는 모델을 만들지 않는다.

## 환경 action

layout operation만으로는 non-default payload가 생기지 않으므로
다른 이미 검증된 domain mutation의 결과를 대표하는 `seed-*` environment action을 둔다.

- seed-chart
- seed-image
- seed-caption
- seed-settings

이는 새 Fast Figure command를 정의하는 것이 아니다.
layout operation이 chart/image/caption/custom-settings를 가진 slot을 만났을 때의
상태공간을 탐색하기 위한 symbolic input이다.

## candidate-first 표현

이 slice의 grid resize/merge는 실제 구현에서:

```text
resolve
→ precondition
→ candidate
→ validation
→ commit once
```

순서를 가진다.

r1에서는 candidate가 authority 밖의 동기 계산이라는 점을 이용해
invalid candidate를 **disabled action**으로 추상화했다.

TLA+ stuttering에서는 invalid request가 persistent project state를 바꾸지 않는 경로로 표현된다.

비동기 validator, lock, callback, concurrent writer가 생기면
이 atomic abstraction으로 충분하지 않으므로 candidate state를 명시적으로 확장해야 한다.

## TLC state-space 축약

검증 가능성을 위해 작은 대표 domain을 사용한다.

- 최대 grid 3 x 3
- 초기 grid 2 x 2
- chart id 2개
- image id 1개
- caption absent/present
- imageSettings default/custom

이는 application 제한이 아니다.

다음 차이는 보존한다.

- default / non-default local state
- chart identity
- image reference 존재
- chart/image mutual exclusion
- merged/visible cell
- grid position
- chart owner 이동

## 제한적 생략과 이유

### runtime selection

`selectedSlotId`와 workspace/graph-object selection은 r1에서 제외했다.

이유:

이번 slice는 persistent project layout/reference integrity만 검증한다.

현재 미검증:

- grid shrink 뒤 제거된 slot을 가리키는 runtime selection 정리

FSM/runtime slice를 추가할 때 반드시 다시 포함한다.

### 단순 read/projection

예:

- ProjectObject.read
- getChart/getProjectImage/getProjectCsv
- dashboard pixel geometry
- renderer projection

이들은 이번 model의 mutation decision에 참여하지 않는 pure read/projection이므로 생략했다.

향후 stale read, TOCTOU, lock, cache consistency 또는 mutation decision의 입력으로 사용되면
정책 §12에 따라 모델에 다시 포함한다.

### file/asset/graph internals

CSV graph object, VFS, FFPX/FFSX, Plotly, export, file I/O는
이번 revision의 범위 밖이며 **검증 완료로 간주하지 않는다**.

후속 verification slice가 필요하다.

### concurrency/lock

이 layout mutation slice는 synchronous atomic commit으로 모델링한다.

실제 구현이 asynchronous validation, multiple writer, lock 또는 callback ordering을 도입하면
현재 모델은 충분하지 않으며 refinement가 필요하다.

## 선택 이유

첫 model에서 전체 project를 한꺼번에 넣으면
TLA+ syntax 문제와 domain counterexample을 구분하기 전에 state space와 모델 복잡도가 급격히 커진다.

slot/layout/chart ownership은:

- 상태 수가 비교적 작고
- Source Script의 핵심 invariant가 명확하며
- swap/reset/merge/split/grid sequence의 조합 오류를 compiler가 검출하기 어려운

독립적인 첫 검증 단위다.

## 고려했지만 선택하지 않은 방향

### 전체 Source Script를 r1에 모두 포함

선택하지 않았다.

### FSM만 먼저 모델링

선택하지 않았다.

현재 가장 강한 project invariant인 chart ownership과 slot-local payload 이동을
직접 검사하지 못한다.

### chart/image/caption을 단순 occupied boolean 하나로 통합

선택하지 않았다.

chart identity와 exact-one ownership,
chart/image mutual exclusion,
non-reference local state(caption/custom imageSettings)를 구분할 수 없어진다.
