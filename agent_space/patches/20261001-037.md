# 20261001-037 — generated TLA+ semantic wiring 수정

## 검사 결과

네 번째 `TLA Slot Core` run:

- PlusCal translation: 성공
- SANY parsing: 성공
- TLC semantic analysis: 실패

주요 오류는 verification code의 generated-TLA wiring 문제였다.

### Sequences module 미포함

procedure call translation이 생성하는 stack handling이
`Head`, `Tail`, `\o`를 사용하지만 module이 Sequences를 extend하지 않았다.

### algorithm variable 선언 전 invariant 참조

`TypeOK`, `SafetyInvariant` 등이
PlusCal translation에서 생성되는 `activeProject`, `lastResult` 변수 선언보다 앞에서
직접 참조하고 있었다.

### verification harness binder 이름 충돌

PlusCal procedure parameter는 translation에서 algorithm variable로 생성된다.
Main harness의 `with slotIds/sourceId/...` binder가 같은 이름을 다시 사용해
generated TLA+에서 multiply-defined symbol이 되었다.

## 변경 내용

- `Sequences`를 EXTENDS에 추가
- `TypeOK(project, result)`를 순수 parameterized operator로 변경
- algorithm 뒤에:
  - `TypeOKSpec`
  - `ChartOwnershipInvariantSpec`
  - `SafetyInvariant`
  wrapper를 두어 generated variable 선언 뒤에 참조
- cfg는 `TypeOKSpec`을 검사
- harness-only binder를 `chosen*` 이름으로 변경해 procedure parameter와 분리

Source Script 대응 함수/parameter 이름은 변경하지 않았다.

## Source Script 영향

없음.

모두 PlusCal/TLA+ generated representation을 정상 연결하기 위한 수정이다.
