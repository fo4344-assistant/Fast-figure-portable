# 20261014-038 — Plan 016 API/Adapter boundary audit

## 목적과 변경

`agent_space/reviews/review-20261014-019-plan-016-boundary-audit.md`를 추가하여 plan-016 §20의 Source Script 변경 전 직접 dependency 감사를 기록한다.

현재 Source Script 11개 파일과 Source Code의 실제 cross-layer 참조를 확인하고, Backend, Application boundary, Frontend 책임 및 selection/reference/projection 흐름을 구분했다. plan-015 완료 상태를 plan-016 완료로 잘못 해석하지 않는다.

특히 InterfaceStateMachine의 projectObjects read, reconciliation의 직접 Backend helper 호출, SELECT_SLOT 후 조건부 SLOT_TYPE_CHANGED, renderer/read API의 live slot imageSettings normalization, domain helper의 application dispatch 역방향 호출, portable_build의 hierarchy 위치를 후속 Source Script 설계에서 처리할 대상으로 기록했다.

## 선택 이유

계획은 Source Script를 변경하기 전에 현재 direct dependency와 ownership을 정확히 추적하도록 요구한다. 기존 plan-015 감사는 EFSM과 interface FSM의 분리를 다루지만 plan-016의 API/Adapter-only 경계를 검사하지 않았으므로 이번 감사의 증거를 별도로 남긴다.

## 고려했지만 선택하지 않은 방향

- plan-015 감사 또는 완료 기록을 수정: 당시 설계와 실행 근거를 덮어쓰므로 선택하지 않았다.
- Source Code에서 먼저 direct access 제거: Source Script/PlusCal hierarchy를 건너뛰므로 선택하지 않았다.
- Frontend 전체가 Backend를 직접 사용한다고 간주: fast-figure-ui.js는 대부분 FastFigureApi를 사용하므로 실제 위반 위치를 구분했다.
- renderer normalization을 harmless read로 가정: live slot field assignment 경로가 있어 확인 전에는 read-only로 판정할 수 없다.
- 이 감사만으로 Source Script r24 closure 선언: architecture와 input contract는 아직 작성되지 않았으므로 선택하지 않았다.

## 실제 변경과 미변경

변경: review 문서 한 파일 추가.

미변경: 정책, plan-016 원문, Source Script, PlusCal, verification model, Source Code, development-versions.json.

Source Script의 revision/fingerprint/closure는 이 감사로 변경되지 않는다. 실제 architecture 변경은 후속 coherent Source Script patch에서 처리한다.

## 검증

- 적용 정책 원문과 plan-016 및 관련 plan-015 review/patch 기록 확인.
- main HEAD 및 development-versions.json 확인.
- Source Script 11개 파일의 책임/import 경계와 fast-figure.js/fast-figure-ui.js의 대표 호출 경로 확인.
