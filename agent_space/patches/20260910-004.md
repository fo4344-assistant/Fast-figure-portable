# 20260910-004 — Mantine print/export ownership 교정본

## 목적
`20260910-003`은 application source에 적용되기 전 `git apply --check`에서 hunk 위치 오류로 실패했다. 기능 설계는 유지하고, 현재 `main`의 실제 line/context를 기준으로 동일한 print/export ownership 구현을 다시 적용한다.

## 변경
- `exportDashboard(capture, options)`가 선택적으로 `{ dpi, format, onStatus }`를 받는다.
- `exportDashboardTarget(options)`가 선택적으로 `{ width, height, dpi, format, onStatus }`를 받는다.
- options가 없는 legacy 호출은 기존 DOM 기반 print controls를 그대로 사용한다.
- options가 있는 Mantine 호출은 legacy print input을 source로 사용하거나 값을 되쓰지 않는다.
- `FastFigurePrintOverlay` Mantine Modal을 추가한다.
- PNG/JPEG, DPI 36–1200, 폭 100–20000, 높이 100–20000 또는 빈 값 자동 높이를 제공한다.
- 설정 크기 저장은 `PRINT_EXPORT`, 현재 화면 캡처는 `CAPTURE_EXPORT` lifecycle을 그대로 사용한다.
- 출력 상태는 React local status로만 유지한다.

## 003 실패와의 관계
`20260910-003.patch`는 `fast-figure.js:7050` 및 `fast-figure-ui.js:20`에서 context/line 위치가 맞지 않아 적용되지 않았다. source 변경은 발생하지 않았다. `004`는 같은 구현을 현재 source의 실제 위치와 충분한 context를 사용해 다시 작성한 대체 패치다.

## 선택 이유
출력 알고리즘을 React에 복제하지 않고 기존 renderer를 값 기반 entry로 확장함으로써 기능 규칙의 단일 source를 유지한다. Mantine에서 legacy `.value`나 `.click()`을 사용하는 bridge도 만들지 않는다.

## 기각안
- 003 설계를 다시 분해하여 선행 helper 패치부터 작성: WIP 우선 구현 원칙에 반하므로 기각.
- Mantine export 알고리즘 복제: 장기 divergence 때문에 기각.
- legacy input을 Mantine에서 조작: DOM bridge이므로 기각.

## Source of truth / EFSM 영향
프로젝트 데이터와 layout/annotation/chart/image 모델은 기존 project object가 계속 source of truth다. print 옵션은 일회성 UI 값이다. `PRINT_EXPORT`/`CAPTURE_EXPORT` lifecycle 및 기존 renderer를 유지하며 FFPX schema는 변경하지 않는다.

## WIP 제한
legacy print panel과 handler는 아직 공존한다. 최종 parity/cutover에서 legacy popup lifecycle과 markup을 제거한다.

## 검증
workflow의 `git apply --check`, JavaScript syntax, portable build, split/portable `file://` smoke를 통과해야 한다.

## Rollback
이 패치를 역적용하면 value-based export options와 Mantine Print Modal만 제거된다. project data/schema migration은 필요하지 않다.
