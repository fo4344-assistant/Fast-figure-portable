## 선택한 방향과 이유

plan-016의 새 검증 property는 project field 값 자체보다 Backend authority가 어느 순서에서 변경되고,
그 결과가 reconciliation과 renderer로 어떻게 전달되는지가 핵심이다.

따라서 기존 Slot/Interaction model에 Application boundary 상태를 중복 삽입하지 않고
pseudocode의 cross-module interface contract만 별도 bounded model로 파생했다.

이는 verification decomposition 정책의 다음 조건을 따른다.

- 기존 module responsibility를 재설계하지 않음
- 다른 module의 내부 state 전체를 복제하지 않음
- 현재 unit이 실제로 관찰하는 projection만 state로 표현
- cross-module invariant가 필요한 경우 interface contract model 허용

## 고려했지만 선택하지 않은 방향

### 기존 Slot Core에 모든 boundary 상태 추가

slot/layout domain state와 Application ordering state가 한 model에 결합되어 상태공간과 책임이 불필요하게 커진다.
pseudocode hierarchy의 Application boundary를 별도 검증 단위로 추적하기 어려워져 기각했다.

### Interaction Core에 renderer/reconciliation ordering 추가

Interaction Core는 CSV/tree/selection domain interaction을 소유한다.
renderer projection ordering은 이 domain 값과 독립적인 cross-layer contract이므로 기각했다.

### Frontend ProjectObject mirror를 verification state로 추가

Source Script r25가 금지한 두 번째 project authority를 model에 도입하는 것이므로 기각했다.

### TLC 없이 passed 처리

실행 증거가 없으므로 기각했다.
