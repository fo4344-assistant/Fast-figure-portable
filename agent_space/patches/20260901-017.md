# 20260901-017

## 목적

Commit B staging에서 아직 placeholder였던 README overlay를 실제 Mantine controlled Modal로 교체한다. README 본문은 이미 단일 HTML에 포함된 정적 문서이므로 내용을 다시 복사하지 않고 문서 소스로 재사용한다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.47-alpha`로 올린다.
- `fastFigureUiBridge.readReadmeHtml()`을 추가한다.
- 기존 `#readmeDialog .readme-content`를 정적 문서 소스로 복제하되 legacy `#closeReadme` 버튼은 제거한 HTML만 반환한다.
- `FastFigureReadmeModalStaging`을 추가한다.
- Modal open/close는 기존 `FastFigureOverlayModalStaging`과 overlay EFSM 경로를 그대로 사용한다.
- README 본문은 Mantine `ScrollArea` 안에 읽기 전용으로 렌더링한다.
- staging overlay host의 README placeholder를 실제 README component로 교체한다.
- staging export 목록에 `FastFigureReadmeModalStaging`을 추가한다.

## 이 방향을 선택한 이유

README는 프로젝트 상태가 아니라 애플리케이션에 포함된 정적 문서이다. 수백 줄의 동일 본문을 React용 상수로 다시 복사하면 문서 원본이 둘이 되고 버전·라이선스·링크 갱신이 어긋날 수 있다. 따라서 cutover 전에는 기존 본문을 정적 소스로 재사용하고, cutover 시 legacy `<dialog>` 껍데기를 `<template>` 또는 동등한 비활성 문서 소스로 바꾸면 같은 helper를 유지할 수 있다.

이 접근에서 legacy popup lifecycle이나 닫기 버튼은 재사용하지 않는다. 재사용되는 것은 문서 본문뿐이다.

## 선택하지 않은 방향

- README 본문 전체를 JavaScript 문자열로 중복 복사하지 않는다.
- legacy dialog의 `showModal()`, `close()`, cancel/backdrop handler를 staging에서 호출하지 않는다.
- `#closeReadme` 버튼을 React 내부에 복제하지 않는다.
- 전체 shell cutover는 수행하지 않는다.

## 검증 항목

- `git apply --check`
- `git diff --check`
- 메인 JavaScript `node --check`
- APP_BUILD와 built-in README 버전 일치
- staging README에서 legacy close control/lifecycle 미사용
- overlay open/close의 EFSM 의미 유지
- README 본문 단일 원본 유지

## 패치에 포함되지 않은 변경사항

이 `.patch`와 설명 `.md` 자체는 재귀적인 diff에 포함하지 않는다. 실제 HTML 수정은 제한된 patch workflow가 검증 후 적용한다.
