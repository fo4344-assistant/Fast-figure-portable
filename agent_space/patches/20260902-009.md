# 20260902-009 — Mantine graph 축 공통 컴포넌트 staging 재분할

## 배경

`20260902-008`은 설계 검토상 Mantine UI 중앙화 범위에 맞지만 GitHub Actions의 `Check and apply patch` 단계에서 실패했다. `Select patch`까지 성공했고 JavaScript 검사와 commit은 실행되지 않았으므로, 실패한 008은 감사·롤백 기록으로 그대로 보존한다.

원 008의 큰 삽입 hunk는 컴포넌트 본문과 unified diff hunk count를 다시 계산할 필요가 있다. 재시도에서 같은 패치를 덮어쓰지 않고 적용 단위를 더 작게 분리한다.

## 목적

축 상세 UI의 공통 구현인 `FastFigureGraphAxisStaging({ chartLayout, axisKey, label })`만 먼저 추가한다. 아직 sidebar에는 연결하지 않는다.

앱 버전은 `1.1.58-alpha`에서 `1.1.59-alpha`로 올린다.

## 변경 범위

추가하는 공통 컴포넌트는 기존 네 축의 UI 의미를 한 곳에 모은다.

- `xBottom`
- `xTop`
- `yLeft`
- `yRight`

컴포넌트가 지원하는 항목은 다음과 같다.

- 축 이름
- 최소/최대
- tick mode / tick 간격
- 로그축 minor tick
- 숫자 표기 방식
- 축 유형
- 값 나누기
- 축 이름 크기
- 숫자 크기
- 축선 굵기
- 격자 표시
- 축 표시
- 값 표시

## source of truth / 쓰기 경계

persisted source는 계속 selected chart의 `editor.globalSettings.axes` 하나뿐이다.

컴포넌트는 `chartLayout` snapshot을 읽고 모든 변경을 기존 경계로 보낸다.

```text
FastFigureGraphAxisStaging
→ fastFigureUiBridge.applyChartLayout({ axes: { [axisKey]: changes } }, chartLayout.chartId)
→ applyGraphLayoutSettings(...)
→ CHART_LAYOUT_CHANGED
→ 기존 Plotly render 경로
```

React state에 axis settings 사본을 만들지 않는다. `TextInput`/`NumberInput`의 focus 중 draft만 컴포넌트 내부에 존재한다.

## 기존 동작 보존

- 비로그축: `plotly`와 `increment`를 기존 의미대로 토글한다.
- 로그축: `tickMode`는 `plotly`로 유지하고 같은 버튼이 `minorTicks`만 토글한다.
- 로그축에서는 tick 간격 입력을 표시하지 않는다.
- scale 선택지는 `linear`, `log`, `reciprocal`을 그대로 사용한다.
- `log` 전환 시에만 `tickMode: "plotly"`를 함께 보낸다.
- notation 선택지는 `none`, `power`, `e`를 그대로 사용한다.
- 텍스트/숫자는 blur에서 commit하고 Enter는 blur 경로로 합친다.
- Select/Switch/tick 버튼은 즉시 commit한다.

## Mantine/Core 분류

이 패치는 inactive Mantine staging용 공통 presentation component만 추가한다.

변경하지 않는다.

- graph/domain 데이터 구조
- graph object EFSM
- `CHART_LAYOUT_CHANGED` event/action/guard
- global settings normalization
- Plotly renderer
- 축 계산 알고리즘
- import/export
- 활성 legacy UI

`20260902-007`의 `expectedChartId` 경계 검사는 재사용만 하며 추가 변경하지 않는다.

## 최소복잡도

네 축에 같은 JSX/callback을 복제하지 않고 axisKey 매개변수 하나로 공통화한다. Mantine 위에 별도 범용 UI framework를 만들지 않으며 Fast Figure의 축 domain 의미와 event mapping만 묶는다.

## 008과의 차이

008이 한 번에 수행하려던 다음 두 작업을 분리한다.

1. 공통 축 컴포넌트 추가 — **009**
2. sidebar Accordion 연결 — 후속 패치

009의 unified diff hunk count는 본문 줄 수를 다시 계산해 생성한다.

## rollback

1. `FastFigureGraphAxisStaging` 함수 제거
2. 앱 버전을 `1.1.58-alpha`로 복원

sidebar가 아직 이 컴포넌트를 참조하지 않으므로 독립적으로 롤백 가능하다.

## 검증

- `git apply --check`

- `git diff --check`
- 마지막 inline JavaScript `node --check`

009가 성공한 뒤에만 sidebar 연결 패치를 작성한다.
