# 20260922-005

## 목적과 변경 내용

layout overlay의 선택 집합을 core 공유 전역에서 제거하고 frontend-local UI input state로 한정한다.

기존 `layoutSelected`는 Mantine overlay가 직접 변경하면서 `mergeSelected()` / `splitSelected()` core 로직도 직접 읽는 공유 buffer였다. 이는 UI 임시값을 다른 로직이 참조하는 구조다.

변경 내용:

- core 전역 `layoutSelected`를 제거한다.
- grid rebuild, project runtime snapshot/rollback/reset에서 layout selection 취급을 제거한다.
- `mergeSelected()`를 `mergeSlots(slotIds)`로 바꾸고 전달받은 정수 slot ID만 검증해 사용한다.
- `splitSelected()`를 `splitSlots(slotIds)`로 바꾸고 전달받은 ID만 사용한다.
- merge 성공 시 빈 selection 배열, split 성공 시 복원된 slot ID 배열을 호출 결과로 반환한다. 이 값은 호출 직후 UI local state 갱신에만 사용한다.
- 사용되지 않던 `clearAllSlotSelections()`를 제거한다.
- core가 `window.FastFigureApi.layout.mergeSlots/splitSlots`를 명시적 public command API로 노출한다.
- Mantine `FastFigureLayoutOverlay`가 `layoutSelection`을 React local state로 소유한다.
- overlay가 닫히면 local selection을 비우고, grid 변경 시에도 local selection을 비운다.
- Mantine은 core 내부 global을 읽지 않고 `FastFigureApi.layout` command에 slot ID 배열을 전달한다.

## 선택 이유

layout slot 선택은 미리보기에서 command 대상을 고르는 UI input이며 project/domain의 영속 상태가 아니다. 따라서 frontend component 안에서만 살아야 한다. merge/split 자체는 project slot SoT를 변경하는 backend command이므로 명시적인 API 경계를 통해 ID를 전달받아 처리한다.

command 반환 배열은 공유 cache가 아니라 한 번의 호출 결과이며 Mantine handler 안에서 즉시 local selection 갱신에만 사용한다.

## 선택하지 않은 방향

### `layoutSelected`를 appFSM에 승격

layout 선택은 영속 의미나 application-wide 상태가 아니라 overlay-local input이다. 공용 SoT로 승격하면 불필요한 상태가 늘어난다.

### core가 UI Set 객체를 계속 참조

UI 임시값을 backend가 읽는 현재 문제를 유지하므로 사용하지 않는다.

### Mantine이 `mergeSlots` / `splitSlots`를 직접 전역 호출

frontend/backend 경계를 명시하기 위해 `FastFigureApi.layout` namespace를 사용한다. 이는 legacy DOM bridge가 아니라 core SoT를 변경하는 공식 command surface다.

### split 결과를 새 global selection에 저장

다시 두 번째 공유 상태가 생기므로 사용하지 않는다. 복원된 ID 목록은 호출 결과로만 반환한다.

## 전제와 후속 작업

- 현재 Mantine layout preview에서 선택 가능한 slot은 visible slot뿐이다. API도 hidden slot ID를 command 대상에서 제외한다.
- 기존 merge/split의 project model 변경, validation message, renderer 갱신, FSM notify 의미는 유지한다.
- 이번 API는 layout merge/split ownership 단위만 노출한다. 다른 Mantine 기능의 backend 직접 접근은 이후 기능군별로 같은 방식으로 API 경계를 정리한다.
- layout style/grid/zoom의 직접 core 접근은 별도 후속 API 경계 작업 대상이다.

## 롤백

역적용하면 `layoutSelected` 공유 전역과 core의 implicit selection 참조가 복원된다. project schema와 FFPX/FFSX 형식에는 변경이 없다.
