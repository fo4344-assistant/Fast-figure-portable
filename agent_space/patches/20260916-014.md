# 20260916-014 — Remove dead native graph axis installers and font-select helpers

## Purpose
Continue the Mantine single-shell cutover after the CSV/image SoT cleanup by removing a closed set of legacy graph-UI helpers that no longer have callers.

The active Mantine graph layout editor already owns graph title/global/axis controls and sends `CHART_LAYOUT_CHANGED` directly. This patch does not remove graph layout semantics or renderer functions; it only removes native DOM construction/installation helpers and definition-only font/color UI helpers.

## Ownership decision

Preserve backend/domain and renderer responsibilities:

- `currentAxes()`;
- `axisRangeValueFromPlotly()`;
- `readGlobalSettings()`;
- `normalizeGlobalSettings()`;
- `axisKey()`;
- chart/global settings stored in the project model;
- `CHART_LAYOUT_CHANGED` logic-EFSM mutation path;
- Plotly layout/render functions.

Remove legacy native UI ownership:

- `GRAPH_FONT_OPTIONS`;
- `fillGraphFontSelect()`;
- `setGraphFontSelectValue()`;
- `syncAxisTickModeControl()`;
- `axisFields()`;
- empty `graphColorInputs()`.

Current-source reference inspection shows the font helpers and `graphColorInputs()` have only their definitions. `syncAxisTickModeControl()` is referenced only by `axisFields()`, while `axisFields()` itself has no caller except the obsolete `REQUIRED_APP_FUNCTIONS` audit entry.

## Mantine coverage

`FastFigureGraphLayoutEditor` already provides direct controls for:

- graph title;
- legend/title/zero-line visibility;
- graph font family, title size, legend size;
- bottom/top X and left/right Y axis title;
- min/max;
- Plotly/increment tick mode and log minor ticks;
- tick interval;
- notation;
- linear/log/reciprocal scale;
- divide;
- axis title/value font sizes;
- axis line width;
- grid/axis/value visibility.

It mutates the authoritative chart state through `CHART_LAYOUT_CHANGED` and `readGlobalSettings()` rather than native form DOM.

## Exact changes

1. Delete the definition-only native graph font option list and select population/custom-value helpers.
2. Delete native tick-mode DOM synchronization and dynamic axis-field construction/handler installation.
3. Delete the empty native graph color input installer.
4. Remove `axisFields` from `REQUIRED_APP_FUNCTIONS`; it is no longer an application/core requirement.

## Why this direction
These helpers are UI renderer/lifecycle code that Mantine has already replaced. Retaining them would keep a second graph-control implementation and native DOM ownership even though no active path calls it.

The patch intentionally stops at the closed installer group. `readAxis()`, `chartLayoutSettingsFromForm()`, `configFromForm()`, `applyGraphLayoutSettings()`, `graphPalette()`, and `applyGraphSettings()` are still a separate legacy form-read/apply ownership chain and will be removed together after a final reference check.

## Rejected alternatives

- Delete all legacy graph code in one patch: rejected because data/object-list form state and layout-form apply logic are separate rollback units.
- Delete `axisKey`, `currentAxes`, or `readGlobalSettings`: rejected because active Mantine and renderer paths use these functional/domain helpers.
- Replace the removed font select with a new Mantine font-option registry: rejected. The current Mantine editor accepts the stored font-family string directly; adding a registry would introduce unnecessary UI policy/state.
- Keep `axisFields()` for compatibility: rejected because it has no caller and rebuilding native controls contradicts the single-shell cutover.

## Rollback
Revert `Apply agent patch 20260916-014`.

No project schema, chart settings schema, FFPX/FFSX format, logic-EFSM event contract, or Plotly renderer semantics are changed.

## Follow-up
Re-audit and remove the remaining closed native graph form-read/apply chain (`readAxis`, `chartLayoutSettingsFromForm`, `configFromForm`, `graphPalette`, `applyGraphLayoutSettings`, `applyGraphSettings`) together with their obsolete `REQUIRED_APP_FUNCTIONS` entries, then proceed to native graph data/object-list UI cleanup.
