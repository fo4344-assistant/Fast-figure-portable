# 20260907-043 — Mantine FFSX / Plotly file action buttons

## Purpose

Continue the Mantine UI port by replacing only the call-side UI for graph-slot file actions while preserving the existing functional EFSM, project model, FFSX implementation, Plotly JSON implementation, and file-input import path.

## Scope

This patch changes only `fast-figure-ui.js`.

It does not modify:

- `fast-figure.js`
- `ApplicationStateMachine`
- `APP_STATE_DEFINITIONS`
- project classes/state
- `ffsxBuildSlot()` / `ffsxReadSlot()`
- `downloadSlotFfsx()`
- `downloadPlotlyJson()`
- `importSlotFile()`
- lifecycle wrapping installed by `connectLifecycleTasksToFSM()`

## Exact changes

1. Adds `runLifecycleTask(lifecycle, eventName, task)` inside the Mantine UI file so the already-required lifecycle call pattern is not duplicated across project, FFSX, and Plotly export buttons.
2. Changes the existing Mantine FFPX export button helper to use this UI-only lifecycle helper without changing its event name or functional command.
3. Adds Mantine graph-slot actions shown only when `appFSM.state.workspace === "slot.graph"`:
   - `FFSX 내보내기`
   - `Plotly JSON 내보내기`
   - `FFSX/Plotly JSON 불러오기`
4. The export buttons call the same existing functions through the same existing lifecycle states/events:
   - `appFSM.run("exporting", "SLOT_EXPORT", ...)` → `downloadSlotFfsx()`
   - `appFSM.run("exporting", "PLOTLY_EXPORT", ...)` → `downloadPlotlyJson()`
5. The import button opens the existing hidden `importSlotJsonFile` input. Its existing `onchange` handler remains wrapped by `connectLifecycleTasksToFSM()` with `appFSM.run("importing", "SLOT_IMPORT", ...)`.

## Why this direction

The Mantine migration should replace generic UI controls without moving or rewriting domain/file-format behavior. FFSX and Plotly export/import logic is already implemented and connected to lifecycle EFSM transitions. The new buttons therefore only reproduce the invocation surface.

The lifecycle helper is kept inside `fast-figure-ui.js`; it is not a bridge to legacy buttons and does not create a second state owner. It simply avoids repeating identical `appFSM.run(...).catch(...)` code in the Mantine presentation layer.

## Rejected alternatives

### Calling legacy button `.click()`

Rejected because it would make the legacy DOM an internal API and create a compatibility bridge that must later be removed.

### Moving FFSX / Plotly implementations into React

Rejected because those are functional/file-format concerns, not generic UI concerns, and are already correctly implemented outside React.

### Modifying lifecycle EFSM transitions for Mantine

Rejected because the existing lifecycle events already express the required import/export state transitions. Mantine should invoke them, not redesign them.

## Rollback

Revert only the `fast-figure-ui.js` hunk from `20260907-043.patch`. No FFSX, Plotly, project, or EFSM state needs migration or rollback because none of those structures are modified.
