# 20260911-002 — Decouple graph model commands from legacy graph DOM

## Purpose

Stop the active Mantine graph/model path from reading or synchronizing the obsolete `#buildBox` graph form. This is the runtime cutover step before deleting the legacy graph form itself. Legacy UI compatibility is not retained; FFPX/FFSX/Plotly file compatibility is unchanged.

## Exact changes

### `fast-figure.js`
- Add `activateChartModel(id)`, a UI-independent chart activation helper that updates runtime chart/CSV selection and data caches without populating legacy controls.
- Route graph workspace entry and `connectDataToSlot()` through `activateChartModel()` instead of `editChart()`.
- Remove `#buildBox` hide/show side effects from workspace state synchronization.
- Stop `graphEditorCommit()` and `graphEditorSelectObject()` from calling the legacy `renderGraphObjects()` DOM renderer.
- Stop `graphEditorHeaderLines()` from writing `#headerLines`, rebuilding legacy X/Y controls, or refreshing the legacy table preview; retain the in-memory row/column cache update.
- Stop `graphEditorSetEditable()` from calling `syncEditableUi()`.
- Stop Plotly range synchronization from writing axis range values back into legacy axis inputs; the chart model remains the source of truth.

## Rationale

Mantine already owns graph data/object selection, object editing, graph layout/axes, palette, editable/original mode, and FFSX/Plotly file actions. Continuing to mirror those changes into a hidden legacy form creates a second UI authority and prevents clean removal of `#buildBox`.

This patch deliberately does not preserve the old sidebar graph editor. `editChart()` and other legacy form functions may remain temporarily only because their old handlers are removed in the immediately following cutover patch; no active Mantine/model flow enters them after this change.

## Source of truth

- Chart/object data: project chart model and `appFSM` graph events.
- CSV/header data: project CSV model.
- Plotly axis ranges: chart `editor.globalSettings.axes`.
- Generic graph editor UI: Mantine components only.

## EFSM / core impact

No event semantics, chart schema, trace/layout generation, renderer behavior, or project mutation rules are changed. `activateChartModel()` replaces only the presentation-coupled activation side effects of `editChart()` on active runtime paths.

## File-format compatibility

No FFPX, FFSX, Plotly JSON parser/serializer, package schema, version, import, or export code is modified.

## Rejected alternatives

- Keep synchronizing hidden legacy controls: rejected because old UI compatibility is not required and hidden two-way synchronization is structurally inconsistent.
- Delete the complete graph facade before rerouting active callers: rejected because active runtime commands should first have a clean UI-independent boundary.
- Reimplement graph state in React-local state: rejected because project model/appFSM already own persistent graph state.

## Validation

Repository CI must pass patch application, JavaScript syntax, portable build, and split/portable Chromium `file://` smoke tests.

Manual regression focus: selecting a graph slot activates the correct chart/CSV, object edits still rebuild/render the graph, header-line changes still rebuild dependent editable charts, imported Plotly editable/original switching still works, and Plotly pan/zoom still updates model axis ranges.

## Rollback

Revert the application commit for this patch. No stored project migration is involved.

## Follow-up

Delete the now-obsolete graph form reader/apply functions, legacy graph DOM renderer, graph-form event handlers, and finally the full `#buildBox` markup/CSS/required IDs. File-format functions remain intact.
