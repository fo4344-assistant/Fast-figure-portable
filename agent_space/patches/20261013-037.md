# 20261013-037 — Reduce SlotCore selection harness state space

## 목적과 변경 내용

verification r14의 SlotCore에서 이번 요구에 불필요한 반복 선택 harness를 제거한다.

- `selectedSlotId`는 대표 visible slot 1에서 시작한다.
- 임의 slot을 반복 선택하는 `VerificationHarnessSelectSlot` action을 제거한다.
- successful slot swap의 source/target selection identity assertion은 유지한다.
- verification revision을 r15로 올리고 fingerprint를 갱신한다.
- TLC는 새 r15 결과가 확인될 때까지 pending으로 유지한다.

## 선택 이유

이번 검증 목적은 slot swap 시 기존 선택 payload가 source/target 이동을 따라가는지 확인하는 것이다. 모든 layout state에서 임의 선택 action을 반복 생성하는 것은 같은 의미를 과도하게 중복 탐색하여 상태공간만 증가시킨다.

대표 selected slot에서 시작해 swap action이 선택을 이동시키는 연쇄는 요구된 변환을 직접 검사하면서 기존 slot/layout 상태공간의 불필요한 곱을 줄인다.

## 고려했지만 선택하지 않은 방향

- selectedSlotId 검증 제거: bookmark swap 요구를 검증하지 못하므로 기각.
- 모든 slot 선택을 persistent harness action으로 유지: 검증 의미 증가 없이 상태공간이 커지므로 기각.
- merge/grid/split에 새로운 selection reconciliation 규칙 추가: Source Script에 없는 의미를 verification model이 발명하게 되므로 기각.

## 추상화 한계

초기 selection은 대표 slot 1로 고정한다. 이는 모든 초기 selection 값을 별도 상태로 열거하지 않는다. 대신 이후 valid swap 조합에서 selection이 source/target과 일치하는 경우의 변환을 assertion으로 검사한다. selection id 자체의 대칭성이 깨지는 별도 도메인 규칙이 추가되면 이 abstraction을 재검토해야 한다.

## 후속

r15 hosted TLA workflow 결과를 확인한다. interaction-core와 slot-core가 모두 성공하고 로그가 검토된 뒤에만 `tlc: passed`와 validation review를 기록한다.
