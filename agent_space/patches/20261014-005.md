# 20261014-005 — Use window pointer listeners for settings Modal resize

## 목적과 변경 내용

Source Code r16에서 실제 `Modal.Content` ref를 사용하도록 바꿨지만 headless regression의 합성 pointer event에서는 높이 변경이 여전히 관찰되지 않았다.

r17에서는 resize interaction lifecycle을 pointer capture에 의존하지 않고 window-level pointer listener로 변경한다.

- handle `pointerdown`에서 current content height와 pointer id를 기록.
- `window.pointermove`에서 height 계산 및 clamp.
- `window.pointerup/pointercancel`에서 listener와 drag state 정리.
- unmount cleanup에서도 동일 listener cleanup 실행.
- handle 자체에는 `pointerdown`만 유지.
- source-code revision r17, app build `1.1.37-wip`.

## 실패 근거

Fast Figure regression run `38503482265`에서도 tests 1–28, 30, 31은 inline/split 모두 pass했다.

유일한 실패는 test 29의 label modal height resize였다.

따라서 tree/trash/bookmark/layout-preview 변경은 손대지 않고 공통 Modal resize event transport만 수정한다.

## 선택 이유

window listener는 실제 사용자가 handle을 잡고 포인터를 handle 밖으로 움직여도 drag를 계속 추적한다. browser pointer-capture implementation과 synthetic event의 차이에 의존하지 않고 interaction lifetime도 명시적으로 cleanup할 수 있다.

## 고려했지만 선택하지 않은 방향

- pointer test 삭제 또는 완화: 사용자 요구의 핵심 기능을 검증하지 못하므로 기각.
- mouse event만 지원: pointer/touch semantics를 잃으므로 기각.
- CSS native resize만 사용: 공통 손잡이와 clamp/cleanup 의미를 잃으므로 기각.
- 각 overlay별 listener 구현: 중복이므로 기각.
