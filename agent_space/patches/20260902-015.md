# 20260902-015 — Mantine graph object form staging

## 목적

`20260902-012`~`014`에서 준비한 graph object read/write/column 경계를 inactive Mantine sidebar에 연결한다.

이번 패치는 아직 shell cutover가 아니므로 활성 legacy UI를 제거하지 않는다. Mantine staging은 domain/EFSM state를 복제하지 않고 현재 selected object snapshot을 렌더하며 모든 변경을 기존 object 전용 command 경계로 보낸다.

## 변경 내용

- 앱 버전 `1.1.63-alpha` → `1.1.64-alpha`
- `FastFigureGraphObjectStaging` 추가
- sidebar staging에서 `fastFigureUiBridge.readGraphObject()` 호출
- selected graph object가 있을 때 다음 Mantine controls 표시
  - 참조 CSV 이름
  - X/Y column Select
  - X/Y axis side Select
  - graph type Select
  - legend name TextInput
  - line width / line dash
  - marker symbol / marker size
  - bar opacity / bar line width
- 모든 write는 `fastFigureUiBridge.applyGraphObject(changes, chartId, objectIndex)` 사용
- `graphObjectTypeVisibility(type)` 순수 helper 추가
- 기존 `updateTypeSpecificOptions()`도 같은 helper를 사용하도록 변경하여 type별 UI 표시 규칙 중복 제거

## 기존 commit timing 보존

legacy binding을 확인한 결과:

- `xCol`, `yCol`, `xAxisSide`, `yAxisSide`, `chartType`, `lineDash`, `markerSymbol`: native `change`에서 즉시 `applyGraphSettings()`
- `legendName`: change/blur, Enter는 blur
- `lineWidth`, `markerSize`, `barOpacity`, `barLineWidth`: change/blur, Enter는 blur

Mantine staging도 같은 의미를 사용한다.

- Select `onChange`: 즉시 `applyGraphObject`
- TextInput/NumberInput `onBlur`: commit
- Enter: preventDefault 후 blur

React local persistent object state는 만들지 않는다.

## X/Y column source

`20260902-014`에서 추가한 `graphObject.columns`만 사용한다.

이 값은 selected object의 `csvId`가 가리키는 project CSV의 `rows/headerLines`에서 계산되므로 다음을 읽지 않는다.

- 전역 `columns`
- 전역 `rows`
- native `#xCol/#yCol` option
- active CSV form의 현재 DOM 값

## type option 공통화

기존 legacy `updateTypeSpecificOptions()`는 다음 규칙을 직접 가지고 있었다.

```text
line: scatter / lines+markers / hidden
marker: markers / lines+markers
bar: bar
```

Mantine component에서 동일 조건문을 다시 만들지 않고 `graphObjectTypeVisibility(type)`로 추출한다.

legacy `updateTypeSpecificOptions()`와 Mantine renderer가 같은 helper를 사용하므로 type별 표시 규칙의 source가 하나가 된다.

이 helper는 presentation visibility만 계산하며 chart type의 domain 의미나 trace 생성 알고리즘을 바꾸지 않는다.

## option 값

표시 label은 UI presentation이므로 Mantine component에 정의하되, domain value는 기존 값과 동일하게 유지한다.

- chart type: `scatter`, `markers`, `lines+markers`, `bar`, `hidden`
- X axis side: `bottom`, `top`
- Y axis side: `left`, `right`
- line dash: `solid`, `dot`, `dash`, `dashdot`
- marker symbol: `circle`, `square`, `diamond`, `cross`, `x`, `triangle-up`, `triangle-down`

새 value나 validation 의미를 추가하지 않는다.

## editable guard

snapshot의 `editable`이 false이면 Mantine controls를 disabled로 표시한다.

실제 write command에도 `chart.editor.editable === false` guard가 있으므로 UI disabled는 presentation이며 권위 검증을 대체하지 않는다.

## source of truth

- selected object: 기존 graphObject EFSM + `selectedObjectIndex`
- persisted object data: `chart.editor.objects[index]`
- X/Y option source: object CSV model
- type visibility: `graphObjectTypeVisibility(type)` 순수 계산
- form draft: 각 uncontrolled TextInput/NumberInput의 focus~blur 수명

React component는 object 전체를 `useState`에 저장하지 않는다.

## 기존 command 재사용

```text
Mantine control
→ fastFigureUiBridge.applyGraphObject
→ applySelectedGraphObjectFromValues
→ graphObjectSettingsFromValues
→ saveGraphObjects
→ GRAPH_OBJECTS_REPLACED
```

새 EFSM event/action을 만들지 않는다.

## Mantine/Core 분류

Mantine 대상으로 허용된 일반 sidebar form migration이며, 동시에 type visibility 중복을 순수 helper로 통합한다.

변경하지 않는다.

- graphObject EFSM state 의미
- `GRAPH_OBJECTS_REPLACED` action
- `CHART_MODEL_REPLACED` action
- object schema
- trace 생성
- Plotly renderer
- CSV import/export
- active legacy form ownership

## 선택하지 않은 방향

### React에서 `configFromForm()` 호출

선택하지 않았다. legacy DOM 전체 form 상태를 읽어 새 UI가 legacy renderer에 종속된다.

### React local state에 object clone 유지

선택하지 않았다. domain object의 장기 복제본이 되어 동기화가 필요해진다.

### 타입별 UI 표시 조건을 React에 복사

선택하지 않았다. legacy와 Mantine의 조건이 분기될 수 있으므로 공통 helper를 사용한다.

### graph type 변경 시 `updateTypeSpecificOptions()` 직접 호출

선택하지 않았다. 이 함수는 legacy DOM renderer다. Mantine는 snapshot의 새 type을 렌더하고 공통 visibility helper만 사용한다.

### graph object list/reorder/delete/color까지 한 패치에서 이관

선택하지 않았다. 이번 범위는 selected object form이다. 목록 renderer/actions는 별도 경계로 검토한다.

## 회귀 위험

중간이다. staging UI는 비활성이므로 사용자-visible legacy behavior 영향은 작지만, `updateTypeSpecificOptions()`가 공통 helper를 사용하도록 바뀐다.

검사 항목:

- helper 반환값이 기존 showLine/showMarker/showBar 조건과 완전히 동일
- legacy `updateTypeSpecificOptions()` 결과 동등
- Mantine Select가 object CSV columns만 사용
- select 즉시 commit
- text/number blur commit + Enter blur
- type별 control 표시가 기존과 동일
- editable=false control disabled + command guard 유지
- write가 `GRAPH_OBJECTS_REPLACED` 경로 사용
- trace/Plotly/EFSM event table diff 없음
- staging은 cutover 전 inactive

## rollback

1. `FastFigureGraphObjectStaging` 제거
2. sidebar의 `graphObject` read 및 render block 제거
3. `updateTypeSpecificOptions()`에 기존 inline showLine/showMarker/showBar 계산 복원
4. `graphObjectTypeVisibility()` 제거
5. 앱 버전 `1.1.63-alpha` 복원

`012`~`014`의 read/write boundary는 독립 유지할 수 있다.

## 후속 작업

다음은 graph object list/action UI를 조사한다.

현재 legacy list에는 selection, drag reorder, color input, delete가 결합되어 있으므로 기존 `SELECT_GRAPH_OBJECT`, `CLEAR_GRAPH_OBJECT`, `saveGraphObjects()` 등의 command를 그대로 재사용할 수 있는 DOM-free action schema가 있는지 확인한 뒤 Mantine list/menu/action으로 이관한다.
