# 20260902-045 — graph palette load parser reuse

## 목적

`20260902-044`에서 추가한 `parseGraphPaletteText(text)`를 legacy palette file-load handler가 실제로 사용하게 해 JSON/HEX 검증 규칙의 단일 source of truth를 완성한다.

## 변경 범위

- `loadGraphPaletteFile.onchange` 내부의 다음 중복 코드를 제거한다.
  - `JSON.parse`
  - 최상위 배열 / `{ colors }` 분기
  - colors 배열 존재 검사
  - `#RRGGBB` 필터
  - 유효 색상 존재 검사
- 대신 `parseGraphPaletteText(await file.text())`를 호출한다.
- chart 존재 검사, palette mutation, status/debug, input reset은 기존 그대로 유지한다.
- 버전 `1.1.84-alpha` → `1.1.85-alpha`

## 043 실패에서의 교정

`043`의 load hunk는 실제 old/new line 수가 `11 / 5`인데 `9 / 3`으로 기록되어 `corrupt patch`가 발생했다. `045`는 이 위치만 독립 hunk로 분리하고 올바른 line count를 사용한다.

## source of truth

- palette 파일 파싱/검증: `parseGraphPaletteText()`
- palette mutation: `setGraphObjectColorsFromPalette()`
- legacy file input lifecycle: 기존 `loadGraphPaletteFile.onchange`

## EFSM / core 영향

없음. 파일 텍스트 파싱의 중복만 제거한다. graph mutation/EFSM/chart schema/Plotly renderer는 수정하지 않는다.

## 기각안

- legacy load handler를 즉시 제거: 기각. active legacy UI가 아직 owner이므로 Mantine cutover 전에는 유지해야 한다.
- parser가 chart mutation까지 수행: 기각. 파일 형식 검증과 graph-object mutation 책임이 섞인다.

## rollback

load handler에 기존 inline JSON/HEX parser 블록을 복원하고 버전 문자열 두 곳을 되돌리면 된다. `044`의 parser 정의와 save helper 재사용은 독립적으로 유지할 수 있다.
