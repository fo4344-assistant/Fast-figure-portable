# 20260906-011 — image settings command / legacy form synchronization 분리

## 상태

첫 큐 실행은 `git apply --check`에서 `fast-figure.js:1` context 적용 실패로 중단되어 실제 source에는 적용되지 않았다.

원인은 구현 내용이 아니라 같은 파일의 세 hunk 시작 위치를 모두 `1`로 작성한 patch 형식이었다. 첫 버전 hunk 뒤의 image settings hunk가 실제 source 위치보다 앞에서 시작하는 것으로 해석될 수 있어 적용되지 않았다. 현재 split source의 실제 줄 위치를 다시 확인해 image settings hunk를 `10349`, legacy adapter hunk를 `10356` 기준으로 교정한다.

## 목적

Mantine image settings controls가 사용하는 `fastFigureUiBridge.applyImageSettings()` 경로에서 legacy native form DOM 의존을 제거한다.

현재 `applyImageSettingsFromValues()`는 image model의 `fit/scale/x/y`를 변경한 뒤 `syncImageSettingsUi()`를 직접 호출한다. 이 함수는 `#imageFitMode`, `#imageScale`, `#imagePositionX`, `#imagePositionY`, `#imageManualFields`를 직접 읽고 쓰는 legacy presentation 함수이므로, React/Mantine shell이 native image form 없이 owner가 되면 bridge callback이 깨진다.

반면 `syncSlotImageElement()`는 현재 dashboard renderer에 이미 존재하는 선택 슬롯의 이미지 element를 즉시 동기화하는 renderer update이고, model 변경을 화면에 반영하기 위해 유지한다.

## 변경 내용

- 앱 버전 `1.1.114-alpha` → `1.1.115-alpha`
- `applyImageSettingsFromValues()`에서 `syncImageSettingsUi()` 직접 호출 제거
- legacy `applyImageSettings()` adapter가 model command 성공 후에만 `syncImageSettingsUi()` 호출
- Mantine bridge는 기존대로 `applyImageSettingsFromValues()`를 직접 사용하므로 legacy image form DOM을 요구하지 않음

## 의미 보존

### model / renderer

`normalizeImageSettings()`, 입력 clamp, `syncSlotImageElement()`, debug log, `appFSM.notify("images", "IMAGE_SETTINGS_CHANGED")`의 순서와 의미는 유지한다.

### legacy UI

기존 native image controls에서 발생하는 `change`/Enter-blur 경로는 `applyImageSettings()` adapter를 계속 사용하므로 성공한 변경 뒤 form synchronization이 그대로 실행된다.

### Mantine UI

`FastFigureUiBridge.applyImageSettings()`는 model/renderer command만 실행하며 제거 예정인 legacy form ID에 의존하지 않는다. React state 갱신은 기존 FSM/UI store notification 경로를 사용한다.

## Mantine 전환과의 관계

이 패치는 UI 기능을 새로 구현하지 않는다. 동일 기능을 legacy presentation adapter와 owner-independent command로 분리해, 단일 React/Mantine shell cutover 시 native image settings form을 제거할 수 있게 한다.

## source of truth / EFSM / core

- image settings source of truth는 `activeProject.images[*].settings` 그대로 유지
- EFSM state/transition target 변경 없음
- FFPX/FFSX schema 변경 없음
- 이미지 위치/scale clamp 범위 변경 없음
- dashboard image renderer 의미 변경 없음
- 새 React/global state 없음

## 선택하지 않은 방향

### `syncSlotImageElement()`까지 제거

이는 legacy form synchronization이 아니라 dashboard renderer update다. 현재 renderer owner가 완전히 React로 교체되지 않았으므로 제거하면 이미지 설정 직후 화면 갱신 의미가 바뀐다.

### legacy form을 Mantine bridge에서 조건부 검사

두 UI 구현을 command 내부에서 동시에 아는 구조가 되어 cutover 경계를 흐리므로 선택하지 않는다.

## 회귀 위험

낮음.

실제 image model 변경과 renderer update는 그대로이고, native form 동기화 호출 위치만 legacy adapter로 이동한다.
