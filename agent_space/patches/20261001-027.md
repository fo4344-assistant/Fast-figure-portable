# 20261001-027 — PlusCal/TLA+ + TLC 검증 정책 도입

## 변경 요구

사용자가 기존의 자유형 pseudocode 중간 단계를 대신해
PlusCal + TLA+ + TLC를 사용하도록 상위 개발 정책 변경을 명시적으로 지시했다.

추가 요구:

- 일반 소스코드 컴파일러가 잘 잡는 구문/타입/단순 호출 오류보다,
  컴파일러가 놓치기 쉬운 전역 상태전이·순서·참조·실패 원자성 충돌을 검증할 것.
- Source Script의 핵심 알고리즘은 가능한 한 검증 모델에 포함할 것.
- 단순 조회처럼 다른 핵심 동작과 상당히 독립적이고,
  검증 효과 대비 모델링 비용이 큰 부분만 제한적으로 생략할 수 있을 것.
- 조회라도 file access order, lock, stale read, TOCTOU 등으로
  검증 대상 property에 영향을 주면 생략하지 않을 것.

## 변경 내용

### 개발 순서

기존:

```text
Source Script
-> language-neutral pseudocode
-> target-language implementation
```

변경:

```text
Source Script
-> PlusCal/TLA+ verification model
-> TLC model checking
-> target-language implementation
```

### PlusCal/TLA+ 책임

- PlusCal:
  핵심 알고리즘과 상태전이의 절차적 표현
- TLA+:
  state/action/invariant/safety/liveness와 환경 제약 표현
- TLC:
  bounded state space에서 실행 경로와 counterexample 탐색

### 모델링 기본 규칙

Source Script 핵심 알고리즘을 기본적으로 모델링한다.

특히 다음은 우선 검증 대상이다.

- authoritative/shared state
- mutation precondition
- candidate/validation/commit 순서
- reference 생성/이동/삭제
- FSM/lifecycle
- 여러 operation의 연속/교차 실행
- 실패/취소/부분 결과
- lock/concurrency/interleaving
- resource ownership
- safety invariant
- 필요한 liveness/deadlock 조건

### 추상화와 상태공간 축소

TLC state-space를 줄이기 위해
실제 collection 크기, 문자열, 수치 범위 등을 작은 symbolic domain으로 축약할 수 있다.

그러나 다음 의미를 숨기는 추상화는 금지한다.

- reference 차이
- mutation 순서
- lock 상태
- failure atomicity
- lifecycle
- resource ownership
- 검증하려는 property에 영향을 주는 branching

상태공간이 커지면 핵심 알고리즘을 제거하기 전에
bounded domain, representative state, symmetry, atomic abstraction 등
검증 의미를 보존하는 축약을 먼저 사용한다.

### 완전 생략의 제한

완전 생략은 예외다.

다음 조건을 모두 만족하는 경우만 허용한다.

1. 핵심 상태전이와 상당히 독립적
2. authoritative/shared state를 변경하지 않음
3. 결과가 mutation 권한/순서/reference/transaction/lifecycle을 바꾸지 않음
4. lock/concurrency/stale read/resource lifetime/callback/external side effect가 property에 영향을 주지 않음
5. 생략해도 현재 invariant/safety/liveness 반례가 가려지지 않는다는 근거를 설명 가능

단순 조회/표시 projection/독립 pure calculation은 생략 후보지만,
file access order, lock, TOCTOU, cache consistency, stale read가 관련되면 포함한다.

불확실하면 생략하지 않고 atomic action, environment action 또는 symbolic result로 모델링한다.

### 생략/추상화 기록

각 검증 run에는 다음을 기록한다.

- omitted/abstracted Source Script item
- 이유
- 독립이라고 판단한 state/property
- 검증하지 못하는 위험/한계
- 다시 모델에 포함해야 하는 조건
- TLC bound와 environment assumption

### 대상 언어 구현

구현은 closed Source Script와 TLC-passed verification model을 함께 따른다.

핵심 구현 경로는 검증 모델의 action/state/property와 대응 관계를 추적할 수 있어야 한다.

컴파일러/타입검사/테스트는 추가 검증 수단이며 TLC를 대체하지 않는다.

## 정책 버전

`source-script-policy.md`:

- v0.1.1 -> v0.2.0

단순 문구 보완이 아니라 개발 중간 단계 자체를 바꾸는 정책 변경이므로
minor revision이 아니라 현재 0.x 체계에서 v0.2.0으로 올렸다.

## 선택 이유

기존 language-neutral pseudocode는
실행 순서와 책임을 사람이 검토하기에는 유용하지만,
가능한 operation sequence와 invariant 위반을 자동으로 탐색하지 못한다.

PlusCal/TLA+ + TLC는 대상 언어 compiler와 역할 중복을 줄이면서
다음과 같은 오류를 직접 탐색하는 데 더 적합하다.

- 각 함수는 개별적으로 valid하지만 조합 후 orphan/shared reference가 생기는 경우
- validation 전에 authority가 일부 변경되는 경우
- 실패 path에서 partial commit이 남는 경우
- lifecycle/state-machine 조합이 dead-end에 빠지는 경우
- lock/interleaving 순서 때문에 invariant가 깨지는 경우

## 고려했지만 선택하지 않은 방향

### 기존 pseudocode를 유지하고 TLC를 선택적으로 추가

선택하지 않았다.

검증이 optional이면 구현 일정이 촉박할 때 핵심 상태전이 검사가 다시 생략될 가능성이 있고,
중간 단계의 책임도 pseudocode와 TLA+ 사이에 중복된다.

### FSM만 TLA+로 모델링

선택하지 않았다.

reference integrity, transaction atomicity, asset ownership, candidate/commit 같은
핵심 알고리즘은 FSM 바깥에서도 전역 상태 충돌을 만들 수 있다.

### 모든 Source Script 함수를 기계적으로 1:1 모델링

선택하지 않았다.

독립 pure read/projection까지 상세 모델링하면 state space와 작업량이 증가하지만
핵심 invariant 탐색 범위가 실질적으로 늘지 않을 수 있다.

대신 생략을 예외로 제한하고,
생략 조건과 위험을 기록하도록 했다.

### 단순 조회는 항상 생략

선택하지 않았다.

조회가 file access order, lock, stale read, TOCTOU 또는 이후 mutation decision에 참여하면
전역 상태 오류의 원인이 될 수 있기 때문이다.

## 기존 Fast Figure 계층에 미치는 영향

이번 patch는 상위 정책 원문과 정책 index만 변경한다.

현재 Fast Figure 저장소에는 이전 정책에 따라 생성된:

- Source Script r12 current/closed
- pseudocode r2 current/passed
- source-code r0 stale

lineage가 남아 있다.

새 v0.2.0 정책에서 기존 pseudocode r2는
PlusCal/TLA+ + TLC 검증을 대신할 수 없다.

따라서 **다음 source-code 구현을 시작하기 전에** 프로젝트 고유 계층 metadata/checker를
새 formal verification model 단계에 맞게 마이그레이션하고,
Source Script r12의 핵심 알고리즘을 PlusCal/TLA+로 옮겨 TLC 검증을 통과시켜야 한다.

정책 변경 자체가 Source Script의 domain 의미를 바꾸지는 않으므로
이번 patch에서 Source Script revision/fingerprint는 변경하지 않는다.
