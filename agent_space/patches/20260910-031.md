# 20260910-031 — Remove legacy slot-type controls

## Purpose

Remove the retired sidebar slot-type selector and legacy file-type hint now that `FastFigureDataActions` owns slot type selection and import affordances in Mantine. Legacy UI compatibility is explicitly not retained. File-format compatibility remains unchanged.

## Exact changes

### `Fast-figure.html`
- Remove `#slotTypeControls`, `#slotTypeGraph`, and `#slotTypeImage` markup.
- Remove `#fileTypeHint` markup.
- Remove the dedicated `.slot-type-controls` CSS rules.

### `fast-figure.js`
- Remove the four retired controls from `REQUIRED_CONTROL_IDS`.
- Simplify `syncSlotContentTypeUi()` so it no longer renders slot-type selection or file-type guidance into legacy DOM.
- Remove the legacy `#slotTypeGraph.onclick` and `#slotTypeImage.onclick` handlers.
- Keep `setSlotContentType()` because Mantine calls it directly and it remains the UI-independent command boundary.

## Rationale

`FastFigureDataActions` already derives the selected slot type from `appFSM`/project state and calls `setSlotContentType("graph" | "image")` directly. Retaining the old buttons and synchronizing their visual state creates duplicate generic UI ownership without providing file or model compatibility.

The file-type hint is also a legacy sidebar presentation concern. Mantine already presents the active import controls and their accepted content by context. It should not require a hidden legacy text node to remain initialized.

## Source of truth

- Slot content type: selected slot/project model through `appFSM`.
- Slot type mutation: existing `setSlotContentType()` / FSM path.
- Generic slot-type UI: Mantine `FastFigureDataActions` only.

## EFSM / core impact

None. `setSlotContentType()` and the underlying `SLOT_TYPE_CHANGED` transition are retained unchanged. No project object schema or renderer algorithm is modified.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, CSV, image import/export, serializer, parser, package version, or stored project field is changed.

## Rejected alternatives

- Keep hidden legacy controls as fallback: rejected because legacy UI compatibility is not a requirement and hidden controls preserve duplicate ownership.
- Make Mantine click the legacy buttons: rejected because it would recreate the forbidden Mantine-to-legacy-DOM bridge.
- Inline slot mutation into React: rejected because the existing UI-independent command/FSM boundary is already appropriate.

## Validation

Repository CI must pass patch application, JavaScript syntax checks, portable build, and split/portable Chromium `file://` smoke tests.

Manual regression focus: selecting graph/image in the Mantine data actions still changes slot type correctly; image/graph workspace selection still follows the FSM state; imports remain available through Mantine.

## Rollback

Revert the application commit for this patch to restore the old slot-type buttons, hint, CSS, required-control checks, synchronization, and handlers. No project/file data migration is involved.

## Follow-up

Remove the remaining legacy data-selection and image/graph editor DOM only after their active DOM-dependent helpers are cut over or deleted. Preserve file-format readers/writers independently of those UI removals.
