# 20260902-041 — Mantine graph palette reset action

## 목적

Mantine graph-object 목록에서 기존 기본 graph palette로 즉시 되돌릴 수 있게 한다.

## 변경 범위

- `FastFigureGraphObjectListStaging()`의 Mantine component import에 `Button`을 추가한다.
- graph-object 목록 제목 옆에 `기본 색상` 버튼을 추가한다.
- 버튼은 기존 `fastFigureUiBridge.setGraphObjectColors(DEFAULT_COLORS, chartId)` command만 호출한다.
- 편집 불가 chart이거나 graph object가 없으면 버튼을 비활성화한다.
- 애플리케이션 버전을 `1.1.83-alpha`로 올린다.

## 이유

`20260902-039`에서 palette 전체 적용이 DOM-free command로 중앙화됐고, `20260902-040`에서 legacy reset/load도 같은 command를 사용하게 됐다. 따라서 Mantine reset은 새로운 상태나 mutation 규칙을 만들 필요가 없다.

Mantine component가 직접 `chart.editor.objects`를 수정하거나 legacy `renderGraphObjects()`를 호출하면 UI renderer가 domain mutation 책임을 다시 갖게 된다. 이 패치는 기존 command만 호출하고 EFSM 구독을 통한 staging 재렌더에 맡긴다.

## source of truth

- graph object 배열: 기존 `chart.editor.objects`
- 기본 palette: 기존 `DEFAULT_COLORS`
- palette mutation: 기존 `setGraphObjectColorsFromPalette()` / bridge `setGraphObjectColors()`

새 persistent state, React draft, palette copy를 만들지 않는다.

## EFSM / core 영향

없음. 기존 graph-object mutation command와 `GRAPH_OBJECTS_REPLACED` 경로를 재사용한다. Plotly renderer, trace 생성, chart schema, import/export는 수정하지 않는다.

## 기각안

### Mantine component에서 object 배열을 map해서 직접 저장

기각. `20260902-039`에서 중앙화한 palette mutation 규칙을 다시 중복한다.

### reset용 React state 추가

기각. 기본 palette와 canonical object 색상 이외의 권위 상태가 필요하지 않다.

### load/save 파일 기능까지 한 번에 Mantine으로 이동

기각. reset은 순수 mutation action이지만 load/save는 browser file picker·download I/O 책임을 포함한다. I/O adapter를 별도 단계로 분리하는 편이 책임 경계와 rollback이 명확하다.

## rollback

이 패치의 목록 component import 변경과 `기본 색상` Button block, 두 버전 문자열만 제거하면 된다. `20260902-039/040`의 command나 legacy UI 동작에는 영향을 주지 않는다.
