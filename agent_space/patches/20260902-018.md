# 20260902-018 — Mantine graph object sidebar wiring

## 배경

`20260902-015`의 일괄 patch는 `git apply --check`에서 실패했으나 HTML에는 적용되지 않았다.

이후 분할 결과:

- `016`: graph type visibility 공통 helper + legacy renderer 통합 — 적용 성공
- `017`: `FastFigureGraphObjectStaging` component 정의 — 적용 성공

따라서 이번 패치는 남은 sidebar read/wiring만 적용한다.

## 목적

inactive `FastFigureSidebarStaging()`이 기존 bridge의 selected graph object snapshot을 읽고, 선택된 graph object가 있을 때 `FastFigureGraphObjectStaging`을 렌더하도록 연결한다.

## 변경 내용

- 앱 버전 `1.1.65-alpha` → `1.1.66-alpha`
- sidebar render 시 `fastFigureUiBridge.readGraphObject()` 호출
- 반환값이 있으면 `FastFigureGraphObjectStaging({ graphObject })` 렌더
- 기존 graph global layout/axis staging 다음, 일반 선택 섹션 이전에 배치

## source of truth

sidebar는 object 상태를 저장하지 않는다.

```text
FastFigureSidebarStaging render
→ readGraphObject()
→ selectedGraphObjectModel()
→ current chart.editor.objects[selectedObjectIndex]
```

렌더 snapshot은 presentation 입력일 뿐이다.

write는 이미 `017` component 내부에서:

```text
applyGraphObject
→ applySelectedGraphObjectFromValues
→ saveGraphObjects
→ GRAPH_OBJECTS_REPLACED
```

만 사용한다.

## UI ownership

이번 연결은 여전히 inactive staging shell 내부다. 활성 legacy sidebar를 제거하거나 두 UI를 동시에 사용자에게 노출하지 않는다.

최종 cutover 전에는:

- legacy sidebar = active owner
- Mantine shell = inactive complete staging tree

관계를 유지한다.

## 변경하지 않는 영역

- graphObject EFSM event/action
- selectedObjectIndex 의미
- `GRAPH_OBJECTS_REPLACED`
- `CHART_MODEL_REPLACED`
- graph object schema
- CSV model
- trace/Plotly renderer
- legacy graph form/list handler
- shell cutover 상태

## `015` 실패 원인 분리 결과

`016`과 `017`이 각각 성공했으므로 `015`의 실패는 적어도 다음 자체의 문제는 아니다.

- type visibility helper 코드
- `FastFigureGraphObjectStaging` component 코드

이번 `018`까지 성공하면 `015`의 실패는 여러 hunk를 한 patch에 묶을 때의 stale context/line composition 문제로 좁혀진다. 기능 설계 문제로 보지 않는다.

## 선택하지 않은 방향

### sidebar에서 object를 local state에 저장

선택하지 않는다. 매 render에서 canonical source를 다시 읽는다.

### component가 legacy form DOM을 읽도록 연결

선택하지 않는다. `012`~`014`에서 만든 DOM-free read/write 경계를 사용한다.

### graph object list까지 동시에 이관

선택하지 않는다. 목록은 selection/reorder/color/delete/add가 결합되어 있어 별도 command 경계 감사가 필요하다.

## 검증

- `git apply --check`
- 실제 apply
- `git diff --check`
- inline JavaScript `node --check`
- sidebar에서 `readGraphObject()`가 한 번만 호출되는지 확인
- object가 null이면 component 미렌더
- 기존 graph layout/axis staging 순서와 구조 보존
- active legacy UI 변경 없음

## rollback

1. sidebar local variable의 `graphObject` read 제거
2. component render block 제거
3. 앱 버전 `1.1.65-alpha` 복원

`012`~`017`은 독립 유지 가능하다.

## 후속 작업

다음은 graph object 목록/action 경계를 준비한다.

구형 기준본에서 목록은 다음 기능을 직접 DOM handler에서 수행한다.

- `SELECT_GRAPH_OBJECT` / `CLEAR_GRAPH_OBJECT`
- drag reorder 후 `saveGraphObjects()`
- color 변경 후 `saveGraphObjects()`
- delete 후 `saveGraphObjects()` + `CLEAR_GRAPH_OBJECT`

현재 main에서도 이 command 의미가 유지되는지 확인한 뒤, 먼저 DOM-free list snapshot/action command를 만들고 Mantine 목록 renderer는 그 다음 패치로 분리한다.
