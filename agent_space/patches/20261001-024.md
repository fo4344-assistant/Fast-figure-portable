## 번역 원칙

Source Script module 책임 경계를 그대로 유지했다.

pseudocode에는 다음만 정규화했다.

- 입력과 출력
- 실행 순서
- 분기/거부 조건
- candidate 생성
- reference resolve
- validation
- authoritative commit
- runtime/projection 후처리
- 실패 시 원본 유지

대상 언어 자료구조, JavaScript/React/Plotly 호출 문법, 구체 exception 타입 같은 구현 세부는 추가하지 않았다.

## 주요 번역 확인

- protected default CSV 없이 zero-object chart를 유지
- chart ↔ slot 1:1 ownership
- slot-local payload = chart/imageId/contentType/imageSettings/caption
- grid shrink/merge가 `SLOT_LOCAL_DEFAULTS`와 non-default guard를 사용
- image bytes는 asset, display settings는 slot-local
- global caption과 slot caption owner 분리
- candidate-first mutation
- FFPX/FFSX copied-byte/reference semantics
- Plotly original representation과 editable conversion 분리
- persistent export settings와 current-screen capture 분리
- public API owner가 모호한 legacy surface를 authoritative pseudocode에 다시 만들지 않음

## 선택 이유

pseudocode를 Source Script module과 같은 책임 단위로 분리하면
각 식별자와 알고리즘이 어느 Source Script에서 파생되었는지 직접 추적할 수 있다.

동시에 자연어 설명만 반복하지 않고
구현 단계에서 필요한 순서/분기/commit 경계를 명확히 검증할 수 있다.

## 고려했지만 선택하지 않은 방향

### 하나의 거대한 pseudocode 파일

선택하지 않았다.

Source Script의 책임 경계와 식별자 추적성이 약해지고,
file/project/graph/layout/API 문제를 독립적으로 검증하기 어렵다.

### JavaScript와 비슷한 실행 가능한 pseudocode

선택하지 않았다.

대상 언어의 object/Promise/DOM/error 구조를 미리 결정하게 되어
언어 중립 검증 단계의 역할을 약화한다.

### 생성과 동시에 validation=passed

선택하지 않았다.

pseudocode 번역 후에는 Source Script와 다시 대조해
누락·순서 모순·새 의미 추가 여부를 별도로 검증해야 한다.
따라서 r1 생성 시점에는 `pending`으로 유지한다.

Source Script는 r12 current/closed를 유지한다.
