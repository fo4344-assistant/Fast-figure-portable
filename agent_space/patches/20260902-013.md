# 20260902-013 — graph object values/command 경계 통합

## 목적

`20260902-012`에서 추가한 selected graph object 순수 read 경계에 대응하는 write 경계를 만든다.

현재 legacy `configFromForm()`은 graph object 필드의 DOM 입력 수집과 숫자 clamp/default 규칙을 직접 구현한다. 한편 graph object 순서/색상/삭제 저장에는 이미 `saveGraphObjects()` → `GRAPH_OBJECTS_REPLACED`라는 object 전용 EFSM 경로가 존재한다.

따라서 Mantine용 별도 mutation을 만들지 않고 다음 세 책임으로 분리한다.

1. legacy DOM 값 수집 — `graphObjectControlValues()`
2. object 값 정규화/부분 갱신 — `graphObjectSettingsFromValues(current, values)`
3. selected object command — `applySelectedGraphObjectFromValues(...)` → 기존 `saveGraphObjects()`

기존 `configFromForm()`도 같은 values helper를 사용하게 하여 legacy/Mantine 경로의 object field 규칙을 하나로 통합한다.

## 변경 내용

- 앱 버전 `1.1.61-alpha` → `1.1.62-alpha`
- `graphObjectControlValues()` 추가
  - x/y column
  - X/Y axis side
  - legend name
  - chart type
  - line width/dash
  - marker symbol/size
  - bar opacity/line width
- `graphObjectSettingsFromValues(current, values)` 추가
  - 전달된 필드만 갱신
  - 전달되지 않은 필드는 기존 object 값을 그대로 보존
  - legacy `configFromForm()`이 사용하던 숫자 clamp/default 규칙을 동일하게 재사용
- `applySelectedGraphObjectFromValues(values, expectedChartId, expectedObjectIndex)` 추가
  - 현재 selected chart/object identity 검증
  - editable guard 유지
  - 현재 object array를 shallow copy
  - selected object만 공통 values helper로 교체
  - 기존 `saveGraphObjects(next)` 호출
- UI bridge에 `applyGraphObject(values, chartId, objectIndex)` 추가
- 기존 `configFromForm()`의 object field 직접 DOM read/clamp를 `graphObjectControlValues()` + `graphObjectSettingsFromValues()` 사용으로 교체

## 기존 object 전용 EFSM 경로 확인

기존 코드에는 이미 다음 흐름이 있다.

```text
graph object reorder / color / delete
→ saveGraphObjects(objects)
→ appFSM.send("GRAPH_OBJECTS_REPLACED", payload)
→ 기존 chart/object renderer 및 notify 경로
```

따라서 selected object form을 Mantine로 옮기기 위해 새 EFSM event를 만들거나 전체 `CHART_MODEL_REPLACED` payload를 React에서 재구현할 이유가 없다.

이번 패치의 Mantine command도 동일한 `saveGraphObjects()`를 재사용한다.

## `CHART_MODEL_REPLACED`에 대한 처리

기존 `applyGraphSettings()`는 계속 `configFromForm()` 결과를 사용하며 전체 chart replacement 의미를 유지한다. 이번 패치에서 이 event나 legacy Apply 동작을 제거하지 않는다.

다만 `configFromForm()` 내부의 graph object 필드 정규화는 공통 helper를 사용한다. 즉 사용자 관찰 가능한 legacy 동작은 유지하면서 중복 규칙만 제거한다.

향후 shell cutover에서 legacy `applyGraphSettings()`가 제거 가능한지는 별도 단계에서 판단한다. Mantine 전환만을 이유로 지금 전체 chart replacement 의미를 바꾸지 않는다.

## source of truth

persisted graph object source of truth는 계속 selected chart의 `editor.objects`다.

- `graphObjectControlValues()`는 legacy DOM 순간 입력 adapter
- `graphObjectSettingsFromValues()` 반환값은 계산 결과
- `applySelectedGraphObjectFromValues()`의 `next` 배열은 EFSM command에 전달하기 위한 일회성 payload
- React snapshot/draft는 persisted state가 아님

실제 저장은 기존 `GRAPH_OBJECTS_REPLACED` action 경로를 통과한다.

## 부분 update 의미

Mantine control은 한 필드씩 즉시/blur commit할 수 있으므로 `graphObjectSettingsFromValues()`는 전달된 필드만 수정한다.

이를 위해 `Object.prototype.hasOwnProperty.call(values, key)`로 필드 존재 여부를 검사한다.

따라서 예를 들어 `{ lineWidth: 3 }`만 전달하면 x/y/type/color/csvId/plotlyTrace 등 나머지 object 필드는 그대로 보존된다.

반대로 legacy `graphObjectControlValues()`는 기존 form object 필드를 모두 전달하므로 기존 `configFromForm()`과 같은 결과를 만든다.

## 기존 정규화 규칙 보존

기존 `configFromForm()`의 의미를 그대로 옮긴다.

- `lineWidth`: 0.1–20, invalid/0 입력은 2
- `lineDash`: 빈 값은 `solid`
- `markerSymbol`: 빈 값은 `circle`
- `markerSize`: 1–40, invalid/0 입력은 6
- `barOpacity`: 0.05–1, invalid/0 입력은 1
- `barLineWidth`: 0–10, invalid 입력은 0

x/y, axis side, legend name, chart type은 기존 select/input 문자열을 그대로 사용한다.

새 validation 범위를 추가하지 않는다.

## stale callback guard

`20260902-007` graph layout과 동일한 원칙으로 optional identity를 검증한다.

- `expectedChartId`가 현재 selected chart와 다르면 write 거부
- `expectedObjectIndex`가 현재 selected object와 다르면 write 거부

이 값들은 source of truth가 아니라 오래된 UI callback을 차단하기 위한 식별자다.

정상적으로 같은 chart/object가 선택된 경우 기존 command 의미에 영향을 주지 않는다.

## Mantine/Core 분류

이 변경은 두 범주에 해당한다.

1. Mantine 이관을 위한 DOM-free explicit values/command 경계
2. 기존 graph object form의 중복 정규화 규칙을 하나의 helper로 통합하는 최소복잡도 개선

변경하지 않는다.

- `GRAPH_OBJECTS_REPLACED` event/action 의미
- `CHART_MODEL_REPLACED` event/action 의미
- graphObject EFSM selection 의미
- `saveGraphObjects()`
- trace 생성 알고리즘
- Plotly renderer
- graph object data schema
- CSV/image/project import/export

## 선택하지 않은 방향

### Mantine callback에서 chart clone 후 `CHART_MODEL_REPLACED` 직접 전송

선택하지 않았다. 이미 object 전용 `GRAPH_OBJECTS_REPLACED` 경로가 있으므로 더 큰 mutation payload를 새 UI가 재구현할 필요가 없다.

### object 전용 새 EFSM event 생성

선택하지 않았다. 기존 event가 이미 같은 기능 의미를 담당한다.

### `configFromForm()` 전체 제거

선택하지 않았다. 활성 legacy UI가 아직 이를 사용하고 있으며 layout/palette/title 등 다른 의미도 포함한다. cutover 이전에 제거하면 legacy behavior를 바꾼다.

### partial values를 전체 object default로 다시 정규화

선택하지 않았다. 한 control의 callback이 다른 필드까지 불필요하게 채우거나 덮어쓸 수 있다. 전달된 필드만 수정한다.

## 회귀 위험

중간 이하이다.

새 Mantine command는 아직 staging 연결 전이고 기존 object 전용 저장 경로를 재사용한다. 다만 `configFromForm()`의 object field 계산이 공통 helper를 통과하도록 바뀌므로 기존 결과 동등성 검사가 필요하다.

검사 항목:

- legacy full control values에서 기존 `configFromForm()`과 같은 object field 결과
- partial values에서 미전달 필드 보존
- `csvId`, `color`, `plotlyTrace` 등 object extension/identity 필드 보존
- stale chart/object callback write 거부
- editable=false write 거부
- selectedGraphObjectGuard 의미 유지
- `saveGraphObjects()` → `GRAPH_OBJECTS_REPLACED` 경로 재사용
- `CHART_MODEL_REPLACED` event/action diff 없음
- trace/Plotly code diff 없음

## rollback

독립적으로 되돌릴 수 있다.

1. bridge `applyGraphObject` 제거
2. `graphObjectControlValues`, `graphObjectSettingsFromValues`, `applySelectedGraphObjectFromValues` 제거
3. `configFromForm()` object fields에 기존 직접 DOM read/clamp 식 복원
4. 앱 버전을 `1.1.61-alpha`로 복원

`20260902-012`의 pure read selector는 독립 유지 가능하다.

- X/Y options는 object가 참조하는 CSV에서 계산

- text/number는 기존 commit timing에 맞는 draft 사용
- select는 기존 timing과 동일하게 commit
- 모든 write는 `applyGraphObject(...)` 하나를 사용

하도록 한다.
