## 선택한 방향과 이유

Source Script의 닫힘 근거 확인을 구현 착수 조건으로 둔다. Backend 상태·정규화·조회 연결을 먼저 맞추고, EFSM 재시도·결과, graph 저장 표현, asset import, Frontend/public 경계, UI 현재 입력, caption 순서로 수정한다. P1 자료 보존·명령 반영 문제와 모듈 간 의존 관계를 함께 고려한다. 각 항목의 같은 입력·반환·실패를 정적으로 대조하고 후속 review에 근거를 남기도록 한다.

## 고려한 대안

심각도 순으로 항목을 각각 수정하면 공통 정규화·조회와 소비자 사이의 연결이 분리될 수 있어 책임 경로별 그룹을 선택했다. Source Script의 미확정 의미를 source code에서 가져오는 방식은 상위 의미의 권위를 보존하지 못하므로 채택하지 않는다. source code 전파와 실행 검증은 별도 승인 범위로 유지한다.

## 실제 diff와 범위

- 동명 `.patch`는 새 계획과 이 설명 문서의 실제 native Git diff다. patch 자체는 자기 diff에 포함하지 않는다.
- `git diff --no-index --binary --full-index`로 두 새 파일을 `/dev/null`과 비교한다. 기존 미커밋 review와 016 패치 쌍은 보존한다.
- 현재 작업에서는 Source Script·pseudocode·source code·설정·metadata·정책·AGENT·index를 수정하지 않는다.
- Source Script 52/stale/open, pseudocode 26/stale, source code 157/stale의 기록을 유지한다.
- 구현·테스트·앱·브라우저·빌드·TLC·checker·Actions·커밋·푸시는 수행하지 않는다. 계획의 수정 단계는 후속 승인을 받은 뒤 진행한다.
