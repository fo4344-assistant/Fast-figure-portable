# 20260907-055 — Mantine-owned data file picker and collision choice

## 목적

Mantine `FastFigureDataActions`의 `데이터 추가`가 더 이상 legacy `#file` input을 클릭하지 않도록 한다. 파일 선택, 같은 이름 충돌 선택, input reset은 React/Mantine UI가 소유하고, 실제 파일 판정·프로젝트 변경은 기존 Fast Figure 기능 함수와 `20260907-054`에서 분리한 순수 충돌 계획 함수가 담당한다.

## 변경 분류

- Mantine UI 포팅
- legacy DOM UI 의존 제거
- 기존 기능 경계 재사용
- EFSM/domain 의미 변경 없음

## 정확한 변경

`fast-figure-ui.js`만 수정한다.

1. 전역 `openDataPicker()`에서 `document.getElementById("file").click()` 하던 legacy DOM bridge를 제거한다.
2. `FastFigureDataActions()`에 React-owned hidden file input을 추가한다.
   - `accept=".csv,.tsv,.json"`
   - `multiple=true`
   - 이는 현재 legacy `#file` input의 속성을 그대로 보존한다.
3. 선택 파일 처리 시 기존 `ASSET_IMPORT` lifecycle을 유지한다.
4. 현재 legacy `#file.onchange`의 분기 의미를 보존한다.
   - 선택 슬롯이 이미지 슬롯이면 첫 파일만 처리한다.
   - slot 파일이면 기존 `importSlotFile()`을 사용한다.
   - image 파일이면 기존 `loadImageFile()`을 사용한다.
   - data 파일이면 기존 `loadDataFile()`을 사용하며 이미지 슬롯을 data로 교체하는 경우 `replaceSlotContent: true`를 유지한다.
   - 그래프 슬롯이면 모든 선택 파일을 기존 `loadDataFile()`로 처리한다.
   - 슬롯 미선택이면 `slotFileKind()` 결과에 따라 기존 `loadImageFile()` / `loadDataFile()`을 사용한다.
   - 실패 시 기존과 동일하게 `불러오기 실패: ...` 상태 메시지를 표시한다.
   - 완료 후 file input 값을 비워 같은 파일을 다시 선택할 수 있게 한다.
5. 파일명 충돌은 `20260907-054`의 `projectAssetImportCollisionModel()`과 `resolveProjectAssetImportPlan()`을 사용한다.
   - 충돌 없음: 바로 기존 loader에 `{ assetPath, replaceAssetId }` 계획을 전달한다.
   - 같은 종류 교체 가능: Mantine `Modal`에서 `새 이름으로 추가` / `기존 파일 교체`를 선택한다.
   - 교체 불가 충돌: Mantine `Modal`에 기존 notice를 표시하고 `새 이름으로 추가`만 제공한다.
   - Modal close는 기존 `window.confirm()`의 취소 의미와 동일하게 rename을 선택한다.

## Source of truth 영향

없음.

- 파일 종류: 기존 `slotFileKind()`
- 충돌 판정: `projectAssetImportCollisionModel()`
- 최종 경로/replaceId: `resolveProjectAssetImportPlan()`
- 프로젝트 변경: 기존 `loadDataFile()` / `loadImageFile()` / `importSlotFile()`
- lifecycle: 기존 `appFSM.run(..., "ASSET_IMPORT", ...)`

React state는 현재 표시 중인 충돌 Modal과 그 일회성 선택 대기 상태만 보관한다. 프로젝트 데이터의 source of truth가 아니다.

## EFSM/domain 영향

사용자 관찰 가능한 EFSM/domain 의미는 변경하지 않는다.

- `ASSET_IMPORT` lifecycle 유지
- 기존 slot/content 전환 규칙 유지
- 기존 loader validation 및 파일 해석 유지
- FFPX/FFSX 의미 변경 없음
- project model schema 변경 없음

## 기각한 대안

### Mantine 버튼이 legacy `#file`을 계속 클릭

기각. Mantine UI를 legacy DOM event path에 의존시키는 bridge를 유지하며 최종 cutover 후 제거 비용이 남는다.

### `planProjectAssetImport()`를 Mantine에서도 직접 호출

기각. 해당 wrapper는 legacy `window.confirm/alert`를 보존하기 위한 호환 경로이므로 Mantine에서 호출하면 native UI가 다시 나타난다.

### 새 import service/state machine 추가

기각. 기존 UI FSM/lifecycle과 loader가 이미 기능 경계를 제공한다. 이번 변경에 새 상태 계층은 필요하지 않다.

## 위험

- 다중 파일 import 중 충돌 Modal이 열리는 동안 lifecycle이 `importing` 상태로 유지된다. 이는 해당 import 작업이 아직 완료되지 않았다는 의미와 일치한다.
- Modal close가 rename으로 해석되어야 기존 native confirm의 Cancel 동작과 동일하다.
- 각 파일은 순차 처리되므로 앞 파일이 추가된 뒤 다음 파일의 충돌 판정에 현재 project state가 반영된다.

8. import 중 lifecycle이 ready → importing → ready로 복귀

## 롤백

`20260907-055.patch`를 역적용하면 된다. 롤백 시 Mantine `데이터 추가`는 다시 legacy `#file` input을 클릭하고, 기존 native `planProjectAssetImport()` 충돌 UI를 사용한다. `20260907-054`의 순수 함수 분리는 독립적으로 남겨도 legacy 동작에는 영향이 없다.
