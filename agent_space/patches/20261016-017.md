## 목적과 내용

사용자가 열거된 일부 API 반환을 먼저 마저 작성하도록 요청했다. project.setName, slots.setContentType/reset/swap, images.insertEmpty, assets.delete/move/createDirectory/emptyTrash/connectToSlot의 성공/미commit/오류 반환을 기존 owner wrapper에 명시했다. Source API inventory 87개는 유지한다.

- 완료 값 없는 None과 False/True, fresh detached asset/name, 실제 canonical path 결과를 operation별로 구별한다.
- command 내부 tuple을 public 값으로 반환하지 않는다. 미commit에는 성공 query/selection을 하지 않고 오류는 전파한다. 사후 실패는 이미 commit한 state를 숨은 rollback하지 않는다.
- name/image model/slot payload 계산은 Backend command, directory/connection 사후 selection은 기존 Application path다. move/directory는 실제 result.changed path를 사용한다.
- Source r34 current/open, closure_review null; fingerprint `sha256:024c9de52803c2743ab65742753e94b09dd15fdaa1f3f1d40f34567c648478ac`.

## 이유 / 고려했으나 기각한 대안

- 공통 bool/envelope로 강제하면 기존 scalar/path/void 계약 자유도를 줄이고 불필요한 변환을 추가하므로 기각했다.
- stale plan/input path 또는 Backend live model을 성공값으로 재사용하지 않는다. 실제 command 결과와 기존 read로 같은 의미를 더 작은 경계에서 충족한다.
- 별도 post-mutation selection authority/중복 query registry/legacy bridge는 기각했다. 기존 interface-intent/reconciliation과 official query만 재사용한다.
- 하위 selected-slot-only type wrapper의 pending global 복원은 Source explicit target 계약과 충돌한다. 기존 adapter의 explicit pendingContentType 선택 경로는 유지하며 하위 API 전파는 뒤 단계다.
