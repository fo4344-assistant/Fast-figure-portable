# 20260922-006

## 목적과 변경 내용

Mantine layout overlay가 project/layout/renderer 내부 상태를 직접 읽고 변경하던 경로를 `FastFigureApi.layout` read/write API로 옮긴다.

추가되는 API:

- `readState(previewWidth)`
  - grid rows/columns
  - immutable slot-style snapshot
  - visible slot의 layout geometry 식별 정보
  - preview geometry
  - dashboard zoom 및 lock 상태
- `setStyle(patch)`
- `setGrid(rows, cols)`
- `setZoom(value)`
- `commitZoom()`
- `setZoomLocked(locked)`
- `resetZoom()`
- 기존 `mergeSlots(slotIds)`, `splitSlots(slotIds)`

Mantine overlay는 더 이상 다음 backend/core 구현을 직접 참조하지 않는다.

- `activeProject.layout`, `activeProject.slots`
- `dashboardZoomIntent`, `dashboardZoomLocked`
- `dashboardGeometry()`
- `makeSlots()`
- `applySlotStyle()`
- `applyDashboardZoom()`
- `commitDashboardScale()`
- `setDashboardZoomLocked()`

또한 zoom의 React mirror state를 제거하고 core runtime zoom state를 API snapshot으로 직접 읽는다.

## 선택 이유

layout/project state와 renderer zoom state는 실제 기능 상태의 source of truth이므로 SoT 구현체가 read/write API를 노출할 수 있다. 반대로 Mantine local component가 backend object를 직접 보유하거나 동기화하는 구조는 피한다.

`readState()`는 호출 시마다 SoT에서 새 immutable snapshot을 만들어 반환하며 저장·공유하지 않는다. snapshot은 해당 render에서만 소비되고 다른 기능이 권위 상태로 참조하지 않는다.

style command는 기존 project import와 같은 허용 범위를 사용해 값을 정규화한다. grid command는 1~8 정수 조건을 backend에서도 검증한다.

## 선택하지 않은 방향

### `activeProject` object를 API로 그대로 반환

frontend가 mutable project object를 다시 직접 수정할 수 있으므로 사용하지 않는다. 필요한 primitive/geometry만 immutable snapshot으로 반환한다.

### zoom 값을 React와 core에 둘 다 저장

즉시 적용되는 zoom 값을 양쪽에 동기화하면 중복 SoT가 된다. React zoom mirror를 제거하고 core 값을 API로 읽는다.

### geometry 계산을 frontend에 복제

dashboard geometry 규칙을 UI 쪽에 복제하면 계산 규칙이 두 군데 생긴다. preview geometry도 core read API에서 계산한다.

### frontend clamp만 신뢰

API가 외부 호출 경계이므로 core에서도 grid/style/zoom 허용 범위를 검증 또는 정규화한다.

## 전제와 후속 작업

- `previewWidth`와 layout slot 선택 Set은 presentation/input-only 값이므로 계속 Mantine local state다.
- API read snapshot은 캐시하지 않는다.
- merge/split domain 동작은 005에서 만든 command 경계를 그대로 사용한다.
- overlay close는 현재 application state event를 사용한다. UI-FSM/application-router 경계는 별도 횡단 작업에서 정리한다.
- 다른 Mantine 기능의 `activeProject`, `projectVfs`, graph/image 내부 직접 접근은 후속 ownership 단위에서 API로 이동한다.

## 롤백

역적용하면 Mantine layout overlay가 다시 project/layout/zoom 내부 상태를 직접 읽고 변경하며 React zoom mirror가 복원된다. project schema와 FFPX/FFSX에는 변경이 없다.
