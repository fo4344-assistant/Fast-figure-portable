# 20260901-001

## 목적
`plan-003.md` Commit A를 수행해 Mantine shell cutover 전에 UI-state/domain code와 legacy DOM renderer의 결합 지점을 inventory로 확정한다.

## 변경 내용
- `agent_space/reviews/review-002.md` 추가.
- 기존 `ApplicationStateMachine` region 분리는 유지해야 함을 재확인.
- 코드를 A(domain renderer 유지), B(React/Mantine binding으로 이전), C(legacy UI infrastructure 제거)로 분류.
- workspace, overlay, label/caption, layout, sidebar, asset tree/menu, graph form, print/export, global handler/CSS를 각각 검토.
- 다음 Commit B의 selector/subscription/command 경계와 Commit C cutover 제거 목록을 확정.

## 이 방향을 선택한 이유
기능/domain EFSM과 UI 상태 region의 논리 분리는 이미 존재한다. 현재 문제는 일부 entry/update/exit 및 helper가 native input/panel/dialog DOM을 직접 source of truth 또는 renderer lifecycle로 사용한다는 점이다. 실제 UI 코드를 쓰기 전에 유지/이전/삭제 경계를 확정해야 EFSM을 불필요하게 재설계하거나 legacy UI infrastructure를 Mantine shell 위에 다시 만드는 일을 막을 수 있다.

## 검토 기준 소스
현재 GitHub connector가 대용량 `Fast-figure.html` 본문을 반환하지 않아 legacy UI 정적 분석에는 `/mnt/data/Fast-figure.html` 1.1.28-alpha 기준본을 사용했다. 이후 main의 slot swap 구조 변경은 이 inventory의 근거에서 제외했으며, toolbar/sidebar/popup/form은 아직 Mantine로 이관되지 않았다는 현재 GitHub 이력을 교차 확인했다. 다음 실제 application patch는 현재 main의 정확한 context에서 생성한다.

## 고려했지만 선택하지 않은 방향
- **EFSM 재설계:** 이미 region 분리가 있으므로 불필요하다.
- **toolbar만 먼저 활성 전환:** `plan-003`의 단일 UI ownership 원칙을 위반한다.
- **모든 DOM ID 제거:** domain renderer mount의 명시적 ID/ref contract는 정당하다. 제거 대상은 일반 UI control을 domain 코드가 source of truth로 읽는 결합이다.

## 검증 및 후속 작업
이 패치는 review 문서만 추가하며 `Fast-figure.html` runtime은 변경하지 않는다. 다음 단계는 review의 Commit B 경계에 따라 비활성 Mantine shell 준비 코드를 작성하는 것이다. Selector는 DOM을 읽지 않고 command binding은 기존 EFSM/domain mutation 경로를 재사용해야 한다.
