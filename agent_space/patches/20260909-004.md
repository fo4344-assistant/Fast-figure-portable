# Project export source-of-truth correction

## 목적

Mantine `FastFigureProjectActions`는 프로젝트 이름을 `activeProject.projectName`에 직접 기록하지만, 공용 FFPX export command인 `downloadProject()`가 다시 legacy `#projectName.value`를 읽어 model을 덮어쓰고 있었다. 이 패치는 export 시 프로젝트 이름의 authority를 기존 project model 하나로 바로잡아 Mantine 경로의 legacy DOM 역참조를 제거한다.

## 변경 내용

대상은 `fast-figure.js` 하나다.

기존 `downloadProject()` 시작부:

- `$("projectName").value`를 읽음.
- trim/120자 제한 후 `activeProject.projectName`에 다시 기록.
- 정규화한 값을 다시 legacy input에 씀.

변경 후:

- `activeProject.projectName` 자체를 `String(...).trim().slice(0, 120)`으로 정규화한다.
- export command는 프로젝트 이름을 DOM에서 읽지 않는다.
- FFPX build, 파일명 생성, status/debug 동작은 기존 그대로 유지한다.

## source of truth

프로젝트 이름의 영속 source of truth는 `activeProject.projectName` 하나다.

legacy `#projectName`과 Mantine `TextInput`은 모두 UI projection/input surface일 뿐이며 export command의 authority가 아니다. Mantine `TextInput`은 이미 input 시 model을 갱신하고 blur 시 trim/120자 제한을 적용한다. export에서도 같은 trim/120자 제한을 model 값 자체에 적용하므로 포커스가 아직 input에 있어도 의미가 유지된다.

## 선택 이유

현재 구조에서 `downloadProject()`는 legacy 버튼과 Mantine 버튼이 함께 사용하는 공용 command다. 공용 command가 특정 UI의 DOM 값을 읽으면 Mantine 이전 후에도 legacy UI가 숨은 source of truth로 남는다.

project model을 직접 읽도록 바꾸면:

- 별도 helper/store가 필요 없다.
- 기존 export 알고리즘은 그대로다.
- legacy와 Mantine 어느 UI에서 호출해도 같은 project state를 사용한다.
- 최종 legacy markup 제거 시 추가 수정이 필요하지 않는다.

## 고려했지만 선택하지 않은 방향

### 1. Mantine export 직전에 legacy `#projectName` 값을 맞춤

기각했다. Mantine → legacy DOM synchronization을 명시적으로 추가하는 방향이다.

### 2. `downloadProject(name)` 인자로 Mantine draft를 전달

기각했다. project model이 이미 프로젝트 이름 authority이므로 같은 값을 별도 인자로 전달하면 호출자마다 다른 source가 생길 수 있다.

### 3. legacy input projection을 export command 안에 계속 유지

기각했다. export command의 책임은 project state를 package로 만드는 것이며 UI display synchronization은 입력 handler/state sync 책임이다. 현재 legacy input도 `input/change`에서 model을 갱신한다.

## EFSM / domain 영향

프로젝트 export format과 EFSM 의미는 변경하지 않는다.

- FFPX 구조/버전 변경 없음.
- `ffpxBuildProject()` 변경 없음.
- lifecycle `exporting` 변경 없음.
- project name trim 및 최대 120자 의미 유지.
- 파일명 생성/status/debug 의미 유지.

이 변경은 UI migration 과정에서 발견한 source-of-truth 정리이며, Mantine이 건드리면 안 되는 domain 알고리즘 변경이 아니다.

## 검증

자동 workflow:

1. `git apply --check`
2. `git diff --check`
3. `node --check fast-figure.js`
4. portable HTML build
5. split/portable `file://` smoke

수동 회귀:

1. Mantine 프로젝트 이름을 입력하고 바로 FFPX export했을 때 해당 이름이 project metadata/파일명에 반영되는지.
2. 앞뒤 공백이 trim되는지.
3. 120자 제한이 유지되는지.
4. legacy project name input 경로에서도 export 결과가 동일한지.
5. slot 선택 중 export 금지 의미가 그대로인지.
