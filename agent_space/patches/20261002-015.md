`review-022-mantine-ui-regression-qa.md`의 5번 문제인
graph/label/caption 글꼴 선택 control이 문자열 직접 입력으로 바뀐 회귀를 수정한다.

변경:

- `fast-figure-ui.js`
  - graph/label/caption TextInput을 Mantine Select로 교체
  - pre-Mantine predefined font 목록 복원
  - 목록 밖 현재 font family를 `기존: ...` option으로 보존
  - graph의 빈 문자열 자동 값을 UI-local token으로 표현
- `agent_space/tests/browser-regression.js`
  - regression target r8
  - label/caption predefined/custom font Select 검증
  - graph auto/custom font Select 검증
- `development-versions.json`

- `agent_space/reviews/review-026-source-code-r8-font-selectors.md`
  - source of truth와 adapter 경계 기록

## 이 방향을 선택한 이유

기존 기능은 단순 문자열 입력이 아니라 predefined font selector였다.
특히 graph selector는 imported/custom 기존 값을 목록에 동적으로 추가해
값을 잃지 않았다.

Mantine Select의 option value를 project font 문자열과 직접 동일시하면
graph의 빈 문자열 `자동` 표현이 UI component 동작에 종속될 수 있다.
따라서 Select 내부에만 prefix token을 사용하고 onChange에서 원래 font 문자열로 즉시 변환한다.

이 token은 project state, API 또는 file format으로 전달되지 않는다.

label/caption:

- 기본(system-ui)
- Arial
- Times New Roman
- Georgia
- Courier New

## 고려했지만 선택하지 않은 다른 방향

### TextInput 유지 + datalist

선택 UI가 Mantine 공통 component 체계 밖으로 나가며 기존 Select interaction과 다르다.

### custom font를 predefined 목록으로 강제 normalization

imported Plotly와 이전 project의 custom font family를 손실하므로 선택하지 않았다.

### Select state를 별도 React state로 소유

authoritative font value와 중복 source of truth가 생긴다.
현재 settings에서 매 render option/value를 파생하는 방식으로 충분하다.

### graph 자동 값을 persistent sentinel로 변경

file/project 의미를 UI component 때문에 바꾸는 것이므로 사용하지 않았다.

## 검증

annotation과 graph에서 실제 Mantine Select input을 확인하고
predefined 값과 custom historical 값이 올바른 display label로 projection되는지 검사한다.

검사에서 변경한 font settings는 각 test 안에서 원래 값으로 복원한다.

## rollback

font control을 기존 TextInput으로 복원하고 r8 regression/review/version metadata를 r7로 되돌리면 된다.
persistent data migration은 없다.
