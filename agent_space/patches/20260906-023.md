# 20260906-023 — Mantine asset tree drag/drop wiring

## 목적

Mantine asset tree가 legacy `#assetTree` DOM event infrastructure 없이도 기존 프로젝트 자산 drag/drop 기능을 사용할 수 있도록 한다.

## 이유

`20260906-021`에서 asset tree 자체를 Mantine component로 재구성했고, `022`에서 CSV/image selection command를 legacy form presentation에서 분리했다. 남은 핵심 기능은 내부 자산 이동, 슬롯 연결, 외부 파일 폴더/슬롯 drop이다.

이 기능의 정책과 실제 domain command는 이미 `assetTreeDropPolicy()` / `executeAssetTreeDrop()`에 구현되어 있으므로 새 drag/drop 규칙을 만들지 않고 그대로 재사용한다.

## 변경

- Mantine bridge에 다음 경계를 추가한다.
  - `canDragAsset(path)`
  - `beginAssetDrag(path, dataTransfer)`
  - `readAssetDropPolicy(dataTransfer, target)`
  - `dropAsset(dataTransfer, target)`
- 내부 drag payload는 기존 `ASSET_TREE_DRAG_TYPE`, `ASSET_TREE_LOCKED_TYPE` 형식을 그대로 사용한다.
- `FastFigureAssetTreeStaging`의 Mantine `NavLink`에 drag/drop event를 직접 연결한다.
  - asset file: drag source
  - movable directory: drag source
  - directory: folder drop target
  - slot: slot drop target
- drop effect 결정도 기존 policy의 `link` / `move` / import 결과를 사용한다.
- `executeAssetTreeDrop()`에 `preserveLegacyOpenState` 옵션을 추가한다.
  - 기본값 `true`로 기존 legacy tree 동작을 유지한다.
  - Mantine 경로는 `false`를 전달해 `#assetTree details` open-state DOM 조회를 하지 않는다.
- 앱 빌드 `1.1.126-alpha` → `1.1.127-alpha`.

## 유지

- VFS move/validation 규칙.
- 기본 빈 CSV 이동 제한.
- 휴지통 이동 시 참조 제거 확인.
- CSV/image를 slot에 연결하는 기존 domain command.
- 외부 CSV/image/FFSX drop 지원 의미.
- FFPX/FFSX file schema와 roundtrip 의미.

## 제거하지 않는 것

이 patch에서는 아직 active legacy owner를 제거하지 않는다. 기존 `installAssetTreeInteractions()`는 현재 legacy UI가 active인 동안 그대로 동작하며, owner cutover patch에서 제거 대상이 된다.

## 기각안

- React 쪽에서 별도 drag/drop 정책을 재작성: VFS 규칙이 이중화되므로 기각.
- legacy tree DOM을 Mantine sidebar 안으로 이동: `plan-004/005`의 단일 Mantine ownership과 충돌하므로 기각.
- drag/drop 기능을 cutover 후로 미루기: 실제 기능 누락 상태에서 owner를 바꾸게 되므로 기각.

## 회귀 위험

- 브라우저 dragover 시 `DataTransfer.files`가 비어 있는 상황은 기존 policy가 `types`를 사용해 이미 처리한다.
- Mantine `NavLink`가 underlying DOM에 drag/drop event를 전달하지 않으면 staging interaction이 동작하지 않을 수 있으므로 runtime 검증이 필요하다.
- legacy open branch 상태는 Mantine 경로에서 보존하지 않는다. Mantine component의 자체 open state가 UI lifecycle을 소유해야 하므로 의도된 차이다.

## 다음 단계

1. status/palette/debug 등 남은 generic sidebar UI를 Mantine으로 이식한다.
2. toolbar/sidebar/overlay 기능 누락 최종 inventory를 다시 대조한다.
3. active React/Mantine owner cutover 후 대응 legacy markup/handler/CSS를 제거한다.

## 롤백

이 patch만 되돌리면 Mantine asset tree는 click/select만 가능한 `022` 상태로 돌아간다. VFS/domain/file-format migration은 없다.
