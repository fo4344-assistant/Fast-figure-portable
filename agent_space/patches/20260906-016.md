# 20260906-016 — lifecycle domain / legacy presentation 분리

## 목적

lifecycle entry callback에서 native busy/control presentation과 공통 lifecycle domain helper를 분리한다.

현재 `enterLifecycleState()`는 importing/exporting 여부를 `body`와 native import/export controls에 반영한 뒤 `applyLifecycleDomainState()`를 호출한다. React/Mantine cutover 시 lifecycle EFSM callback이 제거 예정 native control ID를 요구하지 않도록 경계를 명시한다.

## 변경 내용

- 앱 버전 `1.1.119-alpha` → `1.1.120-alpha`
- native busy/control 동기화를 `syncLegacyLifecyclePresentation({ state })`로 추출
- `enterLifecycleState(context)`는 기존 순서대로
  1. `syncLegacyLifecyclePresentation(context)`
  2. `applyLifecycleDomainState(context)`
  를 호출

## 의미 보존

기존 importing/exporting busy 판정, `body.app-busy`, `aria-busy`, 각 native control의 `fsmWasDisabled` 보존/복구 로직은 그대로 이동한다.

`applyLifecycleDomainState()`는 기존과 같은 시점에 호출되며 error payload debug 의미도 유지한다.

## Mantine 전환과의 관계

후속 cutover에서 lifecycle EFSM entry는 `applyLifecycleDomainState`만 사용할 수 있다. Mantine 버튼 disabled/busy 표현은 React snapshot에서 lifecycle state를 읽어 렌더링해야 하므로 native control mutation helper는 legacy owner 전용이 된다.

이번 패치에서는 active owner가 아직 legacy UI이므로 wrapper가 두 단계를 모두 실행한다.

## source of truth / EFSM / core

- lifecycle source of truth는 `appFSM.state.lifecycle` 그대로 유지
- lifecycle state/transition/event 변경 없음
- import/export task 구현 변경 없음
- write lock 의미 변경 없음
- 새 상태 추가 없음
- FFPX/FFSX/Plotly 동작 변경 없음

## 선택하지 않은 방향

### native controls를 optional chaining만 추가

cutover 후에도 lifecycle command가 legacy DOM을 아는 구조가 남으므로 명시적인 presentation helper 분리를 선택한다.

### lifecycle presentation을 즉시 Mantine local state로 복제

동일 사실을 두 상태가 소유하게 되므로 선택하지 않는다. React는 `appFSM.state.lifecycle` snapshot을 직접 읽어야 한다.

### helper 호출 순서를 바꾸기

기존 error/debug 및 busy presentation 관찰 순서를 바꿀 필요가 없어 그대로 유지한다.

## 회귀 위험

낮음.

기존 함수 본문을 helper로 이동하고 같은 위치에서 같은 순서로 호출한다.

## rollback

`syncLegacyLifecyclePresentation()` 본문을 `enterLifecycleState()`에 다시 합치고 `applyLifecycleDomainState({ state, payload })` 직접 호출 형태로 복원한 뒤 앱 버전을 `1.1.119-alpha`로 되돌린다.
