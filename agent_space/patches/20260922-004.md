# 20260922-004

## 목적과 변경 내용

graph object 선택 index의 중복 source of truth를 제거한다.

기존에는 같은 선택을 `selectedObjectIndex` 전역 변수와 `appFSM.state.graphObjectIndex`가 동시에 보유했고, `selectedGraphObjectGuard()`가 두 값이 같은지를 다시 검사했다. 이 구조는 어느 쪽이 최신인지 판정해야 하는 이중 상태다.

변경 후에는 `appFSM.state.graphObjectIndex`와 `appFSM.state.graphObject`만 선택 상태를 소유한다.

- `selectedObjectIndex` 전역을 제거한다.
- selection action은 machine state만 갱신한다.
- Mantine graph editor/palette는 `useAppState()`의 `state.graphObjectIndex`를 직접 읽는다.
- graph workspace exit에서 machine graph selection을 명시적으로 clear한다.
- `SLOT_DATA_CONNECTED`가 새 데이터를 연결할 때 이전 선택을 machine state에서 clear한다.
- project load transaction의 runtime snapshot/rollback은 별도 selection 변수가 아니라 machine `graphObject/graphObjectIndex`를 캡처·복원한다.
- model helper와 chart activation에서 selection side effect를 제거한다.
- registry의 `ui` projection에서 중복 selection index를 제거한다.

## 선택 이유

graph object selection은 이미 ApplicationStateMachine에 명시적인 region과 index가 있으므로 그 값이 authoritative SoT가 되어야 한다. 별도 전역 selection buffer를 유지할 이유가 없고, 두 값을 비교하는 guard는 SoT 중복을 드러내는 구조였다.

project load 중에는 새 project render 전에 graph selection을 machine state에서 clear하고, 실패 시 같은 machine state를 rollback하도록 하여 중간 단계에서도 stale selection을 참조하지 않는다.

## 선택하지 않은 방향

### 두 selection 값을 계속 동기화

동기화 코드를 강화하면 어느 값이 최신인지 판정하는 구조가 유지된다. SoT 원칙에 맞지 않아 사용하지 않는다.

### Mantine local state로 graph selection 복제

graph object selection은 UI 표시만이 아니라 editor/domain command의 대상 선택에 사용되므로 frontend draft로 복제하지 않는다.

### model helper가 FSM state를 직접 수정

`connectDataToSlotModel()` 같은 model helper에는 FSM mutation을 넣지 않는다. selection clear는 `applySlotDataConnectedAction()`에서 수행한다.

## 전제와 후속 작업

- `graphObjectIndex`는 ApplicationStateMachine의 기존 필드이며 새 상태를 추가하지 않는다.
- `GRAPH_OBJECTS_REPLACED`는 기존 `applyGraphObjectSelectionAction`과 payload index를 통해 유효 selection을 정한다.
- 다음 작업에서는 `layoutSelected`를 backend 공유 전역에서 제거하고 Mantine layout overlay local state에서 slot id 목록을 command에 전달하도록 바꾼다.

## 롤백

역적용하면 `selectedObjectIndex` 전역과 machine state의 이중 보유 구조가 복원된다. project schema/FFPX/FFSX 형식에는 변경이 없다.
