# 20261002-008 — tracked distribution artifacts

## 목적과 변경 내용

배포 결과물을 저장소 안에 유지하도록 배포 흐름을 변경한다.

- `dist/inline/Fast-figure.html`과 `dist/split/Fast-figure.zip`을 추적 대상 산출물로 둔다.
- `.gitignore`에서 `dist/` 제외를 제거한다.
- `.github/workflows/build-distribution.yml`을 추가한다.
- main의 배포 입력이 바뀌면 GitHub Actions가 `scripts/build-portable.py`를 실행한다.
- 빌드 결과가 기존 저장소 산출물과 다를 때에만 Actions가 두 결과물을 main에 커밋한다.
- 빌드 중 main이 더 최신 커밋으로 이동하면 오래된 결과를 밀어 넣지 않고 종료한다.
- README와 LICENSE가 split ZIP 안에 원본 bytes로 포함되었는지 Actions에서 확인한다.

## README 변경

배포 결과가 더 이상 로컬에서만 생성되는 임시 `dist/`가 아니라 저장소에 추적되는
파생 산출물이라는 점을 문서화했다.

또한 실제 vendored runtime 상태와 맞게 third-party 목록을 다음 네 구성요소로 정리했다.

- React / ReactDOM 19.2.8
- Mantine 9.5.2
- Iconoir 7.11.1
- Plotly.js 2.35.2

split 배포와 inline 배포에서 각 런타임이 위치하는 방식도 함께 적었다.

## LICENSE 변경

라이선스 원문은 변경하지 않았다.

설명 문구만 현재 배포 구조에 맞게 갱신했다.

- split 배포에서는 React/Mantine runtime과 Plotly가 `vendor/` 파일로 존재한다.
- inline 배포에서는 같은 runtime 파일이 HTML에 인라인된다.
- Iconoir SVG 정의는 애플리케이션 HTML에 직접 포함된다.
- split ZIP에는 저장소 LICENSE가 그대로 포함된다.

## GitHub Actions 빌드/커밋

새 workflow는 다음 입력을 감시한다.

- `Fast-figure.html`
- `fast-figure.js`
- `fast-figure-ui.js`
- `vendor/**`
- `README.md`
- `LICENSE`
- `scripts/build-portable.py`
- workflow 자체

빌드 후 다음 파일만 staging/commit한다.

- `dist/inline/Fast-figure.html`
- `dist/split/Fast-figure.zip`

생성물 커밋은 `github-actions[bot]` 명의로 수행한다.

`dist/**` 자체는 workflow path trigger에 포함하지 않았고, generated artifact commit은
source build를 다시 시작시키지 않는다.

## 선택 이유

사용자가 저장소에서 바로 배포 결과물을 받을 수 있게 하면서도, 사람이 생성물을 직접
편집하는 별도 source of truth를 만들지 않기 위해 GitHub Actions만 생성물을 갱신하게 했다.

builder를 별도로 복제하지 않고 기존 `scripts/build-portable.py`를 그대로 호출하므로
로컬 빌드와 CI 빌드가 같은 규칙을 사용한다.

## 고려했지만 선택하지 않은 방향

### dist를 계속 ignore하고 Actions artifact로만 제공

저장소 자체에 결과물이 들어가야 한다는 요구를 충족하지 못하므로 선택하지 않았다.

### release asset만 생성

release 생성 시점과 별도 버전 정책이 필요하고, main의 최신 결과물을 저장소에 유지한다는
이번 요구보다 범위가 커서 선택하지 않았다.

### 빌드 결과를 사람이 직접 commit

source와 generated output의 동기화가 다시 수동 절차가 되므로 선택하지 않았다.

### workflow에서 source 파일까지 자동 수정

배포 workflow의 책임을 생성물 갱신으로 제한하기 위해 선택하지 않았다.

## 개발 계층 버전

이번 변경은 README, LICENSE, .gitignore, workflow와 생성물 추적 정책만 바꾼다.

`development-versions.json`의 source-code fingerprint 대상 파일은 수정하지 않으므로
Source Script, verification-model, source-code revision은 변경하지 않는다.

## 관련 생성물 변경

이 패치를 main에 반영하면 새 workflow가 실제 빌드를 수행하고 다음 파생 파일을 별도
Actions commit으로 추가한다.

- `dist/inline/Fast-figure.html`
- `dist/split/Fast-figure.zip`

해당 대형/바이너리 파생 결과물은 이 수동 변경 패치에 원문 diff로 중복 보관하지 않는다.
원천 변경과 생성 규칙은 이 패치에 기록하며, 생성물은 builder로 재현 가능하다.

## rollback

1. `.github/workflows/build-distribution.yml`을 제거한다.
2. `.gitignore`에 `/dist/`를 복원한다.
3. 추적된 `dist/` 생성물을 제거한다.
4. README와 LICENSE의 배포 설명을 이전 상태로 되돌린다.
