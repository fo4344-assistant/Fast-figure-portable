# 20261013-035 — Correct verification r12 overreach and symbol collision

## 목적과 변경 내용

첫 r12 TLC 실행에서 드러난 두 verification-model 문제를 수정하고 r13으로 올린다.

- InteractionCore: PlusCal generated symbol과 충돌한 procedure parameter `source`, `targetLocation`을 국소 이름으로 변경한다.
- SlotCore: selectedSlotId를 모든 layout operation에 강제하는 전역 invariant를 제거한다.
- slot swap 직전 selection을 `selectionBefore`에 보존하고 successful swap 직후 source/target identity 변환을 assertion으로 직접 검사한다.
- r13 fingerprint를 기록하고 TLC는 다시 pending으로 유지한다.

## 실패 원인

### InteractionCore

PlusCal translation은 `source`, `targetLocation` 이름을 생성된 symbol과 중복 정의하여 SANY semantic error를 냈다. 도메인 의미 문제가 아니라 verification 표현의 식별자 충돌이다.

### SlotCore

추가했던 `selectedSlotId ∈ VisibleSlotIds ∪ {none}` 전역 invariant가 기존 merge action에도 적용되었다. Source Script에는 merge 후 selection reconciliation 규칙이 정의되어 있지 않으므로 이 invariant는 이번 swap 검증 범위를 넘어선 새 규칙이었다.

## 선택 이유

정책에 따라 verification model은 pseudocode를 검증하기 위한 projection이지 새로운 설계 권위가 아니다. 따라서 merge semantics를 Source Script에 소급 추가하지 않고, 이번 요구인 swap selection identity만 해당 action 직후 assertion으로 검사한다.

## 고려했지만 선택하지 않은 방향

- merge 후 selectedSlotId를 anchor로 이동하도록 Source Script 변경: 이번 요구에서 도출되지 않은 새 기능이므로 기각.
- grid/merge/split까지 selection reconciliation invariant를 확대: 같은 이유로 기각.
- selectedSlotId 검증 자체 제거: swap 요구를 검증하지 못하므로 기각.

## 후속

r13 push 후 hosted TLA workflow를 다시 실행하고 translation/parse/TLC 결과를 확인한다. passed 전환은 성공 로그와 별도 validation review가 있을 때만 수행한다.
