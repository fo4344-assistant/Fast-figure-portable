# 20261001-015 — Source Script r6 FSM/API mutation contract 완결

## 변경 원인

plan-008 Phase 5에 따라 r2~r5에서 확정한 project/file/layout/caption 의미를
ApplicationStateMachine과 public FastFigureApi contract까지 일관되게 연결한다.

r5 이후 의미 blocker는 해소되었지만 application_fsm.py에는 여전히:

- global editing pointer
- protected default CSV
- mutate 후 rollback 중심 project load
- persistent caption slotMode

등 stale 하위 구현 의미가 남아 있었다.

api_ui.py도 domain category 수준 설명만 있고 method별 read/mutation authority가 닫히지 않았다.

## 의미 변경

### FSM

- global editing import와 의미 제거
- candidate-first mutation 공통 contract 정의
- project/slot-local/assets/graphs/layout/captions mutation group 책임 정의
- PROJECT_LOADED를 validate -> single commit -> runtime/projection 순서로 정리
- project move에서 default CSV 예외 제거
- graph objects=[] 허용
- slot reset이 chart/image/contentType/caption local properties 전체를 reset
- slot swap이 local properties 전체를 원자적으로 교환
- caption text event가 persistent mode 대신 explicit owner target을 받음
- slot captions insertion은 source slot caption을 유지하면서 global caption text만 변경
- grid change는 safe candidate resize만 commit

### FastFigureApi

모든 domain의 authoritative method contract를 method 단위로 추가했다.

각 method에 대해:

- read / calculation / runtime mutation / persistent mutation / export 구분
- authoritative source 또는 mutation target
- candidate-first/atomicity 의미
- failure 시 기존 authority 유지 여부

를 명시했다.

### 하위 API 교체

현재 source code의 다음 API는 authoritative Source Script surface에서 교체 대상으로 기록했다.

- print.readDefaults -> print.readSettings
- captions.readState -> captions.readGlobal/readSlot
- captions.setSlotMode -> 제거, UI-local editor target
- captions.setText -> captions.setGlobalText/setSlotText
- labels.previewPosition -> 제거
- labels.commitPosition -> labels.finishPositionInteraction

## 선택 이유

API method 이름이 owner를 숨기면 UI가 persistent mode state에 의존하게 되고,
global caption과 slot caption처럼 authority가 다른 값을 같은 command에서 암묵적으로 분기하게 된다.

owner를 method/argument에서 명시하면:

- project global state
- slot-local state
- UI-local target state

가 서로 섞이지 않는다.

candidate-first FSM contract는 r3 asset transaction과 r4 layout transaction에 이미 사용한 원칙을
project/graph/slot mutation에도 동일하게 적용한다.

## 기존 안을 채택하지 않은 기록

### 현재 source code API를 그대로 Source Script contract로 고정

채택하지 않았다.

이유:
현재 source code는 version chain상 stale lower layer이며
r4/r5에서 이미 의미가 변경된 preview/commit, slotMode 등을 그대로 보존하면
상위 Source Script가 하위 구현의 중복 state에 다시 종속된다.

### 모든 UI interaction을 FSM persistent event로 유지

채택하지 않았다.

caption editor target, label interaction finish, zoom lock처럼
figure 의미를 만들지 않는 interaction state는 UI/runtime 책임으로 남기는 편이
project Source of Truth를 작게 유지한다.

## 닫힘 판정 영향

project/file/graph/layout/caption semantics와 public mutation/API contract까지 작성되었다.

남은 작업은 Source Script 전체를 다시 읽어:

- 모듈 간 모순
- unresolved marker
- stale default CSV/editing/slotMode 의미
- duplicate authority
- project 목적/FFPX 계약

을 검증하는 closure review다.

review가 통과하기 전까지 r6는 current/open이다.

## 하위 단계 전파 범위

pseudocode/source code에서는 r6 PUBLIC_API_METHODS와 CANDIDATE_MUTATION_CONTRACT를 따라야 한다.
현재 lower-layer API compatibility가 필요하면 UI adapter에서 일시적으로 처리할 수 있으나,
legacy API를 새로운 authoritative 의미로 유지하지 않는다.
