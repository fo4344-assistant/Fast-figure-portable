## 선택 이유

상위 Source Script는 FFSX local-id remap, imported Plotly conversion state,
zero-object chart, candidate-first move를 이미 정의하고 있었다.

따라서 하위 구현에서 발견된 차이를 이유로 Source Script를 수정하지 않고
JS 구현과 stale regression assertion만 수정했다.

## 고려했지만 선택하지 않은 방향

### Source Script 수정

선택하지 않았다.
발견된 네 regression failure와 추가 move mutation 문제 모두 현재 r12의
명시적 알고리즘으로 해결 가능했다.

### FFSX와 Plotly를 하나의 CSV-remap import path로 유지

선택하지 않았다.
Plotly conversion object는 editable conversion 전에는 project CSV reference가
아니므로 FFSX package-local remap 규칙을 적용할 수 없다.

### authoritative object identity를 commit 뒤에도 유지

선택하지 않았다.
candidate commit은 ProjectObject state graph를 교체할 수 있으므로 stable id로
다시 resolve하는 것이 source-of-truth 원칙에 맞다.

### project-node move를 in-place mutation + rollback으로 유지

선택하지 않았다.
Source Script가 candidate-before-commit을 명시하고 있고 partial mutation 위험도
있으므로 whole-project candidate를 사용한다.
