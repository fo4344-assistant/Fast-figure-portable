# 20260907-040 — Mantine FFPX action buttons

## 목적

FFPX 기능의 핵심 구현과 lifecycle EFSM을 변경하지 않고, Mantine UI에서 FFPX 내보내기/불러오기 호출 버튼을 구현한다.

## 변경 범위

변경 대상은 `fast-figure-ui.js` 하나뿐이다.

- Mantine project action 영역 추가
- `FFPX 내보내기` Mantine Button 추가
- `FFPX 불러오기` Mantine Button 추가
- lifecycle 상태가 `ready`가 아니면 두 버튼 비활성화

다음은 변경하지 않는다.

- `fast-figure.js`
- `ApplicationStateMachine`
- `APP_STATE_DEFINITIONS`
- `connectLifecycleTasksToFSM()`
- `downloadProject()`
- `importProject()` / FFPX read/package/ZIP/XML 구현
- project object/class/model
- FFPX/FFSX format semantics

## 호출 경로

### 내보내기

기존 legacy 버튼은 `connectLifecycleTasksToFSM()`에 의해 다음 lifecycle 경로로 감싸진다.

```text
exportProject button
→ appFSM.run("exporting", "PROJECT_EXPORT", ...)
→ downloadProject()
```

Mantine 버튼도 같은 `appFSM.run("exporting", "PROJECT_EXPORT", ...)`을 직접 호출한 뒤 기존 `downloadProject()`를 실행한다. 따라서 lifecycle EFSM을 우회하지 않는다.

### 불러오기

기존 import lifecycle은 `importProjectFile.onchange`가 `connectLifecycleTasksToFSM()`에 의해 `PROJECT_IMPORT`로 감싸진다. Mantine 버튼은 기존 file input을 여는 역할만 수행한다.

```text
Mantine FFPX 불러오기
→ importProjectFile.click()
→ 사용자가 파일 선택
→ 기존 wrapped onchange
→ appFSM.run("importing", "PROJECT_IMPORT", ...)
→ 기존 importProject(file)
```

슬롯 선택 시 import를 거부하는 기존 UI 조건도 동일하게 유지한다.

## 이유

이번 단계의 목표는 FFPX 기능 호출 UI만 Mantine으로 옮기는 것이다. 기능 핵심이나 EFSM을 Mantine에 맞춰 재구성하면 기존 기능 경계를 훼손하고 회귀 위험이 커진다.

## 기각안

- `downloadProject()`를 수정해 Mantine 전용 인자를 받는 방식: 기능 핵심 변경이므로 기각.
- FFPX lifecycle을 별도 bridge/store로 복제: 기존 EFSM과 중복되므로 기각.
- legacy `exportProject` 버튼 `.click()` 호출: 제거 대상 UI를 내부 API처럼 사용하므로 기각.
- import parser/package 로직 재구성: 이번 UI 교체 범위를 벗어나므로 기각.

## 롤백

`20260907-040.patch`를 reverse apply하면 Mantine FFPX action 영역만 제거된다. 기존 legacy FFPX 기능은 그대로 남아 있으므로 rollback 시 기능 핵심에는 영향이 없다.

## 검사

- patch target이 `fast-figure-ui.js` 하나인지 확인
- JS syntax check
- split/portable `file://` smoke
- Mantine export가 `PROJECT_EXPORT` lifecycle을 통해 실행되는지 확인
- Mantine import 버튼이 file input만 열고 실제 import는 기존 `PROJECT_IMPORT` lifecycle 경로를 사용하는지 확인
