# 20260906-026 Mantine debug UI staging

## Purpose

Remove the legacy debug DOM from debug-state ownership before the single Mantine shell cutover, while preserving the existing debug toggle, bounded log, clear, and save behavior.

## Current problem

The current debug path mixes state and presentation:

- `debugEnabled` exists in JavaScript, but the legacy toggle handler derives the next value from `#toggleDebug.dataset.active`.
- `debugLog()` appends directly to `#debugLog.textContent`, so the DOM node is effectively the log buffer.
- Clear empties `#debugLog.textContent` directly.
- Save reads `#debugLog.textContent` directly.

This prevents a Mantine owner from using the same debug facility without keeping the legacy DOM alive.

## Change

1. Add an in-memory `debugLines` buffer next to the existing `debugEnabled` and `debugSequence` state.
2. Preserve the existing maximum of 500 retained log lines.
3. Add `debugText()` and legacy projection helpers so `#debugLog` reflects the buffer but no longer owns it.
4. Make `debugLog()` append to the buffer, update the legacy projection, and publish a UI-store invalidation after the store is ready.
5. Add DOM-independent commands for:
   - reading debug state/text,
   - enabling/disabling debug,
   - clearing the buffer,
   - saving the current buffer.
6. Replace legacy toggle/clear/save handlers with calls to those shared commands. Legacy button/text visibility updates remain presentation-only.
7. Expose the commands through `fastFigureUiBridge`.
8. Add a Mantine debug staging panel with `Switch`, `Button`, `ScrollArea`, and `Code` using the shared buffer and commands.

## Ownership

- Debug enable state: `debugEnabled`.
- Debug sequence: `debugSequence`.
- Debug log contents: `debugLines`.
- Legacy `#debugLog`: projection only.
- Mantine panel: projection and command caller only.

Debug state is intentionally session-only and is not added to the project object or FFPX format.

## Preserved behavior

- Logging remains disabled by default.
- Log numbering resets on clear.
- The retained log limit remains 500 lines.
- Console logging behavior remains unchanged.
- Save still runs `auditApp("debug:save")`, records the build/user-agent/location diagnostic entry when debugging is enabled, and downloads `chart-builder-debug-<timestamp>.log`.
- Existing legacy toggle labels and hidden state are preserved through the projection helper.
- No EFSM region/state, project schema, Plotly logic, or file-format semantics change.

## Rejected alternatives

### Keep `#debugLog.textContent` as the canonical buffer and read it from React

Rejected because the legacy DOM would remain a required state container after cutover.

### Add debug data to `ProjectObject`

Rejected because debug history is transient session diagnostics and must not become persisted project meaning.

### Maintain separate React and legacy log buffers

Rejected because it duplicates state and creates synchronization/failure-order ambiguity.

## Risk

When debugging is enabled, each appended log line also invalidates the React UI store so the staged viewer updates. This can add UI-store notifications during verbose debugging, but the buffer remains bounded and debugging is opt-in. Domain/FSM transitions are not triggered by these invalidations.

## Rollback

Revert `20260906-026`. There is no data migration because the debug buffer is not persisted.
