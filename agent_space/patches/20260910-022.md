# 20260910-022 — Legacy asset-tree renderer call cutover

## 목적
021까지 legacy asset explorer의 interaction/menu/DnD 구현을 제거한 뒤, 상태 동기화와 selection helper에 남아 있는 `renderProjectDataTree()` 호출을 제거해 legacy DOM tree renderer를 실행 경로에서 완전히 분리한다. Mantine PROJECT DATA는 `useAppState()`와 `projectDataTreeSnapshot(projectDataTreeObjects())`를 source로 사용하므로 별도 DOM tree refresh가 필요하지 않다.

## 변경 내용
- `syncAssetSelectionState()`의 `renderProjectDataTree(...)` 호출 제거.
- project/graph/image workspace sync의 legacy tree render 호출 제거.
- `selectCsvFromTree()`와 `selectImageFromTree()`의 legacy tree render 호출 제거.
- `projectDataTreeSnapshot()`/`projectDataTreeObjects()`는 Mantine tree가 사용하므로 유지.
- `renderProjectDataTree()` 정의와 DOM renderer helper는 이번 패치에서 유지하되, 성공 후 참조가 정의 1회만 남는지 검사한 뒤 다음 패치에서 삭제한다.

## Source of truth 및 EFSM 영향
없음. asset selection은 `appFSM.state.assetSelection/assetPath`, project assets는 `projectObjects`/`activeProject`가 authority다. 제거되는 호출은 동일 상태를 legacy `#assetTree` DOM에 투영하는 부수효과뿐이다. Mantine은 FSM subscription으로 같은 authority를 직접 읽는다.

## 기각안
- legacy renderer를 계속 호출하되 DOM을 숨김: 필요 없는 DOM 업데이트 비용과 ownership 흔적이 남으므로 기각.
- snapshot helper까지 제거: Mantine tree가 직접 사용하므로 기각.
- renderer 정의까지 같은 hunk에서 대규모 삭제: 먼저 실행 참조를 끊고 workflow 검증 후 dead definition을 삭제하면 rollback 원인이 명확해진다.

## 검증
Workflow의 patch/diff check, JavaScript syntax, portable build, split/portable `file://` smoke를 통과해야 한다. Mantine tree가 asset add/delete/move/import/selection 뒤 즉시 갱신되는지, graph/image workspace 전환 뒤에도 tree state가 appFSM subscription을 통해 일치하는지 확인한다.

## 롤백
이 패치만 revert하면 legacy DOM tree refresh 호출만 복원된다. 017~021의 legacy interaction cutover는 유지된다.

## 후속
`renderProjectDataTree()`가 정의 1회만 남는 것을 확인하고 renderer helper와 함께 삭제한 뒤 legacy explorer HTML/CSS/REQUIRED_CONTROL_IDS를 제거한다.
