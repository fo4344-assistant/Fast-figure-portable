# 20260906-031

## 목적

프로젝트 탐색기에서 참조 중 자산 또는 폴더를 휴지통으로 드래그할 때 제공하던 경고와 참조 정리 기능을 그대로 유지하면서, Mantine 경로의 `window.confirm` 의존성을 공통 confirmation Modal로 이관합니다.

## 변경 내용

- 내부 프로젝트 drag/drop의 move 요청을 직렬화 가능한 descriptor로 읽는 경계를 추가합니다.
  - `DataTransfer`에서 drop 시점에 종류와 원본 경로를 읽습니다.
  - Mantine 상태에는 `DataTransfer` 자체를 저장하지 않고 `{ kind, path, targetPath }`만 보관합니다.
- move-to-trash의 참조 수를 계산하는 confirmation read model을 추가합니다.
  - 참조가 있는 경우 기존 경고 문구를 그대로 제공합니다.
  - 참조가 없으면 기존처럼 즉시 이동합니다.
- 내부 move 실행을 descriptor 기반 command로 분리합니다.
  - 확인 시점에 VFS에서 원본과 대상을 다시 resolve합니다.
  - 기본 CSV, 고정 폴더, 동일 폴더, 자기/하위 폴더 이동 금지 등 기존 `assetTreeDropPolicy`를 다시 검사합니다.
  - 실제 이동은 기존 `PROJECT_NODE_MOVED` FSM 이벤트를 그대로 사용합니다.
- legacy asset-tree drop은 기존 UI owner가 남아 있는 동안 임시 `window.confirm` adapter를 유지합니다.
- Mantine `FastFigureAssetTreeStaging`은 confirmation이 필요하면 sidebar의 기존 공통 `FastFigureConfirmationStaging`으로 요청을 올립니다.
- 앱 빌드를 `1.1.135-alpha`로 올립니다.

## 기능 보존

- 프로젝트 내부 자산/폴더의 drag 이동 기능을 유지합니다.
- 휴지통 이동 시 CSV graph-object 참조 및 이미지 slot 참조 제거 의미를 유지합니다.
- 참조가 있는 경우 정확한 참조 개수를 보여주는 기존 경고를 유지합니다.
- 참조가 없는 경우 추가 확인 없이 바로 휴지통으로 이동합니다.
- 기본 빈 CSV는 이동할 수 없습니다.
- 기본 프로젝트 폴더는 이동할 수 없습니다.
- 폴더를 자기 자신이나 하위 폴더로 이동할 수 없습니다.
- 이미 같은 폴더로의 이동은 거부합니다.
- 휴지통의 자산을 슬롯에 연결할 수 없는 규칙을 유지합니다.
- 일반 폴더 간 move, 프로젝트 자산을 슬롯에 link, 외부 파일 import 동작은 변경하지 않습니다.
- legacy tree의 branch open-state 보존은 legacy path에서 계속 유지합니다.

FFPX/FFSX schema, project VFS 구조, `PROJECT_NODE_MOVED` 의미, EFSM transition 정의는 변경하지 않습니다.

## 선택 이유

브라우저의 `DataTransfer`는 drag/drop 이벤트 수명에 묶인 임시 객체이므로 Mantine Modal이 열려 있는 동안 React state의 source of truth처럼 보관하기에 적절하지 않습니다. drop 시점에 필요한 프로젝트 경로만 descriptor로 추출하고, 확인 시점에 현재 domain state에서 다시 resolve하는 편이 stale UI 상태와 domain 상태의 이중 소유를 피합니다.

또한 현재 confirmation Modal은 휴지통 비우기, 슬롯 초기화, 참조 중 자산 삭제가 공유하고 있으므로 drag-to-trash 역시 같은 상위 confirmation 기능으로 통합하는 것이 최소 복잡도와 UI 일관성에 맞습니다.

## 고려했지만 선택하지 않은 방향

### 참조 중 항목의 drag-to-trash 금지

현재 제공되는 cascade 참조 제거 기능을 축소하므로 기각했습니다.

### 경고 없이 항상 휴지통으로 이동

안전 확인 기능을 삭제하므로 기각했습니다.

### `DataTransfer`를 React state에 저장

브라우저 이벤트 객체를 Modal 수명까지 보관하면 수명과 재사용 가능성이 불명확하고 임시 UI 객체가 command authority처럼 됩니다. 직렬화 descriptor를 사용합니다.

### Mantine용 drag/drop 구현을 별도로 작성

legacy와 Mantine이 서로 다른 VFS 이동 규칙을 갖게 되므로 기각했습니다. 기존 `assetTreeDropPolicy`와 `PROJECT_NODE_MOVED`를 재사용합니다.

### 모든 drag/drop을 이번 패치에서 dialog 기반으로 재작성

외부 파일 import collision은 replace/rename 선택이라는 별도의 기능 의미가 있습니다. 이번 패치에는 내부 move-to-trash만 포함하고 import collision은 다음 독립 패치에서 처리합니다.

## 위험 요소

- Modal이 열린 사이 원본 자산 또는 대상 폴더가 변경될 수 있으므로 confirmed command에서 다시 resolve하고 policy를 재검사합니다.
- 폴더 이동 시 포함 자산과 참조 수가 바뀔 수 있으므로 confirmation descriptor의 reference count는 표시용이며, 실제 `PROJECT_NODE_MOVED` 실행은 현재 상태를 사용합니다.
- legacy open-state 보존은 DOM 기반이므로 Mantine confirmed path에서는 사용하지 않습니다. 이는 기능 삭제가 아니라 Mantine NavLink가 legacy `<details>` open-state를 소유하지 않는 UI 구현 차이입니다.
