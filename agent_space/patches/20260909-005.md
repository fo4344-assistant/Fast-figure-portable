# 20260909-005 — Mantine graph/data editor ownership

## 목적

`review-010-mantine-ui-inventory.md`의 Graph editor / 데이터 편집 항목 중 서로 강하게 결합된 핵심 경로를 하나의 UI ownership 단위로 Mantine으로 옮긴다.

이번 패치는 이전처럼 CSV header, editable toggle, graph object editor를 각각 독립 패치로 잘게 나누지 않는다. 세 기능이 같은 CSV/chart/editor 상태와 선택 상태를 공유하므로 같은 패치에서 값 기반 command 경계를 만들고 Mantine UI가 그 경계를 직접 사용한다.

## 변경 파일

- `fast-figure.js`
- `fast-figure-ui.js`

## 변경 내용

### 1. graph object 값 기반 command

`fast-figure.js`에 다음 UI 독립 함수들을 추가한다.

- `graphObjectFromValues(chart, csv, values, current)`
- `commitGraphObjectsFromValues(chart, objects, index)`
- `selectProjectCsvForGraph(csvId)`
- `selectGraphObjectFromValues(index)`
- `updateGraphObjectFromValues(index, values)`
- `moveGraphObjectFromValues(from, to)`
- `deleteGraphObjectFromValues(index)`
- `addGraphObjectFromValues(values)`

기존 project chart object와 `GRAPH_OBJECTS_REPLACED`, `SELECT_GRAPH_OBJECT`, `CLEAR_GRAPH_OBJECT`, `SLOT_DATA_CONNECTED` 경로를 그대로 사용한다. 별도 React graph model이나 migration store를 만들지 않는다.

오브젝트 수치 범위는 기존 의미를 유지한다.

- line width: 0.1–20
- marker size: 1–40
- bar opacity: 0.05–1
- bar line width: 0–10
- X axis: bottom/top
- Y axis: left/right
- type: scatter / markers / lines+markers / bar / hidden

CSV를 바꾸면 새 CSV의 실제 column definition에 없는 기존 X/Y 값은 새 CSV의 기본 column selection으로 정상화한다.

### 2. CSV header line command

`setCsvHeaderLinesFromValues(csvId, value)`를 추가한다.

- `headerLineCount()`로 0..row count 범위를 유지한다.
- project CSV의 `headerLines`가 source of truth다.
- 해당 CSV를 참조하는 editable chart만 기존 `rebuildEditableGraph()`로 재생성한다.
- dashboard를 다시 렌더링하고 `CSV_HEADER_LINES_CHANGED` notification을 발생시킨다.
- legacy `#headerLines`와 table preview는 retained legacy renderer를 위한 one-way projection으로만 갱신한다. Mantine callback은 이 DOM 값을 읽지 않는다.

기존 `#headerLines.onchange`도 동일 command를 호출하도록 변경한다.

### 3. editable 전환 command

기존 `#editorEditable.onclick` 안에 있던 Plotly JSON → editable 변환 기능을 `setGraphEditableFromValues()`로 추출한다.

- CSV reference가 없는 imported Plotly chart는 기존 conversion rows / fallback rows 규칙으로 project CSV를 생성한다.
- 생성 CSV를 기존 graph objects에 연결한다.
- `chart.editor.editable`이 계속 authority다.
- `rebuildEditableGraph()`, `syncEditableUi()`, `renderDashboard()`를 그대로 사용한다.
- Mantine 경로는 legacy `#headerLines`, `loadData()`를 읽거나 클릭하지 않는다.

legacy editable 버튼은 이 command를 호출하는 얇은 retained projection으로 바뀐다.

### 4. Mantine `FastFigureGraphDataEditor`

`slot.graph` workspace에서 다음 기능을 직접 제공한다.

- project CSV 선택
- CSV header 행 수 변경
- 최대 30행 CSV preview
- editable / original JSON 전환
- graph object 추가
- graph object 선택
- drag reorder
- graph object 삭제
- object color
- object CSV 변경
- X/Y column
- X/Y axis side
- type
- legend name
- line width / dash
- marker symbol / size
- bar opacity / border width

오브젝트 목록과 form은 `activeProject`, selected chart, existing `selectedObjectIndex`, project CSV를 직접 읽는다. React local state는 drag 중 index 외에는 persistent graph state를 소유하지 않는다.

## Source of truth

변경하지 않는다.

- project CSV: 기존 `activeProject.csvFiles`
- CSV header lines: 각 project CSV의 `headerLines`
- graph objects/settings: 기존 `chart.editor.objects`
- editable: 기존 `chart.editor.editable`
- selected graph object: 기존 application selection state / `selectedObjectIndex`
- selected asset/workspace: 기존 `appFSM`

Mantine form 값의 독립 복사본을 영속 상태로 두지 않는다.

## EFSM / domain 영향

새 EFSM을 추가하지 않는다. 기존 event/notification과 기존 project model mutation 경계를 사용한다.

이번 패치가 바꾸는 것은 legacy DOM event handler에 묻혀 있던 실제 command를 값 기반으로 호출 가능하게 만드는 것과 React/Mantine UI ownership이다.

Plotly renderer, FFPX/FFSX, chart validation, CSV parser, VFS 의미는 변경하지 않는다.

## 선택하지 않은 방향

### 각 기능을 별도 patch로 분리

CSV header, editable toggle, object editor가 같은 legacy data/graph form 상태를 공유하므로 각자 분리하면 임시 DOM bridge와 양방향 sync가 늘어난다. 사용자가 지적한 중간 작업 반복 문제도 커지므로 하나의 ownership 패치로 묶었다.

### Mantine 전용 graph store

project chart model과 별도의 React/Mantine graph store를 만들면 동일 의미의 source of truth가 두 개가 된다. 사용하지 않는다.

### legacy form `.value`를 Mantine callback에서 읽기

빠르지만 `plan-006`과 review-010의 직접 ownership 규칙을 위반한다. 값 기반 command로 대체한다.

### legacy graph object list를 Mantine 안에 DOM clone

renderer ownership이 계속 legacy DOM에 남으므로 사용하지 않는다. Mantine 목록은 project graph objects에서 직접 렌더링한다.

## 이번 패치에 포함하지 않은 항목

Graph editor의 전역 graph layout과 네 axis의 상세 설정은 아직 legacy `axisFields()` renderer에 남아 있다. 이 패치는 그 앞의 CSV/object/editable ownership을 실제로 이전하는 본체 단계이며, 다음 graph editor 확장에서 같은 값 기반 방식으로 global/axis settings를 직접 연결한다.

README, layout, label, caption, print/export의 Mantine ownership은 별도 inventory 항목이다.

## 위험 요소

- imported Plotly chart를 editable로 전환할 때 conversion CSV 생성 경로가 기존 동작과 동일해야 한다.
- graph object CSV를 변경할 때 존재하지 않는 X/Y column을 새 CSV의 column으로 정상화해야 한다.
- graph object reorder 이후 selection index가 이동한 object를 가리켜야 한다.
- 마지막 graph object 삭제 시 기존 `GRAPH_OBJECTS_REPLACED` recovery 의미를 보존해야 한다.
- Mantine controlled inputs의 연속 변경이 appFSM revision을 발생시키므로 selection이 유지되는지 smoke/manual 확인이 필요하다.
