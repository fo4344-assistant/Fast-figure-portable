# 20261014-018 — Implement plan-014 projection invalidation and Layout deselection as WIP

## 변경

- `fast-figure.js`
  - trash move/empty action이 실제 removed graph reference 수와 reset image slot 수를 payload에 남긴다.
  - `dashboardProjectionEffect`와 `dispatchDashboardAffectingEvent`를 추가한다.
  - PROJECT_NODE_MOVED / PROJECT_TRASH_EMPTIED / SLOTS_SWAPPED는 send 반환 뒤 한 번만 full dashboard invalidation을 판정한다.
- `fast-figure-ui.js`
  - settings content click hook을 추가한다.
  - Layout slot click과 merge/split/clear command는 propagation을 차단해 selection을 먼저 소비한다.
  - 그 밖의 Layout Modal content click은 UI-local selection을 clear한다.
- browser regression에 Layout background deselection과 trash image-reference stale projection 검사를 추가한다.
- Source Code를 r24로 올리되 verification TLC가 아직 진행 중이므로 상태는 `stale`로 유지한다.

## 선택 이유

검증 workflow가 장시간 실행되는 동안 구현과 browser/build 검증을 병렬화하되, TLC 성공 전 Source Code를 current로 선언하지 않기 위해 WIP 규칙을 사용한다. 영속 project state나 schema를 추가하지 않으므로 중간 commit도 데이터 호환성을 깨뜨리지 않는다.

## 기각한 방향

- appFSM 내부 completion subscriber 추가: 동기 send 반환 경계가 이미 존재한다.
- 모든 mutation마다 renderDashboard 호출: targeted projection과 불필요한 full render를 구분할 수 없다.
- renderer가 VFS를 재탐색해 변화 추측: mutation owner가 이미 정확한 결과를 알고 있다.
- Layout selection을 appFSM/project에 저장: component-local lifetime을 불필요하게 승격한다.

## 검증 상태

이 commit 자체는 최종 완료가 아니다. push-trigger development-layer check, browser regression, distribution build와 진행 중 TLC 결과를 확인한 뒤 validation review에서 current/passed 여부를 확정한다.
