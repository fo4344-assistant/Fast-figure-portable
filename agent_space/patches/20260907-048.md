# 20260907-048 — Mantine selected-asset deletion confirmation

## Purpose

Replace the selected CSV/image asset deletion call-side UI with Mantine controls and confirmation while preserving the existing project model and functional EFSM events.

The legacy `deleteProjectCsv()` and `deleteProjectImage()` functions are not called from Mantine because they contain `window.confirm()` internally. The Mantine path instead performs the same UI-controller orchestration using the existing EFSM events that those handlers already use.

## Scope

Only `fast-figure-ui.js` is modified.

No changes are made to:

- `fast-figure.js`
- `deleteProjectCsv()` / `deleteProjectImage()` legacy handlers
- `ApplicationStateMachine`
- `APP_STATE_DEFINITIONS`
- project classes/models
- chart/slot/image mutation actions
- project VFS

## Existing functional events reused

CSV deletion uses existing events already present in the application:

- `CLEAR_GRAPH_OBJECT` to clear graph-object UI/FSM selection before referenced objects are removed
- `GRAPH_OBJECTS_REPLACED` for charts that reference the CSV
- `DATA_OBJECT_DELETED`
- `CLEAR_ASSET_SELECTION`

Image deletion uses:

- `SLOTS_RESET` when image slots reference the image
- `IMAGE_OBJECT_DELETED`
- `CLEAR_ASSET_SELECTION`

No new event or functional mutation path is introduced.

## Exact changes

1. Adds presentation-local deletion-dialog state to `FastFigureDataActions`.
2. Adds a Mantine `선택 에셋 삭제` button enabled only for a currently selected deletable CSV/image while lifecycle state is ready.
3. The default empty CSV remains protected and cannot be deleted, matching the existing functional rule.
4. When the selected asset has no references, deletion can proceed immediately as in the existing legacy behavior.
5. When references exist, Mantine opens a confirmation `Modal` with the same semantic warning:
   - CSV: referenced graph objects will also be removed.
   - image: referencing image slots will be reset.
6. Confirming a referenced CSV deletion:
   - clears graph-object selection through the existing `CLEAR_GRAPH_OBJECT` event rather than writing React state or calling legacy DOM,
   - removes objects referencing that CSV with existing `GRAPH_OBJECTS_REPLACED` events,
   - sends `DATA_OBJECT_DELETED`,
   - sends `CLEAR_ASSET_SELECTION`,
   - rerenders and reports status.
7. Confirming a referenced image deletion:
   - sends `SLOTS_RESET` for referencing slots,
   - sends `IMAGE_OBJECT_DELETED`,
   - sends `CLEAR_ASSET_SELECTION`,
   - rerenders and reports status.
8. The dialog captures asset identity rather than relying on whatever becomes selected later.
9. No legacy delete button `.click()` and no native `window.confirm()` are used by the Mantine path.

## State ownership

The dialog state contains only temporary confirmation metadata. Asset, chart, graph-object selection, and slot state remain owned by the existing project model/FSM.

## Why this direction

The existing deletion functions mix browser confirmation with UI-controller orchestration, but the actual mutations are already separated into FSM/EFSM events. Calling those legacy functions from Mantine would preserve native confirmation. Modifying EFSM or project mutation code is unnecessary. The narrow replacement is therefore a Mantine confirmation controller that dispatches the existing events.

## Rejected alternatives

### Calling `deleteSelectedAsset()` / legacy delete button

Rejected because that reaches the legacy `window.confirm()` path and would make legacy UI behavior part of the Mantine implementation.

### Adding Mantine-specific delete events

Rejected because all required functional mutation events already exist.

### Writing `selectedObjectIndex` directly from React

Rejected because the existing `CLEAR_GRAPH_OBJECT` FSM event already represents that UI state transition and avoids a second direct state-mutation path.

### Moving chart/slot mutation logic into React state

Rejected because persistent state ownership must remain in the existing model/EFSM.

### Refactoring `fast-figure.js` deletion functions in this patch

Rejected to preserve the user's requirement that UI replacement not alter EFSM-connected functional core during this migration step.

## Rollback

Revert the `20260907-048.patch` changes in `fast-figure-ui.js`. No data-format, project-model, or EFSM rollback is required.
