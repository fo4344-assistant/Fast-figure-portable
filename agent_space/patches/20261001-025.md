# 20261001-025 — pseudocode r2 공통 식별자 추적성 보완

## 변경 원인

pseudocode r1 검증에서 모든 Source Script 함수는 대응되었지만,
여러 top-level 상수·공통 변수의 의미만 번역되고 식별자 이름 자체가 생략된 것을 발견했다.

Source Script 정책은 같은 대상을 단계마다 다른 이름으로 부르지 않고
공통 식별자를 단계 간 일관성에 사용하도록 요구한다.

이 문제는 Source Script의 의미 누락이 아니라 pseudocode 번역의 추적성 누락이다.

## 변경 내용

9개 Source Script 대응 pseudocode 파일에 `Source identifiers` 절을 추가했다.

각 절은 해당 Source Script의 top-level 공통 식별자를 이름 그대로 보존하고
pseudocode에서 어떤 책임을 가리키는지 연결한다.

알고리즘 실행 순서나 domain 의미는 변경하지 않았다.

version metadata:

- pseudocode revision: r2
- status: current
- validation: pending
- fingerprint: `sha256:39d7bccaa29c116b5e8db207a2d604742ab726711d37fe7b86f3ddb92f025759`
- derived Source Script: `sha256:c8bde1257048128f5c17081cb08fb9ef5bee1cc94dd9bb690d3e9419032655db`

## 선택 이유

pseudocode는 자연어 요약이 아니라 Source Script와 대상 구현 사이의 정식 번역 경계다.

동일한 규칙을 의미만 비슷한 제목으로 바꾸어 쓰면
후속 구현에서 어느 Source Script 식별자를 구현하는지 다시 추론해야 한다.
식별자 이름을 그대로 유지하면 의미를 추가하지 않고 추적성만 복구할 수 있다.

## 고려했지만 선택하지 않은 방향

### r1을 그대로 validation 통과

선택하지 않았다.

함수 이름만 보존하고 공통 상태/규칙 식별자를 생략하면
정책의 단계 간 변수·참조 일관성 기준을 충분히 만족하지 못한다.

### Source Script를 수정

선택하지 않았다.

누락된 것은 Source Script 내용이 아니라 pseudocode의 번역 표기다.
Source Script r12는 이미 필요한 식별자를 명시하고 있다.

### 모든 상수 정의를 Source Script 문장 그대로 복제

선택하지 않았다.

pseudocode는 실행 절차 검증 단계이므로 Source Script 설명 전체를 중복할 필요는 없다.
식별자와 책임 연결을 보존하고 실제 실행 의미는 기존 pseudocode 본문에서 유지한다.

## 다음 검증

r2에서:

1. 모든 Source Script 함수 이름 대응
2. 모든 top-level 공통 식별자 이름 대응
3. input/output/reference/order/failure/commit 의미 대조
4. pseudocode에 Source Script에 없는 새 domain rule이 없는지

를 다시 확인한다.

통과 전까지 validation은 pending이다.
