# 20260915-009 — Remove native caption editor/install ownership

## Purpose
Continue the annotation cutover cleanup after `20260915-008` by removing the remaining native caption editor/install path and simplifying the shared caption commit helper so active Mantine code no longer carries a legacy DOM-mode parameter.

## Exact changes
- Replace `applyCaptionSettings(fromControls = true, notify = true)` with `applyCaptionSettings(notify = true)`.
- Remove all reads/writes of deleted native caption controls from `applyCaptionSettings`.
- Preserve `syncDashboardCaption()`, debug logging, and `CAPTION_SETTINGS_CHANGED` notification behavior.
- Remove `installCaptionSettings`, whose only responsibility is binding deleted native caption inputs.
- Remove `installAnnotationPopup`, which binds removed native annotation toggles and still references the already deleted `syncPopupBounds()` helper.
- Change the Mantine caption overlay from `applyCaptionSettings(false)` to `applyCaptionSettings()` so notification behavior remains unchanged under the new signature.

## Why this direction
The active caption editor is `FastFigureCaptionOverlay`, while project caption state remains in `activeProject`. The native caption inputs and annotation popup controls no longer exist in `Fast-figure.html`. Keeping a `fromControls` mode and native installers would preserve a second dead UI ownership path and a dangling dependency on removed popup code.

The new helper remains renderer-neutral: it does not own editor state and only projects already-authoritative project state into the actual dashboard caption, logs it, and emits the existing notification.

## Rejected alternatives
- Keep `fromControls` for compatibility: rejected because no live caller owns native caption controls anymore.
- Recreate hidden caption inputs or annotation toggle DOM: rejected because hidden bridge controls violate the current Mantine ownership/source-of-truth policy.
- Inline `syncDashboardCaption()` and notification logic into React: rejected because the existing helper is a useful UI-independent commit/render boundary and is already shared by the active Mantine path.
- Change caption limits, text semantics, slot-caption behavior, or renderer structure here: rejected as unrelated to native UI ownership removal.

## Source of truth
`activeProject.annotations.captions` and existing compatibility accessors remain authoritative. Mantine owns caption editing UI. `syncDashboardCaption()` continues to own rendering of the actual dashboard caption.

## EFSM/core impact
No intended change to caption state transitions, notification names, slot/whole caption selection, persistence, FFPX/FFSX semantics, or export geometry. The previous Mantine call used `applyCaptionSettings(false)` where `false` disabled native-control reads but left `notify=true`; the new zero-argument call preserves that notification behavior.
