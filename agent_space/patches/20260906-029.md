# 20260906-029

## 목적

슬롯 초기화 기능을 축소하지 않고 기존 `window.confirm` 및 legacy 버튼 `.click()` 우회를 Mantine 공통 confirmation Modal로 이관합니다.

## 변경 내용

- 슬롯 초기화 확인 내용을 `selectedSlotResetConfirmation()`으로 분리합니다.
- 실제 초기화 동작을 `resetSelectedSlotConfirmed()` command로 분리합니다.
- 취소 시 기존 debug 의미를 유지하는 `cancelSelectedSlotReset()`을 추가합니다.
- 기존 native 버튼은 임시 legacy adapter인 `resetSelectedSlotLegacy()`를 사용합니다.
- Mantine sidebar의 `슬롯 초기화` 버튼은 `FastFigureConfirmationStaging`을 열고 확인 시 동일 command를 호출합니다.
- Modal이 열려 있는 동안 대상 슬롯을 descriptor에 고정하고, 확인 시 selection이 달라졌으면 다른 슬롯을 잘못 초기화하지 않습니다.
- 앱 빌드를 `1.1.133-alpha`로 올립니다.

## 기능 보존

기존 슬롯 초기화의 다음 동작을 유지합니다.

- 선택 슬롯이 없으면 `초기화할 슬롯을 먼저 선택하세요.` status와 `slotReset:no-selection` debug를 남깁니다.
- 초기화 전 `데이터를 잃습니다.` 경고를 표시합니다.
- 사용자가 취소하면 mutation 없이 `slotReset:cancel` debug를 남깁니다.
- 확인하면 기존 `SLOTS_RESET` FSM event를 그대로 사용합니다.
- asset selection을 기존과 같이 지웁니다.
- dashboard를 다시 렌더링합니다.
- `선택한 슬롯을 초기화했습니다.` status를 유지합니다.
- `slotReset:complete`에 기존 `removedChartIds` 정보를 유지합니다.

FFPX/FFSX schema, slot reset domain semantics, EFSM transition 정의는 변경하지 않습니다.

## 선택 이유

슬롯 초기화 버튼을 제거하거나 확인 절차를 없애는 것은 기능 축소입니다. 반대로 confirmation을 Mantine 공통 Modal로 승격하면 기능은 유지하면서 close/Escape/backdrop/focus/button layout 규칙을 다른 파괴적 작업과 공유할 수 있습니다.

## 고려했지만 선택하지 않은 방향

### Mantine 버튼에서 legacy `#resetSelectedSlot.click()` 호출

DOM 우회를 유지해 single-owner cutover를 방해하므로 기각했습니다.

### 확인 없이 즉시 초기화

기존 안전 절차를 제거하므로 기각했습니다.

### 슬롯 초기화 전용 popup 작성

`027`의 공통 confirmation 기능과 중복되므로 기각했습니다.

### 선택 변경 시 현재 슬롯을 초기화

Modal을 연 시점과 확인 시점의 대상이 달라질 수 있어 잘못된 슬롯을 지울 위험이 있으므로, 확인 descriptor의 `slotId`를 guard로 사용합니다.

## 위험 요소

- Mantine Modal 취소가 기존 browser confirm 취소와 동일하게 debug만 남기고 mutation하지 않아야 합니다.
- stale slot guard는 기존 browser confirm에는 없던 비동기 UI 안전장치지만 domain 의미를 바꾸지 않고 오작동만 방지합니다.
