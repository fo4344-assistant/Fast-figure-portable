# 20260928-003

## 목적과 변경 내용

Mantine Print/Export overlay가 core export 함수와 dashboard reference width를 직접 참조하던 경로를 `FastFigureApi.print` 경계 뒤로 이동한다.

추가 API:

- `readDefaults()`: 현재 project layout의 reference width를 바탕으로 초기 export width를 반환
- `save(options)`: 기존 `exportDashboardTarget(options)` 실행
- `capture(options)`: 기존 `exportDashboard(true, options)` 실행

Mantine `FastFigurePrintOverlay`는 입력 draft(width/height/DPI/format/status message)와 lifecycle UI 처리만 유지하고 실제 export renderer는 위 API를 통해 호출한다.

## 선택 이유

export renderer와 layout reference width는 core/project 상태 및 dashboard renderer에 의존한다. Mantine frontend가 해당 구현 함수를 직접 참조하지 않고 core가 소유한 명시적 API를 사용해야 `review-011-sot-api-boundary.md`의 frontend/API/core 책임 경계를 유지할 수 있다.

반면 width/height/DPI/format 입력 중 아직 적용하지 않은 값과 진행 메시지는 overlay 수명에만 필요한 UI draft이므로 React local state에 두는 것이 맞다.

## 선택하지 않은 방향

### export 옵션을 global store에 저장

입력 draft를 두 번째 runtime SoT로 만들 이유가 없으므로 추가하지 않는다.

### export 알고리즘을 React 쪽으로 이동

Plotly/image/caption/label geometry와 raster validation을 포함한 기존 functional renderer를 분산시키므로 선택하지 않는다.

### lifecycle helper까지 core API로 이동

`runLifecycleTask`는 import/export 전반의 UI/application lifecycle을 공통 처리하고 있으며 이번 ownership 단위의 문제는 export renderer 직접 호출이다. 이번 패치에서 그 범위를 확대하지 않는다.

### width/height/DPI validation을 core와 UI 양쪽에서 새로 통합

기존 renderer 자체의 validation을 변경하지 않는다. Mantine 입력 clamp도 기존 UX와 동일하게 유지한다.

## 보존 사항

- PNG/JPEG
- DPI 36–1200
- width 100–20000
- height 공란 시 자동 계산
- raster 16384px / 64MP 제한
- caption/label/slot geometry
- status callback
- `PRINT_EXPORT` / `CAPTURE_EXPORT` lifecycle
- schema/FFPX/FFSX 의미
