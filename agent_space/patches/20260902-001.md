# 20260902-001 — 이미지 설정 selector 순수 읽기 교정

## 목적과 변경 내용

`plan-004.md`의 첫 교정 항목으로 `20260901-025`에서 추가된 `selectedImageSettingsModel()`의 읽기 부작용을 제거한다.

현재 `selectedImageSettingsModel()`은 `normalizeImageSettings(image)`를 호출한다. 이 함수는 누락되거나 범위를 벗어난 이미지 설정을 정규화하면서 `image.settings` 자체를 다시 대입하므로, UI가 값을 읽는 것만으로 project/domain state가 변경될 수 있다.

이번 패치는 기존 정규화 규칙을 두 벌로 복제하지 않고 다음처럼 책임을 분리한다.

- 순수 함수 `normalizedImageSettingsValues(settings)`를 추가해 현재 이미지 설정 정규화 계산만 수행한다.
- 기존 `normalizeImageSettings(image)`는 이 순수 함수를 호출한 뒤 결과를 `image.settings`에 대입하여 기존의 의도된 mutation 동작을 유지한다.
- `selectedImageSettingsModel()`은 `normalizedImageSettingsValues(image.settings)`를 직접 사용하여 domain state를 변경하지 않는 snapshot만 반환한다.
- 앱 버전을 `1.1.56-alpha`로 올린다.

## 선택한 이유

핵심 문제는 정규화 규칙 자체가 아니라 **읽기 selector가 mutation 경계를 통과한다는 점**이다.

기존 `normalizeImageSettings()`의 정규화 결과와 허용 범위를 그대로 유지하면서 계산과 대입을 분리하면:

- selector/read 경계는 side effect 없는 순수 읽기가 된다.
- 기존 legacy UI와 image mutation 경로가 의존하는 `normalizeImageSettings(image)` 동작은 바뀌지 않는다.
- fit/scale/x/y 기본값 및 clamp 규칙을 selector와 mutation 경로에 중복 구현하지 않는다.
- 하나의 정규화 계산 규칙만 유지하므로 source of truth 원칙과 최소복잡도 원칙에 맞는다.

## source of truth 검토

이미지 설정의 유일한 source of truth는 계속 project image model의 `image.settings`다.

`normalizedImageSettingsValues(settings)`가 반환하는 객체는 계산 결과일 뿐 저장 상태가 아니다. 함수는 입력 객체를 수정하지 않고 새 객체를 반환한다.

`selectedImageSettingsModel()`이 반환하는 고정 객체 역시 렌더 한 번에 사용하는 snapshot이며 다른 기능의 권위 상태로 사용하지 않는다.

실제 `image.settings` 정규화가 필요한 기존 mutation/sync 경로는 계속 `normalizeImageSettings(image)`를 통해 명시적으로 대입한다. 이번 패치는 그 기존 의미를 변경하지 않는다.

## 기능/EFSM 영향

- EFSM event, transition, guard는 변경하지 않는다.
- 이미지 import/export 의미를 변경하지 않는다.
- 이미지 렌더링 규칙을 변경하지 않는다.
- `applyImageSettingsFromValues()`와 `insertEmptySlotImage()`를 변경하지 않는다.
- Mantine staging component의 callback과 값 범위를 변경하지 않는다.
- legacy image settings UI의 정규화 동작을 변경하지 않는다.

즉 Mantine 전환 때문에 domain 동작을 바꾸는 패치가 아니라, UI read adapter의 책임 경계를 바로잡는 교정 패치다.

## 고려했지만 선택하지 않은 방향

### `selectedImageSettingsModel()`에서 image를 얕게 복사한 뒤 기존 `normalizeImageSettings()` 호출

선택하지 않았다. domain state는 보호할 수 있지만 순수 계산을 얻기 위해 가짜 mutable image 객체를 만드는 우회 구조가 생긴다. 정규화 계산과 대입 책임을 분리하는 쪽이 더 직접적이고 재사용 가능하다.

### selector 안에서 fit/scale/x/y 정규화 규칙을 별도로 다시 작성

선택하지 않았다. 같은 기본값과 clamp 범위를 두 군데에서 관리하게 되어 이후 규칙 변경 시 불일치 가능성이 생긴다.

### `normalizeImageSettings()` 자체를 완전한 순수 함수로 의미 변경

선택하지 않았다. 기존 호출부는 이 함수가 `image.settings`를 보정한다는 동작에 의존할 가능성이 있으며, 이번 문제를 고치기 위해 그 모든 호출부의 의미를 한 번에 변경할 필요가 없다.

### `20260901-025` 전체 롤백

선택하지 않았다. 값 기반 image settings command, 빈 이미지 삽입 공통 command, Mantine staging UI 자체는 현재 구조에 적합하다. 문제가 있는 read 경계만 수정하는 것이 최소 범위다.

## 회귀 위험

낮다. 새로운 계산 함수는 기존 `normalizeImageSettings()`의 계산식을 그대로 이동하고 기존 함수는 그 결과를 이전과 동일하게 `image.settings`에 대입한다.

주의할 항목:

- `settings`가 없거나 객체가 아닐 때 기본값이 기존과 동일한지
- `fit`이 유효하지 않을 때 `contain`이 유지되는지
- `scale` 1–1000, `x/y` -100–200 clamp가 동일한지
- 기본 `scale=100`, `x=50`, `y=50`이 동일한지
- 기존 `settings`의 추가 필드가 spread로 보존되는지
- selector 호출 전후 `image.settings` 객체와 값이 바뀌지 않는지

## rollback

이 패치는 독립적으로 되돌릴 수 있다.

rollback 시:

1. `normalizedImageSettingsValues(settings)`를 제거한다.
2. `normalizeImageSettings(image)` 안에 기존 정규화 계산과 `image.settings = {...}` 대입을 복원한다.
3. `selectedImageSettingsModel()`을 다시 `normalizeImageSettings(image)` 호출 방식으로 되돌린다.
4. 앱 버전을 이전 값으로 되돌린다.

다른 Mantine staging 패치나 EFSM 변경을 함께 롤백할 필요가 없다.
