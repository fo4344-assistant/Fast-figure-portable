# 20260910-019 — Legacy asset delete/create wrapper removal

## 목적
017에서 legacy asset controls의 event wiring을 끊고 018에서 legacy action-menu 계열을 제거한 뒤 호출되지 않는 native-confirm 삭제 wrapper와 native-prompt 폴더 생성 wrapper를 제거한다. Mantine PROJECT DATA/DataActions가 이미 동일 기능을 기존 FSM/project model 경계로 수행하므로 중복 UI 정책 코드를 남기지 않는다.

## 변경 내용
- `deleteProjectCsv()` 제거: legacy `window.confirm` 기반 CSV cascade-delete wrapper다.
- `deleteProjectImage()` 제거: legacy `window.confirm` 기반 image/reference reset wrapper다.
- `deleteSelectedAsset()` 제거: 위 두 wrapper로 dispatch하던 legacy 선택 삭제 entry다.
- `createAssetDirectory()` 제거: legacy `window.prompt`로 이름을 받아 `PROJECT_DIRECTORY_CREATED`를 보내던 wrapper다.
- `selectCsvFromTree()`, `selectImageFromTree()`, `downloadProjectAsset()` 등 Mantine에서 아직 재사용하는 command/helper는 유지한다.

## Source of truth 및 EFSM 영향
없음. CSV/image 삭제 authority는 기존 `DATA_OBJECT_DELETED`, `IMAGE_OBJECT_DELETED`, `GRAPH_OBJECTS_REPLACED`, `SLOTS_RESET` events이며 Mantine DataActions가 이를 직접 사용한다. 폴더 생성 authority도 `PROJECT_DIRECTORY_CREATED` 그대로다. 이번 패치는 호출되지 않는 UI wrapper만 삭제한다.

## 기각안
- wrapper를 남기고 native confirm/prompt만 Mantine으로 바꾸기: 동일 기능의 두 UI entry가 다시 생기므로 기각.
- delete semantics를 새 공용 함수로 재추출: 현재 Mantine 경로가 이미 명시적인 FSM event 조합을 사용하고 있어 새로운 abstraction을 추가할 이득이 없다.
- selection helper까지 함께 제거: Mantine tree가 직접 재사용하므로 기각.

## 검증
Workflow의 patch check, diff check, JavaScript syntax, portable build, split/portable `file://` smoke를 통과해야 한다. Mantine CSV/image 삭제에서 참조 cascade가 유지되고, 폴더 생성/선택이 기존과 동일하게 project VFS validation을 거치는지 확인한다.

## 롤백
이 패치 하나를 revert하면 legacy wrapper 함수 정의만 돌아오며 017에서 event wiring은 여전히 끊긴 상태다. 따라서 실사용 UI ownership에는 영향을 주지 않고 wrapper 삭제만 되돌릴 수 있다.

## 후속
legacy asset-tree DnD policy/execution/install block을 제거한다. 이후 legacy explorer renderer/markup 및 REQUIRED_CONTROL_IDS의 실제 필요성을 정리한다.
