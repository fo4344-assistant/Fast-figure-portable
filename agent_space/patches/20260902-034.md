# 20260902-034 — graph object 추가용 순수 read model

## 목적

기존 `addGraphObject` UI는 active CSV, legacy X/Y form, 선택 object form, chart editor를 한꺼번에 사용한다. Mantine 쪽에서 이를 그대로 복제하면 새 object draft가 legacy DOM 또는 별도 persistent React state를 source of truth로 삼게 될 위험이 있다.

이번 패치는 mutation을 만들기 전에 active CSV + canonical chart/selection에서 추가 예정 object 기본값을 순수하게 파생하는 read model만 추가한다.

## 변경 내용

- 앱 버전 `1.1.76-alpha` → `1.1.77-alpha`
- `selectedGraphObjectAddModel(slot)` 추가
- bridge에 `readGraphObjectAdd()` 추가

## read model 입력

- selected slot
- `activeCsvId`가 가리키는 project CSV
- selected chart/editor
- `selectedObjectIndex`

## 기본값 계산

현재 선택 object가 있으면 그 object의 X/Y/축 위치/스타일을 source로 사용한다.

선택 object가 없으면 chart editor를 source로 사용한다.

chart가 아직 없으면 빈 editor source를 사용한다.

그 뒤 기존 순수 helper를 재사용한다.

```text
baseGraphObject({ editor: source }, csv)
→ graphDataSelection(csv.rows, csv.headerLines, source)
```

새 object color는 기존 add 동작과 같이 object count에 따른 `DEFAULT_COLORS[index]`를 사용한다.

## 반환값

- slotId
- chartId / hasChart
- editable
- csvId / csvName
- active CSV column definitions
- 추가 예정 object snapshot

모든 반환값은 render용 snapshot이며 source of truth가 아니다.

## read 순수성

`graphDataSelection()`은 column definition/data rows를 계산해 X/Y를 고를 뿐 state를 수정하지 않는다.

`baseGraphObject()`도 명시적 CSV를 전달한 경우 editor/CSV를 읽어 새 object literal을 반환할 뿐 project를 수정하지 않는다.

selector에서는 `ensureGraphObjects()`나 normalization mutation helper를 호출하지 않는다.

## source of truth

- active CSV: 기존 `activeCsvId`
- graph objects: chart `editor.objects`
- selection: graphObject EFSM / selectedObjectIndex
- add model: 일회성 render snapshot

새 persistent add-object state를 만들지 않는다.

## 변경하지 않는 영역

- 실제 add mutation
- 기존 `addGraphObject` button handler
- `SLOT_DATA_CONNECTED`
- `CHART_MODEL_REPLACED`
- graph object list/detail UI
- Plotly renderer / trace 생성
- 인라인 Plotly library
- import/export

## 선택하지 않은 방향

### React local draft를 먼저 생성

선택하지 않는다. 실제 add command의 commit/cancel 수명주기가 정해지기 전에 draft를 만들 필요가 없다.

### legacy X/Y `<select>` 값을 read model에서 읽기

선택하지 않는다. Mantine cutover 후 제거되어야 하는 DOM source다.

### `configFromForm()`을 selector에서 호출

선택하지 않는다. DOM read와 전체 chart form 결합을 read 경계에 다시 가져오게 된다.

### `ensureGraphObjects()` 사용

선택하지 않는다. read selector에서 mutation 가능성이 있는 normalizer를 호출하지 않는다.

## 회귀 위험

낮음. read-only bridge method만 추가하며 아직 UI에서 호출하지 않는다.

검사:

- active CSV 없으면 null
- image/no-slot이면 null
- no-chart 상태에서도 add model 계산 가능
- selected object가 있으면 스타일 기본값 파생
- X/Y가 active CSV에 없으면 `graphDataSelection`이 유효 column으로 fallback
- selector mutation 없음
- Plotly/trace diff 없음

## rollback

- bridge `readGraphObjectAdd` 제거
- `selectedGraphObjectAddModel` 제거
- 앱 버전을 `1.1.76-alpha`로 복원

## 후속

DOM-free add command를 별도 패치에서 설계한다.

- no chart: 기존 `SLOT_DATA_CONNECTED`
- existing chart: canonical chart clone + explicit object values + 기존 `CHART_MODEL_REPLACED`
- 축 제목 자동 채움 규칙 유지

legacy `configFromForm()` 전체를 Mantine add command에 재사용하지 않는다.

## Plotly 범위

이번 패치는 read selector/application bridge만 다룬다. 인라인 Plotly library 본문은 읽거나 수정하지 않는다.
