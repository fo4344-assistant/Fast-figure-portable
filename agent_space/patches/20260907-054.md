# 20260907-054 — Renderer-neutral asset-import collision plan

## Purpose

Extract only the collision decision data from `planProjectAssetImport()` so the Mantine file-import UI can present filename-collision choices without invoking native `window.confirm()` / `window.alert()` and without duplicating VFS rules.

This extraction is now required by the direct Mantine implementation: the remaining `#file` bridge cannot be removed cleanly while collision analysis and browser presentation are fused in one helper.

The legacy `planProjectAssetImport()` remains available and preserves its current browser-confirm/alert behavior until cutover.

## Scope

Only `fast-figure.js` is modified.

No changes are made to:

- project model structures
- project VFS rules
- CSV/image loaders
- FFPX/FFSX formats
- UI FSM or functional EFSM definitions/events
- legacy import behavior
- `fast-figure-ui.js` in this patch

No app-build/version bump is included in this patch.

## Verified prior implementation

The repository already contains the historical patch `20260906-032`, which introduced the same renderer-neutral boundaries under the verified names:

- `projectAssetImportCollisionModel()`
- `resolveProjectAssetImportPlan()`

This patch reuses only that functional extraction against the reset branch because the current Mantine implementation has now demonstrated the need for it. It does not restore the later staging architecture.

## Exact changes

1. Replaces the mixed collision-analysis portion of `planProjectAssetImport()` with `projectAssetImportCollisionModel(file, directory, reservedPaths)`.
2. The collision model computes and freezes:
   - asset kind
   - parent directory
   - normalized name/path
   - collision mode: `available`, `replace-or-rename`, or `rename-only`
   - replaceable asset ID when applicable
   - existing replacement prompt text
   - existing rename-only notice text
3. Adds `resolveProjectAssetImportPlan(model, choice, reservedPaths)` which converts the collision model plus `replace`/`rename` choice into the same `{ path, replaceId }` loader plan used today.
4. Rewrites legacy `planProjectAssetImport()` as a thin presentation wrapper:
   - `replace-or-rename` still uses the existing `window.confirm()` text
   - rename-only collision notice still uses existing `window.alert()` text
   - the selected choice is resolved by the new pure plan helper
5. Available-path and unique-name behavior continues to use existing `projectVfs.uniquePath()` and `activeProject._state`.
6. No Mantine-specific code or callback is added to `fast-figure.js`.

## State and responsibility boundaries

The new helpers do not own UI state and do not mutate persistent project state. They expose the existing VFS collision result in renderer-neutral data so either the legacy renderer or Mantine can present the choice.

The actual loader/model mutation paths remain unchanged.

## Why this direction

Calling `loadDataFile()`/`loadImageFile()` from a React-owned picker without a precomputed plan would still reach native browser confirmation through `planProjectAssetImport()`. Reimplementing collision logic in React would duplicate path normalization, default-CSV protection, replaceability, reserved-path handling, and unique-path generation.

Extracting the already-existing decision logic is therefore the minimum change that preserves one source of truth while allowing Mantine to own presentation.

## Rejected alternatives

### Keep the legacy `#file` bridge

Rejected because the target architecture removes legacy DOM as a Mantine internal API.

### Duplicate collision logic in `fast-figure-ui.js`

Rejected because that would create two implementations of VFS collision policy.

### Remove `window.confirm/alert` from the legacy path immediately

Rejected because legacy UI remains the parity reference before final cutover.

### Restore the whole historical `20260906-032` and subsequent staging chain

Rejected because the user explicitly rejected the earlier bridge/staging strategy. Only the now-demonstrably-required pure functional boundary is reused.

## Rollback

Revert `20260907-054.patch`. `planProjectAssetImport()` returns to its previous combined analysis + native-presentation form. Project data and file formats require no rollback.

- same-kind replaceable collision + cancel → unique renamed path
