# 20261015-014 — Plan 016 Application lifecycle task ownership

## 목적과 변경 내용

Source Script r25 / PlusCal pseudocode r11의 `Application boundary가 task callback을 실행하고 Frontend FSM은 lifecycle state만 전이한다` 계약을 실제 Source Code로 전파한다.

- `fast-figure.js`: `InterfaceStateMachine.run`을 제거한다. Application boundary의 `runLifecycleTask`로 동기·비동기 task 실행과 Promise 처리, ready guard, 결과·실패 전달을 옮긴다.
- Frontend FSM은 `InterfaceStateMachine.send`의 `LIFECYCLE_START`, `LIFECYCLE_COMPLETE`, `LIFECYCLE_FAILED` 입력을 `transitionLifecycle`에 전달해 자체 lifecycle/error state만 갱신한다. Application Adapter가 `interfaceFSM.state`를 직접 변경하지 않는다.
- 기존 `appFSM.run` 공개 호출 계약은 유지하며, 내부에서는 Application boundary의 함수로 연결한다.
- `agent_space/tests/browser-regression.js`: 36번 테스트에서 synchronous rejected, asynchronous busy guard/completion, synchronous failure 및 Frontend FSM failure/recovery 이벤트를 검사한다.
- `development-versions.json`: Source Code revision r30 → r31, fingerprint `sha256:82854953e4608d8bd350a1968e1642fa1bd2af41b90a82786ee13ee27130593a`. Plan 016 전부가 끝나지 않아 `stale`과 `validation_review: null` 유지.
- `dist/inline/Fast-figure.html` 및 `dist/split/Fast-figure.zip`은 허용된 GitHub Actions Build distribution이 새 core script 기준으로 생성했다.
- 검토 문서: `agent_space/reviews/review-20261015-026-source-code-r31-lifecycle-adapter.md`.

## 선택 이유 및 기각한 방향

- **선택:** task callback은 Application boundary가 실행하고, Frontend runtime state는 오직 FSM event로 갱신한다. 기존 UI 호출부와 결과/실패 ordering을 보존하고 별도 store나 third FSM을 만들지 않는다.
- **기각:** 기존 `InterfaceStateMachine.run` 유지 — Frontend가 persistent task 실행의 수명과 callback을 소유한다.
- **기각:** 단순히 `run` 메서드의 본문을 외부로 복사해 adapter가 `interfaceFSM.state`를 직접 대입 — Backend/Frontend 경계가 남는다. 이전에 로컬 준비했던 014 후보의 이 부분을 보완하여 저장소에 적용했다.
- **기각:** 새 task bus, 별도 lifecycle store, DOM/React bridge — 이미 존재하는 `appFSM.run`과 FSM event만으로 충분하다.
- **기각:** TLC pass를 기다림 — TLC는 선택적 검증이며 Source Code 선행 조건이 아니다.
