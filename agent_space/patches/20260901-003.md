# 20260901-003

## 목적

`20260901-002`에서 추가한 React external-store bridge가 동일 FSM state에서 발생한 domain update도 React에 확실히 전달하도록 snapshot identity 계약을 수정한다.

## 확인된 문제

`20260901-002`의 `getSnapshot()`은 `appFSM.state` 자체를 반환했다. `ApplicationStateMachine.notify()`는 revision을 갱신하므로 새 state 객체를 만들지만, `send()` 처리 중 action이 domain object를 변경한 뒤 region target이 현재 state와 동일한 update transition으로 끝나는 경로에서는 `publish()`가 호출되어도 `appFSM.state` 객체 identity가 그대로일 수 있다.

`useSyncExternalStore`는 subscribe callback 호출 자체만으로 변경을 판정하지 않고 `getSnapshot()` 결과의 identity/value 변화도 사용한다. 따라서 이 경우 domain 값은 바뀌었는데 React shell이 재렌더하지 않는 누락 가능성이 있다.

## 변경 내용

- 애플리케이션 버전을 `1.1.33-alpha`로 올린다.
- `fastFigureUiListeners`를 별도 listener set으로 추가한다.
- `fastFigureUiStoreSnapshot`을 `{ version, state, event }` 형태의 immutable snapshot으로 둔다.
- bridge 생성 시 `appFSM.subscribe()`를 한 번 등록한다.
- FSM의 모든 `publish()`마다 bridge version을 증가시키고 새 snapshot identity를 만든 뒤 React listeners에 알린다.
- `getSnapshot()`과 `getServerSnapshot()`은 이 bridge snapshot을 반환한다.
- 기존 EFSM `state.revision`의 의미와 증가 위치는 변경하지 않는다.

## 이 방향을 선택한 이유

EFSM의 `revision`은 이미 project load/notify 등 기존 의미를 갖고 있고 export snapshot에도 사용된다. React 렌더링을 위해 이를 모든 `publish()`마다 증가시키면 UI adapter 요구 때문에 domain/FSM semantics를 바꾸게 된다.

따라서 React renderer에 필요한 invalidation counter는 bridge 내부에만 둔다. 이렇게 하면 EFSM core를 수정하지 않으면서 `publish()` 단위의 UI invalidation을 정확히 표현할 수 있다.

## 고려했지만 선택하지 않은 방향

### `ApplicationStateMachine.publish()`에서 `state.revision` 증가

선택하지 않았다. 기존 revision semantics와 export/debug 의미를 변경한다.

### React subscriber마다 local counter 증가

선택하지 않았다. subscriber 수에 따라 version 증가 횟수가 달라지고 store 자체의 snapshot contract가 불명확해진다.

### `buildFastFigureUiSnapshot()` 전체를 `getSnapshot()`에서 매번 새로 생성

선택하지 않았다. `useSyncExternalStore`는 변경이 없을 때 snapshot identity가 안정적이어야 한다. 매 호출마다 새 객체를 만들면 불필요한 렌더 또는 계약 위반이 생긴다.

## 검증 기준

- FSM transition으로 state identity가 바뀌는 경우 새 bridge snapshot 생성.
- `notify()`인 경우 새 bridge snapshot 생성.
- 같은 target의 update transition에서 state identity가 그대로여도 `publish()` 시 새 bridge snapshot 생성.
- 기존 `state.revision` 증가 규칙은 그대로 유지.
- 일반 UI DOM을 bridge source of truth로 사용하지 않음.
- 기존 legacy UI는 여전히 유일한 활성 renderer.

## 후속 작업
