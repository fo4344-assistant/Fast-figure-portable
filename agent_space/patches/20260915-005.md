# 20260915-005 — Remove native annotation editor ownership after Mantine cutover

## Purpose
Finish the annotation ownership cutover after 20260915-004 detached active Mantine label/caption paths from removed native editor DOM.

## Exact changes
- Remove `syncLabelControlsFromObject` and `syncCaptionControlsFromObject`, which only projected project state into removed native annotation controls.
- Stop the legacy project-control synchronizer from calling those removed annotation projectors.
- Remove the inert `renderDashboard()` hook that attempted to refresh `labelPreview` when such DOM existed.
- Remove the native annotation toggle writeback from `setAnnotationEnabled`; visibility state, dashboard rendering, debug logging, and EFSM notification remain unchanged.
- Remove native-only label editor functions: `finiteLabelPosition`, `labelPreviewGeometry`, `constrainLabelPreviewPosition`, `renderLabelPreview`, `applyLabelSettings`, `applyLabelPosition`, and `installLabelSettings`.
- Replace `applyCaptionSettings(fromControls, notify)` with a DOM-independent caption commit/render notifier that only synchronizes the actual dashboard caption, logs state, and emits `CAPTION_SETTINGS_CHANGED`.
- Remove `installCaptionSettings` and `installAnnotationPopup`, which target removed native controls and include a stale call to the already removed `syncPopupBounds`.
- Update the Mantine caption overlay to call the simplified `applyCaptionSettings()` API.

## Rationale
The label and caption editors are now Mantine-owned. Retaining a second native editor layer leaves dead control identifiers, hidden writeback paths, and dangling references to deleted popup/layout helpers. The actual figure renderers (`renderDashboard`, `syncDashboardCaption`), project annotation state, geometry helpers used by the React preview, and export logic remain shared/core responsibilities and are intentionally retained.

## Rejected alternatives
- Keep dead functions because they are not normally called: rejected because several already contained stale references and preserve false ownership boundaries.
- Recreate hidden native annotation DOM: rejected because it would reintroduce duplicate state projection and synchronization complexity.
- Move actual dashboard labels/captions into Mantine: rejected because those are figure-renderer output rather than editor chrome and are used independently of the overlay.
- Change label geometry, caption aggregation, slot-caption semantics, persistence, or export behavior while removing the editor layer: rejected as outside this ownership unit.

## Source of truth
`activeProject.annotations` and its compatibility accessors remain authoritative. Mantine owns annotation editing and preview UI. `renderDashboard()` owns actual slot labels and `syncDashboardCaption()` owns the actual dashboard caption.

## EFSM/core impact
No intended change to annotation state transitions, label order/format, slot-caption selection, project serialization, export rendering, or dashboard geometry. The existing notification names remain unchanged.

## Validation
Run standard patch check/apply, JavaScript syntax checks, portable build, and split/portable Chromium `file://` smoke tests. After application, source inspection must show no executable references to `renderLabelPreview`, `labelPreviewGeometry`, `constrainLabelPreviewPosition`, `installLabelSettings`, `installCaptionSettings`, `installAnnotationPopup`, or `syncPopupBounds`.

## Rollback
Revert `Apply agent patch 20260915-005`. If the native annotation editor is intentionally restored, also restore its markup/CSS and revert 20260915-004 so ownership remains coherent rather than partially duplicated.

## Follow-up
Remove CSS selectors that only style the deleted native annotation editor (`.label-preview*`, legacy annotation panel/control layout rules) after confirming they are not reused by Mantine or actual dashboard rendering. Then continue with print/export fallback DOM cleanup and graph compatibility DOM cutover.
