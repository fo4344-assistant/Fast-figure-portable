# 20260902-028 — selected graph object write에서 legacy list renderer 의존 제거

## 배경

`20260902-027`에서 graph object mutation의 공통 경계를 다음처럼 분리했다.

```text
replaceGraphObjects()
→ GRAPH_OBJECTS_REPLACED
→ graph rebuild / updateGraphView / notify

saveGraphObjects()
→ replaceGraphObjects()
→ legacy renderGraphObjects()
```

`027`은 active legacy caller의 동작을 유지하기 위해 `applySelectedGraphObjectFromValues()`의 기존 `saveGraphObjects(next)` 호출은 아직 바꾸지 않았다.

## 목적

Mantine selected-object form의 DOM-free write 경계가 legacy `#graphObjects` renderer를 요구하지 않도록 해당 호출 한 줄만 공통 mutation command로 전환한다.

## 변경 내용

- 앱 버전 `1.1.71-alpha` → `1.1.72-alpha`
- `applySelectedGraphObjectFromValues()` 내부:
  - `saveGraphObjects(next)` → `replaceGraphObjects(next, chart.id)`

## 기능 의미

변경되지 않는다.

`applySelectedGraphObjectFromValues()`는 이미 호출 전에 다음을 검사한다.

- expected chart id stale guard
- expected object index stale guard
- selected graph object guard
- editable 여부
- current object 존재

그 뒤 만드는 `next` object 배열과 `GRAPH_OBJECTS_REPLACED` mutation은 동일하다.

달라지는 것은 mutation 뒤 legacy graph-object list DOM을 강제로 다시 그리지 않는다는 점뿐이다.

## stale write

현재 chart id를 `replaceGraphObjects(next, chart.id)`에 전달하므로 selection/form snapshot 이후 대상 chart가 바뀌면 mutation 경계에서도 다시 거부된다.

이 id는 source of truth가 아니라 stale callback identity guard다.

## active legacy 영향

active legacy graph form의 `applyGraphSettings()` / `configFromForm()` 경로는 이번 함수가 아니라 기존 chart-model replacement 경로를 사용하므로 변경되지 않는다.

legacy row color/delete/reorder/palette caller도 계속 `saveGraphObjects()`를 사용하므로 목록 재렌더를 유지한다.

## 변경하지 않는 영역

- `GRAPH_OBJECTS_REPLACED` event/action
- selectedObjectIndex / graphObject EFSM
- object normalization
- graph rebuild / updateGraphView
- legacy row action
- Plotly renderer
- 인라인 Plotly library
- import/export

## 선택하지 않은 방향

### `saveGraphObjects()` 내부에서 호출자 종류 판별

선택하지 않는다. UI ownership에 따라 분기하는 공통 helper는 복잡도와 결합만 늘린다.

### legacy list renderer를 지금 제거

선택하지 않는다. active UI cutover 전에는 legacy row action이 필요하다.

### Mantine form이 직접 `appFSM.send("GRAPH_OBJECTS_REPLACED")`

선택하지 않는다. `replaceGraphObjects()`에 이미 debug/update/notify와 stale-chart 검증이 중앙화되어 있다.

## 검증

- patch는 버전 2곳 + 호출 한 줄만 변경
- `git apply --check`
- 실제 apply
- `git diff --check`
- application inline JavaScript `node --check`
- Plotly/trace diff 없음

## rollback

- 호출을 `saveGraphObjects(next)`로 복원
- 버전을 `1.1.71-alpha`로 복원

`027`의 command/renderer 분리는 독립 유지 가능하다.

## 후속

color/delete/reorder용 DOM-free command를 `replaceGraphObjects()` 위에 추가하고, selection/reorder 시 selected index 의미를 기존 EFSM event로 보존한다.
