# 20260910-036 — Remove legacy image settings form

## Purpose

Complete the image-editor cutover by removing the remaining legacy `#imageBox` form and its DOM synchronization/form-reader path. Mantine `FastFigureImageEditor` already owns these controls and calls `applyImageSettingsFromValues()` directly. Legacy UI compatibility is not retained; file-format compatibility remains unchanged.

This patch supersedes failed patch `20260910-035`. Patch 035 did not modify application source because `git apply --check` failed. The 036 application changes are the same intended cleanup, regenerated against the current post-034 source with hunks ordered monotonically by source location.

## Exact changes

### `Fast-figure.html`

- Remove the entire `#imageBox` fieldset.
- Remove legacy fit-mode, manual scale/X/Y controls, and legacy image preview element with that fieldset.

### `fast-figure.js`

- Remove `imageBox`, `imageFitMode`, `imageManualFields`, `imagePositionX`, `imagePositionY`, `imagePreview`, and `imageScale` from `REQUIRED_CONTROL_IDS`.
- Remove `syncImageSettingsUi()`.
- Remove `imageBox`/`imagePreview` writes from workspace synchronization and project runtime reset paths.
- Remove `exitImageWorkspaceState()` and the image-workspace exit hook because they only hid the deleted legacy form.
- Remove the legacy `applyImageSettings()` DOM form reader and input event handlers.
- Change the capability audit from `applyImageSettings` to `applyImageSettingsFromValues`.
- Keep `normalizeImageSettings()`, `syncSlotImageElement()`, and `applyImageSettingsFromValues()` unchanged as the functional/model-rendering boundary used by Mantine and dashboard rendering.

## Source of truth

- Persistent image settings: project image object settings.
- Image-setting mutation: `applyImageSettingsFromValues()`.
- Slot image rendering: `syncSlotImageElement()` and existing dashboard renderer.
- Generic image editor UI: Mantine only.

No hidden legacy controls or bidirectional synchronization remain necessary for the image settings surface.

## EFSM / core impact

No project transition semantics, image data model, renderer geometry, or image-setting normalization is changed. The image workspace continues to enter/update through the existing FSM callback; only the obsolete exit-side DOM hide action is removed.

## File-format compatibility

No FFPX, FFSX, Plotly JSON, image bytes/base64 representation, package layout, parser, serializer, import/export routine, or package version is changed.

## Rationale

The deleted form is a duplicate UI authority. Mantine already reads image state from the project model and sends value objects through the UI-independent command. Keeping the old fieldset solely as a fallback would preserve exactly the legacy UI compatibility that is no longer required and would encourage future DOM bridges.

## Rejected alternatives

- Keep `#imageBox` hidden: rejected because legacy UI compatibility is explicitly not a requirement.
- Synchronize Mantine values into the old form: rejected because it recreates a bidirectional compatibility bridge.
- Move image-setting mutation into React-local state: rejected because the existing command and project model are already the proper authority.
- Retry patch 035 unchanged: rejected because its same-file hunks were not ordered by source location and failed `git apply`.

Revert the application commit for `20260910-036` to restore the old image settings fieldset and DOM form path. No persisted project migration is involved.
