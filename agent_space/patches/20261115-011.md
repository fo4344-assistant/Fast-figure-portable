# Source Script 50 — 변수 정의의 절차 설명 분리

## 요청과 범위

전역 경계 규칙과 명령 설명 표를 포함하여 변수 정의에 들어 있던 처리·완료 서술을 찾아 정리한다. 모듈·클래스·지역변수와 원형을 대상으로 자료형·값·연결 자료와 실행 절차를 구분했다.

## 실제 수정

- 절차 설명이던 전역 정의 91개를 제거하고 각 담당 함수의 `처리`에 실제 분기·계산·검증·자원 정리 순서를 연결했다. 과거 검토·이력 문구도 제거했다.
- 명령·이벤트 목록은 식별자 tuple, 등록 경로는 필드 경로 tuple, 공개 메서드는 실제 함수와 query/event/call 연결 자료로 작성했다. 공개 namespace·메서드 이름과 기존 인자 순서를 유지했다.
- `createPublicApi`에서 메서드 연결, 조회 인자, 현재 선택 참조, importing/exporting 작업 연결을 작성했다. 프로젝트 불러오기는 기존 `assets.importProjectFile`을 사용한다.
- Project EFSM의 명령별 candidate 처리와 검증·authority 재확인·한 번 반영·실제 결과 계산을 연결했다. Frontend의 no-op·거부·성공·error→ready 발행을 구분했다.
- 변수 정의의 복사·생성·검증 서술을 담당 처리로 옮겼다. 불필요한 경계 구호와 A-not-B 문구를 제거하고 실제 오류·부재·유효성 조건은 유지했다.
- STORE 패키지 읽기·CSV header 정규화·프로젝트 설정 정규화를 각각 readStorePackage·normalizeCsvHeaderLines·normalizeProjectSettings에 연결했다. 파서와 읽기 함수에 옮겨졌던 다른 입력·소유자의 처리를 정리하고 실제 operation과 인자로 분기하도록 수정했다.
- ProjectObject 초기화의 정규화·검증·한 번 교체, graph 기본값·palette 처리의 소유자, UI API 연결과 단일 drop receiver, system의 runtime 준비·ready·단일 mount 순서를 대조하여 수정했다.
