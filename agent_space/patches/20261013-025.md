# 20261013-025 — Correct UI regression observation boundaries

## 발견

20261013-024에서 추가한 세 UI regression 중 두 검사가 inline/split 모두 실패했다.

실패 항목:

- Layout preview centered 판정
- trash asset Menu opened 판정

코드와 DOM ownership을 다시 대조한 결과 두 실패는 application 의미 위반이 아니라 테스트가 잘못된 관찰 경계를 사용한 것이다.

## 원인

### Layout preview

요구는 preview가 실제 Modal content 영역에서 가운데 정렬되는 것이다.

024 테스트는 preview의 직접 layout container가 아니라 Mantine Modal outer content box와 중심을 비교했다. Modal outer box에는 framework가 소유하는 내부 padding/scroll 영역이 포함될 수 있으므로 renderer-local preview wrapper의 실제 정렬 기준과 동일하지 않다.

교정 후에는:

- preview grid의 parent = 공통 width wrapper
- 그 wrapper의 parent = 실제 layout content container

를 사용해 두 영역의 수평 중심을 비교한다.

### trash Menu

024 테스트는 Menu open 여부를 Mantine 내부 class name `.mantine-Menu-dropdown`으로 판정했다.

이 class는 application contract가 아니며 portal/rendering 세부에 종속된다. Menu target 자체는 이미 존재하고 enabled 상태였다.

교정 후에는 target click 뒤 접근성 contract인 `role="menu"`이 나타나는지를 기존 `waitFor`로 기다린다.

## 변경

`agent_space/tests/browser-regression.js`만 수정한다.

application Source Code, Source Script, verification-model, development lineage는 변경하지 않는다.

## 선택 이유

실패한 두 assertion의 관찰 기준만 실제 UI ownership과 public/accessibility contract에 맞춘다. 테스트를 통과시키기 위해 application 코드를 바꾸지 않는다.

## 후속

GitHub-hosted Fast Figure regression을 다시 실행하여 inline 및 split ZIP에서 28~30을 포함한 전체 회귀를 확인한다.
