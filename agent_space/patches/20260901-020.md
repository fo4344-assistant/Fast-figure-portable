# 20260901-020

## 목적

Mantine sidebar의 실제 form control을 연결하기 전에, EFSM 전이가 없는 domain-only 변경도 `useSyncExternalStore` 구독자에게 알릴 수 있는 최소 invalidation 경계와 프로젝트 이름의 DOM-free mutation 계약을 준비한다.

현재 프로젝트 이름은 native `input` 이벤트에서 즉시 `activeProject.projectName`을 갱신하고 `change`에서 trim 및 debug log를 수행한다. 이 변경은 EFSM event를 발생시키지 않으므로 현재 React binding은 값을 다시 읽을 계기를 얻지 못한다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.50-alpha`로 올린다.
- 기존 `appFSM.subscribe()` 내부의 external-store 갱신 코드를 `publishFastFigureUiStore(state, event)`로 분리한다.
  - FSM 전이는 기존 subscribe 경로에서 동일 helper를 호출한다.
  - domain-only 변경도 같은 helper로 React 구독자에게 invalidation을 전달할 수 있다.
  - project/domain 상태 자체를 별도 store에 복제하지 않는다.
- `setProjectNameFromValue(value, commit)`를 추가한다.
  - input 단계는 기존과 동일하게 최대 120자까지만 반영한다.
  - commit 단계는 기존과 동일하게 trim 후 최대 120자로 반영하고 `project:name` debug log를 기록한다.
- `fastFigureUiBridge.setProjectName(value, commit)`을 추가한다.
  - 위 mutation helper를 호출한 뒤 external-store version만 갱신한다.
  - 반환값은 실제 정규화된 project name이다.
- 기존 native project name `input`/`change` handler와 FFPX export 직전 이름 정규화도 새 bridge 계약을 재사용한다.

## 이 방향을 선택한 이유

React가 project/domain state를 별도 state로 복제하면 `plan-003`의 source-of-truth 원칙을 어긴다. 반대로 EFSM 전이가 없는 모든 domain mutation을 억지로 새 FSM event로 바꾸는 것도 기능 상태기계의 의미를 UI 갱신 때문에 확장하는 문제가 있다.

따라서 external store가 보유하는 것은 기존과 동일하게 `appFSM.state` 참조와 증가하는 version/event뿐이며, domain 값은 render 시 `fastFigureUiBridge.read()`가 기존 project object에서 다시 읽는다. 이는 상태 복제가 아니라 재렌더링 invalidation 경계다.

프로젝트 이름 역시 React 전용 mutation을 새로 만들지 않고 legacy handler와 Mantine가 공유할 수 있는 하나의 values 기반 helper로 수렴시킨다.

## 선택하지 않은 방향

- 프로젝트 이름을 React local state의 영속 source로 옮기지 않는다.
- UI 갱신만을 위해 새 EFSM region/event semantics를 추가하지 않는다.
- 모든 domain mutation을 이번 패치에서 한꺼번에 external-store invalidation에 연결하지 않는다. 실제 sidebar control을 옮길 때 필요한 경로만 점진적으로 연결한다.
- project export/FFPX 형식이나 파일명 규칙은 변경하지 않는다.
- 이번 패치에서 Mantine `TextInput` 자체를 활성 staging sidebar에 추가하지 않는다. mutation/invalidation 계약과 UI wiring을 분리한다.

## 후속 작업

다음 패치에서는 `FastFigureSidebarStaging`의 프로젝트 이름 표시를 Mantine `TextInput`으로 바꾸고 `setProjectName()`을 연결한다. 이후 같은 방식으로 slot type과 project-level action controls을 분리한다.
