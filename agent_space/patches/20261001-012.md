# 20261001-012 — Source Script r3 file/graph semantics 완결

## 변경 원인

plan-008 Phase 2와 Phase 3 중 project/file/graph 책임을 r2 invariant에 맞춰 닫기 위해 수정한다.

r2에서 zero-object chart, chart 1:1 ownership, persistent export settings를 확정했으므로
asset import, FFPX/FFSX, graph editor, Plotly conversion이 더 이상 protected default CSV나 shared chart 예외에 의존하면 안 된다.

## 의미 변경

### VFS와 asset transaction

- canonical path/resolve/unique/descendant/fixed/trash 의미를 하나의 VFS 규칙으로 정의
- batch import, asset delete, move-to-trash, empty-trash를 candidate-first commit으로 변경
- asset reference count와 실제 cascade가 같은 reference collector를 사용
- protected default CSV 관련 collision/delete/move 예외 제거

### tabular parser

- CSV는 comma, TSV는 tab을 확장자로 결정
- quote 내부 delimiter/newline과 doubled quote 처리
- 내부 blank row는 보존
- JSON은 top-level array 또는 data array
- parsed rows와 원본 bytes의 책임을 분리

### FFPX/FFSX

- typed XML null/boolean/number/string/array/object grammar 명시
- persistent export settings를 project setting으로 기록
- 현재 v3에서 additive field로 취급하고 missing field는 project default로 정규화
- current FFPX만 application project import로 취급하고 legacy conversion은 외부 책임
- FFSX blank editable chart는 CSV 없이 zero-object chart로 표현
- package-local default CSV id 0/remap 제거
- FFSX 적용은 새 독립 chart를 target slot이 1:1 소유하는 candidate로 검증 후 commit

### graph/Plotly

- global settings와 네 axis schema 명시
- editable chart의 objects=[] 허용
- graph object list를 0개로 commit해도 fake object를 만들지 않음
- imported Plotly 원본과 Fast Figure conversion view를 구분
- zero-trace Plotly는 fake X/Y rows 없이 empty conversion으로 유지
- editable 전환 시 conversion object가 있을 때만 project CSV를 생성

## 선택 이유

같은 empty graph를 default CSV + fake graph object로 표현하면 file import, asset protection, FFSX remap, delete cascade에 특수 규칙이 퍼진다.
zero-object chart를 직접 표현하면 동일 기능을 더 적은 의미 구조로 유지할 수 있다.

candidate-first transaction은 mutate 후 rollback보다 authority가 실패 중간 상태를 거치지 않으며,
asset/import/file-format 전반에서 같은 mutation 원칙을 재사용할 수 있다.

CSV/TSV delimiter는 지원 확장자가 이미 분리되어 있으므로 첫 줄 sniff보다 확장자 기반이 예측 가능하다.

## 기각한 대안

- first-line tab sniff 유지: .csv/.tsv의 명시 형식보다 내용 우연성에 delimiter가 좌우되므로 채택하지 않음
- default CSV를 FFSX 내부 전용으로만 유지: 같은 empty graph에 project/FFSX 두 표현이 생기므로 채택하지 않음
- malformed shared chart를 import 시 clone: chart identity를 조용히 변경하므로 채택하지 않음
- legacy JSON project import를 application에 유지: README의 current-format-only 계약과 맞지 않아 Source Script에서는 제외
- 모든 package 의미 변경에 즉시 version bump: 이번 export setting은 additive이며 same-version missing field를 명시적 default로 정규화할 수 있어 v3 유지. 기존 field 의미가 깨지는 변경부터 bump

## 닫힘 판정 영향

VFS, tabular parsing, asset transaction, chart empty state, graph axis schema, Plotly conversion,
FFPX typed-value grammar, FFSX zero-object/apply semantics는 Source Script 수준에서 닫혔다.

아직 layout/caption operation matrix, export interaction, FSM/API mutation contract,
editing/layoutMapWidth 중복 검토가 남아 있으므로 closure는 open이다.

## 하위 단계 전파 범위

- default CSV 생성/보호/reuse/remap 코드 제거
- CSV/TSV parser delimiter/blank-row 의미 변경
- candidate-first import/delete/move transaction
- whole-project chart ownership validation
- zero-object graph renderer/editor 지원
- persistent export settings FFPX read/write
- Plotly zero-trace/editable conversion 변경
- legacy JSON project import 제거 또는 별도 converter로 이동

현재 pseudocode/source code는 수정하지 않는다.
