# 20260928-004

## 목적과 변경 내용

Mantine 도입의 핵심 목적인 공통 GUI 규칙 재사용을 실제 활성 UI에 복구한다.

현재 main은 복구 과정 이후 Mantine component를 사용하고 있지만 `MantineProvider`에 application theme가 연결되어 있지 않아, Button/Input/Modal의 공통 geometry와 lifecycle 규칙이 component 사용처마다 다시 흩어질 수 있는 상태였다.

이번 변경은 `fastFigureTheme`를 현재 `fast-figure-ui.js`에 정의하고 다음 규칙을 한 곳에서 소유한다.

- 공통 font: `system-ui, "Segoe UI", sans-serif`
- 공통 control font size: 14px
- 공통 radius: 6px
- Button 기본 높이: 38px
- Button 기본 horizontal padding: 12px
- ActionIcon 기본 크기: 38px
- Input 계열 기본 높이: 38px
- Modal 공통 동작:
  - centered
  - outside click close
  - Escape close

각 Modal에서 반복하던 `centered`, `closeOnClickOutside`, `closeOnEscape` 지정은 제거하고 theme defaultProps를 사용한다.

## 왜 이 변경을 먼저 하는가

Mantine을 사용하는 주 목적은 기존 custom CSS에서 버튼/입력/팝업마다 크기와 동작을 조금씩 다시 구현하던 구조를 없애는 것이다.

legacy generic CSS를 제거하기 전에 Mantine 쪽 공통 수치가 명시적인 단일 위치에 있어야 한다. 그렇지 않으면 CSS 삭제 뒤 각 component에 다시 size/style 숫자를 흩뿌리게 된다.

따라서 순서는 다음으로 고정한다.

1. Mantine theme/default props에 공통 UI 수치와 lifecycle 규칙을 둔다.
2. component의 반복 props를 제거한다.
3. 다음 patch에서 대응 legacy generic CSS와 dead numeric variables를 제거한다.

## 기존 기록과의 관계

`20260831-017`에서 같은 목적의 theme가 한 차례 구현된 적이 있으나 이후 plan-006 복구 과정에서 application source에서는 사라졌다.

이 patch는 그 과거 patch를 replay하지 않는다. 현재 `fast-figure-ui.js` 구조를 기준으로 다시 구현하며, 현재 사용 중인 Modal 공통 lifecycle까지 theme에 포함한다.

## 선택하지 않은 방향

### AppButton / AppInput / AppModal wrapper 추가

단순 style/default props 재사용을 위해 별도 wrapper 계층을 만들지 않는다. Mantine `theme.components`가 이미 해당 책임을 제공한다.

### 각 component에 size/radius/height 반복 지정

Mantine 도입 목적과 반대이므로 사용하지 않는다.

### popup lifecycle을 custom hook으로 재구현

center/outside-click/Escape는 Mantine Modal의 공통 기능이므로 별도 구현하지 않는다.

### renderer CSS까지 함께 제거

dashboard/slot/Plotly/layout preview는 generic UI가 아니라 기능 renderer이므로 이번 변경 범위가 아니다.

## 후속 작업

다음 patch에서 현재 활성 markup/renderer에서 사용되지 않는 legacy generic UI CSS를 제거한다. 특히 native `button/input/select/label`, old toolbar/sidebar/popup/layout-panel 규칙과 그 규칙만 참조하는 CSS variable을 제거 대상으로 한다.
