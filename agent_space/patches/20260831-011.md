# 20260831-011

## 목적

두 번째 Mantine vendoring 실행에서 확인된 형식 검증 실패를 정확히 수정하고, 성공 시 실제 runtime 변경을 다음 순번 `20260831-012`로 기록한다.

## 변경 내용

- Mantine CSS를 HTML에 삽입하기 전에 각 줄의 trailing whitespace만 제거한다.
- React/Mantine top-level LICENSE 섹션 제목의 `=` 반복선을 `-` 반복선으로 변경해 `git diff --check`가 conflict marker로 오인하지 않도록 한다.
- corrected builder는 별도 v3 workflow로 한 번만 실행되도록 한다.
- 성공 결과 커밋이 생성할 patch pair를 `20260831-012.patch/.md`로 지정한다.

## 이 방향을 선택한 이유

두 번째 실행에서도 npm 설치, esbuild bundle 생성, HTML 변환, JavaScript 문법 검사는 정상 진행되었다. 실패는 `git diff --check`가 vendored CSS의 줄 끝 공백과 LICENSE의 `=======` 구분선을 검사한 결과였다. 따라서 third-party 코드의 의미나 dependency 구성을 바꾸지 않고 형식 문제만 제거하는 것이 최소 수정이다.

## 고려했지만 선택하지 않은 방향

- `git diff --check` 자체를 제거하지 않았다. 이후 실제 소스 변경에서도 유용한 검증이므로 유지한다.
- Mantine CSS를 임의로 재포맷하지 않는다. 각 줄의 끝 공백만 제거한다.
- 실패한 Actions run을 그대로 rerun하지 않는다. 같은 원인이 반복되므로 수정된 별도 one-shot workflow만 실행한다.

## 안전장치

- v3 workflow 자신의 경로에서만 trigger된다.
- 정확한 setup commit message에서만 job이 실행된다.
- GitHub Actions bot commit에서는 실행되지 않는다.
- 결과 runtime commit은 workflow trigger 경로를 변경하지 않는다.

## 패치에 포함되지 않은 변경사항

실제 runtime 변경은 이 builder가 성공한 경우 별도 `20260831-012` 커밋에서 기록한다. 이 patch와 설명 파일 자체는 재귀적으로 diff에 포함하지 않는다.
