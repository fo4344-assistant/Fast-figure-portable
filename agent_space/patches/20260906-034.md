# 20260906-034

## 목적

`20260906-033`에서 Mantine FileButton 경로에 연결한 파일 충돌 choice resolver를 asset-tree의 외부 파일 drag/drop에도 재사용하여, 동일 이름 파일의 교체/새 이름 추가 선택을 browser dialog가 아닌 동일 Mantine choice Modal에서 처리한다.

## 변경 내용

- `FastFigureAssetTreeStaging`이 선택적 `resolveImportChoice` callback을 받아 외부 file drop 실행 시 bridge에 전달한다.
- sidebar는 `20260906-033`의 기존 `requestImportChoice`를 asset tree에도 그대로 전달한다. 별도 Modal 상태나 resolver를 만들지 않는다.
- `fastFigureUiBridge.dropAsset()`은 선택적 `resolveImportChoice`를 받아 `executeAssetTreeDrop()`으로 전달한다.
- `executeAssetTreeDrop()`은 외부 파일을 `DataTransfer`에서 즉시 배열로 복사한 뒤에만 비동기 choice를 수행한다.
- 슬롯 외부 drop의 data/image 파일은 기존 project asset directory 기준으로 충돌 계획을 먼저 resolve한 후 `loadFileIntoSlot(..., { assetPlan })`에 전달한다.
- 폴더 다중 drop은 기존 `reserved` Set 하나를 유지하면서 파일 순서대로 `resolveProjectAssetImportChoice()`를 await하고, 선택된 path를 즉시 reserve한다.
- 이후 실제 import와 rollback은 기존 staged import 경로를 그대로 사용한다.
- legacy DOM asset-tree drop은 resolver를 전달하지 않으므로 `resolveProjectAssetImportChoice()`가 기존 `planProjectAssetImport()` browser dialog adapter를 호출한다.
- 앱 빌드를 `1.1.138-alpha`로 올린다.

## 기능 보존

- 외부 파일을 슬롯에 놓는 동작과 폴더에 놓는 동작을 유지한다.
- FFSX는 슬롯에만 놓을 수 있는 기존 정책을 유지한다.
- 슬롯에는 파일 하나만 놓을 수 있는 기존 정책을 유지한다.
- 동일 종류 충돌의 `기존 파일 교체 + 참조 유지`와 `새 이름으로 추가` 두 선택을 유지한다.
- 기본 빈 CSV 또는 다른 종류 충돌은 교체하지 않고 unique 이름으로 추가하는 기존 의미를 유지한다.
- 다중 파일의 순서를 유지한다.
- 같은 batch 안에서 앞 파일이 선택한 경로를 뒤 파일의 충돌 판단에 반영하는 기존 reserved-path 의미를 유지한다.
- import 실패 시 새로 추가한 자산 제거와 교체된 원본 복구 rollback을 유지한다.
- 내부 프로젝트 자산 drag/link/move 및 drag-to-trash confirmation 경로는 변경하지 않는다.

## 선택 이유

`20260906-033`에서 이미 generic choice Modal과 async resolver가 존재하므로 외부 drop을 위해 별도의 UI 상태를 만들 필요가 없다. 동일 충돌 의미에는 동일 descriptor/resolver를 사용해야 source of truth가 하나로 유지된다.

`DataTransfer`는 이벤트 이후 비동기 Modal이 열린 동안 안정적으로 유지된다고 가정하지 않는다. 따라서 외부 파일 배열은 await 전에 snapshot하고, 이후에는 `File` 객체 배열과 프로젝트 VFS만 사용한다.

다중 파일 계획은 `files.map()`으로 동시에 계산하지 않고 순차적으로 계산한다. 앞 파일의 rename/replace 결과와 reserved path가 뒤 파일의 unique path 결정에 영향을 주기 때문이다.

## 고려했지만 선택하지 않은 방향

### 외부 drop 전용 collision Modal 추가

동일 충돌 의미를 중복 구현하므로 기각했다.

### DataTransfer를 React state 또는 Promise resolver에 저장

브라우저 drag event 객체를 UI 장기 상태로 승격하며 수명 의존성이 생기므로 기각했다.

### 모든 파일의 계획을 먼저 병렬 계산

동일 batch 내부의 reserved-path 순서를 깨뜨릴 수 있으므로 기각했다.

### legacy drop도 Mantine resolver를 강제

현재 active shell cutover 전에는 legacy DOM 경로가 계속 동작해야 한다. 이번 패치는 Mantine path만 새 resolver를 넘기고 legacy adapter는 유지한다.

## 위험 요소

- drop event에서 `File` 배열을 await 전에 반드시 snapshot해야 한다.
- 슬롯 drop에서 FFSX에는 CSV/image collision plan을 만들면 안 된다.
- 다중 folder drop에서 `reserved.add(plan.path)` 시점이 각 choice resolve 직후여야 한다.
- rollback용 `replacedCsv`/`replacedImages` 계산은 최종 staged plan을 기준으로 해야 한다.
