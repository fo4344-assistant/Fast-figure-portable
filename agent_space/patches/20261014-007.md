# 20261014-007 — Give settings Modals a resizable initial height

## 목적과 변경 내용

settings Modal resize가 실제로 늘고 줄 수 있는 초기 geometry를 부여한다.

- 공통 `FastFigureSettingsModal`의 초기 content height를 `min(72dvh, 720px)`로 설정.
- 기존 max height `calc(100dvh - 24px)`와 내부 `Modal.Body` overflow scroll은 유지.
- 사용자가 handle을 드래그하면 r18의 mouse drag algorithm이 이 초기 높이에서 UI-local height를 변경한다.
- source-code revision r19, APP build `1.1.39-wip`.

## 실패 원인

r18까지 resize event 자체는 명시적으로 처리했지만 settings Modal의 초기 height가 `auto`였다.

특히 Label overlay처럼 내용이 긴 popup은 작은 headless viewport에서 intrinsic content와 max-height 제약으로 이미 최대 높이에 가까운 geometry가 되었고, drag로 높이 값을 계산해도 실제 box height가 달라질 여지가 없었다.

사용자가 요구한 기능은 popup 아래 handle로 창 길이를 늘이고 줄이는 것이므로, 초기 popup 높이가 content intrinsic size에 전적으로 종속되는 상태보다 명시적인 resizable viewport를 갖는 편이 기능 의미에 맞다.

## 선택 이유

- popup height는 계속 UI-local이고 project state에 저장하지 않는다.
- 네 settings overlay에 동일한 초기 geometry를 적용해 중복 값을 만들지 않는다.
- 내용이 더 길면 Modal.Body 내부에서 scroll하므로 content 손실이 없다.
- width와 Layout preview geometry authority에는 영향을 주지 않는다.

## 고려했지만 선택하지 않은 방향

- test만 완화: 실제 작은 viewport에서 resize 여지가 없는 UI를 숨기게 되므로 기각.
- content intrinsic minimum을 강제로 깨는 CSS: 내부 control layout을 손상할 수 있어 기각.
- overlay별 초기 height: 불필요한 분산 설정이므로 기각.
- 높이를 project 설정으로 저장: UI-local state 원칙에 어긋나므로 기각.
