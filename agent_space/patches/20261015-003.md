# 20261015-003 — GitHub 저장소 작업 방식 정책 추가

## 목적

현재 ChatGPT의 연결된 GitHub 도구로 Fast Figure 저장소를 수정할 때 실제로 안정적으로 사용할 수 있는 쓰기 방식과 동시성 검사 절차를 `agent_space/AGENT.md`에 명시한다.

최근 plan-016 작업에서 저수준 Git Data API와 파일 단위 Contents API를 각각 확인하면서 다음 문제가 드러났다.

- `create_blob/create_tree/create_commit/update_ref` 경로는 일반 파일 수정에 필요하지 않고, 이전 호출에서는 실패가 발생한 적도 있었다.
- 실제 파일 단위 `fetch_file → update_file/create_file` 경로는 안정적으로 동작했다.
- Contents API는 한 파일당 하나의 commit을 만들기 때문에 여러 파일의 coherent 변경을 원자적 multi-file commit처럼 설명하면 실제 기록과 어긋난다.
- 동시 automation/run이 같은 저장소를 건드릴 수 있으므로 write 직전 HEAD/blob/path 재검사가 필요하다.
- 연결된 GitHub tree/blob를 이용한 원격 fingerprint 대조와 로컬 `git clone`/checker 실행은 같은 검증이 아니다.
- 사용자가 GitHub Actions를 사용하지 말라고 한 상태에서는 workflow 실행·재실행을 일반 작업 수단으로 사용하면 안 된다.

이 내용을 프로젝트 작업 정책에 고정해 이후 작업에서 같은 쓰기 경로 혼동과 stale write를 반복하지 않게 한다.

## 변경 내용

`agent_space/AGENT.md`에 **GitHub 저장소 작업 방식** 절을 추가했다.

주요 규칙:

- 일반 파일 수정은 Contents API에 대응하는 파일 단위 경로를 우선한다.
- 기존 파일은 현재 blob SHA 확인 후 update, 새 파일은 경로 미존재 확인 후 create한다.
- 같은 경로의 write를 병렬 처리하지 않는다.
- 저수준 Git Data API는 일반 수정의 기본 경로로 사용하지 않는다.
- branch write 직전 현재 HEAD와 대상 blob/path를 재확인한다.
- multi-file 변경은 각 파일 write 뒤 갱신된 HEAD를 다음 write 기준으로 사용한다.
- 파일 단위 commit을 atomic multi-file commit으로 표현하지 않는다.
- coherent patch 기록은 변경 시작 HEAD부터 의미 변경 완료 HEAD까지 누적 diff로 남긴다.
- 기존 정책의 same-commit 요구를 현재 도구로 충족할 수 없다면 충족했다고 주장하지 않고 제한을 기록한다.
- concurrent run 가능성이 있으면 plan/patch/review/version metadata를 다시 읽고 stale write를 막는다.
- GitHub Actions는 사용자가 해당 작업에서 명시적으로 허용한 경우에만 실행한다.
- 원격 tree/blob 기반 대조를 실제 로컬 checker/test 실행으로 표현하지 않는다.
- 저장소에서 확인하지 않은 파일명, branch, API, workflow 입력값을 임의로 만들지 않는다.

## 선택한 방향과 이유

새 별도 GitHub 운영 문서를 만들지 않고 프로젝트의 실제 작업 규칙 원천인 `agent_space/AGENT.md`에 추가했다.

GitHub 작업 방식은 특정 plan 하나의 구현 세부사항이 아니라 이후 모든 저장소 수정에 적용되는 작업 규칙이므로 plan/review 문서보다 AGENT 정책에 두는 것이 적절하다.

저수준 Git Data API를 완전히 금지하지는 않았다. Contents API로 표현할 수 없는 명시적 필요나 쓰기 경로 진단에는 사용할 수 있지만, 일반 파일 수정에서 branch ref 조작까지 포함하는 경로를 기본값으로 사용하지 않도록 범위를 제한했다.

## 고려했지만 선택하지 않은 방향

- 루트에 새 `AGENTS.md` 생성: 현재 저장소의 실제 정책 파일은 `agent_space/AGENT.md`이며 새 루트 정책 파일은 중복 권위를 만들 수 있어 기각했다.
- Git Data API 전면 금지: 진단이나 Contents API로 표현할 수 없는 작업 가능성까지 막으므로 기각했다.
- Contents API의 다중 commit을 하나의 commit으로 간주: 실제 Git history와 다르므로 기각했다.
- 원격 fingerprint 대조를 checker PASS로 간주: 실제 프로세스 실행 여부를 흐리므로 기각했다.
- GitHub Actions를 자동 검증 fallback으로 사용: 사용자의 현재 명시적 금지와 충돌하므로 기각했다.

## 영향 범위

Source Script, PlusCal pseudocode, verification model, application source code의 의미는 변경하지 않는다.

`development-versions.json` revision/fingerprint를 변경하지 않는다.

이번 변경은 저장소 운영 정책과 기록 방식에만 영향을 준다.

## 검증

- 수정 전 `agent_space/AGENT.md` blob SHA를 확인했다.
- write 직전 main HEAD와 AGENT blob SHA를 다시 확인했다.
- `AGENTS.md`, 루트 `AGENT.md`가 존재하지 않고 `agent_space/AGENT.md`만 실제 정책 파일임을 확인했다.
- 새 patch 번호 `20261015-003`이 비어 있음을 확인했다.
- GitHub Actions는 사용하지 않았다.
