# 20261001-022 — r12 Source Script fingerprint metadata 수정

## 변경 원인

r12 commit `20261001-021` 이후 `Development layer versions` CI가 다음 오류로 실패했다.

```text
Source Script fingerprint changed without updating development-versions.json
```

현재 HEAD의 모든 `sourcescript/**/*.py` Git blob SHA-1을
`scripts/check-development-layer-versions.py`와 동일한 규칙으로 다시 계산한 결과
실제 Source Script layer fingerprint는 다음 값이다.

```text
sha256:c8bde1257048128f5c17081cb08fb9ef5bee1cc94dd9bb690d3e9419032655db
```

manifest에는 다른 값이 기록되어 있었다.

## 변경 내용

- `development-versions.json`의 Source Script r12 fingerprint만 실제 content fingerprint로 수정한다.
- Source Script 파일, 의미, revision은 변경하지 않는다.
- closure는 계속 `open`이다.

## 선택 이유

revision은 Source Script 의미/content 변경을 나타낸다.
이번 오류는 r12 content가 이미 저장된 뒤 lineage metadata의 fingerprint 값만 실제 내용과 맞지 않은 경우이므로
새 Source Script revision을 만들지 않고 metadata correction으로 처리하는 것이 의미와 version history를 정확히 보존한다.

## 고려했지만 선택하지 않은 방향

### Source Script revision을 r13으로 증가

선택하지 않았다.

`sourcescript/` 내용이 한 byte도 변경되지 않았고 새 의미도 추가되지 않는다.
metadata 기록 오류만으로 semantic revision을 증가시키면 revision 의미가 왜곡된다.

### r12 Source Script를 manifest의 기존 fingerprint에 맞게 되돌림

선택하지 않았다.

현재 r12 Source Script 변경은 `20261001-021.patch/.md`에 기록된 의도된 변경이며,
CI가 지적한 것은 실제 Source Script 내용이 아니라 manifest fingerprint 불일치다.

### 실패 원인을 추정해 Source Script를 다시 수정

선택하지 않았다.

현재 확인 가능한 사실은 recorded fingerprint와 checker 계산값의 불일치뿐이다.
근거 없이 source 의미를 바꾸지 않는다.

## 닫힘 판정 영향

없음.

r12는 여전히 `current/open`이며,
이 correction 뒤 version-chain CI를 정상화한 다음 r12 기준 closure review를 수행한다.
