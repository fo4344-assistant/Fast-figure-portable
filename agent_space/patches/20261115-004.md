사용자가 개발 정책을 고려하여 계획을 다시 작성하도록 요청했다. `agent_space/plans/plan-028.md`만 재작성하고 이 설명을 추가한다. 프로그램 수정은 수행하지 않는다.

## 선택한 방향과 이유

이전 계획의 ‘모든 공식 읽기가 같은 보관 객체를 공유한다’는 제안을 제거했다. 기존 revision 숫자를 화면 구독의 변경 감지에 쓰고, 표시 결과와 변경 이벤트의 현재 읽기를 분리한다. 이 방식은 React 반복 읽기 조건을 전체 FSM의 보관 규칙으로 확대하지 않으며, 기존 선택 소유자·공식 읽기·명시적 명령을 유지한다.

객체 추가는 표시용 activeCsv 식별자도 그대로 재사용하지 않고 이벤트 시 공식 graphs.readData의 currentCsv를 읽는다. 비동기 파일 입력의 고정 대상은 그 불러오기 한 건에서만 소비하며 화면 선택이나 공용 읽기 원천으로 사용하지 않는다. 이들은 계획에 적은 후속 구현 절차이지 이번에 반영한 프로그램 변경이 아니다.

## 고려했지만 선택하지 않은 방향

- 공용 불변 상태 cache: 표시와 명령의 재사용 경계 및 갱신 규칙이 추가된다.
- UI의 전체 상태·revision 이중 cache: 기존 권위 원천과 중복된다.
- 화면에 슬롯 번호만 보충: 이전 표시 결과가 명령으로 유입되는 문제가 남는다.
- 새 전역 선택 저장소나 새 public 명령군: 같은 기능을 기존 구조로 제공할 수 있다.
- 정책 변경: 구현을 정책에 맞추는 요청이며 정책 수정은 허용되지 않았다.
