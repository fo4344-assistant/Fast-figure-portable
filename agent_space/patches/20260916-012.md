Its architectural conclusion is unchanged: project/domain CSV state and graph-object `csvId` references are authoritative, while legacy native `rows` / `columns` may survive only as frontend preview/form buffers. `activeDataName` and `activeDataReady` are redundant shared projections and must be removed.

## Ownership decision

- Project CSV rows and `headerLines` are owned by project/domain state.
- Current project asset selection is owned by the application logic EFSM (`assetPath` / selection transition).
- Graph objects own explicit `csvId` references.
- Native `rows` / `columns` remain temporary frontend buffers only for the still-existing native graph form/preview.
- Backend/core, logic EFSM, project load/rollback, shared loaders, chart activation, and functional renderers must not depend on those UI buffers.
- `activeDataName` and `activeDataReady` are duplicate projections and are removed rather than synchronized.

## Exact changes

1. Remove the global `activeDataName` and `activeDataReady` values.
2. Stop slot-selection/type/reset/swap logic from clearing, snapshotting, or restoring graph-data frontend buffer/readiness state.
3. Make shared table helpers independent of native DOM/runtime defaults:
   - `headerLineCount(value, table = [])`;
   - `columnDefinitions(table = [], headerLines = 1)`;
   - `dataRows(table = [], headerLines = 1)`.
4. Remove `tracesSingle()` fallback to global `rows`; missing explicit rows now produce an empty local input instead of borrowing frontend state.
5. Stop `activateChartModel()` from projecting selected chart CSV data into `activeDataName`, `activeDataReady`, `rows`, or `columns`.
6. Keep the legacy native `applyGraphSettings()` functional by deriving its local readiness from its own `rows` / `columns` buffers.
7. Remove `rows`, `columns`, `activeDataName`, and `activeDataReady` from project runtime capture/restore/reset.
8. Remove graph-data frontend projection bookkeeping from `loadDataFile()`; its completion log uses authoritative `csv.rows.length`.
9. Remove the dead `activeDataName` assignment from native object selection while preserving explicit `loadData(csv.rows, csv.name)` for that native UI ownership path.

## Why this direction
A temporary UI buffer is acceptable only inside the frontend ownership area that created it. It stops being a harmless projection when backend/core logic resets it, snapshots it, restores it, or uses it as a rendering fallback.

This patch restores the intended dependency direction:

```text
project/domain CSV SoT + graphObject.csvId
  -> explicit domain/read operations
  -> renderer / backend logic

legacy native graph UI
  -> loadData(...)
  -> rows / columns frontend buffer
  -> native preview/form only
```

It removes the reverse dependency from core/EFSM/project-loader/renderer into the frontend buffer.

## Rejected alternatives

- Replay `20260916-011` unchanged: rejected because its application hunk failed and the patch metadata/contexts should not be assumed valid after failure.
- Rewrite the loader conditional while removing projection assignments: rejected because the structural rewrite is unrelated to ownership and increases rollback/context surface.
- Promote `rows` / `columns` to backend/router state: rejected because they are derived native UI buffers, not domain state.
- Keep `activeDataReady` synchronized with project/selection state: rejected because readiness is derivable and synchronization preserves duplicate state.
- Remove the entire native graph editor now: rejected because that is a separate frontend ownership/cutover unit.
- Modify image-side runtime mirrors in this patch: rejected pending their own ownership audit.
