# 20260910-001 — WIP 표시와 Mantine 레이아웃 구현

## 목적
Mantine 전환을 기능 단위별 완성/검증 때문에 지나치게 잘게 나누지 않고, 중간 상태가 완전 동작하지 않을 수 있음을 버전에 명시한 뒤 레이아웃 편집 UI 본체를 먼저 구현한다.

## 변경
- APP_BUILD를 `1.1.31-alpha`에서 `1.1.31-wip`로 변경한다. PACKAGE_FORMAT_VERSION은 변경하지 않는다.
- `FastFigureLayoutOverlay`를 추가하여 Mantine Modal이 `appFSM.state.overlay === "layout"`를 직접 소유한다.
- 행/열 1–8, 기준 폭 100–20000, gap 0–2000, outer margin 0–5000, radius 0–2000, aspect 0.1–10, slot border를 현재 project layout 값에 직접 적용한다.
- layout slot을 React grid로 표시하고 기존 `layoutSelected`를 사용해 선택한다.
- 기존 `mergeSelected()` / `splitSelected()` command를 직접 호출한다.
- zoom 50–200, lock, reset을 기존 dashboard zoom command에 연결한다.
- 기존 legacy layout popup/renderer 제거는 하지 않는다. WIP 단계에서 기능 구현을 먼저 진행하고 parity/cutover에서 제거한다.

## 선택 이유
현재 병목은 legacy popup geometry를 먼저 완전히 분리하고 나서 Mantine을 구현하려는 순차 작업 자체였다. 사용 지시에 따라 중간 상태의 완전 동작을 보장하기보다 WIP로 명시하고 실제 Mantine ownership 구현을 먼저 진행한다. project layout과 기존 EFSM command가 이미 authority이므로 새로운 영속 상태는 만들지 않는다.

## 기각안
- `syncLayoutMapSize()`를 먼저 renderer-neutral helper로 추출한 뒤 별도 패치에서 Modal을 구현: 중간 작업을 늘리므로 기각.
- legacy layout DOM을 Mantine에 복제하는 bridge: 장기 구조가 잘못되므로 기각.
- layout EFSM/ProjectObject 재설계: UI 이전에 불필요하므로 기각.

## Source of truth / EFSM 영향
영속 레이아웃 값은 계속 `activeProject.layout`과 `activeProject.layout.slotStyle`이 유일한 source of truth다. 행/열은 기존 `GRID_LAYOUT_CHANGED`, merge/split은 기존 command를 사용한다. UI-FSM/functional EFSM 구조와 FFPX schema는 변경하지 않는다. React local state는 layout selection repaint와 zoom control의 임시 표시값에만 사용한다.

## WIP 제한
이 패치는 의도적으로 WIP이다. legacy layout popup/event handler가 아직 공존하므로 Mantine Modal의 outside-click/legacy popup 상호작용 및 resize parity가 완전히 정리되지 않았을 수 있다. 이 제약은 후속 parity/cutover에서 해결하며, 이를 이유로 구현을 다시 작은 선행 패치로 분리하지 않는다.

## 검증
workflow의 git apply, JS syntax, portable build, split/portable file smoke를 통과해야 한다. UI interaction parity는 WIP 후속 통합 검증에서 수행한다.

## Rollback
이 패치를 역적용하면 APP_BUILD가 `1.1.31-alpha`로 돌아가고 Mantine layout overlay만 제거된다. project schema/EFSM 변경이 없으므로 데이터 마이그레이션은 필요하지 않는다.
