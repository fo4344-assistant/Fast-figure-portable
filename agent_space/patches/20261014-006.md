# 20261014-006 — Use desktop mouse drag for settings Modal resize

## 목적과 변경 내용

공통 settings Modal의 하단 resize handle을 desktop mouse drag lifecycle로 단순화하고 regression도 동일 경로를 검증하도록 변경한다.

- `mousedown`에서 current `Modal.Content` 높이와 시작 Y를 기록.
- `window.mousemove`에서 UI-local height를 clamp하여 갱신.
- `window.mouseup`에서 listener/state/cursor를 정리.
- unmount cleanup도 동일한 정리 함수를 사용.
- regression test 29는 같은 mouse event 경로를 사용.
- source-code revision r18, APP build `1.1.38-wip`.

## 실패 근거

r15–r17의 hosted browser regression에서 Tree, trash recovery, tree→slot drag, bookmark 즉시 rerender, Layout preview aspect는 inline/split 모두 반복해서 통과했다.

유일한 실패는 synthetic PointerEvent로 검사한 settings Modal height resize였다. pointer-capture 제거와 direct `Modal.Content` ref 적용 후에도 동일한 합성 이벤트 경로에서 높이 변화가 관찰되지 않았다.

## 선택 이유

이 UI는 desktop용 bottom resize handle이며 mouse drag가 요구된 기본 interaction이다. 실제 구현과 test가 동일한 browser event path를 사용하게 하여 synthetic pointer-capture 차이를 제거한다.

## 고려했지만 선택하지 않은 방향

- test 29 제거: 사용자 요구의 핵심 기능을 검증하지 못하므로 기각.
- 임의 imperative test hook 추가: 제품 코드에 test-only API가 생기므로 기각.
- CSS native `resize`: 공통 손잡이 위치/height clamp/cleanup 책임을 잃으므로 기각.
- project state에 popup height 저장: UI-local 상태를 persistent authority로 확대하므로 기각.
