# 20260906-009 — workspace domain helper active wrapper 연결

## 상태

첫 큐 실행은 `git apply --check`에서 `corrupt patch at ...:23`으로 중단되어 `fast-figure.js`에는 적용되지 않았다. 첫 workspace hunk의 old/new line count를 실제 `10/10`으로 교정한 뒤 재시도했지만, 두 번째 실행도 `corrupt patch at ...:40`으로 중단됐다.

두 실패 모두 구현 context가 아니라 unified diff hunk header 계산 오류였다. 최종 재계산 결과 graph hunk는 old/new `11/12`였고 여기에서 new file이 1줄 늘어나므로 뒤의 hunk 시작 위치도 각각 +1 누적되어야 했다. 최종 patch는 이를 반영해 `git apply --check`, JavaScript syntax, portable build, split/portable `file://` smoke test를 모두 통과했고 실제 `fast-figure.js`에 적용됐다.

## 목적

`20260903-009`에서 cutover용으로 준비한 workspace domain helper를 현재 active legacy workspace wrapper에서도 먼저 호출하도록 연결한다.

현재 `APP_STATE_DEFINITIONS.workspace`는 아직 legacy wrapper(`syncProjectWorkspaceState`, `syncGraphWorkspaceState`, `syncImageWorkspaceState`, `exitGraphWorkspaceState`)를 사용한다. 이 wrapper들은 domain/transient synchronization과 native DOM presentation을 한 함수 안에서 수행하고 있어, Mantine cutover 시 별도 callback 경로와 의미가 갈라질 수 있다.

JS source split 이후 현재 `fast-figure.js`를 다시 확인한 결과 다음 cutover helper는 현재 소스에 존재하며 DOM을 직접 읽거나 쓰지 않는다.

- `syncProjectWorkspaceDomainState()`
- `syncGraphWorkspaceDomainState()`
- `syncImageWorkspaceDomainState()`
- `exitGraphWorkspaceDomainState()`

`refreshCsvControls()`는 이름과 달리 `activeCsvId` 정규화만 수행하며 DOM 접근이 없고, `setActiveImageFromId()`도 `activeImageId` 정규화만 수행한다.

## 변경 내용

- 앱 버전 `1.1.112-alpha` → `1.1.113-alpha`
- `syncProjectWorkspaceState()`가 먼저 `syncProjectWorkspaceDomainState()`를 호출하고 반환된 availability model을 `updateFileAvailability(availability)`에 전달
- `syncGraphWorkspaceState()`가 `syncGraphWorkspaceDomainState()`를 호출해 slot/availability/chart selection을 얻음
  - 새 chart selection이 발생한 경우 기존 `editChart()` 전체를 다시 호출하지 않고 이미 분리된 `syncLegacyGraphEditorSelection(selection)`만 presentation 단계에서 호출
  - chart가 없는 경우 기존 legacy clear/hide 동작 유지
- `syncImageWorkspaceState()`가 `syncImageWorkspaceDomainState()`의 slot/availability를 사용
- `exitGraphWorkspaceState()`가 `exitGraphWorkspaceDomainState()`를 호출한 뒤 legacy `buildBox` 표시만 정리

## 의미 보존

### project workspace

기존 availability policy, active CSV/image 정규화 의미를 domain helper가 먼저 수행한다. 파일명/preview/tree/label/caption/native panel 동기화는 기존 wrapper에 남긴다.

### graph workspace

기존 `editChart(id)`는 이미 `selectChartForEditing(id)` + `syncLegacyGraphEditorSelection(selection)`으로 분리되어 있다. domain helper가 전자를 담당하고 legacy wrapper가 후자를 담당하므로 chart selection source of truth를 새로 만들지 않는다.

### image workspace

selected slot image → `activeImageId` 정규화는 domain helper가 담당한다. 파일명/preview/native image controls/tree/caption은 legacy wrapper가 담당한다.

### graph exit

`selectedObjectIndex = null`은 domain helper가 담당하고 `buildBox` 숨김만 legacy wrapper에 남긴다.

## 중복 호출에 대한 판단

현재 `updateFileAvailability()`가 호출하는 legacy `syncSlotContentTypeUi()` 내부에는 `refreshCsvControls()`와 `refreshImageControls()` 호출이 남아 있다. 따라서 active legacy 경로에서는 일부 transient 정규화가 한 번 더 idempotent하게 실행된다.

이번 patch에서 이를 함께 제거하지 않는다. `updateFileAvailability()`는 workspace 외 여러 legacy 호출처에서도 사용되므로, 이 내부를 동시에 presentation-only로 바꾸면 범위가 넓어진다. 우선 authoritative workspace callback 경계를 공통 helper로 맞춘 뒤, cutover 직전 legacy infrastructure cleanup에서 호출 관계를 확인해 제거한다.

## Mantine 전환과의 관계

아직 `APP_STATE_DEFINITIONS`의 callback을 domain helper로 직접 교체하지 않는다. active owner는 legacy UI이며 `FastFigureShellStaging`은 mount되지 않은 상태다.

이번 변경은 cutover 전 의미 통합 단계다. cutover 시에는 동일 domain helper를 EFSM callback으로 사용하고 legacy presentation wrapper를 제거할 수 있게 된다.

## source of truth / EFSM / core

- workspace state 의미와 transition target 변경 없음
- selected slot/chart/CSV/image의 기존 source of truth 유지
- 새 React/local/global state 없음
- FFPX/FFSX/Plotly schema 및 import/export 의미 변경 없음
- Plotly/image/layout renderer 변경 없음

## 선택하지 않은 방향

### APP_STATE_DEFINITIONS를 즉시 domain helper로 교체

legacy active UI가 더 이상 갱신되지 않으므로 cutover와 동시에 해야 한다. 이번 단계에서는 선택하지 않는다.

### legacy wrapper와 domain helper 양쪽에서 chart selection을 각각 수행

`selectChartForEditing()`이 두 번 실행될 수 있어 선택하지 않는다. domain helper가 selection을 수행하고 legacy wrapper는 반환된 selection을 presentation에만 사용한다.

### updateFileAvailability 내부까지 동시에 정리

workspace 외 호출 경로까지 영향 범위가 확장되므로 별도 감사 후 처리한다.

## 회귀 위험

낮음~중간.

외부 observable UI는 유지하지만 graph workspace의 기존 `editChart()` 호출을 domain selection + legacy presentation 두 단계로 명시적으로 사용한다.
