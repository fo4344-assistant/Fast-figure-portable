# 20260902-036 — Mantine graph object 추가 버튼 연결

## 배경

`20260902-034`는 선택 슬롯과 active CSV에서 새 graph object 기본값을 계산하는 `readGraphObjectAdd()` read model을 추가했고, `20260902-035`는 해당 snapshot을 기준으로 기존 EFSM event/action을 사용하는 `addGraphObject()` DOM-free command를 추가했다.

chart가 아직 없는 슬롯에서는 `readGraphObjects()`가 `null`이어도 `readGraphObjectAdd()`는 유효할 수 있으므로 기존 목록 component 자체에 add 책임을 억지로 합치지 않는다.

## 목적

- Mantine sidebar에서 graph object 추가 기능을 실제로 노출한다.
- chart 존재 여부와 관계없이 active CSV가 준비된 그래프 슬롯에서 추가할 수 있게 한다.
- React persistent state나 legacy DOM form을 추가 source of truth로 만들지 않는다.

## 변경 내용

- 앱 버전 `1.1.78-alpha` → `1.1.79-alpha`
- `FastFigureGraphObjectAddStaging` 추가
- sidebar snapshot read에 `readGraphObjectAdd()` 추가
- 유효한 add model이 있을 때 Mantine `Button` 렌더
- 클릭 시 `fastFigureUiBridge.addGraphObject(slotId, chartId)` 호출

## UI 구조

```text
readGraphObjectAdd()
→ FastFigureGraphObjectAddStaging
→ Mantine Button
→ fastFigureUiBridge.addGraphObject(...)
→ 035 command
```

chart가 없는 슬롯에서도 add model이 있으면 버튼은 표시된다. 기존 object 목록은 `readGraphObjects()`가 있을 때만 별도로 렌더한다.

## source of truth

component는 `graphObjectAdd` prop을 저장하거나 복제하지 않는다. sidebar가 EFSM snapshot 재렌더마다 bridge selector를 다시 호출한다.

버튼 클릭 시 snapshot에 포함된 `slotId`와 `chartId`를 command에 넘기며, `035` command가 현재 canonical 선택 상태와 다시 비교한다.

## 변경하지 않음

- 기존 graph object 목록 component
- legacy `#addGraphObject` handler
- graph/domain schema
- EFSM event/action
- Plotly trace/layout 코드
- import/export

## 기각한 대안

### 목록 component에 add 기능을 직접 합치기

기각. chart가 없는 상태에서는 목록 model 자체가 없기 때문에 nullable 모델 처리와 책임이 불필요하게 복잡해진다.

### 로컬 React draft를 만든 뒤 확인 버튼으로 추가

기각. 현재 기능은 추가 직후 새 object를 선택해 상세 form에서 편집할 수 있으므로 별도 draft source of truth는 필요하지 않다.

## 검증

- patch apply/check
- JavaScript syntax
- Mantine `Button`은 기존 runtime에서 가져옴
- `readGraphObjectAdd()` 결과가 없을 때 렌더하지 않음
- command 외 직접 domain mutation 없음
- Plotly bundle 미접촉

## rollback

- `FastFigureGraphObjectAddStaging` 제거
- sidebar `graphObjectAdd` read/render 제거
- 앱 버전 `1.1.78-alpha` 복원

`035` command 자체는 남으므로 UI 연결만 독립적으로 rollback할 수 있다.

## 후속

성공 적용 후 legacy `#addGraphObject` handler의 기능 중 Mantine command와 중복되는 부분을 제거하고 동일 command를 재사용하도록 정리한다. legacy renderer에 필요한 DOM 갱신만 wrapper에 남긴다.
