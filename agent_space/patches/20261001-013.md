# 20261001-013 — Source Script r4 layout/annotation/export/runtime 정규화

## 변경 원인

plan-008 Phase 4와 중복 상태 정리 항목을 r3 위에 반영한다.

r3까지 project/file/graph 의미는 정리되었지만 layout resize, label drag, export settings 사용 경로,
editing/layoutMapWidth가 여전히 하위 구현 의미를 따라가고 있었다.

## 의미 변경

### grid resize

- grid resize를 content reflow와 분리
- 확대는 기존 좌표/span/content/caption을 보존하고 새 empty cell만 추가
- 축소는 제거 영역에 다음이 있으면 거부
  - chart/image reference
  - explicit slot caption
  - merged span
- 안전한 shrink는 empty 1x1 cell만 제거
- 자동 row-major packing을 하지 않음

### merge/split/caption

- merge/split의 renderable content와 chart ownership 이동 규칙을 candidate-first로 명시
- caption은 별도 annotation으로 유지
- swap/merge/split/reset caption 이동/삭제는 근거가 부족해 명시적으로 미확정 상태로 유지
- FFSX caption 전달만 현재 공개 계약에 따라 확정

### label position

- label x/y는 single persistent SoT
- pointer drag도 같은 mutation path로 연속 갱신
- 별도 preview draft 제거
- interaction finish는 position의 두 번째 commit이 아님

### export

- persistent export settings read/set command 정의
- target export는 project snapshot의 persistent settings에서 geometry를 계산
- DOM current size를 target export geometry authority로 사용하지 않음
- current-screen capture는 one-shot operation이며 persistent target width/height를 변경하지 않음

### 중복 runtime state

- global `editing` Source Script state 제거
- selectedSlotId -> slot.chart -> chart resolve로 통합
- `layoutMapWidth`를 authoritative project schema에서 제거
- 기존 v3 field는 legacy no-op input으로만 취급
- debugEnabled -> telemetry는 one-way projection으로 정리

### startup

- default CSV 생성과 makeSlots domain 재초기화를 startup에서 제거
- createProjectState/loaded ProjectObject가 이미 valid slot structure를 소유한다.

## 선택 이유

grid resize에 자동 packing을 넣으면 layout 변경이 사용자의 panel 위치까지 암묵적으로 바꾸므로 별도 reflow command가 아닌 resize에서는 안전한 거부가 더 예측 가능하다.

label position은 별도 draft 없이 continuous authoritative edit로 같은 기능을 표현할 수 있으므로 상태 복제를 만들지 않는다.

editing과 layoutMapWidth는 독립적인 기능 자유도를 제공하는 producer/consumer가 확인되지 않아 제거하는 편이 최소 복잡도와 SoT 원칙에 맞다.

## 기각한 대안

- unsafe shrink 후 자동 packing: 암묵적 panel 재배치이므로 기각
- caption을 graph/image와 항상 함께 이동: 현재 FFSX/swap/merge/reset 동작과 요구가 하나의 의미로 수렴하지 않아 임의 확정하지 않음
- label preview local draft: 별도 상태 없이 같은 UX가 가능해 기각
- editing cache 유지: 선택 chart를 항상 current project에서 resolve할 수 있어 기각
- layoutMapWidth 유지: 실제 의미를 생성/소비하는 경로가 없어 기각
- target export에서 DOM bounds 사용: persistent logical project geometry와 화면 viewport를 혼합하므로 기각

## 닫힘 판정 영향

grid resize, label position, export-settings 사용, editing/layoutMapWidth/debug 중복 문제는 해결되었다.

slot caption의 swap/merge/split/reset semantics는 여전히 미확정이며 closure blocker로 남는다.
FSM/API mutation contract도 다음 revision에서 보완해야 하므로 closure는 open이다.

## 하위 단계 전파 범위

- grid resize unsafe shrink 거부
- label preview/commit API 단순화
- persistent export settings UI/API/FFPX 구현
- editing global pointer 제거
- layoutMapWidth writer/state 제거 및 legacy read-ignore
- startup default CSV/makeSlots side effect 제거
- caption operation semantics 확정 후 해당 operation 구현

현재 pseudocode/source code는 수정하지 않는다.
