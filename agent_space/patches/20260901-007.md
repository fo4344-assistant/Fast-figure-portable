# 20260901-007 — Mantine Layout staging 계약 연결

## 목적

`plan-003.md` Commit B를 이어서 수행합니다. `20260901-006`에서 DOM과 분리한 Layout values/payload 계약을 비활성 React/Mantine Layout Modal에 연결합니다. legacy Layout UI는 계속 유일한 활성 UI로 유지하며 shell cutover는 수행하지 않습니다.

## 변경 내용

- 애플리케이션 버전을 `1.1.37-alpha`로 갱신합니다.
- `FastFigureLayoutModalStaging({ opened })`을 추가합니다.
- Mantine `NumberInput`으로 `gridRows`, `gridCols`, `referenceWidth`, `gap`, `outerMargin`, `radius`, `aspect`를 편집합니다.
- Mantine `Switch`로 `showBorders`를 편집합니다.
- Modal이 열릴 때 `fastFigureUiBridge.read().layout`에서 draft를 다시 구성합니다.
- 적용 버튼은 DOM control을 읽지 않고 `fastFigureUiBridge.applyLayoutSettings(draft)`만 호출합니다.
- 기존 `FastFigureOverlayHostStaging`의 Layout 읽기 전용 summary를 실제 staging form으로 교체합니다.
- `window.FastFigureReactShell` export에 `FastFigureLayoutModalStaging`을 추가합니다.

## 상태 소유권

- 영속 상태의 권위는 기존 `activeProject.layout` / project object입니다.
- React local state는 Modal에서 아직 commit되지 않은 임시 입력값만 보유합니다.
- overlay open/close 상태는 기존 EFSM `overlay` region이 계속 소유합니다.
- Layout mutation은 `20260901-006`에서 만든 DOM-free 계약을 재사용합니다.

따라서 React가 project/domain state의 두 번째 소유자가 되지 않습니다.

## 기존 기능과의 관계

이번 단계는 rows/columns 및 slot style 적용 계약만 연결합니다. merge/split, layout map, dashboard zoom은 기존 renderer 및 기존 handler에 남겨 둡니다. 이들을 임시로 DOM을 통해 호출하지 않습니다. 해당 기능의 domain 경계가 분리되기 전까지 Mantine staging에 억지로 연결하지 않는 것이 `plan-003`의 결합 제거 원칙에 맞습니다.

## 고려했지만 선택하지 않은 방향

- legacy input 값을 React에서 직접 읽지 않습니다.
- 기존 `applyGrid.click()`을 Mantine 버튼에서 호출하지 않습니다.
- Layout Modal을 현재 화면에 mount하지 않습니다.
- merge/split/layout-map을 DOM event forwarding으로 연결하지 않습니다.
- 별도 React global store를 추가하지 않습니다.

## 검증 기준

- `20260901-007.patch`는 `Fast-figure.html`만 변경해야 합니다.
- `git apply --check`와 `git diff --check`를 통과해야 합니다.
- main inline JavaScript가 `node --check`를 통과해야 합니다.
- staging shell은 여전히 mount되지 않아 현재 사용자 UI와 legacy handler 동작이 바뀌지 않아야 합니다.
- Layout staging 적용 경로에서 `gridRows`, `gridCols`, `slotStyle` 값이 `fastFigureUiBridge.applyLayoutSettings()`로 전달되어야 하며 native input ID를 참조하지 않아야 합니다.

## 재시도 기록

첫 큐 커밋에서 Layout summary 교체 hunk의 unified-diff 라인 수 헤더가 본문과 일치하지 않아 `git apply --check` 단계에서 실패했습니다. 코드 내용이나 적용 범위는 변경하지 않고 해당 hunk를 `9 -> 8` 라인으로 바로잡아 재시도합니다.

## 후속 작업

다음 논리 커밋에서는 Label 편집의 DOM control 읽기와 실제 domain mutation을 분리합니다. 이후 그 values/payload 계약을 `FastFigureLabelModalStaging`에 연결합니다. Caption과 Print도 같은 순서로 진행하고 Commit B가 완성된 뒤에만 Commit C의 단일 shell cutover를 수행합니다.
