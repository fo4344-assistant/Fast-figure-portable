# 20260928-017

## 목적과 변경 내용

프로젝트 UI 팔레트가 Mantine shell과 controls에 다시 반영되도록 한다. 기존 편집기에는 10개 팔레트 필드가 있으나, legacy generic CSS를 제거한 후에는 `uiColor`, `uiBackgroundColor`, `uiSubtleColor`와 renderer용 색상만 제한적으로 표시됐다.

`FastFigureApp`은 기존 `appFSM` 구독을 통해 현재 `FastFigureApi.appearance.readPalette()`를 읽고, `MantineProvider.cssVariablesResolver`에 투영한다. 새 팔레트 상태는 만들지 않는다.

| 프로젝트 팔레트 값 | Mantine 표시 대상 |
| --- | --- |
| `uiColor` | 기본 테두리, primary button의 채움·hover·light variant |
| `uiBackgroundColor` | body/shell 배경 |
| `uiSurfaceColor` | 기본 표면과 hover 바탕 |
| `uiMutedColor`, `uiSubtleColor` | 보조 텍스트와 placeholder |
| `uiDisabledBgColor`, `uiDisabledTextColor` | 비활성 표면·테두리·글자 |
| `uiShadowColor` | Mantine 기본 shadow geometry의 색상 |
| `fontColor` | 일반 글자·기본 표면 글자·light button 글자 |

`paperColor`와 기존 dashboard/slot CSS 투영은 계속 기능 renderer가 담당한다. accent 배경의 글자색은 저장된 `#RRGGBB` 값의 상대 휘도로 흑/백 중 하나를 선택한다. shadow의 크기와 위치는 Mantine theme 기본값을 재사용하고 검정 `rgba` 색상만 프로젝트 색상으로 바꾼다.

## 선택 이유

`review-010-mantine-ui-inventory.md`는 프로젝트 팔레트를 유일한 영속 상태로 두고 최종 cutover에서 Mantine theme/CSS variables에 투영하도록 명시한다. `appFSM.notify("ui", "UI_PALETTE_CHANGED")`와 프로젝트 load의 기존 발행 경로가 provider 재렌더를 구동한다. `cssVariablesResolver`의 `variables/light/dark` 병합과 `ScrollArea` 등에서 사용하는 변수 이름은 현재 vendored Mantine runtime과 CSS에서 확인했다.

## 고려했지만 선택하지 않은 방향

- **`applyUiPalette()`에서 Mantine CSS 변수를 직접 `document.documentElement.style.setProperty`로 쓰기:** 변경 줄 수는 적지만 Provider가 생성하는 값과 별도의 DOM inline 값이 같은 일반 UI 색상을 소유하게 된다. Provider 경계에서 읽어 투영하는 편이 더 명확하다.
- **`uiColor` 한 값으로 임의의 Mantine 10단계 색상표를 생성해 `theme.colors`를 교체하기:** 일부 variant에는 유리하지만 새로운 색상 생성 규칙을 정의해야 하고, 나머지 표면·보조·비활성·shadow 필드의 대응은 여전히 별도로 필요하다. 이번 팔레트 계약에는 CSS 변수별 대응이 더 직접적이다.
- **첫 렌더 시에만 팔레트를 읽기:** 변경량은 작지만 적용·기본값·프로젝트 가져오기 후 Mantine 색상이 갱신되지 않는다.
