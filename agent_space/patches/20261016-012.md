## 목적 / 이유

## 대안 / 배제 이유

- JS부터 수치 처리 변경: 하위가 상위 의미를 결정하게 하므로 배제한다. 기존 JS는 scalar/표시 호환 차이의 정적 확인에만 사용했다.
- 모든 blank를 결측값으로 변경하거나 category x 제거: 기존 CSV 사용 의미를 불필요하게 바꾸므로 배제한다. 반면 실제 비유한 numeric/overflow는 유효 좌표가 아니므로 제외하도록 상위에서 명시했다.
- renderer가 자체 CSV resolve/trace를 계산: 같은 project에 두 계산 owner가 생기므로 배제한다.
- candidate 새 CSV를 찾기 위해 live 부분 commit 또는 global pointer 교체: 실패 원자성과 단일 authority를 손상시키므로 배제한다.
- projection 전체를 command candidate로 역전달: query와 mutation 방향을 섞으므로 배제한다.
- 새 validator/독립 숫자 framework/결과 envelope: 기존 graph domain 절차와 query/renderer 공통 계약으로 충분하므로 배제한다.
- 부분 계산 구체화로 closed 선언: layout/palette와 전체 API trace가 남아 있어 배제한다.

## 제외 / 전송 한계

정책, PlusCal/model, JS/UI/tests/build/distribution은 변경하지 않았다. D 전체 public API trace와 E의 layout/style/extension/axis 보조 표시, palette/default color 원천, 전체 왕복 closure는 남아 있다. 문서의 시나리오는 정적 추론이며 실행 결과가 아니다.

GitHub Contents API로 매 파일의 예상 branch HEAD와 현재 blob SHA를 확인하고 LF 정규화한 내용을 순차 PUT했다. 새 review/patch 경로는 404와 기존 tree 부재를 확인한다. 다중 파일 원자 commit이 아니므로 source 선게시와 metadata 후게시 사이 push checker가 실패할 수 있다. 실제 baseline에서 patch 쌍까지 포함하는 누적 검사를 별도로 수행하며 중간 실패를 최종 성공으로 표시하지 않는다.
