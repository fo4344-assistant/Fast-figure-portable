# 20261013-014 — Add r17 interaction verification slice

## 목적

Source Script r17에서 추가·수정된 slot selection/deselection과 일반 빈 CSV 생성·선택·graph reference 의미를 canonical `verification/` 계층에 실행 가능한 상태 모델로 추가한다.

## 변경 내용

- `verification/FastFigureInteractionCore.tla`를 추가한다.
- `verification/FastFigureInteractionCore.cfg`를 추가한다.
- `verification/README.md`에 r17 interaction slice의 범위와 현재 검증 상태를 기록한다.
- verification-model revision을 r7로 올리고 현재 Source Script r17 fingerprint에서 파생되었음을 기록한다.
- 아직 TLC를 실행하지 않았으므로 verification-model은 `stale`, `tlc=pending`, validation review 없음으로 둔다.

## 모델링한 의미

- explicit no-slot 입력에 의한 slot deselection
- 미선택 visible slot surface click의 content-type 비의존 selection
- 선택된 content slot surface의 content interaction pass-through
- 선택된 empty slot surface의 same-slot toggle
- bookmark same-slot toggle
- dashboard background deselection
- 일반 빈 CSV 생성
- 생성된 CSV의 current CSV selection
- 빈 CSV 생성 자체가 기존 graph-object 수를 변경하지 않음
- 이후 graph-object 추가가 current selected CSV를 참조함

## 모델링하지 않은 UI-local 항목

- trash row Menu의 열린 상태
- 구체적인 Mantine Modal px/token
- layout preview의 DOM 측정값

이 값들은 r17 Source Script에서 persistent project authority가 아니며, 이번 상태변경 검증 모델에 별도 상태로 추가하지 않는다.

## 선택한 방향

기존 `FastFigureSlotCore.tla`를 재작성하지 않고 이번 r17에서 새로 필요해진 interaction/mutation 의미를 별도 canonical module로 추가했다. 기존 slot/layout candidate 검증과 이번 selection/CSV interaction 검증의 상태공간을 불필요하게 결합하지 않으면서 각각 Source Script 책임을 직접 추적할 수 있다.

## 기각한 방향

- 기존 slot-core 모델 안에 CSV asset/editor 전체 구조를 억지로 추가하지 않았다.
- UI Menu opened state와 Modal size를 persistent verification state로 승격하지 않았다.
- 빈 CSV 생성 후 graph-object 수가 0이라고 가정하지 않았다. 생성 이전 graph-object 수를 저장하고 생성 이후 동일함을 검사한다.
- TLC 실행 없이 `current/passed`로 표시하지 않았다.

## 검증 상태와 중단 조건

현재 실행 환경에는 `tla2tools.jar`가 없고 외부 다운로드를 사용할 수 없어 공식 PlusCal translator/SANY/TLC 실행을 수행하지 못했다.

따라서 Source Code 수정 gate는 열리지 않는다. `fast-figure.js`, `fast-figure-ui.js` 등 application Source Code는 verification-model이 current이고 TLC가 passed가 되기 전까지 수정하지 않는다.

## 후속 작업

1. 공식 TLA+ tools 1.7.4 환경에서 interaction module을 translate/parse/model-check한다.
2. 성공 결과에 대해 새 validation review를 작성한다.
3. verification-model을 current + passed로 승격한다.
4. 그 이후에만 r17에 따른 application Source Code를 수정한다.

## rollback

이 patch를 되돌릴 때는 두 InteractionCore 파일, verification README 추가 절, verification-model r7 metadata를 함께 r6 상태로 복원한다.
