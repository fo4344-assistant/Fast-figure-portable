# 20260914-003 — Mantine layout and palette command ownership

## 목적
20260914-002 이후 남은 layout/zoom/UI palette의 legacy input/button wiring을 제거해 Mantine path만 command owner가 되도록 한다.

## 변경
- `setDashboardZoomLocked()`가 old slider/button DOM을 갱신하지 않도록 한다.
- old dashboard zoom slider/reset, layout numeric inputs, aspect reset, merge/split button event wiring을 제거한다.
- `uiPaletteFromControls()`를 제거한다.
- `applyUiPalette()`는 persistent project palette만 읽고 legacy color input으로 역동기화하지 않는다.
- old palette 적용/초기화 button handler를 제거한다.

## 이유
Mantine overlay와 palette editor가 이미 기존 command/model API를 직접 사용한다. 이 시점에서 old controls를 동시에 유지하면 동일 기능에 두 owner가 생기고 markup 삭제도 막는다.

## 기각한 대안
legacy controls를 hidden 상태로 유지하거나 optional DOM bridge를 두는 방식은 최종 단일 UI ownership과 맞지 않아 기각했다.

## Source of truth
- layout: `activeProject.layout` 및 `activeProject.layout.slotStyle`
- zoom runtime: 기존 dashboard zoom runtime state
- palette: `activeProject.appearance.uiPalette`

## EFSM/core 영향
FFPX/FFSX/Plotly, project schema, merge/split 알고리즘은 변경하지 않는다.

## 검증
workflow의 patch check, JS syntax, portable build, split/portable smoke를 통과해야 한다.

## 롤백
patch revert로 old control wiring을 복원 가능하며 persistent migration은 없다.

legacy sidebar/debug/startup wiring과 HTML markup은 다음 단계에서 제거한다.
