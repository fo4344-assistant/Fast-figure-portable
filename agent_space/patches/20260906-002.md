# 20260906-002 — split source portable build 경계

## 목적

`20260906-001`에서 개발 source의 inline JavaScript를 분리하면서 작업 과정의 대형 bundle 오염 문제는 해결했지만, repository root의 `Fast-figure.html` 한 파일만 복사하면 실행되던 기존 portable 배포 계약은 더 이상 성립하지 않는다.

개발 source는 분리 상태로 유지하면서 동일한 JavaScript bytes를 다시 inline한 단일 HTML portable build를 생성할 수 있도록 한다. 동시에 source split 이후 사실과 맞지 않게 된 top-level README와 built-in README를 수정한다.

## 변경 내용

- 앱 버전 `1.1.110-alpha` → `1.1.111-alpha`
- `scripts/build-portable.py` 추가
  - `Fast-figure.html`
  - `fast-figure.js`
  - `vendor/plotly.min.js`
  - `vendor/fast-figure-ui-runtime.js`
  를 읽어 세 external classic script tag를 동일한 script body로 치환한다.
- 기본 출력은 `dist/Fast-figure.html`
- 별도 minify/transpile/bundle dependency를 추가하지 않는다.
- top-level README에서 개발 source와 단일-file portable build를 구분한다.
- built-in README에서도 React/Mantine, Plotly, Iconoir의 개발 source 위치와 portable build 내 embedded 상태를 구분한다.

## 이 방향을 선택한 이유

이번 source split의 목적은 개발 source의 물리적 크기와 patch/search 오염을 줄이는 것이다. 배포 시 single-file portable이라는 기존 장점까지 포기할 이유는 없다.

따라서 source of truth는 split source 하나만 유지하고 portable HTML은 그 source에서 생성되는 산출물로 둔다. application code를 split source와 portable source에 별도로 유지하는 이중 권위 구조는 만들지 않는다.

## 고려했지만 선택하지 않은 방향

### root `Fast-figure.html`을 다시 inline 상태로 유지

개발 과정에서 application JS와 vendor bundle이 다시 하나의 대형 HTML에 들어가므로 `001`의 목적을 잃는다.

### split source와 portable HTML을 둘 다 repository에서 수동 편집

같은 application 의미가 두 source에 중복되어 어느 쪽이 최신인지 판정해야 하므로 AGENT.md의 source-of-truth 원칙과 충돌한다.

### npm/webpack/vite 기반 build

현재 작업은 단순 역-inlining만 필요하다. 별도 dependency/toolchain을 추가하면 portable 프로젝트에 불필요한 복잡도를 만든다.

## 검증

업데이트된 Actions는 다음을 검사한다.

1. `node --check fast-figure.js`
2. `node --check vendor/plotly.min.js`
3. `node --check vendor/fast-figure-ui-runtime.js`
4. `python scripts/build-portable.py --output ...` 성공
5. portable 결과에 세 external local script tag가 남지 않음
6. portable 결과에 application source와 `Plotly.setPlotConfig`가 존재함
7. split development source를 `file://`로 headless Chrome에서 실행
8. generated portable HTML을 `file://`로 headless Chrome에서 실행
9. 두 경우 모두 Plotly, FastFigureUiRuntime, FastFigureReactShell, appFSM이 존재하고 lifecycle이 `ready`
10. `git diff --check`

## 파일 포맷 / EFSM 영향

없음.

- `PACKAGE_FORMAT_VERSION = 3` 유지
- FFPX/FFSX reader/writer 변경 없음
- graph/image/layout/caption/label 의미 변경 없음
- EFSM transition 변경 없음
- script 실행 순서는 `001`에서 유지한 classic script 순서를 그대로 사용

## rollback

이 patch를 역적용하면 build script와 source/portable 구분 문서만 제거되고 `001`의 split source 자체는 유지된다.
