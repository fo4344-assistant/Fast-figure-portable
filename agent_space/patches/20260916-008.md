# 20260916-008 — Remove active Mantine CSV-selection dependence on shared runtime projections

## Purpose
Repair the first CSV-selection ownership boundary identified in `review-011-sot-api-boundary.md` before any more legacy graph UI deletion.

The goal is not to redesign the logic EFSM or project model. The goal is to ensure that the active Mantine graph/data path reads selected CSV state from the existing authoritative selection/project state instead of the legacy shared runtime projections `activeCsvId`, `activeDataName`, `activeDataReady`, `rows`, and `columns`.

## Ownership decision

- Project CSV contents (`name`, `rows`, `headerLines`, id) are owned by the project/domain state.
- Asset-selection transition semantics are owned by the application logic EFSM (`SELECT_ASSET`, `appFSM.state.assetPath`, `assetSelection`).
- A read operation may resolve the selected project asset/CSV from that authoritative state.
- `activeCsvId`, `activeDataName`, `activeDataReady`, `rows`, and `columns` are not accepted as an API-facing source of truth for the active Mantine path.
- Legacy native graph preview/form code may still temporarily contain its own historical UI buffer until that ownership unit is removed, but those values must not be the interface used by Mantine or backend/domain commands.

## Exact changes

### SoT-owned read boundary
Add two read helpers adjacent to the application-state router:

- `selectedProjectAsset()` — resolves `appFSM.state.assetPath` through `projectVfs`.
- `selectedProjectCsv()` — returns the selected asset only when it is a CSV.

These helpers do not store or synchronize a second copy of selection state.

### Stop exposing legacy CSV projections as UI registry state
Remove `activeCsvId` and `activeDataName` from the `projectObjects` `ui` read projection. A shared legacy cache must not be promoted to an API/read-model contract.

### Active project-tree CSV selection
`selectCsvFromTree(path)` keeps:

- graph-object selection clearing;
- `SELECT_ASSET` routing;
- filename/status behavior;
- existing selected-slot messaging.

It no longer writes:

- `activeDataName`;
- `activeDataReady`;
- `rows`;
- `columns`.

### Active Mantine graph/data editor
The active CSV choice is resolved in this order:

1. CSV referenced by the selected graph object;
2. `selectedProjectCsv()` from the authoritative asset-selection state;
3. first project CSV fallback used by the existing editor.

The Mantine editor no longer reads `activeCsvId`.

### Graph editor command helpers
Remove active-path dependence on the shared projection:

- `baseGraphObject()` defaults to `selectedProjectCsv()`;
- `ensureGraphObjects()` uses `selectedProjectCsv()` as its selection fallback;
- `graphEditorSelectCsv()` routes only through `SELECT_ASSET` and does not write `activeCsvId`, `activeDataName`, or `activeDataReady`;
- `graphEditorAdd()` defaults from `selectedProjectCsv()` rather than `activeCsvId`;
- `graphEditorHeaderLines()` no longer synchronizes `rows`/`columns` caches;
- `graphEditorSetEditable()` no longer calls `refreshCsvControls()` solely to update the legacy active-CSV projection.

## Why this direction
`20260916-006` removed native DOM projection from `selectCsvFromTree`, but replaced it with writes to global runtime projections. That removed DOM coupling while preserving a second shared representation of selected-data context.

The corrected direction is to keep the existing logic-EFSM/project SoT and expose a read operation derived from it. No new store, bridge, synchronization loop, or Mantine-specific backend state is introduced.

## Rejected alternatives

- Keep `activeCsvId` as the Mantine-selected CSV because it is non-persistent: rejected. Non-persistence does not make a shared value safe; Mantine and other logic would still depend on a second representation.
- Move the same values into a new React store/context: rejected because it creates another SoT/read model.
- Make `rows`/`columns` part of an API object: rejected because they are derived from project CSV data and would promote a cache to an API contract.
- Remove every historical `activeCsvId`/`rows`/`columns` reference in this patch: rejected because that crosses into loader, workspace activation, native preview, rollback snapshot, image-selection, and legacy graph-form ownership. Those historical cross-references are the next SoT cleanup unit and must be changed coherently rather than by blind string deletion.
- Change logic-EFSM transition semantics: rejected; `SELECT_ASSET` remains the authoritative mutation route.

## SoT status after this patch
This patch removes the active Mantine/project-tree dependency on the shared CSV projections and stops exposing two of those projections through the `ui` registry.

It does **not** claim that the historical runtime projections are fully eliminated. Remaining backend/legacy consumers such as loader/workspace activation, rollback snapshots, `refreshCsvControls`, and native graph preview are follow-up SoT debt and have priority over further legacy markup/CSS deletion.

## Frontend/backend impact
Frontend selection continues to call the existing application router/event. The new read helpers are derived reads over backend/core SoT and do not mutate state.

No frontend component gains direct mutation access to project/domain state in this patch.

## EFSM/core impact
No intended logic-EFSM transition change.

Preserved:

- `SELECT_ASSET`;
- graph-object selection events;
- graph object/project CSV identity;
- chart/project persistence;
- FFPX/FFSX meaning;
- Plotly/rendering algorithms.

## Validation
Repository workflow must pass:

1. `git apply --check` / patch application / `git diff --check`;
2. JavaScript syntax checks;
3. portable build;
4. split and portable Chromium `file://` smoke tests;
5. source inspection confirming `selectCsvFromTree` no longer writes `activeDataName`, `activeDataReady`, `rows`, or `columns`;
6. source inspection confirming active Mantine `FastFigureGraphDataEditor` no longer reads `activeCsvId`;
7. source inspection confirming graph editor active selection/add/header-line paths use authoritative selection/project data rather than shared CSV projections.

## Rollback
Revert `Apply agent patch 20260916-008`.

No data migration is involved.

## Follow-up priority
Before legacy graph UI deletion:

1. eliminate remaining backend/core references to CSV UI/runtime projections (`activeCsvId`, `activeDataName`, `activeDataReady`, `rows`, `columns`) or confine genuine UI buffers to legacy UI ownership;
2. remove projection fields from runtime capture/restore and EFSM actions where they are not SoT state;
3. then audit Mantine graph mutation/read API boundaries;
4. only after those boundaries are correct, resume native graph UI JS/markup/CSS removal.
