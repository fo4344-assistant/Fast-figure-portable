# 20260901-019

## 목적

`20260901-018`에서 분리한 DOM-free asset action model을 비활성 Mantine staging sidebar에 연결한다. custom legacy action menu의 기능 의미를 복제하지 않고 Mantine `Menu`가 동일한 action availability와 기존 domain handler를 사용하도록 준비한다.

## 변경 내용

- 애플리케이션과 built-in README 버전을 `1.1.49-alpha`로 올린다.
- `FastFigureSidebarStaging()`이 `fastFigureUiBridge.readAssetActions()`로 현재 선택 자산의 action model을 읽는다.
- staging sidebar의 Mantine import에 `Button`과 `Menu`를 추가한다.
- Asset 요약 아래에 Mantine `Menu`를 추가한다.
  - 선택 가능한 자산이 없으면 trigger를 비활성화한다.
  - 메뉴 항목은 `assetActions.items`를 그대로 렌더링한다.
  - 기존 schema의 disabled 판정과 disabled title을 그대로 반영한다.
  - 실행은 `fastFigureUiBridge.runAssetAction(item.key, assetActions.context)` 하나만 호출한다.
- action이 없는 경우 비활성 안내 항목을 표시한다.

## 이 방향을 선택한 이유

`018`에서 legacy renderer와 staging renderer가 같은 action model을 사용하도록 만들었으므로, 이번 단계에서는 Mantine가 제공하는 menu open/close, focus, keyboard, portal lifecycle만 사용하면 된다. React 쪽에 별도 menu state나 action registry를 만들 필요가 없다.

이 구조는 Mantine 도입 목적 중 popup lifecycle과 공통 control 규칙의 재사용을 직접 충족한다. 동시에 선택 자산과 action availability의 권위는 기존 EFSM/domain 상태에 유지된다.

## 선택하지 않은 방향

- `Menu`의 open 상태를 React local state로 별도 관리하지 않는다. Mantine의 자체 presentation state를 사용한다.
- action availability를 JSX 조건문으로 다시 구현하지 않는다. `018`의 action model만 사용한다.
- legacy `assetActionMenu`와 global outside-click/Escape handler는 아직 제거하지 않는다. staging shell은 비활성이므로 Commit C 이전에 활성 UI를 둘로 만들지 않는다.
- asset tree 자체의 hierarchy renderer, drag/drop, rename/move/import semantics는 이번 패치에서 변경하지 않는다.
- 전체 shell cutover를 수행하지 않는다.

## 검증 항목

- `git apply --check`
- `git diff --check`
- 메인 JavaScript `node --check`
- APP_BUILD와 built-in README 버전 일치
- staging Menu에서 legacy `assetActions`/`assetActionMenu` DOM ID 미사용
- Mantine Menu lifecycle에 별도 open/close/Escape/outside-click 코드 추가 없음
- action 실행은 `runAssetAction()`을 통해 기존 handler로만 전달
- `assetSelection`/`assetPath` 상태 복제 없음
- staging shell은 계속 mount되지 않아 현재 활성 legacy UI 동작 비변경

## 후속 작업

Asset action menu staging까지 준비되면 Commit B의 큰 잔여 범위는 실제 sidebar form controls와 domain renderer host 연결이다. 다음 패치에서는 sidebar의 project/slot 공통 control부터 기존 DOM read/write 계약을 분리할 대상을 좁혀 진행한다.

## 패치에 포함되지 않은 변경사항

이 `.patch`와 설명 `.md` 자체는 재귀적인 diff에 포함하지 않는다. 실제 HTML 수정은 제한된 patch workflow가 검증 후 적용한다.
