# 20261001-017 — Source Script r8 프로젝트 목적 invariant 명시

## 변경 원인

plan-008 closure 기준의 “프로젝트 목적 부합”을 Source Script만으로 검증할 수 있도록
README에 이미 명시된 Fast Figure의 상위 목적을 system-level invariant로 올린다.

r7까지 domain 알고리즘은 정리되었지만 local/offline single-file 동작과
FFPX copied-asset independence는 README에는 명시되어 있어도 Source Script 최상위 rule에는 없었다.

## 의미 변경

새 제품 요구를 추가하지 않는다.
README의 기존 계약을 Source Script invariant로 명시한다.

- scientific figure draft용 slot-based workspace
- loaded data/image의 browser-local processing
- ordinary core workflow에 server/account/mandatory network dependency 금지
- single-file Fast-figure.html portable runtime
- ProjectObject/FFPX가 complete persistent figure state
- session-only UI/runtime state는 project persistence에서 제외
- FFPX copied asset은 original filesystem path 없이 복원 가능
- Plotly JSON / FFSX / FFPX 책임 경계 유지

portable build에도 core runtime dependency를 artifact 안에 포함해야 한다는 rule을 명시했다.

FFPX/FFSX에는 package asset이 copied bytes이며 원본 filesystem path가 reopen dependency가 될 수 없다는 rule을 추가했다.

## 선택 이유

Source Script가 다음 단계의 권위 원천이라면
프로젝트 목적상 금지되는 mandatory network dependency나 external-path project dependency도
Source Script만 보고 판정 가능해야 한다.

README에만 남겨 두면 pseudocode/source code 단계에서 이를 단순 배포 설명으로 오해할 수 있다.

## 기존 안을 채택하지 않은 기록

### README만 프로젝트 목적 원천으로 두고 Source Script에는 반복하지 않음

채택하지 않았다.

상위 요구의 근거 문서는 README이지만, 구현 단계가 반드시 보존해야 하는 invariant는
Source Script의 system boundary에도 추적 가능하게 있어야 구조적으로 닫힌 명세가 된다.

### 모든 외부 연동 자체를 금지

채택하지 않았다.

README 요구는 ordinary/core use가 local/offline이라는 것이다.
향후 optional integration까지 금지할 근거는 없으므로
optional integration은 허용하되 core open/edit/export를 mandatory network dependency로 바꾸지 않는 범위로 한정한다.

## 닫힘 판정 영향

프로젝트 목적 부합 기준을 Source Script 자체에서 검증할 수 있게 되었다.

r8은 closure review 전까지 current/open으로 유지한다.

## 하위 단계 전파 범위

pseudocode/source code와 portable build는:

- core use의 local/offline 성질
- single-file runtime dependency bundling
- package copied-asset independence

를 보존해야 한다.
