# 변경 목적

- 사용자 요청에 따라 ego-browser로 실제 사용자 경로를 다양하게 확인할 후속 계획을 작성한다.
- `agent_space/plans/plan-034.md`에 80개 독립 워크플로우의 목표, 시작 상태, 짧은 UI 과정, 기대 결과와 추가 변형을 기록한다.

## 적용 방향과 이유

- 각 과정은 준비를 포함한 조작 8회 이내와 통상 30~90초를 목표로 한다. 실패를 보존하고 WF마다 reload·checkpoint 복원으로 분리하여 로그·상태 누적을 제한한다.
- 일반 과정은 디버깅을 끄고, 짧은 디버깅 과정에서만 로그 저장·비우기·끄기 후 reload한다.
- 입력 파일, 실행본, 시작 상태를 담은 파일, 실행 스크립트와 다운로드는 실행별로 분리한다. 준비 프로젝트는 앱 UI로 만들고 API mutation으로 UI 성공을 대신하지 않는다.
- 데이터·그래프·이미지·VFS·배치·라벨·캡션·FFPX/FFSX/Plotly·그림 저장·취소·복구·키보드·split 배포를 포함하며, 도구 제한과 UI에서 관찰할 수 없는 내부 경계는 별도로 기록한다.

## 검토한 다른 방향

- 한 페이지에서 모든 기능을 연속 수행하는 방식은 실패 원인과 로그 누적을 분리하기 어려워 채택하지 않았다.
- 테스트 전용 API·프로젝트 내부 fixture·루트 임시 index·자동 구현 수정은 이번 계획 범위에 넣지 않았다.

## 실제 기록과 범위

- 기준 HEAD는 `9991697cf25c29ceb051c91779dc506331d6a7ba`이며 기존 source code 158 미커밋 수정과 이전 문서를 보존한다.
- 패치는 새 plan과 이 설명 파일에 대한 실제 `git diff --no-index --binary --full-index` 출력이다. patch 자체는 payload에서 제외한다. index를 만들거나 staging하지 않는다.
- 설치된 ego-browser 가이드와 문서·기존 UI 경로를 읽고 WF01~WF80의 번호 중복·누락을 정적으로 확인했다. 앱·브라우저 세션·빌드·테스트·fixture 생성·커밋·푸시는 실행하지 않았다.
- 가이드 복사본과 계획 작성 중의 비교 파일은 패치에 포함하지 않았다.
