# Plan036 — UI 구조 복구와 입력·오브젝트 선택·이름 표시 개선

Plan035의 개정판. 기존 세 수정 목표를 유지하고 WF37의 빈 행 입력 표시, WF16의 순서 변경 후 선택 대상, 그래프 오브젝트 이름에 그래프 제목을 함께 표시하는 수정을 추가한다.

## 1. 수정 목표

1. 같은 역할의 UI 컨트롤이 공통 크기 규칙을 사용하고, 입력 행의 폭·간격·하단 정렬을 일관되게 적용한다.
2. 전역 설정·축·오브젝트 등 기존 접기 계층과 개폐 동작을 복구한다.
3. 실제 작업영역과 레이아웃 미리보기가 기하 계산 및 grid/slot 표현 구현을 공유하도록 통합한다.
4. 행·열 입력을 비운 뒤 편집을 마치면 입력란에 현재 반영된 행·열 수가 표시되도록 한다.
5. 그래프 오브젝트 순서를 바꿀 때 선택했던 오브젝트를 계속 편집할 수 있도록 선택 index를 갱신한다.
6. 그래프 오브젝트의 표시 이름에 기존 열·범례 식별 정보와 해당 그래프 제목을 함께 표시한다.

## 2. 원인 분석

### 2.1 크기·정렬 설정의 분산

**현재 확인한 사실**

- `sourcecode/frontend/mantine_ui.js:62-119`의 `fastFigureTheme`가 Button/Input/ActionIcon의 공통 크기를 정한다. 높이 38px 등의 스타일은 `props.size === "ff"`인 경우에 적용된다.
- 같은 파일의 그래프 오브젝트 행은 Button `xs`, ColorInput `xs`와 폭 72, ActionIcon `sm`을 따로 지정한다(`sourcecode/frontend/mantine_ui.js:1517-1532`). 축 토글에도 `xs`가 지정된다(`sourcecode/frontend/mantine_ui.js:1597`, `sourcecode/frontend/mantine_ui.js:1620`). 기본 크기 입력과 서로 다른 규칙을 사용한다.
- 축 편집 행의 `Group`은 `gap`과 `grow`를 지정하지만 라벨 있는 입력과 단독 버튼의 하단 정렬을 명시하지 않는다(`sourcecode/frontend/mantine_ui.js:1648-1689`). 높이를 맞추는 것만으로 라벨 영역을 포함한 행 정렬이 완성되지 않는다.

**발생 과정과 원인**

1. `172e2cd417f67dd2c51792dc08f8fe9e819b8b11`(2026-09-09 UTC)의 그래프 데이터 UI 이전에서 각 위치의 `xs`, 고정 폭, 개별 행 배치가 추가되었다.
2. `148b306952152963d88f44a46d2c093e0f765409`(2026-09-09 UTC)의 전역·축 편집도 개별 Stack/Group 배치로 구현되었다.

4. `6ea9edd8a2620ee030b627fb7ffb80fc9bd0ab78`(2026-09-28 UTC)에서 legacy CSS를 제거하면서 기존 공통 높이·하단 정렬 규칙을 새 배치 체계에 모두 옮기지 못했다. `90ffa8bec406024d3fe573a72edfa6be5eca5eff`에서는 일부 아이콘 버튼이 `sm`으로 변경되었다.

공통 theme의 추가와 개별 지정의 정리가 함께 끝나지 않았고, 컨트롤 자체의 크기와 행의 정렬 책임을 구분해 감사하지 않았다. `agent_space/patches/20260928-008.md`에도 반복 size/style 감사가 후속 작업으로 남아 있다. 이 혼합 구성은 source code158 수정 이전부터 존재한다.

### 2.2 접기 가능한 UI 계층의 소실

**현재 확인한 사실**

- 원래 참고 화면에는 열린 전역 설정 아래 X축→아래/위, Y축→왼쪽/오른쪽의 중첩 접기가 있었다. 오브젝트 설정과 종류별 세부 설정, UI 색상, 디버그 로그도 접기 단위였다(`agent_space/history/Fast-figure-1.1.35-alpha-reference.html:11287-11528`).
- 현재 네 축의 데이터와 편집 항목은 남아 있다. `sourcecode/frontend/mantine_ui.js:1584-1589`에 네 key가 있고 `sourcecode/frontend/mantine_ui.js:1778`에서 모두 표시한다.
- `axisEditor`는 제목 Text와 입력 Stack을 반환한다(`sourcecode/frontend/mantine_ui.js:1630-1736`). 원래 접기 계층은 이 구성에 연결되어 있지 않다. 오브젝트별 X/Y축 위치 선택은 원래도 존재했던 별도 기능이다.

**발생 과정과 원인**

`148b306952152963d88f44a46d2c093e0f765409`의 전역·축 이전에서 네 축의 입력 기능은 옮겼지만 `details/summary`가 담당하던 그룹 계층·열기/닫기 동작을 평면 Stack으로 바꾸었다. 이후 화면에 입력이 존재하는지를 기능 이전의 기준으로 삼아, 원래 정보 배치와 접기 조작을 같은 기능군의 계약으로 보존하지 못했다.

`agent_space/reviews/review-010-mantine-ui-inventory.md`의 기능 목록과 `agent_space/reviews/review-012-mantine-cutover-completion.md`의 전환 완료 판단만으로 접기·시각 배치 보존을 증명할 수 없다. `agent_space/reviews/review-022-mantine-ui-regression-qa.md`에도 이전 화면 대비 정렬·표현 회귀와 시각 검증의 부족이 기록되어 있다.

### 2.3 레이아웃 미리보기의 별도 구현

**현재 확인한 사실**

- 미리보기는 `FastFigureLayoutOverlay` 안에서 자체 grid와 슬롯 버튼을 만든다(`sourcecode/frontend/mantine_ui.js:2955-3010`).
- `borderRadius: previewGeometry.radius`는 전체 grid 컨테이너에 적용되고 자식 슬롯에는 해당 반경이 없다(`sourcecode/frontend/mantine_ui.js:2978`). 컨테이너의 border와 `overflow: hidden`도 별도로 설정한다.
- 실제 작업영역은 `renderDashboardProjection`에서 dashboard와 slot을 배치한다(`sourcecode/frontend/renderer.js:572-690`). `.dashboard`의 반경은 0이고 `.slot`이 `--slot-radius`를 사용한다(`sourcecode/Fast-figure.html:9388-9420`). 따라서 동일한 radius 값이 서로 다른 대상에 적용된다.
- 미리보기는 공식 `layout.readState(width)`가 반환한 `previewGeometry`를 사용한다(`sourcecode/backend/project_state.js:331-343`). 실제 renderer에는 폭·간격·여백·반경 계산이 별도로 남아 있다(`sourcecode/frontend/renderer.js:106-114`, `sourcecode/frontend/renderer.js:572-587`).

**발생 과정과 원인**

1. `73727212ec70910e3a933a8fbadfebf11a271d9f`(2026-09-10 UTC)에서 미리보기 전용 React grid를 도입했다. `agent_space/patches/20260910-001.md`는 기존 `syncLayoutMapSize()`의 renderer-neutral 추출을 선행하는 방향을 작업 분할 비용 때문에 기각했다고 명시한다.
2. `50a2f0eb0bc91ba8313c478499af9e811cc04ceb`(2026-09-11 UTC)에서 `dashboardGeometry(previewWidth)`의 숫자를 사용하도록 바꾸면서 radius를 미리보기 컨테이너에 넣었다. 실제 슬롯의 표현 구조를 공유하는 작업은 포함되지 않았다.
3. `51ae4e15a1896c5ccc676f7f4d2dac9986f1b90b`(2026-09-22 UTC)에서 공식 layout API로 조회를 옮겼지만 기존 미리보기 DOM·스타일 구조는 유지되었다.

즉, 상태 조회와 일부 기하 계산의 공통화를 화면 표현 구현의 공통화로 간주했다. `agent_space/patches/20260911-012.md`의 기하 일치·기능 완성 판단과 `agent_space/patches/20260922-006.md`의 단일 상태 원천 설명은 두 화면의 구조·스타일 적용 대상까지 같다는 근거가 되지 않는다. 반경 한 줄만 고치면 별도 grid/slot 구현과 이후 회귀 가능성이 남는다.

### 2.4 WF37 — 빈 행 입력과 실제 행 수의 표시 불일치

- 근거: `agent_space/reviews/review-20261117-001-ego-workflows.md`의 WF37.
- 빈 3×3 프로젝트에서 행 입력을 지우고 Tab으로 포커스를 옮겼다. 실제 배치는 3×3·9개 슬롯을 유지했지만 행 입력란은 빈칸으로 남았다.
- 기존 PASS 판정은 프로젝트 배치 보존 범위다. 이번 수정은 편집 종료 후의 입력 표시와 현재 프로젝트 값도 일치시키는 것이다.
- 기존 기록은 원인을 확정하지 않았다. 구현에서는 행·열 입력의 임시 편집값, 빈 값 처리, 포커스 이탈 시 표시 갱신 경로를 확인한다.

### 2.5 WF16 — 순서 변경 후 선택 대상 변경

- 근거: 같은 결과 문서의 WF16.
- G checkpoint의 slot 0에서 첫 오브젝트를 선택하고 범례를 `First`로 지정한 뒤 둘째 행을 첫째 행 위로 드래그했다.
- 순서는 `First, 기본`에서 `기본, First`로 바뀌었지만 선택 index는 0에 남았다. 편집기에는 다른 오브젝트의 빈 범례 이름이 표시됐다.
- 이번 수정의 기준은 선택했던 오브젝트를 순서 변경 뒤에도 유지하는 것이다. 현재 index에서 변경 후 index로의 대응과 Frontend 선택 반영 경로를 확인한다. 기존 기록만으로 Backend의 대응 계산과 Frontend 반영 중 어느 단계가 원인인지 확정하지 않는다.

### 2.6 그래프 오브젝트 이름에 그래프 제목 표시

- 사용자 관찰: 그래프 오브젝트 이름이 `C1`, `C2` 등의 열 식별 정보만으로 표시되어 어느 그래프인지 구별하기 어렵다.
- 표시 이름에 해당 오브젝트가 속한 그래프의 현재 제목을 함께 표시한다. 제목의 기존 공식 조회 경로와 오브젝트 표시 이름을 만드는 위치를 확인하여 연결한다.
- WF16·WF37과 구분되는 표시 개선 요구다. 기존 테스트에서 통과하거나 실패했다고 기록하지 않는다.

## 3. 수정 원칙과 책임

| 책임 | 소유 위치와 처리 방향 |
|---|---|
| 일반 컨트롤 크기·간격·글꼴·반경 | 기존 Mantine theme/default props. 같은 역할의 중복 지정 제거, 필요한 역할 차이는 한 곳에 정의 |
| 입력 행의 폭·정렬·줄바꿈 | Mantine 배치. 라벨 포함 높이와 입력 하단을 기준으로 배치 |
| 접기 계층·열림 상태 | Frontend UI-local 상태. 프로젝트 데이터와 분리하여 기존 화면 계층 복구 |
| 영속 layout/grid/slot 값 | 기존 Backend ProjectObject 및 명령 경계 유지 |
| 폭에 따른 기하 계산 | 기존 Backend 기하 절차를 단일 계산 경로로 사용. Application을 통해 각 화면의 해당 회차 입력·결과 전달 |
| dashboard/grid/slot의 공통 틀·스타일 적용 | Frontend renderer의 공통 표현 절차. 실제 작업영역과 미리보기가 같은 절차·스타일을 사용 |
| Plotly·이미지 decode·실제 content 수명 | 실제 renderer의 기존 소유 유지. 미리보기 슬롯 틀 갱신에서 실행하지 않음 |
| 미리보기 폭·선택 강조 | UI-local 입력·표현. 공통 기하와 슬롯 배치를 유지하면서 표시 |
| 행·열 입력의 편집 중 표시 | Frontend UI-local 값. 편집 종료 시 공식 조회의 현재 행·열 수 표시 |
| 오브젝트 순서와 index 대응 | 기존 Backend 변경 결과. Frontend가 현재 선택에 대응을 적용 |
| 선택 오브젝트 index | 기존 Frontend 상태. 순서 변경 뒤 같은 오브젝트의 새 index 사용 |
| 그래프 오브젝트 표시 이름 | 공식 조회의 현재 그래프 제목과 기존 오브젝트 이름을 표시 단계에서 조합 |

공통화 대상은 실제 중복된 계산·표현·배치다. 범용 UI 프레임워크나 독립 preview 모델을 새로 만들지 않는다. mutation용 draft를 화면들의 공용 읽기 상태로 사용하지 않는다. 조회 결과는 각 호출·표시 범위에서 소비하고 project와 양방향 동기화하지 않는다.

## 4. 수정 순서

### 4.1 Source Script의 UI·표현 계약 보완

- `sourcescript/frontend/mantine_ui.py`에 일반 컨트롤과 행 배치의 책임, 접기 계층, UI-local 열림 상태, 공통 미리보기 틀 사용을 구체적으로 기록한다. 행·열 입력의 편집 종료와 현재 값 표시, 그래프 제목을 포함하는 오브젝트 표시 이름도 담당 절차에 명시한다.
- 오브젝트 이동의 기존 Backend 절차, `sourcescript/application/public_api/graphs.py`의 이동 경계, `sourcescript/frontend/interface_fsm.py`의 선택 반영을 대조한다. 순서 변경 결과의 index 대응으로 같은 오브젝트의 선택을 유지하는 절차를 연결한다.
- `sourcescript/frontend/renderer.py`에서 dashboard/grid/slot 틀의 생성·갱신과 content render/자원 수명을 분리하여 설명한다. 실제 작업영역과 미리보기의 공통 절차 및 허용된 차이를 명시한다.
- `sourcescript/backend/layout_annotations.py`와 `sourcescript/application/public_api/layout_annotations.py`의 기존 기하·조회 절차를 대조하여 각 화면의 폭을 전달하는 경계를 연결한다. 새로운 계산 규칙이 필요한지 확인하고, 기존 규칙을 보존한다.
- `agent_space/policies/examples/source-script_example1.py`의 형식으로 지역값을 선언하고 Args/Return/변경/처리에 실제 원형·현재 원천·입력·출력·알고리즘을 적는다. 정의 설명에 계산이나 새 정의를 숨기지 않는다.
- 논리·목적·비중복 검토를 끝낸 다음 pseudocode, source code 순서로 전파한다. 각 계층 변경에 실제 fingerprint와 derived_from을 기록한다.

### 4.2 공통 크기·정렬을 해당 UI 기능군에서 함께 정리

1. 일반 입력·주요 버튼·행 동작 아이콘을 실제 역할별로 목록화하고 theme의 기존 기본값과 대조한다. 텍스트 크기, renderer 기하, resize handle까지 기계적으로 같은 크기로 바꾸지 않는다.
2. 그래프 데이터/오브젝트/축/레이아웃/라벨/캡션/프린트/자산 행의 중복 `size`·폭·padding·radius를 정리한다. 필요한 compact 역할은 공통 정의와 사용 이유를 남긴다.
3. 라벨 있는 입력과 버튼의 하단을 맞추고, 같은 역할의 입력 폭·행 간격·줄바꿈을 일관되게 적용한다. 특정 줄에 임의 margin을 추가해 보정하는 방식을 피한다.
4. 정리 후 같은 의미의 값이 theme과 개별 inline style에 함께 남아 있는지 확인한다.

### 4.3 기존 접기 계층 복구

1. 참고 화면의 전체 `details/summary` 목록과 현 화면을 대응시킨다. 전역/오브젝트/종류별 세부 설정/UI 색상/디버그까지 누락 여부를 확인한다.
2. Mantine의 기존 접기 component로 전역 설정→X축→아래/위, 전역 설정→Y축→왼쪽/오른쪽 계층을 복구한다. 전역·오브젝트 초기 열림, 세부 축 초기 닫힘 등 참고 화면의 초기 상태를 보존한다.
3. 오브젝트의 X/Y축 위치 선택은 해당 오브젝트 설정 안에 유지한다. 접기 조작은 축 설정값과 선택 오브젝트를 변경하지 않는다.
4. 같은 화면의 재렌더에서 사용자의 열림 상태를 유지하고, 키보드 조작·포커스·aria-expanded를 연결한다. 영속 설정이나 패키지 필드를 추가하지 않는다.

### 4.4 실제 작업영역·미리보기의 공통 틀로 통합

1. 실제 renderer의 dashboard/grid/slot 생성·배치·스타일 적용 중 content와 자원 수명에 의존하지 않는 부분을 공통 절차로 추출한다. 실제 작업영역도 그 절차를 사용하도록 같은 변경에서 연결한다.
2. Mantine overlay는 미리보기 host와 설정 입력을 소유한다. 미리보기 host 내부의 grid/slot 틀은 실제 작업영역과 같은 표현 절차로 생성·갱신한다. 기존 overlay의 독립 grid/slot 스타일 구현을 제거한다.
3. 양쪽 화면의 실제 폭을 명시적으로 전달하여 기존 Backend 기하 계산 결과를 사용한다. renderer의 중복 수식을 정리하고 Application 경계를 통해 해당 표시의 입력을 전달한다. Frontend renderer에서 Backend 현재 상태를 직접 읽지 않는다.
4. radius는 각 슬롯에 적용하고 dashboard 외곽은 기존 의미를 유지한다. 행·열·span·숨은 슬롯·gap·outerMargin·border와 box-sizing도 공통 절차에서 처리한다. 미리보기 장식용 테두리가 기하 면적을 바꾸지 않도록 별도 표시한다.
5. 미리보기 선택·좌표 표시는 공통 틀 위의 입력/강조로 처리한다. 선택 색·focus·외곽선 변경이 셀 크기와 배치를 바꾸지 않도록 한다. 숨은 슬롯 제외, merge/split, 배경 클릭·닫기·grid 변경 시 선택 정리 규칙을 보존한다.
6. 미리보기의 재표시에서 실제 Plotly host, 이미지 decode, graph/image resource registry, dashboard generation을 생성·폐기하지 않는다. 기존 실제 content renderer와 label/caption·출력 경로에 미치는 영향을 확인한다.

이 단계에서 숫자 전달만 공통화하고 별도 React grid를 유지하는 상태를 완료로 기록하지 않는다. 공통 틀을 추출한 뒤 양쪽 연결을 별도 준비 패치로 장기간 분리하지 않는다.

### 4.5 빈 행·열 입력의 편집 종료 처리

1. 행·열 입력의 현재 처리와 UI component의 임시 편집값을 확인한다. 입력 도중 숫자를 지우고 새 숫자를 입력할 수 있는 동작을 유지한다.
2. 빈 값으로 편집을 종료하면 공식 `layout.readState`에서 그 시점의 행·열 수를 읽어 입력란에 표시한다. 행·열 수를 변경하는 명령을 추가로 보내지 않는다.
3. 유효한 숫자 입력의 기존 변경 경로를 유지한다. 반대쪽 차원도 명령 직전의 현재 조회값을 사용한다.
4. 행과 열 양쪽에서 값 지우기→Tab 또는 다른 컨트롤 클릭을 확인한다. 편집 종료 후 입력 표시와 현재 배치가 일치해야 한다.

### 4.6 순서 변경 후 같은 오브젝트 선택 유지

1. WF16의 `First` 재현 절차를 기준으로 이동 전 선택 index, 이동 순서, 변경 결과의 index 대응, 최종 선택 index를 대조한다.
2. 기존 이동 절차가 반환하는 index 대응을 현재 선택에 적용한다. 선택한 오브젝트가 이동하는 경우와 다른 오브젝트의 이동으로 선택 index가 밀리는 경우를 함께 처리한다.
3. Backend는 순서 변경과 대응 계산을 소유하고 Frontend는 선택 index를 소유한다. Application은 실제 반영 결과를 기존 선택 조정 경계로 전달한다. 대응 계산을 UI에 중복 구현하거나 선택 보존용 오브젝트 사본을 공용 상태로 두지 않는다.
4. 미반영·실패·동일 위치 이동은 기존 순서와 선택을 보존한다. 선택 없음도 유지한다. 순서 변경으로 오브젝트의 CSV 참조·내용·범례를 변경하지 않는다.
5. 이동 뒤에도 선택했던 오브젝트의 이름과 값이 편집기에 표시되는지 확인하고, 후속 편집이 그 오브젝트에만 반영되는지 확인한다.

### 4.7 그래프 제목을 포함하는 오브젝트 이름

1. 그래프 오브젝트 이름을 표시하는 목록·선택 항목과 그 이름을 구성하는 현재 절차를 확인한다. 해당 오브젝트가 속한 그래프의 제목을 기존 공식 조회 결과에서 얻는다.
2. 기존 열·범례 식별 정보를 유지하면서 그래프 제목을 함께 표시한다. 예를 들어 제목이 `측정 결과`이고 기존 표시가 `C2`이면 `측정 결과 — C2`처럼 두 정보를 읽을 수 있게 한다.
3. 제목이 비어 있으면 기존 식별 정보를 표시한다. CSV 파일명이나 다른 그래프의 제목을 해당 그래프 제목으로 대신 사용하지 않는다. 긴 제목도 기존 식별 정보를 확인할 수 있도록 배치한다.
4. 제목 변경·오브젝트 추가·이동·프로젝트 불러오기 뒤 현재 제목이 반영되도록 한다. 표시 문자열은 현재 조회 결과로 구성하고 별도 영속 필드나 동기화 상태를 추가하지 않는다.
5. 이 수정으로 Plotly trace 범례, 그래프 제목 자체, 열 id, 저장 형식 또는 오브젝트 선택에 쓰는 식별값을 변경하지 않는다.

## 5. 검증과 완료 증거

| 대상 | 확인할 증거 |
|---|---|
| 크기·정렬 | 같은 역할의 Button/Input/Select/ColorInput/ActionIcon 실제 높이·padding·라벨 하단·입력 폭 측정. 긴 한국어 라벨, 비활성 상태, 좁고 넓은 사이드바에서 행 배치 확인 |
| 접기 | 참고 화면과 계층 대조, 각 그룹 독립 개폐, 키보드/aria, 재렌더 중 상태 유지. 네 축에 서로 다른 값을 입력하고 다른 축·오브젝트 값 보존 확인 |
| radius | 0과 양수에서 실제 슬롯·미리보기 슬롯의 반경과 dashboard 외곽을 각각 확인. 같은 폭에서 직접 비교하고 다른 폭에서는 기존 scale 규칙 적용 확인 |
| 기하 | 1×1/다행다열, 병합·분할·숨은 셀, margin/gap/aspect/referenceWidth/border 조합의 slot bounding box 비교. 컨테이너 장식·선택 강조에 따른 배치 변화 확인 |
| 상태·수명 | 미리보기 폭 변경·선택·접기가 project/zoom/slot content를 변경하지 않는지, 실제 graph/image가 재생성·폐기되지 않는지 확인 |
| 데이터·출력 | 기존 graph/image/label/caption, FFPX·FFSX 저장 내용, 정상 화면과 출력 경로에 영향이 있는 부분을 구분하여 확인 |
| 구현 비중복 | 공통 기하 절차와 공통 grid/slot 표현의 실제 호출부 확인. 제거한 중복 수식·DOM 생성·스타일 목록 기록 |
| WF37 입력 표시 | 3×3에서 행·열 각각 지우기→blur 후 입력값 3 복원, 배치·슬롯 수 유지. 유효한 새 숫자 입력 및 반대 차원 보존 확인 |
| WF16 선택 유지 | `First, 기본`→`기본, First` 뒤 `First`의 새 index 1 선택과 편집 값 유지. 이동 방향·선택 위치를 바꿔 확인하고 후속 편집 대상·CSV 참조 보존 확인 |
| 그래프 오브젝트 이름 | 같은 `C2`를 쓰는 서로 다른 제목의 그래프를 구별하고 제목 변경·불러오기 뒤 표시 갱신 확인. 빈 제목·긴 제목, 기존 식별 정보와 실제 범례·저장 내용 보존 확인 |

- 같은 입력의 논리 일치, 사용자 목적 달성, 상태·계산·표현의 비중복을 각각 증거로 남긴다. 화면 스크린샷 하나나 roundtrip 성공으로 대체하지 않는다.
- UI 검증은 정상 `dist/` 배포본에서 짧은 ego-browser workflow로 수행한다. 입력·로그는 `.work/`에 보관하고 debug는 필요한 짧은 구간에만 켠다. API 호출을 UI 조작 성공으로 기록하지 않는다.
- 변경 파일의 실제 diff와 계층 lineage를 확인하고, 정적 대조 결과와 실제 UI 검증 결과를 구분하여 기록한다.

## 6. 선택하지 않은 방향과 중단 조건

- 공통 theme만 추가하고 명시적 `xs`/`sm`·개별 정렬을 남기는 방향: 기존 우회 경로가 유지된다.
- 네 축 key를 추가하거나 오브젝트 축 위치 선택을 제거하는 방향: 확인된 접기·배치 회귀를 해결하지 못하고 기존 기능을 바꾼다.
- 미리보기 radius만 자식으로 옮기는 방향: 즉시 증상은 줄지만 독립 grid/slot 구현이 남는다.
- 전체 실제 renderer를 미리보기에 그대로 호출하는 방향: 실제 graph/image 수명과 선택·session 효과를 잘못 공유할 수 있다.
- 독립 preview model이나 공용 draft를 만들어 두 화면을 동기화하는 방향: 원천과 파생값의 소유가 중복된다.
- legacy DOM·숨은 입력·bridge를 복구하는 방향: 기존 Mantine/renderer 경계를 우회한다.

구현 중 기존 Source Script로 결정할 수 없는 의미 차이, 기존 기하 계산 간의 서로 다른 규칙, UI-local 상태의 소유 충돌이 확인되면 해당 절차·입력·차이와 필요한 결정을 기록하고 그 항목의 변경을 보류한다. 하위 구현에서 새 의미를 정하지 않는다.
