# Plan046 — 필요한 화면만 다시 읽고 Plan045의 누락 보완

근거: [Plan045 준수 검토](../reviews/review-20261118-013-plan045-policy-compliance.md).

## 1. 화면 갱신과 명령 처리

- Frontend 상태에서 `revision`과 이를 비교하는 절차를 제거한다. 화면은 자신이 표시하는 값에 영향을 주는 변경 알림을 받았을 때 기존 목적별 API를 호출한다. 최초 표시와 조회 대상 변경 시에도 해당 API로 읽는다.
- Frontend 소유 필드 변경은 Frontend가 알린다. Backend 명령이 반영되면 Application이 실제 변경 결과와 참조 보정 결과를 사용해 영향을 받는 화면에 알린다. 선택 슬롯 변경, 공유 CSV 변경, 프로젝트 교체처럼 여러 화면에 영향이 있는 경로와 알림 대상을 함께 정의한다. 기존 API의 조회 결과와 명령 경계를 유지한다.
- CSV 선택은 기존 경로·종류 확인을 거쳐 선택을 적용하고 화면에 쓸 현재 CSV 정보를 조회한다. 번호 비교와 수락 여부를 확인하는 절차를 제거한다.
- 확대·축소 및 초기화 API가 지정한 확대율을 반영하고 기존 CSS 변환을 실행한다. 확대율 변경 API를 호출하지 않는 작업은 현재 확대율과 표시에 손대지 않는다.

### 선택 이유와 대안

목적별 API를 호출하기 전에 변경의 관련성을 판단하면 무관한 화면의 조회 비용을 줄일 수 있다. 전체 알림 후 각 화면이 조회 결과를 비교하는 방식은 화면 갱신을 생략해도 조회를 수행하므로 채택하지 않는다. 화면마다 변경 번호를 두는 방식은 변경과 소비자의 연결을 정해야 하는 일은 그대로이고 번호 관리만 추가한다. 실제 변경과 영향을 받는 표시를 연결하고, 공유 CSV와 프로젝트 교체의 영향 범위를 확인한다.

## 2. 읽기와 반환 계약 보완

- 공통 입력의 `commit`, `send`, `step`, 그래프 제어 조회, 레이아웃 제어 조회와 grid·merge·split 처리에서 공식 조회와 호출 결과를 반환값에 명시적으로 연결한다. 기존 취소·거부·예외 경로를 보존한다. `readCurrent`의 필드와 동반 값은 실제 기능별 정의를 가리킨다. 신규 조회는 필요한 입력, 대상 부재 시 결과, 반환 필드를 읽는 사람이 따라갈 수 있게 정리한다.
- CSV 미리보기는 펼쳤을 때만 열과 최대 30행을 읽는다. 객체 편집용 열과 미리보기용 열은 조회 입력과 결과가 같을 때 한 표시 작업에서 함께 사용한다. CSV 헤더와 변환 데이터가 다른 경우는 각각 올바른 열을 사용한다.

## 3. 반영 순서와 확인

1. Source Script 예시 양식으로 위 계약을 수정한다. 관련 호출부 전체를 연결해 반환값, 명령 경계, 화면별 알림과 조회, 공유 참조, 실패 시 유지 조건을 확인한다. 논리적 완결성·목적·중복 검토를 기록한 뒤 닫힘을 판정한다.
2. 닫힘을 확인한 범위만 pseudocode로 옮기고, 그 대조를 마친 뒤 source code에 반영한다. 각 변경의 실제 Git patch와 설명에 선택 이유, 검토한 대안과 기각 이유, 확인 범위를 적는다. 기존 기록의 보완 설명은 후속 문서에 남긴다.
3. 정적으로 각 알림의 발행 지점부터 API 소비자까지 추적하고, 변경된 계층의 버전·파생 관계를 기준 커밋과 대조한다. 닫힘 조건을 충족하지 못하면 막힌 근거를 기록하고 해당 하위 번역을 보류한다.
4. 실행 확인에서는 무관한 편집 시 트리·미리보기 조회가 없는지, 공유 CSV 변경과 프로젝트 교체가 관련 화면에 반영되는지, 재선택과 확대율 변경이 제 기능을 하는지 확인한다. 닫힌 미리보기의 조회 0회, 동일 입력의 열 조회 1회, 펼친 미리보기의 최대 30행을 확인한다. 실제 호출 수와 소요 시간은 정적 판정과 구분해 기록한다.
