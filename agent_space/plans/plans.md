# plans

구현 또는 수정에 들어가기 전에 작업 계획을 기록하는 경로입니다.

여기에는 확인된 문제, 작업 목표, 적용 순서, 의존 관계, 영향 범위, 검증 기준, 중단 조건과 후속 작업을 정리합니다.

역할은 다음과 같이 구분합니다.

- `memo`: 아직 확정되지 않은 아이디어, 가설, 검토 후보
- `plans`: 실제 적용을 전제로 정리한 작업 계획과 실행 순서
- `docs`: 적용 후에도 장기 기준으로 유지할 확정 설계와 규격
- `patches`: 실제 변경 diff와 그 변경에 대한 설명
- `tests`: 계획 또는 패치에 대한 검증 절차와 결과

계획 문서는 `plan-NNN.md` 형식으로 이름을 정합니다. `NNN`은 전체 계획 문서의 3자리 순번이며 `plan-001.md`, `plan-002.md`처럼 증가시킵니다. 계획 파일 이름에는 날짜나 계획 내용을 넣지 않고, 계획의 내용과 작성·수정 시점은 문서 본문과 Git 이력에서 확인합니다.

계획이 변경되면 기존 내용을 덮어써서 맥락을 없애기보다, 필요한 경우 새 계획 문서를 만들어 변경 이유와 이전 계획과의 관계를 남깁니다.
