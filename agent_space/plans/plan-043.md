# Plan043 — 선택 슬롯 자동 갱신과 버튼을 통한 전체 렌더링 분리

## 1. 목표

1. 일반 렌더링 요청은 요청을 처리할 때 확정된 현재 선택 슬롯 하나에 적용한다. 선택 슬롯이 없으면 슬롯 콘텐츠를 렌더링하지 않는다.
2. 작업영역 전체의 콘텐츠 재렌더링은 사용자가 도구 모음의 `렌더링` 버튼을 클릭했을 때 실행한다. 버튼은 `프린트` 바로 왼쪽에 배치하고 기존 공통 Button·UiCommand·테마 규격을 사용한다.
3. 프로젝트 변경·참조 보정·Sidebar 읽기는 기존 소유자와 API를 유지한다. 렌더링 범위 변경을 이유로 명령의 반영을 지연하거나 다른 슬롯의 데이터를 선택 슬롯에 합치지 않는다.

기존 `plan-042.md`와 `review-20261118-006-workspace-rendering-scope.md`는 보존한다. 이 계획은 위 검토의 현재 호출 경로를 기반으로 한 후속 변경안이다.

## 2. 가능 여부와 변경이 필요한 이유

**가능하다.** 현재도 그래프별 plot host와 slot/chart 연결, 작업 대기열을 분리해 소유한다. 이 자원을 재사용하면서 요청 대상과 조회 범위를 슬롯 하나로 제한할 수 있다.

다만 전체 표시 함수에 선택 id 필터만 추가해서는 목표를 충족하지 못한다.

## 3. 갱신 범위의 계약

### 3.1 자동 요청

- 명령 반영·참조 보정이 끝난 시점의 Frontend `selectedSlotId`를 읽는다. `0`도 유효한 대상이다.
- 같은 프로젝트의 현재 Backend 상태에서 대상이 visible slot인지 검증하고 그 슬롯의 표시 입력을 구성한다. 전달 인자는 대상 식별자와 필요한 너비 등이며, UI가 보관한 프로젝트 사본을 읽기 원본으로 사용하지 않는다.
- 선택 슬롯의 graph·image·empty 전환, figure·이미지·slot caption·label·선택 장식과 해당 host resize를 처리한다.
- 다른 슬롯의 `Plotly.react`, `Plotly.Plots.resize`, 이미지 재decode, content 교체를 예약하지 않는다. 대상이 없거나 사라졌으면 전체 갱신으로 전환하지 않는다.
- 경로·이름만 바뀌어 표시 갱신이 필요 없는 기존 `NONE` 조건은 유지한다.
- 선택 해제는 이전 선택 장식과 입력 가능 상태를 정리한다. 해제 직전 슬롯을 자동 렌더링 대상으로 다시 사용하지 않는다.
- 선택이 A에서 B로 바뀌면 A의 강조·포인터/포커스 제어를 DOM 장식·입력 처리에서 정리하고 B만 렌더링한다. A의 Plotly 설정 변경을 위해 A까지 다시 그리는 경로를 남기지 않는다. 이전 graph의 명령 콜백도 현재 선택과 slot/chart 연결을 검증한다.

### 3.2 전체 렌더링 버튼

- `렌더링` 클릭은 현재 Backend 상태를 한 번의 일관된 전체 표시 조회로 읽고 모든 visible slot을 갱신한다. 기존 전체 renderer의 자원 재사용·정리 절차를 이 경로에서 사용한다.
- 선택이 없어도 프로젝트와 lifecycle이 유효하면 실행할 수 있다. 버튼은 프로젝트 값을 변경하지 않는다.
- 기존 공통 UiCommand의 준비 상태 확인·실행 중 중복 클릭 방지·완료/실패 정리를 사용한다. 원래 예외와 취소 의미를 유지한다.
- 전체 갱신의 명시적 공개 진입점 하나를 기존 공개 API 계약에 정의한다. UI는 그 API를 호출하고 renderer나 Backend를 직접 호출하지 않는다.
- 일반 명령, 선택, 알림, ResizeObserver, 창 resize, startup에서 이 전체 진입점을 자동 호출하지 않는다. host 불일치도 전체 렌더링의 대체 호출 사유로 사용하지 않는다.

### 3.3 전역 설정·배치·초기 표시

전체 갱신을 버튼으로 제한하면 선택하지 않은 슬롯은 마지막 표시를 유지한다. 이를 다음과 같이 명시한다.

| 변경 | 자동 표시 | 전체 버튼 이후 |
|---|---|---|
| 선택 슬롯의 graph/object/CSV 또는 이미지 변경 | 선택 슬롯만 현재 값으로 갱신 | 모든 슬롯이 현재 값을 표시 |
| 다른 슬롯도 사용하는 CSV·전역 label/caption/palette 변경 | 선택 슬롯의 종속 표시만 갱신 | 영향을 받는 다른 슬롯도 현재 값을 표시 |
| 행·열·병합/분할·기준 폭·gap·margin·배율 등 공통 배치 변경 | 프로젝트·설정 UI·미리보기는 현재 값을 표시. 작업영역 전체 틀의 재배치는 버튼까지 보류 | 현재 공통 틀과 전체 콘텐츠에 함께 적용 |
| 프로젝트 열기/교체 | 이전 프로젝트의 선택·무효 host·작업·자원을 정리. 새 전체 콘텐츠를 자동으로 그리지 않음 | 새 프로젝트의 배치와 콘텐츠 표시 |
| 최초 시작 | controller와 선택에 필요한 빈 틀 등 최소 UI 준비. Plotly 전체 렌더링 없음 | 첫 전체 콘텐츠 표시 |

- 선택 슬롯만 갱신할 때 공통 grid의 너비·행열·CSS 변수·전역 caption 영역을 함께 변경해 다른 슬롯까지 움직이는 부작용을 방지한다.
- 현재 표시된 공통 배치에서 대상 슬롯을 안전하게 갱신할 수 없는 경우에는 자동 전체 fallback 없이 `전체 렌더링 필요`를 안내한다. 이를 판단할 배치·host 조건과 반환 결과는 Source Script에서 구체적으로 정의한다. 표시된 DOM과 renderer 자원 연결만 검사하며 별도 프로젝트 읽기 캐시를 만들지 않는다.
- 작업영역 내부의 프로젝트 palette 적용도 전체 CSS 변수 변경이 다른 슬롯의 외곽선·장식을 바꾸는 경로를 점검한다. 선택 슬롯 자동 표시에는 대상 host 범위의 스타일을 사용하고 공통 작업영역 스타일은 전체 버튼에서 적용한다. 도구 모음·Sidebar의 현재 설정 표시는 기존 UI 경로를 유지한다.
- 무효 참조·제거 슬롯의 작업 취소와 자원 해제는 즉시 수행한다. 제거된 chart를 되살리거나 다른 프로젝트의 host를 새 프로젝트 입력에 연결하지 않는다. 이 정리는 다른 슬롯의 새 콘텐츠 렌더링을 예약하지 않는다.
- 전역 설정 반영 대기를 위해 별도 영속 dirty 목록·프로젝트 사본·동기화 모델을 추가하지 않는다. 전체 버튼은 언제나 현재 원본을 다시 읽는다.

## 4. 소유와 실행 경계

| 책임 | 소유자와 처리 |
|---|---|
| 프로젝트 값·CSV·chart·이미지·기하 계산 | 기존 Backend. 선택 조회는 대상 슬롯과 실제 종속 데이터만 계산하고 전체 조회는 현재 전체를 계산한다. |
| 현재 선택·lifecycle | 기존 Frontend FSM. 자동 요청의 대상은 처리 시점의 확정된 선택에서 얻는다. |
| 명령 뒤 조회 범위·버튼 요청 연결 | Application. 기존 command→reconcile 순서를 유지하고 이후 선택 조회 또는 명시적 전체 조회를 구분한다. |
| 슬롯 content·Plotly·이미지·비동기 작업 | renderer의 슬롯별 자원. 공통 틀과 출력 소유는 기존 경계를 유지한다. |
| 버튼 UI·실행 상태 | 기존 공통 Button과 UiCommand. 새로운 명령 등록부나 상태 복제본을 만들지 않는다. |

### 4.1 선택 조회와 전체 조회

- 기존 renderer 조회에 선택 슬롯 범위를 명시하는 입력·반환 계약을 추가한다. 선택 조회 결과에는 대상 id, 해당 chart/image 연결, figure 또는 이미지 입력, 필요한 label/caption·기하 정보만 포함한다.
- 전체 작업영역 조회 후 Frontend에서 배열을 자르는 방식은 사용하지 않는다. Backend에서 대상 검증 후 해당 figure만 만든다. label 순번처럼 전체 배치에 의존하는 값은 기존 Backend 계산을 사용하되 다른 슬롯의 figure를 생성하지 않는다.
- 자동 렌더링에는 명령 뒤 참조 보정을 마친 대상과 그 조회 결과를 함께 전달한다. 비동기 완료 시 선택·프로젝트·host가 바뀌면 다른 슬롯으로 결과를 옮기지 않는다.
- 전체 버튼의 조회와 표시는 한 작업의 입력으로 연결한다. 기존 mutation result와 projection의 반환·실패 계약도 새 범위를 명시하도록 함께 수정한다.

### 4.2 슬롯별 수명과 동시 작업

- 현재 전역 dashboard generation 검사를 그대로 사용하면 A 갱신이 B의 대기 작업을 무효화할 수 있다. 선택 갱신은 대상 슬롯의 작업 식별·host/chart/image 검증으로 관리한다.
- 프로젝트 교체·전체 재구성은 해당 전체 작업의 이전 자원을 무효화하고, 개별 슬롯 갱신은 다른 슬롯의 유효한 작업을 취소하거나 다시 예약하지 않는다.
- 같은 host의 Plotly 작업 직렬 연결, 새 작업 이후 오래된 완료 무시, 이미지 decode/URL 해제를 보존한다. 실패한 선택 갱신 때문에 다른 슬롯의 정상 content를 purge하지 않는다.
- 전체 버튼이 시작한 다른 슬롯의 비동기 작업이 진행 중일 수 있다. 후속 선택 갱신은 대상 슬롯의 이전 작업만 대체하며 다른 슬롯의 작업을 자동 요청으로 중복 예약하지 않는다.
- 선택 전환·참조 제거·전체 재구성·부분 실패 각각의 자원 정리 순서를 Source Script와 pseudocode에서 대응시킨다.

### 4.3 출력과 미리보기

- 프린트/이미지 출력은 기존 출력 작업 소유의 host와 현재 프로젝트 조회를 사용한다. 출력용 `Plotly.newPlot`과 live 작업영역 전체 갱신을 구분한다. 프린트 실행이 live 전체 렌더링 버튼을 대신 호출하지 않도록 한다.
- 작업영역 현재 캡처와 전체 프로젝트 출력이 서로 다른 입력을 사용하는 기존 의미를 확인하여 보존한다. 화면에 보류 중인 설정과 출력 입력의 차이도 확인 시나리오에 포함한다.
- 레이아웃 미리보기는 자신의 host에서 공통 frame을 사용하며 Plotly를 실행하지 않는다. 미리보기 갱신을 작업영역 전체 렌더링 요청에 연결하지 않는다.

## 5. 버튼 규격

- 위치: 기존 `selectedTargetText` 다음, `프린트` 바로 왼쪽. 텍스트와 접근성 이름은 `렌더링`이다.
- 기존 공통 Button·테마·크기·모서리·글꼴·가로 padding·도구 모음 gap을 재사용한다. 전용 높이·폭·작은 size·별도 CSS 버튼을 만들지 않는다.
- overlay 토글 버튼의 상태와 전체 렌더링 실행 상태를 구분한다. 렌더링 버튼에 존재하지 않는 overlay의 `aria-expanded`를 부여하지 않는다.
- 클릭·키보드 활성화는 같은 UiCommand 경로를 사용한다. 실행 중 중복 전송을 막고 완료·실패 후 다시 실행할 수 있게 한다.
- 좁은 창에서 프린트와의 순서·포커스 이동·버튼 규격이 유지되는지 확인한다.

## 6. 수정 순서와 대상 모듈

### R01 — Source Script

1. `sourcescript/backend/project_state.py`: 선택 슬롯 renderer 조회의 대상 검증·반환 필드·기하·종속 계산과 전체 조회를 구분한다.
2. `sourcescript/application/adapter.py`: 명령 뒤 참조 보정, 선택 갱신 요청, 명시적 전체 요청, startup/resize callback을 분리한다. 자동 전체 projection 조회를 제거한다.
3. `sourcescript/application/public_api/__init__.py`와 관련 공개 wrapper: 전체 렌더링 진입점, 선택·graph·asset·layout·label·caption·appearance·zoom의 갱신 범위를 연결한다. 자동 전체 fallback을 제거한다.
4. `sourcescript/frontend/renderer.py`: 선택 슬롯 표시, 전체 표시, 장식/입력 제어, 공통 배치 보류, 슬롯별 작업 수명, resize와 자원 해제를 정의한다.
5. `sourcescript/frontend/mantine_ui.py`: 기존 도구 모음 규격의 렌더링 버튼을 공통 UiCommand에 연결한다.
6. `sourcescript/system.py`: 초기 controller·빈 틀 준비와 전체 콘텐츠 표시를 분리한다. 최초 시작의 자동 전체 콘텐츠 렌더링을 제거한다.

Args·Return·변경·처리는 저장된 Source Script 예시에 맞춘다. 판단·분기·호출 순서는 책임 절차에 적고 변수 정의에 알고리즘을 숨기지 않는다.

### R02 — pseudocode

- Source Script 변경 patch를 기준으로 위 모듈의 인자·반환·대상 없음·배치 불일치·실패·선택 변경·수명 분기를 번역한다.
- 자동 경로에서 전체 조회/전체 표시로 이어지는 호출과 fallback이 남지 않았는지 확인한다.
- 초기 표시·슬롯 선택·비동기 완료·전체 버튼의 경계를 명시하고 같은 프로젝트/slot/chart/host 검증을 보존한다.

### R03 — source code

- 갱신된 pseudocode patch에서 실제 수정 함수와 직접 호출자를 먼저 찾는다.
- `backend/project_state.js`, `application/adapter.js`, `application/public_api/*`, `frontend/renderer.js`, `frontend/mantine_ui.js`, `system.js`에 대응시킨다. 외부 입력·명령·내보내기 형식과 Backend 검증은 유지한다.
- `renderDashboardProjection` 호출, `presentSuppliedGraph`, `Plotly.react`, `Plotly.Plots.resize`, 이미지 decode, caption/label 동기화, observer, resize 예약을 각각 추적한다. 자동 호출에 전체 순회가 남지 않도록 한다.
- 기존 공통 frame·자원 helper를 재사용한다. 선택 renderer와 전체 renderer에 같은 graph/image 렌더링 알고리즘을 복제하지 않는다.

### R04 — 대응 검토와 기록

- 전체 호출자와 fallback을 검사하고 Source Script→pseudocode→source code의 대상·조회 범위·자원 수명을 대조한다.
- 실제 변경에 맞는 계층 fingerprint·파생 관계·native Git patch와 새 후속 review를 기록한다. 기존 계획과 검토는 보존한다.
- 현재의 정적 가능성 판단, 변경 후 정적 확인, 실제 브라우저 호출 계측을 구분한다.

## 7. 실제 확인과 완료 조건

실행 시 디버그를 켜고 짧은 독립 시나리오별로 로그를 저장한 뒤 비운다. 정상 프로젝트 `dist` 빌드를 사용하고 입력·로그·이미지는 `.work`에 둔다. 현재 계획 작성에서는 테스트를 실행하지 않는다.

기존 로그만으로는 실제 render·Plotly 호출 횟수를 판정할 수 없다. 확인 단계에서는 요청의 원인·범위·대상 slot/chart, 실제 Plotly/resize/decode의 시작·완료·취소를 관측할 수 있게 한다. 계측을 위해 프로젝트 상태나 figure 읽기 캐시를 추가하지 않는다.

| 구분 | 조작 | 기대 결과 |
|---|---|---|
| V01 | 그래프 A/B/C를 전체 버튼으로 표시한 뒤 A를 선택하고 object 변경 | A 표시만 현재 값으로 변경. B/C의 Plotly·resize·decode 신규 호출 0회 |
| V02 | A→B 선택, 포인터 이동, 선택 해제 | 이전 강조와 입력 가능 상태 정리. 새 선택 B만 갱신. 해제 시 전체 또는 직전 슬롯 렌더링 없음 |
| V03 | 선택 없이 데이터·전역 설정 변경 | 명령·설정 UI는 현재 값. 슬롯 콘텐츠 렌더링 없음 |
| V04 | A 선택 후 A/B 공용 CSV의 header 또는 전역 palette/label/caption 변경 | A만 현재 표시. B는 전체 버튼까지 마지막 표시 유지 |
| V05 | 프린트 왼쪽 렌더링 버튼 클릭 | 현재 전체 조회 한 작업으로 모든 visible slot 표시. 버튼 규격·순서·키보드 조작 유지 |
| V06 | 연속 클릭·실패·실행 중 선택 변경 | 중복 실행 방지, 원래 오류 전달, 재실행 가능. 늦은 결과가 다른 슬롯을 덮지 않음 |
| V07 | 행열·병합/분할·기준 폭·gap·zoom 변경 | 자동 전체 재배치 없음. 안전한 선택 표시가 불가능하면 전체 필요 안내. 버튼 뒤 현재 배치 적용 |
| V08 | startup·프로젝트 교체·참조 삭제 | 자동 전체 콘텐츠 렌더링 없음. 이전 프로젝트/제거 자원 정리, 잘못된 참조 부활 없음 |
| V09 | 창 크기·Sidebar 폭 변경·ResizeObserver 반복 | 전체 refresh/resize 없음. 선택 슬롯에 필요한 동작만 수행하고 observer 순환 없음 |
| V10 | A/B 비동기 작업 중 A만 다시 갱신, 이어서 전체 버튼 실행 | 슬롯별 취소·완료 검증 유지. B를 불필요하게 재예약하지 않으며 오래된 완료가 최신 표시를 덮지 않음 |
| V11 | graph/image/empty 전환과 무효 host·slot/chart 불일치 | 대상만 교체·정리. 자동 전체 fallback 없음, 다른 정상 host 보존 |

완료 판정에는 자동 요청별 실제 대상과 선택하지 않은 슬롯의 신규 호출 0회를 포함한다. 함수 이름을 바꾸거나 Sidebar가 재렌더되지 않는다는 설명만으로 완료 처리하지 않는다.
