# Plan042 — 공통 UI 객체로 입력·명령 전송 통일 및 표시 복원

## 1. 목표

1. 명령을 실행하는 버튼과 숫자 입력에 공통 UI 객체를 적용한다. 입력·확정·취소·`send()`를 공통으로 처리하고, 각 기능의 기존 공개 API를 연결한다. 모든 숫자 입력칸을 점검해 입력 중 값이 강제로 바뀌는 문제와 입력값을 확정하는 방식의 불일치를 수정한다.
2. 레이아웃 팝업의 크기 고정/해제 기능과 연결된 상태·이벤트·API·너비 분기를 제거한다. 확대 비율과 100% 초기화는 유지한다.
3. 외곽선 OFF일 때 레이아웃 미리보기의 점선 경계를 복원한다.
4. 작업 영역의 빈 슬롯 선택 표시를 복원하고 graph/image bookmark 표시의 위치·겹침·잘림을 조사해 필요한 부분을 수정한다.

Plan041의 입력 수정 방향을 공통 UI 객체 중심으로 구체화한 후속 계획이다. Plan040의 두 표시 복원 목표와 크기 고정 제거도 유지한다. 기존 `plan-040.md`, `plan-041.md`, `review-20261118-002-selection-ui.md`는 보존한다. CSV 선택 초기화 원인·사이드바 재구성 가설은 이번 조사·수정에 포함하지 않는다.

## 2. 숫자 입력의 원인과 조사 범위

### 2.1 확인된 입력 도중의 값 변경 경로

기준: commit `da28814cdfb5dab33d94b234f1c4a7f9f5405bba`의 source code. 아래 내용은 정적 확인이며, 사용자 입력 이벤트를 브라우저에서 재현한 결과와 구분한다.

- 확대 비율은 `NumberInput.onChange → changeZoom → clamp(value,100,50,200) → layout.setZoom → SET_DASHBOARD_ZOOM → readState → NumberInput.value`로 되돌아온다. `sourcecode/frontend/mantine_ui.js:2808-2811,2849-2851,2956-2963`, `sourcecode/application/public_api/layout_annotations.js:303-313`, `sourcecode/frontend/interface_fsm.js:77-83`.
- 입력 문자가 완성되기 전에 UI가 즉시 50..200으로 제한하고 FSM도 같은 제한을 적용한다. 예를 들어 기존 값을 선택해 `150`을 입력하려 해도 첫 글자 `1`을 처리하는 시점에 `50`이 공식 값으로 돌아오는 경로가 있다. 이후 문자는 사용자가 시작한 문자열과 다른 값 위에서 처리될 수 있다.
- 기준 폭·간격·바깥 여백·반경·종횡비도 `onChange`에서 즉시 clamp한 프로젝트 값을 controlled value로 되돌린다. 이미지·캡션·프린트는 직접 UI clamp가 없어도 매 문자마다 명령을 보내 Backend가 보정한 값을 다시 표시한다.
- 레이블 크기와 위치는 UI가 `Number(value)`를 즉시 적용한다. 빈 문자열은 0으로 변환되어 크기는 6, 위치는 0이 될 수 있다. 프린트 세로는 빈 문자열을 즉시 자동 높이 명령으로 바꾼다. 일시적으로 지우는 조작과 설정 확정을 구분하지 않는다.
- 축·그래프 글자 크기는 문자열을 보내지만 Backend의 정규화가 숫자·기본값으로 바꾼다. 문자열 전달 자체만으로 편집 중인 `-`, 소수점, 빈 값이 보호되는 구조가 아니다.
- 행·열만 UI-local 편집 값을 두고 `clampBehavior: "none"`과 blur 처리를 사용한다. 그러나 유효한 숫자로 해석되는 각 중간 값에는 여전히 setGrid를 보낸다. 다른 입력에 비해 부분적으로 보완된 상태다.

세 자리라는 길이를 검사해 200·500을 만드는 공통 분기는 찾지 못했다. 확대 비율의 200은 실제 상한과 일치한다. 500이 만들어진 정확한 입력칸·이벤트 순서와 선택 범위 변화는 아직 재현하지 않았다. 입력 도중의 보정 경로는 확인됐으며, 특정 숫자가 나타나는 모든 과정을 같은 원인으로 단정하지 않는다.

### 2.2 입력 위젯의 추가 보정

실제 포함된 `vendor/fast-figure-ui-runtime.js:109`의 NumberInput 구현도 확인했다.

- 기본 `clampBehavior`는 `"blur"`다.
- blur 처리에서 범위 제한·선행 0 정리를 수행하고 값이 달라지면 onChange를 호출한 뒤 사용자 onBlur를 호출한다.
- 화살표·증감 버튼도 값을 변경하고 커서를 옮기는 별도 경로를 가진다.
- 따라서 앱의 onChange 보정, 위젯 blur 보정, 앱의 onBlur 확정이 겹칠 수 있다. 행·열의 `"none"` 설정만 전체 입력으로 복사하는 것으로 수정을 끝내지 않는다. 문자열 보정과 증감 경로도 실제 동작을 확인한다.

라이브러리 전체 교체·vendor 직접 수정에 앞서 기존 위젯 설정과 앱 입력 처리로 해결한다. 번들에서 `trimLeadingZeroesOnBlur`의 기본값도 `true`다. `clampBehavior="none"`은 숫자의 blur 범위 제한을 끄지만, 선행 0을 정리하는 문자열 분기까지 끄지는 않는다.

## 3. 공통 UI 객체

### 3.1 책임과 연결 방법

현재 Application의 `dispatchProjectCommand()`가 Backend 명령 전송·참조 보정·renderer 조회를 담당한다. UI 객체는 기존 공개 API를 통해 이 경로를 사용한다. 공개 API가 담당하는 렌더링·알림·import/export lifecycle과 Backend의 검증·한 번의 반영 절차를 유지한다.

| 구분 | 책임 |
|---|---|
| 공통 UI 객체 | 입력 문자열 보관, 확정·취소 처리, 현재 대상 확인, `send()` 호출, 중복 실행 방지, 결과·오류에 따른 표시 갱신 |
| 기능별 연결 | 대상 식별 정보, 현재 공식 값을 읽는 함수, 확정값을 기존 API 인자로 만드는 함수, 호출할 공개 API, 기존 범위·step·빈 값 규칙 |
| 기존 Application·Backend | 현재 참조와 명령 검증, 프로젝트 변경, 참조 보정, 렌더링과 알림 |

공통 동작은 다음 순서로 정의한다.

1. 숫자 입력의 변경 이벤트는 공통 객체의 입력 처리에 연결한다. 객체는 입력 문자열과 편집을 시작한 대상을 UI-local 상태로 보관한다.
2. Enter·blur는 공통 확정 처리에 연결한다. 문자열을 해석하고 해당 필드의 기존 규칙을 적용한 뒤 `send()`를 호출한다. 필수 값의 미완성 입력은 현재 공식 값으로 복원한다.
3. `send()`는 현재 lifecycle·대상 유효성·실행 중 여부를 확인하고, 편집을 시작한 대상과 현재 대상이 같은지 확인한다. 현재 공식 값과 같으면 전송을 생략한다. 변경할 값은 기능별 연결을 통해 기존 공개 API에 전달한다.
4. 일반 명령 버튼은 클릭을 같은 `send()`에 연결한다. 버튼은 입력 문자열을 편집하는 단계 없이 자신의 대상·인자를 전달한다. 각 명령의 기존 실행 조건과 비동기 lifecycle을 유지한다.
5. 같은 확정의 Enter→blur 연속 이벤트와 실행 중 중복 클릭은 한 번만 실행한다. 비동기 작업의 실행 상태는 완료·실패 시 정리한다. 기존 API의 반환·취소·미반영·예외 의미에 따라 표시를 갱신한다.
6. Escape·대상 변경·팝업 닫힘은 공통 취소 처리에 연결한다. 미확정 입력을 정리하고 현재 공식 값을 표시한다. 이미 반영된 명령은 기존 명령 처리 규칙을 따른다.
7. React 재렌더 중에도 같은 입력의 편집 상태와 객체 연결을 유지한다. 대상 변경과 unmount 때 해당 UI가 소유한 편집 상태·이벤트 연결을 정리한다.

기능별 연결에는 기존 함수와 필요한 인자만 둔다. 공통 객체는 프로젝트 값의 별도 사본을 읽기 원본으로 보관하지 않는다. 범위·명령·공개 API의 별도 전역 등록부를 만들지 않는다. 범위는 기존 소유자의 정의를 참조한다. 파일 선택·다운로드·드래그처럼 브라우저 이벤트 조건이 있는 동작은 해당 이벤트 조건을 유지한다.

### 3.2 숫자 입력의 편집·확정 규칙

1. 입력 중에는 사용자가 편집하는 문자열을 해당 UI 입력에 보관한다. 전체 선택 교체·부분 선택 교체·삭제·붙여넣기·소수점·음수 입력 중간 단계에서 프로젝트나 Frontend의 확정 숫자로 덮어쓰지 않는다.
2. 타이핑만으로 도메인 명령을 보내지 않는다. Enter 또는 blur에서 문자열을 해석해 기존 범위·정수화·빈 값 규칙을 적용하고, 현재 소유자의 값을 읽어 변경 여부를 판단한 뒤 확정한다.
3. Enter 뒤 발생하는 blur로 같은 명령·notify를 두 번 보내지 않는다. Escape는 편집을 취소하고 현재 공식 값을 표시한다. 값이 같으면 불필요한 명령을 보내지 않는다.
4. 필수 값의 빈 입력·완성되지 않은 숫자·유한하지 않은 입력은 명령 없이 현재 공식 값으로 복원하고 안내한다. 일시적으로 지웠다는 이유로 0·최솟값·100을 저장하지 않는다.
5. 빈 값에 기능상 의미가 있는 필드는 별도 규칙을 명시한다. 프린트 세로는 확정 시 auto, 축 min/max/tick과 그래프 글자 크기의 빈 값은 기존 자동/기본 표시 의미를 유지한다. divide의 0 제한 등도 기존 계약을 따른다.
6. 범위를 벗어난 완성 값은 확정 시 기존 제한을 적용하고 적용된 값을 알린다. Backend의 최종 검증·범위 규칙은 유지한다. UI와 위젯이 서로 다른 시점에 다른 값으로 치환하지 않도록 정리한다.
7. 증감 버튼·키보드 화살표는 완성된 숫자 조작으로 다룬다. 같은 범위·step 규칙을 적용하고, 포커스·입력값과 명령 횟수를 함께 확인한다. 레이블 드래그처럼 직접 위치를 조작하는 기존 경로는 별도로 유지한다.
8. 편집 상태는 UI가 소유하고 프로젝트 읽기의 원본으로 사용하지 않는다. 슬롯·오브젝트·CSV·축·팝업 대상이 바뀌면 미확정 편집을 이전 대상에 적용하지 않는다. 확정할 때 같은 대상이 유효한지 확인하고 현재 소유자의 명령으로 전달한다.
9. §3.1의 공통 객체에 숫자 입력 처리와 명령 버튼의 전송 처리를 모은다. 각 입력칸의 개별 onChange·blur·클릭에 흩어진 전송·보정 코드를 기능별 연결로 정리한다. 일반 텍스트·색·선택 입력의 정상 동작은 유지한다.

| 계층 | 제거·정리 대상 |
|---|---|
| Source Script | `frontend/interface_fsm.py`의 dashboardZoomLocked/LockedWidth와 SET_DASHBOARD_ZOOM_LOCK, `application/adapter.py`의 잠금 너비 분기, `application/public_api/layout_annotations.py`의 setLayoutApiZoomLocked/readState 잠금 필드, `application/public_api/__init__.py`의 setZoomLocked, UI 절차의 잠금 처리 |

- 너비 계산은 `현재 기준 폭 × 확정된 확대 비율 / 100`으로 통일한다. Backend 기하 계산과 실제/미리보기 공통 틀은 유지한다.
- 100% 초기화는 확대 비율만 100으로 되돌린다. 제거한 lock 상태를 재설정하는 코드는 남기지 않는다.
- 공개 setZoomLocked와 저장되지 않는 Frontend lock 필드를 제거한다. 저장 프로젝트 형식에 새 필드·임의의 버전 변환을 추가하지 않는다.
- 실제 크기 측정 함수는 다른 표시·캡처·미리보기 경로의 사용처를 확인한다. 잠금용 사용만 제거하고 필요한 측정은 유지한다.
- 전체 세 계층과 호출자를 검색해 잔여 호출·무효 버튼·이름만 남은 이벤트가 없는지 확인한다. 잠금 효과의 유용성을 입증하는 조사로 기능 제거를 지연하지 않는다.

## 5. 미리보기 점선·작업 영역 선택 표시 복원

Plan040의 확인된 두 경로를 그대로 수정 대상으로 유지한다.

## 6. 수정 순서

### R01 — Source Script

- §3의 공통 UI 객체와 기능별 연결의 구조·소유·수명, 입력/확정/취소/`send()`의 인자·반환·변경·처리를 정의한다. 숫자 입력과 일반 명령 버튼이 사용하는 경로를 명시한다.
- 각 필드·버튼이 호출하는 기존 API와 대상·인자·반환·실패 의미를 연결한다. §4의 기능 제거와 §5의 표시 절차도 실제 책임 함수에 적는다.
- 저장된 Source Script 예시의 Args·Return·변경·처리를 따른다. 변수 정의는 의미·구조를 설명하고, 변환·분기·갱신은 처리 절차에 둔다.
- 입력별 기존 도메인 규칙과 새 UI 편집 규칙을 연결한다. 현 source code를 UX 요구사항의 근거로 삼지 않는다.

### R02 — pseudocode

- 공통 UI 객체의 생성·이벤트 연결·입력·확정·취소·`send()`·정리와 기능별 API 호출을 대응시킨다. 편집 상태·입력 문자열·현재 대상 검증·단일 확정·무명령 복원·후속 표시 순서를 명시한다.
- lock 상태와 분기를 제거하고 확대 비율 경로를 단순화한다. 점선·선택 장식의 조건과 정리 순서를 대응시킨다.

### R03 — source code

- 공통 UI 객체를 구현하고 숫자 입력과 명령 버튼에 연결한다. 기존 공개 API와 `dispatchProjectCommand()` 경로를 재사용한다. 각 기능의 렌더링·알림·취소·실패 처리를 유지한다.
- §2.3의 모든 숫자 입력칸에 공통 객체를 적용한다. 공통 함수 호출로 생성되는 필드도 개별 동작을 확인한다. 명령 버튼도 클릭 처리의 대상·인자·중복 실행·비동기 완료를 점검해 연결한다.
- 위젯의 기본 blur 보정·선행 0 처리·onChange 재진입과 앱의 확정 처리를 정리한다. 전역 테마 설정 한 줄 변경으로 완료 처리하지 않는다.
- UI-local 편집, 기존 API/FSM/Backend의 현재 값 검증과 명령을 연결한다. lock 호출자와 사용하지 않는 코드도 제거한다.
- 공통 프레임을 분리 구현으로 되돌리지 않고 점선·선택 표시를 복원한다. Plotly/이미지 비동기 완료·해제·host 재사용·내보내기 처리는 유지한다.

### R04 — 대응 검토와 기록

- Source Script→pseudocode→source code의 필드·분기·반환·실패·대상 변경·자원 소유를 대조한다.
- 실제 계층 변경에 맞는 fingerprint·파생 관계와 native Git patch를 기록하고 새 후속 review를 작성한다. 기존 계획·검토 문서는 보존한다.
- 정적 원인 확인과 실제 입력 재현을 구분한다. 테스트별 기대·관찰·판정을 읽을 수 있게 작성한다.
