1. Old queued resize stored only a boolean; at callback time resizePlots enumerated whatever graph map was then current. Thus a request from an obsolete generation could resize a later graph instead of being discarded. Changed requests to renderer-local lifetime descriptors containing exact record/operation/generation/slot/chart/host/plot. Flush verifies every association against the live map. A later *explicit* request coalesces by replacing the pending descriptors, so latest requested work is not lost. Descriptors are released at flush, with no project snapshot/copy or FSM query.
2. Observer installation was guarded only by dashboardObserver. Without native ResizeObserver that field stayed null and every render registered another window listener. Added resizeObserverInstalled, set only after successful installation in either path. Native partial installation now disconnects both locally created observers, preserves the original observe failure even if disconnect throws, and leaves installation retryable. Normal runtime owns its one lifetime observer pair/listener; no new global domain state or cleanup protocol.

Observer callbacks consume only supplied public actions: graph-area/window resize calls Application refreshDashboard (which obtains a fresh official renderer input); dashboard observer synchronizes caption width and schedules graph resize without a Backend read. The captured action surface contains functions, not a retained project/interface snapshot. Existing Application/Mantine zoom/style/selection callers still call the same schedulePlotResize boundary. Full-render graph completion already has its own generation/operation current guard before its direct RAF resize and remains unchanged.
