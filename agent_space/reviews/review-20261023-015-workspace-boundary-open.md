## Ownership, copy/write paths and failure/release

The selectedSlotId in interfaceFSM remains the single session selection authority. Backend owns visibility/content associations. A workspace context is acquired once for one synchronous ready/audit operation; only the derived string crosses into Frontend, no future mutation is fed from that context, and the local read becomes unreachable at return/throw. Selected-slot public reads are separately acquired detached results, never a general cache, mutable Project model or new authority. Existing callers use the relevant scalar in their own operation; this change does not claim their entire graph editor/domain translation is complete.

There is no new asynchronous work, queue, handle, URL, observer or native surface in this unit, and no new release owner. Existing graph/image/pointer lifetimes are untouched. No Frontend publication occurs when the initial query fails; downstream ready failure propagates without retry/rollback. Ordinary lifecycle events are unchanged and do not gain Backend reads; only the existing domain-dependent startup workspace resolution was relocated.

Rejected: moving `slotAt` into another Frontend helper keeps the violation; adding a selected-slot mirror/store introduces authority and invalidation rules unnecessarily; a new Backend query duplicates the existing provider; blindly removing fixed graph-event IDs or consolidating Layout freshness now would resume the explicitly deferred task rather than the main translation.
