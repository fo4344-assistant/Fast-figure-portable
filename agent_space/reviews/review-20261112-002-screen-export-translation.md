## Stage 2: current/target raster procedure translation

`pseudocode/frontend/renderer.pcal`: renderDashboardCurrent, renderDashboardTarget, exportCaptionLayout, downloadExportPayload. Actual public callers are `sourcecode/application/public_api/layout_annotations.js`: capturePrintApi/savePrintApi, exposed by `sourcecode/application/public_api/index.js`. Both acquire one official export input inside the existing exporting lifecycle and pass only that input/status sink. No protocol or second authority is introduced.

- **Current:** all visible-slot rectangles, colors/radius, label geometry, caption geometry/font/padding and source bounds are captured before asynchronous raster work. Live `.plot-item` handles are no longer retained across earlier-slot awaits. Supplied precomputed figures are copied/scaled/rendered in exportChartImage's task-owned host at measured viewport size; no CSV transformation/Backend reread, live plot purge, freeze, revision sync or persistent preset update. Snapshot + viewport is the Source-permitted one-shot representation, not target width/height rendering.
- **Clipping:** current image/graph painting is clipped to the captured slot radius, including cover/manual images. Caption border follows supplied visibility. Target retains its target-geometry clip.
- **Caption:** current uses the existing paragraph/prefix algorithm with a task-local viewport measurement input (measured width/font/line-height/padding). This is a read-only physical measurement adaptation, not a new export preset or modified official snapshot. Explicit and blank paragraphs, first-line name/prefix, resolved fonts and clipping use the same emitted line list for painting. Target caption baseline is explicitly alphabetic, independent of label painting.
- **Resources:** paintExportImage owns one decode through synchronous painting and releases its src in finally. exportImageLoad removes callbacks on completion and releases src on decode/setup failure. Current and target canvas backing stores are released on success, early rejection and exception; a boolean preserves even null/undefined primary failures if cleanup also fails. Existing exportChartImage host/Plotly purge and downloadExportPayload URL/handoff lifetime remain task-local and preserve original failure.
- **Completion:** existing supplied dimension/area limits, rejected reasons, PNG/JPEG DPI encoding, one download handoff, saved shape and automaticHeight meanings remain. Progress/debug failures do not authorize cancellation, retries, rollback or replacement failure. No disk-save confirmation is invented.

Stage 2's named current/target procedure and resource boundaries have now been translated in the statically inspected scope.
